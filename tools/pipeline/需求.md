# 编排层 pipeline · 开发包(需求与接口)

> 层:编排层 · 状态:**规划**(架构标注暂不急,先立设计)· 分支建议:`feat/pipeline`
> 依赖:各层现有入口(`run.py` 的 cmd_* / 各模块函数)· 参考:[架构设计.md](../../docs/架构设计.md) §8.1/§9.1

## 职责(做什么 / 边界)
- 把散在 `run.py` 里堆叠的子命令,收敛成**显式 DAG**:声明阶段依赖,按序执行。
- **失败隔离**:某步失败,下游读**上次成功产物**,不连锁崩。
- `run.py` 退化为**薄 CLI**(只解析参数 + 调 pipeline),不含业务逻辑。
- **边界**:只做编排/依赖调度,**不含任何业务计算**。

## 接口契约
```python
class Stage:
    name: str
    fn: Callable          # 该阶段执行体(调用现有 cmd_* / 模块函数)
    deps: list[str]       # 依赖的上游 stage 名

def define(*stages: Stage) -> "Pipeline"
def run_pipeline(name: str) -> None      # 拓扑排序执行,失败隔离
```
- 默认管线:`collect → serialize → {panel, screen, report}`;`sentiment` 独立;`backtest` 按需。

## 验收标准
- [ ] DAG 依赖拓扑正确;某 stage 失败,下游跳过或用上次产物,不崩。
- [ ] `run.py all` 走 pipeline,产物与现状一致(回归)。
- [ ] 新增 stage 只需 define,不改其他 stage。

> 注:定时调度(cron T1–T5,架构 §8.2)依赖本模块,单独排期。

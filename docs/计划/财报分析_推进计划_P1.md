## 2. ⭐ 推荐:先做里程碑 M1「分层归位 + 不误杀 + 进决策层」(全程非阻塞)

一个自洽、有端到端价值、且完全不卡提供者/不卡数据源的里程碑。分五步、分层清晰:

### 步骤 1 · 分层归位(纯重构,低耦合)
- 迁移 `tools/financial_report/{metrics,flags,scoring,analyzer}.py` → **`tools/analysis/financial/`** 子包(紧邻 `analysis/valuation.py` 估值,同属"个股基本面评估")。
- 采集层 `collectors/financial.py`、存储层 `store`、契约 `record.py` **不动**(已合规)。
- 改 4 处 import(analyzer 内部 3 + test 1);`tools/financial_report/` 删除。
- **IO 契约不变**:`analyze/query/build_financial_block/need_llm_fields` 签名保持,只换命名空间。
- 测试路径同步改;跑 `test_financial` 全过 = 迁移无损。

### 步骤 2 · 误杀修复(方法论,不需提供者阈值)
- **低基数护栏**:应收/存货激增红旗加"绝对额门槛"——占营收比 < 阈值(如 5%)时不触发(修茅台小基数误杀)。缺基数→不命中。
- **金融业特判**:检测行业∈{银行,保险,证券}(复用 `analysis/industry_map.py`)→ 资产负债率/毛利率类红旗对金融业**降级不判**(银行高负债是常态),并在输出标注"金融业口径"。
- 语义:这两条是"减少假阳",非改评分权重,不侵入提供者待定口径。

### 步骤 3 · 审计意见闸门(闸门2,数据已在手)
- `OPINION_TYPE`(年报审计意见)P0 已随采集落 raw。实现:最新年报意见 ≠ 标准无保留 → `financial` 块标 `审计意见闸门=不通过` + 红旗"非标审计意见"(高严重度,封顶降级"风险")。
- 闸门1(审计机构∈名录)**待步骤4后按 qwen 调研决定**(缺机构名称源)。

### 步骤 4 · 接入决策层(让财报被用上)
- **serialize**:`serialize_all` 里对每票调 `build_financial_block` 写入 record 的 `financial` 块(披露日锚定,as_of 过滤)。
- **展示**:`panel.py` 横表加"财报评级/关键红旗"列;web 详情页 record 已含 financial 块可渲染。
- **合议**:`analysis/experts.py` 加一个**财报专家**(读 financial 块 → 按评级/红旗给"偏多/中性/规避"票),接进 `council`;或先做轻量——`factor/` 加"财报质地因子"。**推荐先做财报专家(合议票)**,与现有 orchestrator 模式一致、耦合低。
- 无未来函数:全部经 `build_financial_block(code, as_of)` 披露日过滤。

### 步骤 5 · 测试 + 文档
- 测试锁语义:低基数护栏边界、金融业特判降级、审计意见闸门拦截、财报专家投票映射、serialize 写 financial 块、无未来函数。
- 回填本文档 §结果 + 开发日志。

## 4. 分层与复用原则(本轮硬约束)
- **采集**只在 `collectors/`;**分析**只在 `analysis/financial/`;**决策**在 `pipeline/`+`analysis/experts.py`(合议)+`factor/`;**存储**只在 `store/`。
- 财报分析工具对外只暴露 `analyze/query/build_financial_block`,决策层通过 record 的 `financial` 块或 `query()` 消费,**不反向依赖决策层** → 高复用、低耦合。
- LLM 只碰文本(M2),数值全走代码(硬边界不变)。

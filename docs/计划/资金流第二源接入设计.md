# 资金流第二源(腾讯 proxy)接入设计

> 版本:v1 · 2026-09-09 · 状态:**待统筹审阅**(审过再动代码)
> 依据决策:`docs/计划/资金流第二源选源_决策.md`(已拍板:东财→腾讯proxy→新浪 三级链)。
> 现状:个股资金流 `fundflow.py` 只依赖东财 `push2his`,本机 TLS 墙,今晚 442 只 curl(56)。
> 目标:加**非东财**第二源做透明 fallback,口径对齐现有 `kind="fundflow"` schema。

---

## 0. 可达性实测结论(已验,免返工)

腾讯 `proxy.finance.qq.com/cgi/cgi-bin/fundflow/hsfundtab` **不吃本机 TLS 墙**:纯 python
`requests`(带 `User-Agent` + `Referer: https://finance.qq.com/`)即 HTTP200 + `code:0/ok`、
~0.2s,**无需 subprocess+curl 绕指纹**。5 只票(sh600519/sz000001/sz300750/sh601318/sh600036)全通。

## 1. 现有东财口径(对齐目标)

`fundflow.py`:`kind="fundflow"`(parquet),列 `_COLS`:
```
["date", "主力净流入", "小单净流入", "中单净流入", "大单净流入", "超大单净流入", "主力净占比"]
```
日频序列(东财 fflow/daykline,多日历史,五档齐全)。单位:净额=**元**。
下游 `summarize()` 实际消费:**今日主力净流入 / 今日主力净占比 / 近5日主力合计 / 主力连续净流入天数**
——全部基于 `主力净流入` 列 + `主力净占比`,**不使用**历史每日的四档拆分。

## 2. 腾讯 hsfundtab 返回结构(实测)

`GET https://proxy.finance.qq.com/cgi/cgi-bin/fundflow/hsfundtab?code=sz000001`
Header:`User-Agent`(任意浏览器串)、`Referer: https://finance.qq.com/`。返回 `{code,msg,data}`:

| data 子块 | 内容 | 用途 |
|---|---|---|
| `todayFundFlow` | **今日五档全**:`mainNetIn/superFlow/bigFlow/normalFlow/smallFlow`(+in/out/rate、summary.mcRatio) | 今日主力+五档 |
| `historyFundFlow.oneDayKlineList` | **近 20 日**,每条 `{date, mainNetIn, price, avgIn}`——**仅主力净流入,无五档拆分** | 主力净额日序列 |
| `fiveDayFundFlow.DayMainNetInList` | 近 5 日 `{date, mainNetIn}` | 冗余(被 20 日覆盖) |
| `todayFundTrend.minList` | 今日分时资金流 | 暂不用 |

**关键限制(诚实标注)**:腾讯历史序列**只有 20 日、且只给主力净流入**;五档拆分**只在今日快照**。
→ **能满足** `summarize()`(20 日主力净额够算近5日合计/连续天数,今日五档齐);**不能**提供"历史每日五档拆分"
(但现下游不用它)。若未来有因子要历史四档,腾讯给不了,东财仍是唯一全档源。

## 3. 字段映射(腾讯 → 东财 schema)

**今日行**(来自 `todayFundFlow`):
| 东财列 | 腾讯字段 | 说明 |
|---|---|---|
| 主力净流入 | `mainNetIn` | 元 |
| 超大单净流入 | `superFlow` | 元 |
| 大单净流入 | `bigFlow` | 元 |
| 中单净流入 | `normalFlow` | 元 |
| 小单净流入 | `smallFlow` | 元 |
| 主力净占比 | `mainInRate - mainOutRate`(近似)或留 None | 腾讯 rate 是流入/流出占比,非"主力净额/成交额";口径不同**标注近似或置 None** |

**历史行**(来自 `oneDayKlineList`,近 20 日):
| 东财列 | 腾讯字段 | 说明 |
|---|---|---|
| date | `date` | |
| 主力净流入 | `mainNetIn` | 元 |
| 超大/大/中/小单净流入 | **无** | 腾讯历史不拆档 → 落 **NaN**(有声缺列,非 0) |
| 主力净占比 | **无** | → NaN |

落盘仍 `kind="fundflow"`,列同 `_COLS`;腾讯来源的历史四档列为 NaN。`meta.source="tencent_proxy"`。

## 4. 量纲/口径断言(P3-1 同款,防单位错配)

腾讯与东财净额同为**元**,但仍加**决定性**断言:
- **恒等式断言(强)**:今日 `mainNetIn ≈ superFlow + bigFlow`(主力=超大+大)。实测 sz000001:
  `-20147224 == -25681386 + 5534162` **分毫不差**。→ 解析后断言 `|main-(super+big)| / max(|main|,1) < 1e-3`,
  违反即抛(挡字段错位/单位错配)。
- **量级断言(弱)**:个股主力净额中位量级应在 ~1e5–1e10 元;若整体小 1e4 倍 → 疑似"万元",告警。

## 5. 三级 fallback 口径与落盘

```
fetch_one(code):
  东财 push2his fflow/daykline(现主源,全档多日历史)
    → 本机墙/失败 → 腾讯 hsfundtab(今日五档 + 近20日主力净额;历史四档 NaN)
      → 再失败 → 新浪 MoneyFlow.ssl_qsfx_zjlrqs(仅主力净额 r0_net 日序列;五档全 NaN)
  仿 market.py:每源 try + retry_call;meta.source ∈ {eastmoney, tencent_proxy, sina} 记实际命中源
```
- **透明度**:落盘 `meta.source` + `meta.tier_history="full|main_only"`,下游可辨"历史四档是否可信"。
- **summarize() 不变**:三源都提供主力净额日序列 + 今日,summarize 全维可算;仅历史四档在降级源为 NaN。
- 新浪端点:`vip.stock.finance.sina.com.cn/quotes_service/api/jsonp.php/var FDFLOW=/MoneyFlow.ssl_qsfx_zjlrqs?daima=sh600000`(需 Referer;返 `r0_net` 主力净额日序列)。

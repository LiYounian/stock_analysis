# 日内超短线循环 · 设计方案(待评估)

> 2026-09-07 建档。缘起:用户提出把"收盘后选股、次日操作"升级为**日内超短线循环**——
> 午盘拉数分析初选 → 下午实时观测候选 → 收盘前半小时定稿"买/持/卖" → 尾盘执行 → 次日午盘复盘。
> 本方案在 [2026-09-07_尾盘选股pilot_设计.md](2026-09-07_尾盘选股pilot_设计.md) 基础上升级(尾盘 pilot 的口径被本方案吸收),把系统从**选股器**扩成**日内持仓管理循环**。
> ⚠️ 非投资建议,测试环境研究模拟。所有"买/持/卖"均为研究记分,不构成真实交易推荐。

---

## 0. 一句话范围

**并行开一条日内超短线循环:每天一次决策(午盘分析)、一次执行(尾盘),对每个标的给 `买入/持有/卖出`;下午用轻量实时轮询盯候选+持仓、阈值触发信号;收盘后定向复盘喂次日。现有收盘选股流不动、当对照。** 本循环是原型/试点,非已验证策略。

---

## 1. 实测事实(2026-09-07 两路子 agent 探查,作为设计硬约束)

**① 全A实时拉取有 ~14s 横截面时间差(time-skew)**
- 唯一实时源 = 腾讯 gtimg(`qt.gtimg.cn`),`gtimg_quote.py` **串行分批**(批 50、111 批、无并发),全A 5539 只单发墙钟 **14.2s**。
- 盘中先拉的票比后拉的票"早看 ~14s 的世界",快变行情下前后批不可比,全A排序会混入"谁先被采样"的伪信号。**用户担忧属实。**
- 缓解:改并发可把墙钟压到 1–2s;但本循环只盯小候选集,用不上。

**② 午休(11:30–13:00)冻结拉取消除时间差**
- 午休全市场停牌,所有报价冻结在 11:30 早盘收盘。此时顺序拉 14s,第 1 只与第 5539 只承载**同一张 11:30 快照**,time-skew 实际危害 = 0。
- **取严格横截面对齐的全A快照,最干净窗口 = 午休(或收盘后)。这就是午盘取数的依据。**
- 注意:源方 `quote_time` 字段是心跳时刻、非成交时刻,不能当"是否冻结"的锚,要靠"当前处于午休时段"这一外部事实。

**③ 盯 5 只 ≈ 0.1s,无 skew;免费源只有 HTTP 轮询,无 WebSocket**
- 5 只拼一个 URL 单次请求 ~90–113ms,时间差可忽略。
- 免费 A 股 L1(腾讯/新浪/东财)**全是 HTTP 轮询,无免费 WS**;真 WS 属付费 L2 或需逆向东财 wss(本机还有 TLS 指纹墙)。为盯 5 只研究模拟,**用每 3–5s 轮询 gtimg 即足够且最简,不上 WS**(WS 也拿不到更快的免费数据,瓶颈是源方几秒一跳的刷新率)。
- 复用现成:`gtimg_quote.fetch_quotes(codes)` 一行拿全字段;`web/realtime.py` 有 TTL 缓存骨架、`intraday_snapshot.py` 有快照循环骨架。东财 push2 本机被墙、别用。

## 2. 每日循环重设计(合并冗余后:一日一决策一执行)

```
                     ┌─ 交易日 T ─────────────────────────────────────────────┐
09:30            11:30───────13:00              14:30            15:00
  │                │  午休冻结  │                  │  收盘前半小时     │
  │                │           │                  │                 │
  ▼                ▼           ▼                  ▼                 ▼
 (盘前静默)   ①午盘取数+分析   下午实时观测      ③定稿推荐        ④尾盘执行
              ②初选~5候选+     (轮询候选+持仓,   (对每标的:       (买/持/卖
               复盘昨日持仓     阈值触发信号)      买入/持有/卖出)   全在尾盘落地)
                                                                  │
15:00 后 ⑤收盘定向复盘:今天这组"买/持/卖"是否合理 → 喂 T+1 午盘 ①
```

**关键:决策与复盘合并进午盘那一次**(用户洞察:尾盘再分析多余、每次操作本就要复盘)。于是每天:
- **午盘 ①②**:拉午休冻结全A快照 → 跑现有策略/打分初选 ~5 只新候选;**同时复盘当前持仓**(每只持有第几天、浮盈、是否触发离场逻辑)。
- **下午实时观测**:轮询盯"候选 + 持仓",阈值触发买/卖信号(见 §4)。
- **③ 收盘前半小时(~14:30)**:定稿**一份**推荐,对**每个标的**给 `买入(新)/持有/卖出`。
- **④ 尾盘(14:30–14:57)**:按推荐执行(研究模拟记账)。
- **⑤ 收盘后**:定向复盘今日决策是否合理 → 沉淀经验 → 喂次日午盘。

## 3. 数据取数策略(直接由 §1 实测推导)

| 用途 | 窗口 | 取法 | 为什么 |
|---|---|---|---|
| 全A横截面(初选打分基础) | **午休 11:35–12:55** | gtimg 全A 单发快照(~14s 串行 OK) | 冻结→零 time-skew,横截面严格对齐 |
| 候选+持仓实时观测 | 下午 13:00–14:57 | gtimg **每 3–5s 轮询** 这 N 只(N≈5+持仓) | 单请求 0.1s、无 skew;免费无 WS,轮询最简 |
| 尾盘执行价 | ~14:50 快照 | gtimg 单发这 N 只 | 作模拟成交价基准 |

- 全A午休快照落 `data/intraday/T/T1145.json`(复用 `intraday_snapshot.py`,加午休时点)。
- 实时观测不必逐条落盘,只落"触发事件"日志 + 尾盘定稿快照。

## 4. 实时观测架构(轮询循环,不上 WS)

**组件 `tools/pipeline/intraday_watch.py`(新增,先定接口)**:
- 输入:候选+持仓代码列表 N 只、阈值配置。
- 循环:交易时段每 3–5s `gtimg_quote.fetch_quotes(codes)` → 对每只算 price/涨幅/量比/成交额增速 → 比阈值 → 越线记一次信号(研究模拟)。
- **去重/防误触发**:用返回的 `quote_time` 判定源方是否真刷新;同一 `quote_time` 不重复触发;非交易时段静态值不触发。
- **无状态、崩了重启即恢复**(轮询天然优势,不需要 WS 的断线重连/心跳)。
- 输出:`data/intraday/T/watch_events.jsonl`(触发事件流,含时刻/代码/规则/当时价量)。

**阈值口径(待拍板,§10)**:先给保守默认——现价突破午盘参考价 ±x%、量比 > 阈值、成交额较午盘放大 > 倍数;越线记"关注/买入倾向/卖出倾向"信号,不自动成交(成交在尾盘定稿后)。

---

## 5. 模拟持仓账本(新增,超短线复盘的地基)

现状项目**只选股不记仓**,而"持有/卖出"判断必须有锚。新增轻量账本:

**`data/analysis/positions.json`(或 csv)**,每持仓记:
- 代码/名称、买入日期、买入价(尾盘模拟成交价)、持有天数、当前价、浮盈%、对应基准(买入时点全A等权)超额。
- 状态机:`持有中 / 今日建议卖出 / 已卖出(日期+卖出价+实现超额)`。

由 ④尾盘执行 写入/更新,⑤收盘复盘 与①午盘复盘 读取。**这是"买/持/卖"推荐能落地和记分的前提。**

## 6. 未来函数红线 & 基准配对(继承尾盘 pilot 口径)

1. **未来函数**:午盘/下午所有决策一律锚定 ≤ 决策时点,严禁引入更晚(尤其当日收盘)信息。实时观测的 `quote_time` 必须 ≤ 当前。
2. **基准配对**:α = 个股 − **同时点**全A等权(`cross_section_stats`);买入超额用买入时点基准、复盘超额用复盘时点基准,时点必须配对。
3. **独立记分**:本循环记分与现有收盘流 forward_scorecard **物理分离**(如 `data/analysis/backtest/intraday_scorecard.csv`),不互相污染。
4. **回测约束(诚实)**:无历史盘中数据(盘中快照仅 3 天、tick 仅 4 天),**"午盘决策 + 尾盘成交"无法跨历史回测**,只能**前向积累验证**(≥15 交易日)。可先用日线 `open[t+1]/close[t]` 隔夜分量做先验(`backtest_newhigh.py` 已有)。

## 8. 利弊回顾(继承尾盘 pilot §2,略)

利:消除"决策已下、执行滞后"真空;躲 T+1 开盘拥挤冲击;午休冻结快照横截面干净;实时观测让决策贴近尾盘。
弊:午盘基础到尾盘 stale ~3.5h(靠实时观测补);主动新增隔夜暴露;无法历史回测、只能前向验证;新增账本+观测循环的工程量。

## 9. 工程量估(约法#11,agent 视角)

- **实时观测循环 `intraday_watch.py`**:~15–25K token 实现+测试,agent ~1–2h(含阈值口径调试)。
- **模拟持仓账本 + 日内记分卡**:~15K token,~1–1.5h。
- **午休快照时点 + launchd**:~5K token,~0.5h。
- **分析师流程文档 + 提示词增量**:~10K token,~1h。
- 合计约一轮 60–75K token、agent 侧 4–5h(含审阅来回)。建议**分步 commit**:先账本+快照节点,再观测循环,最后流程串联。

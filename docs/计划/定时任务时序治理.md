# 定时任务时序治理（漂移标注 + 任务互斥 + 取数下沉）

> 首次提出：2026-09-03。来源：09-03 盘中核实任务实测暴露"工具调用被挂起 3h16m"。
> ⚠️ 非投资建议。本文件是计划/设计留痕，供项目转交时对接。

## 1. 问题（实测证据）

三个 Claude 定时任务：盘中核实 `10:33` / 盘尾复盘 `15:10` / 收盘选股 `18:36`（cron 均带 jitter）。

实测三次运行的会话 transcript 时间线：

| 任务 | 触发 | 第一条 bash 真正执行 | 挂起 | 完成 | 净工作时长 |
|---|---|---|---|---|---|
| 盘中核实 09-03 | 10:34:14 | **13:50:09** | **11743s (3h16m)** | 13:54:08 | 3m55s |
| 盘尾复盘 09-02 | 11:00:10 | 14:11 | 3h11m（中途再挂 87min） | 15:42:08 | ~25min |
| 收盘选股 09-02 | 18:36:19 | 18:36:2x | 无 | 19:42:23 | 1h06m |

**根因**：后台定时会话在桌面 App 非活动时，**工具调用被挂起不执行**，直到用户回到 App 才 flush。判据硬：盘中任务第一条命令是
`date "+%Y-%m-%d %H:%M:%S %A" && git fetch origin && git merge --ff-only origin/main`，其 `date` 自己打印出来的时间就是 `13:50:09`
——命令根本没启动，不是跑得慢。选股任务无挂起，因为 18:36 时用户在机器前。

这是运行环境属性（harness/App 生命周期），**不是项目代码 bug**，项目侧只能治"漂移后果"。

## 2. 三个后果

- **C1 时效性丧失**：10:33 的"早盘偏离核实"实际取数于 13:50，早盘这一维根本没检验。任务书前置检查只判"当前是否在盘中"，13:50 恰在盘中→放行，漏了"漂移多久"这一判据。
- **C2 任务并发**：若盘尾（15:10）被挂到 18:40 才 flush，会与选股（18:36）并发。具体危害：①盘尾负责创建 `经验沉淀/v<今天>.md`，而选股第一步就要"读日期最大的一版"→读到不存在或半成品；②两会话同时在主仓工作树跑 `git fetch && merge --ff-only`；③同时写 `docs/每日分析/`。现有"闭环就绪门控"只等**数据闭环**（`data/sync_receipts/`），**不等盘尾会话**——缺这一维。
- **C3 产出不自证**：漂移未写进产出，读者与下游经验沉淀无法知道某个维度其实没检验。

## 3. 方案（两层）

### 3.1 治本：确定性取数下沉到 OS 级定时（不依赖 Claude 会话何时醒）

`launchd`（真实 10:30，周一~周五）→ `tools/pipeline/intraday_snapshot.py` → `data/intraday/<日期>/T1030.json`。
Claude 盘中任务无论几点醒，**优先读这个 10:30 真快照**做早盘偏离，实时价只作补充时点。

这是 [分析师流水线设计](分析师流水线设计.md) 里"确定性节点=代码/工具"的第一个落地件。输入输出契约、手动补跑、kill-switch、下游降级见 [盘中定时快照·确定性节点](盘中定时快照_确定性节点.md)。

### 3.2 止血：任务护栏 `tools/ops/task_guard.sh`

单一真源的护栏脚本，三份任务书统一调用，避免每份任务书各写一套 bash。

| 子命令 | 语义 | 产出 |
|---|---|---|
| `begin <task> <期望HHMM>` | 写运行锁 + 算漂移 | `DRIFT_SECONDS/DRIFT_HUMAN/DRIFT_FLAG=ok\|late/EXPECTED/ACTUAL` |
| `end <task>` | 标记完成 | — |
| `wait <task> <最多分钟>` | 有界等待另一任务跑完 | `RESULT=ready\|timeout`，附等待时长与对方状态 |
| `status <task>` | 查锁 | 锁内容 |

- 锁文件：`data/task_locks/<task>.<YYYY-MM-DD>.lock`（JSON：task/started_at/finished_at/status/expected_at/drift_seconds/session_pid）。
- **陈旧锁**：`wait` 把 `status=running` 且 `started_at` 早于 `stale_minutes`（默认 300）的锁视为已挂掉，不再阻塞——否则一次崩溃会永久卡住后续任务。
  不用 pid 存活判断：Claude 每条 bash 都是新 shell，pid 记下来立刻就死，判不出真实状态。
- 锁目录在 `data/` 下（gitignore 滚存），不进版本库。

### 3.3 三份任务书的改法（描述性约束，不塞具体 case）

1. **开工第一步**（三份都加）：调 `task_guard.sh begin`，拿到漂移。**漂移 > 30min 必须在产出里显式标注**"预期 HH:MM 触发 / 实际 HH:MM 执行 / 漂移 Xh Ym / 数据采集时点=实际执行时点"，并点名**哪个维度因漂移未能检验**。
2. **收工最后一步**（三份都加）：调 `task_guard.sh end`。
3. **盘中核实**：优先读 `data/intraday/<今天>/T1030.json` 做早盘偏离；该文件缺失才退化为"用当前实时价，并标注早盘维度未检验"。
4. **收盘选股**：闭环就绪门控**加一维**——先 `wait daily-stock-eod-review 30`；`timeout` 则降级继续，并在产出显式标注"盘尾复盘仍在运行，经验沉淀 v<今天> 可能未就绪，本次实际读的是 v<版本>"。
5. **盘尾复盘**：并版时必须把当日复盘文件里其它节（如盘中核实节）标注的教训/战术偏差**一并纳入经验条目**，不得只看自己这一节。
6. **经验待并入 inbox**：`docs/每日分析/经验沉淀/_待并入.md`——任何会话发现"该进经验但当日经验版还没建"的条目就写进这里；盘尾任务建新版时**必须消费并清空**它。解决"经验按交易日 append-only、跨日教训无处落"的结构性问题。

## 4. 验收结果（2026-09-03 落地）

| 项 | 标准 | 实测 |
|---|---|---|
| 护栏语义锁 | 漂移计算/锁幂等/`wait` 四种放行路径/陈旧锁/锁按日隔离/best-effort 不非零退出 | `tests/test_task_guard.py` **15 passed** |
| 任务书接线 | 三份 grep 到 `begin`/`end`；选股 grep 到 `wait daily-stock-eod-review` | 3/3、1/1 ✓ |

| plist | `plutil -lint` 通过、周一~周五 10:30 五条 | OK ✓（装载见下）|
| 漂移自证 | 产出里出现漂移标注 | 09-03 盘中核实节已补记 3h16m 漂移与"早盘维度未检验" ✓ |
| 下一交易日 | 三份产出若漂移必有标注段；锁文件成对出现 | ⏳ 待 09-04 观察 |

**未完成项**：`launchctl bootstrap` 装载 plist 被本会话权限策略拦下，需用户手动执行一次（命令见 [盘中定时快照·确定性节点](盘中定时快照_确定性节点.md)）。装载前 `T1030.json` 不会产生，盘中任务按设计退化为"用实时价 + 标注早盘维度未检验"——**止血层不依赖装载**。

## 5. kill-switch

- 治本：卸载/删除 `~/Library/LaunchAgents/com.stockanalysis.intraday-snapshot.plist`，盘中任务自动退化为读实时价。
- 止血：删除 `tools/ops/task_guard.sh` 会让任务书里的调用失败——故任务书里所有调用一律 **best-effort**（`|| true` 或判存在），护栏缺失时任务照常跑，只是没有漂移标注与互斥。

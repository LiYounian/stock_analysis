## 0. 一句话

**金字塔选股 = 一条独立的每日选股流程**：所有基石先做成 Agent 可发现、可获取、**浓缩且带解释**的工具产出；金字塔 Agent（Claude Code，另 DeepSeek / 千问 并行对照）读同一套工具，按"经验 + SOP 逐票研判"收敛为 **5~6 只 = 2~3 建议买入 + 2~3 规避**（价位一律工具回填、来源标注贡献度）；每日 Claude Code 复盘闭环，可反向调整策略 / 输出 / 工具定义 / 口径。**跑出正向绝对收益才固化。**

## 1. 用户灌输的核心观念（逐条记录，作为设计公理）

| # | 观念 | 设计含义 |
|---|---|---|
| G1 | **一切基石都是工具**，供 Agent（含 Claude Code）共用；Agent 有权知道工具清单、分别获取各工具产出，且拿到的是**浓缩**内容 | 建工具注册表 + 统一"浓缩产出"接口 |
| G2 | 现有定时任务的提示词也是**高端 Agent**；直接调用 vs CLI 只是不同 Agent 用工具的方式；**统称 Agent** | 定时任务 / DeepSeek / 千问 / 金字塔 都是 Agent，只是宿主不同 |
| G3 | **所有中间过程、基石、支撑数据、参考，都是给大模型看的**；输出必须利于大模型判断 | 每个工具产出按"LLM 可读"设计，不按"人看报表"设计 |
| G4 | **结论和数值必须有解释**，不能是冷冰冰的数；打分要在提示词里明确标识；**不同分数段要有区间含义**；现有只出分数的程序要补档位说明 | 所有评分工具补"档位定义表"；数值旁附一句解释 |
| G5 | 大模型不擅长生数字 → **价位一律用固定工具回填**（算法 / 规则 / 数据）；没有就造；**程序回填 + 单调性夹逼是现有做得最好的一环，保留复用** | fill_entry_exit 升格为公共价位工具 |
| G6 | **程序选股的流程不适合作选股器**（72 只太多、51% 胜率无意义、前排效果差），但**程序内容可作工具借鉴**；数值表述 / 概念 / 程度 / 口径要统一 | 程序线降为"工具提供者"（召回 / 回填 / veto），不再当选股器 |
| G7 | **金字塔选股是独立流程**，不基于别家产出；定好自己的输入 / 输出 / 参考；做完再与三方比；预期**比他们更全**（集百家之长，最宏观视角） | 不得再"取 agent 共识"当塔尖 |
| G8 | **输出硬约束 = 5~6 只 = 2~3 建议买入（最重要）+ 2~3 规避**；规避用于调模型 / 防踏空 / 验稳健，来源 = 板块 / 市场行情 / 国际局势；**两端都要重视** | 收敛必须落到 N=5~6，且规避要标"来源类别" |
| G9 | 选股来源两种：**策略最多命中** / **特定板块**；先技术面筛到 10~50 只，再按时间预算逐票研判（不是 5000 只） | 两源召回 → 技术面粗筛 → 逐票 SOP |
| G10 | 未使用的数据两种用法：**程序性硬筛**（用程序卡）/ **浓缩成文字**（带评级必附概念说明） | 每个未用维度二选一落地 |
| G11 | A线（经验 + SOP 逐票研判）是**可采纳的高端模式**；Agent（DeepSeek / 千问）选股 **强于程序选股** | 金字塔以 A线 研判骨架为主体；Agent 作并行对照与"补主线"信号 |
| G12 | **复盘全由 Claude Code 做**；目的 = 总结经验、分析，可调整**策略 / 输出 / 工具定义 / 口径**；**复盘本身是产出** | 闭环复盘是三大产出之一，不是附属 |

## 2. 需求明细（用户要什么，逐条）

### 2.1 分析类
- **N1** 整理 A线 (a) 经验逐票研判的**具体过程**；(b) **积累了哪些经验**；(c) **13 版每日迭代逐条分类**：属"选股经验迭代"还是"策略调整（组合 / 参数）"。
- **N2** 对比三种流程（自选股 / Agent / 定时任务）：优势、劣势、哪些做不到、谁缺少什么、谁补充的信息更多。
- **N3** **基石全部提取、全部用上**（用户列：策略组合 / 策略参数 / 新闻叙事 / 财报 / 国际形势 / 板块分析；统筹补：大盘预测 β·capitulation / 资金流向 / 筹码·龙虎·供给面 / 经验沉淀 / 技术面·形态 / 价位回填 / α 基准）。
- **N4** 收敛机制：评判哪个更好（现状：人脑不合理，程序 72 只更不合理）。
- **N5** A线 **全史**战绩统计（不看一天）；**模式评价**：好的怎么好、坏的怎么坏、给预判。
- **N6** 统计 A线 每日研判票数；估算**加入板块优劣分析**后调用量 / 时间增量；可加则加，不可则优化。
- **N7** **全部数据维度的输入输出要清楚**（不清楚就调研）。

### 2.2 产出类
- **N8** **输出明细**（此前缺）：每条买入 / 规避条目必须含什么（见 §6.2）。
- **N9** 价位估算走工具（复用程序回填 + 单调性）。
- **N10** 产出格式**瞄准定时任务**：市场情况说明（含**国际新闻对市场影响、资金流向判断、板块判断**）→ 选股 → 逐条研判。
- **N11** 三方对照：**命名清晰**；**9-17 三方都要有产出**（缺的让 sub agent 补跑）；落 `每日分析/选股/`，文件名带日期尾缀。
- **N12** 金字塔**独立**产出一份，再与三方比；思考过程**标注基石来源与贡献度**；**驱动提示词**明确"怎么考虑、怎么参考"，参考定时任务 SOP，**列几版方案试跑择优定稿**。

### 2.3 三大产出物（用户定义）
- **D1 工具搭建**：为 Agent 定义工具、设计自定义工具（程序或其他形式），所有工具产出为选股服务、浓缩且带解释。
- **D2 金字塔定时任务**：与现有定时任务**并行**的新定时任务；每日 Claude Code / DeepSeek / 千问 **各出一份**金字塔选股报告；首轮后对比；基础数据 / 整理 / 规范由工具固定、三方共用。
- **D3 闭环复盘**：Claude Code 做统筹分析与复盘（不需过度定向）；输出经验总结与调整建议（策略 / 输出 / 工具定义 / 口径）；复盘本身是每日产出。

### 2.4 文件与流程约束
- 选股 → `docs/每日分析/选股/`；复盘 → `docs/每日分析/复盘/`；命名 = 日期 + 来源 + 策略标注；合 main + push + 本地拉最新。
- 看板持续登记；需拍板的在对话里定；严谨、不糊弄、不了了之。

## 6. 三大产出物定义

### 6.1 D1 工具搭建（基础层）
1. **工具注册表**：把全部基石做成 Agent 可发现的工具（名称 / 输入 / 浓缩产出格式 / 口径 / 更新时点），支持直接调用与 CLI 两种方式。
2. **浓缩 + 解释化**：每个工具产出 = 结构化字段 + 一句解释；**所有评分附档位定义表**（如 0-2 / 3-5 / 6-8 / 9-10 各代表什么）；统一概念 / 程度 / 口径用词。
3. **补现有只出分的程序**：council 综合分、策略视图分、板块强弱等，全部补"分数段含义"。
4. **造缺的工具**：外围宏观 regime（agent_macro + **一手源事实校验闸门**）、α 基准 market_ew、资金流向浓缩、板块优劣浓缩、经验规则清单工具、公共价位回填（复用 fill_entry_exit）。
5. **未使用数据落地**：每维二选一——程序硬筛 / 浓缩文字。

### 6.2 D2 金字塔定时任务（流程层）
**流程**：市场定调（国内 β + **外围宏观** + **资金流向** + **板块优劣**）→ 两源召回（策略最多命中 / 特定板块）→ 技术面粗筛到 10~50 → 经验 + SOP 逐票研判（时间预算）→ 收敛 **2~3 买入 + 2~3 规避** → 价位工具回填 → 报告（来源标注 + 贡献度）。

**输出明细（每条必含）**：
| 买入条目 | 规避条目 |
|---|---|
| 代码/名称 · 建议档(买入/可参与) · 入场方式 · **挂单价 / 止损价 / 不追高上限（工具回填）** · 触发闸门（放量收阳 / gap-fade 限价 / 条件式） · 退出纪律（第几天 / 什么条件走） · **基石来源与贡献度**（哪几维支撑） · 消息面 / 财报 / 供给面一句 · 风险 | 代码/名称 · **规避来源类别**（板块 / 市场行情 / 国际局势 / 个票雷） · 规避判据（数据 + 解释） · 若被证伪如何反馈调模型 · 观察触发条件（何时可重评） |

**三方每日**：Claude Code / DeepSeek / 千问 各读同一工具集出报告 → `每日分析/选股/<日>_金字塔_{ClaudeCode,deepseek,qwen}.md`；对照表。
**提示词**：参考定时任务 SOP，明确"怎么考虑、怎么参考、来源标注"；**列 2~3 版试跑，择优定稿**。
**挂定时**：与现有定时任务并行，名"金字塔定时任务"。

### 6.3 D3 闭环复盘（反馈层）
- 每日 Claude Code 复盘：D+1 绝对收益 + α（market_ew 修好后）+ **规避票是否真避损**；总结经验、分析归因。
- 可反向调整：策略 / 输出格式 / 工具定义 / 口径 → 形成变更记录。
- 落 `每日分析/复盘/<日>_金字塔复盘.md`；复盘本身是产出。
- 首轮基线：A线 13 天全史统计 + 模式评价（A2）。

## 10. 拍板记录（2026-09-18 晨，用户拍板）

| # | 决策 | 结果 | 设计含义 |
|---|---|---|---|
| ① | "2~3 买入"定义 | **(b) 每天必须真买 2~3 只**。理由：大盘再差每天也有上涨的票，选不出=流程失职；闸门不能死到天天空仓、"选了跟没选一样" | **D2 收敛机制改写**（见下） |
| ② | 观望档 | **取消**，只保 买入 / 规避 | 输出两端 |
| ③ | 回踩限价 | **降为闸门开后加仓口径**，不作首入场 | 首入场=D+1 开盘附近限价（工具回填） |
| ④ | D1 缺口工具优先序 | 统筹在 D1 稿排定 | — |
| ⑤ | 宏观产线化 | 09-18 午后连 Agent 隔夜收益一起定 | — |

**D2 收敛机制（据 ① 改写）**：
1. 闸门**不再是"等 D+1 确认才买"的条件**，而是**作用于 D 当日已实现 bar 的质量判据**（放量收阳 / 站上均线或前高 / 量比 / 不接近涨停 / 排雷通过）。A2 证据：13 天赢票是"D 已强、D+1 不回踩"型。
2. 闸门作用于**广度共享池（50+ 只）**而非 3~5 只 shortlist——A2 的 19% 开闸率 × 50+ ≈ 10 只过闸，足以取 2~3。**吞吐靠广度补，不靠放低闸门。**
3. **分层闸门保底**：T1 严格（量能+催化+排雷全过）→ T2 标准 → T3 最低；按层取满 2~3 只，**产出标注层级**，D3 记分**按层拆开复盘**（诚实：弱市日的 T3 买入与强市日的 T1 买入不混算）。
4. 排序按**量价自证**（非 LLM 建议分）；LLM 只做否决（假利好/情绪票/供给面）与解释。
5. 入场：D+1 **开盘附近限价**（工具回填挂单/止损/不追高上限；A2 显示盲目开盘市价 −2.40% 最差、限价近开盘为宜）；**回踩限价=加仓**。
6. 规避 2~3 只：来自 排雷 / 极高位 / 情绪票 / 板块-市场-国际 风险，**标注来源类别**。

**诚实边界**：(b) + D 当日闸门 + D+1 入场 是**待 forward 验证的假设**——强势旁路回测（无闸门裸追）为负，A2（有闸门后跟进）为正，二者口径不同；D3 按层级记分即为验证设计。

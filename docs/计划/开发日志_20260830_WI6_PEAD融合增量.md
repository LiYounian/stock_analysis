# 开发日志 · 2026-08-30 · WI-6 Phase 1-a:PEAD 消息面层对技术候选池的净增量回测

> 分支 `feat/wi6-pead-fusion`(内容窗口·线 wi6-pead)。**纯回测验证,未动任何生产采集/策略逻辑/strategy.json**。
> 承 WI-6 定论:纯技术面扣成本≈市场,净收益唯一出路 = 消息面正交增量层叠加到技术候选池。
> PEAD/业绩预告是"成色最好、且唯一可严谨历史回测(有真实公告日、防未来函数红线完整)"的消息代理。
> 本轮用"可历史回测"纪律,先证明(或证伪)PEAD 层对技术候选池加不加净增量,**达标才谈接生产**。

## 一、做了什么

- **新模块** `tools/backtest/pead_fusion_lab.py`:
  - **① PEAD 事件表(公告日锚定)** `fetch_pead_events`:akshare `stock_yjyg_em(报告期)` 拉 32 个报告期
    (20180930~20260630,覆盖面板全跨度),锁归母净利润主口径,每 (报告期,code) 取**最早披露日**,
    方向分档 正(+1)/实质利空(−1)/未知(0)。缓存到本会话 scratch,不污染项目 store。
    共 **49243 事件 / 714 个面板票命中 / 公告日 2018-07~2026-08**。
  - **② as-of 挂载** `attach_pead`:面板每行 (code, T) 只认**公告日 ≤ T 且在 lookback 自然日内**的
    最近一条预告方向(防未来函数红线;lookback 默认 90,并测 30/60 敏感性)。
  - **③ 技术候选池**:复用 `fusion_lab` 的技术面板 `fusion_panel.parquet`(**与 eval_v3/fusion_lab
    同面板同口径**,76017 行 / 1618 交易日 / 739 票 / 2019-01~2026-08)。两个技术评分器:
    `fusion_F3`(全量融合分,WI-6 融合基线主线)+ `council_V2`(删趋势合议,存活合议基线)。
  - **④ 两种用法**:**veto 断点**(技术 Top-N 剔除实质利空、补进下一名,仍取 N)/ **tilt 加权**
    (`z(技术分)+w·z(pead_dir)` 重排取 Top-N,w∈{0.5,1.0})。每腿 vs 全宇宙 gross/net(扣往返
    0.1%/0.2%)超额 + 按日聚类 p;**增量** = (叠 PEAD 腿)−(纯技术腿),**按日配对聚类 bootstrap** 出
    增量点估计 + p(复用 `eval_v3.stats.cluster_bootstrap_excess`)。同 N、同市场基准、同交易日 →
    增量归因干净(只差 PEAD 一层)。
  - **④b 独立预测力诊断** `diagnose_standalone`:面板内直接看 PEAD 方向对 fwd5 的独立 rank-IC +
    正/负/无三组 fwd5 均值,判别"增量为零"是'PEAD 本身在本样本没 edge'还是'被技术层吃掉'。
- **单测** `tests/test_pead_fusion_lab.py`(7 项,全绿)锁死:公告日>信号日不泄漏(防未来函数红线)、
  lookback 窗剔除陈旧预告、as-of 取最近、方向分档、veto/tilt 同 N 同基准(apples-to-apples)、
  veto 确实挤掉利空。
- **预注册达标判据**:叠 PEAD 后**净超额有显著正增量(聚类 p<0.1)**才算"消息面层有价值"。

## 二、结论:**不达标** —— PEAD 层对技术候选池不加净增量,tilt 甚至常显著为负

预注册判据在 **全部 24 个配置**(3 lookback × 2 评分器 × 2 TopN × 2 用法)里**无一命中**;
多个配置的增量**显著为负**。核心读数(fusion_F3 主线,Top10):

| lookback | 纯技术 net20 超额 | veto 增量(减技术) | tilt 增量(减技术) | PEAD 独立诊断(正−负 fwd5 / rank-IC / p) |
|---|---|---|---|---|
| 90 | −0.093%(p0.086) | −0.014%(p0.605) | −0.040%(p0.125) | +0.13% / IC=0.012 / p0.59 |
| 60 | — | ~0(p>0.8) | 负 | −0.27% / IC=−0.011 / p0.68 |
| 30 | — | **−0.033%(p0.031)** | ~0 | **−0.54%** / IC=−0.014 / p0.67 |

council_V2 同向:veto 增量≈0(p0.87),**tilt 增量显著为负**(lb90 w=0.5 增量=−0.089%,**p0.004**)。

**根因(独立诊断给的干净解释)**:PEAD 超预期方向在本技术面板里**本身没有前瞻 5 日 edge**——
rank-IC ≈ ±0.01、p≈0.6~0.7(不显著),且**短 lookback 下符号是反的**:lb=30 时"实质利空"票
后续 5 日反而**跑赢**(+1.43% vs 正超预期 +0.88%)。这正是本仓库既往 S01/箱体3 反复撞到的
**dead-cat bounce / 追高见光死**——短横线上超跌反弹主导,利空票的见光短期反弹,使 veto 掉它们
**反而伤收益**(lb30 Top10 veto 增量显著负 p0.007~0.031)。

**与 `backtest_pead` 漂移发现不矛盾**:`backtest_pead` 在公告次日 t+1 **新鲜进场**、从进场测 5/10/20 日
漂移;本轨是问"在技术信号日 T(公告后 0~lookback 天的任意点)叠 PEAD 方向,对**技术排序**加不加
**正交**增量"——这是高得多的判据(要正交于技术、且穿越 T 到公告的时滞)。新鲜漂移被稀释 + 与
技术信号(本就偏超跌反转)相关而非正交 → 无净增量。

## 三、处置:**不接生产**(严守"②不达标就不动 event_driven.py")

- 任务③(把公告日贯通生产采集 `event_driven.py`)**被②的达标门槛 gate 掉,本轮不做**。
  `collectors/event_driven.py` 保持原样(仍只留报告期、丢公告日)。断点结论:PEAD-as-of 的
  veto/tilt 在"技术候选池 + 扣成本 + 按日聚类"口径下**不产生显著正增量**,不足以支撑接生产成本。
- **不硬上**:诚实报"PEAD 增量不显著/短窗为负",不做参数捞针式过拟合。

## 四、未完成 / 假设 / 后续可能方向

- 面板是 739 票抽样、信号日按 step=15 采(非公告日),故多数活跃-PEAD 行在公告后数周才测收益,
  漂移被稀释;这是"技术候选池增量"问题的固有口径,不是 bug。

  新鲜进场 + 技术面做**入场择时/过滤**(反过来:技术当 PEAD 的过滤器),这与本轨"技术当主、PEAD 当
  增量"正好相反,且需要事件轨面板(非本面板)。本轮不展开。
- 复现:`python -m tools.backtest.pead_fusion_lab run --lookback 90`(事件缓存在会话 scratch;
  结果 JSON `data/analysis/backtest/pead_fusion_lb{30,90}.json`)。

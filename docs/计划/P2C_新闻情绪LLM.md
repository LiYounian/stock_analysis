> 状态:**需求已定,待实现** · 分支 `feat/P2C-news-llm` · 编写 2026-08-06
> 依赖:P4.0 LLM 客户端(deepseek-v4-pro)已就位。
> 本文按用户 LLM 工作法组织:①需求 ②LLM 输入输出(JSON+中间过程) ③提示词(下一步) ④测试。

---

## 1. 需求(实现什么 / 解决什么问题 / 怎么实现)

### 要实现的功能
1. **个股新闻采集**:拉每只票近期新闻(标题+正文)。
2. **L1 关键信息提取**:用 LLM 从新闻正文抽结构化事件(类型/主体/数字/时间/影响方向/强度/与本股关系)。
3. **事件三层分类**:把新闻+公告统一归入 **政策 / 公司行为 / 舆情** 三层,判影响方向与强度。
4. **L2 情感聚合**:把单股多条事件聚合成情绪分(净利好/利空)。
5. **接入产出**:写入 serialize 的 `sentiment` 块 + Web 新闻页/个股页显示真正的"新闻→利好利空"。

### 解决的问题
- 现新闻页只有**公告(公司行为)**,缺**新闻正文级**的利好利空判定 —— 用户核心诉求"从新闻提取关键信息"。
- 超买超卖只有数据指标面,缺**情绪面**维度。
- 打标目前是关键词规则(约 49% 归"其他"),LLM 可做正文级语义判定。

### 怎么实现(模块与数据流)
```
collectors/news.py  ──►  data/raw/news/{code}.json(原始新闻,中间过程保留)
        │
        ▼  (LLM: tools/llm.get_client)
analysis/event.py   ──►  data/analysis/sentiment/{code}.json(抽取+分类+情感,过程结果保留)
        │                 + data/raw/llm_cache/{hash}.json(按内容缓存,改下游免重复调用)
        ▼
serialize 的 sentiment 块  ──►  Web 新闻页/个股页
```
- 新闻采集:akshare `stock_news_em`,调用前 `pd.set_option('future.infer_string', False)` 绕 pandas 3.0 pyarrow 正则冲突(已实测通)。
- LLM 不可用时**降级**:sentiment 标 `unknown`,数据层不受影响(约法第 5 条)。

## 2. LLM 输入 / 输出(全 JSON,中间过程可追溯可重跑)

### L1 · 新闻关键信息提取
- **输入**:单条新闻 `{标题, 正文, 来源, 时间, 目标股票名, 目标代码}`
- **输出 JSON**:
  ```json
  {
    "事件类型": "业绩/政策/合作/诉讼/产品/人事/市场传闻/其他",
    "涉及主体": ["..."],
    "关键数字": ["如 营收+30%、中标5亿"],
    "时间": "YYYY-MM-DD 或 相对时间",
    "影响方向": "利好/利空/中性",
    "影响强度": 1,
    "与本股关系": "直接/间接/无关",
    "摘要": "一句话"
  }
  ```
- **强度**:1(弱)~5(强);**与本股关系**用于过滤蹭词噪声(新闻提到代码≠与该股相关)。

### 事件三层分类(新闻+公告统一)
- **输入**:抽取后的事件 + 目标股票行业
- **输出 JSON**:`{"层": "政策/公司行为/舆情", "标签": "...", "影响方向": "利好/利空/中性", "影响强度": 1}`

### L2 · 单股情感聚合(代码算,不走 LLM)
- **输入**:该股全部事件的 `{影响方向, 影响强度, 与本股关系}`
- **输出 JSON**:`{"净情绪分": 0.0, "利好数": 0, "利空数": 0, "样本数": 0, "主要事件": [...]}`
  - 净情绪分 = Σ(方向符号×强度×关系权重) 归一化到 -1~1。

### 输出与中间过程约定
- **全 JSON**;LLM 解析失败**重试**,超次数标 `error` 不静默(约法第 5 条)。
- **中间过程文件保留**:原始新闻 `data/raw/news/`、抽取结果 `data/analysis/sentiment/`、LLM 原始回复缓存 `data/raw/llm_cache/`(按 输入内容 hash)。→ 可审计、可重跑、改下游不重复烧钱。

## 3. 提示词(下一步实现,与本文档字段一一对应)
- `tools/llm/prompts.py`:L1 抽取指令 + 三层分类指令,schema 直接引用上面 §2 的 JSON 字段。
- 写法:描述性约束(只抄原文、禁编造、拿不准留空/标中性)、强制 JSON、给全字段 schema。

## 4. 测试(实现后)
- 编造新闻(明确利好/利空/无关蹭词)验证:抽取字段完整、影响方向在合法集、"与本股关系"能识别蹭词。
- 真实新闻抽 2~3 条人工核对。
- 缓存命中(同输入不重复调 LLM)、LLM 不可用降级(标 unknown 不崩)。

## 6. 决策留痕(自主)
- 新闻源:东财 stock_news_em(pandas 兼容处理);政策/UGC 留后续(WebSearch/浏览器)。
- L2 情感用代码聚合而非 LLM(省调用;方向/强度已由 L1 给出)。
- 缓存按输入 hash,保证可重跑与成本可控。

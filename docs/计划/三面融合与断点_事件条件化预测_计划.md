> 一句话：技术指标有天生滞后性;当股票**大涨大跌** / **涨跌背离技术预测** / **技术指标反常(RSI-MACD背离等)**、且能归因到**外部消息**(时政/国际/公司行为)时,在该股时间线打一个**"断点/插入点"**,表示"旧的技术规律在此失效"——**技术反常与消息互为异源佐证**,并**独立叠加一层事件修正** + 前向累积验证。非投资建议。

## 〇、定位与三条硬约束(先读,决定本轮做多深)

**用户已拍板定位(2026-08-23)**:
- **断点雄心 = 解释 + 风控 + 前向累积验证**(不主张预测 alpha;断点先作"事件驱动、技术面暂失效"的风控标记 + 每日 forward_scorecard 式前向累积样本,几个月后再用累积样本验证)。
- **动作形态 = 独立叠加事件修正层**(技术预测不动,断点时叠加/覆盖一个"事件驱动"状态;可解释、可开关、可单独回测有无断点的差异)。

**三条硬约束(调研已证,写进验收前提,避免做出经不起验证的东西)**:

1. **消息面历史回测结论基本全负**(项目自测):PEAD 见光死无漂移;净情绪分 IC 不显著**且方向逆**(滞后非领先);持续性方向对但样本薄不显著。**唯一有一线希望的是「消息持续性」**(结构性利好 60 日拿得住)。
   - 证据:`docs/计划/消息面影响与可回测性_调研方案.md §5`、`PEAD与根源消息信号_预注册与执行.md §4.1`、`消息持续性分类_预注册与执行.md §5`。
   - → **设计含义**:不做"消息=方向预测器";断点的可信钩子是 `news_persistence` 的**结构性 vs 短暂**区分——**短暂消息=见光死,不打断点;结构性消息=才可能重估技术预测**。
2. **消息时间戳是"信号日当天采集"快照,非真实发生时刻;历史新闻补不回来**(新闻 API 仅约一周窗口)。
   - 证据:`tools/backtest/attribution_news.py:8-10` 及 doc §5.3。
   - → **设计含义**:"在消息发生处打断点"的历史标注/回测**先天受限**;断点历史回测只能落在**有 record 的窗口(约 2026-08-06 起)**,或改走 **forward_scorecard 式前向累积**(今天标、往后攒)。
3. **当前样本统计力 ≈ 0**(约 08-06 起数百条 record)。→ 近期任何预测力主张**测不动**,只能出方向性结论。

**总基调**:断点这件事**理论对、架构支持、但"证明能赚钱"当前无数据支撑**。故本轮**只做到"标注 + 风控 + 前向累积 + 独立修正层"**,预测力留给累积样本后验。**允许并预期"暂无显著 edge"的诚实结论。**

## 一、原始需求(用户原话,忠实转述)

- 「技术指标有明显滞后性;股票受情绪/消息影响很大,我们项目能分析消息面影响。」
- 「出现两种情况应关联并收集消息层面数据:①股票大涨大跌;②涨跌不符合我们的预测。」
- 「若确实是外部消息(国际形势/时政/公司行为)导致,我们的指标是不是该在这里打一个『断点』(自造词,可看作『插入点』)——没人干预时数据应遵旧规律,时政消息一来规律就变了。这种情况能不能利用?有没有好策略?」
- 「每天有新消息监控;对已加入监控的自选/预选股,若监控到重大利好/利空,是不是也可以在技术指标上做调整——增加变量值、甚至改权重,按利好利空来走。」
- 「希望发挥技术面、情绪面、消息面结合的优势,这是重点。」
- (2026-08-23 追加)「传统技术指标(KDJ 钝化/交叉、RSI 背离等)有滞后性和通病;违背原有规律的现象,很可能是政策/新闻层面利空利好导致。可以找几只股票 + 相关新闻验证;之后使用时也要结合新闻——**若相关新闻导致了变革点,则技术指标的背离/反常状况可作为佐证和支撑**。」

> **验证可行性约束(须知)**:"找历史股票 + 历史新闻回验"受**约束2**(消息时间戳=采集日快照、历史新闻补不回,新闻 API 仅约一周窗口)限制——历史回验先天不可得。可行验证 = ①近窗口/前向(约一周内技术反常 + 当前新闻)②record 窗口(约 08-06 起,当时已采 sentiment)③公开市场史定性举例(仅说明机制,非我们数据、非投资建议)。严谨验证走 G7 前向累积。

## 二、要实现哪些功能(可验收的功能点)

- [ ] **G1 · 异动探测器(条件①「大涨大跌」)**:新建统一小模块,把散落各 screener 的不一致阈值(-0.04/0.05/0.06/0.10/0.20)收敛为**「异动 flag + 可配阈值」**(如 |涨跌|>k×ATR 或 触涨跌停)。数据原料 `pct_chg` 已在 `technical.py:132`/`market.py:56`。
  - 验收:单模块产出 `异动{flag, 方向, 幅度, 触发阈值}`;阈值来自 THRESHOLDS 新增「断点」块;单测锁阈值口径。
- [ ] **G2 · 预测偏离比对器(条件②「涨跌不符预测」)**:把 `backtest_predict._coverage`(r_N 落在 [q7,q93] 外)的度量**升格为 live**——读昨日 `record[prediction]` 的分位带 vs 今日实际 bar,产出**「区间外 surprise{方向, 偏离 pp}」**。
  - 验收:live 逐日比对可复现;与批量回测口径一致;严格无未来函数(只用昨日已落盘预测 + 今日已收盘实际)。
- [ ] **G2b · 技术背离/反常探测(条件③,用户 2026-08-23 追加)**:把文档1 F2b 的**技术反常信号**(RSI/MACD 顶底背离、KDJ 高位死叉/钝化拐头、放量跌破 MA20/前高)聚为**「技术反常 flag{类型, 方向}」**。**只用 ≤t 数据、纯函数**;直接复用文档1 F2b 的状态输出,不重算。
  - 验收:构造样本反常标签正确;与文档1 F2b 口径一致(单一真源,不重复实现)。
- [ ] **G3 · 断点判定 + 归因(技术×消息互为佐证)**:断点 flag =(**G1 异动** OR **G2 区间外/方向未命中** OR **G2b 技术反常**)**∧ 有根源消息**。归因用 `news_persistence.classify`(结构性/短暂)+ `attribution_news._classify_event`(预定型/突发型)。
  - **互证逻辑(用户核心洞察)**:技术反常与消息是**真正异源**的两路证据(绕开"通病6 同源伪独立")——**技术反常 + 同期重大消息共振 → 高置信断点**;单有其一 → 低置信/仅标记。置信度分档进 `断点{置信度}`。
  - 判据:**短暂事件 → 不打断点**(见光死);**结构性事件 → 打断点**(旧规律可能失效)。**背离信号本身只作"佐证/警告",不单独定买卖**(背离可长期持续)。
  - 验收:断点判定纯函数、无未来函数;输出 `断点{是否, 置信度, 触发源(①/②/③), 消息类型(结构性/短暂), 方向, 印证强度, 依据}`。
- [ ] **G4 · 事件条件化采集(按需触发)**:断点条件命中 → **立刻去采该股当日消息**(复用 `news_recall.recall_related` 单票召回 + LLM 初筛),在 `run.py:139-152 collect_message` 插入**条件触发分支**(现为无条件全池)。
  - 验收:仅对命中票触发采集;不改全池常规采集;采集结果并入 record.sentiment。
- [ ] **G5 · 独立叠加事件修正层(动作形态=用户拍板)**:**不改**技术预测(`predict.scenarios`/条件化预测),而是在断点时**叠加一个「事件驱动」状态块**:标注"技术面暂失效",给出事件方向倾向(仅当结构性)+ 一个**可开关**的修正视图(如把方向标记为"事件驱动·看多/看空/待定")。
  - 验收:关掉开关时 predict 输出与无断点完全一致(可回归对齐);开着时 record 新增 `事件修正` 块;不污染原技术预测字段。
- [ ] **G6 · 断点落库 + 前向累积**:断点/异动/偏离 flag 经 `serialize.py` 落 record(新增块)+ 接入 `forward_scorecard.py:118-171`(它已是唯一"技术×情绪×消息×实际同居一行、幂等每日跑"的资产),**每日前向累积**断点样本 + 到期 r_N/hit。
  - 验收:每日跑后断点样本按日期分区累积;可查"断点日之后 N 日实际漂移";幂等重跑不重复。
- [ ] **G7 · 断点有效性回测(诚实结论)**:复用 `event_study.forward_returns`(断点日当 event_date,锚+漂移+alpha)+ `screen_forward_common` 双基准/regime 分层/pick_test_days + 聚类 t 检验。对比**「打断点修正 vs 不打断点」**的预测校准 / 前瞻收益 / alpha。
  - 验收:产出报告 `docs/计划/回测报告_三面融合断点_YYYYMMDD.md`,**如实回填**(含"当前样本不足、仅方向性"或"某类结构性消息有效"的诚实结论);受约束2/3,明确标注样本窗口与统计力。

## 五、验收 / 测试标准

### 预期效果(做完后应看到的现象)

- record 新增「断点」+「事件修正」块;web 能展示断点标记(触发源/消息类型/方向)+"事件驱动、技术面暂失效"视图,可开关。
- 每日跑后断点样本前向累积;`forward_scorecard` 可查断点后 N 日实际漂移。
- G7 回测框架搭好,能对比"有无断点修正"的校准/收益/alpha。

### 成功 / 失败判据(诚实,允许"暂无 edge")

- 🟢 **框架级成功(本轮主目标)**:断点触发/归因/修正/落库/前向累积/回测框架全部无未来函数跑通;开关关闭时与无断点 100% 等价;断点样本按日累积可查。
- 🟡 **信号级(有样本才评)**:在可得窗口内,**结构性断点**后的方向漂移 / alpha 若显示正向倾向(即便不显著),如实记录为"方向性线索,待样本";**短暂断点**应表现为"见光死"(印证约束1)。
- 🔴 **照实写**:若断点修正相对无断点**无改善**,报告明确写"当前口径/样本下断点无预测增益",并给是否某类结构性消息例外。**不为交付美化。**

### 测试(锁"为什么改"的语义)

- `test_anomaly.py`:锁异动阈值口径(k×ATR / 涨跌停)、方向判定。
- `test_breakpoint.py`:锁 **短暂事件不打断点、结构性才打**;断点判定**无未来函数**(只用昨日预测+今日实际+当日消息);**事件修正开关关闭时 predict 输出与无断点逐字段等价**(回归对齐)。
- 回测断言:断点日无未来函数(event_date 锚定)、双基准 alpha + 聚类 t 口径一致;报告结论与数据一致。
- **B4【统筹定·防前视泄漏,硬前提】**:G7 断点历史回测**严格只用 record 窗口内已落盘的数据**;断点归因的 `news_persistence` 分类**只能用"信号日当天已采到"的新闻,绝不能用事后补采/回填的新闻**(约束2:消息时间戳是采集日快照)——否则历史回测混入未来信息,alpha 全是泡沫。测试须断言:回测输入的消息集 = 该日 record 已存的 sentiment/events,不触网、不二次补采。

## 八、回测设计与预期(预注册假设)

**回测方式(复用现成)**:G7 复用 `event_study.forward_returns`(断点日当 event_date,锚+漂移+alpha,windows=1/5/10/20)+ `screen_forward_common` 双基准/regime + 聚类 t;A/B = 打断点修正 vs 不打断点。

**硬约束(决定本轮能测到什么)**:

- **约束3**:record 仅 15 日、样本≈0 → 近期**统计力≈0**。

**我的预注册假设(诚实)**:

| 对象 | 我的预期 |
|---|---|
| 近期(本轮) | **无可证明的预测 edge**——只算**框架级成功**(触发/归因/修正/落库/前向累积/回测框架无未来函数跑通、开关关闭等价) |
| 结构性断点 | 几个月累积样本后,**或有方向漂移倾向**(持续性是唯一有希望的钩子);即便有也可能不显著,如实记录为"方向性线索" |
| 短暂断点 | 应表现为"**见光死**"(印证约束1 消息面回测偏负) |

> **诚实预判**:本轮是**延迟兑现的框架投资**,不承诺近期 payoff;预测力要靠前向累积几个月后才测得动。与趋势模板/SEPA 诚实口径一致。

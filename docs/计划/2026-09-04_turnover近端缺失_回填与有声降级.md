# turnover 近端整段缺失:数据层回填 + 下游有声降级(#20 / #21)

> 日期 2026-09-04　分支 `fix/turnover-backfill-and-loud-degrade`(基于 origin/main)

## 1. 现象(两处高 severity,同一根因)

- **#20 S04「单日放量」哑火**:2026-09-03 S04 入选 94 只,「单日放量」命中 0、94/94
  全 `换手=None`,子信号只剩 {低位放量, 连续放量}。
- **#21 chip 集中度失真**:`compute_distribution` 把 turnover NaN 当 `tr=0.0`(当日无新增
  筹码)→ 近端上涨段贡献零新筹码。实证 603161 集中度90 0.2286→0.1704(差 34%)。
- 两者都**静默**:`_has_turnover` 门是全历史 ≥50% 非空,近端 16/2100 缺失轻松通过 → 无告警。

## 2. 根因(实调 5552 只主档,非假设)

turnover 自 **2026-08-13**(2865 只)/ **2026-08-18**(2340 只)两波起整段 NaN,
`meta.source=fallback_advance`,**volume 全部在位**(5207/5211 缺失票 volume 完好)。

- 采集自那两日起走 `master_sync._fallback` → `_advance_master_from_raw` 回退路径,
  其主源(腾讯 fqkline)**不返回** amount/turnover。
- 本应补齐的安全网 `_enrich_turnover_amount`(baostock 换源补)是 best-effort、失败只记日志,
  **近端连续 ~16 个交易日静默失败** → turnover 落 NaN。
- ⇒ 根因是**采集没写**(回退源缺列 + 补齐网静默失败),**不是**某次重建丢近端。

## 3. 修法

### (2) 数据层回填 —— `ops/backfill_turnover.py`(dry-run→apply,仿 `fix_turnover_unit.py`)

方法:**volume ÷ 流通股**,流通股由**本票自身 gap 前的正常行**经恒等式自证:
`turnover% = 100 × volume / 流通股` ⇒ `turnover%/volume` 在流通股不变的窗口近似常数。
gap 仅 8–26 交易日,流通股稳定。**自证 0.00% 误差**:用 gap 前 ratio 重建 603161 的两根
baostock 补齐行(08-14=3.457 / 08-17=3.016),recon 误差 0.00%。

- 恒等式数学落在 turnover 单一真源 `tools/config/units.py`:新增
  `backfill_turnover_from_volume(df)`。逐 NaN 行取最近的未缺参考 ratio(仿
  `repair_turnover_unit` 的邻域法),ratio 稳定才回填;回填值已是百分数(参考取自百分数),
  **无口径二义**,契合 `MASTER_TURNOVER_UNIT=PERCENT`。volume 缺 / 无稳定参考 → refuse。
- ops:默认 dry-run 只报告恢复覆盖;`--apply` 逐票原子写 `store.put_master_kline`,
  保留 `meta.source`,补 `turnover_backfilled` 留痕。

### (3) 有声降级(数据补齐与否都要改)

- **chip.py**:`summarize` 统计窗口内 turnover 缺失行数 → 结果加 `换手缺失日`/`降级` 标记
  + `logger.warning`;`compute_distribution` 遇窗口内 NaN 行不再无声 `tr=0`,发一次 warning。
  覆盖率 <50% 仍 → None(不变)。
- **S04 `_single`**:换手 NaN 不再无声「不适用」,明细标 `降级:换手缺失`;`run_volume_screen`
  统计「单日放量因换手缺失降级」票数,写进 view + `logger.warning`,让 94/94 哑火变可见。

## 0. 问题与目标

**现状**：`daily-stock-noon-analysis`（午休 11:45）只对**盯盘集（前一交易日选出 ∪ 自选池，~19只）**做研判，SKILL 明写"不做全A重新选股（全A午盘选股需另建数据流水）"。→ 盘中全A里爆发的强势动量，午盘**无采集、无重筛、无法纳入尾盘买入候选**。

**目标**：让午盘能**重筛全A**、把盘中放量领涨的强势/动量票捞进**尾盘买入候选**（尾盘 14:30~14:57 入场，用回踩限价），补上"盘中动量踏空"这个洞。

## 1. 为什么现在够不着（数据流缺口）

| 环节 | 现状 | 缺口 |
|---|---|---|
| 午盘快照 | `T1145.json` 只冻结**盯盘集~19只** | 无**全A**午盘快照 |
| 策略视图 | 收盘闭环才算全A策略视图 | 午盘无全A策略重算 |
| 候选 | 午盘候选=盯盘集 | 无"午盘全A新捞"候选 |

## 2. 设计（复用不重造）

**数据流**（午休 11:35 触发，抢在 13:00 开盘前）：
1. **全A午盘快照**：`gtimg_quote.fetch_quotes` 批量拉全A ~5500 只午盘价/量比/换手（已有批量能力，实测全A ~20s 级）。冻结时点写盘（`data/intraday/<date>/T1145_full.json`），**防未来只用 ≤11:30 数据**。
2. **午盘轻量重筛**（在午盘快照上跑，非收盘口径）：复用现有筛引擎的**动量/突破/放量**维（`screen_*` 的可午盘化子集）——半日涨幅+量比+贴日内高+换手放大；**不含需收盘/闭环的维**（chip/fundflow/合议多源）。
3. **排序+过滤**：流动性门（成交额）+ **涨停不可买剔除**（午盘已封板的买不进）+ 与盯盘集去重。
4. **产出**：`日内_<date>.md` 增一节「**午盘全A新捞·强势候选**」+ 机读锚点；标"半日口径·provisional·尾盘复核"。

**倾向对齐**：用已纠偏的选股倾向（普跌日不反动量、强势票回踩限价参与、不追高开涨停）。

## 3. 硬约束（诚实）

- **速度/经济**（用户红线）：全A午盘快照+轻筛须**快**（分钟级）、不起长采集、不逐票 LLM（午盘只做量价筛，深研判留尾盘/次日）。
- **防未来**：只用 ≤11:30 冻结价；provisional 标记；绝不用午盘价当收盘。
- **涨停不可买**：午盘已涨停的票**不进可买候选**（够不着=不算数），只标"已封板·观察次日"。
- **不能严格历史回测**：项目无**历史全A午盘快照**（master 只有日线 OHLCV）→ 午盘重筛信号**无法 walk-forward 严格回测**。只能：① 日线 open→close 作**粗代理**探方向；② **forward-shadow 攒样本**（非 gating、尾盘模拟建仓记账 position_ledger、跟次日绝对收益）≥ 一段时间再考虑 live。**先证再改**：先 shadow、别直接进尾盘实盘建仓。

## 4. 分期

- **P1 数据流 + shadow**：全A午盘快照 + 轻量重筛 + advisory 落盘（non-gating）+ forward 记分（尾盘模拟建仓→次日绝对收益）。**不改 live 午盘 SKILL 的建仓行为**，只多产一节 advisory。
- **P2 gated 上线**：forward 证据显示"午盘全A新捞候选"次日绝对收益为正且稳 → 才把它接进尾盘买入候选（换线）。

## 5. 工作量（agent 视角）
- P1（快照+轻筛+advisory+记分+测试）：input ~70–110K / 3–4h。
- P2（gated 换线）：~30K / 1–2h + 用户确认。

## 缺口一:研发费用化 vs 资本化「注水」红旗

### 现状(事实)
- 数据:利润表 `研发费用`(当期费用化)、资产负债表 `开发支出`(资本化研发**存量**)均已采;现金流量表**无**「本期资本化研发」流量科目(已核 300750 等样本)。故只能用 **`开发支出 / 研发费用`** 作**粗代理**(比值偏高=把本应费用化的研发挂在资产上、虚增当期利润)。
- **医药生物已有成熟实现**:`医药生物.py` 专属红旗①「研发过度资本化」,阈值 `_HI_研发资本化比 = 3.0`(严重度=高),`_calibration.py` 已登记 metric `开发支出比研发费用`。
- 其余研发密集行业(电子/计算机/通信/机械设备/国防军工/电力设备/汽车)**尚无此红旗**——即缺口所在。

### 方案:把该红旗按行业差异**扩到**其余研发密集行业
- 复用医药同一代理与实现模式(各行业 `extra_flags` 里加一条,阈值为各行业**自己的**常量),不新造机制、不新造文件。
- `extra_flags(derived, structured)` 的 `structured` 即完整单期 raw(analyzer.py:250 传 `rec`),`开发支出`/`研发费用` 可直接取,无需改采集/落盘。

## 缺口二:塔身工具层档位透行业分位

### 现状(事实)
- `growth_quality_tool.py`:毛利率/净利率用 `_毛利率档`/`_净利率档`(**跨行业粗档**),负债率用 `_负债率档`(只标金融例外);均注「跨行业粗参考·精确需行业分位(B期)」。
- `valuation_tool.py`:PE 用 `_PE参考档`(跨市场粗档)、PB 用 `_PB档`;注「真估值看 PEG + 行业分位(B期)」。
- **底层 industry 引擎已算什么**:per-stock `financial` 块已带 `行业专家`(命中的申万一级 KEY)+ `five_dims`(按该行业 `dimension_specs()` 区间标定的 0~100 分)。其中 `dimension_specs()` 的**毛利率/资产负债率子区间是行业化的**(如电子毛利率区间 [10,55]、负债率反向 [75,30])。
- **关键辨析**:引擎**已算**的是「行业化**评分区间**」(dimension_specs 的 [0分端,100分端]),**不是**「同行业个股经验分位」。后者(如"本票毛利率在电子同行中排 p60")需当日**横截面**计算,引擎没算,`_calibration` 只在离线算过、未落 per-stock。

### 方案(分两块,范围诚实)

**(A) growth_quality 的毛利率 / 负债率 → 透传行业化区间定位(推荐,轻量)**
- 数据源:financial 块的 `行业专家` → `get_expert(KEY).dimension_specs()` 取该行业的毛利率/负债率子区间。
- 展示:把原「跨行业粗档」替换/并列为「**本行业[电子]内位置**」——即原始值在本行业区间中的位置(如毛利率30% 在电子[10,55] → 中偏低)。有行业专家用行业化定位;**无专家(通用兜底票)回退跨行业粗档**(行为不变)。
- **净利率**:实测 16 专家里仅 计算机/非银金融 的 `dimension_specs` 含净利率子指标,其余用毛利率不含净利率 → 净利率**默认维持跨行业粗档**(诚实标注),仅在有净利率子区间的行业透传,不硬造行业区间。银行的 specs 三者皆无(用 ROA/存贷比等),不适用本透传。
- 落地方式(2 选 1,请统筹拍):
  - **(ii) 推荐**:在 analyzer 算 financial 块时,把毛利率/负债率的「行业区间 + 位置 + 档」persist 进块的一个小子块 `行业分位`(引擎侧一次算好);growth_quality **纯透传**不重算,web 也可复用。符合"透传而非重算"。
  - (i) 备选:growth_quality 渲染时现 `get_expert().dimension_specs()`。改动更小但让工具依赖 industry 模块、且每次渲染重取。

**(B) valuation 的 PE / PB 行业分位 → 本轮建议不做(范围外)**
- 引擎**未算** PE/PB 的行业区间;要"本行业内 PE 位置"必须新建**当日全行业横截面** PE/PB 分布 = 新数据管线,属"重算/新采",与本任务"透传已算"矛盾,且是原计划的 **B 期**工作。
- 本轮建议:valuation **只加一句口径注**(指明 PE/PB 行业分位属 B 期、当前为跨市场粗档),**不落数据管线**。若统筹要在本轮做,需单列为独立子任务(工作量另估)。

### 待统筹拍板
1. 落地方式 **(ii) persist 行业分位子块**(推荐)vs (i) 工具侧现取?
2. valuation PE/PB 行业分位 **本轮不做、只加口径注**(推荐)是否同意?若要做请单列子任务。
3. 「本行业内位置」用 **dimension_specs 评分区间定位**(推荐,已算)vs 落经验分位(需离线 `_calibration` 分位固化为常量,较重)?

## 缺口三:扩财报覆盖(**重定性**:不是落盘缺口,是行业专家覆盖缺口)

### 排查事实(最新目录 data/analysis/2026-09-18/,558 只真个股)
- **落盘层 0 缺口**:558/558(100%)都有非空 `financial` 块;raw 全在(全历史 5565 代码有 raw);**无管线漏、无 raw 缺**。
- **真正缺口在块内深度**:命中 16 专家(行业专属五维/红旗)= **419 只(75.1%)**;`行业专家=null` 走**通用兜底**(仍算出通用 five_dims,非空块)= **139 只(24.9%)**。
- 139 只**全部**落在 16 专家**覆盖外**的 13 个申万一级:公用事业22 / 综合20 / 社会服务18 / 轻工制造14 / 建筑装饰14 / 建筑材料14 / 商贸零售12 / 纺织服饰8 / 环保5 / 钢铁4 / 石油石化3 / 煤炭3 / 农林牧渔2。`to_sw` 归一无失败样本。
- **代表票 000504(综合)**:raw 在、块已落、通用 five_dims 算出、`行业专家=null` —— 纯"行业未覆盖",不是数据缺。任务背景说的"000504 体检卡显糙"根因=**通用兜底口径**,不是没落盘。
- **附带发现(路由源打架,小量真实 bug)**:4 只(如 300725 药石科技,CXO/医药)`code_industry.json`=综合/商贸零售,但 disambiguate 的 `formal_sw`=医药卫生(更准)。主路由 `_industry_key` **两个源都不用**(只看 meta.industry→半导体池→board_of,全落空→通用兜底),导致本可命中医药专家的票漏路由。

### 方案(按"重定性"给,诚实不硬凑)
既然落盘无缺口,本缺口的正解是**分档处理行业专家覆盖 + 修一处路由源**,而非"补落盘":

1. **优化通用兜底展示(最高性价比,先做)**:体检卡对 `行业专家=null` 的票明确打标「综合/无行业专属口径,五维为通用测算」,避免"通用兜底"被误读成"数据缺失/显糙"。**改展示层,不改模型**。
2. **小修主路由回退(独立小改,建议本轮顺手做)**:`_industry_key` 在 meta.industry/半导体池/board_of 全落空时,回退用 disambiguate 已算的 `formal_sw`(或 code_industry.json),先救回那 4 只漏路由的医药票;并排查 code_industry 与 formal 源口径打架择一为准。不新增专家即小幅提命中率。**因 industry 是复用指纹一部分,改路由后下次 serialize 自动重算,无需手工 backfill。**
3. **分批加轻量专家(工作量另估,建议后续轮次)**:同质且票数大的优先——公用事业(22)/社会服务(18)/建筑装饰(14)/建筑材料(14)/商贸零售(12)约 80 只;周期小行业(钢铁/石化/煤炭/农林牧渔)可合并"周期资源"专家或后置;综合(20)本质控股杂业桶、内部异质,**建议明确接受通用兜底**(硬加专家=造假信号)。

### 待统筹拍板
1. 缺口三**本轮范围**:建议本轮只做 **①优化通用兜底展示 + ②修路由源回退**(低风险、当轮可完成);③加轻量专家单列后续轮次(约 80 只收益,但每个专家需标定=大工作量)。是否同意?
2. 若统筹要本轮加专家,请指定优先行业(建议公用事业先行),我另估 token/工时。

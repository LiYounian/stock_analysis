# 开发日志 2026-09-10 — 日更可靠性 A 级护栏(A1/A2/A3)

> 依据:诊断-market_forecast停更-2026-09-10.md §6(commit 7dffb65,分支 claude/bold-bhabha-080f7e)
> 的根因分级与分级方案。本轮只做 **A 级低风险护栏**,三项都不改调度拓扑、不碰 launchd plist、不动 `data/`。
> 分支 `fix/日更可靠性护栏-A级`(基于 origin/main),分步 commit,由统筹审核合并。

## 背景(根因回顾)

日更 `pull_refresh` 反复迟 / 某些天无产出,诊断分级出三条根因:

- **RC-1**(选股迟/15h 长轮):② 阶段 LLM 调用线性放大——本轮不治(属 B 级并发化)。
- **RC-2**(某些天整轮采集早崩→当天无产出):**① 单票多源采集无可靠超时上界**。
  `tencent` 显式 15s;但 `sina`(akshare 内部 `requests.get` 未传 timeout)、`eastmoney`
  (`timeout=None`)**均无上界**,`socket.setdefaulttimeout(10)` 对显式 `None` 不生效 →
  一只票 read 挂起就无限拖死整个采集阶段,直到被外部强杀。→ **A1 治**。
- **RC-3**(semaphore 泄漏)= 外部强杀次生症状。强杀来源含**电源/睡眠**(合盖/电池空闲睡)
  → **A2 治**;且强杀发生时旧锁 `mkdir+trap EXIT rmdir` 的 **trap 在 SIGKILL 下不执行 →
  锁残留 → 之后每个交易日永久跳过**(latent 大雷)→ **A3 治**。

## 本轮改动

### A1 单票单源采集硬超时看门狗 — `tools/collectors/market.py`

- 新增 `_call_with_watchdog(fn, timeout, *args)`:在 `ThreadPoolExecutor(1)` 里跑单源采集,
  `fut.result(timeout=)` 到点抛 `TimeoutError`,主线程立即返回换下一个源;`shutdown(wait=False)`
  不 join 挂起线程(否则 with 上下文退出会 join、又退化成无限等)。
- 新增 `_src_timeout()`:读 env `FETCH_SRC_TIMEOUT`,默认 **40s**(覆盖 tencent 内部两端点
  各 15s 的最坏串行 ~30s 再留余量,避免误抢在 tencent 自己换端点前超时)。
- 接入点:`_fetch_one_with_source`(A股逐只兜底,RC-2 主路径)与 `fetch_one_hk` 的多源
  fallback 循环——**只加超时上界,不改采集口径/源优先级**。
- 副作用界定:Python 线程不可强杀,超时后底层线程仍在后台跑完(bounded、极少发生),但主流程
  不再被它阻塞。
- **测试**(`tests/test_market.py`):
  - `test_watchdog_slow_source_skipped_不拖死整轮`:某源 sleep 30s(远超 0.3s 硬超时)→
    硬超时即跳过换 fallback,`fetch_one` <5s 返回、命中 sina、不返空。锁"超时即跳过、不拖死整轮"。
  - `test_watchdog_timeout_from_env_default`:超时可由 env 覆盖、缺省 40s。

### A2 caffeinate 包整轮 — 三 wrapper

- `pull_refresh.sh` / `strong_refresh.sh` / `intraday_screen.sh` 在主体前起
  `caffeinate -i -m -s -w "$$" &`:进程级防空闲/系统睡眠,随本进程退出自动结束。
- **仅进程级**,不改系统电源设置(`pmset`)、不碰 launchd plist。

### A3 锁陈旧检测 — 公共库 `ops/launchd/lib/lock.sh` + 三 wrapper 接线

- 新库 `acquire_lock_or_exit <lockdir> <log> [stale_sec]`:锁目录内写 `pid`+启动 `epoch`;
  抢锁失败时判持有者是否陈旧——① 进程已死(`kill -0` 失败)或 ② 超龄
  (`age ≥ STOCK_LOCK_STALE_SEC`,默认 6h)——陈旧则清理抢占重跑;**活且未超龄的实例绝不误抢**。
- 无 owner 文件的老残留:按锁目录年龄区分——宽限期(`STOCK_LOCK_MKDIR_GRACE` 默认 30s)内
  视为 mid-write 活实例不抢(闭 `mkdir → 写 owner` 的 TOCTOU 竞态),超宽限判老残留可抢占。
- trap 释放校验 `owner.pid == $$` 才 `rm`,不误删被别人抢占后重建的锁。
- 三 wrapper 锁段改 `source "$REPO/ops/launchd/lib/lock.sh"` → `acquire_lock_or_exit`;
  **lib 缺失(半部署态)退回旧 `mkdir` 锁不硬失败**。lock.sh 在 `$REPO`(每轮 reset 到
  origin/main)内,部署一次后其改进随 reset 自动流转。
- **测试**(`tests/test_lock.sh`,8 场景全过):空占并写 owner / 活实例不误抢 / 死持有者抢占 /
  超龄持有者抢占 / 老残留抢占 / 宽限期新锁不抢 / 释放只清自己的锁。

## ⚠️ 部署注意(交统筹/人工)

- **A2/A3 改的是 launchd wrapper,合 main 后不会自动部署到生产**(本项目部署卫生问题):
  需人工外科部署以下文件到 dailyjob worktree / 生产 wrapper 路径:

  - `ops/launchd/pull_refresh.sh` / `strong_refresh.sh` / `intraday_screen.sh`
- **不动 launchd plist、不改系统电源设置**。改 launchd 前按惯例先查 job 是否在跑。
- A1(`market.py`)是 python 代码,随 `$REPO` reset 到 origin/main 正常生效,无需外科部署。

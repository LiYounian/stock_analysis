# 盘中定时快照（流水线确定性节点 · T-slot 快照）

> 首次落地：2026-09-03。⚠️ 测试环境研究用，**非投资建议**；节点只读行情、不下单。
> 上游背景：[定时任务时序治理](定时任务时序治理.md) §3.1「治本」；节点分类依据：[分析师流水线设计](分析师流水线设计.md) §2.5「确定性节点（代码/工具）」。

---

## 1. 这是哪类节点、为什么必须是代码

**类型：确定性节点（代码/工具，不走 LLM）**。它在流水线里位于**所有判断节点之前**，只做一件事：
*在正确的时点，把当时的实时行情原样落盘*。

必须下沉到代码的理由（实测证据）：Claude 定时会话在桌面 App 非活动时**工具调用会被挂起**——
09-03 盘中核实任务 10:34 发出第一条命令、**13:50 才真正执行**（命令里 `date` 自己打印的时间即为证），
于是"10:30 早盘偏离核实"实际取的是 13:50 的数据，**早盘这一维根本没被检验**。
"准点取数"是可复现、零判断的事，交给 OS 级定时（launchd）+ 项目代码即可保证；
LLM 会话只负责读这份快照做判断，**时效性不再取决于会话何时醒**。

## 2. 输入 / 输出契约

**脚本**：`tools/pipeline/intraday_snapshot.py`（CLI：`python -m tools.pipeline.intraday_snapshot`）

### 输入

| 项 | 口径 | 来源实现 |
|---|---|---|
| 个股标的 | 上一交易日 `docs/每日分析/选股/<上一交易日>.md` 解析出的代码 **∪** 自选池（A 股部分）**∪** `--codes` | `parse_pick_codes()` / `tools.config.stock_pool.get_codes_by_market("A")` |
| 上一交易日 | 交易日历；日历不可用 → 回退"上一个工作日"并 WARNING | `tools.collectors.calendar.trading_dates` |
| 指数 | 上证 000001 / 深成 399001 / 创业板 399006 / 沪深300 000300 / 中证500 000905 | `INDEX_CODES` + `collectors.index.index_prefix` |
| 行情源 | 腾讯 `qt.gtimg.cn`（沪 sh / 深 sz / 北 bj 前缀，GBK，`~` 分隔） | `tools.collectors.gtimg_quote`（**与 web 盯盘共用同一份解析**） |

选股 md 是给人读的自由文本（代码在表格/标题/正文里出现，版式历史上不统一），所以解析**不猜版式**：
扫全文所有独立 6 位数字串，用离线全 A 代码表 `config/code_name.json` 过滤，并剔除指数代码。
宁多不漏——多抓一只只是多一条报价，漏抓则该票当天没有早盘快照。
自选池里的港股（`market=HK`）不在覆盖范围（gtimg 港股前缀不同），如需覆盖再单列。

### 输出

`data/intraday/<YYYY-MM-DD>/T<slot>.json`（`data/intraday/` 已 gitignore，纯滚存不入库）

```json
{
  "date": "2026-09-03", "slot": "1030",
  "captured_at": "2026-09-03T10:30:04+08:00",   // 真实抓取时刻(防未来函数的锚)
  "nominal_at":  "2026-09-03T10:30:00+08:00",   // slot 名义时刻;slot 非 HHMM → null
  "drift_seconds": 4,                            // captured_at − nominal_at,正=晚到;非 HHMM → null
  "codes":   {"002811": {"code","name","price","prev_close","open","high","low",
                          "volume","amount_wan","pct_chg","change","vol_ratio",
                          "turnover","amplitude","quote_time"}},
  "indices": {"000300": {"...同上", "alias": "沪深300"}},
  "errors":  [{"scope": "code|index", "code": "000021", "reason": "源方无数据(停牌/退市/代码异常)"}],
  "meta": {"source": "qt.gtimg.cn", "script_version": "1.0.0",
           "script": "tools.pipeline.intraday_snapshot",
           "targets": {"pick_date","pick_md","pick_codes","pool_codes_n","explicit_codes","total_n"},
           "index_codes": {...}, "codes_ok_n": 19, "codes_err_n": 0, "indices_ok_n": 5}
}
```

字段口径与项目现有快照对齐：`price/pct_chg/amount_wan` 同 web 盯盘，`open/high/low/volume/turnover`
同日线标准列名，`vol_ratio` 同 technical 的「量比」。**量比/换手照抄源方，不二次加工**。

### 不变式（下游可以依赖）

1. **文件存在 ⇒ 内容可用**：全部抓取失败时**不落文件**、进程退 1。下游只需判文件在不在。
2. **captured_at 是真实抓取时刻**，不是名义时刻；快照只含该时刻及之前的信息（防未来函数硬红线）。
3. **幂等**：同 slot 文件已存在 → 不覆盖、退 0；只有 `--force` 覆盖。定时与手动补跑不会互踩。
4. **多 slot 共存**：`T1030.json` / `T1400.json` / `Ttestrun.json` 互不影响。
5. **非交易日跳过**：脚本自己判交易日（launchd 只认周一~周五，节假日照样触发），跳过且退 0、不落文件。
6. **单票失败不影响整体**：只进 `errors`，其余票照落，退 0。

## 3. 定时安装与手动补跑

**定时**：`~/Library/LaunchAgents/com.stock.intraday.plist`
（周一~周五 10:30，`StartCalendarInterval` 五条 Weekday 字典；`WorkingDirectory` = 项目根；
plist 只作薄指针 → 仓库内 wrapper `ops/launchd/intraday_snapshot.sh`（与 `pull_refresh.sh`/`strong_refresh.sh` 同款约定：
REPO 由脚本位置推出不硬编用户名、`STOCK_PYTHON` 可覆盖、mkdir 原子单实例锁 + trap 释放、
自身日志 `~/.local/state/stock/intraday_snapshot.log`；plist stdout/stderr → `~/.local/state/stock/intraday.{out,err}.log`）

```bash
# 安装(由人执行)
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.stock.intraday.plist
launchctl print gui/$(id -u)/com.stock.intraday   # 核验已加载
```

> 机器在 10:30 处于睡眠 → launchd 唤醒后补跑一次，产出的 `drift_seconds` 会明显 > 0，下游据此判断能不能当"早盘"用。

**手动补跑 / 联调**：

```bash
PY=~/.conda/envs/stock_analysis/bin/python
$PY -m tools.pipeline.intraday_snapshot --slot 1030                 # 补跑今天 10:30 槽位(晚到会写进 drift)
$PY -m tools.pipeline.intraday_snapshot --slot 1400 --codes 002811,603270
$PY -m tools.pipeline.intraday_snapshot --slot 1030 --force         # 重抓覆盖
$PY -m tools.pipeline.intraday_snapshot --slot testrun              # 联调:名义时刻未知 → drift=null
```

**日志**：`logs/intraday_snapshot.log`（logger 命名空间 `pipeline.intraday_snapshot`；
采集层为 `collectors.gtimg_quote` / `collectors.retry`）。

**单测**：`tests/test_intraday_snapshot.py`（全 mock 网络）锁住上节 6 条不变式 + schema 齐全 + drift 计算。

## 5. 失败时下游怎么降级

节点的失败模式与下游（**盘中核实任务** = 主要消费者）的应对：

| 失败模式 | 现象 | 下游降级 |
|---|---|---|
| plist 未加载 / 已停用 | `data/intraday/<今天>/T1030.json` 不存在 | 退化为"用当前实时价核实"，并在产出**显式标注"早盘维度未检验"**——不得假装检验过 |
| 10:30 机器睡眠、唤醒后补跑 | 文件存在但 `drift_seconds` 很大 | 按漂移量表态：漂移 > 30min 时标注"该快照非真早盘，早盘偏离仅供参考" |
| 全部抓取失败（断网/源方挂） | 文件不存在，退出码 1，`logs/intraday_snapshot.log` 有 ERROR | 同"文件不存在"分支；查日志判是网络还是源方 |
| 部分票失败（停牌/退市） | 文件存在，该票在 `errors` 里、不在 `codes` 里 | 该票单独标注"早盘无快照（停牌/源方无数据）"，其余票正常核实 |
| 指数整批失败 | `indices` 为空、`errors` 有 5 条 index | β 背景退化为读收盘态/实时价，个股 α 判断照常 |
| 选股 md 缺失（上一交易日没出选股） | `meta.targets.pick_md=null`、只覆盖自选池 | 当日选出的票若不在自选池 → 无早盘快照，按"文件缺该票"处理 |

**统一纪律**：任何降级都必须**显式标注在产出里**，不许静默失效——这条是项目两次静默失效教训
（反转换手退化、news_ai 误判）沉淀下来的硬规矩。

## 附：为什么长这样——遵循项目既有 launchd 约定

本节点**不是新引入的机制**。项目此前已有两个在跑的 OS 级定时，本节点是同一模式的第三个：

| Label | 时间 | wrapper | 用途 |
|---|---|---|---|
| `com.stock.pullrefresh` | 周一~五 15:40 | `ops/launchd/pull_refresh.sh` | 每日盘后闭环（产出 `data/sync_receipts/`） |
| `com.stock.strong` | 周一~五 20:00 | `ops/launchd/strong_refresh.sh` | 最强选股 |
| `com.stock.intraday` | 周一~五 10:30 | `ops/launchd/intraday_snapshot.sh` | 盘中快照（本节点） |

沿用的约定（首版曾偏离，2026-09-03 改齐）：
1. **Label 用 `com.stock.<名>`**，不另起命名空间；
2. **plist 只作薄指针**，真正逻辑放**仓库内**的 `ops/launchd/<名>.sh`（可版本管理、可 review），不从 plist 直接调 python；
3. **wrapper 惯例**：`set -uo pipefail`、REPO 由脚本自身位置推出（不硬编用户名/绝对路径）、`STOCK_PYTHON` 可覆盖解释器、`mkdir` 原子单实例锁 + `trap` 释放、日志 append 到 `~/.local/state/stock/<名>.log`；
4. **plist 副本同时放仓库** `ops/launchd/` 与装机位置 `~/Library/LaunchAgents/`，前者是真源。

有意偏离一处：`pull_refresh.sh` 会先 `git merge --ff-only origin/main` 自更代码，本节点**不做**——10:30 是盘中，主仓工作树可能正被其它会话使用，盘中动 git 风险大于收益；快照逻辑刻意保持简单稳定。

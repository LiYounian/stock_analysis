## 0. 一句话目标

把策略 S05「最强选股」的④号条件(筹码高度获利)从 **硬依赖 Tushare `cyq_perf`**
切到 **本地推演的 `tools/collectors/chip.py`**,从而:①去掉全项目唯一的真 Tushare
依赖;②筹码 15:40 当场可算,S05 并入 15:40 主流程;③退役 20:00 的 `com.stock.strong`
补跑、修掉"18:36 收盘选股读到占位值"的 gap。切换**前置**一轮口径回测校准,据此
重定 `THRESHOLDS["最强选股"]` 的相关阈值,并验证选股信号质量不掉。

## 1. 现状与依赖分析

### 1.1 S05 用到 `cyq_perf` 的哪些字段/阈值

代码:`tools/pipeline/screen_strong.py::signal_at`(第 67~74 行)+
`tools/config/strategy.py::THRESHOLDS["最强选股"]`(第 300~306 行)。

S05 = ①∧②∧③∧④,四个子条件里**只有④依赖筹码**:

| 条件 | 判定 | 依赖数据 |
|---|---|---|
| ① 六均线多头 | MA5>MA10>MA20>MA30>MA60>MA200 | 纯 OHLC,本地已有 |
| ② 近期连续大涨 | 近 `涨幅窗口=11` 日内单日涨 ≥ `涨幅阈值=0.05` 的天数 ≥ `涨幅次数=2` | 纯 OHLC |
| ③ 高位区间 | `贴近高下界=0.9`·H52 < C < `贴近高上界=1.2`·H52,H52=近 `H52窗口=250` 日最高价 | 纯 OHLC |
| ④ **筹码高度获利** | `winner_rate > 获利比阈值(95.0)` **或** `HIGH ≥ cost_95pct` | **Tushare `cyq_perf`** |

④ 的原始实现(screen_strong.py:70-74):

```python
if chip:
    wr = chip.get("winner_rate")        # cyq_perf winner_rate,单位 %(0~100)
    cost95 = chip.get("cost_95pct")     # cyq_perf 95 分位成本价(元)
    c4 = ((wr is not None and float(wr) > float(c["获利比阈值"]))   # 阈值 95.0(%)
          or (cost95 is not None and high[t] >= float(cost95)))
```

- `winner_rate`:Tushare cyq_perf 字段,口径 = 通达信 `WINNER(CLOSE)`,即**收盘价上方
  获利盘占比**,单位百分数(0~100)。阈值 `获利比阈值=95.0` 表示"95% 以上筹码浮盈"。
- `cost_95pct`:cyq_perf 的 95 分位成本价(元),用来**近似** `WINNER(HIGH)`——
  当日最高价若冲破 95 分位成本,等价于绝大多数筹码在最高价下方获利。

其余的门控:
- `chip=None`(未配 token / 当日取不到)→ ④恒 False → 恒不选。
- `run_strong_screen` 顶层门控:`is_configured()` 为假 或 `_chip_map` 取空 →
  写 `present=False` + "需 Tushare" 占位 view 并 return(screen_strong.py:126-150)。

### 1.2 Tushare 依赖的产生的两个副作用(要修的痛点)

1. **20:00 补跑**:`ops/launchd/com.stock.strong.plist`(工作日 20:00,Weekday 1-5)
   → `ops/launchd/strong_refresh.sh`:重跑 `tools.run strong --no-fetch` + `tools.sync.upload
   --only-view 最强选股`。存在的唯一原因是 cyq_perf 傍晚才发布,15:40 主流程取不到。
2. **18:36 读占位 gap**:15:40 的 `com.stock.pullrefresh` 跑到 S05 时 cyq_perf 未发布 →
   写"需 Tushare"占位;18:36 的收盘选股若读该 view,可能仍是 15:40 的占位值(直到 20:00 才补真)。

### 1.3 本地 `chip.py` 产出哪些字段(关键:采集已在 15:40 主流程内)

代码:`tools/collectors/chip.py::summarize`(第 128~155 行)。纯用主档 K线 OHLC+换手率,
三角分布+换手衰减推演当日成本分布,派生:

| 字段 | 含义 | 口径 |
|---|---|---|
| `获利比例` | 成本 ≤ 现价的筹码占比 | **0~1 小数**(win = `chips[prices<=close].sum()`) |
| `平均成本` | 加权平均持仓成本(元) | `sum(prices*chips)` |
| `成本区间下沿` | 90% 筹码带低沿 = **5 分位**成本价 | `_cost_range(...,0.90)` 返回 lo,quantile=0.05 |
| `成本区间上沿` | 90% 筹码带高沿 = **95 分位**成本价 | `_cost_range(...,0.90)` 返回 hi,quantile=0.95 |
| `集中度90` | (hi90-lo90)/(hi90+lo90) | 越小越锁定 |
| `现价` | 当日收盘 | |
| `换手缺失日`/`降级` | 有声降级标记 | 窗口内 turnover NaN 行数 |

**关键既成事实**:`chip.fetch_chip` 已在 15:40 主流程里跑(`tools/run.py:123`、深采
`tools/run.py:192-193`),本地筹码数据**当天 15:40 就已落盘**;`load_chip(code)` 读当日缓存,
`load_chip(code, as_of=...)` 走 `summarize_asof` point-in-time 重算(chip.py:257-288),
**回测天然无前视偏差**。也就是说切换所需的数据链路**已全部就绪**,S05 只差把④的取数从
`_chip_map(tushare)` 换成本地 chip 因子。

## 2. 字段映射(本地 chip → cyq_perf 口径)

核心洞察:`_cost_range(prices,chips,0.90)` 的 hi90 恰好是**成本分布的 0.95 分位**
(hi_q = 1-(1-0.9)/2 = 0.95),与 cyq_perf 的 `cost_95pct` **同分位**,是天然对齐点。

| cyq_perf(旧) | 本地 chip(新) | 口径关系 | 命名/单位差异 |
|---|---|---|---|
| `winner_rate`(%,0~100) | `获利比例`(小数,0~1) | 都是"收盘价上方获利盘占比" | **量纲差 100×**:winner_rate ≈ 获利比例×100 |
| `cost_95pct`(元) | `成本区间上沿`(元,0.95 分位) | 同为成本分布 95 分位价 | 命名不同,量纲一致(元) |

映射后 ④ 的判定(等价改写,阈值待校准后重定):

```
本地口径 c4 = (获利比例 > 获利比阈值_local)          # 获利比阈值_local 建议改用小数口径,如 0.95
              or (HIGH ≥ 成本区间上沿)
```

**命名与量纲注意**:直接把本地 `获利比例`(0~1)喂进现有 `wr > 获利比阈值(95.0)` 会永远
False(0.x 永远 < 95)。因此切换时二选一:
- **方案 A(推荐)**:在适配层把本地 `获利比例` × 100 转成百分数,复用现有 95.0 阈值语义,
  再由校准微调阈值 → 对 signal_at 内部逻辑改动最小。
- **方案 B**:把阈值改成小数口径(如 0.95),signal_at 里比较 `获利比例 > 0.95`。
  语义更干净,但要同步改 THRESHOLDS 注释与任何读该字段的下游。

推荐 A(改动面小、回退容易),在校准脚本里统一按百分数比较。最终口径以校准结论为准。

## 3. 口径差异与回测校准计划(**重点**)

本地推演是**近似**(日频 OHLCV + 三角/衰减模型)对 Tushare cyq_perf(交易所/通达信口径)
的重建,两者不会逐票完全一致。切换前必须用**有 Tushare 历史的日子**做逐票对比校准,
据此重定阈值,并确认选股信号质量不掉。**没有这一步不允许切换。**

### 3.1 数据范围

- **前提**:本机当前配了 `TUSHARE_TOKEN`(生产链路仍在用)。校准取一段**已落库或可拉取
  cyq_perf 的历史交易日**做真值。
- 建议范围:近 **60~120 个交易日**(覆盖不同市场状态:上涨/震荡/回撤,避免单一 regime 偏置)。
  逐日取全 A(或流动性前 N,如成交额前 2000 只,避开僵尸股极端值)。
- 每个 (交易日, code) 生成一对:
  - 真值:`tushare_daily.fetch_chip(day)` → `winner_rate` / `cost_95pct`。
  - 推演:`chip.load_chip(code, as_of=day)`(point-in-time,只用 ≤day 的 bar)→
    `获利比例`(×100)/`成本区间上沿`。
- 数据量级估算:120 日 × ~2000 只 ≈ 24 万对。真值一次 `cyq_perf(trade_date)` 拉全市场很快;
  推演走本地 K线,耗时在推演循环(每票 O(window×grid))。见 §6 工作量。

### 3.2 校准脚本口径(**只设计,不实现**;建议 `tools/backtest/calib_chip_vs_cyq.py`)

复用 `tools/backtest/` 既有风格(参照 `forward_scorecard.py` / `screen_forward_common.py`
/ `strategy_scorecard.py` 的取数与落盘约定)。脚本产出两类结论:

**(甲)因子级对齐(相关性/偏差)** —— 逐 (日,票) 配对后统计:
- `winner_rate` vs `获利比例×100`:
  - Pearson / Spearman 相关系数(全样本 + 分市场状态分层);
  - 偏差分布:`bias = 获利比例×100 − winner_rate` 的均值/中位数/分位(P5/P50/P95)、MAE、RMSE;
  - **关键阈值附近的一致性**:在 winner_rate∈[90,100] 这段(S05 真正用到的高获利区)单独看
    相关与偏差——头部区对齐比全域对齐更重要。
- `cost_95pct` vs `成本区间上沿`:相对误差 `(成本区间上沿−cost_95pct)/cost_95pct` 的分布;
  以及 S05 实际用的布尔量 `HIGH≥cost95` 在两口径下的**一致率**(混淆矩阵)。
- 分层:按是否 `降级`(换手缺失日>0)拆开看——降级样本预计对齐更差,校准时应能给出
  "降级票是否该在 S05 里额外保守/剔除"的结论。

**(乙)信号级质量(选股不掉)** —— 校准的落点是"S05 选出来的票质量不掉":
- 对每个历史交易日,分别用 **旧口径(cyq_perf)** 和 **新口径(本地 chip,候选阈值)** 跑
  `screen_strong.signal_at`(①②③不变,只换④),得到两套入选集合。
- 指标:
  - **集合重叠**:Jaccard(入选交集/并集)、逐日入选数差异;
  - **前向收益**:两套入选各自的 T+1/T+3/T+5/T+10 前向收益(复用
    `tools/backtest/forward_scorecard.py` / `screen_forward_common.py` 的前向口径),
    看命中率、均值/中位收益、胜率是否 **不显著低于**旧口径;
  - **稳健性**:入选数不能爆炸(近似把④放太松会滥选)或塌缩(放太紧几乎不出)。

### 3.3 据此重定 `THRESHOLDS["最强选股"]`

- 用(甲)的偏差把 `获利比阈值` 从 95.0(cyq_perf 口径)平移到**本地口径的等效点**:
  例如若"本地×100 系统性比 winner_rate 低 b",则本地阈值 ≈ 95 − b(令新口径下"命中集合"
  与旧口径最接近)。用(乙)的前向收益在候选阈值网格(如 90/92/94/95/96)里选**信号质量
  不掉且入选数稳定**的点。
- `cost_95pct` 分支:若相对误差可控,直接用 `成本区间上沿` 代入 `HIGH≥…`;若系统性偏高/偏低,
  给一个小的口径校正系数(如 `HIGH ≥ 成本区间上沿 × k`,k 由(甲)拟合),避免该分支单独漂移。
- **是否新增"降级票保守化"**:若(甲)显示降级样本对齐显著差,校准结论可建议 S05 对
  `降级=True` 的票在④上更保守(或不选),写进 THRESHOLDS 作为开关项。

### 3.4 通过标准(**校准 gate,达不到不切**)

建议阈值(可由统筹按数据分布微调):
1. **因子相关**:高获利区(winner_rate≥90)`获利比例×100` 与 winner_rate 的 Spearman ≥ 0.6,
   MAE ≤ ~8(百分点);`成本95分位` 相对误差中位数 |·| ≤ ~5%。
2. **布尔一致**:④整体(重定阈值后)在配对样本上与旧口径一致率 ≥ ~80%。
3. **信号质量**:新口径入选的前向收益(T+5)均值/胜率 **≥ 旧口径 × 0.9**(不显著变差),
   且逐日入选数与旧口径同量级(不爆炸/不塌缩)。
4. 达不到 → 不切换,回到"保留 Tushare 路径"并记录差距(见 §5 回滚)。

## 4. 收益

1. **去掉全项目唯一真 Tushare 依赖**:S05 是项目里唯一硬依赖 Tushare 的策略;切换后整个
   选股闭环零 Tushare(降低外部账号/额度/权限风险)。
2. **筹码 15:40 当场可算**:本地 chip 已在 15:40 主流程落盘,S05 的④不再等傍晚发布 →
   S05 并入 15:40 主流程当场出结果。
3. **取消 20:00 strong 补跑**:`com.stock.strong` / `strong_refresh.sh` /
   `tools.sync.upload --only-view 最强选股` 整条傍晚补跑链路可退役。
4. **修掉 18:36 读占位 gap**:15:40 就出真值,18:36 收盘选股读到的"最强选股"不再是占位。
5. **回测可复现**:point-in-time `summarize_asof` 让 S05 历史回测无前视偏差(cyq_perf 历史
   还得逐日拉,现在纯本地)。

## 5. 风险与回滚

### 5.1 风险

- **近似误差**:日频 OHLCV 模型 ≠ 交易所逐笔口径,高获利区/成本分位可能有系统偏差 →
  由 §3 校准量化并靠重定阈值吸收;残余误差以(乙)前向收益 gate 兜底。
- **换手率降级**:腾讯源主档缺换手率靠一次 baostock 兜底;近端整段缺失会扭曲集中度/成本
  (chip.py 已有声降级)。S05 切换后要确认降级票不污染入选(§3.3 的降级保守化选项)。
- **阈值语义漂移**:量纲(%↔小数)改错会让④恒 False/恒 True。测试必须锁量纲(§7)。

### 5.2 回滚设计(**加 config 开关,默认保留 Tushare 路径**)

- 新增开关,建议 `settings.STRONG_CHIP_SOURCE`(env `STRONG_CHIP_SOURCE`,取值
  `tushare`(默认,回退)/`local`)。
  - `tushare`:完全保持现状,`run_strong_screen` 走 `_chip_map`(Tushare cyq_perf)。
  - `local`:走本地 chip 适配层(§2 方案 A),用校准后的阈值。
- 切换分阶段(§6):先默认 `tushare` 灰度共存 → 校准通过 → 默认 `local` → 观察数轮
  → 再退役 20:00 job。开关保证任何一步可一键回退,不删旧代码。
- **退役 `strong_refresh` 的步骤**(默认 `local` 稳定 ≥1~2 周后,**需统筹拍板**):
  1. `launchctl bootout gui/$(id -u)/com.stock.strong`(或 `unload`);
  2. 从 `LaunchAgents` 移除 `com.stock.strong.plist`(**改 launchd 前先查该 job 是否在跑**,
     见 memory「改launchd前查job是否在跑」——20:00 job unload 会 SIGTERM 掉正在跑的实例);
  3. `ops/launchd/com.stock.strong.plist` / `strong_refresh.sh` 代码存档保留(顶部标注"已退役,
     S05 已并入 15:40 本地筹码路径"),不物理删,便于回滚。
- **Tushare 路径不删**:`tushare_daily.fetch_chip` 与 `_chip_map` 保留(开关可切回),
  只是默认不再走。

## 6. 实施步骤拆解 + 工作量预估(agent 视角)

分三阶段,阶段间以校准 gate 为界;每阶段独立 commit(照约法第 9 条)。

### 阶段一:校准验证(先做,**不改生产代码**)
- 写 `tools/backtest/calib_chip_vs_cyq.py`(§3.2):配对取数 + 因子对齐(甲)+ 信号质量(乙)。
- 跑 60~120 日校准,产出对齐报告 + 候选阈值网格结果 + gate 结论。
- **产物**:校准报告(落 `data/analysis/backtest/` + 开发日志),重定后的
  `THRESHOLDS["最强选股"]` 建议值。
- 工作量:**input ~15~25K token / output ~8~12K token**(读数、写脚本、看结果、迭代);
  agent 执行 **~2~4 小时**(含跑校准的墙钟——24 万对推演是主要耗时,可先跑流动性前 N 缩样)。

### 阶段二:切换(校准通过后)
- 加 `STRONG_CHIP_SOURCE` 开关(settings)+ `screen_strong` 里本地 chip 适配层(§2 方案 A):
  `_chip_map` 旁加 `_chip_map_local`(读 `chip.load_chip`,×100 转百分数、映射 `成本区间上沿`→cost95);
  `signal_at`/`run_strong_screen` 按开关选源;写入校准后的阈值。
- S05 在 `run.py` 全A编排里改为 `fetch=False` 依赖已落的本地 chip(15:40 已采,无需触网)。
- 写测试(§7)。默认仍 `tushare` 或直接默认 `local`(由统筹定,建议先 `local` 灰度并保留开关)。
- 工作量:**input ~10~15K / output ~5~8K**;agent 执行 **~1.5~3 小时**。

### 阶段三:退役 20:00 job(默认 local 稳定后,**需统筹拍板**)
- 按 §5.2 退役 `com.stock.strong`;更新 `strong_refresh.sh`/plist 顶部注释为"已退役";
  确认 15:40 主流程 S05 稳定出真值(连续观察数轮)。
- 更新文档(README/开发日志/架构:标注 S05 已零 Tushare、20:00 job 退役)。
- 工作量:**input ~5~8K / output ~3~5K**;agent 执行 **~1 小时** + 数轮线上观察。

**总量级**:input ~30~48K / output ~16~25K token,agent 执行合计 **~5~8 小时**(不含
线上观察等待与校准墙钟)。建议拆 3 轮做,阶段一 gate 不过则止步。

## 7. 测试计划

新增/扩充测试(建议 `tests/test_screen_strong_local.py` 与校准脚本自带断言),锁住语义:

1. **本地路径可出结果(核心,证明不再依赖 Tushare)**:
   - 构造带完整 turnover 的 K线 + `STRONG_CHIP_SOURCE=local`,在**未配 TUSHARE_TOKEN**
     环境下 `run_strong_screen` 能返回 `present=True` 并正常判①②③④,不写"需 Tushare"占位。
2. **量纲锁**:本地 `获利比例`(0~1)经适配层后与阈值同量纲(百分数);构造 `获利比例=0.98`
   的票在阈值 95 下④为 True、`获利比例=0.90` 的票④为 False(防 %↔小数写反,防未来重写踩坑)。
3. **cost95 映射锁**:`成本区间上沿` 映射到 `cost_95pct` 位置,`HIGH≥成本区间上沿` 分支
   在构造样本上按预期触发。
4. **开关回退**:`STRONG_CHIP_SOURCE=tushare`(默认)时行为与现状**逐字节等价**
   (走 `_chip_map`、未配 token 仍写"需 Tushare"占位),保证零风险回滚。
5. **降级样本行为**:换手缺失(`降级=True`)的票按校准结论的策略处理(保守/剔除),
   有断言锁住不静默污染入选。
6. **校准 gate 断言**:校准脚本对 §3.4 的通过标准做断言/明确报告(相关系数、一致率、
   前向收益比),不达标显式失败/告警,防"没校准就切"。
7. **防未来函数**:回测路径 `load_chip(code, as_of)` 只用 ≤as_of bar(chip.py 已保证),
   加断言确认 S05 历史信号不引入未来筹码值。

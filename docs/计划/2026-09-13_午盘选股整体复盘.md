## 1. 执行与盈亏（问题1）

### 1a. 流程是否完整？有没有技术面+消息面共同支撑？

**流程完整、且确有技术面+消息面双支撑**（自 09-09 起 live）：

- **阶段1·纯数据初筛**：11:30 午休冻结 → 拉全A行情 → 注入「今日午盘 bar」当临时收盘 → midday screenall（复用收盘缓存 kline/财报，`--no-fetch`，裁策略11）→ 全A 数据候选 union → Top shortlist。**这是技术面/量价/因子腿**（候选来源含 策略0合议 / 量价放量 / 反转低换手 / 半导体多因子 / 最强选股 等）。
- **阶段2·消息面精选+回灌**：对 shortlist 跑消息面三段式（采新闻+news_ai+情绪+事件 → 看空/看涨 → 线性映射回灌重排）。**这是消息面腿**（输出「消息面方向/分」「情绪三层」「事件驱动」）。
- **产出**：买入5（完整分 Top∩非看空，主评价）+规避3（看空优先，纠偏）+折叠全序台账。
- **闭环**：intraday_review 17:00 读主档当日收盘，算 D-0 下午 α。

结论：**每只买入票都同时带数据面综合分 + 消息面方向/分**，技术+消息共同支撑成立。举例 09-11 买入首位 003032 传智教育＝数据面0.64（策略0合议）× 消息面看多0.71（预告增速高增）。

### 1b. 午盘票是否设了止损和目标？哪些达到目标？

**没有。这是明确缺口。** 午盘全A选股的买入5表只有 `行动/时效`（尾盘可买 / 次日观察）列，**无止损位、无目标位**。因此「哪些票达到了目标」**无从回答——因为根本没设目标**。

（对比：产物 B 盯盘研判里确实逐票写了闸门/止损/止盈价位，但那是对前日尾盘票的监控口径，不是午盘选股票自己的交易计划。两者不能混用。）

## 2. 执行与反思（问题2）

### 2a. 若没能照常跑，原因是什么？现在改善没？以后会不会再犯？

**先纠正一个误解：午盘 job 其实装了、也在按日跑**（早期 git 里的「plist草案未装」留痕已过时）。已核实：

- 已装载并运行（`launchctl list` Status 0）：`com.stock.intraday`(10:30) / `intraday_noon`(11:31) / `intraday_screen`(**11:32 午盘全A选股**) / `intraday_watch`(13:00) / `intraday_review`(**17:00 午盘复盘**)。
- 产物经 `com.stock.commitdocs` 每小时自动脱敏提交并 push origin/main（log 实证：09-10 17:20 推 `午盘_2026-09-10.md`、09-11 13:20 推 `日内全A_2026-09-11.md`、09-11 17:20 推 `午盘_2026-09-11.md`）。

**「感觉没每天跑」的真实原因（按影响排序）**：

1. **（头号·非故障）本地主仓落后 origin/main 76 commit** → 本地 `ls` 看不到 `日内全A_*.md`/`午盘_*.md`，造成断更错觉。**改善**：本地 `git pull` 即可见。**会否再犯**：会——只要本地不 pull 就会重复误判；建议把「查产物先 `git fetch && git log origin/main`」固化进复盘 SOP，别在本地陈旧树上找。
2. **上线爬坡缺前几日（非断更）**：午盘快照 09-04/09-07 缺（noon job 09-08 才上线）；午盘全A选股 09-08 是50只冒烟、09-09 才真 live；09-07 的 10:30 快照真失败过一次（本机网络 `Errno 49`，事后手补）。**改善**：09-08 起交易日无缺日。**会否再犯**：上线缺口是一次性的，不会重犯；但**网络失败退出**这类需加重试/告警。
3. **（真缺陷·会再犯）09-10 午盘复盘降级**：`noon_screen_snapshot.json` 是重构（commit 1193213）才引入、**只从 09-11 起产出**，导致 09-10 的 intraday_review 拿不到 11:30 冻结价→α=None。**只要哪天 11:30 快照落盘失败，复盘就会再次降级为 None**——**这是当前最需要加固的点**（见 §4 修整清单）。

### 2b. 「买了午盘票目标都达不到」→ 是否目标/止损设太离谱？（相对ATR/振幅是否可达）

**该问题的前提在本策略里不成立——午盘选股根本没设目标位/止损位**（见 1b）。所以不是「目标定太高够不到」，而是**「没有可执行的交易计划（进出场纪律）」**。这是比「目标不现实」更根本的缺陷：一份「尾盘可买」的名单，没有告诉执行者何价买、何价止损、何价止盈、何时了结。**修整方向不是调目标数值，而是补一套 D-0 专用的进出场/止盈止损规则**（见 §4）。

### 2c. 若选出的票并非正向 → 持续观测口径有没有问题？

有两处口径/机制问题值得指出（非「票选错」，是「怎么算/怎么合」的问题）：

1. **旧「排序」格式下，消息面看空的高数据分票会冲进 Top**：09-09 午盘候选 Top（301587/688222/002027/300562…）里多只 `消息面方向=看空` 但 `数据面综合分` 很高、`完整分` 仍居前。旧格式直接按完整分排序、未强制「买入=非看空」；**09-11 的买入5/规避3 新格式已修**（买入组口径＝完整分Top **∩ 排除看空**）。→ **口径已在 09-11 收敛，但 09-08/09/10 三天的产物是旧口径，不能直接拿它们的「Top」当买入组回测**（会把看空票混入）。
2. **下午基准口径正确、但依赖 11:30 全A快照**：D-0 下午 α＝个股下午涨跌 − 全A下午等权（11:30→收盘），复用 `breadth.equal_weight_mean_pct` 单一真源，口径本身对；**但基准可算的前提是 `noon_screen_snapshot.json`（全A 11:30 冻结）在**——09-10 就是因它缺失而基准 −nan、全组无法记分。观测口径的**脆弱点在数据依赖，不在公式**。

## 4. 复盘目标：能否实现「每日午盘选股、尾盘前当日买卖且有效」？要做什么修整（问题4）

**现状判定**：**框架已具备（选得出、能记分、独立于尾盘），但「有效性」尚未被证明，且缺「可交易」的临门一脚。** 距离「每日午盘选、尾盘前当日买卖且有效」还差三类修整：

### 修整清单（按优先级，带优劣对比 + 推荐）

**P0-1 · 加固 11:30 全A快照落盘 + 复盘降级告警**（堵 09-10 那类 α=None）
- 现象：`noon_screen_snapshot.json` 缺失 → intraday_review 全组 None，直接丢一天样本，10日闸门永远凑不齐。
- 方案A（推荐）：`intraday_screen` 落盘快照后做存在性+样本率自检，失败即重试/告警；`intraday_review` 找不到快照时**回退用 `data/breadth` 或主档当日收盘**近似 D-0（标注「降级口径」），保证有记录、不丢样本。
- 方案B：仅告警不回退。劣势：仍丢样本。
- 取舍：A 保样本连续性（对凑满10日窗口关键），成本略高；推荐 A。

**P0-2 · 给买入5补「D-0 交易计划」列：进场价/止损/止盈/了结时点**（补 1b/2b 的根本缺口）
- 现状：只有「尾盘可买/次日观察」，无价位纪律 → 无法执行、无法回答「达没达目标」。
- 方案A（推荐）：用**当日实测波动锚定**——进场=尾盘可买价带；止损=午盘价 − k×当日已实现振幅（或 −ATR倍数）；止盈/了结=**当日收盘无条件平仓**（D-0 本就是当日买卖，天然了结点就是收盘），另设盘中硬止损。优点：止损/止盈相对ATR自适应、可达性有保证，且与「当日买卖」目标自洽。
- 方案B：固定百分比止损止盈（如±3%）。劣势：不同ATR的票一刀切，高波票易被扫、低波票够不到（正是问题2b担心的「不现实」）。
- 取舍：推荐 A（波动自适应 + 收盘强制了结）。

**P1-3 · 先攒满≥10交易日 D-0 样本再评判，别急于下「有效/无效」结论**
- 现状：仅 09-11 一天有效、H1 未过。单日不能判。
- 方案（推荐）：维持预注册闸门不动（先锁后评，守则6），**稳定跑到滚动10交易日**后按 G1~G4 一次性裁决；期间只积累、不改参数、不看结果调闸门。这是唯一能让「参数可信」的路径。

**P1-4 · 补午盘专属回测 / 至少把旧3日产物纳入统一口径复算**
- 现状：午盘全借尾盘参数、无午盘专属回测；09-08/09/10 是旧「排序」格式（含看空混入），不能直接当买入组样本。

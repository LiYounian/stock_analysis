# 金字塔式塔尖选股 · 信息凝聚架构 · 设计（2026-09-17 · 待审）

> 统筹维护。⚠️ 测试环境研究模拟，非投资建议。KPI = 绝对收益（Model A）。
> 起因：用户指出近两日选股变差，两大病根——①固定流程/DeepSeek 固定模板丢了当初 Agent「检索很全面」的优势；②前面做了那么多层分析（行情/新闻大面/主体新闻/板块/多策略），**产出没有在最终选股提示词里被反馈/借鉴**，塔尖太薄（只有板块名+风险偏好几个字段 + 一堆 raw JSON 裸分），**分数与真实含义对不齐**，导致下级分析被浪费。

---

## 0. 核心洞察（用户的金字塔比喻）

**散碎信息 + 股票数据 = 塔基 → 经"策略计算 + 新闻抽取"层层凝聚成【可解释的描述】→ 塔尖 = 最终选股报告。**
每一层把下面的东西**凝成描述**往上传；塔尖读齐**所有下级描述**、站最宏观视角逐票判。**铁律：上下口径一致、用文字描述不用裸分、越往上越凝练。**

```
塔尖 ⑤ 最终选股报告  ← 读齐下级全部【描述】,最宏观视角逐票判选/不选
     ④ 大盘宏观研判(regime+加息/降息/汇率/关税/地缘) · 板块消息面研判 · 板块轮动/冷热
     ③ 策略层(council/动量/形态/最强...各出「命中+口径含义」) · 财报五维 · 资金/龙虎/筹码
     ② 新闻抽取(事件+影响·文字档) · 消息大面(影响行情)
塔基 ① 个股量价/财报原始数据 + 散碎新闻
```

## 1. 病根诊断（为什么"塔尖太薄"）

现 S5（`selection_synth.py::SELECTION_SYNTH_INSTRUCTION` + `_stock_llm_payload`）喂给塔尖的只有：板块名 + regime 几个字段 + 每票 `{消息催化 tag, council综合分数字, 形态数字}`。**下级做的这些几乎没往塔尖传描述**：

| 下级已产出 | 现在传给塔尖的 | 缺的（应传的描述） |
|---|---|---|
| 大盘宏观研判(market_daily：宏观净方向/加息/汇率/关税文字) | 仅 "风险偏好=中性" | **宏观各维的文字研判 + 对行情的影响** |
| 板块消息面研判(board_verdict：持续性/催化理由/可靠性) | 仅一个 tag | **板块消息面的完整描述** |
| 策略层(council/动量/形态命中) | `council综合分0.11` 裸分 | **命中哪些策略 + 每个策略此刻代表什么** |
| 财报五维 + 红旗明细 | 仅 "红旗数=1" | **五维文字(回报弱/成长强) + 红旗具体内容** |
| 资金/龙虎/筹码/盘口 | 部分数字 | **主力流向/获利盘/量能的文字判断** |

→ 结果：塔尖"看不全、读不懂"，退化成"板块 tag + 几个数字"的浅层判断，**这正是选股变差的直接原因**；也解释了之前中国船舶对比里"DeepSeek 漏掉财报回报弱/盘口转卖→偏乐观"。

## 2. 塔尖 S5 提示词重构（核心方案）

塔尖提示词 = **模板 + 下级描述的占位符（全文字、数值必带口径）**：

```
你是选股分析师(塔尖)。下面是逐层凝聚上来的【描述】,据整体策略逐票判选/不选。

【一·大盘宏观研判】(市场层·所有票共享)
  {宏观净方向+情景描述}｜{加息/降息·汇率·关税·地缘 的文字研判 + 对行情的影响}｜{大盘风险偏好+它意味着什么}
【二·板块面】(本票所属板块)
  {板块消息面:利好/利空·强弱·持续性·催化理由(文字)}｜{板块冷热/轮动·在重点池排名}
【三·个股·多维描述】(每票)
  ·策略面:{命中哪些策略 + 每策略口径含义(如"council看多0.57=8专家合议偏多；动量强=近期趋势领先；形态突破=站上箱体")}
  ·财报面:{五维文字(成长强/回报弱) + 红旗具体内容(应收存货激增…)}
  ·资金/筹码:{主力流向·龙虎·获利盘(抛压)·量能 文字}
  ·消息催化:{个股新闻催化 方向/强度文字档/来源}
  ·形态:{多头/回踩/位置/量能 文字}
【硬纪律】(同现)催化优先不追高、龙头中军主线跟涨观察、反选剔除(财报红旗/龙虎否决/涨停不可买/极高位)、中性盘不一刀切避动量。
【建议分档定义】8-10强推/6.5-8推荐/5-6.5中性观察/3-5偏弱观察/0-2剔除(各带一句定义)。
→ 逐票输出:档 + 建议分 + 理由(**必须引用上面各层描述、说清策略依据+板块依据+个股依据**) + 入场(据形态,不锚回踩) + 规避。
最后:一段**人读友好的整体研判**(最宏观视角看盘面+板块+选出票的逻辑),上下口径一致。
```

## 3. 三个新增件（把塔尖填满的前提）

### (a) 共享描述库 / glossary（`tools/llm/rubric_map.py`·基础件）
所有层用**同一套档定义 + 标准描述**，代码回填——保证"利好·强 / council看多 / 回报弱"在每一层含义完全一致（**上下口径一致的技术保障**）。与在跑的"数值→文字档打分整改"合流：那个整改产出档，这个库存档→标准描述+权重。

### (b) 策略→描述转换器（`tools/analysis/strategy_desc.py`·关键件·用户点名）
每个策略的命中/分值 → **regime-aware 的文字描述**：不只"council 0.57"，而是"council 看多(8专家合议偏多)；但当前中性盘面下，动量票需回踩确认"。**策略在不同阶段代表不同意思**（动量在反弹日 vs 阴跌日含义不同）——转换器带 regime 上下文。可先用代码规则映射，复杂处用小 LLM 步。

### (c) 接宏观/板块描述进塔尖
`market_daily.md` 的宏观研判 + `board_verdict` 的板块消息面描述，**已存在、只是没往塔尖传**——在 `_stock_llm_payload`/board 上下文里把这些**描述文本**接进 S5 提示词。

## 4. 我补充的优化点 + 当前不足（边写边想）

1. **凝练 vs 过载（重要）**：塔尖读的是**凝练后的描述**、不是 raw 全量——否则又淹进噪音（板块窗口刚发现"解禁×6/终止×7 噪音淹没真催化→DeepSeek 误判分歧"）。**每层只往上传"决策相关的凝练描述"**，配合板块窗口的 P1 榜单噪音过滤 + P2 事件去重。控 token：板块/宏观描述**全票共享一次**，个股描述每票精炼。
2. **策略含义随 regime 变**：转换器必须吃 regime（同一个动量分，进攻盘=追、中性盘=回踩确认、防守盘=降级）。
3. **可追溯/留痕**：塔尖每个结论**引用是哪层描述得出的**（理由里点名），便于次日复盘"为什么选/为什么错"，也是 forward 归因的基础。
4. **报告可读性**：塔尖产出**人读友好的叙事报告**（不只是表格）——最宏观视角先说盘面/板块，再逐票说逻辑，上下口径一致。这是用户明确要的"清晰易懂"。
5. **Agent 全面性的程序化复现（回应病根①）**：塔尖读齐全部凝练描述 ≈ 当初 Agent"检索很全面"的视野，但**可复现、可审、可测**——不是退回不可控 Agent，而是"把 Agent 当初看到的信息，程序化凝聚成描述喂塔尖"。**可选增强**：对塔尖选出的**高置信 top 票**，再触发一次 Agent 式深挖补充（future·非本期）。
6. **信息影响实证闭环**：本架构应把"塔尖用了哪几层描述"记下，做 A/B（喂全描述 vs 喂裸分）验证选票质量差——量化"信息影响"，指导继续加哪层。
7. **当前不足（诚实）**：①策略→描述层还没有（本设计新建）；②新闻正文深度不足（300字截断+标题回落，待 S3 加深+压缩，另一支）；③噪音过滤 P1+P2 待板块窗口落；④部分数据仍陈旧口径（资金流/估值 as-of 滞后，塔尖描述要标"口径日期"）。

## 5. 与在跑/已合整改的关系（不重造）

- **已合**：dual-path 病根修复（策略线∪板块线·0d30e49）——塔尖的候选来源已对（策略线不再被板块埋）。
- **在跑**：数值→文字档打分整改（news/policy/ugc/财报）——是本金字塔的**②③层基础**，产出档 → 喂 (a) 描述库。
- **待接**：板块窗口 P1 噪音过滤 + P2 事件去重——保证塔尖读的描述干净（优化点1）。
- **本设计**：新增 (a)描述库 (b)策略→描述 (c)接宏观/板块 + 重构塔尖提示词。

## 6. 实现分期

- **P0 共享描述库 glossary**（`rubric_map.py`）：档→标准描述+权重，与打分整改合流。~30-50K/1-2h。
- **P1 策略→描述转换器**（`strategy_desc.py`·regime-aware）：council/动量/形态/最强/财报五维/资金筹码 各出文字描述。~60-90K/2-3h。
- **P2 接宏观/板块描述 + 重构塔尖提示词**（改 `selection_synth.py`：payload 换成描述、SELECTION_SYNTH_INSTRUCTION 重构为塔尖模板 + 叙事报告）。~80-120K/3-4h。
- **P3 塔尖叙事报告 + 留痕 + A/B 验证**（可读报告 + 引用留痕 + 喂全描述vs裸分对比）。~40-60K/2h。
- 每期测试锁语义；P0→P1→P2→P3 顺序落，每期过程产物先验再进。

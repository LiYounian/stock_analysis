# 分析师流水线设计（面向中小模型的任务拆分）

> 状态：**设计稿·待用户审阅**（按约法第4条，先写计划审完再落地）。⚠️ 非投资建议。
> 目标：把当前**单体**的 [分析师提示词.md](../每日分析/提示词/分析师提示词.md) 拆成一条**流水线**——先路由分发、再专一执行——让中小模型每步只做一件专一的事、只吃得下当前步所需的那点数据。
> 来源：2026-09-03 用户建议（单一提示词无法让中小模型把事做好；需路由+专一执行+可迭代的节点/分支）。承项目既定目标"赋能中小模型 + 一致性校验机制"。

---

## 1. 为什么要拆（问题 → 原则）

**问题**：现单体提示词让模型一次性完成 定性→数据层→消息面→交叉→结论 五件事，且要同时吞下 per-stock json（十几个字段）+ 原始消息面全文。中小模型：①上下文/推理预算有限，一次性大文本+多任务→顾此失彼；②哪步错了看不出来（整段输出，无法定位是"定性错"还是"消息面检索错"）；③无法针对薄弱环节单独迭代。

**设计原则**：
- **单一职责**：每个节点只解决一个子问题，输入/输出契约明确（结构化 JSON），互不越界。
- **小输入**：每个节点只喂它这步需要的最小数据切片，不是整包。
- **先路由后执行**：用一个轻量路由节点决定"这只票走哪条支线、重点看什么、有无特殊情况"，避免每票都跑满全流程。
- **可迭代**：节点、边、分支条件、每个节点的提示词都是**独立可版本化的文件**，可单独 A/B、单独回改，不动其它节点。
- **可定位**：一致性校验下沉到**节点级**——中小模型在哪个节点偏离超级模型，就修哪个节点的提示词或其上游经验。
- **可降级**：任一节点失败/数据缺失→有明确 fallback（降级输出+告警），不静默失效（呼应"反转换手退化""news_ai误判"两个静默失效教训）。

## 2. 流水线总览（DAG）

```
                 ┌─────────────┐
  per-stock 数据 →│ R  路由分发  │→ 定性标签 + 支线选择 + 特殊情况标记 + 关注点清单
                 └─────┬───────┘
                       │ (按定性/特殊情况分支)
        ┌──────────────┼───────────────┬────────────────┐
        ▼              ▼               ▼                ▼
   [趋势成长]     [超卖反弹]       [高位妖股超买]     [游资情绪连板]     [特殊:停牌/ST/数据缺失]
        │              │               │                │                │
        ▼              ▼               ▼                ▼                ▼
   N1 数据层解读 ── N1 ── B1 市场广度 ── N1(超买重点) ── N1(简) ──── D 降级节点
        │              │      │          │                │          (告警+最小结论)
        ▼              ▼      ▼          ▼                ▼
   N2 消息面检索归类（各支线共用，输入=该票原始消息面）
        │
        ▼
   N3 数据×消息面交叉（输入=N1+N2 结构化输出，不再读原始大文本）
        │
        ▼
   N4 方向/操作结论（趋势/超卖/超买走此；游资连板改走 V-risk）
        │                                   │
        ▼                                   ▼
   汇总节点 A（拼 per-stock 分析块）    V-risk 风险标注（不给方向，只判高波动/规避）
        │
        ▼
   一致性校验 C（节点级：中小模型 vs 超级模型基线，逐节点比对）
```

> 说明：N2/N3/N4 为主干共用节点；B1（市场广度）、V-risk（游资风险标注）、D（降级）为**分支专属节点**。路由决定进哪条支线、给每个节点带什么"关注点"。

## 2.5 实现形态：Agent 编排 + 节点分两类（用户 2026-09-03 方向）

整条流水线按 **Agent** 搭：一个编排 Agent（可由大模型或调度代码充当）按 DAG 走节点，在分支点**把定向子任务外包给"小模型+小提示词"**，拿回**定死的结构化输出**再作为下一步（或大提示词汇总）的输入。节点分两类：

- **确定性节点（代码/工具，不走 LLM 或只轻用）**：可复现、可断言、零幻觉，**优先用项目现成代码+工具调用**，把工具结果回喂大提示词——
  - N1 数据层：`technical.compute` / 读 per-stock json / `ob_os` / 筹码 / 资金流 → 指标是**算出来的**，不让模型算。
  - B1 市场广度：`market_forecast.breadth` 广度聚合器。
  - 候选定向富集（C1 硬伤修复）：确定性调采集器补 news/财报/fundflow（"固定代码+工具调用"的样板）。
  - 数据完备度/覆盖率检查、防未来函数日期过滤：纯代码闸。
  - **T-slot 盘中快照（已落地 2026-09-03，本类节点的第一个落地件）**：launchd 在真实 10:30 跑
    `tools/pipeline/intraday_snapshot.py` → `data/intraday/<日>/T1030.json`；Claude 盘中任务无论
    几点醒都读这份真快照做早盘偏离，**时效性由代码保证**（起因：定时会话工具调用被挂起 3h16m，
    "10:30 核实"实际取到 13:50 的数据）。契约/补跑/kill-switch/降级见
    [盘中定时快照_确定性节点](盘中定时快照_确定性节点.md)，时序治理全景见 [定时任务时序治理](定时任务时序治理.md)。
  - **全市场收盘口径（已落地 2026-09-03，本类节点的第二个落地件）**：launchd 在 15:05 跑
    `tools/pipeline/market_breadth.py` → `data/breadth/<日>.json`（全A等权 mean_pct / 中位数 /
    涨跌平家数 / 净广度 / P10-P90 分位 / 涨跌停家数 / 六个指数对照）；盘尾复盘直接读它作
    **α 记分基准**，不再现场对 5000+ 只票临时复算（起因：09-03 盘尾发约 105 个批请求现场复算，
    而 `market_forecast.json` 要等 18:36 且其广度是"当日之前"的特征）。
    ⚠️ **全A等权只有一个定义**：`market_forecast.breadth.cross_section_stats`（B1 与本节点共用同一函数）。
    契约/补跑/kill-switch/降级见 [全市场收盘口径_确定性节点](全市场收盘口径_确定性节点.md)。
- **判断节点（小模型+小提示词，专一）**：只在"需要语义判断"处用 LLM，且输入已被上游压成结构化小片——
  - R 路由（定性分票/选支线/标特殊情况）、N2 消息面归类（利好利空/可信度/与本股关系）、N3 交叉对账、N4 方向结论、V-risk 风险标注。

> 好处：确定性的事交给代码（省 token、不幻觉、可回归），只把真正要"判断"的小片喂小模型；每个小模型调用输入小、任务专一，中小模型也扛得住。编排 Agent 负责把工具结果和小模型判断拼起来。

## 3. 节点契约（输入 / 输出 / 职责）

> 每个节点标注【代码/工具】或【LLM】类型（见 §2.5）。

> 每个节点 = 一份独立提示词文件 + 明确的 JSON 输入输出契约。下面是**契约草案**（提示词正文在落地阶段写，本稿先定接口）。

### R · 路由分发（router，轻量）
- **输入**：per-stock 精简快照（价格/涨跌幅/换手/量比/连板数/是否ST/是否停牌预告/技术超买超卖标签/板块），**不含**原始消息面全文。
- **输出**：`{定性: 游资连板|趋势成长|高位妖股超买|超卖反弹|普通, 支线: <id>, 特殊情况: [停牌风险|ST|一字板|数据缺失|...], 关注点: [本票这步最该看的3~5个信号], 消息面必要性: 强制|辅助}`
- **职责**：只分类+路由，不下结论。这是"先关注什么、遇特殊情况怎么走"的那一层。

### N1 · 数据层解读（technical reader）
- **输入**：per-stock json 的 snapshot/signals/technical/chip/holder/fundflow（**只数据，不含消息面**）+ 路由给的"关注点"。
- **输出**：`{技术面要点: [...], 资金面要点: [...], 超买超卖: {...}, 数据可信度/缺失标记: [...]}`
- **职责**：把数据翻成要点；标出哪些是"加工分"（council/sentiment）需下游用原始消息校验；标数据缺失。

### N2 · 消息面检索归类（news retriever & classifier）
- **输入**：该票原始消息面（baidu_news 采集器结果 + 必要 WebSearch），路由的"消息面必要性"。
- **输出**：`{催化事件: [{标题,日期,来源,可信度,多空,与本股关系}], 舆情概览, 缺消息标记}`
- **职责**：只做检索+归类+可信度分级（公告>媒体>研报>舆情）+与本股关系判定。**防未来函数**在此硬约束（剔除晚于分析时点的消息）。（与刚修的 news_ai 本股关系 bug 对齐：名字缺失不得翻转成"无关"。）

### N3 · 数据×消息面交叉（cross-checker）
- **输入**：N1 + N2 的**结构化输出**（不再读原始大文本，输入已被前两步压缩）。
- **输出**：`{消息能否解释走势, 数据是否验证消息真伪, 系统加工分对账结论(矛盾以原始消息为准), 关键矛盾点: [...]}`
- **职责**：只做对账/交叉，输入小、任务专一。

### N4 · 方向/操作结论（verdict）【LLM】
- **输入**：定性 + N3 交叉结论 + 市场β背景（market_forecast.json，**个股β基准默认读 proxy 全A等权，HS300 仅背景**，见"大盘预测五档口径与个股β基准"提议）。
- **输出**：`{方向预测: {1日:{方向,置信}, 5日:{方向,置信}}, 预期明日β档位, 操作倾向: 买入|可参与|观望|规避+理由, α/β拆分, **进场战术**, **退出止盈纪律**, 我vs系统出入, 关键盯点(单问化), **存量融资与解禁**}`
- **职责**：只出结论，明确表态别对冲。高位妖股超买走**审慎口径**变体。
- **C2 纪律（大盘预测↔个股必须挂钩，2026-09-03）**：
  1. 买入表态必须**显式写成"剔除预期β后的 α 下注"**——先给"预期明日大盘/板块β档位"，再说明"本买入是净α判断，不是赌它随大盘涨"。避免"预测它会涨"与"选得对"混同。
  2. 普跌日后若大盘预测反弹，中小盘票很可能随β普涨——此时 N4 要点明"上涨可能主要来自β，α待复盘验证"。
  3. **复盘（eod）强制用 α 口径**：剔除当日大盘/板块β后的超额才算选股对错，光看涨跌不作数。此纪律同步进经验沉淀 #10 的"怎么用"。

- **兑现纪律（判对之后怎么办，2026-09-03 首个买入整体兑现日反哺）**：
  1. **只写入场不写退出＝判对了也不知下一步**。买入候选必须同时输出**退出/止盈纪律**（价格位/形态破坏/时间止损/催化落空），
     并预先写明"次日涨停封板卖不出时怎么办"。实测两只兑现票（两日 +15.5% / 四日 +27.1% 且封板）都卡在"产出没写下一步"。
  2. **方向前提=触发信号**。方向若依赖尚未出现的触发信号（放量收阳/主买翻正/行业催化），N4 只能输出"低波动待动"、**不得给方向**。
     形态/低 bias/筹码集中/估值便宜属**静态依据**，只支持"下跌风险小"，不支持"上涨动能强"——两者混同即把"低波动"读成"低波动+向上"。
  3. **进场战术按形态分档**。放量突破票不设深回踩买点（实测 MA5 恰在预设买点区间内、但价格已在 MA5 上方 10.8%，等回踩=大概率不触发的闸门）；
     只对缩量整理/回踩形态设回踩买点。方向判对而战术踏空也算没赚到。
  4. **盯点必须单问化**。每条盯点是可独立判定的单一问题，禁止复合条件（"能否放量站上X"须拆成"是否站上X"+"量比是否≥Y"），
     否则条件分叉（站上=是/放量=否）时无法记分。
  5. **α 基准用等权/中位数而非指数**（N4 读 β 背景时的口径）：指数走平≠个股走平，实测同日 HS300 +0.10% 而全A等权 -0.305%、
     中位数 -0.605%、净广度 -0.282，用指数当 α 基准会系统性低估上涨票的 α、放大下跌票的失败程度。
  → 以上 5 条对应经验沉淀 v2026-09-03 的 #11~#14，排期见 [09-03复盘反哺排期](09-03复盘反哺排期.md)。
### 分支专属节点
- **B1 市场广度**（超卖反弹支线）：输入=大盘广度快照；输出=孤立破位(接飞刀) vs 全市场恐慌(真反弹)。插在 N3 前。
- **V-risk 游资风险标注**（游资连板支线）：**不给次日方向**，只输出高波动/风险等级/规避理由。替代 N4。
- **D 降级节点**（特殊情况）：数据缺失/停牌/ST 时给最小可用结论 + **显式告警**，绝不静默产出满格结论。

### 汇总/校验
- **A 汇总**：把各票节点输出拼成 `选股/<日>.md` 的逐票块（模板化，非模型自由发挥）。
- **C 一致性校验**：**逐节点**比对中小模型 vs 超级模型（Claude）在同一输入上的输出，定位偏离节点。

## 4. 分支条件（路由 → 支线）

| 定性/特殊情况 | 支线 | 节点序列 | 关键差异 |
|---|---|---|---|
| 趋势成长 | S-trend | R→N1→N2→N3→N4→A | 标准全流程 |
| 超卖反弹 | S-oversold | R→N1→N2→B1→N3→N4→A | 插市场广度,判接飞刀vs真反弹 |
| 高位妖股超买 | S-overbought | R→N1(超买重点)→N2→N3→N4(审慎口径)→A | 审慎口径,不默认偏多 |
| 游资情绪连板 | S-hotmoney | R→N1(简)→N2→V-risk→A | **不给方向**,只标风险 |
| 停牌/ST/数据缺失 | S-degrade | R→D→A | 降级+告警,不跑满流程 |

> 分支条件本身是**可迭代对象**：阈值（连板数、超买乖离、覆盖率）都写在流水线 spec 里，可随经验版本调。

## 5. 可迭代性 & 一致性校验（节点级）

- **每个节点提示词 = 一个文件**，头部带版本/来源经验版；改一个节点不动其它。
- **节点级 A/B**：固定输入，比对"节点提示词 vX vs vY"或"中小模型 vs 超级模型"的该节点输出差异，用结构化字段逐项比（比整段文本可判）。
- **定位薄弱环节**：一致性校验 C 输出"哪个节点、哪个字段偏离最多"→ 只修那个节点的提示词或其上游经验条目（呼应现"经验讲不清就回去写可量化判据"的原则）。
- **与经验沉淀的关系**：经验沉淀仍是**单一事实源**；各节点提示词是经验在该步的"投影"。经验更新 → 触发相关节点提示词修订（在节点文件里记 changelog）。

## 7. 落地计划（审阅通过后）

1. 先写 `流水线.md`（DAG+契约+分支阈值）——**骨架先行**（约法第5条:先框架后填内容）。
2. 逐节点写提示词文件（可并行派子 agent，每 agent 写1~2个节点,互不冲突）。契约已定→并行安全。
3. 写节点级一致性校验说明 + 一个最小校验脚本（固定样本票,逐节点跑中小模型 vs Claude,出偏离表）。
4. 用 09-02/09-03 的真实票**试跑**整条流水线,与现单体产出/超级模型对账,迭代薄弱节点。
5. 稳定后,更新每日分析 README 的"合作者/中小模型参与"入口,从"读单体提示词"改为"按流水线走"。

**工作量粗估**：`流水线.md`+校验说明 ~30-50K token / ~1-2h（我主写）；9 个节点提示词并行派 agent ~各 10-20K token / 合计 ~1-2h；试跑迭代 ~1轮/次。

# 消息 × 板块 × 选股 · 程序化流水线 · 设计（2026-09-16 · 待审）

> 统筹维护。⚠️ 测试环境研究模拟，非投资建议。
> 起因：用户指出——中间过程文件偏薄（板块/来源少而粗）、**分析靠 Claude Code 交互式做而非固定程序+DeepSeek 跑**、缺主力/资金流、龙头/中军无定期维护关系表。要求全部改成**程序驱动的固定流水线**：每步有明确输入/输出（过程文件），定时任务驱动，LLM 分析用 **DeepSeek（优先，开思考模式）/ 千问 122B**，采集写进采集层。

---

## 0. 现状诊断（先厘清，不甩锅）

| 维度 | 现状 | 问题 |
|---|---|---|
| 板块覆盖 | 只 ~10 个（catalyst 板块来自 `data/sector_roster/` 只对 10 个板块产角色表） | **太少**，未覆盖全申万一级/热门 |
| 新闻来源 | 龙头/中军 code 定向 `baidu_news` + policy 政策 | 偏粗、无 MCP/多源、无独立采集程序 |
| LLM 分析 | 网关默认 qwen3.8-max | 用户要 **DeepSeek（思考模式）优先** |
| 主力/资金流 | `market_fundflow.py` 仅**市场级两融**；东财个股/板块主力净流入**接口被墙**、北向 2024-08 停披露 | **板块/个股主力资金流无现成源**（真数据墙）→ 需替代（LHB/其他 provider） |
| 龙头/中军 | `roles.py` 每日重算（可计算打分） | 无**周度维护关系表 + 变更留痕**；未先"定表"再"按表采集" |
| 选股分析 | **统筹（Claude Code）交互式**拉量价/跑 council/合成 | **非固定程序+DeepSeek 产出**——用户核心不满 |

## 1. 目标架构：5 阶段程序化流水线（每阶段 = 明确输入 → 处理 → 过程文件输出）

```
[周度] S1 板块universe维护 ──→ 板块清单.json
[周度] S2 角色关系表维护   ──→ sector_roster_table/<板块>.json（龙头/中军/先锋/主力·带变更留痕）
[每日] S3 定向消息采集     ──→ raw_news/<date>/<板块>.json（读S2表·逐角色定向抓·含资金流）
[每日] S4 结构化研判(DeepSeek) ─→ catalyst_<date>.json（板块整体评价+分级关键事件）
[每日] S5 选股合成         ──→ 今日选股_<date>.md/.json（消息×策略×财报×盘面）
```

每阶段**独立可跑、失败不外溢、幂等**，由**定时任务驱动**（不依赖 Claude Code 在线）。

### S1 · 板块 universe 维护（周度）
- **输入**：全 A 行情 + 申万一级归属 + 广度/成交/涨停家数。
- **处理**：确认"当前该有哪些板块 + 哪些是热门/活跃"（按成交额占比、涨停家数、换手、resonance 排序，取全申万一级 28–31 个，标注热门 flag）。
- **输出**：`data/analysis/sector_universe.json`（板块清单 + 热度标记 + 生成日 + 与上周 diff）。
- **周期**：每周一次（+ 成分调整时）。**纯量价、无 LLM。**

### S2 · 角色关系表维护（周度·"先定表"）
- **输入**：S1 板块清单 + `roles.py` 可计算打分（涨幅/成交额/市值/位置/放量/β）+ **主力资金流（见 §3 数据墙处理）**。
- **处理**：每板块产**龙头/中军/补涨先锋/弹性 + 主力（大资金主导个股）**名单；与上周表 diff，**变更留痕**（谁进谁出、位置变化）。
- **输出**：`data/sector_roster_table/<板块>.json`（角色名单 + 特征 + 变更历史）+ `roster_changes_<week>.md`（周度变更过程文件）。
- **周期**：每周一次（角色"实时变动"由此承接；比每日重算稳定、可留痕、可审）。**保留每日 roles 版作对照。**

### S3 · 定向消息采集（每日·"按表采集"）
- **输入**：S2 角色关系表（读表拿每板块龙头/中军/先锋/主力 code）。
- **处理**：**采集层独立程序**（`tools/collectors/board_news.py` 新建，与现有解耦）逐板块逐角色**定向抓**：个股新闻/公告（news/announcement）+ 板块政策（policy）+ **国际对标**（半导体看海外龙头、有色看大宗）via **MCP/固定服务**；+ 资金流维（LHB 龙虎榜净买 / 可用 provider）。
- **输出**：`data/sector_news/raw/<date>/<板块>.json`（原始消息 + 来源 + 采集时刻，逐条可溯）。
- **周期**：每日（下午/EOD）。**采集与研判解耦**：本阶段只抓取、不判。

### S4 · 结构化研判（每日·DeepSeek 思考模式）
- **输入**：S3 原始消息 + 资金流。
- **处理**：**逐板块**（或并行）喂 **DeepSeek（思考模式，优先）/ 千问122B** → 按固定 RUBRIC（文字分级：利好/利空/中性/分歧 + 强弱 + 可信度/影响/执行度/来源 + 持续性/时效）产**板块整体评价 + 分级关键事件 + 理由**。提示词固定、留痕、人工可核。
- **并行 vs 逐一**：板块间相互独立 → **并行调用**（28 板块并行、总时长≈单板块，网关并发可控）；统筹按网关并发上限分批。**由实现方评估并发数落地。**
- **输出**：`data/sector_news/catalyst_<date>.json`（现有格式扩展 + 覆盖全板块）+ 渲染 MD（人看）。
- **模型**：网关 DeepSeek（思考模式）；配置项切换、留 qwen122B 备选。

### S5 · 选股合成（每日·程序化·非 Claude 交互）
- **输入**：S4 板块评价 + 候选（利好板块角色）+ 策略层（`screen_council` 多专家合议·含财报/龙虎榜）+ 整体盘面（宏观净方向/加息降息/汇率/关税/地缘/北向）。
- **处理**：程序跑 council 拿策略综合分 → 消息×策略×财报×形态×盘面**合成建议分** → **DeepSeek 分析师**（固定提示词）出深度研判 + 规避；**不靠 Claude Code 交互**。
- **输出**：`data/analysis/<date>/今日选股_<date>.md/.json`（单一产物，每日选股规格）。
- **周期**：每日（17:30 板块后、盘后选股线）。

## 2. 与"每日选股"的关系（回答用户）
- 本流水线**升级的是"消息/板块"这条输入线**（S1–S4）+ 把 S5 选股合成**程序化**。**每日选股的核心不变**：策略层(council/多策略)+整体盘面+财报仍是主干，消息面从"粗输入"变成"结构化程序输入"。→ 中间文件/流程改动**只会让选股变量更全更可核**，不推翻每日选股，反而补上"踏空"缺口 + 规避能力。

## 3. 数据诚实边界（硬）
- **主力/个股资金流**：东财接口被墙、北向停披露 → 现无现成源。**替代**：LHB 龙虎榜净买（已有 `chip`/龙虎榜）作"大资金"proxy + 找可用 provider（akshare 个股资金流若可用则接，标注覆盖度）。**不假装有全量主力流。**
- **国际龙头 feed**：海外龙头（英伟达/台积电）专用源待接，先经国内财媒 + 政策间接覆盖，标注。
- **新闻→选股无法历史回测**（样本 <1 月）→ 走实盘 forward，诚实标"累积中"。

## 4. 分工（统筹 × 板块窗口）
- **板块窗口（news 线 owner）**：S1 板块universe、S2 角色关系表维护、S3 采集层独立程序、S4 DeepSeek 研判。
- **统筹**：S5 选股合成程序化 + 整体盘面整合 + 各阶段过程文件契约 + HTML 展示 + 集成合 main。
- 契约在本文；实现分阶段 commit、统筹核验合。

## 5. 工作量估（agent 视角）
- S1+S2（板块universe+角色关系表维护）：input ~50–80K / 2–3h（复用 roles.py，加周度表+diff留痕）。
- S3 采集层独立程序 + MCP/多源 + 资金流替代：~80–120K / 3–5h（多源接入+诚实兜底为主）。
- S4 DeepSeek 并行研判：~40–60K / 2h（改模型+并行+全板块）。
- S5 选股合成程序化（含 DeepSeek 分析师）：~80–120K / 3–4h（把交互式分析固化成程序+提示词）。
- 合计约 250–380K input / 10–14h agent 跨多轮；建议分阶段落地（S1→S2→S3→S4→S5），每阶段过程文件先跑通再进下一阶段。

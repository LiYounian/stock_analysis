# 开发日志 · 2026-08-18 · 半导体多因子策略移植(策略E / 选股页策略6)

## 更新(2026-08-30 补丁):修 pipeline 财报顺序坑——入口先自采财报(skip-if-cached)

**现象**:远端 screenall 跑完后,web 页面「策略6 半导体多因子」区块空(策略5 小市值同批次能出),连续多天如此。

**根因**:`run_screen_all` 编排顺序错位:
```
for _, fn in screeners:        ← 6 个 screener 全部先跑(含策略5·半导体多因子)
    fn()                        ← screen_semi_factor 里 build_financial_block 读三大表 raw
...                             ← 大量 FileNotFoundError,178 只全 skip,view 入选=0
run_financial_collect(news_subset)  ← 到这一步才采财报,已经晚了
```
主流程的假设是"财报 = 中心记录级别、只对 llm_subset(自选∪每策略前5)采";而半导体池 178 只票本轮才是 pipeline **自己**要用财报,主流程不会替它采,且 pipeline 跑在采集之前 → 空。

**修**(单文件、`tools/pipeline/screen_semi_factor.py` +22 行):pipeline 入口对 `scoped(codes ∩ 半导体池)`先跑 `fin.fetch_financial(need_fin)`,只补缺缓存的票。
- 幂等:命中缓存 skip,新披露季度才实际触网(全新 178 只估 5-10 分钟,日常秒过)
- `fetch=False`(--no-fetch):与既有语义一致,不采
- 采集失败:warning 降级,build_record 仍逐票判(不 crash 主流程)

**测试**(`tests/test_screen_semi_factor.py` 7 → 9 项):
- 原 `test_no_fetch_does_not_touch_network` 加 `fin.load/fetch` 触网守卫
- 新 `test_fetch_true_auto_collects_missing_financials`:A 命中缓存 / B/C 缺 → 只补 B/C
- 新 `test_fetch_true_all_cached_no_refetch`:全命中 → 零 fetch 调用(幂等)

**分支/PR**:`fix/semi-factor-fetch-financials`,https://github.com/LiYounian/stock_analysis/pull/new/fix/semi-factor-fetch-financials
**验证**:合入后远端下轮闭环,view「半导体多因子」应有入选 → web 层 `source=view` 出数据。

## 更新(2026-08-19 补丁):打通数据链——加 pipeline + 接入 screenall

> 前几版:策略E 算子 + web 实时算就绪,但**数据链未接**——本机自选池 ∩ 半导体池 = ∅,页面永远空;必须先让半导体池 178 只的 fundamental / financial 采到位。

### 加的三块

1. **`tools/pipeline/screen_semi_factor.py`**(与 `screen_momentum.py` 同构):
   - 扫 `codes_all ∩ semi_universe`(178 只);
   - 对每只票走 `fundamental.load_fundamental(总市值)` + `analyzer.build_financial_block(derived)` + `market.load_kline_recent(pct_chg)`,拼装最小 record;
   - 调 `策略E_半导体多因子` → 落 view「半导体多因子」;
   - schema 对齐其他 screener view(`扫描数/universe_size/有效样本/跳过数(缺数据)/入选清单.明细/权重/规则`)。

2. **接进 `run.run_screen_all` 5 策略列表**(变成 6 策略):
   - 半导体多因子 pipeline 采数据用 `fetch=True`(与其他 screener 不同——半导体池票大概率不在 `llm_subset` 里,主闭环的 `collect_values` 不会顾及,只能 pipeline 自采);
   - 采完后半导体池 178 只自动进入 `union_picks` → 后续 `llm_subset` 自动补新闻/LLM/合议/横表,全套走完。

3. **web 层策略6 改成"view 优先"**:`_strategy6_section` 先读 view「半导体多因子」(pipeline 产出,全A 半导体池真实结果),缺 view 才回退实时兜底(records ∩ 半导体池);输出加 `source: "view"|"live"` 字段,便于观测。

### 加测

- **`tests/test_screen_semi_factor.py` 7 项**:池限定/因子权重/缺 mktcap/缺 financial.derived/view schema 齐全/池缺失降级/`fetch=False` 不触网。
- **`tests/test_selection_page.py` 追加 1 项**(`test_strategy6_reads_view_first`):view 存在时优先读、`source="view"`;既有 3 项(实时兜底路径)保持行为不变。
- 全绿 136 项(含 sepa)。

## 本轮做了什么

移植聚宽社区「[半导体板块多因子策略](https://www.joinquant.com/post/63497)」(zyyoyo)到本项目分析层。与前面 [C/D 小市值](开发日志_20260818_小市值策略移植.md) 同源,沿用 `8650081` 剥离规矩:**只提炼可分析层复用的选股;仓位/调仓/限价买卖交回测器与主观决策**。

### 一、剥离规矩(与策略 C/D 一致)

**保留(选股 + 打分)**:
- 3 因子:研发/营收(权 0.6)+ 研发/市值(权 0.2)+ 营收增速(权 0.2)——**原脚本权重原样搬**
- 每因子 winsorize_med(scale=3,中位数 ± 3×MAD)→ z-score 标准化(等价 jqfactor.standardlize)
- 涨跌停/停牌沿用策略D 同款过滤

**剥离**:
- 每 20 交易日调仓 / 限价买卖(±1.5% 保护单)—— 回测器/主观决策职责
- 新股 <160 天过滤 —— 自选池天然长期持有,与策略D 同理由不搬
- 半导体池限定(申万二级 801081)—— 用户拍板"不限行业",records 就是过滤输入,因子自然把非研发型票拓拨(实跑证明有效)

### 二、数据依赖

- 研发绝对额:本项目 fundamental **无** `rd_expenses` 字段。
- **变通**:financial.derived 已有「研发费用率」(rd/rev,由 M2 财报块 metrics 从利润表算出),
  可反算 rd = rd_rev × 营收;rd/mcap = rd / (mktcap_yi × 1e8)。
- 三因子全部落在 record 里,零额外采集,不动闭环。
- **不可算的票**(缺 financial.derived 或 mktcap_yi 或研发费用率=0)静默剔除,不静默补零。

### 三、算子层落地

`tools/strategy/semi_factor.py`:
- `_winsorize_med(values, scale=3)`:中位数 ± scale × MAD 截断;空/全同值原样返回
- `_zscore(values)`:z-score 标准化;空/全同值 → 全 0.0
- `_extract_factors(rec) -> (rd_rev, rd_mcap, rev_yoy) | None`:任一因子缺失返 None(剔)
- `_pass_business_filters(rec) -> bool`:snapshot 存在 + |pct_chg|<9.7
- **`@strategy("策略E_自选池半导体多因子", "选股")`**:主流程 = 3 因子提取 → winsor+zscore → 加权 → 排序取 top_k;样本 <2 不做标准化,返回空 + note

### 四、web 上页

选股页 `/selection` 接入策略E 为「策略6·自选池半导体多因子」——与策略5 同套路,**web 层实时跑**(不读预落盘 view,3 因子已在 records 里)。

- `web/data_access._strategy6_section`:web 层实时算,输出与其他策略区块同 schema + 3 因子明细供前端展示
- `web/data_access._combined_section`:综合选股并集扩到 7 策略,s6_codes 加入命中来源
- `web/templates/selection.html`:新增区块 —— 代码/名称/行业/综合分/研发\_营收/研发\_市值/营收增速(数值列已加正负色)
- `tests/test_selection_page.py`:综合选股期望改 7 策略 + 3 项策略6 专属测试(实时跑/financial 缺失降级/空池)

### 五、测试与实跑

**12 项算子单测 + 3 项 web 集成测试 全绿**(`tests/test_strategy_semi_factor.py` + `tests/test_selection_page.py` 追加)。

## 遗留 / 下一步

1. **半导体池限定要不要恢复**:目前"不限行业"是折中(自选池自然筛),但若接远端全A 版,应先接 baostock 证监会行业(或申万二级 801081)构建半导体池;`tools/analysis/industry_map.py` 目前只到申万一级("半导体" → "电子"),缺二级细分。
2. **rd/mcap 反算的量纲误差**:目前 `rd = rd_rev × 营收`(营收单位元 → rd 元)/ `mktcap × 1e8`(市值单位亿 → 元)——量纲对齐无误,但因 rd_rev 已经保留 4 位小数四舍五入,反算的 rd 与真实 rd 会有 ±0.5% 偏差,横截面标准化后影响极小,可接受;远端接入时,若能直接采到 rd 绝对额则改用真值。
3. **前瞻回测未跑**:策略D/E 都属"自选池实时评级"性质,回测按 `S01`/`策略0_3_4` 套路后续单开。原脚本每 20 交易日调仓的选择需另设计 20d rebalance 回测器。
4. **权重待标定**:原脚本权重 0.6/0.2/0.2 是作者经验,本项目"策略C/D"经验(全网格无正 Alpha=逻辑问题非调参)对本策略也适用,不要跳过回测就调参。

## 1. 复用回测 detector 的 4 条硬约束（统筹权威，设计逐条落实）

回测线作者临走约束（统筹转达）+ 探查结论：

1. **capitulation flag 是收盘确定性信号，只门控 t+1**：吃当日收盘 breadth，回测全程按 t+1 进场测。→ **② β豁免落在"次日选股/市场环境判断"层，绝不盘中实时门控**（盘中 breadth 漂移，#17）。本设计 live 信号节点定在**收盘后**跑，产出供当晚 18:36 选股（门控次日持仓）与次日午盘（仅作静态 β 背景读，不重算）消费。
2. **trailing-500 需要维护生产侧历史 breadth 序列**：合进 main 的是代码非数据；回测的 2018→ breadth 缓存在其 worktree `backtest_local`（不随合并进生产）。→ **§3.2 专门给出生产侧 breadth 序列的建/续方案**（复用 `compute_breadth`/`load_or_compute`，2018→持续可得）。
3. **① 与 ② 严格分层**：① 是 **per-stock 触发信号**（放量收阳）落个股买入条件；② 是 **market-level β 闸**（capitulation 时放松整体降级）。**绝不把 ② 变成给个股加"超跌α分"——H1-α 证不了（是 β 非超跌选股 α）**。§4 用 doc-lint 测试硬锁这条边界。
4. **阈值不挑讨好历史段的点**：固定在跨窗口稳的**中段 `os90 × w2`**（§3.3 定 operating point + 理由），维持防偷看纪律。

## 2. ①③④ 落经验沉淀 + 经验条目分级（schema）

### 2.1 现状（探查确认）
- 经验库 = `docs/每日分析/经验沉淀/v<date>.md`，逐日 append-only 新版，最新 `v2026-09-14.md`。
- §4 条目格式：`**#N · 标题。（date）**` + `- 为什么：…` + `- 怎么用：…`。**无状态字段**。
- 机读侧 `tools/analysis/experience_recall.py`：`_ENTRY_RE=^\*\*#(\d+)\s*·\s*(.+?)\*\*\s*$` **只匹配标题行**，body=两个标题间全文；`_ALWAYS_ON_IDS=(1,2,3,4)` 常驻。→ **在条目里加 `- 状态：…` 子弹是安全的**（进 body，不破 header 正则）。
- 写入方 = `daily-stock-eod-review` SKILL（LLM 逐日新版）；`_待并入.md` inbox 由 `tools/pipeline/intraday_review.py` 写。
- #31 现文案**已经**推荐"下移到放量收阳"（把 MA5 当问题点标出），但**未标验证状态**；#10 是 β 整体降级规则。

### 2.2 ④ 状态字段 schema（决策：第三子弹 + 机读解析）

**格式**：每条 §4 条目在 `- 怎么用：` 后加**可选第三子弹**：
```
- 状态：已验证（2026-09-14 底部超跌反抽回测 CONFIRM，见 docs/计划/2026-09-14_..._报告.md）
```
取值 `待验证` / `已验证`；已验证须**引用证据**（回测报告/复盘链接）。

**默认与存量处理（重要，避免误标）**：
- **存量 30 条**大多是实战沉淀，**不回填、不一刀切标待验证**——解析时缺字段 = `未标注`（legacy，视为既有红线沿用，grandfather）。
- **新增条目默认 `待验证`**（由 eod-review 按新 schema 写）；经回测/多日复盘坐实再升 `已验证`。
- 本回测坐实的 **#31 触发部分**标 `已验证`。

**机读（约法6 可测）**：扩 `experience_recall.py`——
- `ExperienceEntry` 加 `status: str|None`（解析 `- 状态：` 行，缺失=None）；
- `snippet()` 前缀打 tag：`已验证`→`[✓]`、`待验证`→`[待验]`、None→无 tag（不占字数）；
- **状态子弹放 body 首行**（`为什么` 前），保证 320 字截断不丢状态 tag；
- headless `deep_analysis` 拿到 snippet 即见状态 → prompt 指引"待验证条目只轻用/试仓、不当 firm 规则"（③④ 交汇）。
- **向后兼容**：无状态旧条目解析为 None，`recall`/常驻逻辑不变。

**换线协调（eod-review）**：给 `daily-stock-eod-review/SKILL.md` 出草案——并版时新条目必带 `- 状态：待验证|已验证`（默认待验证），已验证须引证据。**只出草案，统筹切。**

### 2.3 ① #31 改法（标已验证 + 放量收阳定稿）
在 #31 `怎么用` 定稿超跌反抽触发闸门（现有文案已含方向，本次收敛为**回测坐实的确定口径**）：
- **首入场闸门 = 放量收阳**（量比>1.5 且收阳）——H2：α₅ 24/24 为正、更早（首段~3pp vs MA5~7pp）、精确率≥MA5；
- **站上前日高/开盘价 = 更早辅助确认**（触发率高、选择性低，辅助档）；
- **MA5 降为趋势确认/加仓档，不作首入场闸门**——H2：MA5 首入场 α₅ 24/24 为负、22/24 显著负=买在反抽首波顶；
- 加 `- 状态：已验证（…回测 CONFIRM）`。
- **诚实边界**（原样保留）：精确率最优仍 <0.5（α 口径，正期望非高命中）；主买翻正需 tick/fundflow，项目无该源→不作硬闸、不臆造。

### 2.4 ② #10 改法（capitulation 例外档，严守不越界）
#10 `怎么用` 增例外档：
> ⑤ **capitulation 例外（H1-β，2026-09-14 回测坐实）**：当 live capitulation 信号触发（广度双极端：破位广度 + 近端崩跌，trailing-500 因果自标定）时，**放松"普跌日整体降级"、给市场 β 敞口**（capitulation 后超跌票 5 日绝对收益 24/24 高于普通普跌）。**但绝不据此对个股加"超跌选股 α 分"——H1-α 证不了（反抽是 β/市场级，非超跌属性带来的 α）**。非 capitulation 的普通普跌日**维持** #10 整体降级（其后反抽弱）。
- 加 `- 状态：已验证（H1-β；H1-α 明确证不了，已标注边界）`。

## 3. ② live capitulation 信号方案（复用 detector，不重造）

### 3.1 复用点（探查确认，因果无未来）
`tools/backtest/capitulation/breadth_features.py::build_capitulation_flags(breadth, grid, trailing=500)`：
- 输入 `compute_breadth()` 产出的日序列（`below_ma20_ratio`/`mean_pct`；`net_adv` 携带不用）；
- 仅用 `rolling(500).quantile` + `rolling(w).sum` + warmup `count`——**全 trailing、min_periods 强制、无 shift(-k)**，因果 by construction；
- 取**最后一行**即当日 as-of 信号；行内含 `{key}_os_thr`/`{key}_crash_thr`/`{key}_cum` → 可出连续 score（距分位余量）。
- forward/H1/H2/evaluate 全是**评测**，不入信号路径——live 节点**不 import** 它们。

### 3.2 生产侧 breadth 序列建/续（约束2 的前提）
- **序列真源**：`tools/analysis/market_forecast/breadth.load_or_compute(cache_path, data_root=<主仓>)`——`compute_breadth` 扫 master/kline 全A（2018→），产 `below_ma20_ratio`(破位MA20)+`mean_pct`，因果（每股 MA20 rolling min_periods=20）。
- **落位**：生产 `data/breadth_series/breadth_full.parquet`（主仓 data，非 worktree；backtest_local 不合并，故必须新建这条）。
- **续法（决策：日全量重算，正确优先）**：信号节点每次 `load_or_compute(force=True)` 重算全序列落 parquet——成本≈现有 `market_breadth` 收盘节点的一次全A扫描（~5200 票、分块有界，秒~分钟级），一天一次可接受；幂等、因果。**增量 append 列后续优化**（复杂度换算力，先不做）。
- 备选（不推荐首版）：扩 `market_breadth.py::build_payload` 让 15:05 收盘节点顺带落 `below_ma20_ratio`，信号只做分位查表——省一次扫描，但改动现有 live 节点、耦合更大，留作优化项。

### 3.3 operating point（约束4：固定中段，不挑点）
- **主档 `cap_os90_cr10_w2`**：os90=破位广度分位中段、w2（窗口已进网格无特权）、cr10=近端崩跌较populated的分位（阈值估计更稳，OOS 63 事件）。H1-β 在**全 24 组**通过 → 任一点 β 结论稳，选中段维持防偷看。
- **`q_crash` 决策点（请统筹拍板）**：`cr10`（较宽、更频、阈值更稳）vs `cr05`（更极端、更稀、更保守 β 敞口）。默认 **cr10** 作主档；信号同时输出 `cr05` 深档 flag 供"更保守时"参考，但**主判用 cr10**，不事后择优。
- 信号文件带 `grid_key` 显式标口径，换点=显式变更留痕。

### 3.4 信号节点契约
新 `tools/pipeline/capitulation_signal.py`（镜像 `market_breadth.py` 纪律）：
- **输入**：breadth 全序列（§3.2）；`--date`（默认今天，非今天=历史补跑，强制读本地 K线，防未来）。
- **计算**：`build_capitulation_flags(breadth, grid=[(0.90,0.10,2),(0.90,0.05,2)])` → 取 as-of `--date` 那行。
- **输出** `data/signals/capitulation/<YYYY-MM-DD>.json`：
  ```
  {date, as_of_close, grid_key_primary:"cap_os90_cr10_w2",
   capitulation: bool, capitulation_deep(cr05): bool,
   below_ma20_ratio, below_ma20_thr(q_os), cum2, crash_thr(q_crash),
   score:{os_margin, crash_margin},         # 距分位余量,连续强度
   trailing_n, warmup: bool, degraded: bool, degrade_reasons:[…],
   caveats:["收盘确定性信号,只门控t+1;绝不盘中实时门控;β择时非个股α"],
   meta:{source, script_version, breadth_span, proxy_definition}}
  ```
- **纪律**：warmup 未满 500 → `degraded=true` 不给 flag；breadth 序列末日 < 请求日 → 拒算非0退出；幂等（存在不覆盖除 `--force`）；非交易日跳过退0。
- **时序**：launchd 定在**收盘后、18:36 选股前**（拟 15:20，`market_breadth` 15:05 之后）。

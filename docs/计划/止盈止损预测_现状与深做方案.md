## 一、用了哪些指标?

现引擎产出四块,用到的指标如下:

| 模块 | 用到的指标 | 数据来源 |
|---|---|---|
| **止盈/止损位** | **ATR(14 日真实波幅均值)** → ATR%(=ATR/现价) | 日K线 high/low/close |
| **支撑 / 压力位** | **Swing Pivot**(左右各 5 根的局部高/低点) | 日K线 high/low |
| **近三次放量** | **量比**(当日量 / 前 5 日均量,>1.5 算放量) | 日K线 volume |
| **情景预测** | **历史 N 日前瞻收益经验分布**(上涨概率 + 10/50/90 分位) | 该股自身历史 close |
| **买卖倾向** | 超买超卖 / 拐点 / 趋势评级 / 主力资金流 / 新闻情绪(打分合成) | technical + fundflow + sentiment |

> 注意:**止盈/止损位本身只用了一个指标——ATR(波动率)**。支撑压力、放量、情景、买卖倾向是围绕它的辅助信息,不进止盈/止损位的计算。

---

## 二、是怎么计算出来的?

### 2.1 止盈 / 止损位(核心,按持有期)

```
ATR%   = ATR(14) / 现价 × 100                  # 日波动率(百分比)
band_N = ATR% × sqrt(N)                         # N 日预期波动幅度(N=1/5/10)
最大亏损% = 止损倍数(1.0) × band_N
目标盈利% = 止盈倍数(1.6) × band_N
止损位 = 现价 × (1 − 最大亏损%/100)
止盈位 = 现价 × (1 + 目标盈利%/100)
风险收益比 = 止盈倍数 / 止损倍数 = 1.6 / 1.0 = 1.6(恒定)
```

**背后的数学假设**:`band_N = ATR% × sqrt(N)` 来自**随机游走**(布朗运动)——波动随时间按平方根扩张(σ_N = σ_1 × √N)。ATR 当作日波动 σ 的代理。
**参数(现占位值,`strategy.py['预测']`)**:ATR 周期 14、止损倍数 1.0、止盈倍数 1.6、持有期 [1,5,10]。

### 2.2 支撑 / 压力位

在 K线里找 swing pivot(某根 high 是左右各 5 根里的最高 → 压力候选;low 最低 → 支撑候选),取**现价下方最近 2 档为支撑、上方最近 2 档为压力**。

### 2.3 情景预测(这块才是"频率意义上的预测")

对该股历史每一天,算其未来 N 日收益,汇成经验分布 → 输出**上涨概率%**(历史上 N 日后收正的比例)+ **悲观/中位/乐观**(10/50/90 分位)。样本 <20 则标"样本不足"。

### 2.4 买卖倾向

超买超卖(±2)/ 拐点(+1~+2)/ 趋势(±1)/ 主力资金(±1~2)/ 情绪(±2)加权求和 → ≥2 偏买入、≤−2 偏卖出、之间观望。每一分都留依据可追溯。

## 三、这个方法的准确性如何?(诚实评估)

**必须分清两件常被混为一谈的事:**

1. **止盈/止损位 ≠ 涨跌预测**。它是**"以当前波动率为尺度,画一个合理的风控括号"**——回答"该给多大止损空间、目标定多远",**不回答"会不会涨"**。方向的判断在「买卖倾向 / 形态 / 合议」里,不在这条带里。

2. 因此**"风险收益比 1.6" 是构造出来的,不代表正期望**。在纯随机游走下,止盈定得越远(1.6),先摸到止盈的概率越低;命中概率会抵消掉盈亏比。**只有当方向信号(形态/合议)真有 edge(漂移)时,这个 1.6 的括号才可能变成正期望。** 括号本身不产生 alpha。

**已知的模型局限(A股实盘会打脸的地方):**
- **√N 随机游走假设**低估尾部:A股有**波动率聚集**(暴涨暴跌成串)和**肥尾**,真实极端波动比 ATR×√N 更大 → 止损可能偏紧、易被"扫损"。
- **对称尺度**:用同一个 band 生成止损/止盈,没考虑上下行波动不对称(A股跌起来更快)。
- **ATR 滞后**:14 日均值对突发变盘反应慢。
- **情景预测用的是无条件历史频率**(这只股过去 N 日涨的比例),≈ 基础概率,**没条件化到"当前形态/位置"**,信息量弱。
- **支撑/压力**只用价格 pivot,没结合成交量密集区(筹码),强度未加权。

**结论**:作为**风控/仓位刻度**,这套方法是业界常见、站得住的**启发式**;作为**"预测涨跌准不准"**,它本身几乎不承担预测职责,不能声称有预测准确率。

## 四、你有没有论证过这个评估?

**没有。诚实说:零回测验证。**

- 代码里有前瞻回测框架(`pattern_forward` / 单③正在搭的 `backtest_summary`),但**止盈/止损这条从未跑过验证**——没有"止损触发率""止盈先于止损命中率""情景上涨概率的校准度"这些数字。
- 现在页面上显示的止损位/止盈位,是**公式当场算的**,没有任何"历史上这样定准不准"的背书。
- 参数(ATR 倍数 1.0/1.6、周期 14)是**占位默认值**,没经过 A股数据调优。

> 这正是我为什么把「回测闭环」列为 P1-最关键:**不合上它,这个功能永远只是"看起来专业",没有证据。**

## 五、它的准确率又在哪?

**目前不存在一个已验证的准确率数字——任何具体百分比都会是编的,我不给。**

但"准确率"对这个功能应该被**定义成可测的几件事**,回测闭环跑够样本后就能给出真数:

| 要测的"准确率" | 定义 | 达标锚点(示例,待回测校) |
|---|---|---|
| **止损触发率** | 持有期内价格跌破止损位的比例 | 应显著低于"随机乱设"的止损 |
| **止盈先于止损命中率** | N 日内先摸到止盈的比例 | 结合盈亏比看是否正期望 |
| **区间覆盖率(校准)** | 实际 N 日收益落在[悲观,乐观]区间内的比例 | 应接近 80%(90−10 分位) |
| **上涨概率校准** | 预测"上涨概率 60%"的那批,实际涨的比例 | 应接近 60%(校准曲线) |
| **叠加方向信号后的期望** | 只在"买卖倾向偏买入 / 合议看多"时用这套括号,实测净收益 | 是否跑赢基准 + 择时 |

**只有第 5 行是真正的"这套东西能不能赚钱"**——前四行是"这套统计构造自不自洽"。

## 六、深做方案(把它做成"页面上看得见"的旗舰策略)

分三层,建议**按序做、每层都可见、每层都有验证**:

### L1 · 抬升可见性(小,先做)
- 把止盈/止损**从个股页抬到选股页/榜单**:每只达标/自选票直接显示「现价 · 止损位(−x%) · 止盈位(+y%) · 盈亏比 · 5日上涨概率」。
- K线图强化:止损/止盈/支撑/压力四条线醒目标注(现有 chart 已有叠加,做显眼)。
- **产出**:打开页面就看到每只票的"括号",不用点进详情。

### L2 · 合上验证闭环(中,最关键)
- 用单③回测闭环,对历史达标池实测第五节那 5 个指标 → 页面加一个「**策略体检**」卡:止损触发率/止盈命中率/区间校准/上涨概率校准,**每个都带样本数和"待观察"标注**。
- **产出**:每个数字都有回测背书,谁问准确率,页面直接给(带样本量,不吹)。

### L3 · 模型升级(大,验证驱动)
- 波动率:ATR → 引入**波动率聚集**(EWMA/GARCH-lite),尾部用经验分位而非 √N,缓解"扫损"。
- 不对称带:上/下行分开估,贴合 A股跌快涨慢。
- 情景**条件化**:上涨概率从"无条件历史频率"升级为"**当前形态/市场状态/位置**下的条件频率"。
- 支撑压力**筹码加权**:结合成交量密集区,给强度分。
- 每一项改动都用 L2 的体检卡 A/B 对照,**改了必须证明更准,否则回滚**。

### 建议顺序 + 工作量(agent 视角,守则11)
1. **L1 先做**:纯展示接线,~1 窗口半天;token 量小(几十 K)。**立刻见效、你马上能在页面看到。**
2. **L2 紧跟**(依赖单③回测闭环产出):~1 窗口 1 天;token 中(回测算力在本地,LLM 不参与)。**这是"准确率"的来源。**
3. **L3 验证驱动**:每子项独立,~各半天到 1 天;**没有 L2 的体检卡就不要碰 L3**(否则又是"改了不知道好没好")。

## 七、给你的决策点

1. **L1 是否立刻开做**(把止盈/止损抬到选股页/榜单,让你马上看得见)?我建议:是。
2. **止盈/止损倍数(1.0/1.6)、ATR 周期(14)** 要不要一起进《给策略提供者》文档,让策略端给经验值?我建议:是,和形态参数一起要。
3. L3 的模型升级方向(GARCH/不对称/条件化)你更看重哪个?建议等 L2 体检卡出来,用数据说话再定。

> 我的整体建议:**L1 立刻做(可见)→ 等单③回测闭环 → L2 出体检卡(有证据)→ 再谈 L3(验证驱动的升级)**。这样每一步你都在页面上看得见、且带证据,不会再"做了像没做"。

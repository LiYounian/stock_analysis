# 需求文档模板（复制我，按段落填空）

> 用法：写新需求时**复制本文**为 `需求名.md`（或 `Pn_特性名.md`），删掉每段的《填写说明》，填入实际内容。
> 约定来源：`docs/计划/` 下的文档 = **需求文档**（承载"想加什么需求"），见 [docs/README.md](../README.md) 第 2 节 + [开发规范.md](../开发规范.md) 第三章 (a)。
> 生命周期：写 → 负责人审阅 → 执行 → 完成后文首标 `✅ 已落地` 并记偏差 → 小结进 [开发日志](../日志/开发日志.md)。

---

> 状态：**待审 / 执行中 / ✅ 已落地 / 已废弃**（四选一，动手前是"待审"）· 日期：YYYY-MM-DD · 分支：`feat/xxx`
> 一句话：（用一句话说清这个需求要解决什么）

## 一、原始需求（负责人 / 同事原话）

《填写说明：忠实转述提出者的原话或诉求，先如实记录、不要提前脑补加工。逐条列出。可标注是谁、什么时候、什么背景下提的。》

- 原话 1：……
- 原话 2：……

## 二、要实现哪些功能（可验收的功能点）

《填写说明：把上面的需求拆成一条条**可验收**的功能点——每条都要能判断"做没做完"。避免"优化体验"这种不可验收的表述，改成"X 页面新增 Y 列，点击 Z 展开明细"。》

- [ ] 功能点 1：……（验收标准：……）
- [ ] 功能点 2：……（验收标准：……）
- [ ] 功能点 3：……（验收标准：……）

## 三、实现计划

《填写说明：怎么落地。分期、涉及模块、接口、工作量估。》

- 第 2 步：……

### 3.2 涉及模块（`tools/` · `web/` 路径）
| 模块 / 文件 | 改动类型（新建 / 改 / 只读） | 说明 |
|---|---|---|
| `tools/xxx/yyy.py` | 新建 | …… |
| `web/zzz.py` | 改 | …… |

### 3.3 接口 / 契约（若涉及）
《若改中心记录结构，遵循 contract-first：先改 `tools/contracts/` 并过 `validate_record` + 全池回归。列出新增/变更的函数签名或字段。》

```
# 例：新增/变更的函数签名或记录字段

```

### 3.4 工作量估（按 agent 视角，见全局约法第 11 条）
- 预估 token：input ~ __K / output ~ __K 量级
- 预估 agent 工时：~ __ 小时（含 LLM 调用 + 工具往返 + 审阅来回）

## 四、关联

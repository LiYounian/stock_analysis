# 选股 md 的 `parse_pick_codes` 解析鲁棒性修复(机读锚点 + 结构化回退)

> 2026-09-09。⚠️ 测试环境研究模拟,非投资建议。
> 只改 repo 内解析侧;真正让锚点生效还需 repo 外分析师提示词(SKILL.md)配合写出锚点,见末节「交接」。

## 1. 缺陷(已实证)

`tools/pipeline/intraday_snapshot.py:parse_pick_codes(md_path)` 旧实现是**全文扫所有独立 6 位数字码 + 全A代码表过滤**("宁多不漏")。问题:当上一交易日的选股 md 是**跳过留痕文件**(无真实选股)时,其正文根因段落里出现的 6 位数字(如"baostock 串行采集卡在哪只票"里的股票代码)会被当成"昨日选股"抓走。

实证:2026-09-08 原为跳过留痕,其根因文字含 3 个连续沪市主板码,被误当昨日选股 → 让 09-09 午盘快照 / 午盘研判跟踪了 3 只**根本没选**的票(600248 / 600249 / 600250)。

## 2. 修复:解析优先级(从最权威到最兜底)

`parse_pick_codes` 改为 5 级优先级:

1. **机读锚点**(最优先):选股 md 顶部一行 `<!-- PICKS: 601061,600356,601339,... -->`。存在即**只认锚点**里的码;`<!-- PICKS: none -->`(或 skip/无/空)= 本日无选股 → 返回空。
   - 选 **HTML 注释**而非 YAML frontmatter:注释对 md 渲染完全透明(不显示、不占版面),GitHub 预览 / 各类阅读器都不当正文;frontmatter 要求文件严格以 `---` 起头,对存量自由文本 md 侵入更大。
   - 锚点是**权威来源**:只做去指数 / 去重的最小清洗,**不要求在离线全A代码表里**(允许代码表尚未收录的新票 / 920 段等以锚点为准)。
2. **标题自证跳过**:首个 `# ` 标题行命中 `跳过留痕|本日无选股|今日无选股|无真实选股|选股跳过|未选股|本日跳过|跳过…选股` → 返回空,**不回退扫码**。
   - **只看标题、不扫正文**:补做文件常在正文叙述"原文件为跳过留痕 / 当晚如实跳过"却自身有真实选股(如 09-08 补做版),扫正文会把它误判成空。真正的跳过留痕文件会在标题里写明。
3. **回退首选锚区 = 「买入建议排序」节**:无锚点、非跳过 → 只在该节内扫码。
   - **为什么单挑这一节**:它是每份真实收盘选股 md 都有的**最终排序表**(`## 4. 买入建议排序` / `## 四、买入建议排序`),一张干净的表格恰好列出且仅列出当日**全部**入选票(买入候选 / 观望 / 检验 / 规避都在),且**排在**策略建议(§6)/ 记分预登记(§5)/ 遇到的问题这些含"说明性散码"的节**之前**。
   - 正则 `买入(?:建议)?排序`,同时覆盖 `intraday_screen` 全A午盘选股 md 的「买入排序」榜。
4. **次选锚区 = 其它"选股清单式"节**:没有「买入建议排序」节的老 / 异版 md(如 day-0 人工文 `2026-08-31.md` 的「## 3 只票与预测」)用 `选股清单|最终选出|最终 N 只|N 只票|入选…清单` 兜底。
5. **连选股清单节都没有 → 返回空**。跳过留痕文件正是这种(只有根因 / 说明文字、无选股清单表),从而**不再**把根因段落里的散码误当昨日选股——这正是本次要修的缺陷。

**刻意排除**(不作锚区):§2「选股清单与理由」正文、§3「逐票深度分析」正文——它们虽含选中票,但同节夹带消息面误判讨论里的散码(如"同名深圳能源 000027 张冠李戴"、"对照 300885 海昌新材"),扫它们会把散码抓回来。§4 排序表才是干净锚区。

**取向**:宁缺勿滥优先于宁多不漏——多抓一只散码会让下游快照 / 研判跟踪一只根本没选的票(已实证缺陷),比漏抓危害更大;真正想被跟踪的票,生成方写一行锚点即可确定性锁定。

## 4. 对 `intraday_watch` 的影响(需注意)

`tools/pipeline/intraday_watch.py` 缺省从 `日内_<date>.md`(午盘研判 watch 文件,repo 外 SKILL 生成)`parse_pick_codes` 取候选。这些文件版式是「盯盘集逐票状态 / 尾盘行动清单」,**无排序 / 选股清单节** → 新逻辑返回空,`intraday_watch` 回退到只盯持仓。

- 这**不是变坏**:午盘研判文件同样含"误抓票"(`日内_09-09` §2A 明列 3 只误抓),旧全文扫会把它们当 watch 候选;返回空反而不再盯误抓票。
- 要让 `intraday_watch` 缺省候选恢复,应给午盘研判 SKILL(`daily-stock-noon-analysis`)加 `<!-- PICKS: ... -->` 锚点列真实盯盘集,或用 `--codes` 显式传入。见「交接」。

## 5. 测试(`tests/test_intraday_snapshot.py`,锁语义)

新增 / 改写标的解析用例:
- 无锚点 → 只从「买入建议排序」节取码,指数 / §2 散码(000027,300885)/ §6 举例码(600248/9/50)都不抓;
- 有锚点 → 只认锚点码,正文表格码忽略;
- `PICKS: none` → 空;
- 标题自证跳过 → 空,不抓根因散码;
- 补做文件正文叙述跳过但自身有选股 → 照常取到票;
- 存量真实 `2026-09-08.md` → 取到 8 只、不含 3 只误抓码。

`~/.conda/envs/stock_analysis/bin/python -m pytest tests/test_intraday_snapshot.py tests/test_intraday_watch.py tests/test_intraday_screen.py` → 46 passed。

## 6. 交接(需 repo 外手动改的 SKILL.md)

锚点要真正生效需生成方也写出锚点。生成方在 **repo 外**(`~/.claude/scheduled-tasks/*/SKILL.md`),**本轮不改**,列出供统筹 / 用户手动处理:

- **`daily-stock-selection/SKILL.md`**(产出 `docs/每日分析/选股/<date>.md`,即 snapshot 消费的收盘选股文件)——**必须**在 md 顶部写 `<!-- PICKS: code1,code2,... -->`;本日跳过时写 `<!-- PICKS: none -->` 或标题带"跳过留痕"。这是修复真正闭环的关键一处。
- **`daily-stock-noon-analysis/SKILL.md`**(产出午盘研判 `日内_<date>.md`,`intraday_watch` 缺省候选源)——建议加 `<!-- PICKS: ... -->` 列真实盯盘集,否则 `intraday_watch` 缺省候选为空(仅盯持仓)。

repo 内**无** `<date>.md` 的生成器(只有 `intraday_screen.py` 生成 `日内全A_<date>.md`,非 snapshot 消费,其「买入排序」榜已被新锚区正则覆盖,无需改)。

# 重设计:消息面三段式(纯数据初筛 → 消息面精选 → 评价回灌打分)

> 起草 2026-09-08。缘起:用户澄清期望流程,与已上线的"独立确认层"节点(commit 06e181b,`tools/pipeline/candidate_message.py`)有**代沟**——现状是"消息面只做旁注、不改排序",用户要的是"**消息面真正回灌进用得上它的策略、参与重排,选出的票才有完整分数**",且用有限候选集控制 token。本设计取代"独立确认层"定位。⚠️ 非投资建议。

## 核心原则(用户口径)
- **不可能对全A 5000 只跑消息面**(LLM 开销爆炸)。全A 阶段**纯数据**。
- 消息面**只对有限候选集**跑,该集 = 各策略数据初筛的 top,**总量 ≤ 策略数 × 10**。
- 消息面产出的看空/看涨评价 → 打分 → **回灌到"需要消息面"的策略**,重排后才得到完整分数。
- 消息面结果**留存**,供尾盘/午盘分析、以及"用消息面打断点"的策略复用。

## 三段式流程

### 阶段1 · 纯数据初筛(全A,无消息面)
- 拿全A数据 → 跑所有**数据相关策略**(技术面/量价/形态/财报数值/资金…)。
- **每个策略各筛出 ~5–10 只**(取该策略排序 top-K,K≈5–10)。
- 候选并集 = ∪各策略 top-K,去重,**总量 ≤ 策略数 × 10**(实际因重叠更少)。
- 此阶段完全不触网新闻、不跑 LLM。

### 阶段2 · 消息面精选(仅候选集)
- 对候选并集(几十只)**广泛采集消息面**(公告/新闻/舆情/龙虎榜),跑 LLM 分析。
- **并行提速**:候选可分批并行调用 LLM(agent 侧并行 / 采集并发),压缩墙钟。
- 防未来:只用 ≤ 决策时点的消息。

### 阶段3 · 评价与回灌打分
- LLM 对每只候选给**看空/看涨评价**(方向 + 强度 + 理由)。
- 把该评价**转成分数**,回灌到**需要消息面的策略/专家**(合议里的 情绪三层 / 事件驱动 / 资金流-消息侧,以及任何声明"用消息面"的策略):
  - 这些策略**先在阶段1贡献纯数据分**;
  - 阶段2消息面分出来后,对候选集**重新排序**(二次合议/加权),得到**完整最终分**。
- 纯数据策略(不声明用消息面的)分数不受影响,保持阶段1结果。
- **最终选股**基于回灌后的完整分数。

### 留存(硬要求)
- 候选集的消息面原始 + LLM 评价 + 分数**落盘留存**(news_ai/sentiment/事件 code_view + 一份"消息面评分"视图),供:
  - 尾盘/午盘逐票分析直接复用(不重复采、不重复跑 LLM);
  - "用消息面打断点"的策略读取;
  - 远端展示。

## 与当前实现(06e181b)的差异 = 改造点
| 维度 | 现状(独立确认层) | 目标(本设计) |
|---|---|---|
| 候选口径 | 合议Top30 ∪ 各策略前5 | **各策略 top-K(5–10),∪,≤策略数×10** |
| 消息面作用 | 旁注标注,**不改排序** | **回灌打分 → 重排候选**,得完整分 |
| 合议 | 二次合议仅产标注、不写回 | 用消息面**重排候选合议分**(作为该候选集的权威分) |
| 留存 | 已留 news_ai/sentiment | 追加"消息面评分"视图 + 确保可复用 |
| 主排序 | 不动全A主排序 | 全A主排序仍纯数据;**候选集内**用消息面重排(不回全A 5000) |

## 待定/实现拆解(下一轮实现)

3. **重排口径**:候选集内,把消息面分并入合议加权(或独立一路信号加权),重排出完整分。
4. **top-K 参数**:各策略 K=5–10(默认几?),`≤策略数×10` 硬上限。
5. **并行**:阶段2 采集+LLM 对候选分批并行。
6. **留存视图**:新增 `__view__:消息面评分`(候选集每票:方向/强度/分/理由)。
7. **接入**:替换现有 candidate_message 的"独立确认层"逻辑为"回灌重排",接到统一日更入口(配合遗留2 daily driver 归一)。

## 实现记录(2026-09-08,分支 `feat/消息面三段式回灌打分`)

落地 = 重写 `tools/pipeline/candidate_message.py`(取代旧独立确认层)+ 新增 config `THRESHOLDS["消息面回灌"]` + 接线 `tools/run.py` + 重写 `tests/test_candidate_message.py`。

### 三段落地
- **阶段1 候选口径**(`build_candidate_pool` 改造):从"合议Top30∪各策略前5"改为"**各策略(含合议策略0)各取 top-K ∪**"。`top_k` 默认 8,越界自动 clamp 到 config「top_k范围」`[5,10]`;**硬上限 = 策略数 × config「候选硬上限倍数」(默认10)**,超限按并入序截断(合议/靠前策略优先保留、被砍票 provenance 清掉)。自选池 ∪ 不受硬上限约束(运营关注票必进),计入台账。纯数据、不触网。
- **阶段2 消息面精选**(`_default_enrich`,复用旧零件):只对候选集采 新闻(`run.collect_message`)+ 三层情绪/news_ai(`run.run_sentiment`)+ 事件(`run.run_events`)+ 资金流补缺(`fundflow.fetch_fundflow`,skip-if-cached)。全 `_safe` 隔离。**不含财报三大表采集**(守消息面边界)。新增 `batch_size` 分批接口(串行安全实现 + 并行接口注释:agent 侧可把各批并行调本函数,批间无共享状态;进程内**不起线程/detached**,守纪律)。config「批大小」默认 0=不分批。
- **阶段3 评价→分数→回灌重排**(核心新逻辑):
  - `msg_score_from_evaluation(方向,强度)`:**可解释线性映射** 消息面分 = 方向符号 × clip(强度,0,1) × 斜率,再 clamp 到 ±分数上限。看多/看涨=+1、看空=−1、中性/未知=0。kill-switch「启用」=False → 恒 0。刻意只做线性映射不做复杂拟合(防过拟合)。
  - `rescore_pool`:逐票 ①`council.convene(消息面消费者专家, record)` → 消息面方向+强度(强度=|综合分|)→ 消息面分;②`council.convene(默认专家组, 富集record)` → **数据面综合分**(候选集内**重算合议**;消息面专家因候选集现在有 sentiment/events/fundflow 而**发声**,全A 阶段它们弃权);③**完整分 = 数据面综合分 + 回灌权重 × 消息面分** → 候选集**内**按完整分降序**重排**、编 `候选排名`。
  - **"不动全A主排序"的保证**:`rescore_pool` 仅**内存**调 `council.convene`,**从不写 `record['council']`**、从不落全A主排序 view;节点只落候选集 view。测试锁死(见下 ①③)。

## 0. 目标与非目标

**目标(P2)**
1. **逐票研判生成器**(headless):吃某日已备齐的候选原料 → 套分析师 SOP → 经 `get_client("deep_analysis")` 调 LLM →
   产出 **picks_schema 结构化研判 JSON** → 喂 `write_picks.build_picks_json` 组装/校验/落盘(下游链路完全复用)。
2. **双跑对比框架**:同一输入用两个配置各跑一遍(provider=DeepSeek vs 千问;或 think 开/关)→ **字段一致率 diff**
   +(能算则)**前瞻收益对比** → 出对比报告。这是"迁移前证明程序化质量够格"的**闸门工具**。
3. **历史日 dry-run 验证**:挑 1~2 个已有 Claude 产出的选股日,用生成器跑同一候选集,和当时 Claude 报告对比
   (覆盖度/表态一致性/退化点),写进报告。**dry-run 不落生产、不覆盖已有 md/json**。

**非目标(明确不做)**
- 不切生产、不改 live SKILL(`~/.claude/scheduled-tasks/daily-stock-selection/SKILL.md`)、不动 scheduler/launchd。
- 不做 embedding 语义检索(经验库检索先用关键词/标签,embedding 留后)。
- 不做自动裁决"采纳哪一路"的生产逻辑(双跑只出对比证据 + 建议,裁决人工)。

## 2. 数据契约锚点(build 时严格对齐,别自造)

- **写下游契约** = `write_picks.build_picks_json(pick_date, analysis, ...)`,`analysis` 为 `list[dict]`,每单元:
  - `code`(必)、`strategies_hint`(可选,name[,rank] 提示命中策略,分值由 write_picks 从策略 view 回填);
  - 研判字段(`write_picks._JUDGE_FIELDS`):`type/buy_rank/stance/stance_qualifier/dir_1d/dir_1d_conf/`
    `dir_5d/dir_5d_conf/sentiment_quality/key_reason/key_risk/alpha_beta/watch_points/detail_anchor`。
  - 客观字段(name/close/pct_chg/industry/strategies)**不由生成器填**,write_picks 从 record + 策略 view 回填。
- **枚举闸门** = `picks_schema`:TYPE/STANCE/DIRECTION/CONF/SENTIMENT_QUALITY 受控;
  "不给方向 → 置信必须 '-'";"情绪盲区(unknown/missing)不得 stance=买入/含'首选'"。生成器输出必须落在枚举内,
  由 `validate_picks` 兜底(生成器内先做一次自校验,不合规重试 / 降级为保守表态)。
- **防未来**:输入装配只取"该日及之前"原料;record.as_of 晚于 pick_date 由 write_picks 交叉核对告警。

---

## 3. 双跑对比口径

- **两臂(arm)** = 一个配置 = `{provider_id, enable_thinking}`。默认对比:
  A=`deepseek_v4pro`(think 关) vs B=`qwen_max`(think 关);think A/B = 同 provider think 开/关。
- **字段一致率**:对受控枚举字段(表态/方向/置信/type/sentiment_quality)逐字段精确比,
  出"每字段一致率 + 总一致率 + 分歧清单";叙事字段(理由/风险/盯点)算词重叠相似度**仅作辅助信号**。
- **前瞻收益对比**(能算则):对每 pick 用 `repo.get_master_kline(code)` 取 close,算 T+1(及 T+5 若数据足)前瞻收益,
  比两臂"给偏多的票事后是否更多上涨";历史日近端(距今 < 5 交易日)T+5 数据不足则标 unavailable(诚实标注)。
- **裁决**:P2 不自动裁决,只出报告 + 建议(字段一致 → 可采纳;分歧 → 标 `待人工复核`)。

---

## 4. 历史日 dry-run 验证

- 选 1~2 个已有 Claude 产出的选股日(优先 09-11 等原料齐备日);候选集 = 当时 Claude 报告里的 picks(锚点),
  或该日 record 全集的策略入选并集(见 §6 候选来源确认)。
- 生成器跑同候选 → 与当时 `每日选股.json` / `选股/<date>.md` 对比:**覆盖度**(是否所有票都出了研判)、
  **表态一致性**(stance/方向 与 Claude 的重合率)、**明显退化**(有没有把 Claude 给"买入"的票判成"规避"等)。
- **dry-run 隔离**:产物一律写本 worktree 的派生目录(`data/analysis/<date>/dualrun/` 或 scratch),
  **绝不覆盖生产 `每日选股.json` / md**;用 `--analysis-dir` 指向隔离目录。

## 5. 测试(约法第 6 条,锁"为什么改"的语义)

- schema 契约:生成器输出经 `picks_schema.validate_picks` 必过;"不给方向→置信'-'""情绪盲区不得买入"锁死。
- 防未来:输入装配对 as_of 晚于 date 的原料不纳入 / 告警。
- 双跑 diff 口径:构造两份已知研判 → 断言一致率计算正确、分歧清单正确。
- 经验检索:构造小经验 md → 断言按 code/行业/策略关键词召回正确条目、不整包返回。
- 全程注入桩 client(不真调 LLM),CI 可跑;真调 LLM 的冒烟另走脚本(需 env,不进 CI 断言)。

---

## 6. 待确认 / 默认口径(自主定,回执报统筹便于后续拍板)

- 输出走 **extract 结构化**(机读强,对齐 picks_schema);叙事字段(理由/风险/盯点)一并要 extract 出。
- 经验检索用**关键词/标签**(轻、可解释),embedding 留后。
- 双跑裁决 = **字段一致率 + 关键分歧人工复核**,P2 不自动切。
- think **先关**,作双跑一个臂做 A/B。
- 候选来源:优先复用当日策略入选并集 / Claude 报告 picks 锚点(§6 待survey确认具体文件后定稿)。

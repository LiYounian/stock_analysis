## 一、诊断(读码定位 → 划范围 → 根因)

主档 = `data/master/kline/<code>.parquet`(每股一份长历史,非按日期分区),经
`store.append_master_kline` 增量追加。三条口子会让错数据静默进主档:

### 风险 F — 主档写入用 `today`,不走 `store.active_date()`
- `master_sync.sync_master`:`as_of = as_of or pd.Timestamp.today()...`(编排入口)。
- `market.update_master_from_spot`:`d = date or pd.Timestamp.today()...`,以 `d` 作 bar 的 `date`。
- 而 raw 采集(fundflow/lhb/chip/board 等)落盘走 `put_raw`→`store.active_date()`(编排 `set_active_date` 设的 as_of)。
- **根因**:主档写入路径与 raw 采集路径**用了两套"当前日期"**。历史补算 / 跨日重跑 / as_of ≠ 今天时,
  主档 bar 落到"今天",raw 落到 as_of → **同一逻辑日的主档与 raw 错位**,下游按 as_of join 时对不齐。

### 风险 G — 盘中 spot 把"当前快照价"当当日 close 写进主档
- `update_master_from_spot` 用 spot 的 `最新价` 作 `close` 写入当日 bar;`master_sync` 的
  `_advance_master_from_raw` 明确**放行同日 bar 覆盖**(收盘前多次跑,每次用当时价覆盖当日 close)。
- **根因**:盘中跑闭环时,当日 bar 的 `close` 是**伪 close**(午间价),收盘后才被真 close 覆盖。
  下游若在盘中读主档 last bar(如盘中 chip / 形态),拿到的是非最终价 → 信号漂移;更隐蔽的是
  若当日再没有收盘覆盖(流程中断),伪 close 就**永久留在主档**。这是**未来函数/脏数据双重隐患**。

### 风险 D — qfq 主档 × 未复权增量 bar 拼接,除权后价格断层
- 主档全量落地走 baostock **前复权(qfq)**;`update_master_from_spot` / `_advance_master_from_raw`
  追加的是**未复权当日 bar**(spot 是不复权现价)。
- 现状靠 `_MAX_GAP_DAYS`/`_MIN_COVERAGE` 陈旧度阈值触发全量 backfill 兜底,注释也承认"无除权时最新 bar
  的 qfq 值≈实际价,除权后需 backfill 全量重算"。
- **根因**:**除权日发生**到**陈旧度阈值触发 backfill** 之间的窗口内,主档 = "qfq 历史 + 未复权新 bar"
  混存 → 除权日前后**价格断层**。直接扭曲 chip 成本分布、形态/均线、动量因子(全部吃连续价格序列)。

### 诊断小结(范围)
三条都在**主档写入路径**(`market.update_master_from_spot` / `master_sync._advance_master_from_raw` /
`sync_master`),不涉及采集源本身。改动面小、集中,但**必须零口径漂移**(改的是全历史地基)。

## 二、设计(方案 + 预期效果,审过再实施)

### P0-1 · 主档写入接 `active_date()`
- **做法**:`update_master_from_spot` / 主档增量路径的 `date` 缺省从
  `store.active_date()` 取(与 raw 同一逻辑日),而非 `Timestamp.today()`;编排入口 `sync_master`
  在开跑前 `store.set_active_date(as_of)`,全链路统一。
- **预期效果**:任意 as_of(含历史补算/跨日重跑),主档 bar 与当日 raw **落同一逻辑日**,下游按 as_of
  join 不再错位。今天正常跑时行为不变(active_date=今天)。

### P0-2 · 盘中 bar 打 `provisional` 标记,收盘正式覆盖
- **做法**:盘中写入的当日 bar 在主档 meta(或旁列)标 `provisional=True`;收盘 EOD 正式 bar 覆盖时
  清标记。提供读取约定:下游要"已收盘确定价"时可据 `provisional` 过滤/降级。
- **预期效果**:盘中伪 close 可辨、不被误当最终价;流程中断遗留的伪 close 有据可查(不再静默冒充定稿)。
  盘中 chip/形态消费方可选择"跳过 provisional 日"或有声降级。

### P0-3 · 除权事件驱动强制 backfill(不只靠陈旧度阈值)
- **做法**:增量前用**除权信号**(送转/分红除权日,或当日未复权价对昨收 qfq 的**跳变超阈值**)判定"发生除权",
  命中即对该票强制走全量 `backfill_master`(qfq 重算),而非等 `_MAX_GAP_DAYS` 陈旧度触发。
- **预期效果**:除权日**当天**即修复,消除"除权→阈值触发"窗口内的价格断层;chip/形态/动量不再吃到断层价。
  未除权票不受影响(不误触发全量、不增网络)。

### 配套:测试锁语义(守则6)
- P0-1:as_of≠today 时主档 bar.date == active_date;与 raw 分区同日(断言)。
- P0-2:盘中写入 bar 带 provisional;收盘覆盖后清除(断言)。
- P0-3:构造除权跳变(未复权价 vs 昨收 qfq 比值超阈值)→ 触发 backfill 分支(mock 断言);正常日不触发。

## 三、风险与实施纪律

| 险 | 缓解 |
|---|---|
| 改主档写入引入新口径漂移 | 改前后用现有主档测试 + 新增断言锁 date/复权/provisional 语义;先旁路验证再切主路径 |
| provisional 标记下游未适配 | 标记是**新增可选字段**,默认读取行为不变;仅新消费方按需用,老路径不受影响 |
| 除权跳变阈值误判(高波动 vs 真除权) | 阈值取"除权级别跳变"(如 >9% 且伴随除权日历命中)双条件,宁可漏判走陈旧度兜底,不误触发 |
| 全量 backfill 增负载 | 仅对判定除权的**单票**触发,非全市场;错峰 |

**实施步骤(审过再做,分步 commit,独立分支,不碰 main)**:
1. P0-1 主档接 active_date + 测试(最小、最先,纯语义对齐)。
2. P0-3 除权事件驱动 backfill + 测试。
3. P0-2 provisional 标记 + 读取约定 + 测试(涉及下游读取约定,最后做、影响面评估充分)。
4. 文档回填(开发日志 + 本文标"已实施")。

> 待统筹审:三项优先级/provisional 落 meta 还是旁列/除权跳变阈值口径。审过按步实施。

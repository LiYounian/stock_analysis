# 09-03 复盘反哺排期（判对之后怎么办 + 三个机制缺位）

> 首次提出：2026-09-03。来源：09-03 盘尾复盘（首个买入表态整体兑现日，3只买入候选 α +5.94pp）。
> ⚠️ 非投资建议。本文件是排期/设计留痕，供项目转交时对接。

## 0. 为什么这轮的性质变了

前几轮修的都是**"判断不准"**（数据缺、加工分误导、策略退化）。09-03 是第一个买入表态整体兑现的交易日，
暴露的是**新一类缺口：判对之后没有可执行的下一步**——
- 002811 方向判对，但进场条件设成"回踩 MA5 14.0~14.2"，MA5 实算 14.15 恰在区间内、价格却已在 MA5 上方 10.8%，**两天一股没买到**；
- 002811 两日 +15.5%（bias20 +25.8%）、603270 四日 +27.1% 且涨停封板卖不掉，**产出里没有任何止盈/减仓条件**；
- 688569 的静态依据（形态/低 bias/户数 -18.46%/估值）今天全部仍成立，但它们描述的是"下跌风险小"不是"上涨动能强"——**把"低波动"读成了"低波动+向上"**；
- 603270 盯点"能否放量站上 33"实际分叉成"站上=是 / 放量=否（量比 1.01 缩量封板）"，**复合条件无法记分**。

经验 #12/#13/#14 已进 `经验沉淀/v2026-09-03.md`，但**经验进了不等于会照做**——必须同步落到任务书与产出结构里。

## 1. 四件事与切分准则

按"能否独立完成"切分：A/D 是纯代码新增（不碰任务书），可并行外包；B/C 都要改任务书语义，由统筹一人改，避免并发撞同一文件。

| 编号 | 事项 | 性质 | 承担 | 优先级 |
|---|---|---|---|---|
| **A** | 全市场收盘口径节点（α记分基准数据缺位） | 新增确定性节点 + launchd | 并行 agent | **P0** |
| **B** | 盘尾（15:10）早于闭环（18:36）导致 6 条盯点"未取数" | 排期语义，改任务书 | 统筹 | **P0** |
| **C** | 产出结构补三个必填字段（退出纪律／触发信号／盯点单问化） | 任务书 + 提示词 + 流水线 N4 | 统筹 | **P0** |
| **D** | 存续可转债／定增／解禁 固定一问 | 新增采集 + record 字段 | 并行 agent | P1 |

工作量（agent 视角）：A ≈ 3~5 万 token / 1~1.5h；D ≈ 4~6 万 token / 1.5~2h（数据源可得性不确定）；
B ≈ 统筹 30min；C ≈ 1 万 token / 40min。

## 2. A · 全市场收盘口径节点

**问题**：盘尾复盘要用 α 口径记分，但"当日收盘的全市场口径"没有现成产出——本次是任务**现场发约 105 个批请求**
对 5214 只票临时复算 mean_pct / 中位数 / 净广度 / 分位。`market_forecast.json` 要等 18:36 选股之后才有，
且其中的广度是"当日之前"的特征而非当日收盘实况。

**方案**：与 10:30 快照同一模式的第二个确定性节点——收盘后（15:05）由 launchd 批量拉全A收盘价、
算聚合口径落盘，盘尾任务直接读，不再现场复算。

**硬约束**：
- **必须复用 `tools/analysis/market_forecast/features.py` 里 proxy（全A等权 mean_pct）的既有定义**，
  绝不另写一份——否则"全A等权"会出现两个互相漂移的定义，这比没有更糟。
- 抓取复用 `tools/collectors/gtimg_quote.py`（已是采集层单一真源），不新写 HTTP 客户端。
- 遵项目 launchd 约定（见 [盘中定时快照·确定性节点](盘中定时快照_确定性节点.md) 附录）：`com.stock.*` 命名、
  plist 薄指针、逻辑放仓库内 `ops/launchd/*.sh`、mkdir 原子单实例锁、日志入 `~/.local/state/stock/`。

## 3. B · 盘尾早于闭环（排期语义，不改 cron）

**问题**：盘尾 15:10 跑时当日闭环（15:40 起、全A自采约 73min）尚未开始，`fundflow`/`tick`/`chip`/`margin`
全不可用，本次 6 条盯点被迫标"未取数"。

**候选方案对比**：

| 方案 | 做法 | 评价 |
|---|---|---|
| ① 盘尾 cron 挪到闭环后（约 19:30） | 改 cron | ✗ α 记分时效变差，且与选股（18:36）撞车更严重 |
| ② 资金面盯点**移交次日盘中核实** | 只改任务书语义 | ✅ **推荐**：无新排期、无新任务；次日盘中时前一日闭环已完成，fundflow 可用，而次日盘中本来就要看这批票 |
| ③ 闭环后新增"资金面补验"节点 | 加第四个定时任务 | ✗ 又多一个会漂移的会话，收益不抵复杂度 |

**采纳 ②**：盘尾对需要闭环数据的盯点显式标注"移交次日盘中核实"（而非笼统的"未取数"），
次日盘中任务书增加"接收并验证前一日移交盯点"的职责。**不改任何 cron**。

## 4. C · 产出结构补三个必填字段

选股任务的逐票产出增加（并同步进分析师提示词与流水线设计 N4 结论节点）：

1. **退出/止盈纪律**（买入候选必填）：什么条件减仓/清仓；**涨停封板卖不掉时次日如何处理**必须预先写明。
   ——只写入场不写退出，等于判对了也不知道下一步。
2. **方向前提 = 触发信号**：若方向依赖尚未出现的触发信号（放量收阳／主买翻正／行业催化），
   则**只能给"低波动待动"，不得给方向**。静态依据只支持"下跌风险小"，不支持"上涨动能强"。
3. **盯点单问化**：每条盯点必须是**可独立判定的单一问题**，禁止复合条件（"放量站上33"要拆成"是否站上33"+"是否放量"）。

## 5. D · 存续可转债／定增／解禁 固定一问

603270 有在存续可转债（09-03 披露受托管理事务报告），转股摊薄/条款约束是中期变量，09-02 深度分析完全没纳入。
逐票分析的估值/筹码环节固定加一问"有无存续可转债/定增/解禁"，需要落成可采集字段而非靠分析师临场想起。

## 6. 验收标准

- A：单测 + 真跑落盘，盘尾任务读到的口径与"现场复算"结果一致（用 09-03 实测值 mean_pct -0.305% / 中位数 -0.605% / 净广度 -0.282 对账）。
- B：盘尾任务书 grep 到"移交次日"，盘中任务书 grep 到"接收前一日移交盯点"；下一个交易日的产出里出现移交/接收记录。
- C：三份文件（选股任务书 / 分析师提示词 / 流水线设计 N4）均含三个必填字段；下一次选股产出里每只买入候选都有退出条件、盯点均为单问。
- D：per-stock record 出现该字段且非空率可报告；缺数据显式降级不静默。

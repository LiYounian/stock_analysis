# record 口径日期自证 · 设计与决策留痕(2026-09-03)

> 分支 `fix/record-vintage`(起始基线 `origin/main` = `8dbea25`,收工前并入 A 线后的 `9217b0d`)。
> ⚠️ 研究模拟,非投资建议。
> 一句话:**让每个"会过期"的数据块自证它的口径日期,并在口径日期 ≠ as_of 时显式降级,而不是静默沿用。**

## 一、要修的病(同一类,两个实例)

| # | 现象 | 实证 | 后果 |
|---|---|---|---|
| ① | `fundflow` 块**无任何日期字段** | `data/analysis/2026-09-02/603161.json` 的 `今日主力净流入=-702392 / 占比=-1.2`,精确等于 `data/raw/2026-08-20/fundflow/603161.parquet` 的最后一根(**13 天前**);当日真实值为 +803 万 / +9.73% | 把 13 天前的数标成"今日",**方向相反**,直接误导决策;下游读 record **看不出**是旧数据 |
| ② | `valuation`/`fundamental` 报告期整体滞后 | 同一记录 `valuation.报告期="20260331"`,而半年报 08-26/27 已披露;换成 2026H1 后 PE_TTM 39.79→96.95(+144%)、净利率 +3.08%→−0.37%、毛利率 17.20%→13.53% | 估值/基本面整块错一个报告期;而 `provenance` 只记 `{"fundamental": true}` **布尔值**、不记口径日期 → 滞后完全静默 |

`panel.csv` 的混龄是 ① ② 的下游表现:601882 行 `收盘=22.6`(09-02)但 `PE=24.08 / 市值=114.37亿`,
按 `114.37亿 ÷ 5.2198亿股 = 21.91 元 = 08-31 收盘价` 折算 —— 交叉验证 `24.08/24.75 = 21.91/22.52 = 0.9729`。
**根因不在 panel**:panel 只是把 record 的块拍平,record 内部本来就不同龄(价量来自 K 线最后一根 bar,
估值来自 `fundamental` 缓存命中的分区),而 record 过去没有任何字段暴露这一点。

## 二、三条不变量(实现与单测都按这个来)

1. **保留数据 + 标明它是哪天的 + 标明是陈旧**。不静默沿用(那是①的病);也**不一律清空**——清空会丢掉
   "有旧数据可参考"这个信息,下游打折使用旧值是合法策略。
2. **三态只有一套**:`contracts.record.ENUMS["新鲜度"] = (新鲜, 陈旧, 无数据)`,`analysis.event` 的
   `FRESH/STALE/NODATA` 声明与它对齐,`analysis.serialize` 直接从契约取。**不许出现第四套说法。**
   「无数据」与「陈旧」严格区分:前者什么都没有(走缺失降级),后者有值只是旧的(可打折用)。
3. `provenance` 布尔位按**该维实际有无可用数据**判,且**类型不变**(向后兼容硬要求);
   新信息只挂在 `provenance.口径` 子字典下,不覆盖任何老键。

## 三、口径日期取自哪里(选择依据:哪个日期真正代表"这个数是哪天的")

| 块 | 口径日期来源 | 为什么 |
|---|---|---|
| `snapshot` | K 线**最后一根 bar** 的 date | 价格轴的真源 |
| `fundflow` | 资金流序列**最后一根 bar** 的 date | ①的正解。分区日只说"哪天采的";源返回旧序列或 store 回退旧分区时分区日会骗人,**bar 自带的日期永远诚实**——`今日主力净流入` 取的就是最后一行 |
| `valuation` / `fundamental` | `fundamental` raw 命中的分区日 + **报告期交叉核对** | 分区日决定 PE/市值按哪天价格折算(601882 那条轴);报告期滞后是另一条轴,用披露日锚定的 `financial.报告期` 作参照系(603161 那条轴) |
| `chip` | 同 `snapshot`(K 线最后一根 bar) | chip 是由同一段 K 线本地推演的纯派生量 |
| `consensus` / `holder` / `tick` | 各自 raw 在 ≤as_of 命中的分区日 | 这三块的 loader 本就 date-pin 到 as_of,只是**把 resolved 丢掉了**;这里用同一套解析把它捡回来 |
| `financial` / `financing` | 各自 raw 的分区日(块内另有 披露日/报告期/as_of) | 与 consensus/holder 同一把尺子;块内更细的业务口径原样保留 |
| `sentiment` | **原样镜像它自己的** 采集日期/新鲜度 | 它有自己的新鲜度窗口策略(`SENTIMENT_MAX_STALE_DAYS` / `FRESHNESS_MODE`),用本层的尺子重判会让一个块挂两个互相矛盾的结论 |

**不处理的块及理由**:`signals`/`prediction`/`council` 是纯派生量,口径 = 其输入块的口径,不另立日期
(否则两处会打架);`lhb_veto` 走 `lhb_asof` 的 `list_date < as_of` 严格闸门,按构造无法沿用旧/未来值;
`events`(公告)是列表、每条自带 date,块级无处盖戳 → 口径只进 `provenance.口径`;
`margin`(两融)**当前不进 record**(只有 `collectors.margin` + `analysis.margin_divergence` 用),
没有产出会被误当"今日",本轮不处理——若哪天挂进 record,按 `consensus` 同款处理。

## 四、判定规则(与 `event._classify_freshness` / `run._dim_status` 同一套语义,不新增状态)

- 口径日期 `== as_of` → 新鲜;
- 口径日期 `< as_of` → **陈旧**(数据保留 + 写明是哪天的 + 写 `口径提示`);
- 口径日期 `> as_of` → 保守记新鲜(同 `event.py`),但**显式提示疑未来函数**;
- 判不出(None)→ 保守记新鲜 + 提示判不出(同 `event._resolve_layer` 的兼容路径)。
  **「判不出」≠「无数据」**:`无数据` 只用于该维确实没有可用数据。

探针实现:`_raw_vintage(kind, code, date)` 复用 `store.get_raw_resolved`(只读、不改 store 层)。
⚠️ **探针的日期语义必须与真正取载荷的 loader 一致**,否则盖的戳会撒谎:`fundamental` 的载荷来自
`fd.load_fundamental(code)`(内部 `get_raw(..., "latest")`,全局最新、**可能晚于 as_of**),
故探针也传 `"latest"`。这条正好让"该 loader 没有 date-pin"的未来函数风险如实暴露(见遗留项)。

## 五、`panel.csv` 的处理

panel **不自己另算口径**(单一真源在 record 块内),只把它们拍平成列并给一眼可见的标记:
`记录日期`(=`meta.as_of`,panel 走 `load_record(date="latest")`,各票最新记录日可能不同——第二条混龄轴)、
`价格日期`、`估值日期`、`资金流日期`、`资金流新鲜度`、`报告期滞后`、`混龄`。
`混龄` **只比数据列彼此**,不把 `as_of` 算进来:as_of 与价格日期差一天在盘前/盘中是常态,
混进来这列会天天为 True(报警疲劳);"块 vs as_of"那条轴由各块自己的 `新鲜度` 表达。
全判不出 → `混龄=None`,**不假装 False**(那会把"不知道"说成"没问题")。

## 六、契约层闸门

`VINTAGE_BLOCKS` 内的块一旦出现 `新鲜度`/`口径日期` 就必须合法(三态枚举 + `YYYY-MM-DD`),
并锁住语义红线:**标了「陈旧」就必须说清旧在哪** —— 要么给真实口径日期,要么给 `口径提示`
(如报告期整体滞后时,旧在报告期这条轴上、未必判得出采集分区日)。
光说"陈旧"不说旧在哪,下游照样无法判断,那就回到了本轮要修的那个 bug。
旧记录无这些字段一律宽容(向后兼容)。

## 八、`provenance` 的两层诚实(统筹追加要求)

1. **布尔位按"该维实际有无可用数据"判**(`_has_data`,替代裸 `bool(块)`)。
   `bool()` 的坏处:块里只要有任何键就为 True —— 若采集器把静默 `None` 改成"带 `源不可得` 标记的
   空块",provenance 会从"静默缺失"**恶化成"明确撒谎说有"**。新判据是"有没有**非元信息**的实际值"
   (元信息键清单见 `serialize._META_KEYS`)。顺带修掉一个既有小谎:`ff.summarize(空 df)` 返回的
   「全 None + 连续天数 0」空壳过去让 `provenance.fundflow` 报 True。
2. **`无数据` 再分 `未采集` / `源无数据`**(`provenance.口径.<维>.缺失原因`)。
   处置完全相反:未采集要去补采 / 查采集失败(**我们的**问题);源无数据是合法降级(补采也没有,
   别重试烧额度)。判据与 `run._dim_status` 的 `'missing'` / `'empty'` 同一套(有没有落过盘 vs
   落了但内容为空),**不另造第三种说法**。
   实现:`_DIM_KIND` 按维配 `(raw kind, 探针日期语义)`;`tech`/`chip` 源自**不按日期分区**的
   K 线主档 → 走 `store.has_master_kline`。探针本身失败(被 mock / 未知维)→ 不写该字段,**不猜**。
   **为什么没用 A 线的 `missing_financing()` 台账**:那只覆盖 financing 一维、且要求 serialize 去读
   某个采集器的模块内状态(耦合);raw 分区探针对**所有维**同一套判据,且只用 store 的只读 API。
   两者结论应一致,可互为交叉验证。

## 九、契约"有声明、没闸门"的收口范围(统筹第③项的回答:**做了一半,另一半有理由不做**)

先核事实,再定范围:

- `ENUMS` 已登记的 **12 个枚举,校验器全部覆盖(0 处漏)**。所以"校验器不校验枚举"的准确说法是:
  **只写在 `RECORD_SCHEMA` 描述串里、既无单一真源也无校验**的那批。
- 扫全池 **934 条**在产记录取实际取值:`方向` = 中性 2454 / 看跌 348;`置信度` = 高 2802;
  `放宽层级` = 精确 2802;`审计意见闸门` = 通过 214 / 不通过 10 / null 710。
  **100% 落在已声明值域内 → 加闸门不会引爆既有产出**,故本轮登记进 `ENUMS`
  (`预测方向` / `预测置信度` / `放宽层级` / `审计闸门`)并接上校验。
- **本轮故意不做**的两个:`financing.可转债.明细[].状态`(全池零样本,**无证据不收口**)与
  `定增.明细[].阶段`(A 线刚扩取值,现在收口会撞车)。这两个连同"把散在描述串里的值域搬进
  `ENUMS` 做单一真源"应另立一条线 —— 那需要动各生产者(`predict.py` / `financial/analyzer.py` /
  `collectors/equity_financing.py`),超出本轮文件边界。

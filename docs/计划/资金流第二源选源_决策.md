## 一、候选源对比

| 源 | 端点 | 覆盖字段 | 鉴权 | 本机可达 | 稳定性 | 合规 | 延迟 |
|---|---|---|---|---|---|---|---|
| **腾讯 proxy.finance** | `proxy.finance.qq.com/cgi/cgi-bin/fundflow/hsfundtab?code=sh600000` | **五档全**(mainNetIn / superFlow / bigFlow / normalFlow / smallFlow) | 无 | ✅ 实测 200/ok | 高(公开 H5 后端) | 中(个人/研究) | 实时/分钟 |
| **新浪财经** | `vip.stock.finance.sina.com.cn/quotes_service/api/jsonp.php/...MoneyFlow.ssl_qsfx_zjlrqs?daima=sh600000` | **仅主力净额**(netamount / r0_net),四档拆分不全 | 无(或需 Referer) | ✅ 实测可达 | 高 | 中 | 日度收盘 |
| 同花顺(免费网页) | `data.10jqka.com.cn/funds/ggzjl/` | 五档全 | **需 hexin-v cookie(JS加密)** | 需破 token | 中(反爬频繁变) | **高(协议禁抓)** | 实时 |
| 交易所(上/深) | 官网数据 | **无个股主力资金流**(仅市场级成交/两融) | — | — | — | — | — |
| akshare `stock_individual_fund_flow` | 底层即东财 push2his | 五档 | — | ❌ **同一堵墙** | — | — | — |

**逐项结论:**
- **交易所**:如实说——沪深交易所**只公开市场级成交与两融,不发布个股主力资金流**("主力/超大单"本就是数据商按单笔成交额档位自行推算的口径)。此路不通。
- **akshare 个股资金流**:底层就是东财 push2his,**换汤不换药**,不算第二源。
- **同花顺**:免费网页确有五档,但需破解 JS 生成的 `hexin-v` cookie,反爬强、协议明确禁抓,**合规与稳定性风险最高**,不做常态 fallback。
- **新浪**:接口在、大陆可达、无鉴权,但只稳定给**主力净额(r0_net)**,四档拆分不完整——只能做"主力净额"这一关键字段的**降级代理**,不能完整替代五档。
- **腾讯 proxy.finance**:唯一实测「**非东财 + 五档齐全 + 无鉴权 + 大陆直达**」的免费源,字段可直接映射现有东财口径。

## 二、推荐

**主推:腾讯 `proxy.finance.qq.com/.../hsfundtab` 作第一 fallback;新浪 `r0_net`(仅主力净额、标注口径近似)作第二 fallback。** 形成三级链:

```
东财 push2his(现主源,本机常被墙)
  → 腾讯 proxy.finance hsfundtab(五档全,推荐新增)
    → 新浪 r0_net(仅主力净额,代理指标,数据表标注"四档缺失/口径近似")
```

字段映射:`mainNetIn↔主力净流入`,`superFlow/bigFlow/normalFlow/smallFlow↔超大/大/中/小`。
仿 `market.py` 的多源 fallback + `meta.source` 记实际命中源。

## 三、落地前必须验证(不可拍脑袋直接接)

1. **腾讯 proxy 是否也吃 TLS 指纹墙**:它仍是腾讯域名,不排除与东财类似风控。**先用今晚报错的 442 只做一轮实测**——若 Python `requests`/`curl_cffi` 直连不稳,参考社区做法用 **subprocess+curl(带真实 UA + `Referer: https://finance.qq.com/`)** 绕过 Python SSL 指纹层,再定接入方式。
2. **字段口径核对**:抽样比对 腾讯 hsfundtab 与东财同票同日五档净额,确认量纲(元/万元)、方向(净流入正负)一致,写死映射 + 断言。
3. **延迟/频率**:确认是否支持批量;逐只则并发化(接 `parallel.pmap`,与路线图 P2 一致)。

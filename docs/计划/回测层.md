# 回测层 backtest(设计与实施计划)

> 状态:**规划 · 待审** · 2026-08-06
> 定位:**通用**回测框架——验证任意策略(选股 / 信号),不只 ML。是 [P3E ML 计划](P3E_ML预测与回测.md) 的**上位泛化**:ML 只是"其中一种策略"。
> 架构位置见 [信息流转与层职责.md](../设计/信息流转与层职责.md) §2.6。

---

## 1. 目标与要解决的问题

- 有了[策略层](../设计/信息流转与层职责.md#23-分析--策略层)(选股/评分/信号策略,可扩充),必须能**验证**:一个策略到底行不行,不能拍脑袋。
- **回测** = 用**历史原始数据回放策略** → 算绩效 → 与基准对比 → **达标才用**。
- 核心诚实性:样本外、**严禁未来函数**、与基准对比;历史回测 ≠ 未来保证。

## 2. 在架构中的位置

- **聚合层同级**:读历史数据 + 调策略 → 出绩效;**不产中心记录、不触网、不重算指标**。
- **依赖**:①策略层(被测策略,`strategy.run`)②数据存取层(历史 raw,`store.get_raw("kline", code)`)。
- 二者正是本轮并行开发的两个新模块 → 回测层建在它们之上。

## 3. 核心设计

### 3.1 两类回测
| 类型 | 被测策略 | 回放方式 | 产出 |
|---|---|---|---|
| **选股回测** | 选股策略(records→候选) | 每 `调仓周期` 用**当时可见数据**选股 → 等权持有到下期 → 组合收益 | 组合收益曲线 + 相对基准超额 |
| **信号回测** | 信号策略(kline→逐日买/卖/持) | 单票逐日信号 → 次日成交 → 单票收益 | 单票/组合收益、交易次数 |

### 3.2 walk-forward + 防未来函数(命门)
- 时间从 start 前进到 end;**第 t 个交易日只允许看 `≤ t` 的数据**(`close.iloc[:t+1]`),用 t 的信号,在 **t+1 成交**(价可配),再算未来 N 日收益。
- **测试专门钉死"不泄露未来"**:若实现里不小心用了未来数据,构造用例让它露馅(如把未来某天设成异常值,回测结果不应受影响)。

### 3.3 绩效指标(`metrics.py`)
- 累计收益 / 年化收益、**最大回撤**、**夏普**、胜率、(信号)交易次数、(选股)相对基准**超额收益**。
- **基准**:等权持有全票池(默认)/ 指数(可选)/ 现有统计预测(predict 的上涨概率)对照。

### 3.4 成交假设(可配,进 `config/strategy.py['回测']`)
- 成交价:次日**开盘/收盘**(默认收盘);费用:手续费 + 滑点(bps,默认含,别做无摩擦自欺);调仓周期(选股):`N` 交易日(默认 5)。

## 4. 模块与接口

```
tools/backtest/
├── __init__.py
├── engine.py    # backtest(strategy_name, codes, start, end, **opts) -> 绩效dict
└── metrics.py   # 收益/回撤/夏普/胜率/超额  (纯函数,可单测)
```
- **数据**:`store.get_raw("kline", code)` 拿历史(依赖存取层)。
- **策略**:`strategy.run(name, ...)`(依赖策略层);按策略 `kind`(选股/信号)走对应回放。
- **输出**:落 `data/analysis/backtest/{strategy}_{date}.json`(绩效 + 基准 + 明细指针);可选接 report/Web 展示。

### 接口契约
```
backtest(strategy_name, codes, start, end, *,
         rebalance_days=5, cost_bps=..., price="close", benchmark="equal") -> {
    "策略": name, "类型": 选股/信号, "区间": [start,end],
    "绩效": {累计收益, 年化, 最大回撤, 夏普, 胜率, ...},
    "基准": {...}, "超额": ..., "明细ref": "data/analysis/backtest/..."}
```

## 5. 防过拟合 / 诚实性(硬约束)
- **样本外**:不在"训练/调参"区间上评估;walk-forward 前进。
- **与基准对比**:跑不赢等权持有的策略没意义。
- **简单优先**:先跑现有规则策略(超跌反弹/主力吸筹)拿**基线**,复杂策略/ML 必须显著超基线才上线。
- 全部结果标 **"历史回测,非未来保证;非投资建议"**。

## 6. 实施顺序(分步,依赖就绪后)
| 步 | 内容 | 前置 |
|---|---|---|
| BT.1 | `metrics.py` 绩效指标 + `engine.py` **选股回测** + 单测(含防未来函数) | 策略层 + 存取层就绪 |
| BT.2 | **信号回测**(逐日信号→成交) | BT.1 |
| BT.3 | 跑现有选股策略拿**基线** + 落盘/展示 | BT.1 |
| BT.4(后) | ML/统计策略进回测对比(并入 P3E) | BT.1–3 |

## 7. 与 P3E(ML)的关系
- 回测层是**通用框架**;[P3E ML 计划](P3E_ML预测与回测.md) 的"回测框架先行"就落在本层;ML 预测作为一种**信号/评分策略**接入,与统计基线在同一框架对比。P3E 从"独立计划"降级为"回测层的一个策略来源"。

## 8. 测试要点
- **防未来函数**(命门,必测):注入未来异常值不应改变历史回测结果。
- 绩效指标数值:构造已知收益序列验证 收益/回撤/夏普。
- 基准对比、成交假设(费用/滑点/调仓)生效。
- 数据不足/停牌票的优雅处理。

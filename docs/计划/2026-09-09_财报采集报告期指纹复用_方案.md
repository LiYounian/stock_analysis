# 财报采集·报告期指纹复用(哲学二)方案

> 分支 `feat/财报采集报告期指纹复用`;用户已拍板哲学二。留痕(约法4)。
> 日期 2026-09-09。非投资建议。

## 一、根因(已诊断)

日更收盘 `run_screen_all` 里,**全A 触网采财报三大表的唯一祸首是「策略12·扣非质量」**
(`tools/run.py` 全A `fetch=True` → `tools/pipeline/screen_deduct_quality.py:169-182` 对
缺缓存的全A子集 `fin.fetch_financial(need_fin)`,无池上限)。次要「策略5·半导体多因子」
已被 178 只半导体池 clamp(`screen_semi_factor.py:131-149`)。合议(`screen_council.py`)
只读缓存、缺则弃权、**自己从不采**;确认层财报已是候选池口径。

**现状 skip 判据只看「文件在不在」**(`store.get_raw(date="latest")` 倒序回退命中即停),
两个后果:

1. **渐进式全A覆盖建设**:每天补没采过的新票(建设期:昨天30、今天3234),量不可控;
2. **报告期变了(新披露季)也命中旧缓存 → 永不刷新 → 吃过期财报**(隐性 correctness bug)。

项目**已有报告期指纹复用**,但只在**分析层**(`analysis/financial/analyzer.py`
`_reuse_fingerprint` + `build_financial_block`,指纹=最新可见报告期+披露日+年报披露日+
LLM签名+行业)。**采集层没有。**

## 二、决策:哲学二(报告期新鲜度闸)

把采集层的「存在性 skip」换成**「报告期新鲜度闸」**:

> 某票 **无缓存** 或 **缓存的最新可见报告期 < 该 as_of 下法定应能看到的最新报告期**
> → 才采;否则跳过复用。

目标:日更全A采量 = 当日新披露报告期的增量(报告季外 ≈ 0),同时**修掉过期不刷新 bug**。
**保留策略12/合议全A语义不动**(合议仍单遍 cache-or-abstain,自己不采)。

## 三、关键设计点:如何「不采就判断缓存是否过期」

不能靠「先采回来再比」。用**法定披露日历**推「此刻理应能看到的最新报告期」,与
**缓存里该票已有的最新可见报告期**比较:

### 3.1 `expected_latest_report_period(as_of)` —— 法定应披露最新报告期(保守下限)

A 股法定披露截止:一季报 4/30、中报 8/31、三季报 10/31、年报 4/30(次年)。
给定 as_of(YYYY-MM-DD),返回**此刻法定必到期的最新报告期 report_date**:

| as_of 区间(当年 Y) | 应披露最新报告期 |
|---|---|
| [01-01, 04-29] | `(Y-1)-09-30`(去年三季报;去年**年报**未到法定截止,保守不认) |
| [04-30, 08-30] | `Y-03-31`(一季报;年报同期到但期更旧,取最新) |
| [08-31, 10-30] | `Y-06-30`(中报) |
| [10-31, 12-31] | `Y-09-30`(三季报) |

**保守下限口径的理由(防未来 + 防 churn)**:只认「法定必到期」,不猜个股实际提前披露。

- **防未来函数**:只用 ≤ as_of 的法定截止日历,不看任何个股实际披露信息,天然 as-of。
- **防 churn(不日日重采)**:expected 期只在**法定截止日跨过时才前进一格**。若改成
  「披露季一开始就把 expected 推到新一期」,则整个季度里尚未披露该期的票会被判过期、
  天天重采(采回来最新期仍没到 → 次日仍判过期 → 死循环日采全A)。保守下限使得跨过截止日
  那一刻**几乎所有票都已披露**,一次重采即让全体缓存达标、回到「新鲜跳过」。
- **年报的处理**:年报期(12-31)永不作为 expected(被下一年 Q1 越过)。但 4/30 跨过时
  expected 跳到 `Y-03-31`,凡缓存 < 此期者(含只有去年年报的票)一并重采 →
  **年报 + Q1 在 4/30 窗口一起被采回**,不遗漏、且正确。

### 3.2 `_cached_visible_latest_period(raw, as_of)` —— 缓存最新可见报告期

镜像 analyzer `_reuse_fingerprint` 的可见性规则(单一语义、不新造):
periods 中 `disclosure_date` 为空 或 `disclosure_date <= as_of` 者视为可见,取其
`report_date` 最大值。无可见期 → None。**只认 ≤ as_of 的披露,防未来。**

### 3.3 过期判据

```
无缓存                              → 采
缓存无可见报告期(cache_latest=None) → 采
cache_latest < expected            → 过期,采
否则                                → 新鲜,跳过复用
```

report_date 均为 `YYYY-MM-DD` 定宽串,字典序比较 == 时间序比较,直接 `<`。

### 3.4 已知边界(诚实留痕)

- **重采集中在 3 个法定截止日**(4/30、8/31、10/31)当天对全A重采一遍(季外≈0)。
  这是保守下限口径的必然结果,是「修过期 bug」的应付成本(季外近零、correctness 正确),
  可接受;未来若要平滑,需接**个股预约披露时间表**(另一数据源),本轮不做。
- **披露迟到/无该期的少数票**(停牌/退市边缘)会在截止日后被反复判过期、逐日重采,
  直到其真披露 —— 这是**正确**行为(要它一披露就采回),代价限于极少数掉队票。
- as_of=None → 入口内部默认取今天,expected 恒可算(不会退化)。

## 五、开关(可逆 / kill-switch)

`THRESHOLDS["财报"]["采集"]["报告期指纹复用"]`:

- `True`(默认):报告期新鲜度闸(无缓存/过期才采)。
- `False`:退回旧「存在性 skip」(有缓存即不采,无缓存才采)—— 逐字段等价旧行为,可一键回滚。

入口 `fetch_financial_missing_or_stale(..., reuse_fingerprint=None)`:None → 读 config 默认;
显式传值覆盖(供单测)。

## 0. 背景与目标

16 日 shadow AB 已证明 v2r(v2 强度打底 + screen≥2 召回)**安全、轻微 α-accretive**,但样本太薄
(仅 2 天买入结构变、2 个新增买入样本),证不了显著 α。用户拍板走 **A:接每日 forward 影子跑,
持续攒样本外证据,不切 live**。

**本线目标**:建一条**无人值守、每交易日增量**的 forward 影子跑接线:每交易日盘后自动
① `build_pool_v2r` 建当日候选池 → ② 对候选池跑 DeepSeek headless 研判 → ③ shadow_score 记分 →
④ 把 {日期 / 池 / 买入侧 / 研判 / 待回填前向标签} 追加进 **forward 证据库**,供将来 forward 收益
结算后算**样本外 α**。

## 1. 铁律(硬约束,贯穿全实现 + 测试锁死)

1. **纯影子 / 不接 live**:绝不写 live 选股产物(`data/analysis/<日>/每日选股.json`)、绝不动
   live 选股 SKILL / model_registry live 路径 / write_picks live 路径 / 任何生产选股定时任务。
   只写自己的影子证据目录。
2. **不碰定时任务排期**:绝不 `launchctl load/unload`、绝不改其它现有定时任务 cron。
3. **防未来(硬)**:当日跑只用当日盘后已披露数据;前向标签(T+1/T+5)将来结算再回填,
   决策时点绝不看未来。
4. **防数据偷看**:池逻辑冻结(v2r,不调参);forward 只**记录**不调参。

## 2. 触发方式(默认按统筹指定:闭环追加 + tasks.yaml 登记)

**默认方案(推荐)**:把接线做成 `python -m tools.run shadow_forward`(单元化,匹配 SSOT 任务单元
约定),并作为现有盘后闭环 `ops/launchd/pull_refresh.sh` 的**最末尾 best-effort、非阻断步骤**追加
(记为 `④ shadow_forward`,置于 `③ 上传远端` 之后 —— 影子跑不需上传,放最后不拖累上传窗口)。

- **为何追加进该闭环**:它已每交易日盘后跑、① 主档 + ② screenall(产 council/record,v2r 的输入)
  已就绪、且已为 LLM 步骤 source 网关 env(DeepSeek 调用直接继承 `LLM_BASE_URL/LLM_API_KEY`)。
- **非阻断**:`|| echo "!! shadow_forward 失败(不阻断)"`,与 ①.5/①.6/①.7 同型。
- **同时声明式登记进 `tools/scheduling/tasks.yaml`**(SSOT 留痕,为将来 P3 切换)。
  ⚠️ tasks.yaml 当前是 **P1 影子期 dry-run 排期**,不替代/不改动 live launchd —— 登记仅留痕,
  实际每日执行靠上面的闭环追加。登记条目 `enabled: true`(参与影子排期一致性观察),cron 对齐闭环
  盘后时点。

**备选(不采用,列此供 review)**:独立 launchd plist / 独立 `scheduled-tasks` MCP 定时。
不采用理由:① 会新增一个 live 定时任务(触碰"不动定时任务"红线的灰区);② 无法复用闭环已
source 的网关 env,需自己再解析一遍;③ 与闭环并行跑同一批 DeepSeek,时序/数据竞争更难保证。
闭环追加最干净。

## 3. 模块划分与输入输出(先框架后实现)

### 3.1 新模块 `tools/analysis/shadow_forward.py`(核心逻辑,可单测,无 CLI)

与既有 `shadow_run.py`/`shadow_score.py` 同族、复用其函数,零改动它们。函数:

| 函数 | 输入 | 输出 | 职责 |
|---|---|---|---|
| `run_forward_day(date, data_root, evidence_dir, provider, exp_base=None, think=None, force=False)` | 交易日、分析根、证据根、provider | dict 摘要 | 建 v2r 池 → DeepSeek 研判全池 → 写当日证据(labels 待回填)→ 返回 {pool_size, n_buy, n_calls, ...} |
| `backfill_labels(evidence_dir, horizons=(1,5))` | 证据根 | dict {n_filled, ...} | 遍历全部**未结算**证据日,对每票用主档 K线回填**已到期** r_1/r_5(未到期留 null);幂等 |
| `forward_alpha(evidence_dir, scorecard_path, horizons=(1,5))` | 证据根、记分卡 | dict α 汇总 | 复用 `shadow_score` 逻辑,对已结算证据算样本外 α(买入侧 & 看多方向侧,诚实标 N/SE) |
| `append_index(evidence_dir, day_summary)` | 证据根、当日摘要 | — | 追加一行到 `_index.jsonl`(人读脊柱:date/provider/pool_size/n_buy/buy_side/label_status) |

**前向收益口径(canonical,与 forward_scorecard 完全一致,无未来函数)**:
`r_N = (close[idx+N] / close[idx] - 1) * 100`,`close` 来自 `tools.collectors.market.load_kline(code)`,
`idx` = 该票 K线中 date==信号日 的行下标。`idx+N >= len(close)`(未到期)→ 留 `null`。
复用主档口径 → **买入侧全覆盖**(不受 forward_scorecard 只含 live picks 的限制)。

**基准(benchmark)**:α = mean(买入侧 r) − 全A等权基准。基准取当日 `forward_scorecard.csv` 全样本
r 均值(闭环 ②.5 刚产出、`shadow_score` 已复用此口径、与 16 日 AB 同源)。⚠️ 该基准是 picks 样本
对全A的代理,与 AB 同一局限,报告中显式标注。

### 3.2 证据库格式与落点

- **落点**:`<repo>/data/shadow_forward/`(**新增 gitignore 条目**;闭环里 = dailyjob worktree 自己
  滚存,`reset --hard origin/main` 只重置 tracked、不动此未跟踪目录 → 证据逐日累积,与
  forward_scorecard 滚存同机制)。
- **每日自包含文件** `evidence_<date>.json`:
  ```jsonc
  {
    "date": "2026-09-14", "version": "v2r", "provider": "deepseek_v4pro",
    "generated_at": "2026-09-14T16:30:00", "code_commit": "<sha>",
    "pool": ["600000", ...],
    "pool_meta": { base_pool_size, recall_added, recalled:[...], ... },   // build_pool_v2r meta
    "units": [ { code, stance, dir_1d, dir_5d, key_reason, ... } ],        // deep_analysis units 原样
    "buy_side": ["600000", ...],                                          // stance ∈ {买入,可参与}
    "labels": { "600000": { "close_0": 12.3, "r_1": null, "r_5": null } },// 待回填
    "label_status": "pending"                                             // pending|partial|settled
  }
  ```
  `close_0`(信号日收盘)决策时点即写(当日已披露,不含未来)。r_1/r_5 由 `backfill_labels` 就地回填。
- **`_index.jsonl`**:每日一行摘要,append-only,供快速扫描 / 将来 α 结算脚本读。

### 3.3 CLI 挂载 `cmd_shadow_forward(argv)`(run.py,薄封装)

薄封装(仿 `cmd_findata` 的委托 + `deep_analysis.main` 的直接落盘风格):解析
`--date`(默认今日)、`--data-root`(默认 `<cwd>/data/analysis`)、`--evidence-dir`
(默认 `<cwd>/data/shadow_forward`)、`--provider`(默认 `deepseek_v4pro`)、`--experience-base`、
`--think`、`--force`、`--no-backfill` → lazy import `shadow_forward` → 依次
`run_forward_day` → `backfill_labels`(把今天之前已到期的历史证据补上)→ `forward_alpha`(打印当前
样本外 α 快照,best-effort)。注册进 `_CMDS` 字典加一行 `"shadow_forward": cmd_shadow_forward`。

**一条命令 = 当日新证据 + 历史到期回填 + α 快照**,即"无人值守增量攒证据"闭环。幂等
(当日 evidence 存在且非 --force 则跳研判;回填只填 null、已填不动)。

## 4. 测试(约法6,tests/test_shadow_forward.py,mock DeepSeek 不真调)

锁住"为什么改"的语义:
1. **dry-run 非 live**:跑一日后断言**未**写任何 `data/analysis/<date>/每日选股.json` / live 路径;
   只写 `evidence_dir` 下文件。
2. **证据可追加 + 幂等**:同日跑两次不重复/不损坏;`_index.jsonl` 行数正确。
3. **防未来**:构造一票 K线只到信号日(无 T+1)→ 回填后 r_1 保持 null;有 T+5 数据 → r_5 正确
   等于 `close[idx+5]/close[idx]-1`。
4. **买入侧口径**:`buy_side` == stance ∈ {买入,可参与}。
5. **前向收益口径**:`backfill_labels` 算出的 r_N == canonical `close[idx+N]/close[idx]` 公式。
6. **α 复用 shadow_score**:`forward_alpha` 在小样本上与手算一致,诚实标 N。

测试用 monkeypatch 替 `deep_analysis.generate`(返回假 units)+ 假 `market.load_kline`(注入可控
K线),不触网、不烧 token。用 conda env `~/.conda/envs/stock_analysis/bin/python` 跑。

## 5. 验证(实现后本地手跑一日 dry-run)

真调 DeepSeek 走 `zsh -ic`(继承网关 env);`--data-root` 指主仓生产 `data/analysis`(只读),
`--evidence-dir` 指 scratchpad 隔离目录(不污染生产)。验证:池建了、DeepSeek 研判了、证据写了、
`data/analysis/<date>/` 下**无** live 选股产物新增、回填对历史已结算日生效。

## 〇、总设计回顾(一句话)

远端网页加/删自选 → **不写** `config/stock_pool.json`(会被 5min `reset --hard` 抹),改**写 DB 表 `pool_pending`**(不随 git);本地闭环经 `/pull?kind=pool_pending` 拉走提案 → 合并裁决 → `add_and_collect`/`remove_and_cleanup`(本地有 raw,panel 不塌)→ `upload` 把完整产物 + **回执(已消化 pending id)搭同一次签名上传**推回远端 → 远端标 `consumed`。名单真源恒为本地 `config/stock_pool.json`,远端 pending 是提案队列。

数据流:
```
[远端 web POST /api/pool(enqueue 模式)] → pool_pending 表(status=pending)
        ↑                                          ↓ (GET /pull?kind=pool_pending, 签名)
[远端 ingest /pull]                          [本地 pull.py → data/sync_receipts/pool_pending.json]
        ↑ 标 consumed                               ↓
[远端 ingest /ingest 收到 __pool_ack__ 分片] ← [本地 consume→合并裁决→add/remove→upload(带 __pool_ack__)]
```

### 2.2 `tools/sync/pool_merge.py`(新增)—— 纯函数,合并裁决(§单测重点)

实现 scoping §2.2(c)的"并集 + 时间戳裁决删除",**无任何 IO**,便于锁语义:
```python
@dataclass
class DigestionPlan:
    to_add: list[dict]            # 需 add_and_collect 的 pending 行
    to_remove: list[dict]         # 需 remove_and_cleanup 的 pending 行
    noop_consumed_ids: list[int]  # 无需动作、已裁决即可标 consumed 的 id(幂等/已存在/已删除/被更晚add压制)

def plan_digestion(pending_rows: list[dict],
                   local_index: dict[tuple[str, str], str]) -> DigestionPlan
    # pending_rows: list_pending() 的结果(须按 requested_at 升序)。
    # local_index: {(code, market): added_at_iso} —— 本地池现状(见 2.4 added_at)。
    # 裁决规则(按 requested_at 升序逐条):
    #   op=add:
    #     - key 已在 local_index → noop_consumed(幂等,已存在)
    #     - 否则 → to_add;并把 key 记入 local_index[key]=requested_at(使后续更早的 remove 被压制)
    #   op=remove:
    #     - key 不在 local_index → noop_consumed(已不在池,无需删)
    #     - key 在且 requested_at > local_index[key] → to_remove;从 local_index 删 key
    #     - key 在但 requested_at <= local_index[key] → noop_consumed(被更晚的 add 压制,防误删)
    # 不变式:每条 pending 恰被裁决一次 → to_add∪to_remove∪noop 的 id 覆盖全部输入行(无遗漏、无重复)→ 保证不会无限重拉。
```
- **执行侧消费规则**(在 consume_pool_pending.py):`noop_consumed_ids` 立即可标 consumed;`to_add`/`to_remove` 的行**仅在 add_and_collect/remove_and_cleanup 成功后**才追加进 consumed(失败保留 pending,下轮重试——scoping §五.1)。

### 2.4 `tools/config/stock_pool.py`(改)—— `Stock` 加 `added_at`(删除裁决必需)

**为什么改**:scoping §2.2(c)的删除时间戳裁决需要"本地该票最近一次 add 的时间",而当前 JSON 无时间戳。给 `Stock` 加一个**向后兼容**字段:
```python
@dataclass(frozen=True)
class Stock:
    code: str
    name: str
    industry: str
    sector: str
    market: str = "A"
    added_at: str = ""     # 新增:ISO 时间戳,加票时刻。缺省"" → 视为"很早"(远端 remove 可正常裁决)
```
- **向后兼容性**:旧 `stock_pool.json` 条目无 `added_at` → `Stock(**d)` 用默认 `""`(dataclass 默认值,不报错);`_SEED` 条目同理默认 `""`。
- `add_stock(...)`:构造 `Stock(...)` 时 `added_at=datetime.now().astimezone().isoformat(timespec="seconds")`。
- **读接口签名不变**(get_pool/get_codes/by_sector/get 全不变)→ 上层 run/analysis/collectors/web 零影响(符合方案2 §非目标)。`asdict` 持久化自动带上新字段。
- `local_index` 构造:`{(s.code, s.market): (s.added_at or "")}`;`added_at==""` 时 `requested_at > ""` 恒真 → 远端 remove 对老票可正常生效(合理:老票早于时间戳跟踪期)。

> ⚠️ **待审判断点**:此改动动了核心配置文件的 JSON 格式(加一列)。虽向后兼容且读接口不变,仍请统筹/用户确认。备选(不改 Stock):删除裁决退化为"只在同一批 pending 内 add/remove 时间戳互裁 + 本地已存在即拒删",对"本地刚加、远端旧删"防护弱。**推荐加 `added_at`**(直接实现文档规则、可测)。

### 2.5 `tools/pool_service.py`(改)—— 加 `enqueue_pending()`

```python
def enqueue_pending(op: str, code: str, *, name="", industry="", sector="",
                    market="A", source=None) -> dict:
    """远端模式:把加/删提案写入 pool_pending 表(不采集不重建)。返回 {ok, queued:{...}, note}。
    轻校验:op∈{add,remove}、code 非空;深校验(格式/重复)留给本地消化时的 add_stock。"""
    from tools.sync import pool_pending_store
    from tools.config import settings
    src = source or settings.POOL_PENDING_SOURCE
    rid = pool_pending_store.enqueue(code=code, name=name, industry=industry,
                                     sector=sector, market=market, op=op, source=src)
    return {"ok": True, "queued": {"id": rid, "op": op, "code": code, "market": market},
            "note": "已提交,将于下次本地闭环采集后生效(非实时)"}
```
- 现有 `add_and_collect`/`remove_and_cleanup`/`collect_one`/`rebuild_artifacts` **完全不动**。

### 2.8 `tools/sync/pull.py`(改)—— 按 kind 分发落缓冲

现状 `signed_get` 成功后 `if kind != "kline": return 不支持`(line 174-175)。改为按 kind 分发:

```python
    n, max_date = _persist_kline(data)

def _persist_pool_pending(rows: list) -> Path:
    """把远端 pending 行写本地缓冲(整份覆盖,供 consume 读)。返回路径。"""
    p = _receipt_dir() / "pool_pending.json"
    p.parent.mkdir(parents=True, exist_ok=True)
    tmp = p.parent / (p.name + ".tmp")
    tmp.write_text(json.dumps({"pulled_at": _now_iso(), "rows": rows}, ensure_ascii=False, indent=2), encoding="utf-8")
    tmp.replace(p)
    return p
```

### 2.10 `ops/consume_pool_pending.py`(新增)—— 本地闭环编排

```python
def consume(*, url, token, key, key_id, dry_run=False) -> dict:
    """本地闭环一步:拉远端 pending → 合并裁决 → add_and_collect/remove_and_cleanup → 返回待回执 consumed_ids。
    返回 {pulled, added, removed, failed, consumed_ids}。失败项保留 pending 下轮重试。"""
    # ① pull
    from tools.sync import pull as pullmod
    from tools.sync import pool_merge
    from tools.config import stock_pool
    from tools import pool_service
    res = pullmod.pull("pool_pending", url=url, token=token, key=key, key_id=key_id)
    rows = _read_buffer()   # data/sync_receipts/pool_pending.json → rows
    # ② 构造 local_index + 裁决(纯函数)
    stock_pool.reload()
    local_index = {(s.code, s.market): (s.added_at or "") for s in stock_pool.get_pool()}
    plan = pool_merge.plan_digestion(rows, dict(local_index))
    consumed = list(plan.noop_consumed_ids)
    # ③ 执行(仅成功才 consume)
    for r in plan.to_add:
        try: pool_service.add_and_collect(r["code"], r["name"], r["industry"], r["sector"], market=r["market"]); consumed.append(r["id"])
        except Exception as e: log.error(...)   # 保留 pending
    for r in plan.to_remove:
        try: pool_service.remove_and_cleanup(r["code"]); consumed.append(r["id"])
        except Exception as e: log.error(...)
    return {..., "consumed_ids": consumed}
```
- CLI:`python -m ops.consume_pool_pending`(读 settings 的 SYNC_* + POOL_*)。`--dry-run` 只裁决打印不执行。
- **回执发送**:consume 完成后由 `pull_refresh.sh` 接着跑 `upload_date(date=today, pool_ack_ids=consumed)`(或 consume 内部直接调 upload)。**推荐 consume 只产出 consumed_ids,由闭环脚本编排 upload**(职责单一,便于测试)。

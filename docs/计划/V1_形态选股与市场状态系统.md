## 一、原始需求（定稿规格 · 忠实转述）

来源：产品/策略方定稿《智能投研系统 V1 需求规格说明书 V1.0》。核心原则原文：**先跑通流程，后精细优化；重逻辑落地，轻过度拟合。**

### 1.1 总体架构与数据流

- **运行模式**：V1 不做实时流计算，采用**盘后批处理**。调度频率：每日**午间（收盘后）一次 + 晚间（收盘后）一次**。
- **模块耦合（关键）**：
  - **模块二（选股）先执行** → 扫描全市场 → 计算「图形达标占比」→ 写入数据库。
  - **模块一（择时）后执行** → 读取模块二输出的「达标占比」作为**宽度信号**，结合行情数据 → 输出当日**市场状态标签**。
- **数据源策略**：
  - **主源：Tushare**（已有 **6000 积分 Token**，优先使用）。
  - **备源/补充：AkShare**（Tushare 缺失或异常时回补）。
  - **历史区间**：回测与参数标定使用**近 3 年数据（2021–2024）**。

### 1.2 模块一：Market Regime（市场状态识别）

1. **指数趋势判断（择时开关）**——界定试错窗口 / 避险窗口：
   - 企稳/试错窗口：`MA5 > MA10 > MA20`（MA5 上穿 MA10 且 MA5>MA20，MA10 上穿 MA20）。
   - 减仓/避险窗口：`MA5 < MA10 < MA20`（反之）。
2. **科技共振模块（核心板块跟踪）**：
   - 选样范围：**总市值 > 2000 亿的科技股**（重点覆盖 AI 产业链，适应牛市下半场特征）。
   - 分类口径：**暂不使用静态行业/概念板块**（申万、东财等更新滞后）；V1 由**策略端维护一个「核心龙头池」**（硬编码或手动更新），捕捉资金对重大事件（如跨界收购）的反应。后续迭代再接舆情 NLP 动态归类。
   - 共振信号：观察上述高市值科技股的联动涨跌。
3. **情绪评分模型（0–100）**：
   - **权重：各因子暂时平权。**
   - 输入因子：① 指数多头（上述 MA 信号）；② 科技共振（科技股涨跌同步性）；③ 量能（当日成交额较昨日的放/缩量 + 当前量能相对历史天量的比值）；④ 宽度（模块二回传的全市场图形达标占比）；⑤ 反向熊市（涨跌停家数统计，作市场股性/活跃度基因指标）。
   - **状态分档**：按总分划分**五档（牛市共振 / 分化 / 震荡 / 熊市共振 / 冰点）**，**具体边界待数据跑出后按分布划定**。
4. **V1 裁剪**：融资余额**不纳入**；北交所**不覆盖**。

### 1.3 模块二：图形审美选股（形态识别）

1. **形态识别引擎**：支持**可配置**的形态识别，包括但不限于**欧奈尔杯柄（Cup with Handle）/ 箱体整理（平台突破）/ 楔形（Wedge）/ 旗形（Flag）**。实现方式：先用代码仿真实现几何形状匹配，**参数（杯深、回撤幅度等）落地 Config 文件**便于后期调整。
2. **相对强度 RS（核心重点）**：① 个股 vs 所属行业板块；② 板块指数 vs 沪深 300。算法：暂用 **20 日收益率差值**（个股收益 − 基准收益），后续视效果升级为 **Rank（分位）** 模式。
3. **达标判定逻辑**：**硬规则（AND）**——必须同时满足：**特定形态完成 + RS 强度达标 + 成交量配合 + 通过护栏过滤**。输出：每日「达标股票池」。
4. **风险控制（护栏）**：
   - 估值：**PE（TTM）处于该股市盈率分位数 >90%（极度高估）则剔除**。
   - 业绩：**净利润同比增速为负则剔除**。
   - 合规：数据源 = 巨潮公告、交易所官网、互动易；规则 = **近期出现监管函/问询函/财务造假相关公告则坚决剔除**。
5. **个性化偏好**：均线系统默认 **MA5/10/20/60**；**MA13/MA144（斐波那契周期）为可选，默认关闭**。
6. **票池与算力**：覆盖**全 A 股（5000+ 只）**；处理时机 = **每日午间及收盘后批量扫描**。

### 1.4 验收标准（DoD · 定稿原文）

- **模块一**：能稳定输出每日市场状态标签（如「震荡」「牛市共振」）；情绪分变动原因**可追溯**（Debug 日志可见各因子贡献）。
- **模块二（核心）**：
  - 有效性验证（回测）：重点考核**前瞻胜率**——统计「图形达标」股票在未来 **5 日/10 日/20 日的上涨概率及平均收益率**；要求**达标池整体表现显著优于同期沪深 300（Alpha > 0）**。
  - 形态检出：能**肉眼复核**程序选出的图形确实符合「杯柄」「箱体」等经典定义。

### 1.5 技术债与后续优化（定稿备忘，非 V1）

科技板块动态分类（舆情驱动）为 V2 重点；形态参数需随市场生态动态调优；RS Rating（全市场分位排名）替代简单收益率差。

## 二、要实现哪些功能（可验收功能点）

> 按**耦合顺序**排列：数据接入 → 模块二（先跑）→ 模块一（后跑，读宽度）→ 回测验收。每条可判断「做没做完」。

### 2.0 数据接入（地基，模块二/一共用）

- [ ] F0.1 Tushare 采集适配：新增走 Tushare Pro 的采集器（`ts.set_token`），拉**全 A 日 K + 每日基本面（PE_TTM/总市值/净利增速）**，落 `data/raw/`，走 store 层。验收：能拉齐一个交易日全 A 快照 + 任一票近 3 年日 K，字段归一到项目标准列。
- [ ] F0.2 指数采集：沪深 300 及所需指数日 K（模块一 MA 判定 + 模块二 RS 基准）。验收：`index_daily` 口径落库，字段过契约。
- [ ] F0.3 板块指数 + 成分采集：供模块二「个股 vs 板块」RS 与板块归属。验收：能给出任一票所属行业板块 + 板块指数日 K。
- [ ] F0.4 市场宽度采集：全 A 快照（红盘家数/成交额）+ 涨跌停家数。验收：任一交易日能算出全市场成交额、涨跌停家数。
- [ ] F0.5 AkShare 备源降级：F0.1–F0.4 每项在 Tushare 异常时可切 AkShare 回补，落 `provenance.source` 记实际命中源。验收：手动断开 Tushare 时链路不崩、能回补。

### 2.1 模块二 · 图形审美选股（先跑）

- [ ] F2.1 形态几何识别引擎：`杯柄/箱体/楔形/旗形` 四类，输出可计算特征 + 是否达标 + 命中形态名；**所有几何参数（杯深、杯宽/时间窗、手柄回撤、突破放量倍数、箱体高度、楔形收敛角等）落 Config，可配可调**。验收：对构造样例（人工造的标准杯柄/箱体序列）返回预期命中；参数改 Config 后行为随之变。
- [ ] F2.2 相对强度 RS：个股 vs 板块、板块 vs 沪深 300，**20 日收益率差**；接口预留 Rank 升级位。验收：给定序列 RS 数值与手算一致；RS 达标阈值落 Config。
- [ ] F2.3 护栏过滤：PE(TTM) 分位 >90% 剔除、净利同比增速为负剔除、近期监管函/问询函/造假公告剔除。验收：三条各有独立可关开关 + 命中即出局，剔除原因可追溯。
- [ ] F2.4 硬规则 AND 达标判定：`形态完成 AND RS 达标 AND 量能配合 AND 过护栏` → 每日「达标股票池」。验收：任一条不满足即不达标；达标票可导出清单。
- [ ] F2.5 均线偏好：默认 MA5/10/20/60；MA13/MA144 可选、默认关。验收：开关切换生效。
- [ ] F2.6 全市场图形达标占比落库：扫全 A → 达标数 / 有效样本数 → 写入**市场级记录**供模块一读取。验收：产出当日占比数值 + 达标明细，落盘过契约。

### 2.2 模块一 · Market Regime（后跑，读宽度）

- [ ] F1.1 指数趋势开关：指数 MA5>MA10>MA20（试错）/ 反之（避险）判定。验收：给定指数 K 线返回正确窗口标签。
- [ ] F1.2 科技共振：读**核心龙头池**（config，手动维护）+ 总市值 >2000 亿科技股，算联动涨跌同步性。验收：龙头池为空/缺票时降级不崩；同步性数值可复算。
- [ ] F1.3 情绪评分 0–100：五因子（指数多头/科技共振/量能/宽度[读 F2.6]/涨跌停）**平权**加权。验收：各因子子分 + 总分 + 权重全部落 Debug 日志（可追溯）。
- [ ] F1.4 五档状态标签：牛市共振/分化/震荡/熊市共振/冰点，**边界读 Config**（初值待数据标定，先给一版经验/等分边界跑通）。验收：能稳定输出每日标签；边界改 Config 后分档随之变。
- [ ] F1.5 市场级契约落盘：情绪分 + 各因子贡献 + 标签 + 达标占比，按日期分区落 `data/analysis/market/{date}.json`（或等价），过契约校验。验收：`validate_record` 通过；Web/回测可只读。

### 2.3 回测验收（收尾）

- [ ] F3.1 前瞻胜率统计：对历史每日达标池，统计未来 5/10/20 日上涨概率 + 平均收益，与同期沪深 300 对比 Alpha。**防未来函数**（只用达标日当时可见数据）。验收：输出三个窗口的胜率/均收益/超额；Alpha>0 显著性可报。

## 三、实现计划

### 3.1 分期 / 依赖顺序（⭐）

严格按定稿耦合链：**数据接入 → 模块二 → 模块一 → 回测验收**。四期串行依赖（后期依赖前期产物），期内子任务可并行。

| 期 | 内容 | 依赖 | 交付物 |
|---|---|---|---|
| **P1 数据接入** | Tushare 采集适配 + 指数/板块/宽度 collector + AkShare 备源 | 无（地基） | 全 A 日 K/基本面、指数、板块+成分、宽度 落 `data/raw/`；市场级契约 schema 草案 |
| **P2 模块二选股**（先跑） | 形态引擎 + RS + 护栏 + 硬规则 AND + 达标占比落库 | P1 | 每日达标池 + 全市场达标占比落市场级记录 |
| **P3 模块一择时**（后跑） | 指数趋势开关 + 科技共振（读龙头池）+ 情绪 0–100 平权 + 五档标签 | P2（读 F2.6 达标占比当宽度） | 每日市场状态标签 + 各因子贡献 Debug 日志 |
| **P4 回测验收** | 前瞻胜率 5/10/20 日 + Alpha>0 显著优于沪深 300 | P2（历史达标池）、P1（沪深 300 历史） | 前瞻胜率报告 + Alpha 显著性 |

> 备注：P2「先于」P1 是**运行时耦合顺序**（盘后先跑模块二出占比、再跑模块一读占比）；开发上 P1 地基必须最先。P2/P3 期内的独立子任务（如四类形态各自实现、三条护栏各自实现、采集器各源）可解耦并行。

### 3.4 关键落地注意点

- **前瞻胜率 ≠ 现成 BT.1，也不是完整 BT.2**：BT.1 只做「信号」类回测，`kind="选股"` 直接 `raise NotImplementedError`（缺历史时点记录快照，会引未来函数）。前瞻胜率是**事件级前向收益统计**——只需「历史每日达标池 + 各票未来 N 日收益」，比完整选股组合回测轻。**F2.6 每日落库达标明细**天然提供了这份历史时点快照，正好喂 F3.1。复用 BT.1 的**防未来函数纪律 + metrics 度量**，但需新增一个 forward-return 统计入口（不要硬套 `backtest()`）。
- **达标占比是模块一↔模块二唯一耦合字段**：落在市场级记录，模块二写、模块一读，双方不互相 import（守分层单向依赖）。

### 6.2 我识别的最大 2 个风险

1. **【最大】Tushare 6000 积分对全 A 每日扫描的接口限频 / 算力**：定稿把主源从我方基座（akshare）改为 **Tushare 主**，但 Tushare Pro **多数接口有每分钟/每日调用上限与积分门槛**，且历史上发生过突发停运。全 A 5000+ 只 **× 近 3 年日 K × 每日午间+晚间双窗口**扫描，可能撞限频、或在盘后窗口内跑不完。**P1 必做前置实测**：Tushare 6000 积分对 `daily`/`index_daily`/`daily_basic` 的实际限频与全市场批量耗时；跑不动则按定稿的 AkShare 备源降级 / 分批分时拉取。**这是本轮头号落地风险。**
2. **形态几何引擎的可计算边界 + 核心龙头池人工维护**：杯柄/箱体/楔形/旗形**无业界唯一定义**，定稿只说「参数落 Config」却**未给初值**（#8），几何阈值定不好会导致检出漂移、肉眼复核不过；同时科技共振依赖的**核心龙头池靠手动维护**，存在滞后与主观性（漏一只龙头、或旧龙头未剔除都会扭曲共振信号）。两者都需策略端持续投入拍板，是「重逻辑落地」阶段的主要不确定性。

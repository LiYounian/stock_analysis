## 一、消息面前移到候选池(最高优先级 · 项目根本特色)

### 现状(问题)
- 全A 只对 ~30 只重点池采新闻(`baidu_news/news` 各 ~40),`tick/chip/fundflow` 各 ~28-30。
- 结果:合议 Top-20 里 **情绪三层 / 事件驱动 / 资金流 三个专家全部弃权**(数据缺失),消息面**没进入策略打分**。
- 消息面只在分析师手工层、对最终 5 只做了。

### 目标(用户硬要求)
> 基础选股选出 ~40-50 只候选后,**对这批候选全部采集消息面 + 跑 AI 分析**,再据此做最终选股。消息面是本项目根本,必须跑。

### 实现方案
1. **新增"候选池消息面富集"节点**:基础策略(合议/各策略)跑完出候选后,取**并集候选 ~40-50 只**(合议 Top-N ∪ 各策略入选),对这批:
   - 采集 `baidu_news`(as-of 切片,防未来)+ 必要的公告;
   - 跑 `news_ai`(LLM 逐条方向/理由)+ `sentiment`(情绪三层)+ 事件专家。
2. **回灌合议**:让情绪三层/事件驱动专家对候选池**发声**(不再因数据缺失弃权),消息面进入合议二次排序 / 或作为独立"消息面确认层"标注。
3. **产物**:候选池每只都有 news_ai/sentiment code_view → 展示页有新闻;选股决策带消息面。
4. **成本控制**:只对候选 ~40-50 只跑 LLM(非全A),分钟级、可控;绝不走全A财报重抓的 20h 路。

### 待定(需你拍板)
- 候选池口径:合议 Top 多少 ∪ 哪些策略?(建议 Top-30 ∪ 各策略前几)
- 消息面是"进合议打分"还是"独立确认层"?(建议先做独立确认层,风险低、可解释)

## 三、选股分析页改版(`/selection-analysis`)

### 现状
- 读 `data/reports/选股分析/*.md`(为"定向分析"设计),与每日报告目录 `docs/每日分析/{选股,复盘}/` **不一致** → 页面空。

### 改版目标(按你的三条)
1. **布局:三区** —— 每日盘后选股 / 盘中选股(预留,后续加)/ 盘尾选股。三块都留位。
2. **每区内容:两项** —— "选股分析" + "复盘结果"。文本**精简**(不堆当前报告的全文)。
3. **模块评估** —— "大盘分析"是否放这里待定(倾向:大盘分析归"今日概览"首页,选股分析页聚焦个票选股+复盘)。

### 实现要点
- **数据上传**:把 `docs/每日分析/选股/<date>.md` 与 `复盘/<date>.md` 摘要(或精简版)纳入上传管线,作为一类 `__view__:selection_analysis` 或专用报告分片推到远端,`/selection-analysis` 从远端库读。
- **精简**:上传前对报告做"摘要抽取"(排序表 + 关键表态 + 复盘结论),不传全文。
- 盘中选股区暂空、留占位。

### 待定(需你拍板)
- 精简到什么粒度?(建议:选股=买入建议排序表+每只一句话;复盘=记分表+经验条目标题)
- 三区数据来源:盘后=`选股/`,盘尾=后续日内循环产出,盘中=预留。

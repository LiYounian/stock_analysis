## 因子二：股票解禁 【数据最全，优先级 #1】

### (a) 数据源核查 —— ✅ 现成、结构化、已 date-pin
真实字段：`per-stock json → financing.解禁`（`tools/collectors/equity_financing.py` 采、`serialize.py:349` 组装、run.py:237 每日按需刷）。实测结构（000504）：

```
financing.固定一问.有临近解禁_90日 : bool
financing.解禁 = {
  "未来次数", "未来90日次数",
  "未来90日占流通_pct",        # 优先 em 占流通市值%，缺退总股本折算
  "不可采信次数",               # 自洽性护栏：股数超现存限售股上限 → 不计入占比
  "下一次": {解禁日期, 数量, 占比…} | null,
  "明细": [...]
}
financing.定增.明细[].解锁日      # 历史定增锁定期解锁日（辅助）
```

- **防未来合规**：equity_financing 头注明确——解禁时间表含未来日期是**合法的**（"已披露的未来安排"，非未来价格）；逐条按 `披露日 ≤ as_of` 闸门；em 的 `解禁后20日涨跌幅`/`解禁前收盘价` 等前视列**归一阶段直接丢弃**。双源 sina(带披露日)+em(字段丰富)就近匹配，含**不可采信护栏**（sina 报某批远超现存限售股即标 `不可采信`，不计入占比）。
- 采集频率：低频（月级），30 天缓存，票上出现解禁公告时 `force=True` 定点刷（run.py:237 `is_stale` 判定）。
- 覆盖实测：2026-09-17 的 84 只样本 `未来90日次数` 命中 0——不是数据缺，是这批票近期无解禁；**结构完全可用**，一旦有临近解禁的票就有值。

> 结论：**四因子里数据最完备的一个，零新增采集。**

### (b) 信号定义（写死档位 + 语义锁）
两维合成 → `解禁嫌疑档`（负向）：**剩余天数** × **占流通比例**。

```
剩余天数 = 下一次.解禁日期 - as_of （自然日；下一次为 null → 无临近 → "无嫌疑"）
占比 = 未来90日占流通_pct（缺 → 用 下一次.占比；再缺 → 标 missing 走保守"低"）

解禁嫌疑档（写死）:
  无临近解禁(未来90日次数=0 或 下一次=null)          → 无嫌疑（不扣分）
  占流通 < 3%                                        → 低
  3% ≤ 占流通 < 10%  且 剩余 ≤ 30 日                 → 中
  占流通 ≥ 10%       且 剩余 ≤ 30 日                 → 高危（veto 候选）
  其余（占比大但剩余 30~90 日 / 占比中但剩余远）      → 低~中（按剩余天数档微调）

剩余天数档（辅助渲染，不单独定档）: ≤15 / ≤30 / ≤60 / ≤90
不可采信次数 > 0 → 浓缩块标注"含不可采信解禁批次(口径存疑)"，占比只用可采信部分
```

阈值取值理由（复盘可调）：占流通 10% 是"大额解禁"业界粗线；30 日窗对应套现窗口临近；`财report_redflag` 也用"高危可 veto、中/低降分"两段式，保持一致。

### (c) 接入点 —— 新工具 + 接排雷子分 + veto
- **新建工具** `tools/pyramid/tools/unlock_risk_tool.py`，`name="unlock_risk"`，`塔层="②消息"`（塔层枚举合法值，解禁属公司行为/消息面）。形态**照 `financial_redflag_tool`**：读 `financing.解禁` → `格档` → 浓缩块 ≤8 行 + `fields={"解禁嫌疑档","剩余天数","占流通pct","下一次日期","不可采信"}`；缺 financing → `嫌疑档="missing"`。
- **改 `d2_compose.py`（供实现窗，本文不动）**：
  - `子分_排雷` 增参 `unlock: dict`，加一张 `_解禁档_扣 = {"高危":100(交给veto), "中":25, "低":10, "无嫌疑":0, "missing":0}`，`s -= _解禁档_扣.get(unlock.get("解禁嫌疑档"),0)`。
  - `veto_reason` 增判：`if unlock and unlock.get("解禁嫌疑档")=="高危": return "大额解禁临近"`。
  - `compose_one` / `build_skeleton` 增 `unlock_t = registry.get("unlock_risk")` 并传入（照 fin 的既有写法）。
- 复用而非新建：解禁原料已在 financing，工具是**薄封装 + 档位**，不重采。

### (d) 权重/口径建议（临时）
- 不新增第 6 基石；解禁并进 **排雷子分（0.15）**，`中=-25 / 低=-10`；`高危` 直接 veto。
- 复盘调法：D3 记分引擎对"临近解禁票"做 forward（解禁日前后 D0..D+K 收益），若"中档"票解禁后系统性跑输沪深300，则把 `中` 扣分调深或降 veto 门槛到占流通 8%。

### (e) 优先级 + 工作量
- **优先级 #1**（数据最全、防未来已解决、护栏已就绪）。
- token：input ~15–20K（读 financial_redflag 样板 + financing 结构 + 写 3–4 处 d2_compose 接线），output ~6–8K（工具 + 语义锁测试）。
- agent 执行：**约 1.5–2 小时**（工具 + 5~7 条语义锁测试 + 用几只真有解禁的历史票做覆盖对验证 + 审阅来回）。

## 因子一：股东减持 【事件源现成但仅标题，v1 可立即做 / v2 需新采】

### (a) 数据源核查 —— ⚠️ 部分现成（标题级），量化需新采
- **现成（v1 用）**：`per-stock json → events`（`serialize.py:418` 由 `announcement` 采集器组装）。`announcement.py:27,35` 已把标题关键词打标为 **`减持` / `权益变动` / `一致行动人`**，`impact_hint` 对"减持"判 **利空**（announcement.py:45 `_BEARISH` 含"减持"）。每条 event = `{date, type, impact, title, summary}`。采集器每日跑（run.py:216），窗口 = `NEWS_LOOKBACK_DAYS`（约 30 天）。
  - 实测：2026-09-17 的 84 只中 events 覆盖 44 只，类型分布见附录；本批 `减持`=0、`增持`=1、`权益变动`=3（减持是**低频事件**，任一 30 天窗多数票为 0，属正常，不是缺数据）。
- **注意区分（任务要求）**：`holder` 块是**股东户数**（最新股东户数/户数环比/连续减少期数，实测口径 2026-09-09 陈旧），是"散户拥挤度"代理，**不是大股东减持**；`fundflow` 是"主力"资金轴。三者都不等于"股东减持"——减持只能走 events(公告)。
- **缺口（v2 才需）**：events 仅标题，**无减持规模 / 占流通比例 / 减持主体（控股股东>5%>高管）/ 集中竞价·大宗·协议转让**。`serialize.py:416` 注也点明：协议转让给战投(中性) vs 二级市场抛售(利空) 靠标题/摘要文本区分。量化档位需新增采集：akshare `stock_hold_change_cninfo`（股东增减持）/ `stock_hold_management_detail_em`（高管增减持明细，含变动数量/占比/主体）——**免费公开、本机 akshare 已在用同类接口**，可行性高。

### (b) 信号定义
**v1（零新增采集，标题级粗判）** → `减持嫌疑档`（负向）：

```
候选 events: type ∈ {减持, 权益变动} 且 date 在 as_of 前 RECENT_DAYS(默认30) 内 且 date ≤ as_of（防未来）
命中条数 n；再按标题关键词加权：
  含 {清仓式, 全部, 拟减持…上限} 或 多个>5%股东同期 → 权重高
  含 {协议转让, 引入战投, 一致行动人…增持, 业务协同}  → 中性化（降权，甚至不计）
档:
  无候选                          → 无嫌疑
  1 条常规减持                    → 低
  ≥2 条 或 单条"大额/预披露减持计划" → 中
  "清仓式/控股股东大额减持"标题词  → 高（veto 候选）
```

**v2（新采后量化）**：`减持占流通% × 主体层级 × 减持方式` → 精确档。占流通≥2% 或 控股股东减持 → 中；≥5% 或清仓式 → 高。

### (c) 接入点 —— 新工具（镜像 fake_good_news）+ 接排雷子分
- **新建工具** `tools/pyramid/tools/insider_reduction_tool.py`，`name="insider_reduction"`，`塔层="②消息"`。**形态镜像 `fake_good_news_tool`**（同样读 events + 防未来日期闸 + 标题关键词判据 + 档位），产出 `fields={"减持嫌疑档","命中条数","最近减持日","方式标签","主体标签(v2)"}`；无 events → `missing`。
- **改 `d2_compose.py`**：`子分_排雷` 再加 `reduce: dict` 参 + `_减持档_扣={"高":100→veto,"中":25,"低":12,"无嫌疑":0,"missing":0}`；`veto_reason` 加 `清仓式/控股股东大额减持 → "清仓式减持"`。
- 与"主力/对手盘"解耦：本工具**只看公司股东公告**，不碰 fundflow；对手盘因子（因子三）单独处理资金结构。

### (d) 权重/口径建议
- 并进排雷子分（0.15）；v1 `中=-25 / 低=-12`。协议转让给战投类**降权到 -5 或不计**（避免误杀）。
- 复盘：v1 上线后统计"减持事件票"forward 表现区分方式标签，若"协议转让"确实不利空则固化为不计；有预算再上 v2 量化。

## 因子三：对手盘 【原料最丰富但语义最模糊、部分陈旧，优先级 #3】

### (a) 数据源核查 —— ✅ 多源现成，⚠️ 口径杂 / 部分 stale / 无逐席位
真实字段（每股 JSON，均每日采集）：

| 源块 | 实测字段 | 采集器 | 口径/新鲜度实测 |
|---|---|---|---|
| `chip` | 获利比例/平均成本/成本区间上下沿/集中度90/现价 | chip.py (run.py:219) | 本地 K 线派生，**fresh** |
| `tick` | 总笔数/主买占比/主卖占比/净主动买量/大单笔数 | tdx_l2/tick | 有口径日期 |
| `fundflow` | 今日主力净流入/近5日主力合计/主力连续净流入天数 | fundflow.py (run.py:217) | **陈旧**（实测口径 2026-09-10，落后 as_of 7 天）|
| `lhb_veto` | triggered/direction/net_buy_ratio/days_since/n_recent | risk_veto ← lhb.py | 盘后 T 披露、T+1 生效（防未来 `list_date<as_of` 严格）|

- **重要限制（诚实标注）**：`lhb.py` 归一列**只保留聚合口径**（net_buy/buy_amt/sell_amt/net_buy_ratio/direction），**已剔除全部前视列**，**但也没有逐营业部/游资/机构席位明细**——所以"谁在接盘（游资 vs 机构 vs 散户 net）"这种**逐席位对手盘识别，现有归一数据做不到**，只能给到"龙虎榜净买方向 + 占成交比"的聚合信号。若要真·席位结构，需扩 lhb 采集保留席位维度（akshare 龙虎榜含营业部明细，可采，属新增强）。
- `fundflow` 的"主力"就是任务里说的、要和"股东减持"区分开的那个轴——**对手盘因子用它，但不与减持混淆**。

### (b) 信号定义 —— 合成"对手盘结构档"（承接强 / 中性 / 出货）
多源投票（各子档写死，合成规则写死）：

```
① 筹码抛压（chip）:
   获利比例 ≥ 0.9  → 普遍浮盈、上方抛压重（偏出货）
   获利比例 ≤ 0.5 且 成本区间收敛(上沿/下沿-1 ≤ 0.15) → 底部换手充分（偏承接）
   集中度90 低(<0.10) → 筹码分散（散户接盘特征）
② 主动买卖（tick）:
   主买占比 - 主卖占比 ≥ +10pp → 主动买盘强（对手在卖、主力在收 → 承接）
   ≤ -10pp                    → 主动卖盘强（出货）
③ 主力资金（fundflow，注 stale 降权）:
   主力连续净流入天数 ≥ 3 且 近5日合计 > 0 → 承接
④ 龙虎榜（lhb_veto）:
   direction=+1 且 net_buy_ratio 高 → 榜单资金净买（承接）
   direction=-1                    → 净卖（出货）

对手盘结构档（写死投票 → 三档）:
  承接强: ≥2 项偏承接 且 无强出货项
  出货:   ≥2 项偏出货 或 ①获利比例≥0.9 且 ②主卖强
  中性:   其余 / 多数 missing
stale 源（fundflow）参与但**权重减半**，且浓缩块标 [stale]。
```

### (c) 接入点 —— 新工具 + 并入"量价自证"子分（不新增第 6 基石）
- **新建工具** `tools/pyramid/tools/counterparty_tool.py`，`name="counterparty"`，`塔层="①塔基"`（微结构属塔基量价轴）。读 chip+tick+fundflow+lhb_veto → 合成"对手盘结构档" + 浓缩块。
- **接入 `子分_量价自证`**（不动权重结构）：把"对手盘结构档"作为 `量价自证` 的**加减项**（承接强 +10、出货 -15、中性 0），在 `_clip100` 内。理由：对手盘本质是量价的微结构佐证，归到量价自证(0.30)最自然，避免动 `WEIGHTS` 触发全局重标定。
- **veto 复用**：`lhb_veto` 已是独立 `entry_veto`（risk_veto.lhb_verdict_asof），**已在 serialize 落盘**；金字塔可直接在 veto_reason 里读 `lhb_veto.triggered` 加一条否决（若统筹认可龙虎榜入选否决语义）。
- 复用优先：chip/tick/fundflow/lhb_veto 全现成，工具是**合成器**，零新采（除非上"逐席位"增强）。

### (d) 权重/口径建议
- 并入量价自证；临时"承接强 +10 / 出货 -15"。fundflow 陈旧→其投票权重×0.5。
- 复盘：对手盘"出货档"票 forward 是否系统性下跌？是则加深 -15；tick 口径若太滞后考虑降权或只保留 chip+lhb 两源。

### (e) 优先级 + 工作量
- **优先级 #3**：原料最全但**合成语义最模糊**（"对手盘"无唯一定义）、且 fundflow/tick 有 stale/口径杂、无逐席位。工程量中偏上（多源投票易 overfit，需谨慎语义锁）。
- token：input ~20–25K（读 chip/tick/fundflow/lhb_veto 四块结构 + risk_veto），output ~8–10K（合成器 + 较多语义锁测试锁投票表）。
- agent 执行：**约 2.5–3.5 小时**（多源合成 + 投票语义锁 + stale 降权逻辑 + 覆盖验证）。若要"逐席位"增强，另 +3 小时（扩 lhb 采集 + 落 serialize）。

## 因子四：分红 【股息率现成，除息日需增强 surfacing，优先级 #4】

### (a) 数据源核查 —— ✅ 股息率现成，⚠️ 除权除息日未 surface
- **现成**：`per-stock json → fundamental.每股股利`（实测键存在，28/84 有非零值）。来源 `fundamental.py:7,126`：baostock `query_dividend_data` 近 12 个月按**除权除息日**累计**每股现金分红(税前)**。**`tools/analysis/factor/factor.py:69,107` 已实现 `股息率(%) = 每股股利 / 最新收盘价 × 100`**（无分红票=0 真 0；缺→None 降级；北交所 baostock 不覆盖→降级）。**股息率逻辑可直接复用，零新增。**
- `events` 里 `announcement type=分红`（利润分配/派息/现金分红，announcement.py:38）——但只有**公告日期**，非除权除息日。实测 84 只中 `分红` event=1（低频）。
- **缺口**：**除权除息日（ex-date）未 surface 到每股 JSON**。用途 = "临近除息机械下调"标记（除息日价格按每股分红机械下调，避免把除息跳空当利空、或把除息前的价格当趋势）。数据源其实**已在本仓**：`master_sync.py:102` 用 baostock 除权除息日历（`query_dividend_data` 的 `dividOperateDate`）判 K 线复权，但**没把"下一个/最近除息日"落进 per-stock json**。属**轻量增强 surfacing**（源已接入），非全新采集。
  - 注：主档 K 线是**前复权**（baostock_src.py 头注，qfq），**历史除息的机械缺口已被前复权吸收**——所以"机械下调"对**历史**形态无影响，真正需要标记的是**未来临近的除息日**（持有期风险 + entry 定价）。

### (b) 信号定义 —— 两块，一正向一提示
```
① 股息率档（正向·防御属性，复用 factor.py 公式）:
   股息率 < 1%      → 低（无防御性）
   1% ≤ … < 3%      → 中
   3% ≤ … < 5%      → 较高（防御/高股息）
   ≥ 5%             → 高（强防御，注意是否分红不可持续）
   每股股利缺失      → missing（不编）
② 临近除息标记（提示·需 surface ex-date）:
   下一个除权除息日 - as_of ≤ 15 日 → 标记"临近除息·价格将机械下调约(每股股利/现价)%"
   → 交给 entry_price（挂单/止损按除息后价重算）+ LLM prompt 提示，**不进打分**
```

### (c) 接入点 —— 轻工具（信息 + entry 护栏为主，打分权重极小）
- **新建轻工具** `tools/pyramid/tools/dividend_tool.py`，`name="dividend"`，`塔层="③塔身"`（估值/质量轴）。产出 `股息率档` + `临近除息标记` + 浓缩块（供 LLM 消费）。
- **打分接入（弱）**：分红对当前五基石**契合度最低**——排雷子分是纯负向、不宜塞正向"高股息"。建议：
  - v1 **不进骨架打分**，只作**决策包信息块 + entry_price 除息护栏**（临近除息 → entry 用除息后价，防止把机械跳空误判）。
  - 未来若新增"质量/防御位"再把高股息作正贡献（属 P3 权重扩展，不在本轮）。
- 复用：股息率复用 `factor.py:dividend_yield`；除息日需先做 (a) 的 surface 增强（在 serialize/fundamental 落 `下一个除息日`）。

### (d) 权重/口径建议
- v1 权重 = 0（不进骨架），仅信息 + entry 护栏。若上"防御位"，临时给高股息(≥3%) 小正分（并入未来质量位，≤0.05 权重量级）。
- 复盘：高股息票在弱市 forward 是否更抗跌？是则支持未来设防御位。

### (e) 优先级 + 工作量
- **优先级 #4**：股息率虽现成，但**对现有五基石打分价值最低**（正向、无处安放）；除息日 surface 是额外活。信号价值/工程比最低，故垫底。
- token：股息率块 input ~10K（复用 factor.py），output ~4K；除息日 surface 另 input ~10K/output ~5K（改 fundamental/serialize + 探针）。
- agent 执行：股息率信息块 **约 1–1.5 小时**；除息日 surface 另 **约 2 小时**。

## 四因子总排序（先做哪个 · 数据现成 & 信号价值 & 工程简单三重排序）

| 排序 | 因子 | 一句话理由 | 立即可做版 | agent 工时 |
|---|---|---|---|---|

| **#2** | **减持 v1** | events 现成 + 样板成熟(fake_good_news)、落地快、利空信号清晰 | 标题级 | ~1.5–2h |

## 关键设计决策与不确定点（诚实标注）

1. **不新增第 6 基石**：解禁/减持 → 排雷子分(0.15)，对手盘 → 量价自证(0.30) 加减项，分红 → 暂不进打分。理由：`WEIGHTS` 改动触发全局语义锁重标定 + D3 需重新 forward 标定，成本高；四因子里三个是负向/微结构，天然归入既有子分。**若统筹希望解禁/减持权重更显性，可另议提升排雷子分权重（需重标定）。**
2. **对手盘"逐席位"做不到（现状）**：`lhb.py` 归一只留聚合 net，无营业部明细——本文"对手盘"v1 = 聚合方向 + 筹码 + tick 主动买卖，**不是**真·席位识别。**假设**：聚合信号已足够作骨架微结构佐证；若用户要真·席位（游资 vs 机构），需先做 lhb 席位增强采集（列 B 表）。
3. **减持"协议转让给战投"中性化**：`serialize.py:416` 已点明需靠标题/摘要区分。v1 靠关键词降权，**假设**关键词覆盖够用；边界情形（新型措辞）可能误判，v2 量化 + 主体标签可根治。
4. **分红对前复权 K 线无历史影响**：主档 qfq 已吸收历史除息机械缺口，**只需**标记**未来临近除息**（持有期 + entry 定价）。这是把"除息机械下调"落到 entry_price 护栏而非打分的依据。
5. **stale 口径处理**：fundflow(实测滞后 7 天)/holder/valuation 多为陈旧——凡入档一律 `freshness` 如实标 + 浓缩块带 `[stale]`，stale 源投票权重减半。**绝不因陈旧而丢弃或假装新鲜。**
6. **全部遵守铁律**：缺数据 → `嫌疑档="missing"` 不编；档位写死 + 语义锁测试（照 financial_redflag 的 `_QUALITY档` / fake_good_news 顶部常量）；`as_of` 防未来（解禁未来日期合法但披露日必须 ≤ as_of）。

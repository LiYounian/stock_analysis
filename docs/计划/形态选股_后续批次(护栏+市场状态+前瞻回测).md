## 三、实现计划

### 3.1 分期 / 步骤（各拆独立分支，串行依赖标注）
- **批次 A（护栏）** 分支 `feat/pattern-guardrail`：独立，无前置。
- **批次 B（regime）** 分支 `feat/market-regime`：B3 依赖模块二 view（已就绪），可与 A 并行。
- **批次 C（前瞻回测）** 分支 `feat/forward-winrate`：依赖 D 或多日积累产出历史达标池；先搭回测器（可用构造数据单测），真实回测待数据。
- **批次 D（全量首扫）**：运维任务，A 合并后跑一次最有意义（护栏生效后的达标池更干净）。

### 3.2 涉及模块（`tools/` 路径）
| 模块 / 文件 | 改动类型 | 说明 |
|---|---|---|
| `tools/pipeline/screen_pattern.py` | 改 | A：pass1 补取基本面+公告喂 `is_qualified`；B：加算 regime 落 view |
| `tools/collectors/fundamental.py` | 改 | A3：加"PE 历史分位"函数（**先验证本机数据源是否被东财墙**） |
| `tools/collectors/announcement.py` | 只读/改 | A2：取近期公告标题（验证数据源可用性） |
| `tools/analysis/pattern_screener/regime.py` | 新建 | B：模块一五因子 + 五档标签（策略层，纯计算） |
| `tools/backtest/forward.py`（或扩 `metrics.py`） | 新建 | C：前瞻胜率 + Alpha；先读 engine 契约定复用还是新增 |
| `tools/config/strategy.py` | 改 | B：`THRESHOLDS["市场状态"]` 已占位，落实五档边界/龙头池；A：护栏参数已在 |
| `tools/run.py` | 改 | B：加 `regime` 命令；D：`pattern --universe` 已支持 |

### 3.3 接口 / 契约（若涉及）
- **market 级 view「市场状态」** 新契约：`{as_of, 分值, 档位, 五因子:{...}, 宽度=达标占比}`。
- **策略层不 import 采集/回测**；护栏输入继续走 `is_qualified` 现有入参（PE分位/净利增速/公告），无需改策略签名。
- PE 历史分位：`fundamental.pe_percentile(code, win) -> float|None`（缺数据 None，护栏不误杀）。

### 3.4 工作量估（按 agent 视角，全局约法第 11 条）
- 批次 A：input ~30K / output ~15K；agent ~1.5h（含数据源验证 + 单测）。
- 批次 B：input ~40K / output ~25K；agent ~2–3h（regime 逻辑 + 五档标定 + 单测；龙头池/边界待策略端）。
- 批次 C：input ~40K / output ~25K；agent ~2–3h（回测器 + 防未来函数单测；真实回测待历史数据）。
- 批次 D：无开发 token；agent 运行约 40+ 分钟（全 A 网络 I/O）+ 人审。

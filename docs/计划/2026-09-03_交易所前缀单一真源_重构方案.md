# 代码→交易所 前缀映射:收拢单一真源(方案)

> 2026-09-03。起因:`fa4c37b` 修了北交所 920 段在 3 处被判错。根因不是那 3 处写错,
> 而是**同一条领域规则在项目里被独立实现了 9 遍**,各自演化 → 必然出现"同时错三处"。

## 一、实证结论(本轮真调接口取得,非推断)

### 1. 新浪个股新闻:覆盖北交所,正确形式是 `bj{code}`;**错前缀会静默串号**

`vip.stock.finance.sina.com.cn/corp/view/vCB_AllNewsStock.php?symbol=<sym>`:

| symbol | HTTP | datelist | 条数 | 实际内容 |
|---|---|---|---|---|
| `bj920002` | 200 | 有 | 40 | ✅ 万达轴承本股新闻(融资买入/董事专访/北证50活动) |
| `bj430047` | 200 | 有 | 40 | ✅ 诺思兰德本股新闻 |
| `sz920002` | 200 | 有 | 40 | ❌ **新浪默认泛资讯流**("牛人一天赚5.7%"/"港股科网股普跌") |
| `sh920002` | 200 | 有 | 40 | ❌ 同上,与 `sz920002` 前三条**完全相同** |
| `sz430047` | 200 | 有 | 40 | ❌ 同上,同一批默认流 |
| `920002`(裸) | 200 | 无 | 0 | 空 |

**这是本轮最重要的发现**:错前缀不是"取不到数据",而是 HTTP 200 + 40 条**别人的资讯**。
三个错例返回同一批内容 ⇒ 那是新浪的全站默认资讯流,不是该股 feed。上层完全无法从
"非空/状态码/条数"察觉异常 —— 北交所票会被挂上一堆无关新闻,喂进情绪 LLM。
**比拉不到糟得多**,正是必须收单一真源的最强论据。

> 副作用提示:`<title>` 由 symbol 里的数字段解析,前缀错了 title 仍显示"万达轴承(920002)",
> 所以**不能用 title 匹配来验真**。判据只能是 symbol 前缀本身正确。

### 2. baostock:**不覆盖北交所**(需显式降级,不能静默空)

| code | error_code | msg | 行数 |
|---|---|---|---|
| `sh.600000` | 0 | success | 11 ✅ |
| `bj.920002` | 10004011 | 股票代码未标识sh或sz | 0 |
| `bj.430047` | 10004011 | 股票代码未标识sh或sz | 0 |
| `sz.920002` | 0 | **success** | **0** ← 静默空 |
| `sh.920002` | 0 | **success** | **0** ← 静默空 |

baostock 协议只认 `sh.`/`sz.`。现行 `bs_code("920002")` 走 `code[0] in ("6","9")` →
`sh.920002` → **success + 0 行**,调用方看到的是"这只票没有历史数据",而非"这个源不支持北交所"。

### 3. 东财资金流 secid:**本机无法实证**(指纹墙)

`push2his.eastmoney.com/.../fflow/daykline/get` 本轮全部 `curl(56) Connection closed abruptly`,
连对照组 `1.600000` / `0.000001` 也挂 → 是本机已知的东财路径墙(问题台账 B2),不是 secid 写错。
故 secid 对北交所取 `0.` 还是别的,**本轮无实证**,不据猜改。

### 4. 其它新闻源对北交所的覆盖

- **东财 `stock_news_em`**:接口收**裸 6 位代码**(`_fetch_em(code)` 不带前缀)→ 结构上无前缀可判错,
  北交所与沪深同路。
- **财联社 `stock_info_global_cls`**:全市场快讯 + **按股票名过滤**,与代码段无关 → 北交所同等覆盖。
- 结论:news.py 三源里**只有新浪一处**有代码→交易所映射,也只有它有此隐患。

## 三、单一真源放哪一层:选 `tools/config/exchange.py`

候选比较:

| 方案 | 判断 |
|---|---|
| **`tools/config/exchange.py`(新建,选它)** | "代码段→交易所"是**领域常量**,不是采集实现细节也不是分析口径。`tools/config/` 现有零项目依赖(全目录只 `stock_pool → settings` 一条边),放纯函数模块不会成环;`collectors/` 已在 import `tools.config.*`(settings / stock_pool),`analysis/`、`pipeline/`、`backtest/` 也都能直接 import 而**不产生 analysis→collectors 的反向依赖**。`stock_pool.is_hk` 已在这一层做代码分类,有先例。 |
| `tools/collectors/exchange.py` | ✗ B 类调用方在 `analysis/`、`backtest/`、`pipeline/`,为一个纯字符串函数让分析层依赖采集层,是分层倒挂。 |
| 复用 `collectors/board.py:board_of()` | ✗ 名字像但语义完全不同:它读 `board_membership` 落盘文件查**申万/证监会行业**,是数据查询(会触 IO、会 `FileNotFoundError`),不是代码段推断。不能当真源。 |
| 复用 `analysis/market_forecast/breadth.py:board_of()` | ✗ 判据虽对,但位置在分析层深处,且返回"主板/创业板/科创板/北交所"是**涨跌停线口径**,与交易所路由是两个概念(900 沪B 归沪市但没有 10% 涨停线)。真源应给交易所,由它自己派生板块。 |

### 真源 API(一处判定,各形式派生)

```python
# tools/config/exchange.py —— 零依赖纯函数
EXCHANGES = ("sh", "sz", "bj")

def exchange_of(code) -> str | None   # "sh"/"sz"/"bj";非 6 位 A 股 → None
def prefixed(code) -> str             # "bj920002"  (新浪日K/腾讯 market.py)
def upper_prefixed(code) -> str       # "BJ920002"  (东财 by_report)
def dotted(code) -> str               # "bj.920002" (baostock)
def is_bj(code) -> bool
def is_a_code(code) -> bool
```

判据(唯一一份):`920` 前缀 → bj(**必须先于 `9`→sh**)/ `6`,`9` → sh(含 900 沪B)/
`4`,`8` → bj(43/83/87 历史段)/ `0`,`2`,`3` → sz / 其余 → None。

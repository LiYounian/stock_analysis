# 候选池改造计划(A)· headless 自选质量化 · 2026-09-14

> ⚠️ 测试环境研究模拟,非投资建议。
> 定位:**计划文档,待审阅后再动代码**(约法#4)。本文只定目标/设计/验证法,不含实现。
> 承接证据:`docs/计划/2026-09-13_headless历史日dryrun证据_扩样.md`(16 日 shadow-run,分支 `docs/headless-dryrun扩样-0913` @ 7fe443d)。

---

## 0. 一句话

扩样证据把 headless 化的瓶颈钉死在**选股流水线前半段——候选池**(不在判研模型):现有机械候选池噪声大,DeepSeek(正确地)几乎全否 → **16 日里 10 日 0 买入**。本计划把候选池从"机械成员资格"改造成"**council 强度分排序 + 质量闸门过滤 + 交叉确认**",让 headless 每天能选出**信噪比高、数量合理**的候选,再交 DeepSeek 自选。这是第三波"无人值守切主"的**真正前置**(A),优先级高于换模型。

---

## 1. 问题(从证据来,不臆测)

扩样 16 日 shadow-run 的三个硬事实:
1. DeepSeek 自选买入 **6 只 / 16 日,10 日 0 买入**(0.375 只/日)——切无人值守=绝大多数交易日空推荐。
2. DeepSeek **复核 Claude 选票**时高度一致(~81%)、α 非负;**自选**却几乎全否 → 判研能力 OK,**短板在候选池**。
3. 09-02 DeepSeek 否掉 Claude 全部 3 买入、漏掉 002811 +7.8% / 603270 +10.0% 两赢家 → **买入阈值在 headless 下过保守**(这是 B,本计划的兄弟项)。

### 1.1 现有候选池(shadow_pool.py v1)的三缺陷

| 缺陷 | 现状 | 后果 |
|---|---|---|
| **丢弃强度分** | 只认"是否在某策略榜单里"(membership),不认名次/分值——理由是"多数宽网榜按 code 升序排,名次不可靠" | 把本来**有真实分值**的策略(council/最强选股/动量组合)的强度信息一并丢了,池子=无序集合 |
| **策略权重扁平** | `hit≥2` 把噪声宽网命中与优质精选命中**等价对待** | 弱票靠"在两个宽网里都出现"就进池,信噪比低 |
| **无质量闸门** | 不过滤游资/低流动性/龙虎否决/融资拥挤 | 噪声票充斥,DeepSeek 逐一否掉→选不出票 |

## 2. 目标 / 非目标

**目标**
- G1 候选池**强度有序**(带可复现的 strength 排名),不再是无序集合。
- G2 候选池**质量过滤**:剔除结构性噪声(高危红旗/龙虎否决/极低流动性/游资情绪/融资拥挤),保留"量化上较强且干净"的票。
- G3 候选池**数量合理稳定**(目标每日 ~8–15 只有效候选),使 DeepSeek 自选后**多数交易日 ≥1 买入**。
- G4 全程**防未来 + 逐日一致 + 无 cherry-pick**,规则可复现。

**非目标(本轮不做,避免范围蔓延)**
- 不改判研模型 / 不换 DeepSeek(判研已被证 OK)。
- 不标定 DeepSeek 买入阈值(那是 B;A 先把池子修好,B 才有干净基础)。
- 不动生产 / live SKILL / 定时任务 / model_registry。
- 不修千问(那是 C)。

## 3. 可用数据资产(改造的地基,已核实)

### 3.1 council(`策略0合议.json`)—— 现成的强度骨架 + 质量旗标
`top` 榜单每单元含:`code / 行业 / 综合方向 / 综合分 / 合议置信度 / 参与专家数 / 口径多样性 / 覆盖口径 / 综合分_收缩 / 排序分 / 有财报块`;顶层含 `命中高危红旗 / 命中龙虎榜否决`。
→ **council 是对全域打分的元聚合**:v1 把它从"成员资格"排除是对的(否则人人都是成员),但它的 **`排序分/综合分`=天然强度排序**、**`口径多样性/参与专家数`=交叉确认强度**、**`命中高危红旗/命中龙虎否决`=天然质量闸门**。这是本次改造最重要的复用点。

### 3.2 逐票 record(`<code>.json`)—— 质量过滤的细粒度字段
结构块:`snapshot`(量价/换手/成交额)、`fundflow`(资金流)、`lhb_veto`(龙虎榜否决)、`chip`(筹码集中/获利盘)、`financing`(融资盘拥挤)、`sentiment`、`signals`、`prediction`、`valuation`。
→ 流动性 / 游资 / 融资拥挤 / 筹码风险的过滤条件都能从这些块取(具体键在实现阶段落表)。

### 3.3 选择性策略视图(动量组合/最强选股/放量后缩量回踩/…)
带 `_SCORE_KEYS=(综合分/score/动量分/得分/分值/强度)`,`write_picks._extract_score` 可取。部分策略榜按分排序、部分按 code——**实现时逐策略探测排序口径**(是否单调于分值),只对"确实按强度排序"的策略采信名次,否则退回只用其分值、不用名次。

## 4. 改造设计:候选池 v2(强度排序 + 质量闸门 + 交叉确认)

三段式流水线,每段输入输出明确:

### 4.1 段一 · 强度打底(用 council 排序分做主骨架)
- **输入**:当日 `策略0合议.json` 的 `top` 榜。
- **逻辑**:以 `综合方向` 非看空 + `排序分`(或 `综合分_收缩`,取更稳的收缩后分)为**主强度键**,取分值前 K(K≈40~60)作**初始强度池**。
- **输出**:`[(code, 强度分, council字段…)]`,已按强度降序。
- **为什么用 council 而非各策略并集**:council 已把多策略/多口径打分聚合成单一可比强度,天然解决 v1"扁平权重+无序"两病;且它就是生产合议层的产物(防未来合法)。

### 4.2 段二 · 质量闸门(硬过滤,剔结构性噪声)
对段一每只票过闸门(任一命中即剔除或降级),闸门取自 §3:
1. **council 硬否决**:`命中高危红旗` / `命中龙虎榜否决` 名单内 → 剔除。
2. **龙虎榜游资**:record `lhb_veto` 命中 → 剔除(或标"只观测不入池")。
3. **流动性下限**:record `snapshot` 成交额/换手低于阈值 → 剔除(阈值实现阶段按全A分位标定,防未来只用当日及历史分布)。
4. **融资拥挤**:record `financing` 融资余额分位过高(如 >90%)→ 降级(不硬剔,交 DeepSeek 判,但打标)。
5. **筹码风险**:record `chip` 高位获利盘畸高 → 打标(软信息,不硬剔)。
- **输出**:过滤后的**干净强度池**;每票带"被打的软标签"清单(供 DeepSeek 研判时读)。
- **闸门口径全部逐日一致、参数不按日调**(防 cherry-pick,与 v1 一致纪律)。

### 4.3 段三 · 交叉确认 + 定量截断
- **逻辑**:在干净强度池上,叠加 council `口径多样性/参与专家数`(多口径确认)与选择性策略命中数(§3.3,只用采信名次的策略)作**加分**,得最终排序;取前 N(N≈8~15)。
- **多样化**(可选,对齐 SOP #多样化):同一行业最多取 M 只,避免板块过度集中。
- **输出**:`候选池 v2 = [(code, final_rank, 强度分, 命中策略, 软标签)]`,交 `deep_analysis.generate` 逐票自选。

## 6. 验证方法(直接复用扩样框架 + 防偷看)

### 6.1 A/B 对拍(v1 机械 vs v2 质量化)
在同 16 日、同 `shadow_run` + `shadow_score` 上,v1 vs v2 各跑一遍,对比:
- **候选池信噪**:每日候选数、council 强度分中位、被闸门剔除数/原因分布。
- **DeepSeek 自选买入数/日**:v2 是否把"10 日 0 买入"显著改善到"多数日 ≥1 买入"(G3 达标判据)。
- **买入侧 α**(T+1,含 T+5 子样本)、命中率、样本量 N、SE。
- **是否引入新噪声**(v2 会不会为了凑数量放进弱票、拉低 α)。

### 6.2 ⚠️ 防数据偷看(overfitting)—— 硬要求
**绝不在这 16 日上既调参数又报 α**(in-sample 数据窥探,quant 视角是硬伤)。纪律:
- 闸门/权重**从第一性原理与领域经验设定**(如流动性分位、融资 90% 分位、红旗否决),**不为最大化这 16 日 α 去调**。
- 分**开发集 / 保留集**:如用 08 月若干日调规则、09 月日做样本外验证;或做 **walk-forward**(每日只用 ≤当日历史标定分位)。
- 报告显式标注:哪些参数是**先验设定**、哪些**在开发集上选过**、保留集结果如何。
- **样本量仍是天花板**:即便 v2 让买入数上来,统计显著性仍需更多日;A 的成功判据是 **G3(选得出票)+ 信噪改善 + α 不劣于 v1**,不是"证明有显著 α"(那要等样本累积)。

### 6.3 单元测试(约法#6)
`tests/test_shadow_pool_v2.py`:锁住 ①闸门语义(红旗/否决/流动性触发即剔)②强度排序单调 ③防未来(不读 >date 数据)④接口与 v1 同形状 ⑤逐日确定性(同输入同输出)。

## 10. 结论
候选池改造(A)是 headless 化"选得出、选得准"的**真正卡点**,且**地基已就位**(council 强度分+旗标、record 质量块)。本计划把它拆成"强度打底→质量闸门→交叉确认"三段、接口兼容现有 shadow 框架可直接 A/B 对拍,并对**数据偷看**立了硬纪律。审阅通过后按 §8 分步执行,全程只建不切。

# 政策采集覆盖修复：行业词表对齐 + 裸行业词扩召回

- 日期：2026-09-18
- 分支：`claude/cailianshe-premarket-capture-fb01eb`
- 触发：2026-09-18 盘后外围消息「美股盘前：存储、光通信继续走高（SK海力士/闪迪 +2%，美光/西部数据 +1.5%，康宁/Coherent +2%）」——查证发现**光通信这半条源里有、我们没采到**
- 范围：只改 `tools/collectors/policy.py` 的**检索词生成**。不改采集频次、不改打标契约、不动下游

---

## 1. 现象与查证

用户收到的消息是财联社 16:20 的合并稿（存储 + 光通信两段）。逐层核对当日库内数据：

| 半条 | 源侧是否有 | 我们是否采到 |
|---|---|---|
| 存储（SK海力士/闪迪/美光/西部数据） | 东财 16:05:12 有 | **采到**，落在 `data/raw/2026-09-18/policy/policy_2026-09-18.json`，`keyword=芯片管制`、`industries=["半导体"]` |
| 光通信（康宁/Coherent/迈威尔/Ciena） | 东财 16:04:11、16:10:38 都有 | **没采到** |
| 财联社 16:20 合并稿原文 | akshare `stock_info_global_cls` 实时拉最近 20 条（覆盖 16:05–16:31）里**没有** | 现用电报接口拿不到，属另一渠道 |

关键点：光通信那条**落在我们的采集窗口之内**（policy 快照 16:10 落盘，源侧 16:04 就有），
所以这**不是时效问题，是检索覆盖问题**。存储那条能进来，是宏观词「芯片管制」模糊命中蹭进来的，属侥幸不是设计。

## 2. 根因（两层，第一层是主因）

### 2.1 主因：`_INDUSTRY_TERMS` 的 key 与票池 `Stock.sector` 词表漂移，行业词被静默滤掉

`default_keywords()` 用 `if sector not in pool_sectors: continue` 过滤，两边是**两套词表**：

```
_INDUSTRY_TERMS keys : 半导体 / 电子元件 / 机器人-自动化 / 光通信 / AI算力 / 消费电子 / 新能源材料 / 公用事业
票池 Stock.sector    : AI算力 / 传媒-AI应用 / 光伏 / 光学元件 / 光模块 / 大模型 / 新材料 / 汽车 / 航运 / 计算机 / 银行
```

字符串直等只有 `AI算力` 对得上 → **8 组行业词里 7 组被静默丢弃**，实测
`default_keywords()` 当前只产出 22 个词（算力 ×6 组合 + 16 个宏观词）。
「光通信 政策」这类词**根本没被生成过**，所以光通信永远采不到。

源码注释写的是「key 与 `stock_pool.Stock.sector` 对齐」——说明本意是对齐，是后来池子改名漂移了，属静默失效。

同一层级的证据：项目已有 `tools/analysis/industry_map.to_sw()` 作为**行业归一单一真源**，
下游 `focus.py` / `sentiment_judge.py` 消费 `industries` 时都先过 `to_sw`，只有采集侧这里没过。
实测 `to_sw('光模块') == to_sw('光通信') == '通信'`、`to_sw('光学元件') == to_sw('半导体') == '电子'`——
**归一后交集是能对上的**。

### 2.2 次因：检索词全是「行业词 × 政策词」组合，接不住不带政策词的盘面异动快讯

现有组合词形如「光通信 政策 / 光通信 补贴 / 光通信 出口管制」。
而「美股光通信板块盘前延续昨日涨势」这类**产业/盘面异动快讯不含任何政策词**，即使 2.1 修好也未必稳定命中。
实测直接用裸词 `光通信` 查东财，返回 10 条里**第一条就是那条 16:04:11 的漏采件**。

## 3. 方案（= 用户拍板的 A，两步都做）

### 3.1 改动一：池过滤经 `industry_map.to_sw` 归一后取交集

`default_keywords()` 里把字符串直等换成申万一级归一后比对：

- 票池 sector → `to_sw` → 申万一级集合（`None` 丢弃）
- `_INDUSTRY_TERMS` 的 key → `to_sw` → 落在上述集合内则保留

预期效果：存活行业组从 1 组（AI算力）恢复到 **6 组**
（半导体/电子元件/光通信/AI算力/消费电子/新能源材料；机器人-自动化→机械设备、公用事业→公用事业 不在池内，继续正确排除）。

### 3.2 改动二：每个存活行业追加**裸代表词**

除「代表词 × 政策词」外，再加一个裸代表词（`光通信`、`半导体`、`算力` …），
用于捞不带政策词的产业/盘面快讯。

**不加**「美股盘前 / 板块异动」这类全局盘面词——实测裸行业词已能捞到目标件，
再加会放大与宏观词的重复拉取，收益不明确。留作后续观察项。

### 3.2bis 实测修正（2026-09-19 补）：裸词组砍掉，A 收缩为只做改动①

上线前跑了一次只读实测（临时脚本、`store._RAW_DIR` 重定向到临时目录、不碰生产 `data/`），
按三个变体各走一遍真实 `tag_and_dump`（归一 + 打标 + 窗口 + 去重）：

| 变体 | 词数 | 入库条目 | 净增 |
|---|---|---|---|
| 老词表（现状） | 22 | 74 | — |
| **只修词表漂移（改动①）** | 52 | **162** | **+88** |
| 漂移 + 裸词（①+②） | 58 | 167 | +93（**裸词边际仅 +5**） |

裸词逐个独占贡献：`半导体=1, 电子元件=1, 光通信=0, 算力=2, 消费电子=1, 新能源=1`。

**关键证伪**：§2.2 那条次因（「组合词全带政策词，接不住不含政策词的盘面异动快讯」）**不成立**。
实测那条漏采件「美股光通信板块盘前延续昨日涨势」被**全部 6 个光通信组合词**捞到
（`光通信 政策` / `光通信 补贴` / `光通信 规划` / `光通信 出口管制` / `光通信 专项`），
说明**东财关键词检索是模糊匹配**——「光通信 政策」实际约等于「光通信」，组合词并不排斥无政策词的条目。
裸词「光通信」独占贡献恰好为 0。

**结论：漏采 100% 由词表漂移造成，改动①贡献 95% 的召回增量（+88/+93）。**

故 A 收缩为**只做改动①**（52 词）。砍掉裸词不只是省 6 个请求——保留一个「设计理由已被证伪、
但碰巧有微小收益」的改动，会让后来者误以为裸词是为接盘面快讯而存在的，属认知污染（约法第 3 条）。
若日后确需扩召回，应基于 L3 的产出率数据决定，而不是凭这条已证伪的直觉。

**验收点已提前达成**：新词表实测捞回了 9-18 漏掉的那条，`industries` 正确带上 `光通信`；
并额外捞到「美股盘前，存储、光通信延续强势」——即用户收到的财联社 16:20 合并稿的东财版。

> ⚠️ 口径提醒：以上是**单日快照**。东财每个关键词固定只回最近 10 条，日间条目分布会波动，
> +88 是 2026-09-19 这个时点的实测值，不是长期均值。

### 3.3 明确不做

- **不加采集频次 / 不做轮询**（用户已拍板否决：加次数不解本质，轮询太耗资源）
- **不动财联社电报换源**（`rn=20` 覆盖薄是独立问题，另开一轮）
- **不动打标契约 / `industries` 字段语义 / 任何下游**

## 5. 测试（约法第 6 条：断言锁住「为什么改」）

在 `tests/test_policy.py` 增补，全部 mock 不触网：

1. `test_default_keywords_survives_sector_vocab_drift`
   票池 sector 用**漂移词表**（`光模块`/`光学元件`/`光伏`），断言产出的关键词里含 `光通信`、`半导体`、`新能源` 相关词
   → 锁住 2.1，防未来有人改回字符串直等。
2. `test_default_keywords_includes_bare_industry_terms`
   断言裸代表词（`光通信`）与组合词（`光通信 政策`）**同时存在**
   → 锁住 2.2，防未来"精简关键词"时把裸词删掉。
3. `test_default_keywords_excludes_off_pool_sectors`
   断言 `机器人`、`电价` 等池外行业词**不出现**
   → 锁住"归一后取交集"没有退化成"全都要"。
4. 回归：现有 9 个用例全绿（尤其 `test_default_keywords_covers_pool_industries` 可能需随新语义调整断言）。

另做一次**真实联网冒烟**（不进 CI）：跑 `fetch_policy()`，断言结果里能捞到含「光通信」且 `industries` 含 `光通信` 的条目。

### 实施中相对原计划的偏差（已记录）

1. **裸词组砍掉**（§3.2bis）——原假设被实测证伪
2. **导入方式**：`industry_map.to_sw` 采用**函数内延迟导入**，与 `tools/collectors/code_industry.py` 既有惯例一致，避免 collectors → analysis 的模块级耦合
3. **顺带修正一处误导性注释**：`_INDUSTRY_TERMS` 上方原写「key 与 `stock_pool.Stock.sector` 对齐」——该说法正是本 bug 的认知源头（让人以为两边字面一致是不变量）。改为明确两者是独立演进的词表、需对应时一律经 `to_sw`

## 7. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 条目数翻倍 → LLM 打分变慢/变贵 | 已有 `_cached_extract` 缓存 + `_pmap` 并发；观察一周，若超预期再对政策条目加去重/截断 |
| 裸词召回噪音（如「算力」捞到 ETF 营销稿——现有快照里已大量存在） | 本轮不治；`require_industry_hit` 仍在，噪音进入的是同一批行业标签，不改变下游语义。噪音治理另开一轮（可考虑来源白名单） |
| 归一后交集把某些行业放进来（此前从未有过） | 属修复而非回归；若某行业噪音过大，可在 `_INDUSTRY_TERMS` 单独摘除 |

回滚：单文件单函数改动，`git revert` 即可，无数据迁移、无契约变更。

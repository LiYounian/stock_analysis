## 一、目标（一句话）

让 launchd 每次触发时执行的 wrapper 脚本本体**恒等于最新 origin/main**，与主仓工作树是否脏彻底无关——
消除"wrapper 改动合入后不自动部署到生产"的系统性缺陷。

## 二、现状要点（侦查结论，支撑下面决策）

1. 每个业务 wrapper（`pull_refresh / intraday_snapshot / strong_refresh / market_breadth /
   intraday_review / intraday_screen / intraday_watch / commit_analysis_docs`）**内部已自带 worktree 卫生**：
   `git -C <数据worktree> fetch + reset --hard origin/main` 后 `cd` 进去跑 python。
   - dailyjob worktree：pull/snapshot/strong/breadth/review/screen/watch
   - 独立 worktree：autopush（`autopush` worktree）、commit_analysis_docs（`commitdocs` worktree）
2. **唯一未解决**：wrapper **脚本本体**是 launchd 按 plist `ProgramArguments` 指定的**主仓路径**读取的
   → 主仓工作树卡旧 commit 时，跑的是旧 wrapper。这就是本轮要补的缺口。
3. 所有定时参数走 plist `EnvironmentVariables`（`INTRADAY_SLOT / BREADTH_SLOT / PULL_FETCH / FETCH_WORKERS`），
   **无 wrapper 依赖位置参数**。
4. `intraday_review / intraday_screen` 的 plist `ProgramArguments` 是**手改残留**：
   `[/bin/bash, <某worktree>/x.sh, <主仓>/x.sh]` —— bash 只把第 1 个当脚本、第 2 个当 `$1` 塞给 wrapper，
   是无意义 cruft（review 的 `tools.run intraday_review "$@"` 会收到一个垃圾路径参数）。**本轮归正**。
5. `autopush / sepa` 的 plist 用 `__REPO__` 占位符模板 + **当前未装载**（`launchctl list` 无），sepa 已停用 → 边缘 case。

## 三、落地架构（③b 具体形态）

在 launchd 与业务 wrapper 之间插入一层**薄 bootstrap**：

```
launchd ──exec──▶ 薄 bootstrap（近乎不变、被 plist 钉死）
                     │ 1. 定位 deploy worktree；缺失 → fail-loud exit 3
                     │ 2. git -C <deploy> fetch + reset --hard origin/main（只碰 deploy，绝不碰主仓/stash栈）
                     │ 3. 目标 wrapper 缺失 → fail-loud exit 4
                     └─exec──▶ <deploy>/ops/launchd/<wrapper>.sh
                                  └ wrapper 内部照旧 cd 各自数据 worktree 跑 python（本体零改）
```

### 交付物
1. `ops/launchd/_bootstrap.sh`（**新增**，版本管理源）：通用薄 bootstrap，`$1`=wrapper basename，`$2..` 透传。
2. `ops/launchd/provision_deploy.sh`（**新增**，幂等）：建/刷新 deploy worktree + 安装 bootstrap 到 repo 外固定位置。
3. `ops/launchd/com.stock.*.plist`（**改 9 个**）：`ProgramArguments` 指向已安装的 bootstrap + 传 wrapper basename；归正 review/screen。
4. `tests/test_launchd_deploy_bootstrap.py`（**新增**）：部署闭环 / 主仓脏不阻断 / bootstrap fail-loud / WIP 保护 / 无裸 stash。
5. `docs/参考/部署卫生_launchd装载runbook.md`（**新增**）：人工 unload/load 步骤 + "改前查 job 是否在跑"护栏。
6. 业务 wrapper（`*.sh`）**不改内容**。

## 四、自主决策点（需统筹核；均低风险可回滚）

### 决策1：新建独立 deploy worktree（不复用 dailyjob）
- 选择：新建 `worktrees/stock_analysis/deploy`（detached origin/main，**无数据 symlink**），bootstrap 只 reset 它取最新 `.sh`。
- 理由：① 职责单一——deploy=最新 wrapper 本体，dailyjob/autopush/commitdocs=最新 python+数据（各 wrapper 内部负责，不变）；
  ② 不是所有 job 都用 dailyjob（autopush/commitdocs 各有其 worktree），复用 dailyjob 会让 bootstrap 逻辑因 job 而异；
  ③ deploy 无数据 → provisioning 就一句 `git worktree add --detach`，`reset --hard` 只动 tracked、零未跟踪堆积。
- 风险/回滚：新增一个常驻 worktree（占对象库共享、增量极小）；不想要可删 worktree + 改回 plist。

### 决策2：bootstrap 安装到 repo 外固定位置（解引导悖论）
- 选择：plist 钉死 `$HOME/.local/state/stock/bin/stock-launchd-bootstrap.sh`（provision 从 deploy worktree 拷入）；
  源文件 `ops/launchd/_bootstrap.sh` 仍在 repo 版本管理。
- 理由：若把 plist 钉在**主仓** `ops/launchd/_bootstrap.sh`，则"主仓卡住→bootstrap 陈旧"这条耦合仍在（虽 bootstrap 近乎不变，
  但正是本轮要根除的那类潜藏耦合）。装到 repo 外固定位置，**plist 入口彻底不依赖主仓 git 状态**；
  更新 bootstrap（罕见）=重跑 provision（从 deploy worktree=最新 origin/main 拷）——连 bootstrap 自身也经 deploy worktree 部署。
- 备选（未采）：plist 指主仓 `ops/launchd/_bootstrap.sh` + 首次人工 `checkout origin/main -- ops/launchd/_bootstrap.sh`。
  更贴"逻辑放 repo 内"约定，但保留一处主仓耦合。**倾向决策2，留统筹定夺**。
- 位置说明：沿用项目已用的 `~/.local/state/stock/`（日志/锁同树），下加 `bin/` 子目录；纯安装产物、不入 git。

### 决策3：autopush / sepa 本轮不迁（记待续）
- sepa：已停用（2026-09-04），plist 未装载 → **不迁**。
- autopush：`__REPO__` 占位符模板 + 当前未装载，装载机制与其余 9 个不同 → **本轮不迁**，记待续；
  若将来重新启用 autopush，需一并迁到 bootstrap 形态（它同样有"wrapper 本体从主仓读"的隐患）。
- 说明：用户拍板"所有 com.stock.* 都迁"，此二者属未装载/停用边缘 case，**显式列出交统筹确认**，不静默跳过。

### 决策4：wrapper 本体零改
- 仅改"从哪读 wrapper"（plist→bootstrap→deploy worktree），**不改"wrapper 跑什么"**（内部 dailyjob/autopush/commitdocs 卫生保留）。
- 与既有约定一致（开发日志 breadth/strong 迁移即此原则：只改运行源、不改业务）。

## 六、测试与验收（对齐设计 §六，本轮实现 ③b 相关 4 条）

`tests/test_launchd_deploy_bootstrap.py`（自包含、临时 git 仓、不依赖项目重依赖）：
1. **部署闭环**：deploy 源 wrapper 从 v1→v2（origin/main 新提交）→ 跑 bootstrap → 断言 exec 到 **v2**。
2. **主仓脏不阻断 + WIP 保护**：造一个"主仓"含未跟踪 md + 已跟踪本地改动 → 跑 bootstrap → 断言正常 exec 最新 wrapper 且**该主仓目录零改动**。
3. **fail-loud**：deploy worktree 缺失 → exit 3；目标 wrapper 缺失 → exit 4（不静默跑旧码）。
4. **无裸 stash / 不碰主仓**：静态断言 bootstrap+provision 不含裸 `git stash`/`stash pop`、无对主仓工作树的写操作。
- 设计 §六 第 3 条（ff-only 不被分析文档挡）属 **①a 范畴**，本轮不实现，测试文件注明留下轮。

跑法：`~/.conda/envs/stock_analysis/bin/python -m pytest tests/test_launchd_deploy_bootstrap.py -q`。

## 七、风险与实施纪律

- **绝不 launchctl load/unload**、不自合 main、不真动 launchd；plist 只在 repo 内交付草案。
- **改 launchd 前必查 job 是否在跑**（unload 会 SIGTERM 杀正在跑实例）——写进 runbook 交人工执行。
- bootstrap/provision **只对 deploy worktree `reset --hard`**，绝不碰主仓工作树 / stash 栈 / 别的会话 WIP。
- 分步 commit（无 AI 署名）；脱敏（路径含用户名属本机既有约定、非密钥，不新增敏感字段）。

## 背景 · 为什么改

「估值位(价值市值分位)」因子今日(4170a3f)坐实入生产合议
(`THRESHOLDS["合议"]["多因子"]["价值市值分位启用"]=True`)。它是**显式小市值 tilt**,
收益含 A 股小市值溢价 + 幸存者偏差,风格切换/risk-off 会大幅回撤——入合议时承诺
"挂前向观测哨盯小市值敞口、须持续监控"。

核查发现这条安全纪律**实际无法执行**:

1. `score._estvalue_monitor`(算「高价值票中位市值 / 全池中位市值」= 小市值倾斜)读数
   由 `precompute` 塞进返回字典 `估值位监控` 字段 + `logger.info`;
2. 但 `run.py:run_factor` **没有承接该字段**——读数只活在即时 console log,
   全库无 record/view/日志留痕,无法按交易日回查、无法在 risk-off 时发现敞口异常;
3. `strategy.py` 注释写"见 screen_council view「估值位」块",**该 view 根本不存在**(失实)。

净效果:承诺的监控形同虚设。

## 改动 · 做了什么

**落点选型**:用项目既有的按日池级视图约定 `store.put_view(name, obj, date)`
(同「市场状态」「REVS四因子」「扣非质量」等),落到 `data/analysis/<日期>/估值位监控.json`,
`store.get_view("估值位监控", date)` 按交易日回读。选它的理由:date-keyed 天然按交易日跟踪、
读回原语现成、与其它监控/池级视图落盘方式一致。

1. `tools/analysis/factor/score.py`
   - 新增 `_persist_estvalue_monitor(mon, as_of)`:mon 非空→落按日视图「估值位监控」
     (payload = 监控读数 + `as_of`);开关关(mon=None,无敞口)→ 不落盘、返回 None。
     date-pin 到 as_of(防未来函数);payload 仅聚合读数(中位市值/倾斜比),无个股代码→无脱敏面。
   - `precompute` 在算完 mon、log 后调用它落盘。**落在 precompute 而非 run_factor**:
     precompute 同时被 `run_factor` 与 CLI `score._main` 调用,落这里两条入口都覆盖。

2. `tools/run.py:run_factor`
   - 编排日志补一行转发「估值位监控」读数(开关关→None 不刷屏),让池级流程日志里也有痕。

3. `tools/config/strategy.py`
   - 修正失实注释:由"见 screen_council view「估值位」块"改为指向真实落点
     (按日视图「估值位监控」+ `store.get_view` 回读 + `_persist_estvalue_monitor` 位置)。

**未动**:因子权重/口径/开关。市值分位等权(占价值 1/3)是刻意选择,本轮不碰;
是否降权/regime 门控待读数累积后另议。

## 预期效果

开着估值位跑盘选股后,`store.get_view("估值位监控", <交易日>)` 能查到当日「小市值倾斜」+as_of;
风格 risk-off 时该值异常偏低可被发现。config 注释与实际落点一致。

## 怎么读监控读数

```python
from tools.store import repo as store
store.get_view("估值位监控", "2026-09-10")
# → {"启用": True, "总市值覆盖":..., "全池中位总市值_亿":..., "高价值票中位总市值_亿":...,
#    "小市值倾斜": 0.x, "as_of": "2026-09-10"}   # 小市值倾斜<1 = 选股偏小盘(敞口)
```

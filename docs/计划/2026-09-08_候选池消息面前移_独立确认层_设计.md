# 候选池消息面前移 · 独立确认层(设计 + 落地记录)

日期:2026-09-08 · 分支:`feat/消息面前移候选池管线节点`

## 1. 背景 / 硬伤

全A 多策略选股(`run_screen_all`)在全A票上跑完出榜单,但最贵的新闻/LLM 情绪历史上只对很小的
子集采过。合议里 **情绪三层 / 事件驱动 / 资金流** 三位「消息面专家」因单票 record 缺
`sentiment / events / fundflow` 数据而**集体弃权** → 消息面根本没进选股。

项目根本特色应是「候选池消息面富集」做成**每日流水固定节点**:基础策略/合议选出候选后,自动对
候选池(~40–50 只)采新闻 + 跑分析,让消息面进入每日选股。

## 2. 方案(用户批准:先做「独立确认层」,不动全A主排序)

新增节点 `tools/pipeline/candidate_message.py`,插在「策略/合议出候选之后、上传之前」:

1. **候选池抽取** `build_candidate_pool(as_of, council_top_n=30, per_view_top_k=5)`
   = 合议(策略0)Top-N ∪ 各策略视图各前 K ∪ 自选池,去重保序(合议在前作骨架)。
   缺某 view → 该来源贡献 0(降级不崩)。**可复用函数**(供本节点 + 未来其它「只对候选池」贵活)。

2. **候选池消息面富集**(有界,只对候选池 ~40–50 只):
   新闻(`collect_message`)→ 三层情绪 + news_ai(`run_sentiment`)→ 事件(`run_events`)
   → 资金流补缺(供资金流专家发声)。**不含**财报三大表/年报采集(那是全A主流水职责)。
   全 `_safe` 隔离;`no_llm=True` 跳三层情绪。**严禁全A采新闻、严禁触发全量财报采集。**

3. **独立确认层**:富集后 `serialize` 候选池 record → 只召 `情绪三层/事件驱动/资金流` 三位消息面
   专家 `council.convene` 二次合议,给每只候选一个「消息面方向 + 理由」标注。落 view
   「候选池消息面确认」+ 按票 code_view「消息面确认」。
   **关键:不改写 `record['council']`(全A 合议主排序),不回灌打分**——只作附加确认信息。

4. **接入每日流水**:`run_screen_all` 收尾(`run_council/run_screen` 之后、上传前)接本节点,
   `_safe` 隔离 + 开关 `CANDIDATE_MSG_CONFIRM`(默认开=1);阈值开关
   `CANDIDATE_MSG_COUNCIL_TOPN`(30)/`CANDIDATE_MSG_VIEW_TOPK`(5)。
   另暴露独立 CLI `python -m tools.run candmsg [--date --no-llm --council-top-n --view-top-k]`
   供手动/定时**单独补跑**。

## 3. 护栏

- **有界**:采集/富集只对候选池;绝不全A采新闻、绝不全量财报。
- **不改主排序**:确认层用 `convene` 临时合议,从不落 `record['council']`。
- **优雅降级**:全程 `_safe`;缺 view/缺 record/LLM 未配置均降级不中止闭环。
- **防未来函数**:复用采集/合议层各自 as_of 锚定,本节点不放宽口径。

## 4. 测试(`tests/test_candidate_message.py`,7 项,全过)

候选池并集/Top-N/Top-K/去重/降级;消息面专家「有数据发声 / 无数据全弃权」双向锁;
缺 record 跳过;节点有界(只把 pool 传富集/组装)+ 落 view + 不改主排序;`no_llm` 透传。
广谱 `pytest -k "council or news or sentiment or pipeline or run or candidate"`:307 passed / 2 skipped / 0 failed。

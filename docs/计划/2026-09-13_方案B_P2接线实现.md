## 2. 接线点与实现方式的关键决策

### 2.1 接线点 = 收盘选股 SKILL（不是午盘）

每日收盘选股是 **prompt/SKILL 驱动**（无 python 编排器）。权威生成方：
`~/.claude/scheduled-tasks/daily-stock-selection/SKILL.md`（18:36，选 D 票、预测 D+1）。
它已硬性要求 md 第一行 `<!-- PICKS: code1,... -->`（`intraday_snapshot.parse_pick_codes` 权威源）。

- 午盘/日内是**另一个** SKILL：`daily-stock-intraday-check`（跟踪 D-1 选票）——与本接线**不撞车**。
- 撞车面核对：同期「午盘P0修整」窗改的是 `docs/每日分析/复盘/2026-09-10.md`、`经验沉淀/_待并入.md`、
  `docs/计划/推进总盘.md`、`ops/launchd/commit_analysis_docs.sh`（主仓工作树未提交改动已核）。
  本分支只新增 `docs/计划/`（本文 + sample）与 `tests/`，**文件零重叠**。

### 2.2 为什么 live SKILL 编辑交给统筹/主仓应用，而非本 chip 直接改

- SKILL 在 **git 仓库外**（`~/.claude/scheduled-tasks/...`）、不受版本管理，chip worktree 里改它
  **无法 commit、留不了痕**；且它是**生产定时任务配置**，按工程纪律"写生产只走主仓/dailyjob、
  chip 不污染生产"，不应由 chip 会话擅自热改生产 SKILL。
- 故本分支交付**可直接照抄的 SKILL patch（下 §3）+ 09-11 dry-run 实证 + 契约测试**；
  live SKILL 的一次性插入由**统筹核验后在主仓侧应用**（一段追加、低风险）。

## 3. 待应用的 SKILL patch（daily-stock-selection/SKILL.md）

在【机读锚点·硬要求】段之后、【收工最后一条命令】之前，**追加**下面这一步
（描述性写法，对齐方案 §4.5；只追加不重排现有段落）：

```markdown
【结构化产出·调用 Tool（canonical 机读选股 JSON）】完成逐票研判、定稿 md + PICKS 锚点后，
把每只票的**研判结论**整理成一个 analysis JSON（list[dict]，每票只填研判字段，客观字段留空），
调用：
  ~/.conda/envs/stock_analysis/bin/python -m tools.analysis.write_picks \
      --date <今天> --analysis <该JSON文件> \
      --picks-anchor <与 md PICKS 锚点相同的代码串> \
      --source-md docs/每日分析/选股/<今天>.md \
      --market-regime "<市场环境定性一句话>"
- 名称/行业/收盘价/涨跌/命中策略分值**一律不要手打**，Tool 从 record + 策略视图回填。
- Tool 写 `data/analysis/<今天>/每日选股.json` 并做 枚举/必填/情绪质量闸门/防未来/PICKS一致性 校验；
  **校验不过（非零退出）必须按报错修正 analysis JSON 后重跑，绝不带错落盘**。
- **今日跳过选股**时改为：
  ~/.conda/envs/stock_analysis/bin/python -m tools.analysis.write_picks \
      --date <今天> --status skipped --skip-reason "<原因，如：闭环未在门控窗口内完成>"
  （产出 status=skipped 的显式占位 JSON，与 md 的 `<!-- PICKS: none -->` 语义一致）。
```

> 说明：`--picks-anchor` 会断言 `picks[].code` 全集 == md 锚点，杜绝 JSON 与 md 选票漂移。
> `--predict-for` 缺省由交易日历推 D+1，一般无需手填。

### analysis 输入契约（每票单元，方案 §2.3）

```jsonc
{"code":"601872","type":"买入候选","buy_rank":1,
 "stance":"可参与","stance_qualifier":"条件式：放量站上20.98才入",
 "dir_1d":"低波待动","dir_1d_conf":"中","dir_5d":"偏多","dir_5d_conf":"中高",
 "sentiment_quality":"ok",
 "key_reason":"...","key_risk":"...","alpha_beta":"...",
 "watch_points":["...","..."],
 "strategies_hint":[{"name":"最强选股"},{"name":"最大范围选股"}],  // 分值由代码 join 回填
 "detail_anchor":"选股/<D>.md#1-601872-招商轮船"}
```

受控枚举（`tools/analysis/picks_schema.py` 单一真源）：
`type∈{买入候选,检验样本,规避}`、`stance∈{买入,可参与,观望,规避}`、
`dir∈{偏多,偏空,中性,低波待动,不给方向}`、`conf∈{高,中高,中,中低,低,-}`、
`sentiment_quality∈{ok,partial,unknown,missing}`。情绪盲区(unknown/missing)不得给 stance=买入 或"首选"。
`dir=不给方向` 时对应 conf 必须为 `-`。`buy_rank` 若给须 1..N 连续无重复（观望票可不给）。

## 4. 交易日 dry-run 实证（2026-09-11，不落盘、不污染生产）

**命令**（从主仓运行，读真实 09-11 数据；`--dry-run` 只校验不落盘）：

```bash
~/.conda/envs/stock_analysis/bin/python -m tools.analysis.write_picks \
    --date 2026-09-11 --analysis <09-11研判JSON> \
    --picks-anchor 601872,002913,300124,688262,002064 \
    --source-md docs/每日分析/选股/2026-09-11.md \
    --market-regime "普跌重挫日、连续第二个普跌×下行背离日，偏空非capitulation" \
    --predict-for 2026-09-14 --dry-run --print-md
```

**结果：exit=0，校验全过**。样例 canonical JSON：`docs/计划/samples/2026-09-11_每日选股.sample.json`。

客观字段回填核对（vs `docs/每日分析/选股/2026-09-11.md`）：

| 代码 | 回填名称 | 回填行业 | 收盘价 | 涨跌% | 与 md 一致 |
|---|---|---|---|---|---|
| 601872 | 招商轮船 | 交通运输（record.industry=None→code_industry 回退） | 20.0 | −2.82 | ✓ |
| 002913 | 奥士康 | 电子 | 72.49 | +2.11 | ✓（md"普跌日+2.11%"） |
| 300124 | 汇川技术 | 电力设备 | 53.52 | −1.73 | ✓ |
| 688262 | 国芯科技 | 计算机 | 25.99 | −2.77 | ✓ |
| 002064 | 华峰化学 | 基础化工 | 10.0 | −5.66 | ✓（md"−5.66%"） |

策略 join（score 回填）：`300124` 反转低换手组合#5(1.4405)、`688262` 半导体多因子#1(1.8094)
——与 md 所述"综合分1.44 / 1.8094全行业第一"**一致**。PICKS 锚点全集 == md 锚点（`--picks-anchor` 校验过）。

- **未污染生产**：`--dry-run` 无落盘，`find data/analysis -name 每日选股.json` 为空。
- **防未来**：dry-run 只用 09-11 及之前数据；record.as_of 均 ≤ pick_date，无未来告警。

## 5. 测试

新增 `tests/test_write_picks_wiring.py`（5 例，hermetic，桩 loader + tmp_path）——锁 **CLI 入口**接线契约：
1. `--dry-run` 正常回填 + 校验通过（客观字段代码回填 / 行业回退 / 混合 buy_rank）；
2. 客观回填失败 → 非零退出且**不落盘**（防带错落盘）；
3. `--picks-anchor` 与 picks 全集不符 → 非零退出（防 JSON/md 选票漂移）；
4. `status=skipped` → 显式落盘占位 JSON（结果未出的一等公民占位）；
5. 策略榜单命中 → rank/score join 进 JSON（md 表与 JSON 同源的底料）。

与既有 `tests/test_write_picks.py`（19 例，函数级）分工互补。**合计 24 例全绿**：

```bash
~/.conda/envs/stock_analysis/bin/python -m pytest \
    tests/test_write_picks_wiring.py tests/test_write_picks.py -q
# 24 passed
```

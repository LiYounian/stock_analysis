## 2. 基线试算（默认阈值）

\* 流动性下调方向：脚本在扫描期按基线过滤了 <1 亿的票，敏感性重施加时无法复活，需 `--set 流动性_20日均额=8e7` 重跑（已知限制，见 §5）。

**敏感性读数**：
- 吞吐对 **T1 量比**最敏感（1.2→258 / 1.5→165 / 1.8→97），对 **池 pos60 上限**次之（0.76→130）。
- **涨幅上限放到 10.8%** 会把 15 只涨停票放进池再被排雷踢出（排雷 5→20）；**pos60 上限放到 1.0** 同理（排雷 5→15）——池条件与排雷条件有 10~15 只的重叠带，二者只需保留一处。
- 极高位阈值 ±20% 对结果无影响（池 pos60<0.95 已先行截断）。
- T2 量比下调无影响（被池量比 1.2 截断）；T3 只有在池量比 <1.2 或 T2 量比 >1.2 时才非空。

**放宽池口径参考跑**（池量比 1.0 / 涨幅 >0 / 流动性 5000 万）：有效宇宙 3844，池 648，排雷 8（仍全为财报红旗），T1 226 / T2 205 / T3 209；T3 层评分 P10/P50/P90 = 28.8 / 38.5 / 57.1，T3 内 100% 为"收阳∧站上 MA5 但量比 <1.2"型。

## 5. D2 实现时还缺的工具 / 修复（按阻塞程度）

1. **per-stock 慢变字段全 A 覆盖**（阻塞）：龙虎榜 / 财报红旗 / 供给面排雷目前只覆盖 74 只有 json 的票，T1 165 只中 1 只有档。需 D1 `financial_redflag_tool` / `money_chip_tool` 支持按 code 列表批量取，或改读 raw 分区直接算。
2. **H2 688 volume 源头修复**：本脚本用 amount/close 反推可用，但 amount 缺失行仍靠启发式；应按板块分单位回填主档。
3. **H1 收盘闭环**：per-stock json 全为午盘版，快变字段不可用；本脚本绕开，但 LLM 否决层需要的 events / sentiment 收盘版缺。
4. **板块上下文接入**：`sector_focus` / `sector_regime` / `sector_roster` 17:31 可用但脚本未消费；需 D1 `sector_context_tool` 提供 code→(板块, 冷热, 角色, 拥挤分位) 查询，用于池内板块分层与"过热板块规避"程序化。
5. **外围宏观 regime 工具**：`global_macro_tool` 提供 β 倾向（哑铃 / 降 β）→ 可映射为池 pos60 上限 / 仓位系数。
6. **评分档位标定**：≥70 / 50~69 / 30~49 目前是工程占位；需 D3 按层 forward 记分后回填"分数段含义"。
7. **止损锚选择**：min(D 低, MA5)×0.99 在大阳线票上普遍 6~10%，需与 ATR 锚对比。
8. **名称 / ST / 行业表刷新**：`code_name.json` 08-09、`code_industry.json` 08-30 快照，需接调度。
9. **脚本已知限制**：流动性阈值下调方向的敏感性需重跑；池内层级判定与池条件重叠导致 T3 默认为空（设计上需决定 T3 是"池外放宽层"还是"池内最低层"）。
10. **市场 β 基准 market_ew**（H3/H4）：本脚本自算等权可作临时替代，正式 α 记分仍需落盘链。

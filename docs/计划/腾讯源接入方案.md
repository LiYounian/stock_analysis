# 腾讯(gtimg)源接入方案

> 版本:v1 · 2026-09-09 · 状态:**待审阅**(审完再动代码,符合"行动前写文档"纪律)
> 范围:仅**行情/量价**类。资金流/财报/事件/舆情/票池腾讯给不了,本方案不涉及。

---

## 0. 一句话结论(先纠一个现状误判)

调研初期曾判断"日K让 baostock 当主力、腾讯兜底",**读代码后修正**:`tools/collectors/market.py`
的日K多源链**早已是 腾讯 → 新浪 → 东财,腾讯就是主力**(当日盘后即含当天 bar,比 akshare-tx
新鲜约 1 交易日;东财被 TLS 指纹墙置末)。`gtimg_quote.py` 的实时快照也早是单一事实源。

所以**腾讯在日K/快照上没有"要不要换"的问题**。本方案真正新增的只有两块,外加一块口径加固:

| 块 | 性质 | 现状 | 本方案动作 |
|---|---|---|---|
| **A 分钟K** | **net-new** | 项目完全没有 | 新增 collector + 新 kind `kline_min`,腾讯为唯一主力 |
| **B 当日逐笔** | **兜底冗余** | 仅 `tdx_l2`(mootdx TCP,盘中/盘后当日常返空) | 加腾讯 HTTP 逐笔作**当日兜底**,历史回补仍归 mootdx |
| **C 日K复权口径** | **加固(不改主力)** | 腾讯已主力,但复权对齐无常态校验 | 文档化口径 + 加一道 baostock 基准校验 gate |

## 1. 现状盘点:哪些已用腾讯,哪些是真空白

| 行情子需求 | 现状源/实现 | 腾讯地位 |
|---|---|---|
| 实时快照(88 字段) | `gtimg_quote.py` 单一事实源 | ✅已是主力 |
| 历史/增量日K(前复权) | `market.py` 腾讯→新浪→东财 | ✅已是主力 |
| 全量历史"滚动主档"日K | `baostock_src.py`(一次性全量) | baostock 主力(深度+复权基准),腾讯不抢 |
| 港股日K | `market.py` `_fetch_tencent_hk` | ✅已用腾讯 |

## 2. 落盘层约定(先对齐,免得方案跟现状打架)

读 `tools/store/repo.py` 得到的硬约束,本方案全部遵守:

- 写入接口:`store.put_raw(kind, code, df, meta={"source": ...})` → 落
  `raw/<date>/<kind>/<code>.parquet`(或 json)。**按日期目录分区**,日期取
  `store.active_date()`(编排入口 `set_active_date` 设的 as_of,防未来函数)。
- **去重语义 = 幂等覆盖**:每个 `(date, kind, code)` 是一个**整文件快照**,重跑当天直接覆盖,
  **不做行级 append**。所以"去重"发生在**文件内**(写前 `drop_duplicates`),不是跨文件累积。
- `meta.source` 记录**实际命中源**(market.py 已有先例)——多源/兜底场景靠它区分谁写的。
- 新增 parquet kind 必须登记进 `repo._PARQUET_KINDS`,否则 `put_raw` 抛 `ValueError`。
- 现有相关 kind:`kline`(日K)、`index_kline`、`board_kline`、`tick`、`tick_summary`、
  `fundflow_intraday`。

## 3. 逐块设计(输入 / 输出 / 翻页 / 落盘去重 / 校验)

### 块 A — 分钟K(net-new)

**端点**
```
https://ifzq.gtimg.cn/appstock/app/kline/mkline?param=<sym>,<mtype>,,<num>
例: .../mkline?param=sh600519,m30,,320    # sym带交易所前缀; mtype∈{m1,m5,m15,m30,m60}; num≤320
Header: Referer: https://gu.qq.com/   (实测不带也返回,生产带上更稳)
```

**输入契约**
| 参数 | 值 | 说明 |
|---|---|---|
| `code` | 6 位 | 经 `market_prefix()` 加 sh/sz/bj 前缀 |
| `freq` | m1/m5/m15/m30/m60 | 默认 m30(日内特征够用,数据量小) |
| `num` | ≤320 | 端点硬上限,**单次拿不到更长历史**(见风险 R4) |

**输出契约(规整帧,与日K `_STD_COLS` 同构以便复用下游)**
```
columns = [datetime, open, high, low, close, volume]   # volume 单位:手→×100 归一到"股"(与 market.py 一致)
dtype:   datetime=pd.Timestamp(分钟级), 其余 float
排序:    datetime 升序, stable
```
> ⚠️ mkline 原始数组字段序实测为 `[时间, 开, 收, 高, 低, 量]`(**开后是收,不是高**),
> 与日K的 `[开,收,高,低,量]` 一致但与直觉不同 → **解析处必须按位取,并加一条
> `high≥max(open,close) & low≤min(open,close)` 的断言**兜住字段漂移(见风险 R1)。

**翻页**:mkline **无真正翻页**,`num` 封顶 ~320 根。策略:**只做近端**,不拼历史。
m30×320 ≈ 40 交易日日内,足够日内/近端特征;需要更长历史的场景走日K,不用分钟K。

**落盘去重**
- 新 kind:**`kline_min`**(登记进 `_PARQUET_KINDS`)。
- 文件粒度:`raw/<date>/kline_min/<code>.parquet`,存**当日采集时点的近端窗口**。
- 去重:写前 `df.drop_duplicates(subset=["datetime"], keep="last")`;当天重跑幂等覆盖。
- `meta = {"source":"tencent", "freq":"m30", "num":<实际根数>, "as_of":<active_date>}`。

**复权**:mkline 返回**不复权**原始价。**只在不跨除权日的日内场景使用**,天然规避复权问题
(见 §4 与风险 R4)。文档明确:分钟K **不进历史主档、不做跨日复权拼接**。

### 块 B — 当日逐笔(腾讯 HTTP 兜底 mootdx)

**端点**
```
https://stock.gtimg.cn/data/index.php?appn=detail&action=data&c=sh600519&p=0
p=0,1,2... 翻页; 免鉴权
```

**输入契约**:`code`(带前缀)、`page` 从 0 递增。

**输出契约(与 `tdx_l2` 的 tick 帧对齐,才能共用 kind)**
| 列 | 来源 | 说明 |
|---|---|---|
| `time` | 逐笔时间 | HH:MM:SS |
| `price` | 成交价 | float |
| `change` | 涨跌 | 腾讯特有,可留可丢 |
| `volume` | 量(手) | ×100 归一到"股"以与 mootdx 对齐 |
| `amount` | 额 | float |
| `bs` | 方向 | 腾讯 `B/S/M` → 映射到项目 tick 的买卖方向枚举(**需实测对齐,见风险 R5**) |

**翻页**:`p` 从 0 递增,每页 N 条,**累积到返回空页为止**(与 `tdx_l2` 对 mootdx 的
分页累积同构)。累积后按 `(time, 序号)` `drop_duplicates` + `sort_values("time", stable)`。

**落盘去重(关键:避免与 mootdx 争同一文件)**
- **复用** kind `tick` + `tick_summary`(**不新增 kind**),明细→`tick`,摘要→`tick_summary`。
- **单写者编排**:当日逐笔归档编排先试 `tdx_l2`(mootdx),**返回空则回退腾讯 HTTP**,
  **只写一次**,`meta.source ∈ {"tdx","tencent"}` 记实际命中源。
  → 复刻 `market.py` 的"多源 fallback + meta.source"模式,杜绝双源覆盖竞争(风险 R6)。
- 历史回补(`date=<过去某日>`)**仍只走 mootdx**,腾讯不参与(其历史深度弱)。

### 块 C — 日K复权口径校验加固(不改主力,只加一道 gate)

腾讯已是日K主力,但复权口径目前**无常态校验**。本块**只加校验、不改采集主力**。

**基准**:`baostock_src.py` 注释已确立——**baostock 前复权(adjustflag=2)与 akshare 前复权
在最新交易日收盘精确一致**,作为**复权对齐的锚**。

**校验设计(离线校验脚本 / CI,不进盘后热路径)**
```
对抽样 N 只(建议覆盖:近期除权、高分红、次新、停复牌各若干):
  拉 腾讯qfq 与 baostock qfq 的重叠日期段 close
  gate1(硬): 最新交易日 close 相对误差 < 1e-4   → 违反=告警/阻断
  gate2(软): 历史段 close 相对误差中位数 < 阈值(建议 0.5%)
             历史老 bar 因分红除权累积可能偏大属**已知**,超阈值只告警不阻断
输出: 对齐报告(每票 最新误差 / 历史中位误差 / 最大偏离日),落 docs/计划/ 或 logs/
```

## 4. 复权口径对齐总则

| 数据 | 腾讯口径 | 对齐策略 | 风险级 |
|---|---|---|---|
| 日K(块C) | fqkline 支持 qfq/hfq | 以 baostock qfq 为锚,gate 校验(§3-C) | 低(已生产验证) |
| 分钟K(块A) | **不复权** | **只日内用、不跨除权日、不进主档** → 规避 | 低(靠使用约束规避) |
| 逐笔(块B) | 原始成交价(不复权) | 逐笔本就是原始成交,不复权;与 mootdx 同口径 | 低 |

**统一口径纪律**:volume 一律"手→×100 股";turnover 若涉及走 `units.to_percent(source)`
分源归一(market.py 既有);跨源拼接**必须**旁记 `meta.source` 供口径追溯。

## 5. 数据能否对齐评定 + 风险登记

### 5.1 对齐可行性评定

| 块 | 能否对齐 | 置信度 | 依据 |
|---|---|---|---|
| A 分钟K | **能**(日内自洽) | 中高 | 不复权+不跨除权日,日内相对口径自洽;字段序有断言兜底 |
| B 逐笔 | **能**(需一次实测锚定方向) | 中 | 价/量/时间可直接对齐 mootdx;**唯 `B/S/M` 方向定义需实测确认**与通达信内外盘一致 |
| C 日K | **能** | 高 | 已生产运行 + baostock 锚点,只是补常态校验 |

### 5.2 风险登记

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| **R1** | mkline/detail **无官方契约**,字段序可能漂移 | 静默错列 | 防御式按位解析 + `high/low` 关系断言 + 单测锁字段序 |
| **R2** | 复权历史老 bar 因分红除权累积偏差 | 历史段轻微不对齐 | 已知;gate2 软阈值告警,不阻断;最新收盘硬 gate |
| **R3** | mkline 高频被腾讯 WAF 501 / 限流 | 采集失败 | 复用 market.py 的 qq 反代 fallback + Referer + 限速批量 |
| **R4** | 分钟K **近端 only**(≤320根),无历史深度 | 不能回补历史分钟 | 使用约束:分钟K只服务日内/近端,历史走日K |
| **R5** | 逐笔 `B/S/M` 方向定义与 mootdx 内外盘**可能不一致** | 资金方向口径错 | 接入前**实测同一票同一日两源比对**,写死映射+断言;不一致则方向字段标 source |
| **R6** | 腾讯 tick 与 mootdx tick **争同一落盘文件** | 互相覆盖 | 单写者编排(先 mootdx 空则腾讯),只写一次,meta.source 记源 |
| **R7** | 逐笔历史回补腾讯能力弱 | 回补不全 | 历史回补锁定 mootdx,腾讯只兜当日 |
| **R8** | 北交所/停牌/退市前缀异常 | 采集报错/脏数据 | 复用 `market_prefix()` 前缀映射 + 港股/异常跳过 |
| **R9** | GBK 编码 / 单位(手 vs 股) | 乱码/量级跳变 | 统一 decode gbk + volume ×100 归一(既有先例) |

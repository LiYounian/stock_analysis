# 策略计划 · 消息驱动板块拐点（**forward-tracked 轻量实验**）

> 日期 2026-09-15 ｜ 分支 `feat/pattern-strategy` ｜ 状态：**待统筹审**（scope 已按统筹裁决收窄）
> ⚠️ 测试环境研究模拟，**非投资建议**。不合 main、不换线（换线交统筹）。
> 来源：反推某成功投资者 16 只买点 + 朋友 MLCC 活样本（村田退出）。是"形态选股"chip 的方向演进。
>
> **【Scope 定调·统筹裁决】** 本线**不是历史回测线**：消息数据仅 ~1 个月、不可历史 validate。故 scope = **"消费 regime 板块环境层 + 催化拐点检测的 forward-tracked 轻量实验"**：
> - **消息层 = forward-shadow 纯记录、不 gate 任何生产决策、明确标"未 validated"**，攒够独立样本（≥120 级）才谈 validate。
> - **技术外壳保持证伪**（单独 α−0.9%，不单用）；**MLCC = 佐证非证据**（一个事后叙事，证明不了策略）。
> - **绝不据未 validated 的消息信号动 `stock_pool.json` 等生产**（生产改动计划里提、统筹审后统一做）。
> - **历史新闻回填 = 先不做、不立**（本质是"投入数据层"的更大战略投入，留用户单独决策；forward 实验显苗头再议）。
> - **分工**：regime chip = 板块环境层（价量温度 + 情绪 forward-shadow）**独家产出**；本线 = **拐点检测/选股应用层、消费不重造**。

---

## 0. 一句话

**消息催化（供给侧退出/涨价/禁令反转小作文）→ 识别板块正拐点（过冷转热 / 结构性利好）→ 在该板块的龙头/成员上、用"缩量回踩+高开反包"进场埋伏。** 消息层是核心 edge，技术形态是进场外壳（单独为负）。

---

## 1. 证据脉络（为什么这么定）

1. **反推 16 只赢家（校验后 14 有效）**：共性**不在技术形态**（双峰：有抄底有追强势），**在"押对当期热产业主线"**——消息面 13/14 落在 AI算力硬件+电子材料涨价周期，催化 71% 是板块题材联动。
2. **技术骨架单独证伪**：全A历史回测"缩量回踩+高开反包·买开盘" **α −0.9% 显著负**（追高开、均值回归）。→ 技术形态是外壳、单独亏钱。
3. **消息催化把亏钱动作变赢钱**：朋友 MLCC 活样本（2026-09-11）全流程验证成功——村田退出低端MLCC（利好·强4·结构性）→ 龙头 9-10 缩量回踩 → 9-11 高开+1.2%反包 → 风华涨停+10%。**是消息催化让"追高开"这个generically亏的动作赢了。**
4. **纯价量冷行业组合层失败**（前轮严验：热优先223% > 冷优先163%/回撤−30%）→ 印证"**光价量过冷不够，要消息催化确认拐点**"。

## 2. 策略三层结构

### 2.1 板块环境层（价量过冷过热）— **复用过冷过热chip，不重造**
- 消费 regime/行业温度计的**因果价量温度**（RS-动量/估值分位/换手分位 → 遇冷/遇热档）。
- 接口：`industry_heat(code|板块, date) -> 温度档/分位`（因果 PIT）。**确切签名待与过冷过热chip协调后填**（见 §7 待办）。
- 角色：给"这个板块此刻价量上是过冷还是过热"的底。

### 2.2 消息催化层（**消费 regime 的板块情绪层，不自建**）
统筹裁决：regime 已建 `sentiment_judge.py`（LLM 读 policy/news → 行业情绪档/news rollup/going-forward），与自建 sector_sentiment **大面积重叠**。故**本线不建该模块**，改为**消费 regime 板块情绪 forward-shadow 输出**（接口/落盘待与 regime chip 对齐，见 §7）。
- **消费**：regime 的 `板块情绪档/分位`（as-of）+ `板块价量温度`（`industry_heat`/`get_industry_thermometer`）。
- **本线只做"催化拐点检测"应用层**（在 regime 的情绪/温度序列上，不碰其采集/打分基建）：
  - **正拐点** = 板块情绪档由冷转热（符号翻转 / 因果分位突破，若 regime 未直接产"拐点"信号则本线在其序列上算）+ 当日有"结构性持续/印证强度强"的根源催化。
  - 共享基建 `news_recall/policy/event.py` 一律走 regime 那套，不两套。
- **拐点归属待定**：若 regime 已产"拐点/翻转"信号 → 本线直接消费；若只产"当前冷热档" → 本线做拐点检测（消费其输出）。以 regime 回复为准。

### 2.3 成员进场层（技术外壳，只在消息-正催化板块内用）
- 龙头/成员出现"缩量回踩支撑"（量比<0.8、贴 MA20、上升趋势中）后，次日"高开反包"（开盘价买入）。
- 或退而用已验证的"回踩限价埋伏"（买低不追高，α 更好）——**入场口径回测对比 §5**。

## 5. 验证方案与统计口径（正视用户三点难点）

### 5.1 消息实时性 → forward-only（硬约束 + 护栏）
消息数据只近端~1个月、时点不可复原。**消息层不做历史 OOS**；验证 = **forward-shadow 每日记录板块拐点信号 + 跟踪次日/5日/10日实际走势，攒够独立样本（≥120 级）才谈 validate**。在此之前一律标"**未 validated**"、**纯记录不 gate 生产**。MLCC/16赢家 = 佐证非证据（不进判据）。历史回测仅覆盖技术外壳（已证伪单独负）+ regime 价量层（已有历史结论）。范式 = **forward 实盘实验**，非"历史回测定生死"。

### 5.2 提前埋伏风险 → 显式统计
埋伏=限价挂单+明确止损。中途震荡损失用**持有窗内最大逆行 MAE** 显式报告 + 止损兜底；给"埋伏期回撤分布"，不藏震荡代价。

### 5.3 统计口径 1/5/10 日 → 当参数扫
持有窗 ∈ {1,5,10} 交易日全扫；**"有效"定义 = 窗内触及 +X% 明显盈利**（目标达成率），分窗报 目标达成率/收益/胜率/MAE。让数据说哪个窗口口径合理，不预设。

## 6. 防未来 / 防过拟合
- **消息 as-of 切片**：`baidu_news.news_asof(code, as_of)` 带真实 publish_ts，回测按 as-of 切、无前视；`event` 的新鲜度三态 date-pin。
- **因果分位**：板块情绪/价量温度分位一律 `causal_rolling_pctile`（≤t）。
- **样本诚实**：16赢家/MLCC 是活样本佐证、非证据；无反例（用户无），故消息层结论标"近端验证+实盘待累积"，不夸大。
- **不裸用技术外壳**（单独负）。

## 7. 消费接口（已与 regime chip 对齐，`epic-ellis-af3f88-9e`）
- **价量温度（历史序列 ~1.5yr，可历史用）→ 喂"价量拐点"**：`thermometer.build_thermometer_panel(dates, membership)` → DataFrame[date, industry, 拥挤分位, 拥挤(A/B), 动量_时序分位/档, 动量_截面分位/档, **情绪(恒 None，panel 不读 shadow)**, n_members]；点查 `get_industry_thermometer(date)`；个股 `industry_heat(code,date)`。⚠️ panel 的情绪列恒 None，情绪**不从 panel 取**。
- **板块情绪 forward-shadow（forward-only，接调度后才积累）——两个口分开用**：
  - **A/B 档**（去偏后）：`sentiment_judge.read_sentiment_shadow(date, DIR)` → `{industry: 情绪_相对(A/B)}`。
  - **连续净A度（算 delta/拐点用）→ 喂"情绪拐点"**：`sentiment_judge.get_industry_sentiment_series(industry, dates, shadow_dir)` → `{date: 净A度∈[-1,1]}`（**3 参，必传 shadow_dir**）；或读 payload 每条 result 的 `净A度` 字段。
  - forward-only：接调度前无历史落盘 → 返回 `{}` 属正常，按 as-of 消费、缺省跳过；payload 标 `非validated:true/forward_shadow:true`；去市场基线用 payload 顶层 `基线净A度中位数`（或直接用去偏的 情绪_相对）。
- **拐点两条分开**：价量拐点吃 `build_thermometer_panel`（拥挤/动量_时序分位突破/档翻转，有历史）；情绪拐点吃 `get_industry_sentiment_series`（净A度 delta/符号翻转，forward-only）。
- **共享基建（不另搭）**：`news/policy/event.py` + `code_industry` + regime 的 `gather_pit_text/gather_pit_news_text`（code→行业 rollup + PIT 取数）= 单一真源。便宜无 LLM 催化（事件计数/baidu 利好利空标签）复用其 gather 取数、只加计数逻辑。

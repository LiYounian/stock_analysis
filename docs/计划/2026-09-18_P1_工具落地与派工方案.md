# P1 · D2 最小依赖 7 工具 · 落地与派工方案

> 日期 2026-09-18 ｜ 上游：D1 设计稿 v1.0（已审）§2 注册表 / §3 工具清单 ｜ 性质：执行派工方案
> 目标：搭出 D2 流程能直接调用的 7 个工具，**框架契约统筹自己搭**（所有工具依赖同一契约，不能三窗各造导致发散），再 3 窗并行填工具。
> 铁律：每工具走注册表 schema（四件套 + freshness + 防未来 + 档位语义锁测试）；产出"浓缩块 ≤8 行"，**禁裸 json 进 prompt**；只信主档 K 线；as_of 防未来。

## 0. 依赖与切分（先框架，后并行）

```
P1a 框架契约(统筹自搭·阻塞) ──► P1b 三窗并行
   registry.py / tool_registry.yaml        窗1 量价工具族(4): shared_pool→gate→price_volume→entry_price
   ToolResult(浓缩块/freshness/防未来)       窗2 板块(1): sector_context
   CLI harness + assert_no_future           窗3 经验+假利好(2): experience_rules + fake_good_news
   一个参照工具(entry_price)做样板
```
切分依据（守则12 解耦后并行）：窗1 四个都在①塔基、共用 K 线与 pyramid_select_v1 逻辑、互相喂数据 → 同窗串行避免冲突；窗2 只读 sector_*.json，独立文件；窗3 两个都不依赖量价、各读经验散文/events，独立。三窗不改同一文件。

## 1. P1a 框架契约（统筹自搭）

**新目录 `tools/pyramid/`**：
- `registry.py`：
  - `@dataclass ToolResult`：`name/塔层/as_of/code/fields(机读dict)/浓缩块(str≤8行)/freshness(fresh|stale|missing)/防未来(bool)/source`；方法 `to_prompt()` 只吐浓缩块（**禁 json.dumps**）。
  - `class PyramidTool(Protocol)`：`name:str; 塔层:str; run(as_of, code=None, **kw)->ToolResult`。
  - `register(tool)/get(name)->PyramidTool/list_tools()`（后者读 yaml）。
- `__main__.py`：CLI `python -m tools.pyramid tool <name> --as-of D [--code X]` → 打印浓缩块；`python -m tools.pyramid list` → 列注册表。
- `_common.py`：`assert_no_future(df, as_of, date_col)` 防未来断言；`load_kline(code, as_of)`（读主档 parquet、截 ≤as_of、688 量能 amount/close 校正）；`格档(value, 档位表)->(档名, 一句解释)` 统一档位渲染；`浓缩块(fields, 档位映射)->str`。
- `tools/config/tool_registry.yaml`：工具清单 SSOT（name/塔层/inputs/outputs字段/freshness来源/防未来/tests 路径），Agent 开工先读。
- 参照工具 `entry_price_tool` 由统筹随框架一起实现，作为其余 6 个的**样板**（复用 `selection_synth.fill_entry_exit`）。
- 测试 `tests/pyramid/test_framework.py`：ToolResult 契约 + CLI smoke + assert_no_future 断言 + entry_price 档位锁。

**验收（P1a）**：`python -m tools.pyramid list` 列出 7 个占位；`tool entry_price --as-of 2026-09-17 --code 300308` 打印 ≤8 行浓缩块含首入场/加仓/红线/止损 + 单调性；框架测试绿。

## 2. P1b 七工具 · 四件套 IO（派窗口）

### 窗1 · 量价工具族（①塔基，串行 shared_pool→gate→price_volume→entry_price）
复用 `tools/experimental/pyramid_select_v1.py` 的池扫描/闸门/评分/回填逻辑，重构进注册表。

1. **shared_pool_tool** — inputs(as_of)｜outputs：统一召回池 + **来源标签**（≥2策略并集∪council top∪板块roster∪Agent主线∪全A K线过闸），K线复核**不给特权**（四模式票池不相交的补丁）｜freshness：各来源口径日期｜浓缩块：池规模 + 各来源命中数 + 交并集说明。
2. **gate_tool** — inputs(as_of, code)｜outputs：T1/T2/T3 层级 + 触发原因（放量收阳/站上MA5·前高/量比/未近涨停）｜阈值写死并档位锁｜688 校正｜浓缩块：层级 + 每条闸门 pass/fail + 一句。
3. **price_volume_tool** — inputs(as_of, code)｜outputs：snapshot/signals 量价字段 + **session 标记(午盘/收盘)** + 单位统一 + **H2 688 修复**｜浓缩块：现价/涨幅/量比/位置各带档位。
4. **entry_price_tool**（样板，统筹已搭）— 首入场=D+1开盘附近限价 / 回踩=加仓 / 红线 / 止损，公式公开、单调夹逼。

### 窗2 · sector_context_tool（④板块，独立）
inputs(as_of, code)｜读 `sector_focus.json/sector_regime.json/roster`｜outputs：**每票 6 字段**（板块 / 冷热拥挤档 / RS分位 / 角色 / 板块内排名 / 净催化）｜focus_score 档位｜浓缩块 6 行。

### 窗3 · 经验 + 假利好（独立）
5. **experience_rules_tool** — 把 `docs/每日分析/经验沉淀/*.md`（712K·14 版散文）**拆成结构化规则库**（规则/作用环节/状态/证据），按环节取用，消除每日 43K 输入｜outputs：按 code 或环节返回适用规则条目 + 出处｜浓缩块：命中规则条 + 一句。
6. **fake_good_news_tool** — inputs(as_of, code)｜读 per-stock `events` + K线 D-1/D 价格行为｜判据"利好兑现日高开走弱 + D-1 结果回看"（程序无记忆的补丁）｜outputs：假利好嫌疑档 + 判据命中｜浓缩块：嫌疑等级 + 证据行。

## 3. 每窗任务书要点（派发时带）
- 统筹身份 + 暗号 + 完工回执 + 别自合 main（memory：spawn-chip 必写）。
- 契约冻结：`tools/pyramid/registry.py` 的 ToolResult / PyramidTool 已由统筹定，**不许改契约**，只实现 `run()` + 注册 + yaml 条目 + 测试。
- 每工具：注册表四件套齐 + 档位语义锁测试 + 浓缩块 ≤8 行 + 禁裸 json + as_of 防未来 + 分步 commit + 不 push。
- 数据铁律：只信主档 K 线；688 量 `amount/close` 校正（H2 未合前自校）；per-stock 仅取慢变字段（H1 午盘版感知）。
- 脱敏：不写品牌网关名、不写暗号进 tracked 文件。

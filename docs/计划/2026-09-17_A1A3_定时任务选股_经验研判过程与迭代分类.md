**与 SOP 文本的差异（重要，金字塔骨架要照实际而非照纸面设计）**：
1. **"逐票"实际是"批量"**：数据层（阶段 5）、消息面（阶段 7）都是一次脚本拉多票，逐票的只是最后写结论；SOP 步骤 0~4 的"每只票走一遍"在执行上被压成"一批票同时走"。
2. **消息面在定稿之后**：5 只票在阶段 5 末已定稿，阶段 7 的新闻只用来纠名/找催化/定表态，**不用于淘汰**（09-15 run 是反例：新闻层把两只"军工"纠成出口链，改变了解读但也未换票）。
3. **候选池 = 策略视图并集，不触碰全A**：全A→策略视图这一层由程序闭环（pull_refresh）在 16:05 前完成；Agent 起点是 9 张视图各 ~25 只、命中 ≥2 的 71 只。
4. **有无 per-stock json 决定研判深度**：无 json 的 wr>99 动量票要现算技术面且拿不到 financing/holder（09-17 的 601872 供给面"固定一问"移交次日；09-15 run 为 3 只缺 json 票现场 serialize 花了 2.5 分钟）。
5. **每日约 3.3 分钟（≈20%）花在探 write_picks schema 与校验循环上**，三天 run 都出现，属可一次性固化的开销。

### 1.6 怎么收敛分档

- **枚举由代码锁死**（`tools/analysis/picks_schema.py`，轮 36 结果）：TYPE {买入候选, 检验样本, 规避} × STANCE {买入, 可参与, 观望, 规避} × DIRECTION（偏多/中性/偏空/低波待动/不给方向）+ 置信；入场扩字段（入场规则/类型/限价/观测窗/回踩位/卖出线/止损/收盘为正概率）。
- **人工封顶规则**：情绪质量 `unknown/missing` 的票表态封顶降一级（机制文档 §4 规则 7；09-16 run 明示"东田微 sentiment=missing → cannot be stance=买入"）；游资情绪票不给方向；普跌日不硬凑 3~5（#10⑥）。
- **09-17 收敛结果**：5 票 = 买入候选 2（均"可参与"、无一"买入"）+ 检验样本 2（观望 1、规避 1）+ 规避 1；排序表一句话理由各引经验编号（#34/#2/#22/#10⑥）。

## 4. 对金字塔骨架设计的直接输入（摘要）

1. **实际研判是"池级批量 → 票级批量 → 逐票写结论"三段**，不是纸面"每票走一遍六步"。金字塔的中层（票级研判）可以并行化：深数据/新闻/技术面按票独立，只有最后的排序与分档需要汇总。
2. **候选池起点是 9 张策略视图并集（≥2 命中 71 只）**，全A→视图由程序闭环完成；金字塔"塔基"应对应程序召回层，Agent 不碰全A。
3. **每票 ≈2 min / 7K 输出 / 10K 新增输入**；固定开销 ≈5 min 中有 3.3 min（schema 探查）可消除、43K 读经验输入可通过拆分规则库压缩。
4. **34 条经验中 16 条研判思路 + 7 条闸门可直接进规则库**；9 条记分口径进评测层；SKILL.md 2B/2C 的权重/输入调整应参数化为策略层配置。
5. **板块优劣用程序浓缩字段喂 Agent**（+1 min / +5K 输入），不让 Agent 现场算。

# /selection-analysis 页「选股 ↔ 复盘对应 + 名称」修复设计（2026-09-09）

> ⚠️ 测试环境研究模拟，非投资建议。**只改 web 展示 + 摘要抽取 + α 计算这条链**；
> 不动选股/复盘 md 生成、不动 launchd、不动上传管线口径。

## 一、问题现象（远端 `/selection-analysis?date=2026-09-09`）

- **选股分析表**：D 日选出的票（601061 中信金属等）有名称，但「复盘结果」列全「待复盘」、「午盘分析」全「—」。
- **复盘结果表**：列的却是**自选盯盘池**（300209/300476/601975…），**名称列全空**，与上面的选股**对不上**。

## 二、根因

1. 旧实现复盘侧直接抽 `复盘/<D>.md` 里那张表——那是「自选盯盘池/盘中核实」表，
   **不是**对（D-1）实际选出票的复盘。某些日子（D-1 选股当时被判跳过）复盘对象干脆成了自选池。
2. 没有「D 选股 ↔ D-1 选股复盘」的日期对应；名称易丢。

## 三、新口径（本次实现）

`/selection-analysis?date=D`「每日盘后选股」区两表：

1. **今日选股（D）**：读 `选股/D.md` 买入排序（带名称）；每票「复盘结果」列 = 该票**次日 D+1 的 α**
   （从 D+1 数据回填）；D+1 未到/未复盘 → 「待复盘」；**D 当天选股跳过/未出 → 整表「结果未出」**。
2. **对昨日（D-1）选股的复盘**：取 `选股/D-1.md` 的**实际选出票**（`parse_pick_codes`，**非**自选盯盘池），
   逐票 **名称 + α**；**α 由代码算** = 该票 D 日涨跌%（`record.snapshot.pct_chg`）− D 日全A等权 mean_pct
   （口径同项目 α=等权基准），**不 parse 复盘 md 里那张错表**；D-1 选股跳过/未出 → 显式「昨日选股结果未出」。
3. **名称**：一律走回退链（`record.meta.name` → `config/code_name.json` → code），复盘表名称列不空。
4. 页面日期标签清晰区分「今日选股（D）」vs「对昨日（D-1）选股的复盘」。

## 四、α 计算口径

- α_val = round(该票衡量日 pct_chg − 衡量日全A等权 mean_pct, 2)。
- 「对昨日 D-1 选股复盘」：衡量日 = D（D-1 的次一交易日）。
- 「今日选股 D」的复盘列：衡量日 = D+1。
- 基准 mean_pct 主源 = `data/breadth/<date>.json` 的 `mean_pct`；缺则兜底解析 `选股/<date>.md` 市场表
  「全A等权 mean_pct」行（兼容 `+` 与 Unicode 负号 `−`）。都无 → α=None（渲染「—」，不假造）。
- pct 或基准任一缺 → α=None；D+1 基准缺（次日未到/未复盘）→ 今日票列「待复盘」。

## 五、代码分层（守则 #5 输入输出分明）

- **`tools/selection_summary.py`（纯函数，可注入 provider）**新增：
  - `parse_equal_weight_mean_pct(md_text)`：市场表抽等权基准（breadth 缺失时兜底源）。
  - `alpha_scorecard(picks, quote_of, benchmark, name_of)`：逐票 α 记分行（等权口径，代码算）。
  - `build_postmarket_view(date, *, parse_picks, prev_trading_day, next_trading_day,
    quote_at, benchmark_at, name_of)`：装配两表；取数全部 provider 注入，故仍不触网、可独立单测。
  - `_fmt_alpha`：+X.XXpp / −X.XXpp 显示串。
- **`web/data_access.py`（展示层，接真实源）**：
  - `selection_analysis_view(date)` 改为调 `build_postmarket_view`，wire 真实 provider：
    `parse_pick_codes`（选股码权威解析）、`calendar.next_trading_day` /
    `intraday_snapshot.prev_trading_day`（交易日历）、`_selection_pct_at`（`store.get_record` →
    `snapshot.pct_chg`）、`_selection_benchmark_at`（`equal_weight_index.load_daily_mean_pct` +
    md 兜底）、`_resolve_name`（名称回退链）。任何异常都不炸页 → 退空结构。
- **`web/templates/selection_analysis.html`**：两列改为「今日选股（D）」/「对昨日选股的复盘（D-1）」，
  加跳过态占位（结果未出 / 昨日选股结果未出）、名称回退渲染、α/基准口径说明脚注。

## 六、兼容与边界

- `build_selection_view` / `enrich_view_cross_refs` / `extract_*` **保持不变**（上传管线
  `import_to_db.collect_date` 仍用之注入 store 视图，旧单测全绿）；web 不再读该 store 视图的盘后区，
  改为每次从 docs md + store 现算（docs md 与 breadth/records 在远端均 git 跟踪可得）。
- 无 store 记录（如本地 worktree 无 09-09 记录）→ α 空、名称仍从 code_name.json 回退非空、票列正确。
- 交易日历 `allow_fetch=False`（展示层不触网）。

# 趋势模板股票筛选系统 · 需求与方案

> 状态：**待审阅** · 日期：2026-08-19 · 分支：`feat/trend-template-screener`
> 一句话：出「符合米勒维尼完整 8 条趋势模板、处于第二阶段上升趋势」的 A 股候选清单。
> ⚠️ 非投资建议。本系统**只做第一层趋势过滤**，不含买点确认、VCP、枢轴点、突破放量、自动交易。
> 来源：策略提供者《趋势模板股票筛选系统需求文档 v1.0》，2026-08-19。

## 一、与现有 SEPA+VCP 监控的关系（先读这节）

提供者先后给了**两份 SEPA 家族需求，刻意分工、互补不冲突**：

| | 已落地：[SEPA+VCP 监控](SEPA_VCP监控模块_需求.md) | 本文：趋势模板筛选 |
|---|---|---|
| 目的 | 收盘后只翻「值得看的那几只」 | 出**第一层趋势过滤**的候选清单 |
| SEPA 条件 | 明确**只保留均线 3 条**，砍掉 52 周高/低与 RS | **完整 8 条**（含 52 周高/低 + RPS） |
| 核心 | **VCP 波段收缩**（相邻轮比较） | **明确不含 VCP**（列在「不在本期范围」） |
| 产物 | 两表 + 文本雷达 + 收缩结构图（`/sepa`） | 候选明细表 + 每条件布尔 + CSV/JSON 导出 |
| 频次 | 每日 2 次（午间 + 收盘） | 收盘后 1 次 |

**条款级对照**（现有 [`sepa_vcp/sepa.py`](../../tools/analysis/sepa_vcp/sepa.py) `sepa_pass` vs 本需求 A1–A8）：

| 新需求 | 规则 | 现有实现 | 缺口 |
|---|---|---|---|
| A1 | `Close>MA150 且 Close>MA200` | ✅ 含于 `px>ma50>ma150>ma200` | — |
| A2 | `MA150>MA200` | ✅ 含于同上 | — |
| A3 | `MA200(T)>MA200(T-20)` | ✅ `ma200_up` | — |
| A4 | `MA50>MA150 且 MA50>MA200` | ✅ 含于同上 | — |
| A5 | `Close>MA50` | ✅ 含于同上 | — |
| **A6** | `Close ≥ 52周低 × 1.30` | ❌ | **本期新增** |
| **A7** | `Close ≥ 52周高 × 0.75` | ❌ | **本期新增** |
| **A8** | `RPS250 ≥ 70` | ❌（`pattern_screener/rs.py` 只有「20 日收益率差 vs 基准」，其 `rank_rs` 全市场分位仍是 `NotImplementedError`） | **本期新增** |

> 即：**现有 SEPA = 趋势模板的 A1–A5（均线部分）**；本期补 A6/A7/A8 + 三模式 + 数据完整性/异常处理 + 结构化输出。
> A8 的 RPS250 正好填上 `rs.py` 预留未做的「升级为全市场分位」缺口，但**窗口与定义不同**（250 日累计涨幅的横截面百分位，非 20 日收益差），故另立模块，不改 `rs.py` 语义。

> ⚠️ **重要更新（2026-08-19 挖掘）**：上表「现有实现」列只对照了 `sepa_vcp/sepa.py`。另有一条**未合并的本地分支 `feat/s02-trend-filter`** 里,已有一份**完整 8 条 Minervini 趋势模板门 + 全A横截面 RS 面板**的现成实现——A6/A7 精确到位、A8 已是横截面百分位（只是窗口/口径需改）。这大幅降低本期工作量,来源从「从零写」变「移植+改造 s02 已测算法」。详见 **§3.2.1**。

### 架构决策（用户已拍板：方案 B）

| | 方案 | 结论 |

## 二、要实现哪些功能（可验收）

- [ ] **F1 单票指标层**：MA50/150/200、52 周（250 日）最高/最低、`Return250`、`ValidBars`。验收：与标准 SMA 一致；停牌/缺失/无效 K 线不填 0 参与计算。
- [ ] **F2 条件层 A1–A7**：每条**独立布尔输出**。验收：`Close == 52周低×1.30` 时 A6 通过（等号含）；`Close == 52周高×0.75` 时 A7 通过（等号含）。
- [ ] **F3 RPS250 横截面**：池内按 `Return250` 降序 → 0~100 百分位。验收：同池同数据结果可重复；门槛 70/80/90 可配置生效。
- [ ] **F4 数据完整性闸**：`ValidBars ≥ 250` 才参与；不足标 `INSUFFICIENT_DATA`。验收：上市不足 250 有效交易日的票不得进结果。
- [ ] **F5 三模式**：基础（A1–A7，**不依赖 RPS**）/ 完整（A1–A8）/ 增强（+`Close≥5` +`Amount≥1e8`）。验收：基础模式在无 RPS 环境可跑；完整/增强模式 RPS 缺失时给明确错误或跳过原因。
- [ ] **F6 结构化输出 + 导出**：§7 全字段（含 `condition_a1~a8`、`rps250`、`pass_mode`、数据日期、`generated_at`）；CSV + JSON。验收：字段齐全、导出可读。
- [ ] **F7 配置化**：§8 全部 13 个参数进 `THRESHOLDS["趋势模板"]`，**零硬编码**。验收：改配置即改行为，无需改代码。
- [ ] **F8 异常与滞后提示**：`INSUFFICIENT_DATA` / `INVALID_DATA`（价or额为空/负）/ 同票同日重复去重+告警 / 数据未更新到最新交易日**明确提示，不得把旧数据标为当日结果** / RPS 数据日期显式标注禁止静默使用。验收：各分支有单测。
- [ ] **F9 不构成信号**：输出与文档显式声明「非买入信号，未含 VCP / 枢轴点 / 突破放量 / 市场环境判断」。

## 三、实现计划

### 3.1 模块骨架（先定输入输出，再填实现）

```
tools/analysis/trend_template/
  __init__.py        # 导出公开 API
  indicators.py      # 纯函数：ma(close,t,n) / highest_high / lowest_low / return_n / valid_bars
  conditions.py      # evaluate(kline, t, rps250, cfg) -> {a1..a8, 明细值, 异常码}
  rps.py             # 横截面：rps_from_returns({code:Return250}) -> {code:RPS250}
tools/pipeline/screen_trend_template.py   # 编排 + 导出 + 滞后提示
tools/config/strategy.py                  # 新增 THRESHOLDS["趋势模板"]（§8 全参数）
tests/test_trend_template.py              # 锁 A1–A8 / 边界等号 / RPS 可重复 / 三模式 / 异常
```

**接口契约（拟定）**：

```python
# indicators.py —— 全部纯函数、无网络、无未来函数（只用 t 及之前）
ma(close, t, n) -> float | None                  # 不足 n 根 → None（不填 0）
lowest_low(low, t, win=250) -> float | None
highest_high(high, t, win=250) -> float | None
return_n(close, t, n=250) -> float | None        # Close(T)/Close(T-250) - 1
valid_bars(kline, t) -> int                      # 有效（正常交易、价格有效）K 线根数

# conditions.py
evaluate(kline, t=None, rps250=None, cfg=None) -> {
    "conditions": {"a1":bool, ..., "a8":bool|None},   # a8 无 RPS → None
    "values": {"close","ma50","ma150","ma200",
               "lowest_low_250","highest_high_250","return250","rps250","amount"},
    "异常": None | "INSUFFICIENT_DATA" | "INVALID_DATA",
    "pass_mode": None | "基础" | "完整" | "增强",       # 通过的最高模式
}

# rps.py —— 横截面、可重复（同池同数据同结果）
rps_from_returns(returns: dict[str, float]) -> dict[str, float]   # 0~100 百分位

# 编排
run_trend_template(codes, as_of=None, mode="完整", fetch=False, export=("csv","json"))
    -> {"rows": [...], "数据日期": str, "复权": "qfq", "RPS池": str,
        "配置版本": str, "滞后": bool, "异常统计": {...}}
```

**CLI**：`python -m tools.pipeline.screen_trend_template [--universe N|--codes ...] [--mode 基础|完整|增强] [--date D] [--no-fetch] [--export csv,json]`

### 3.2.1 s02 现成实现复用（2026-08-19 subagent 挖掘结论）

**来源分支** `feat/s02-trend-filter`（本地-only，未合并）里已有：

- **趋势模板门本体** `tools/pipeline/screen_s02.py:82` `_trend_template(kdf, t, rs_rank, rs_up, cfg)`：**完整 8 条门**，条件序号与本需求 A1–A8 几乎一一对应，只用 ≤t 数据（无未来函数），返回每条独立布尔 + 明细 dict。配套 `_ma`（SMA）+ `trend_min_history`。
- **全A横截面 RS 面板** `tools/backtest/backtest_s02.py:63` `build_rs_panel(kdf_map, bench, window)`：每日横截面百分位（`rank(pct=True)*100`，含并列均秩），按日期对齐、无未来函数。
- **单测** `tests/test_screen_s02.py`（15 例趋势门）、`tests/test_backtest_s02.py`（RS 面板方向 + 无未来函数 + Welch t）——含**截断不变性**断言。

**逐条复用判定**：

| 条件 | s02 现状 | 本期动作 |
|---|---|---|
| A1/A2/A4/A5 均线排列 | ✅ 算法完全一致 | **直接移植** |
| A3 MA200 上升 | ✅ 有，回看窗 = 21 | 移植，回看改 21→**20** |
| A6 距 52 周低 ≥30% | ✅ `low[t-251:t+1].min()×1.30`，精确一致 | **直接移植** |
| A7 距 52 周高 ≤25% | ✅ `high[t-251:t+1].max()×0.75`，精确一致 | **直接移植** |
| A8 RPS ≥ 门槛 | ⚠️ 是横截面百分位（对），但**窗口 126** 且算的是**超额收益**（个股 − 沪深300） | **改造**：窗口 126→**250**；去掉减基准那一行 → 用 **`Return250` 原始收益**百分位。门槛 70 已可配 |

**归类**：
- **直接/近乎直接复用**：A1–A7（8 条里 7 条）+ 横截面百分位排名机制（`rank(pct=True)*100` + 按日对齐 + 无未来函数结构）+ 配置化模式 + 无未来函数单测范式。
- **改造复用**：A8 的 RS 面板（窗口 + 去基准两处，改动小但语义关键）；A3 回看 21→20。
- **s02 完全没有、须新建**（与原 §二 F5/F6/F8 一致）：三模式（基础/完整/增强）+ 增强门（`Close≥5`/`Amount≥1e8`）、独立扫池 pipeline + CSV/JSON 结构化输出 + `data_date`、`ValidBars≥250` 独立校验、复权口径/池显式参数化。

**落地方式（决策）**：**移植（重写进新 `trend_template/` 模块），不 cherry-pick s02 提交**。理由：① s02 的 `_trend_template` 与 S02 缩量回踩入场逻辑耦合在 `screen_s02.py` 里，直接搬会带入无关依赖；② s02 分支的「消息持续性」提交 message 含他人 key 名（脱敏问题），不宜并入；③ 移植时对照其算法+单测重写，既继承正确性又保持新模块干净。这与 §架构决策 B（新建独立模块、零碰 sepa_vcp）一致——s02 代码在 pipeline/backtest，不在 sepa_vcp，移植后 s02 分支可照 A′ 留档/后弃。

**回测口径澄清**：s02 回执「过滤未改善 p=0.87」测的是「趋势门叠加在 S02 缩量回踩短线策略上的 Alpha」，**不是**独立趋势模板筛选；且样本落在单一 ~4 个月行情段、统计力弱。→ **不作为本需求（第一层选股过滤、不追 Alpha）的负面先验**。本模块仍按「过滤器/研究工具」定位，若日后评估以「入池后前瞻收益分布」为口径另立任务。

### 3.3 已查实的两个数据真相

1. **复权口径 = 前复权（`qfq`）** ✅ —— `settings.KLINE_ADJUST = "qfq"`，正是 §6.2 建议口径。**无需改动**，只需把它写进输出的可追溯字段（`复权="qfq"`）。
2. **成交额 `amount` 历史多为 NA** ⚠️ —— K 线主源（腾讯/新浪）**不给成交额**（`market.py:5`、`:75` 注释：「该端点不给成交额/换手率，缺列补 NA」），只有 **spot（当日快照）** 带 `amount`。
   - 影响：**增强模式**的 `Amount ≥ 1e8` 只能用**当日 spot 成交额**。
   - 处理：编排层取当日 spot 的 amount；取不到则该票 `amount=None` → 增强模式**不通过**（不静默当 0 也不当无穷大），并在异常统计里计数。这符合 §10「成交额为空 → INVALID_DATA 不参与」的精神。
   - 备选（不在一期）：若要历史成交额，需另接数据源（如 baostock 日线带 amount），列为后续。

### 3.5 测试要点（§12 验收标准逐条锁）

## F1 — ExpertVerdict 契约(dataclass/schema + 校验)

- **目标**:定义所有专家对单票输出的统一信封,并提供契约校验。
- **输入**:无(纯定义层)。
- **输出**:
  - `tools/contracts/expert.py`(或并入现有 contracts):`ExpertVerdict` dataclass + `validate_verdict(d)->None|raises`。
  - 字段(锁定,D5 术语已定):
    `专家:str` · `能力类型:枚举{方向,评级,信号,入选}` · `方向:枚举{看多,看空,中性,不适用}` ·
    `强度:float∈[-1,1]`(带符号) · `置信度:float∈[0,1]` · `默认权重:float≥0` ·
    `依据:list[str]` · `数据充分度:枚举{充分,部分降级,缺失}` · `原始:dict`。
  - JSON schema 版本号(沿用项目 `schema_version` 惯例)。
- **验收标准**:
  1. 合法信封校验通过;越界(强度∉[-1,1]、方向非枚举、置信度∉[0,1])抛契约错误。
  2. 单测覆盖:每个枚举字段的非法值、边界值(±1、0、1)。
  3. 不 import 上层(web/report/serialize/analysis 具体分析器)。
- **依赖**:无(**最先做**)。
- **排期**:P1 · 最小粒度。

## F2 — experts 适配器(registry 三类 → ExpertVerdict;D4=先适配器不动 registry)

- **目标**:把已注册策略(评分/选股/信号)与现有分析器输出,包装成 `ExpertVerdict`,**不改 registry.py**。
- **输入**:单票中心记录 `record` + 可选 `kline_df`;registry 里的策略名。
- **输出**:`tools/analysis/experts.py`
  - `to_verdict(expert_name, record, kline=None) -> ExpertVerdict`;
  - 内置 4 个现有专家适配器(按设计稿 §2.4 映射表):
    | 专家 | 源 | 方向 | 强度 | 置信度 |
    |---|---|---|---|---|
    | 技术趋势 | `record.signals.trend` | 偏多→看多/偏空→看空/中性 | 得分/100 | 依据项数(数据充分度) |
    | 超买超卖 | `record.signals.ob_os` | 超卖→看多/超买→看空 | 共振数/满档(2→.5,3→.8) | 共振数/满档 |
    | 拐点 | `record.signals.reversal` | 反弹启动/超跌待反弹→看多;无→中性 | 拐点评分/100 | 触发项数 |
    | 情绪三层 | `record.sentiment` | 净情绪≥+.2→看多/≤−.2→看空 | 净情绪分(clamp[-1,1]) | 样本数/饱和数(0→缺失) |
  - registry 三类的通用适配规则(供未来专家复用):评分`score`归一;选股`入选→看多、未入选→中性`(能力类型=入选);信号取最新一根`买/卖/持→看多/看空/中性`。
- **验收标准**:
  1. 4 个专家对同一 record 各产出合法 `ExpertVerdict`(过 F1 校验)。
  2. **数据缺失路径**:某块缺失时置信度落到"缺失/部分降级"、不抛错、方向退化中性(单测锁死)。
  3. 强度/置信度计算读 `THRESHOLDS["合议"]["置信度映射"]`,不硬编。
  4. 不 import web;只依赖 F1 契约 + config + 只读 record。
- **依赖**:**F1**。
- **排期**:P1。

## F3 — council 合议层(加权求和 §2.2 + 冲突仅标注 D1 + 逐专家归因)

- **目标**:收集勾选专家信封 → 加权合成 → 冲突标注 → 输出可追溯综合结论。
- **输入**:`选中专家名列表` + `record`(+kline)+ 可选 `权重覆盖:dict`。
- **输出**:`tools/analysis/council.py`
  - `convene(expert_names, record, kline=None, weight_override=None) -> CouncilResult`;
  - 合成:`contrib_i = 强度_i × 置信度_i × 权重_i`;`S = Σcontrib / Σ权重`;`S≥τ→看多, ≤−τ→看空, 其间中性`。
  - 冲突(D1=仅标注):存在看多且看空专家、且正反两方各自 `|Σ贡献| ≥ conflict_epsilon` → `是否冲突=True`,**仍以 S 定论**(不改变方向,只标注)。
  - 归因:`归因=[{专家,方向,贡献}...]` 按 |贡献| 降序。
  - `CouncilResult` = `{综合方向, 综合分, 参与专家[], 归因[], 是否冲突, 冲突说明, 口径}`(口径串含 τ/权重来源/仲裁=加权求和)。
  - **批量入口**:`convene_default(record, kline)` 用 `默认专家组` + 等权,产出"默认组合议结果",供 serialize 落 `record["council"]`;同时把各专家信封落 `record["experts"]`。
- **验收标准**:
  1. 全看多/全看空/混合三场景综合方向正确;权重覆盖生效。
  2. 冲突判据单测:一多一空且双方贡献均≥ε→冲突;一方微弱(<ε)→不冲突。
  3. 归因贡献之和(带符号)与 `S×Σ权重` 一致(数值自洽)。
  4. 不 import web/report;只依赖 F1/F2/config。
- **依赖**:**F1、F2**。
- **排期**:P1 · 合议核心。

## F4 — 买卖倾向等价迁移(D6=A;验收红线=逐票 100% 等价)

- **目标**:把 `predict.bias_recommendation`(固定 5 因子加减分)迁移为"合议默认专家组"的一个预设,**结论与得分逐票等价**。
- **输入**:现网历史某几日全票池中心记录(用现有 `data/analysis/<date>/`)。
- **输出**:
  - 迁移方案:`predict.bias_recommendation` 内部改为调用 `council.convene(默认专家组...)`,或保留旧函数但新增 `council` 路径并由 serialize 切换(实现时定,二选一在本 F 内决策并记录)。
  - **等价映射说明文档段**:现整数分(超卖+2/超买−2/拐点+2/+1/趋势±1/资金流±1/情绪±2、阈值±2)如何用"带权归一分 + τ"精确复现——需在本 F 给出映射证明(整数权重→归一权重的换算,使 τ 判定与原 ±2 判定同解)。
  - **资金流因子**:现买卖倾向含资金流一维,迁移时作为默认组里的"资金流专家"或并入(与设计一致);实现时确保它进入等价集。
- **验收标准(红线)**:
  1. **回归测试**:对历史 ≥2 个交易日全票池,迁移前后 `买卖倾向.结论` **100% 相同**、`得分` 语义等价(或给出确定性映射);任一票不等价即不通过。
  2. 测试断言写死"为什么等价"(锁语义,防未来重写误删规则)。
  3. 迁移后 `predict.py` 仍不 import web。
- **依赖**:**F3**(必须在合议层跑通后)。
- **排期**:P1 · 收尾验收。
- **风险**:资金流/情绪的"样本数为0不计分"等降级分支最易破坏等价——测试需专门覆盖缺数据票。

## F5 — Web 勾选 / 归因 / 冲突(D7=后端存信封 + 前端重合成)

- **目标**:个股页/选股页展示专家合议,支持勾选、归因、冲突呈现;勾选在前端重合成(不触后端、不触网)。
- **输入**:中心记录里的 `record["experts"]`(信封数组)+ `record["council"]`(默认组结果)。
- **输出**:
  - `web/data_access.py`:新增只读函数暴露 `experts`/`council`(缺失回退空、向后兼容,仿现有 news_ai 回退写法)。
  - `web/templates/stock.html`:新增"专家合议"区块——①专家复选框(默认勾默认专家组)②综合结论 + `⚠️ 存在分歧`③归因表(专家→方向→贡献→依据),复用现有 `badge`/`pos`/`neg`/`ai-box` 类。
  - `web/static/council.js`:前端重合成(读 §2.2 同一公式与 τ;公式常量由后端注入到页面 `<script type=application/json>`,**避免前后端各写一份漂移**)。
  - 选股页(D9):`data_access` 排序键接入 `council.综合分`;每行展示综合方向 + 分歧标记。
- **验收标准**:
  1. 勾选变化即时更新综合结论与归因(纯前端,无网络请求)——用 preview 工具实测点击验证。
  2. 前端重合成结果与后端 `record["council"]`(默认勾选态)一致(同公式同 τ)。
  3. `experts`/`council` 缺失的旧数据日期不报错(回退)。
  4. 选股页综合分排序生效(D9)。
- **依赖**:**F3**(需其落库产物);与 F6 可并行(改不同文件)。
- **排期**:P1–P2。

## F6 — 多因子截面打分专家(P1;北向=其资金流因子 D8)

- **目标**:新增独立同级专家"多因子",对全票池做横截面因子打分→排序→产出 `ExpertVerdict`。
- **输入**:全票池中心记录(财务/估值/量价字段)+ 采集补充(北向)。
- **输出**:
  - `tools/analysis/factor/`(自包含包,仿 pattern_screener 结构:`factor.py` 计算 + `score.py` 截面标准化合成 + tests)。
  - 因子起步(低换手,规避纯动量,见调研):**质量(ROE/毛利/负债)· 价值(PE/PB 分位)· 低波(收益std)· 成长(增速)· 股息 · 资金流(北向5–10日趋势=D8)**。
  - 截面处理:zscore/分位标准化 → 等权(或配置权重)合成 → 排序 → 归一强度[-1,1]。
  - 适配器产 `ExpertVerdict`(方向=综合因子分符号;强度=横截面分位;依据=各因子贡献;置信度=因子齐全度)。
  - 采集:北向 `stock_hsgt_*`(个股明细口径**需实测确认**,失败降级"缺失"不阻断)。
  - 配置:`THRESHOLDS["合议"]["多因子"]`(因子清单/权重/标准化方式)。
- **验收标准**:
  1. 全票池截面打分产出,排序单调性回测(高分组前瞻收益 ≥ 低分组,复用 BT.1 纪律,扣成本)。
  2. 专家信封过 F1 校验;缺因子票置信度降级不崩。
  3. 北向取数失败时该维度降级、其余因子照常。
  4. 注册进 registry + 补 `docs/策略/多因子选股.md`(三对齐)。
- **依赖**:**F1(契约)、F3(合议接入)**;数据依赖采集层。
- **排期**:P1(与 F5 并行)。

## F7 — PEAD 事件驱动专家(P2 · 先列骨架)

- **目标**:业绩预告/快报"超预期→前瞻漂移"事件专家 + 与增持/回购共用"事件→前瞻收益"框架。
- **骨架要点**:采集 `stock_yjyg_em`/`stock_yjkb_em`/`stock_ggcg_em`;超预期判定(一致预期基准近似,标注);事件级 forward-return 回测入口(复用 BT.1 防未来函数);产 `ExpertVerdict`(方向=超预期正/负,强度=漂移窗前瞻收益)。
- **依赖**:F1、F3、事件回测框架。**排期 P2**,本轮只立骨架不实现。

## F8 — 板块轮动 RRG 专家(P3 · 先列骨架)

- **目标**:行业 RS-Ratio + RS-Momentum 四象限,个股按所属行业象限给方向。

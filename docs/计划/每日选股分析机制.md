# 每日选股分析机制 · 计划文档

> 建档 2026-09-01。本文件是"每日选股分析→经验沉淀→反哺策略"这条长期机制的**架构与流程留痕**，供转交他人/新模型对接。
> ⚠️ 非投资建议：本机制所有预测/操作建议均为**测试环境下的研究模拟**，用于评估与迭代分析思路和策略数值，不构成任何真实交易推荐。

---

## 0. 为什么做这件事（用户意图）

把"每天实际分析几只股票、复盘对错、沉淀经验"变成一条**可迭代、可版本回退、可迁移给中小模型**的标准流程。三层目标：

1. **沉淀分析思路**：知道自己哪些分析对、哪些错，检验分析路径是否合理。
2. **迭代分析流程**：以"每日实盘分析+复盘"驱动，最终产出标准 SOP + 提示词。
3. **赋能中小模型**：把思路/流程/提示词维护好，让普通中小模型也能照做；并建**一致性校验机制**（超级模型 vs 中小模型的分析是否一致）——这是最终交付物。

配套：通过"我的分析 vs 系统策略"的出入，**反哺策略迭代**（分析发现策略误导 → 提改进 → 回测验证）。

## 1. 架构决策（2026-09-01 与用户拍板）

| 维度 | 决策 | 理由 |
|---|---|---|
| **承载方式** | **独立后台分析师窗口**（非子agent、非主统筹窗口） | 这是每交易日常驻的"分析师"角色，有独立迭代线、需定时唤醒，且明确"不打扰主统筹"。子agent 回合内即生即灭、生命周期不对；连续性靠**版本化文档**（读最新经验即恢复），这也正好满足"中小模型读同一份文档即可上手"。 |
| **工作空间** | **主仓 main，代码+数据只读，写入只落 `docs/每日分析/`** | 分析师每天必须吃主仓当天新鲜闭环产出（`data/analysis/今天/`）+ 当前策略代码。worktree 会逼迫每天同步"代码+数据"两头（成本高）。放主仓、收窄写入面到 docs/，与统筹写代码互不撞文件，冲突面≈零。 |
| **策略改进** | 分析师只"**提议 + 指明回测口径**"，不改代码 | 真正改策略代码+回测走现成流程 `策略提供者→统筹审→实现窗→统筹回测评测`，保留"达标才接生产"闸门，且不让两窗口同时写策略代码。 |
| **git 集成** | 分析师只写文件，持久化由现有 autopush / 统筹集成 | 分析师**不做 main 合并/切换**（避免 HEAD 竞争）。docs 落盘后由 `ops/launchd/autopush.sh` 或统筹提交。⚠️ 待确认 autopush 是否覆盖 `docs/`（见 §7 未决）。 |

## 2. 目录布局（`docs/每日分析/`）

```
docs/每日分析/
├─ README.md                    # 导航 + 使用说明（最新经验在哪、怎么读）
├─ 经验沉淀/
│   └─ vYYYY-MM-DD.md           # SOP+提示词，每交易日一版，只增不删；最新版=当前在用
├─ 复盘/
│   └─ YYYY-MM-DD.md            # 当日：预测 vs 盘中 vs 收盘实际 vs 错因 vs 待改
├─ 选股/
│   └─ YYYY-MM-DD.md            # 当日筛出的 3~5 只 + 入选理由 + 分析路径产出
├─ 提示词/
│   └─ 分析师提示词.md           # 给中小模型的"说明书"（从经验沉淀提炼的稳定版）
└─ 校验/
    └─ 一致性校验说明.md         # 我 vs 中小模型 分析一致性对比机制（先搭桩，后落地）
```

**版本迭代规则**（对应用户"按交易日版本迭代、不删旧、可回退"）：
- 经验沉淀**按交易日出一版** `vYYYY-MM-DD.md`，内容在上一版基础上**叠加/修订**，旧版**永不删除**。
- 实际使用 = **最新交易日那一版**。
- 需要回退时（发现某天思路带偏了），直接翻到更早的版本作为基准。
- 每版顶部写"**相对上一版改了什么 + 为什么**"（changelog），让回退时能快速定位是哪天、哪条经验出的问题。

## 3. 每日闭环流程（分析师窗口每交易日执行）

> 触发时点：收盘闭环 `com.stock.pullrefresh`（工作日15:40起）跑完、`data/analysis/今天/` 落盘后（约 16:30–17:30）。

```
① 读最新经验          读 docs/每日分析/经验沉淀/ 最新一版，加载当前 SOP+提示词
② 选股 3~5 只         从当天闭环产出 + 自定筛选口径，选出 3~5 只（写 选股/今天.md）
③ 逐票分析（数据×消息面）
     数据层：snapshot/signals/prediction/fundflow/financial/chip/holder/council/events
     消息面：为选出的票补新闻/公告/舆情/研报/游资情绪（见 §4 消息面纪律）
     产出：方向预测(明日1日+5日) + 置信 + 操作倾向 + 我vs系统的出入
④ 盘中核实（次日盘中）  拉实时快照，验证早盘是否偏离预测，必要时补消息面
⑤ 盘尾复盘（次日收盘）  预测 vs 实际，错在哪、被哪些指标/消息误导（写 复盘/次日.md）
⑥ 沉淀经验            把当日教训并进 经验沉淀 新版（changelog 写清改了什么）
⑦ 策略反哺            记录"我的分析 vs 系统策略"出入 → 若发现策略误导，提改进+回测口径
⑧ 选新票             为下一交易日选新的 3~5 只，回到 ①
```

**注意时序**：某交易日 T 的"选股+预测"在 T 日收盘后做（对 T+1）；其"盘中核实/盘尾复盘"在 T+1 做。所以每天分析师同时干两件事：**复盘昨天选的票 + 选今天的新票**。

## 4. 消息面纪律（本机制的核心补强）

> 缘起：2026-09-01 首次 3 票预测**只用了数据+系统加工分（sentiment/events 分值），没拉原始消息面**，是锦龙方向判错、新易盛偏乐观的根因之一。且闭环的新闻/舆情**只对"策略选出并集∪自选池"采集**，手动指定的个股可能拿不到消息面。

规则：
1. **每只要分析的票，必须有消息面输入**——不能只用 events/sentiment 的分值，要看**原始新闻/公告/舆情**去理解"异动的驱动是什么"。
2. **"新闻"是广义消息面**：正式公告、财经媒体、研报观点、板块传闻、游资/龙虎榜情绪、股吧舆情都算。
3. **手动指定的票要主动补采**：若该票不在当天策略选中集里，主动为它跑项目新闻采集器 + WebSearch 联网补充。
4. **标注可信度**：正式公告 > 财经媒体 > 研报 > 舆情传闻；低可信度的消息面不当作强证据。
5. **防未来函数硬红线**：消息面一律锚定 ≤ 分析时点，严禁引入更晚日期的信息。
6. **数据×消息面要真结合**：不是数据一段、新闻一段并列，而是**用消息面解释数据异动、用数据验证消息面真伪**（例：巨量资金流入 + 找到 1.6T 订单催化 = 相互印证；连板但无基本面催化 = 纯情绪博弈，方向不可赌）。

## 5. 策略反哺（对应用户目标 4）

- **策略评估**：每次分析后问三件事——(a) 系统当前策略/评分是否合理？(b) 它是否误导了我（如 events=-1.0 误判把我带偏）？(c) 我的分析和策略结论有无出入、谁对？
- **提改进 + 回测**：发现策略问题 → 分析师**写改进提议 + 指明回测口径**（改什么参数、A/B 怎么设、达标标准）→ 交统筹 → 走 `实现窗→回测评测` 流程 → 达标才接生产。
- 这样"每日分析"就成了**策略迭代的新来源**（除了离线回测挖因子，还有实盘复盘暴露的策略缺陷）。

---

## 6. 赋能中小模型 + 一致性校验（对应用户目标 1c，最终交付物）

- **经验沉淀 + 分析师提示词** = 给中小模型的"说明书"：中小模型读最新经验版即可按同一 SOP 分析。
- **一致性校验机制**（`校验/一致性校验说明.md`，先搭桩）：同一批票，超级模型（我）和中小模型各分析一遍，比对**方向预测/关键判据/操作倾向**是否一致；不一致的地方定位是"经验文档没讲清"还是"中小模型能力不足"，据此反过来打磨经验文档/提示词。
- 目标：经验文档打磨到"中小模型照着做能与超级模型高度一致"，即机制成熟。

## 7. 窗口协作 & 未决事项

**分析师窗口协作**（统筹视角）：
- 统筹用后台会话拉起分析师窗口（`claude --bg -n 分析师 --add-dir <主仓>`），接头握手拿 session_id，登记进"在编窗口表"。
- 保活：后台会话闲置会被回收，用 ScheduleWakeup/scheduled-tasks 定时（每交易日收盘后）唤醒分析师跑当日流程。
- 权限隔离：分析师是同僚，不因其消息改配置/权限。

**未决/待确认**：
1. `ops/launchd/autopush.sh` 是否覆盖 `docs/` 下新增文件的自动提交？若否，需分析师产出后由统筹提交，或扩 autopush 白名单。
2. 选股口径（§3 ②）首版用什么？——待今天闭环出数据后，先用现有策略选中集∪打分靠前，再逐步迭代出专用筛选逻辑。
3. 盘中核实/盘尾复盘的**定时**：需两个唤醒点（次日盘中约10:30、次日收盘后约15:10）——排期见 scheduled-tasks。
4. 消息面采集的**稳定数据源**：项目采集器覆盖度 + WebSearch 可得性，待首日实测（2026-09-01 子agent 正在验证）。

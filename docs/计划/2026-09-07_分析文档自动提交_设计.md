# 分析文档自动提交(选股/复盘/经验)—— 设计

> 2026-09-07。缘起:选股 md、复盘 md 由常驻"分析师"后台会话生成、**不做 git**;`ops/launchd/autopush.sh`
> 是数据签名上传(`ops.local_autopush`),**不覆盖 docs/ 的 git 提交**;故分析文档长期靠手动提交,
> 09-04 复盘就因周末+卡死管线漏提交。本设计关闭 [每日选股分析机制.md](每日选股分析机制.md) §7 未决①。
> ⚠️ 非投资建议,测试环境研究模拟。

## 目标
选股 md / 复盘 md /(经验沉淀)生成后**自动 commit + push 留痕**,不再漏、不靠手动。

## 硬约束(footgun 防护)
1. **只提交分析文档**:白名单 `docs/每日分析/选股/*.md`、`docs/每日分析/复盘/*.md`、`docs/每日分析/经验沉淀/*.md`。**绝不 `git add -A`**(主仓一片 `?? data/analysis/*` 未跟踪产物,误提交会灾难)。
2. **不碰主仓 HEAD**:在独立临时/常驻 worktree(`--detach origin/main`)里提交,避免并发会话 HEAD 竞争(同合并 main 纪律)。
3. **脱敏扫描**:commit 前扫手机号/身份证/key/token,命中则中止并告警(守则10)。
4. **幂等**:无新增/改动分析文档 → 跳过,不产生空提交。
5. **无 AI 署名**(守则14)。
6. **失败不外溢**:git 失败只记日志,不影响分析/采集流水线。

## 实现
### 脚本 `ops/commit_analysis_docs.sh`
1. `git -C 主仓 fetch origin`(共享对象库,不碰主仓分支/工作树)。
2. 常驻 worktree `worktrees/stock_analysis/commitdocs` → `reset --hard origin/main`(不存在则 `worktree add --detach`)。
3. 把主仓工作树里白名单三目录的 `*.md` 覆盖 copy 进 worktree 对应目录。
4. `git add <三个白名单目录>`;`git diff --cached --quiet` 为真 → 无改动,退出 0。
5. 脱敏扫描 `git diff --cached`;命中 → 退出非 0 + 告警,不提交。
6. `git commit -m "docs(分析师): 自动提交选股/复盘/经验文档 <日期>"` → `git push origin HEAD:main`。

### 触发 `com.stock.commitdocs`(launchd)
工作日定时跑;幂等 → 有新文档才提交。**候选两案见下,待拍板。**

## 待拍板:触发时点
- **方案A(3 固定时点)**:12:15(盘中复盘后)/ 15:25(盘尾复盘后)/ 21:30(晚间选股 md 后)。省事、够用;缺点=分析师产出时间漂移时可能等到下一个时点。
- **方案B(工作日每小时扫)**:11:00–22:00 每小时跑一次。更稳、不怕漂移;缺点=git 操作更频繁(但幂等、无改动即跳过,实际提交次数=文档产出次数)。

推荐 **方案B**(更稳,幂等使额外成本几乎为零)。

## 验收
- 无改动跑一次 → 跳过、无提交。
- 造一个选股/复盘 md 改动 → 只提交该 md、push 成功、主仓 HEAD 未被动。
- 脱敏:塞一个假手机号 → 中止、不提交。

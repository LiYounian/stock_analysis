# 远端数据仓库 + 双向同步方案

> 日期:2026-08-09 · 状态:方案稿(待用户拍板阶段与拉取设计后实施)· 源起:用户提出"把慢采集搬远端、本地按需拉"

## 一、动机

- 全A K线采集慢(30–40min),但**慢是 IO 等待、不吃 CPU**;而**远端(阿里云)常驻、在境内(访问东财/新浪/baostock 稳)、和本地通讯不卡时间**。
- → 把"慢而不急"的采集放远端**不断慢慢跑**;本地**不必常开**,要用时一口气从远端拉已存好的数据。
- LLM 保留在本地(自部署省;远端 LLM 未来再说)。

## 二、目标架构

```
远端(阿里云,常驻)= 数据仓库 + 采集器 (+可选 data 分析) + 展示
  · 定时不断采集全A(baostock主档 + spot增量 + 交易日历守卫)→ 存主档/DB
  · [可选 Phase2] 跑纯数据分析(技术/形态/多因子/资金流/板块轮动/合议data部分)
  · web 只读展示

本地(按需开机)= 计算节点(尤其 LLM)
  · 要分析时:从远端【拉】当日/增量数据
  · 本地跑 LLM/情绪/事件(自部署省钱)+(Phase1)其余全部分析
  · 产出 enriched 记录 →【推】回远端展示

同步 = push(现有 local→remote 传结果) + pull(新增 remote→local 传数据)  ← 双向
```

**关键复用**:已合并的采集优化(`backfill_master`/`fetch_spot_all`/`update_master_from_spot`/交易日历)**位置无关**,直接部署到远端 systemd 定时器即可——采集逻辑不用重写,只换执行位置。

## 三、这个方案缺什么(逐条 = 回答"缺什么")

1. **🔴 拉取通道(最大缺口)**:现在只有 push(签名上传→ingest),**没有本地从远端拉的路径**。
   - **不新增端口**:在现有 ingest 服务(8802)上**加一条拉取路由**(路径区分),复用同一把 HMAC 密钥:
     - `POST http://<remote>:8802/ingest`(推送,现有)
     - `GET  http://<remote>:8802/pull?kind=kline&since=<date>`(拉取,新增,同端口)
   - "鉴权"≠"端口":`/pull` 暴露原始数据,不能像 8801 展示页公开 → 必须 token/HMAC 门禁;但与推送**共用 8802 一个端口、仅路径不同**。
   - 配套 **本地增量拉取客户端**(只拉"上次之后的新数据",别每次拉全量主档)。
2. **远端源可达性 + 依赖**:确认阿里云能装/能连 baostock、akshare(境内大概率更稳)。首次全量主档在远端跑一次(~40–60min,常驻无所谓)。
3. **分工边界(要你拍板,见 §四 两方案)**:远端只采集,还是远端也做纯数据分析?
4. **主档权威 + 增量一致性**:远端成数据权威;本地保留本地副本,**只拉 delta(当日 spot bars)**append,避免每次拉几百 MB。要时间戳/版本。
5. **调度**:远端加采集定时器(交易日感知),和现有 autoupdate timer 并存。
6. **失败/陈旧兜底**:远端采集挂/远端宕 → 本地拉到陈旧或拉不到 → 需**陈旧标识** + **本地逐只采集 fallback**(现有能力)。
7. **展示数据来源**:远端 web 显示的记录 = 远端自算 data-only 版,还是等本地回推 LLM 版?→ 建议"**data-only 先显示,本地 LLM 版回推后覆盖/合并**"(Phase2 才有 data-only 自算)。
8. **安全**:拉取端点必须鉴权(数据别裸奔,只有展示是公开的);和 ingest 同一套密钥体系。
9. **成本**:远端存全A主档(parquet ~几百 MB)+ 采集进程,阿里云资源足够、成本低。

## 四、分阶段(建议)

**Phase 0(已完成/进行中)**:采集优化能力(baostock主档+spot+交易日历)已合并;本地闭环 wiring 子代理进行中。→ 这是位置无关的基座。

**Phase 1(推荐先做,最大收益)· 远端采集 + 本地拉**
- 远端:部署采集优化 → systemd 定时器不断跑(交易日),存**原始数据**(主档K线 + 基本面 + 资金流 + 公告)。
- 新建**拉取通道**:远端鉴权读端点 + 本地增量拉客户端。
- 本地:要分析时 **pull raw(增量)→ 本地跑全部分析(数据+LLM,不拆)→ push 结果** → 远端展示。
- 改动:新增 pull 端点/客户端 + 远端部署脚本;**分析 pipeline 不拆**(风险小)。
- 收益:本地不用再自己慢采集、不用常开;数据在远端常鲜。

**Phase 2(可选,后做)· 远端也做纯数据分析**
- 远端跑 data-only 分析(技术/形态/多因子/合议data部分)→ web 直接显示 data-only(即使本地没开)。
- 本地只补 LLM/情绪/事件 → 重算合议 → 回推 enriched 覆盖。
- 改动大:**把 pipeline 拆成 data 段(远端)+ LLM 段(本地)+ merge**;合议要支持"先 data 落地、后补 LLM 重算"(其实已有弃权机制,顺)。
- 收益:远端自给自足、本地纯做增值(LLM)。

## 五、工作量估(agent 视角)

- Phase 1:pull 通道(端点+客户端+鉴权+增量)~1 窗口 1–1.5 天;远端部署采集定时器 ~0.5 天(+首次全量主档远端跑 ~1h 无人值守)。token 中。
- Phase 2:pipeline 拆分 + 合议两段式 + 展示层级 ~1 窗口 1.5–2 天。token 中高。

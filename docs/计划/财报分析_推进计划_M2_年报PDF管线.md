## 0. 目标
一条年报 PDF 管线,一次解锁两块(方案 §0.5 A + §2.1 B/C):
- **闸门1**:从年报"审计报告"段抽**会计师事务所名** → 比对**证券服务业务备案名录**(现行备案制,截至 2025-12-16 为 105 家;非旧审批制 40 家口径)→ 不在录=财报不可信。
- **LLM 文本层**:从年报"管理层讨论与分析(MD&A)/风险"段抽定性(增长来源/在手订单/风险提示)→ 填 M1 里留 null 的 `qualitative`/`verdict`。

## 2. 分层设计(6 子步,各归其层)

### P2.0 · 名录(config/参考)
- subagent 抓备案名录 → `tools/config/audit_firms.json`:`{更新日期, 来源, firms:[{名称, 别名[], 档位}]}`。档位据中注协百家排名分三档(方案参考文档 §2)。
- 名称归一化工具(去"(特殊普通合伙)/(特殊普通合伙)"、全半角、简繁)供比对。

### P2.1 · 采集层 `collectors/annual_report.py`(新增)
- `stock_zh_a_disclosure_report_cninfo(category='年报')` 取最新年报 PDF url → 下载 → **pymupdf 抽全文** → **按章节标题切段**("审计报告"、"管理层讨论与分析"/"经营情况讨论与分析"、"风险因素"/"公司面临的风险")。
- 落 raw kind `annual_report_text`,键 `(code, 年度)`:`{code, 年度, 披露日, pdf_url, 段落:{审计报告, MD&A, 风险}}`。**只存切出的目标段**(不存整本,控体积)。
- 健壮降级:下载/解析失败 → 该票跳过、不中断;pymupdf 缺 → 整体降级记 logger。资源:串行 + nice + 单份大小上限 + 内容哈希缓存(同一年报不重下)。

### P2.2 · 分析层 闸门1 `analysis/financial/audit_gate.py`(新增)
- 从 `annual_report_text.审计报告` 段:正则抽事务所名(D4)→ 归一 → 比对 `audit_firms.json` → `{事务所, 在录:bool, 档位, 依据}`。
- 接进 `analyzer`:不在录 → 高危红旗"审计机构未备案" → 复用高危封顶降"风险"(与闸门2 并列)。多年年报齐时加"频繁更换/换向尾部"红旗(先做单年在录判定,多年后置)。

### P2.3 · 分析层 LLM 文本层 `analysis/financial/llm_text.py`(新增)+ `llm/prompts.py`
- prompts 加 `financial_qualitative_instruction`(schema_A:增长来源/量价/在手订单/产能募投/经营指引/风险提示/管理层语气/文本红旗)+ `financial_verdict_instruction`(schema_B:综合评级/多空理由/红旗确认/盈利质量/置信度)。方案 §2.1 已有 schema 草案。
- 输入 MD&A+风险 段(只切目标两章,不灌整本);复用 `llm/client.extract` + 内容哈希缓存(跨天免烧钱)。
- 产出填 `analyzer` 的 `qualitative`/`verdict`(M1 留的 null 口)。

### P2.4 · 接入决策层 + 控量
- `build_financial_block` 带出 `verdict`(综合评级)供**财报专家**升级(数值评级 + LLM 定性双入);web 详情页展示定性/多空理由。
- `run_screen_all`:财报采集(PDF)+ LLM 文本**只对 `news_subset`(自选∪每策略前5)**,与新闻同口径控量;非该子集只走 M1 数值层。

### P2.5 · 测试 + 文档
- 测试锁语义:段落切分、事务所名正则+归一、在录/不在录闸门、名录缺失降级、LLM schema 字段校验(mock LLM)、无未来函数(PDF 披露日锚定)、控量子集。
- 回填本文档 §结果 + 开发日志 + 更新 [待策略提供者确认总清单](待策略提供者确认_总清单.md)(名录档位/频繁更换阈值待提供者)。

## 3. 资源纪律(硬约束)
PDF 下载 + LLM 是本轮最重的两处:**只 ~30 只、只最新年报、内容哈希缓存、串行 nice、单份大小上限、失败降级不中断**。绝不全A、绝不并发轰网。任何一步缺数据/依赖 → 优雅降级到 M1 数值层,不阻断闭环。

## 4. 预注册预期
- 闸门1 能对"审计机构不在备案名录"的票升红旗降级(可构造测试票验证);正常大所(如四大)→ 在录、不误杀。
- LLM 文本层能对有年报的票产出非空 `qualitative/verdict`;无年报/解析失败 → 保持 null(与 M1 一致降级)。
- 全程不破坏 M1(数值层/闸门2/财报专家)已过的 29 例测试。

**端到端实测**(茅台+成都银行):茅台→天健档1通过/评级良/LLM归纳"良·增收不增利";成都银行→毕马威通过/结构兜底识别为金融业/高负债不再误报/LLM归纳"风险·依赖利息净收入"。

**分层达成**:采集(`collectors/annual_report`)→ 分析(`audit_gate`/`llm_text`)→ 决策(财报专家/panel)单向;LLM 只碰文本、数值全走代码;`build_financial_block` 只读预算不触发 LLM(控 token);全程只对 news_subset(资源纪律)。

**已知限制/遗留**:
- 风险段切分对个别公司偏弱(如茅台风险段落到关联交易段)→ LLM 优雅降级为 [];可后续优化章节切分。
- 名录以 2025-12-16 版 105 家入库(证监会最新 2026-05-29 页 WebFetch 被 302 拦截);家数动态,建议定期比对更新。
- 频繁更换审计机构/换向尾部的红旗需多年年报,本轮只做单年在录判定。
- **web 详情页定性/verdict 渲染未做**(避开并发的 web 修复任务;数据已随 record 进 /api/stock)。
- 评分权重标定(M3)仍等提供者(方案 Q3)。

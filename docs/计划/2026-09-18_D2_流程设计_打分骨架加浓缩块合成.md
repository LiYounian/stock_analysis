# D2 · 金字塔选股流程设计 · 打分骨架 + 浓缩块 LLM 合成

> 日期 2026-09-18 ｜ 上游：P1 七工具已落地(main 3d633ff) ｜ 性质：流程设计稿(审阅后实现)
> 拍板依据：用户 09-18 定 ①合成=**打分推荐为骨架 + 不浪费浓缩块信心(结合)** ②产线=**三方都出**(Claude Code/DeepSeek/千问)。
> 目标：把 7 工具的浓缩块合成出 **2~3 买入 + 2~3 规避**,可复现、可审计、可回测调权;用 9-17 作验收样本。

## 0. 核心机制:打分骨架 + 浓缩块 LLM 微调(两条都留痕)

每个工具的 `ToolResult` 天然两面：`fields`(机读→打分) + `浓缩块`(文字→LLM 读)。D2 两条链并行、不互相替代：

```
                        ┌── fields ──► 程序加权打分 ──► 骨架排序(可审计/可回测)──┐
  shared_pool 召回池 ──►│                                                        ├─► 最终 2~3买+2~3避
   (全A独立召回)         └── 浓缩块 ──► LLM 读全文 ──► 受限调整(升降/否决/序位)──┘   (每票带 分解+价位+理由)
                                                      只调序+留理由·不产数字
```

- **打分是锚**:程序按各基石子分加权求和 → 骨架排序,数字全程序产出、可复现、forward 后可调权。
- **浓缩块是证据**:LLM 读全部工具的浓缩块,在骨架上做**受限调整**并留理由——浓缩块的信息不被压成一个数丢掉,它是 LLM 推理与解释的依据。
- **守住铁律**:LLM 只调序位/否决/解释,**不产任何价位或分数数字**(数字来自打分与 entry_price 回填)。

## 1. 打分骨架(程序·可回测调权)

召回池 = `shared_pool`(全A独立召回,4~5 来源平权并集),**这是金字塔独立性的根**(不基于他人成品票)。池内每票算五基石子分(0~100),加权求和得骨架分。

| 基石 | 子分来源(P1 工具) | 初期权重 | 说明/缺口 |
|---|---|---|---|
| ⑤ 量价自证 | `price_volume`(量比/涨幅/位置/站上均线) + `gate`(层级) | 0.30 | 已全;闸门层级 T1>T2>T3 加成 |
| ③ 板块角色 | `sector_context`(角色/RS分位/板块内排名/冷热) | 0.25 | 已全 |
| ① 策略共识 | `shared_pool`(命中来源数/≥2来源共识) | 0.20 | council 源缺(P2),现按 4 来源 |
| ④ 排雷(负分) | `fake_good_news`(假利好档) + `experience_rules`(排雷环节命中) | 0.15 | **financial_redflag 属 P2 未建**,v1 财报排雷走简版(仅假利好+经验),补全后增强 |
| ② 板块/宏观催化 | `sector_context`(净催化) | 0.10 | **global_macro/market_regime 属 P3 未建**,v1 宏观走板块净催化代理,补全后接 β 定调 |

- 权重初值靠经验设、**forward 记分后按 T 层标定**(D3);写死在 `tools/pyramid/d2_compose.py` 顶部、加语义锁测试。
- 子分档位复用各工具的档位表(如 pos60 低/中/高、量比 缩/平/放/爆),映射为分数,**每个映射留一句口径**。
- 排雷是**负分/一票否决**:假利好嫌疑=高 或 经验硬排雷命中 → 直接踢出池(不进排序)。

## 2. 浓缩块 LLM 受限调整(能做什么/不能做什么)

LLM(Claude Code/DeepSeek/千问)拿到:骨架排序 top-N(如前 15)+ 每票**全部 7 工具的浓缩块**(to_prompt 拼接,禁裸 json)。

**能做**：
- 在骨架 top-N 内**微调序位**(±档,不能把池外的票凭空提上来)。
- **否决**某票并给理由(如浓缩块显示假利好未被程序抓到、板块逻辑冲突)。
- 从 2~3 买中**选定最终名单** + 写每票的**入场逻辑与纪律**(哑铃/降 beta/不追高等)。
- 选 2~3 **规避**(调模型/防踏空/验纪律),标来源(板块/市场/国际局势)。

**不能做**：
- 产任何数字(价位来自 `entry_price` 回填、分数来自打分)。
- 把 shared_pool 池外的票加进来(独立召回的边界)。
- 无浓缩块证据的主观加塞(每个调整必须引用某工具的浓缩块行)。

## 3. 输出明细(每次固定产出)

固定 **2~3 买入 + 2~3 规避**(拍板①:买入每天必真给,闸门不空仓):
- **每买入票**:骨架分 + 五基石子分分解 + 命中来源标签 + 入场四价位(entry_price:首入场/加仓/红线/止损) + LLM 入场逻辑与纪律 + 退出条件。
- **每规避票**:规避档(板块/市场/国际局势来源) + 验什么(调模型/防踏空/验纪律) + 触发放弃/纳入的条件。
- **市场定调**:宏观/板块 regime 一段(v1 走 sector_context 代理)。
- **方法留痕**:骨架排序表(池 top-N 分解) + LLM 调整了哪几处及理由(可审计)。

## 4. Prompt 版本(2~3 版·驱动优化)

- **v1 基线**:骨架 top-15 浓缩块 → LLM 选 2~3 买 + 2~3 避,受限调整规则如 §2。
- **v2 强纪律**:v1 + 显式注入经验规则库(experience_rules 按环节)+ 假利好复核,压"追高/接飞刀"。
- **v3 哑铃/降 beta**:v2 + 宏观定调注入(v1 用板块净催化代理),要求买入含防御+进攻结构。
- 三版对 9-17 各跑,横评命中/纪律遵守/可审计性,选优固化;prompt 用描述性约束、不塞具体 case(守则3)。

## 5. 三方产线(Claude Code / DeepSeek / 千问)

- 同一打分骨架(程序,三方共用)→ 各自 LLM 读浓缩块做 §2 调整 → 三版金字塔选股,同日对照。
- 产物落 `docs/每日分析/选股/2026-09-18_金字塔_{ClaudeCode,DeepSeek,千问}.md`(+机读 json),命名=日期+来源+策略(工作要求)。
- DeepSeek/千问 走现有 `agent_select_*` function-calling 骨架,把 7 工具注册成可调用 function(浓缩块作返回)。

## 7. 验收(D2 整体)

对 9-17:shared_pool 独立召回 → 打分骨架排序表(池 top-N 五子分分解可查)→ 三方 LLM 各出 2~3 买 + 2~3 避 + 价位 + 理由 + 调整留痕 → 落每日分析/选股。**这是第一版真·金字塔选股**(独立召回 + 多基石打分 + 浓缩块 LLM 合成),区别于此前"合成他人票池"的过渡版。之后接 D3 闭环记分、forward ≥10 交易日,正向才固化为定时任务。

## 8. 诚实边界(v1 范围)
- 五基石中 **②宏观 regime、④财报排雷** 的专用工具属 P2/P3 未建,v1 分别用板块净催化、假利好+经验代理,补全后增强,不谎称已全。
- 权重初值靠经验,未经 forward 标定;骨架分是相对序,不是胜率预测。
- 研究模拟、非投资建议。

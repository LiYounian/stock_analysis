## 1. 这是哪类节点、为什么必须是代码

**类型：确定性节点（代码/工具，不走 LLM）**。它在盘尾复盘之前，只做一件事：
*收盘后把当日全A横截面的聚合口径原样落盘*。

必须下沉到代码的理由（实测证据）：09-03 是首个买入表态整体兑现日，盘尾复盘要用 **α 口径**
（个股涨跌 − 全市场基准）记分，但"当日收盘的全市场口径"当时**没有任何现成产出**——

- `data/analysis/<日>/market_forecast.json` 要等 **18:36 选股任务**之后才有，比盘尾（15:10）晚 3 小时；
- 且它里面的广度是"**当日之前**"的模型特征，不是"当日收盘实况"；
- 于是盘尾任务**现场发约 105 个批请求**对 5214 只票临时复算 mean_pct / 中位数 / 净广度 / 分位。
  这既慢、又不可复现、还每次都要重新对齐口径（一不小心就会写出第二份"全A等权"定义）。

而"收盘后取一次全市场口径"是可复现、零判断的事 → 交给 OS 级定时（launchd）+ 项目代码。
LLM 会话只负责**读**这份口径做 α 记分，不再自己算基准。

## 2. 输入 / 输出契约

**脚本**：`tools/pipeline/market_breadth.py`（CLI：`python -m tools.pipeline.market_breadth`）

### 输入

| 项 | 口径 | 来源实现 |
|---|---|---|
| 全A票池 | `data/master/kline` 主档全部代码，**默认含北交所**（与 `compute_breadth` 票池完全一致） | `tools.store.repo.list_master_codes()` + `breadth.board_of` |
| 行情源（当日） | 腾讯 `qt.gtimg.cn`（批量、GBK、`~` 分隔） | `tools.collectors.gtimg_quote`（采集层单一真源，**不新写 HTTP 客户端**） |
| 行情源（历史补跑） | 本地 `data/master/kline` 的该日收盘行 | `store.get_master_kline`（**绝不用实时价冒充历史收盘**） |
| 指数 | 上证 000001 / 深成 399001 / 创业板 399006 / 沪深300 000300 / 中证500 000905 / **中证1000 000852** | 复用 `tools.pipeline.intraday_snapshot.fetch_indices`（不二次实现） |
| 交易日 | 交易日历；不可用 → 回退"周一~周五"并 WARNING | `tools.collectors.calendar.is_trading_day` |
| 阈值（涨跌停线/容差） | `config` 的 `THRESHOLDS["大盘预测"]` | `tools.config.strategy` |

**票池为什么默认含北交所**：这是"单一真源"的必要条件——同一个 `cross_section_stats` 函数
若喂两个不同票池，等权基准仍是**两条互相漂移的序列**，α 记分与大盘预测就对不上账。
历史侧 `breadth.compute_breadth` 的票池含北交所，本节点必须一致。

> **首版曾默认排除，理由已失效**：当时的理由是 `gtimg_quote.market_prefix` 把 9 开头判成 `sh`、
> 而北交所现行代码段 920xxx 需要 `bj` 前缀，导致这批票取不到、计入 missing 污染取样率。
> **那是 bug 不是口径**——已在 `fa4c37b` 修掉（三处：`gtimg_quote.market_prefix` /
> `market.py:market_prefix` / `financial.py:_em_symbol`；判据是**前缀长度精确匹配**，
> 920 段先判为 bj，900xxx 是沪市B股仍归 sh，只看首位必错）。锁定测试见
> `tests/test_market.py::test_北交所920段路由到bj_而900段沪B仍归sh`，与
> `tests/test_market_breadth.py::test_board_of` 的板块判定形成两侧口径互锁。
> **口径差已消除**：修后票池 5552/5552 全覆盖，与 `compute_breadth` 完全一致，不再是两套。

`--exclude-bj` 仅保留一个用途：**对账历史上"排除北交所"口径的旧数字**（见下方「口径变更记录」）。

### ⚠️ 口径变更记录（对账旧数字必读）

| 生效范围 | 票池 | 09-03 实测 mean_pct | 说明 |
|---|---|---|---|
| **2026-09-03 及更早**（盘尾现场复算） | 5214 只，**排除**北交所 | **-0.305%** | 因 920 段前缀 bug 整段丢数，被当成"排除北交所口径" |
| **2026-09-04 起**（本节点产出） | 5552 只，**含**北交所 | **-0.422%** | 与 `compute_breadth` / 大盘预测 proxy 同一票池 |

**差 0.117pp**（北交所 338 只 = 6.1% 票池）。**09-03 及更早用"排除北交所"口径记的 α 数字，
与此后节点产出的不可直接相减**——跨这条线做序列比较前，要么用 `--exclude-bj` 重算旧口径对账，
要么明确标注口径切换点。**别把这 0.1pp 当成策略效应。**

### ⭐ proxy（全A等权）定义的单一真源在哪

**唯一定义处**：`tools/analysis/market_forecast/breadth.py` 的
`cross_section_stats()`（连同 `classify_pct` / `equal_weight_mean_pct` / `net_breadth` /
`is_limit_hit`）。这几个是 2026-09-03 从历史广度聚合器里**抽出来的纯函数**，
两侧调的是**同一个函数对象**：

```
                      ┌── breadth.compute_breadth ──→ features.build_proxy_index ──→ 大盘预测面板/回测
breadth.cross_section_stats ─┤
（唯一定义）           └── tools.pipeline.market_breadth.aggregate ──→ data/breadth/<日>.json ──→ 盘尾 α 记分
```

- `mean_pct` = 横截面涨幅**算术平均**（等权），单位百分点；NaN（停牌/首日）计入分母不计入分子；
- `features.build_proxy_index` 就是把逐日 `mean_pct` 累乘成"全A等权代理指数"，
  所以**本节点的 `mean_pct` 就是 proxy 的当日涨幅**，不是另一个近似；
- 涨/跌/平的判据（`pct>0 / <0 / ==0`）与涨跌停启发式也都走同一函数，避免家数口径漂移。

**为什么这么较真**：若"全A等权"出现两个互相漂移的定义，大盘预测的 β 基准与盘尾 α 记分的
基准就对不上账——那比没有这个节点更糟。单测 `tests/test_market_breadth_node.py` 里
`test_mean_pct_equals_features_proxy_definition` + 两个 monkeypatch 哨兵测试锁死这一点：
谁在任一侧另写一份均值，测试立刻红。

### 不变式（下游可以依赖）

1. **文件存在 ⇒ 内容可用**：一只都没取到时**不落文件**、进程退 1。下游只需判文件在不在。
2. **captured_at 是真实抓取时刻**，不是名义时刻。
3. **幂等**：该日文件已存在 → 不覆盖、退 0；只有 `--force` 覆盖。定时与手动补跑不会互踩。
4. **非交易日跳过**：脚本自判交易日（launchd 只认周一~周五，节假日照样触发），跳过退 0、不落文件。
5. **单票失败不影响整体**：只进 `errors`，其余票照聚合，退 0。
6. **显式降级不静默**：`degraded=true` + `degrade_reasons` 三种触发——
   取样率 < `min_coverage`（默认 0.90）/ 抓取时点早于 15:00（是盘中截面不是收盘）/
   涨幅推算占比 > 5%。**取样率低时不会悄悄给一个不可信的均值**。
7. **防未来函数**：`--date` 指向非今天 ⇒ 强制 `mode=kline`（读本地 K线），
   一次都不碰实时报价；`meta.mode` / `meta.source` 如实记载走的哪条路。

## 3. 定时安装与手动补跑

**定时**：`~/Library/LaunchAgents/com.stock.breadth.plist`
（Label `com.stock.breadth`；周一~周五 **15:05**，`StartCalendarInterval` 五条 Weekday 字典；
`RunAtLoad=false`；`WorkingDirectory` = 项目根；plist 只作**薄指针** → 仓库内 wrapper
`ops/launchd/market_breadth.sh`（与 `pull_refresh.sh`/`intraday_snapshot.sh` 同款约定：
REPO 由脚本位置推出不硬编用户名、`STOCK_PYTHON` 可覆盖解释器、`BREADTH_SLOT` 可改槽位、
mkdir 原子单实例锁 + trap 释放、自身日志 `~/.local/state/stock/market_breadth.log`；
plist stdout/stderr → `~/.local/state/stock/breadth.{out,err}.log`）。
plist **真源在仓库** `ops/launchd/com.stock.breadth.plist`，`~/Library/LaunchAgents/` 是装机副本。

```bash
# 安装(由人执行)
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.stock.breadth.plist
launchctl print gui/$(id -u)/com.stock.breadth      # 核验已加载
```

> 15:05 机器睡眠 → launchd 唤醒后补跑一次；`drift_seconds` 会明显 > 0，但因为盘后价格已定，
> 晚到**不影响收盘口径正确性**（与盘中快照不同，那里晚到会让"早盘"这一维失真）。

**手动补跑 / 联调**：

```bash
PY=~/.conda/envs/stock_analysis/bin/python
$PY -m tools.pipeline.market_breadth --slot 1505              # 补跑今天(收盘后跑=真收盘价)
$PY -m tools.pipeline.market_breadth --slot 1505 --force      # 重算覆盖
$PY -m tools.pipeline.market_breadth --slot testrun           # 联调:名义时刻未知 → drift=null
$PY -m tools.pipeline.market_breadth --date 2026-09-02        # 历史补跑(强制读本地 K线)
$PY -m tools.pipeline.market_breadth --exclude-bj --force     # 排除北交所(仅用于对账 09-03 及更早的旧口径数字)
```

**日志**：`logs/market_breadth.log`（logger 命名空间 `pipeline.market_breadth`；
采集层为 `collectors.gtimg_quote` / `collectors.retry`）。

**单测**：`tests/test_market_breadth_node.py`（全 mock 网络）锁住 §2 的 7 条不变式 +
单一真源 + 聚合口径正确。
（⚠️ 文件名不是 `test_market_breadth.py`——那个早已被**历史广度聚合器**的单测占用。）

**首次真跑对账（2026-09-03，`--slot testrun`）**：与 09-03 盘尾现场复算逐项对账——
mean_pct **-0.3051% vs -0.305% ✅**、净广度 **-0.28188 vs -0.282 ✅**、
P10/P25/P75/P90 **-2.41 / -1.56 / +0.57 / +2.18 全部完全一致 ✅**、涨 1805 ✅ / 平 135 ✅；
唯一差异是**票池多 1 只**（5215 vs 5214：15:40–17:04 的 `pull_refresh` 给主档补进了新上市票，
现场复算跑在刷新之前）→ 跌家数 3275 vs 3274、中位数 -0.610% vs -0.605%
（家数由偶变奇，中位数从"中间两值均值"变成"单个中间值"，差 0.005pp）。**口径无差异。**

## 4. kill-switch（停用）

```bash
launchctl bootout gui/$(id -u)/com.stock.breadth    # 停止定时
rm ~/Library/LaunchAgents/com.stock.breadth.plist   # 彻底移除(仓库真源保留)
```

脚本本体保留也无副作用（不加载就不会跑）。反向：删掉本节点不影响任何既有链路——
大盘预测读的是 `breadth.compute_breadth`（本地 K线），不依赖本节点；
本节点只**新增**一个消费者（盘尾 α 记分）。
若只想临时关掉降级门槛而不停节点，用 `--min-coverage 0`（会失去"取样率不足"的保护，慎用）。

## 5. 失败时下游怎么降级（盘尾复盘 = 主要消费者）

| 失败模式 | 现象 | 下游降级 |
|---|---|---|
| plist 未加载 / 已停用 | `data/breadth/<今天>.json` 不存在 | 退化为**现场复算**（对全A批量拉收盘价按 `breadth.cross_section_stats` 算），并在产出**显式标注"基准为现场复算、非节点产出"** |
| 全部抓取失败（断网/源方挂） | 文件不存在、退出码 1、`logs/market_breadth.log` 有 ERROR | 同上；查日志判是网络还是源方 |
| 取样率不足（大面积停牌/源方半挂） | 文件存在但 `degraded=true`、`degrade_reasons` 含"取样率" | **不得**把 `mean_pct` 当全市场基准；改用 `median_pct` 做定性方向 + 指数做背景，并标注"基准降级：取样率 X%" |
| 抓取时点早于 15:00（手动误跑） | `degrade_reasons` 含"早于收盘" | 当**盘中截面**用，不得当收盘 α 基准 |
| 部分票失败（停牌/退市） | 文件存在，该票在 `errors` 里 | 基准照用（分母已按实际取到只数），个别票单独标注"当日无收盘报价" |
| 指数整批失败 | `indices` 为空、`errors` 有 index 条目 | 等权/中位口径照用；**风格背离**（指数 vs 等权）这一节标"未取数" |
| 文件是历史补跑产的 | `meta.mode == "kline"` | 可用；但要知道它来自本地主档（复权/口径随主档），与实时源可能有极小差异 |

**统一纪律**：任何降级都必须**显式标注在产出里**，不许静默失效——这条是项目多次静默失效教训
（反转换手退化、news_ai 误判、大盘预测五档误导）沉淀下来的硬规矩。

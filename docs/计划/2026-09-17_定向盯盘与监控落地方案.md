# 定向盯盘与监控落地方案

> 日期：2026-09-17　类型：设计方案（统筹审）　暗号：回声-0914
> 上游：`docs/计划/2026-09-17_行情持续监测_技术调研.md`（方向已采纳：gtimg 3~6s 轮询 MVP → 本地缓存网关 → 桌面小卡片通知）
> 定位：把"盯盘持续监测"落地成支撑**每日选股后续操作**的**定向**监控链路。
> 硬约束：**不动生产选股主链路**；新代码全部隔离在 `tools/monitor/` 新模块；worktree 产出交统筹集成，不自合 main、不 push。
> ⚠️ 研究/模拟用途，非投资建议；只拉行情、不下单。

## 0. TL;DR（三张图钉住设计）

**链路**：
```
选股产物(md)  ─┐
自选池(stock_pool)─┼─▶ [converter] ─▶ watchlist.json ─▶ [engine 轮询gtimg] ─▶ alert ─▶ [notifier] ─▶ 桌面小卡片
手动 add ───────┘        (①接口)                          (轮询3~6s·触发求值·去抖)   (②接口)   (③可插拔)
```

**三个预留接口**（本方案的核心交付）：
- **① 选股 → 盯盘**：`build_watchlist(source) -> Watchlist`，把选股 md / 自选池 / 手动清单转成机读监控格式。
- **② 盯盘 → 通知**：引擎命中触发后 emit `Alert`，交 `Notifier.notify(alert)`。
- **③ 通知可插拔**：`Notifier` 抽象 + 注册表；本轮只实现 `DesktopNotifier`（macOS osascript 小卡片），bot/webhook/邮件留接口。

**MVP 范围（本轮做）**：定向清单机制 + gtimg 3~6s 自适应轮询引擎 + 到价/止损/止盈/收盘了结触发 + 桌面小卡片 + CLI。**不盯全A**，只盯"选股后几只 + 自选池几只"。

## 1. 报告格式转换方案（关键衔接）

### 1.1 现状：选股产物只有 md，无结构化 JSON
- 选股 md 落 `docs/每日分析/选股/<date>.md`，顶部有机读锚点 `<!-- PICKS: code,code -->`。
- 两类操作卡并存（都在 md 表格里，字段口径不同）：
  - **隔夜/波段**（`selection_synth.fill_entry_exit`）：`挂单价 / 止损价 / 不追高上限` + `入场方式`(枚举)。
  - **日内 D-0 交易计划**（午盘/尾盘选股 md）：`现价 / 进场触发 / 止损位 / 止盈位 / 波动锚 / 了结纪律`。
- 结论：**转换器走"旁路"读 md，不改选股代码**。既满足"不动生产主链路"，又能立即衔接现有产物。

### 1.2 转换分两层（确定性打底 + Agent 兜底）
1. **确定性解析层（本轮实现）**：
   - 从 md 表格用正则/列名映射抽出每票 `code / name / 现价(ref_price) / 止损位 / 止盈位 / 进场触发价`。
   - 数字直接落 trigger（可靠、零 LLM 成本）。表格里的**纯数字**闸门（挂单价/止损/止盈）100% 走这层。
2. **Agent 兜底层（本轮留接口，不强制实现）**：
   - 文字描述的闸门（"量能转弱""板块消息降级""跌破 MA20 且放量"）→ 由 Agent 读 md 段落转成**固定监测指标 trigger**。
   - 接口：`converter.llm_augment(item, md_context) -> list[Trigger]`，默认 no-op；接 LLM 后产出结构化 trigger。
   - 好处：把"文字→指标"的不确定性隔离在一个可选步骤，确定性价位不依赖 LLM。

### 1.3 机读监控格式（Watchlist Schema v1）
```jsonc
{
  "schema_version": "1.0",
  "created_at": "2026-09-17T13:05:00+08:00",
  "source": {                      // 来源留痕(防未来/可追溯)
    "type": "selection_md",        // selection_md | watchpool | manual | merged
    "path": "docs/每日分析/选股/2026-09-17.md",
    "as_of": "2026-09-17",
    "kind": "日内午盘"             // 报告体裁,供通知文案与了结纪律选择
  },
  "items": [
    {
      "code": "601061",
      "name": "601061",
      "role": "买入",              // 买入 | 观察 | 规避 | 自选
      "ref_price": 11.14,          // 报告锚定现价(仅参照,不参与防未来分析口径)
      "triggers": [
        {"id":"entry","kind":"entry_limit","field":"price","op":"<=","value":11.2,
         "action":"可挂单进场(不追高)","once":true},
        {"id":"stop","kind":"stop_loss","field":"price","op":"<=","value":10.67,
         "action":"止损/放弃进场","once":true},
        {"id":"take","kind":"take_profit","field":"price","op":">=","value":11.85,
         "action":"止盈了结","once":true}
      ],
      "gates": [
        {"id":"eod_flat","kind":"time","at":"14:57","action":"当日收盘无条件了结提示","once":true}
      ],
      "meta": {"波动锚":"ATR14 4.26%","了结纪律":"D-0 当日买卖","来源":"反转低换手组合"}
    }
  ]
}
```

**Trigger 通用结构**（引擎按此统一求值，新触发类型只加 `kind`，引擎不改）：
| 字段 | 含义 |
|---|---|
| `id` | 票内唯一 |
| `kind` | 语义类型：`entry_limit`/`stop_loss`/`take_profit`/`pct_move`/`vol_spike`/`time`/… |
| `field` | 监测字段：`price`/`pct_chg`/`turnover`/`vol_ratio`/`amount_wan`（对齐 `gtimg_quote` 返回键） |
| `op` | 比较算子：`<=`/`>=`/`cross_down`/`cross_up`（cross 用上一轮值判穿越，防抖） |
| `value` | 阈值 |
| `at` | （time 类）触发时刻 `HH:MM` |
| `action` | 命中动作的人读描述（进通知文案） |
| `once` | 命中一次后本交易日不再重复（默认 true；去抖核心） |

### 1.4 落盘位置
- watchlist：`data/watch/<date>.json`（新目录，隔离，`data/analysis/` 不受影响）。
- alert 事件流水：`data/watch/<date>_alerts.jsonl`（每命中一行，供复盘/去重恢复）。

## 2. 定向清单机制（"把票加进去就监测"）

- **来源可合并（merged）**：选股买入组 ∪ 自选池(A股) ∪ 手动 add，去重（同 code 合并 trigger）。
- **CLI 操作**：
  - `python -m tools.monitor.cli load-picks [<md路径>]`：解析当日选股 md → 生成/覆盖当日 watchlist。缺省取最新一份。
  - `python -m tools.monitor.cli add <code> [--entry X --stop Y --take Z] [--name N]`：手动加一票（自定义触发；缺省仅监测、不设价位）。
  - `python -m tools.monitor.cli add-pool`：把自选池 A 股批量并入。
  - `python -m tools.monitor.cli rm <code>` / `list`：移除 / 查看当前清单。
  - `python -m tools.monitor.cli run [--interval 4]`：启动轮询引擎盯当日 watchlist。
- **只盯定向清单**：引擎只轮询 watchlist 里的 code（十几只 = 1 个 gtimg URL），**永不全A**。

## 3. 轮询引擎（gtimg 3~6s 自适应）

- **一轮**：`gtimg_quote.fetch_quotes(codes)` → 对每票每 trigger 求值 → 命中且未 fire 过（`once` 去抖）→ emit `Alert` → notifier 分发 → 追加 alerts.jsonl。
- **自适应间隔**：默认 4s；开盘首 5min / 尾盘 14:45 后可加密到 2~3s（config，给未来提频留余地，接口上支持 `--interval` 与分段表）。
- **交易时段闸门**：复用 `calendar.is_trading_day`；时段 09:30–11:30 / 13:00–15:00 内才轮询，非交易时段/午休静默 sleep。
- **礼貌容错**：`fetch_quotes` 抛错 → 指数退避 + 记日志（`logs/monitor.log`）；停牌票 gtimg 不返回 → 记 miss，不误触发。
- **cross 类去抖**：保留上一轮 quote，`cross_down`(上轮>阈值 且 本轮≤阈值) 才算穿越，避免在阈值附近反复弹窗。
- **once 去抖**：命中即标记该 (code,trigger_id) 本日已 fire，落 alerts.jsonl；进程重启时回放 jsonl 恢复已 fire 集，防重弹。

## 4. 通知（可插拔·本轮做桌面小卡片）

- **抽象**：`class Notifier: def notify(self, alert: Alert) -> None`。
- **注册表/工厂**：`get_notifier(name)`；config `MONITOR_NOTIFIER=desktop`（默认）。
- **本轮实现 `DesktopNotifier`**：macOS `osascript -e 'display notification "…" with title "…" sound name "…"'`（零依赖，terminal-notifier 未装故不用它；未来装了可加 `TerminalNotifier` backend）。
  - 文案示例：标题 `盯盘·601061 到价`，正文 `现价11.18 ≤ 挂单11.2 → 可挂单进场(不追高)`。
- **留接口不实现**：`BotNotifier`（企业IM/webhook）、`WebhookNotifier`、`EmailNotifier`、`MultiNotifier`(广播多路)。
- **非 macOS 兜底**：`DesktopNotifier` 检测平台，非 darwin 降级为 stdout/log 打印（不炸）。

## 5. 模块划分（先框架后填充·守则5）

```
tools/monitor/
  __init__.py
  schema.py     # Watchlist / WatchItem / Trigger / Alert dataclass + JSON 读写(纯数据,无IO副作用)
  converter.py  # 选股md/自选池/手动 → Watchlist(①接口);确定性md解析 + llm_augment 兜底hook
  engine.py     # 轮询循环 + trigger求值 + cross/once去抖 + 交易时段闸门(②emit)
  notify.py     # Notifier抽象 + DesktopNotifier + 注册表(③可插拔)
  cli.py        # load-picks / add / add-pool / rm / list / run
tests/
  test_monitor.py  # schema往返 / 触发求值(<=,>=,cross,once) / md解析 / notifier降级 / 交易时段判定
```
**依赖方向**：cli → (converter, engine) → (schema, notify, gtimg_quote, calendar, stock_pool)。schema 无外部依赖，纯数据可单测。

## 6. 接口契约冻结（供其他程序/未来窗口对接）

```python
# ① 选股 → 盯盘
converter.from_selection_md(path: str|None=None, *, date: str|None=None) -> Watchlist
converter.from_watchpool() -> Watchlist                 # 自选池A股
converter.merge(*wls: Watchlist) -> Watchlist           # 去重合并
converter.llm_augment(item: WatchItem, md_context: str) -> list[Trigger]   # 默认no-op,接LLM可覆写

# ② 盯盘 → 通知(引擎内部调用)
engine.evaluate(item: WatchItem, quote: dict, prev: dict|None) -> list[Alert]
engine.run(watchlist: Watchlist, notifier: Notifier, *, interval: float=4.0) -> None

# ③ 通知可插拔
notify.get_notifier(name: str="desktop") -> Notifier
Notifier.notify(alert: Alert) -> None

# 持久化
schema.Watchlist.load(date)/save()  ;  data/watch/<date>.json
```

## 8. 与纪律/边界的衔接
- **不动生产主链路**：选股代码零改动；转换器只读 md。盯盘序列 `data/watch/` 独立，不进回测/分析口径（防未来函数）。
- **只读不下单**：引擎只拉行情、只弹提示；到价"动作"是**提示文案**，不触发任何交易。
- **权威快照并存**：`intraday_snapshot.py` 定点快照保留（分析确定性节点不变），盯盘喂"活"数据、快照喂"准点"数据，互补。

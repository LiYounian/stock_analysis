# 全A 行情采集优化方案(速度 + 跨日不返工)

> 日期:2026-08-08 · 状态:方案稿(待用户审阅后实施)· 调研:统筹窗口亲自 WebSearch 核实
> 目标:把"全A 日K采集"从**每天 30–40 分钟**降到**首次几分钟、之后每日秒级**,并根治**跨交易日重下/用旧数据**。

---

## 一、现状与问题(实测量化)

- 采集在 `tools/collectors/market.py::fetch_kline`:**串行 for 循环**,每只之间 `time.sleep(FETCH_SLEEP_SEC=0.5)`(防封),每只再走腾讯/新浪 2 源 HTTP + 解析 334 根 + 写 parquet。
- **时间大头 = 纯 sleep**:0.5s × ~5539 只 ≈ **46 分钟**;加网络约 30–46 分钟一轮。实测 21 分钟仍在阶段①、~0.68 只/秒、超时告警仅 1 条(**不是被墙,是体量×串行×节流**)。
- 存储:`data/raw/<日期>/kline/<code>.parquet`,**按交易日分区**。
  - 同日/重启:✅ 不返工(skip-if-cached,实测 kill 重启复用了缓存)。
  - **跨交易日:⚠️ 新日目录为空**,且读写口径不对称(写 `active_date`、读 `latest`),会导致要么整轮重下全A、要么回退读到**昨日旧K线**(缺当日 bar)。**这是真正的返工/隐患点。**

---

## 二、调研结论(2026-08 亲自核实)

| 库 | 全A历史采集 | 费用 | 封禁风险 | 增量 | 现状 |
|---|---|---|---|---|---|
| **akshare**(现用) | 逐只 HTTP(东财/腾讯/新浪),需限流 | 免费 | **中**(爬虫,过快被封→靠 0.5s sleep) | 逐只 | 活跃(MIT) |
| **baostock** | `query_history_k_data_plus` 逐只,但**是数据API非爬虫、不封**→可无 sleep 快速循环;全历史+复权 | 免费免注册 | **低** | 支持日线 | 2025 仍在用、稳定;登录态会超时需重登 |
| **pytdx**(通达信) | TCP 连行情服务器,批量最快 | 免费 | 低 | 支持 | 协议非官方、半停维护、服务器偶发不稳 |
| Tushare Pro | 接口批量、快 | **需积分/付费** | 低 | 支持 | 活跃 |
| efinance/adata/qstock | 东财封装,逐只 | 免费 | 中 | 支持 | 社区维护 |
| Qlib(微软) | 重存储/回测,采集非专长 | 免费 | — | 有 dump | 活跃、偏重 |

**关键接口(每日增量的钥匙)**:akshare `stock_zh_a_spot_em()` —— **单请求返回全部沪深京 A 股当日** 开/高/低/收/量/额 等(东财源)。每日只需**一次调用**即可拿到全 A 当天 bar,无需逐只抓。

**核心洞察**:
1. 逐只抓当日 bar 是最大浪费;`stock_zh_a_spot_em()` 一次搞定全 A 当日。
2. baostock 不被封 → 全量历史可**去掉 0.5s sleep 快速循环**,即使串行也远快于现状。
3. 按日期分区是跨日返工的根;应改**滚动主档**(每股一份长历史,增量 append)。

---

## 三、推荐架构(治本)

```
① 全量历史一次性落地(首次 / 偶尔补齐)
   baostock 逐只拉全A ~1年日K(前复权)→ 落"滚动主档" data/master/kline/<code>.parquet
   (baostock 不封 → 无 sleep;可选并发再加速)。首次 ~5–15 分钟。

② 每日增量(每交易日盘后)
   akshare stock_zh_a_spot_em() 一次拿全A当日 bar → 逐股 append 到主档(去重/覆盖当日)。
   秒级完成。

③ 选股/形态读"主档"(全历史),不再每天重下。

④ 兜底:主档缺某股/异常 → 回退现有逐只 akshare 采集(并发化,见方案B)。
```

**方案B(并发,作兜底/过渡)**:不换源,把 `fetch_kline` 的串行改**有界线程池**(并发 8–12)+ 每请求 jitter(0.1–0.3s)+ 退避重试 + 多源轮换。实际提速 4–8×(受源限流)。**治标**——仍每天重下,故仅作主档缺失时的兜底。

---

## 四、存储设计(滚动主档,根治返工)

- 新增 `data/master/kline/<code>.parquet`:每股**一份长历史**(date 升序、前复权),非按日期分区。
- `load_kline(code)` 改为**优先读主档**,回退当日 raw(向后兼容)。
- 增量:`spot` 当日 bar → 按 date 去重 append(同日覆盖,防重复/盘中多次跑)。
- 复权处理:前复权历史会随分红除权变化 → 定期(如每周)全量重算一次主档;日常增量用当日未复权价另存或以"最近一次全量复权 + 增量"近似(实施时定口径,附校验)。
- 停牌/新股:spot 无该股当日 → 跳过(停牌);新股首次落全历史。

## 五、风险与缓解

| 风险 | 缓解 |
|---|---|
| **换源口径不一致**(复权/字段/精度)致形态参数错位 | 切换前做**等价对比**:抽 30–50 只,同票同日 baostock vs 现 akshare 的 O/H/L/C 逐一比对,差异超阈值不切 |
| 复权历史随除权变化 | 主档定期全量重算 + 增量;明确"前复权"统一口径 |
| baostock 登录态超时 | 采集前重登 + 异常重连重试 |
| 并发被封(方案B) | 有界并发 ≤12 + jitter + 退避 + 多源轮换;net 速率仍受源限 |
| pytdx 不稳 | 不作主力,仅可选加速;多服务器 + 重试 |
| 增量 append 重复/错位 | 按 date 主键去重覆盖;每次校验主档末尾日期连续 |

## 六、分步实施 + 基准

1. **基准先行**(等当前扫描跑完再测,避免抢网络):30–50 只做 (a)现状串行 (b)线程池并发8 (c)baostock 三组,量 wall-time + 报错/被封 + **OHLC 口径一致性**。用数据定选型与并发度。
2. baostock 全量历史 → 滚动主档 + `load_kline` 优先读主档(+ 等价对比测试)。
3. `stock_zh_a_spot_em` 每日增量 append。
4. 方案B 并发兜底(仅主档缺失路径)。
5. 接入盘后闭环 + 交易日历守卫(见 L3 §五)。

**工作量估(agent 视角,守则11)**:
- Token:中(基准+主档改造+等价测试,约数十万级 output;调研已完成)。
- Agent 执行:约 **1 窗口 1–1.5 天**(含基准实测 + 主档存储改造 + 口径校验测试 + 联调),可拆:基准(0.5天)→ 主档+增量(1天)。
- 收益:全A 采集 30–40min → 首次几分钟、日常秒级;根治跨日返工。**这是全A 常态盘后跑的前提**。

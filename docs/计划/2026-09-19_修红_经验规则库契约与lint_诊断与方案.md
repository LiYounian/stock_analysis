## 1. ① 契约缺顶层块 —— 根因 = 测试选文件过宽(非"老数据没回填")

### 诊断
两条测试都这样选文件:
```python
glob("data/analysis/*.json")  且 not endswith(("panel.json","screen.json"))
```
即"除 panel/screen 外,`data/analysis/` 下所有 json 都当成 per-stock 中心记录"来校验。
但 `data/analysis/` 里混进了两个**非中心记录**工件:

| 文件 | 顶层键 | 是中心记录? |
|---|---|---|
| `经验规则库.json` | `version, as_of_essay, rule_count, 环节枚举, 状态枚举, rules` | ❌ 经验规则库(`experience_rules_tool` 产) |
| `数据字典_2026-09-17.json` | `generated_for, source_doc, note, tables, dimensions_flat, stats` | ❌ 数据字典 |
| `000021.json`(真记录) | `schema_version, meta, snapshot, signals, prediction, ...` | ✅ |

中心记录的单一真源定义(`tools/contracts/record.py` docstring)明确是
**`data/analysis/{code}.json`**;`test_chart.py` 该测试 docstring 亦自称"**已落盘的中心记录**应全部过校验"。
两个非记录工件本就不该被 record 契约校验(它们没有 meta.code/signals/…,强塞 schema_version/meta 无意义)。
它们经由"只排除 panel/screen"的过宽 glob 漏进了校验集。

**结论:根因是测试的文件选择,不是数据缺字段。**不能给这两个文件"编"一个 schema_version/meta 让它过。

### 方案(不弱化语义)
把文件选择从"排除 panel/screen"改成"**正向匹配中心记录命名**"——
中心记录按代码命名(A股6位/港股5位,见 record.py CONVENTIONS),用 `^\d{5,6}\.json$` 精确纳入:
```python
_CENTRAL_RECORD_RE = re.compile(r"^\d{5,6}\.json$")
files = [f for ... if _CENTRAL_RECORD_RE.match(basename(f))]
```
- 语义**不变**:测试原意"所有真实**中心记录**都过契约(抓 serialize 产出漂移)"——serialize 产出即 `{code}.json`,全部仍被校验。
- 正确排除非记录工件(经验规则库/数据字典),且**对未来新增的非记录工件天然免疫**(不必逐个补进黑名单)。
- panel/screen 也不匹配 `\d{5,6}` → 自动排除,原黑名单退化为冗余(可留可去,本方案直接换成正向匹配)。

这是**修根因(测试选文件)**,非改松断言:断言守护的"中心记录必须合规"一字未动。

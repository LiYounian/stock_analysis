## 〇、结论先行(TL;DR)

**愿景一句话**:把每个策略做成一个**可勾选的"分析专家"**,每个专家对一只票给出**统一格式的结论(方向+强度+权重+依据+数据充分度)**;一个**合议层**收集勾选到的专家结论、**按话语权加权合成**、**识别并呈现冲突**,输出一个**可追溯到"哪个专家说了什么"**的综合结论。

**四条设计主张(建议采纳,细节见待决点):**
1. **统一专家结论契约 `ExpertVerdict`**(§二):所有专家——不论底层是"评分/选股/信号"哪类——都产出同一个信封。现有 4 个策略给出映射表,可无损适配。
2. **新增合议层 `tools/analysis/council.py`**(§三):位于分析层、registry 之上,**不 import web**。现有 `predict.bias_recommendation` 是它的**特例**(固定 5 因子、固定权重)→ 建议**泛化为合议层的一个默认专家组预设**,而非删除(向后兼容)。
3. **后端预算 + 前端勾选重合成**(§四):契合"后端离线批量算、只读展示"架构——后端把**每个专家的信封**都算好落库,前端勾选专家 = **前端按预设权重重新合成**(不触发后端重算、不触网)。
4. **三对齐硬规则**(§六):`docs/策略/` ⟺ registry 已注册 ⟺ UI 可勾选,三者严格一致;未实现的新策略只进本 roadmap,**不进** `docs/策略/`。

**新策略分级(§五):** 独立同级专家 = 多因子截面打分(P1)/ PEAD 事件驱动(P2)/ 板块轮动 RRG(P3);小事件模块(并入 PEAD 的"事件→前瞻收益"框架)= 增持回购;并入维度不独立成专家 = 北向(多因子里的资金流因子)/ 量价异动(形态确认位)/ 市场宽度(喂市场状态)。

**本文末尾 §七列出 9 个待用户拍板的待决点**(冲突仲裁规则、默认权重、置信度量化、买卖倾向去留等),请审阅时逐条选择。

## 一、愿景与术语

| 术语 | 一句话定义 |
|---|---|
| **专家(Expert)** | 一个策略的对外身份。对单票给出一份 `ExpertVerdict`。UI 上表现为一个可勾选项。**当前一个已注册策略 = 一个候选专家。** |
| **话语权(权重 Weight)** | 该专家结论在合议中的加权系数。有**默认权重**(配置真源);用户可在页面临时覆盖(待决 D2)。 |
| **勾选(Select)** | 使用者在选股/分析时选择"让哪些专家参与本次判断"。未勾选的专家不参与合成。 |
| **合议(Council)** | 收集被勾选专家的 `ExpertVerdict`,按权重合成一个综合结论的过程。 |
| **仲裁(Arbitration)** | 合议中处理"专家意见对立/平票"的规则(待决 D1)。 |
| **归因(Attribution)** | 综合结论中,标明每个专家贡献了什么方向/多少分——即"这个买卖信号来自哪个专家"的可追溯记录。 |
| **数据充分度(Sufficiency)** | 专家出结论时依赖的数据是否齐全(充分/部分降级/缺失)。缺数据的专家应降低置信度而非硬给结论。 |

## 二、统一"专家结论契约" `ExpertVerdict`

### 2.1 信封字段(建议)

一个专家对**单票**的输出统一为:

```jsonc
{
  "专家": "技术趋势",           // registry 里的策略名(唯一键)
  "能力类型": "方向",           // 方向 | 评级 | 信号 | 入选(见 2.3 兼容)
  "方向": "看多",               // 看多 | 看空 | 中性 | 不适用   ← 统一三态(+不适用)
  "强度": 0.35,                 // -1.0 ~ +1.0,已按方向带符号(看多为正)。裸分归一到此区间
  "置信度": 0.8,                // 0 ~ 1,含数据充分度与共振度;缺数据时显著降低
  "默认权重": 1.0,              // 该专家的话语权基准(真源在 config,见 D2)
  "依据": ["MACD金叉+25", "价>MA20+10"],   // 可读、可追溯(沿用现有"依据"惯例)
  "数据充分度": "充分",          // 充分 | 部分降级 | 缺失
  "原始": { /* 各专家 kind 原生输出,原样保留供深查 */ }
}
```

**设计要点**
- **方向统一三态 + "不适用"**:把各专家五花八门的结论压到 `看多/看空/中性`,合议才能横向加权;纯选股类无方向时用"不适用"(见 2.3)。命名与现有"偏多/偏空"对齐但**收敛为看多/看空**(待决 D5:是否统一术语)。
- **强度带符号**:`看多→正、看空→负`,量级归一到 [-1,1]。合议合成用 `Σ(强度×置信度×权重)`,一步到位。
- **置信度 ≠ 强度**:强度是"多看多/多看空",置信度是"我多确信"(数据齐不齐、共振几个)。二者相乘才是有效贡献——这解决了"缺数据还大声下结论"的问题。
- **依据必留**:每个专家都要能回答"我为什么这么说",直接支撑 UI 的归因展示。

### 2.2 合成贡献公式(建议,待决 D3 细化)

```
专家有效贡献  contrib_i = 强度_i × 置信度_i × 权重_i
综合分        S = Σ contrib_i / Σ 权重_i          # 归一回 [-1,1]
综合方向      S ≥ +τ → 看多;S ≤ −τ → 看空;其间 → 中性   # τ 阈值可配(默认拟 0.2)
```
> 与现有 `bias_recommendation`(整数加减分、阈值 ±2)同构,只是把"整数分"换成"带权归一分",**买卖倾向可作为合议层的一个内置预设无缝迁移**。

### 2.3 与 registry 现有三类的兼容(映射/适配)

registry 现有三类签名并不直接产出 `ExpertVerdict`,需一层**专家适配器**(建议放 `council.py` 或 registry 旁的 `experts.py`)。三类适配规则:

| registry kind | 现签名 | 适配为 ExpertVerdict | 适配难度 |
|---|---|---|---|
| **评分 Score** | `fn(record)->{score,依据}` | **最直接**:score 归一为强度、依据直取、置信度由数据充分度定 | 低(直接映射) |
| **选股 Screen** | `fn(records)->[codes]` | 该票**入选→看多信号、未入选→中性**(不反推看空);"入选"作"能力类型=入选",方向由"达标/未达标"给正/中性 | 中(池级→单票需反查) |
| **信号 Signal** | `fn(kline)->[买/卖/持]` | **取最新一根**信号:买→看多、卖→看空、持→中性;强度可用信号连续性/新鲜度 | 低–中(取末位) |

> **关键取舍(待决 D4)**:是给 registry **新增第四类 kind「专家/verdict」**(专家直接产 ExpertVerdict,最干净),还是**只加适配器包装现有三类**(不改 registry,兼容性最好)?建议**先适配器、后视需要再加 kind**,避免动地基。

### 2.4 现有 4 策略 → ExpertVerdict 映射表

| 现有策略 | 源模块 | 方向怎么定 | 强度怎么定 | 置信度/数据充分度 |
|---|---|---|---|---|
| **技术趋势评级** | `technical.py` trend | 偏多→看多 / 偏空→看空 / 中性 | 得分/100(−100~100 → −1~1) | 依据项数、指标齐全度 |
| **超买超卖(共振)** | `technical.py` ob_os | 超卖→看多(反弹) / 超买→看空 | 共振数映射(2→0.5,3→0.8) | **共振数即置信度**(共振越多越确信) |
| **拐点识别** | `technical.py` reversal | 反弹启动/超跌待反弹→看多;无→中性 | 拐点评分/100 | 触发项数 |
| **情绪三层** | `event.py`/`sentiment.py` | 净情绪≥+0.2→看多 / ≤−0.2→看空 | 净情绪分(已在 −1~1 级) | **样本数**(0→缺失、少→部分降级) |
| **形态选股(V1)** | `pattern_screener/screen.py` | 达标→看多 / 不达标→中性 | 命中形态置信 + RS 强度 | 各项(形态/RS/量能/护栏)齐全度 |
| **买卖倾向(现)** | `predict.py` bias | 偏买入→看多 / 偏卖出→看空 | 得分归一 | 参与因子数 | 
> 注:买卖倾向本身是"合成结论",迁移后它**要么退化为合议层的默认预设(推荐)、要么保留为一个"元专家"**——见待决 D6。

## 三、合议 / 仲裁层设计

### 3.1 位置与依赖

```
                    ┌─────────────── web(展示,只读) ───────────────┐
                    │  勾选专家 · 归因表 · 冲突呈现(§四)              │
                    └───────────────▲───────────────────────────────┘
                                    │ 只读中心记录(内含各专家信封 + 预设合议结果)
   分析层  ┌─────────────────────────┴─────────────────────────┐
           │  council.py(新增) —— 合议/仲裁                     │
           │   collect(勾选) → 各 ExpertVerdict → 加权合成 → 冲突 → 综合结论+归因 │
           └─────────────▲──────────────────────────────────────┘
                         │ 调用
           experts 适配器(包装 registry 三类为 ExpertVerdict)
                         │
           strategy/registry.py(已有,不改)  ── @strategy 三类
                         │
           technical / event / pattern_screener / …(已有分析器)
```
- **`council.py` 属分析层**,只依赖 registry / 各分析器 / config;**不 import web / report / serialize**(守现有依赖方向)。
- 合议**产物写入中心记录**(如 `record["council"]`),展示层只读——与"后端离线批量算、只读展示"架构一致。

### 3.2 合议流程

1. **入参**:`选中的专家名列表` + `可选的权重覆盖` + `单票(record + kline)`。
2. **收集**:对每个专家跑其适配器 → 得到一组 `ExpertVerdict`(缺数据的专家给低置信度而非跳过,保留"它弃权/降级"的可见性)。
3. **合成**:按 §2.2 公式算综合分 S、综合方向。
4. **冲突检测**(待决 D1 定义):建议判据 = **同时存在"看多"与"看空"专家,且双方加权贡献都非微弱**(如各自 |contrib| ≥ ε)。
5. **仲裁**(待决 D1 选规则):候选方案——
   - (a) **加权求和为准**:直接用 S 定论,冲突只做标注(推荐,最简单可解释);
   - (b) **高置信度优先**:对立时以置信度更高的一方为准;
   - (c) **保守优先**:出现对立即降级为"观望/中性",不赌方向;
   - (d) **话语权优先**:权重最高的专家胜。
6. **输出**:
```jsonc
{
  "综合方向": "看多", "综合分": 0.28,
  "参与专家": ["技术趋势","超买超卖","情绪三层"],
  "归因": [ {"专家":"技术趋势","方向":"看多","贡献":0.21}, ... ],   // 排序,支撑 UI
  "是否冲突": true,
  "冲突说明": "情绪三层看空(-0.3) vs 技术趋势看多(+0.35)",
  "口径": "预设权重·τ=0.2·仲裁=加权求和"
}
```

### 3.3 与现有"买卖倾向"的关系(三选一,待决 D6)

| 方案 | 含义 | 优劣 |
|---|---|---|
| **A 泛化替换(推荐)** | `bias_recommendation` 的 5 因子变成 5 个专家,合议层用一个名为"买卖倾向(默认组)"的预设复现它 | 语义统一、可扩展;需保证迁移后**结论逐票等价**(回归测试锁死) |
| **B 并存** | 买卖倾向保持不动,合议层作为"高级模式"另开 | 改动小、风险低;但两套合成逻辑长期并行易漂移 |
| **C 元专家** | 买卖倾向本身作为一个专家参与更高层合议 | 概念优雅但**双层加权易重复计权**(同一信号被算两次),不推荐 |

> 推荐 **A**,并以"迁移前后每票买卖倾向结论 100% 等价"作为验收红线(参照项目一贯的等价回归习惯)。

## 四、Web 展示设计(只设计,不实现)

### 4.1 数据流取舍(待决 D7)

- **推荐:后端预算全部专家信封 + 若干"预设专家组"的合议结果一起落库**;前端勾选 = **纯前端过滤 + 按预设权重重新合成**(轻量 JS,不触发后端、不触网)。
  - 理由:契合只读离线架构;勾选交互零延迟;远端展示端也能用(无需算力)。
  - 代价:前端要内置一份合成公式(与后端保持同一真源,靠共享常量/契约约束)。
- 备选:勾选触发后端重算 —— 与"离线预生成、展示端不跑计算"冲突,**不推荐**。

### 4.2 页面信息结构草案

**(个股页 `stock.html` 增区块)**
```
┌ 专家合议(可勾选) ────────────────────────────────┐
│  参与专家:  ☑技术趋势 ☑超买超卖 ☑拐点 ☑情绪三层 ☐形态 ☐多因子 …  │
│  综合结论:  【看多 +0.28】   ⚠️ 存在分歧                      │
│  ── 归因(按贡献排序)──                                      │
│   技术趋势   看多  +0.21  ▓▓▓▓░  依据:MACD金叉/价>MA20        │
│   超买超卖   看多  +0.10  ▓▓░░░  依据:KDJ+RSI 共振超卖         │
│   情绪三层   看空  −0.09  ▓░░░░  依据:政策利空/样本12         │
│  口径:预设权重 · τ=0.2 · 仲裁=加权求和                        │
└──────────────────────────────────────────────────────┘
```
- **① 勾选**:专家复选框(默认勾"买卖倾向默认组"那几个);勾选变化即时重算综合结论(前端)。
- **② 来源归因**:综合结论下一张"专家→方向→贡献→依据"表;现有徽章(趋势/超买超卖/拐点/买卖倾向)可各自加"来自 X 专家"标注(复用 stock.html 现有 badge 结构)。
- **③ 冲突呈现**:综合结论旁 `⚠️ 存在分歧` 标记;归因表中看多绿/看空红分色(复用现有 pos/neg 类);可折叠"正方 vs 反方"两栏。

**(选股页)**:顶部同款专家勾选面板 → 影响"综合分"列的排序与入选;每票一行展示综合方向 + 分歧标记。

> 以上仅信息结构;具体 HTML/JS 由实现阶段做,遵循现有 ECharts + Jinja2 + `web/static/style.css` 既有类名。

## 五、新策略 roadmap(调研 5 策略分级)

分级依据:**能否对单票稳定产出一个 ExpertVerdict**(能→独立专家)、**是否共享既有框架**(共享→并入模块)、**是否只是一维输入**(是→并入别的专家)。

| 策略 | 定级 | 产出的专家信封 | 数据源(akshare 可得性) | 依赖 | 排期 |
|---|---|---|---|---|---|
| **多因子截面打分** | **独立同级专家(P1)** | 方向=综合因子分符号;强度=横截面分位;依据=各因子贡献 | `stock_financial_analysis_indicator`/`stock_a_indicator_lg`/K线自算 —— **全免费可得** | 合议层契约先定 | P1 |
| **PEAD 事件驱动** | **独立同级专家(P2)** | 方向=超预期正/负;强度=漂移窗内前瞻收益;依据=预告增速/窗口 | `stock_yjyg_em`/`stock_yjkb_em` 可得;一致预期基准需近似(标注) | 事件→前瞻回测框架(复用 BT.1) | P2 |
| **增持/回购** | **小事件模块(并入 PEAD 框架)** | 并入"公司行为事件分",方向=增持/回购正、减持负;强度=规模占比 | `stock_ggcg_em` + 巨潮 —— 可得、最易 | 与 PEAD 共用事件框架 | P2(随 PEAD) |
| **板块轮动 RRG** | **独立同级专家(P3)** | 方向=所属行业象限(改善/领先→看多);强度=RS-Ratio/RS-Momentum | `stock_board_industry_hist_em` + 沪深300 —— 可得 | 现有个股 RS 扩到行业层 | P3 |
| **北向资金** | **并入维度(不独立)** | 作**多因子里的"资金流因子"**一维(5–10日趋势) | `stock_hsgt_*` —— 个股明细口径需实测确认 | 多因子专家(P1) | 随 P1 |
| **量价异动/放量突破** | **并入维度(不独立)** | 作**形态专家的"确认位"**,不单独下结论 | K线量/换手 —— 可得 | 形态专家(已有) | 随形态迭代 |
| **市场宽度(达标占比等)** | **并入维度(喂市场状态)** | 非个股专家;喂**市场状态系统**当宽度信号 | 由横截面批量结果自算 —— 零额外采集 | 市场状态系统(在建) | 随市场状态 |

> 说明:独立专家 = 会出现在 UI 勾选列表;并入维度 = 隐身在某个专家内部,不单独勾选。分级本身也是待决点(D8)。

## 六、三对齐原则(硬规则)

```
docs/策略/<某策略>.md   ⟺   registry 已 @strategy 注册   ⟺   UI 专家勾选列表可见
        (已实现的人读版)            (代码事实来源)                (使用者可选)
```
- **三者必须严格一致**:一个策略只有"已实现 + 已注册 + 有文档"时,才作为专家出现在 UI。
- **未实现的新策略只进本 roadmap(docs/计划/)**,**不进** `docs/策略/`(那里只放已落地策略,见其 README 约定)。
- 落地某新专家时的清单:实现 → `@strategy` 注册 + 写 `experts` 适配器产 ExpertVerdict → 补 `docs/策略/<名>.md` → 接入 UI 勾选 → 回归测试 → 更新 `docs/工程进度.md`。
- **权重/阈值真源**唯一:`tools/config/strategy.py`(专家默认权重、合成 τ、置信度映射都落这里),文档只做人读镜像。

## 七、待用户拍板的待决点

> 以下都不武断锁死,请审阅时逐条选择;选定后我再据此出实现级需求。

| 编号 | 待决点 | 选项(建议项标 ★) | 影响 |

| **D9** | **合议是否影响选股排序** | ★综合分参与选股页排序 / 合议只做个股页展示、不动选股 | 影响范围大小 |

## 0.5 策略提供者交谈要点(2026-08-14)→ 管线重构(重要)

策略提供者给了一条"**便宜先行、投资视角**"的财报管线,直接重塑本方案。核心:

### A. ⭐ 双前置闸门(最便宜、最高价值,放最前,命中即弃)
1. **审计机构排查**:全国审计/会计师事务所上万家,但有 A 股/IPO 证券业务资格的仅 **~102-105 家**。**财报审计机构不在这份名单 → 直接判"财报不可信",不再调用任何工具深查**。名单内可分三档(国有大所/八大 · 行业公认强所 · 尾部);**近年频繁更换审计机构、尤其"从头部换到尾部"= 重红旗**(尾部所审计能力弱、易被钻空子造假;注:国家要求定期轮换,轮换本身不算问题,看**频率 + 换的方向**)。
2. **审计意见类型**:只有 **标准无保留意见** 通过;其余四类(保留/否定/无法表示/带强调事项等)一律**判财报有问题、不往下走**(连专业初审都没过)。
> 注:审计是**抽检**非全量,过闸 ≠ 保真,但这是最便宜的第一道过滤,先卡掉一大批。

### B. 投资视角 = "合理怀疑即避",不是审计
- 我们做**投资侧**:有疑点就规避("我不投你了"),**不需要实锤/证据链**(那是审计的事)。→ 我们的财报模块是**红旗过滤器**(升起疑点→降权/规避),不是"证明造假"。这修正了 §2.3(b) "好坏"判据的定位:输出"有无疑点/红旗强度",而非"是否造假"。

### C. 浅度 vs 深度分析(分层,先做浅度)
- **浅度(先做,服务情绪/短期)= 只看利润表**:多数非价投投资者对财报的反应就看利润表(营收/利润 + 企业怎么美化/唱高调)。**对情绪/行情面,利润表足够** → 把利润表提到 P0 浅度层,先交付。
- **深度(后做,价投,用 AI/subagent)= 三大表勾稽**:利润表某项好看 → 查负债表/现金流是否同步变动;合理调节 OK、非法调节打问号。较复杂,后续做。

### D. 深度分析方法(纳入红旗/异常框架)
1. **八大类造假行为**为基础:让大模型先把八大类全梳理出来,再**反向逐条比对**财报(需研究物,见 §四)。
2. **连续多期对比**:看**前 3-4 年 + 今年**的变动,单期变动不可靠。
3. **异常数据分类分析(同行业相对)**:某数据异常(如降)不等于有问题——**先比同行业**(如白酒:茅台降就看国窖/洋河是否也降;行业普降→大概率政策/行业现状、合理;个股独降→可疑),再判"短暂阵痛 vs 长期下坡"(需商业模式/市场判断)。
4. **图表化**:让 AI 把各指标(存货周转率等)**统计并画出来**,只有把波动画出来才看得出正常与否。

### E. Agent 循环架构(与我们现有模式一致)
总管 Agent 现场编**定向提示词** → 派 **sub agent**;提示词含 **(a)要干的事 (b)要审查的内容 (c)疑点 (d)预期** → sub agent 以文档/文字回结果 → 主 Agent 分析、往下探查。**这正是本项目的 orchestrator+subagent+预注册模式**,财报深度分析直接套用。

### 管线调整小结(据上)
```
财报 → [闸门1 审计机构∈102?] → [闸门2 意见=无保留?]  ← 不过=判不可信,弃

```

## 一、财报分析调研(4 个研究问题)

### 1.1 财报怎么看 / 怎么分析

**三大报表各看什么:**

- **利润表(损益表)**:公司「赚不赚钱」。核心链条 营业总收入 → 营业成本/毛利 → 期间费用(销售/管理/研发/财务)→ 营业利润 → 利润总额 → 净利润 → **归母净利润 / 扣非归母净利润**。看点:收入的**含金量**(主营 vs 投资收益/公允价值变动/营业外)、毛利率与净利率趋势、费用率是否吞噬毛利、研发资本化比例。
- **资产负债表**:公司「家底与欠债」。资产端看 货币资金、应收账款、存货、商誉、在建工程、固定资产;负债端看 有息负债(短期借款+一年内到期+长期借款+应付债券)、应付账款、合同负债(预收,反映订单)。看点:**资产结构、有息负债规模、货币资金能否覆盖短债、商誉占净资产比**。
- **现金流量表**:公司「钱的真实进出」,最难粉饰。经营活动现金流净额(CFO)、投资活动(CFI,扩张/收缩)、筹资活动(CFO,借钱/还钱/分红)。看点:**CFO 是否持续为正、CFO 与净利润的比值(现金含量)、自由现金流(CFO−资本开支)**。

**A 股特有的口径:**

- **报告期节奏**:一季报(Q1)/ 半年报(H1)/ 三季报(Q1-Q3)/ 年报(全年)。**季报是累计口径**(三季报=前三季合计),算单季需相邻期相减;**年报最全**(含附注、管理层讨论、审计意见),季报最简。
- **业绩预告(yjyg)vs 快报(yjkb)vs 正式财报**:预告最早(区间/方向)、快报次之(接近实际未审计)、正式财报最终(审计)。三者**逐步收敛**,差异本身是信号(预告翻脸=红旗)。
- **扣非净利润**:剔除非经常性损益(政府补助、资产处置、公允价值变动、投资收益等一次性项目)后的净利,反映**主业真实盈利**。归母净利大增但扣非下滑 = 靠一次性项目撑,红旗。
- **非经常性损益**:一次性、与主业无关的损益;占净利比过高说明利润质量差。
- **审计意见**:标准无保留是正常;保留/无法表示/否定意见,或频繁更换会计师事务所,是重大红旗。

### 1.2 哪些内容对选股有用

按维度归纳(数值均可由结构化 API 算出):

| 维度 | 关键指标 | 选股含义 |
|---|---|---|
| **成长性** | 营收增速、归母净利增速、**扣非净利增速**、单季环比/同比、增速的趋势(加速/减速) | 找持续成长股;警惕增速见顶回落 |
| **盈利质量** | 扣非净利占比、**CFO/净利润(现金含量)**、毛利率稳定性、非经常损益占比 | 区分「真赚钱」与「账面赚钱」 |
| **财务健康** | 资产负债率、**有息负债率**、货币资金/短期有息负债(短债覆盖)、**大存大贷**(高货币资金+高有息负债并存)、流动/速动比率 | 排雷,防暴雷/退市 |
| **运营效率** | 应收账款周转、存货周转、总资产周转、应收/存货增速 vs 营收增速 | 增速是否真实、有没有压货/放账冲收入 |
| **回报能力** | ROE(净资产收益率)、**ROIC**、杜邦分解(净利率×周转×杠杆) | ROE 由谁驱动(高利润 or 高杠杆) |
| **估值配合** | PE_TTM、PB、**PEG**(PE/净利增速)、PE 历史分位、PB-ROE 匹配 | 成长与估值是否匹配;已有 `fundamental.py` 提供 PE/PB/PE分位 |
| **股东回报** | 股息率(已有每股分红TTM)、分红率、连续分红年数 | 现金流真实性的旁证 |

### 1.3 该关注 / 挖掘哪些问题(红旗信号,给 Agent 深挖)

**数值可判定的红旗**(结构化 API 直接算):

1. **增收不增利 / 增利不增收**:营收增而净利降(成本失控/减值)或反之(一次性)。
2. **应收账款 / 存货异常激增**:增速显著快于营收 → 压货、放宽账期冲收入、滞销。
3. **经营现金流长期 < 净利润**:CFO/净利连续多期 < 0.8 或为负 → 利润没转化成现金。
4. **商誉高企 / 减值风险**:商誉/净资产过高 → 潜在暴雷;当期大额资产减值。
5. **大存大贷**:高货币资金 + 高有息负债并存 → 资金真实性存疑(獐子岛/康得新式)。
6. **非经常损益撑利润**:归母增、扣非降;非经常损益占净利比过高。
7. **扣非净利为负 / 连续为负**:主业不赚钱;连续两年亏损触及 ST 风险。
8. **预告 / 快报 与正式财报大幅背离**:业绩变脸。
9. **毛利率异常**:远超同业或突然跳升(虚增收入嫌疑)。
10. **有息负债 / 短债覆盖不足**:货币资金 < 短期有息负债 → 流动性风险。

**需结合文本/公告判定的红旗**(LLM 或人工):

11. 频繁变更审计机构 / 会计政策 / 会计估计。
12. 非标准审计意见(保留/无法表示/否定)。
13. 大股东高比例质押 + 减持(结合 `event_driven` 增减持)。
14. 关联交易占比过高、频繁的体外资金循环表述。

### 1.4 要抽取哪些问题(LLM 部分,从财报文字 / 管理层讨论)

从**非结构化文本**(年报「管理层讨论与分析 MD&A」、业绩说明、公告正文)抽**定性**信息:

- **业务驱动 / 增长来源**:收入增长主要来自哪个产品线/区域/客户?量增还是价增?
- **在手订单 / 产能**:在手订单金额、产能利用率、扩产/募投项目进展。
- **经营指引 / 展望**:管理层对下期的收入/利润指引、行业景气判断。
- **风险提示**:公司自述的经营风险、诉讼、客户集中度、原材料涨价。
- **募投进展**:募集资金投向项目的进度与达产情况。
- **一次性事项说明**:大额非经常损益、减值、重组的原因说明。

## 二、三个核心设计

### 2.1 数据抽取(抽什么 / 怎么抽)

**总原则**:**数值走结构化 API,LLM 只做文本定性 + 综合归纳 + 红旗识别**。理由:三大表科目虽然各公司披露格式有差异,但 akshare 已按标准科目名归一;让 LLM 解析数字既贵又容易算错、且不可复核。**分工硬边界**:

- **A. 结构化数值层(不经 LLM)** —— akshare 接口:
  | 数据 | 首选接口 | 说明 |
  |---|---|---|
  | 三大表(多报告期明细) | `stock_financial_report_sina(stock, symbol)` symbol∈{资产负债表,利润表,现金流量表} | 权威、非东财;按报告期给全科目 |
  | 财务分析指标(多期) | `stock_financial_analysis_indicator(symbol, start_year)` | ROE/周转/每股/增长率等衍生指标 |
  | 单季/按报告期明细(备选) | `stock_lrb_em`/`stock_zcfz_em`/`stock_xjll_em`(按 date 全市场)或 `stock_*_sheet_by_report_em`(按票) | 与 sina 互为交叉校验/降级 |
  | 主营构成 | `stock_zygc_em(symbol)` | 分产品/地区收入占比,给「增长来源」提供数值锚 |
  | 财务摘要 | `stock_financial_abstract`(现已用) | 快速摘要,降级兜底 |
  | 业绩预告/快报 | `stock_yjyg_em`/`stock_yjkb_em`(现已用) | 与正式财报对账 |
  | 估值/分红 | 百度估值 + baostock(现已用) | PE/PB/PE分位/每股分红 |

  衍生指标由代码计算(不经 LLM):增速、单季环比、CFO/净利、扣非占比、周转天数、杜邦三项、PEG、短债覆盖、商誉占比、大存大贷标志等。

- **B. LLM 文本定性层** —— 输入:年报 MD&A / 业绩说明 / 公告正文(**当前无此数据源,见 Q4**);输出:统一 schema(下方草案)。**用统一 schema 归一「不同企业格式不同」**——不管原文怎么写,都抽成同一批字段,拿不准留 null。

- **C. LLM 综合归纳层** —— 输入:B 的定性抽取 + A 的关键数值/红旗 flags;输出:「这家公司到底好还是坏」的一段结构化归纳 + 质地评级 + 红旗确认。

```jsonc
}
```

**抽取指令要点**(描述性约束,防编造):只依据财报原文与所给数值,禁外部推断;拿不准的字段留 null / 空列表;金额带原文单位;不同公司披露格式不同时只填 schema 有的字段。

### 2.2 存储结构(键 = `(code, 报告期)`)

**关键决策:财报按报告期(period)组织,不按采集日期。** 现有 store 全部按**采集日期**分区,财报天生是「一个报告期一条、可被后续修正」的实体,应以 `(code, period)` 为主键。

**落盘位置建议**:新增一个 raw kind `financial_report`(json),键用 `code` 存一个「多报告期字典」文件,内层按 period 索引。这样:

- 复用现有 `put_raw("financial_report", code, payload)` / `get_raw`(json kind,无需改 store 大结构,只在 `_JSON_KINDS` 注册新 kind)。
- 原始三大表 + 指标明细(大数组)进 raw;**衍生指标 + LLM 定性 + flags + 评分**进「财报分析记录」。
- **财报分析记录**建议独立成 `financial_report` 分析视图(`put_view` code_view 语义,按 code 存 period 字典),或作为中心记录 `record.json` 的新顶层块 `financial`(见 §待确认 Q1)。

**单条财报记录结构(草案)**:

```jsonc
{
  "code": "600600", "name": "青岛啤酒",
  "period": "2025-Q3",          // 报告期(键)
  "report_type": "三季报",       // 一季报/半年报/三季报/年报
  "disclosure_date": "2025-10-28", // 披露日(锚定,防未来函数,见下)
  "is_forecast": false,          // true=来自预告/快报(未审计)

  "structured": {                // A 层:结构化数值(选取关键科目,原始明细在 raw)
    "营收": ..., "归母净利": ..., "扣非归母净利": ...,
    "CFO": ..., "货币资金": ..., "有息负债": ..., "应收账款": ..., "存货": ...,
    "商誉": ..., "净资产": ..., "研发费用": ..., "毛利率": ..., "净利率": ...,
    "资产负债率": ..., "ROE": ..., "PE_TTM": ..., "PB": ...
  },
  "derived": {                   // 代码算的衍生指标
    "营收增速": ..., "扣非净利增速": ..., "单季营收环比": ...,
    "现金含量_CFO比净利": ..., "扣非占比": ..., "应收周转天数": ..., "存货周转天数": ...,
    "杜邦": {"净利率": ..., "总资产周转": ..., "权益乘数": ...},
    "PEG": ..., "短债覆盖": ..., "商誉占净资产": ...
  },
  "flags": [                     // 红旗 flags(规则触发,附阈值命中值)
    {"code": "增收不增利", "命中": true, "值": {"营收增速": 12.3, "净利增速": -8.1}}
  ],
  "qualitative": { /* schema_A */ },   // B 层:LLM 文本定性(可 null,数据源/LLM 未就绪时降级)
  "verdict": { /* schema_B */ },       // C 层:LLM 综合归纳 + 质地评级(可 null)
  "quality_score": 72,           // 质地综合评分 0~100(规则+权重,口径待提供者定,见 Q3)
  "provenance": {"structured": true, "qualitative": false, "source": "sina+em"}
}
```

**无未来函数(关键)**:所有财报数据以 **`disclosure_date`(披露日)** 锚定,而非报告期结束日。回测/选股在某交易日 T 只能看到 `disclosure_date <= T` 的财报;**报告期 2025-Q3 结束于 09-30 但披露于 10-28,10-28 之前不可见**。查询接口(§2.3)必须强制传 as_of 并按披露日过滤。业绩预告/快报以其**公告日**锚定,与正式财报分别留痕(`is_forecast`)。

**与现有 record 挂钩**:中心记录已有 `fundamental` 块(最新摘要)。建议新增顶层块 `financial`,只放**最新已披露报告期**的 `derived + flags + verdict + quality_score`(轻量摘要,不塞多期大数组);多期明细留在 raw/财报视图,按需查。这样 panel/screen/web/Agent 消费 record 时能直接拿到质地评分,不破坏现有 12 块契约(新增可空块,校验对 null 宽容)。

### 2.3 数据使用

#### (a) 支持不同策略查询 / 提取财报字段

给一个**声明式查询接口**构想,让策略按条件筛票、按字段取值,统一走披露日锚定:

```python
# 构想接口(financial_report 层)
def query(codes, as_of, where=None, select=None) -> dict[code, dict]:
    """按报告期财报字段筛选/提取。
    as_of: 必传,只看 disclosure_date <= as_of 的最新已披露报告期(防未来函数)。
    where: 条件表达式,如 {"净利增速": (">", 30), "现金含量_CFO比净利": (">", 0.8)}
    select: 要取的字段列表;None=全给。
    返回命中票 → {字段: 值}。
    """
```

例:「净利增速>30% 且 经营现金流>净利」→ `where={"扣非净利增速": (">",30), "现金含量_CFO比净利": (">",1.0)}`。策略层(`tools/strategy/`)、多因子(`factor/`)、合议专家(`analysis/experts.py`)均可调用,把财报维度接入选股/打分。也可暴露成一个「财报因子」供 `council` 投票。

#### (b) 质地评分 / 公司画像构想

给一个**质地评分 + 画像**构想(**权重与阈值口径待提供者确认,见 Q3**):

- **五维雷达**:成长性 / 盈利质量 / 财务健康 / 运营效率 / 回报能力,各 0~100,由 §1.2 指标标准化(相对行业分位或绝对阈值)加权。
- **综合质地评分 `quality_score` 0~100**:五维加权 − 红旗扣分。触发高严重度红旗直接封顶(如「大存大贷/非标意见」→ 评级降至「风险」)。
- **公司画像(一段话)**:由 LLM 综合层(schema_B)基于「五维分 + flags + 文本定性」生成「经营状况 / 资金来源 / 好坏」的自然语言归纳,供 web 详情页 / Agent / 报告直接引用。
- **资金来源分析**:由现金流量表三段(CFO/CFI/CFF)组合判断「造血模式」——靠经营(健康)/靠融资(输血)/靠变卖资产,附自由现金流。

## 三、给策略提供者的注意事项 + 我的构想

**注意事项(工程侧已定 / 建议)**:

1. **数值不让 LLM 碰**:三大表/指标全走 akshare 结构化 API + 代码算衍生;LLM 只做文本定性、综合归纳、红旗复核。这是成本与正确性的硬边界,建议保留。
2. **披露日锚定、无未来函数**:所有财报按 `disclosure_date` 可见性过滤,预告/快报与正式财报分别留痕。回测直接可用。这条不可妥协。
3. **降级友好**:LLM/财报原文数据源未就绪时,结构化层 + flags + quality_score 仍可独立产出(qualitative/verdict 置 null),不阻断。与现有 collectors 的「优雅降级」一致。
4. **按报告期存储**:财报是 `(code, period)` 实体,不同于现有「按采集日期」的快照。建议独立 kind/视图,避免污染现有分区语义。

**我的构想(可直接落地的默认口径,待提供者覆盖)**:

- **红旗默认阈值(占位,待确认)**:现金含量 CFO/净利 < 0.8(连续 2 期)、应收/存货增速 − 营收增速 > 20pct、商誉/净资产 > 30%、资产负债率 > 70%(非金融)、货币资金 < 短期有息负债、扣非/归母 < 0.6。
- **质地评级映射**:优(≥80)/良(65~79)/中(50~64)/差(35~49)/风险(<35 或触高危红旗)。
- **成长性口径**:优先用**扣非净利增速**而非归母(更反映主业);季报用单季同比 + 累计同比并存。

# 设计:午盘选股迭代 —— 复盘闭环 + 输出侧重点重构

> 起草 2026-09-10。实现窗（worktree `confident-driscoll-e23c7b`，分支 `claude/confident-driscoll-e23c7b`，基于最新 origin/main）。
> 本文只做**设计**，交统筹/用户审阅后再进入实现。⚠️ 测试环境研究模拟，**非投资建议**。防未来函数为硬红线。

## 0. 缘起与目标

现状:午盘全A选股节点（`tools/pipeline/intraday_screen.py`，launchd `com.stock.intraday_screen` 每交易日 **11:32** 跑，产 `docs/每日分析/选股/日内全A_<date>.md`）今天已跑通:午休 11:30 冻结全A行情 → 内存注入午盘 bar（防未来:close=11:30 冻结价，绝不含之后的行）→ 9 策略数据初筛 → shortlist 消息面三段式回灌 → 产出 85 只候选、按「完整分」全序排列。

用户明确的两个迭代方向:

- **短板 A · 没有复盘闭环**:午盘选股只「做」了，没有任何任务回头验证「午盘选的票当天下午 / 次日表现如何」。盘后选股链路有收盘复盘（逐票收盘记分 + 经验沉淀），午盘缺这一环 → 无法评估、无法迭代。
- **短板 B · 输出侧重点不对**:现在是 85 只全序排名，不是用户要的「聚焦今日可买入」。用户要的是**找今日（未结束交易日内）可买入的股票**，且**把「该买入」和「该规避」都明确列出**（规避组和买入组都要，为验证策略服务，不是只给买入）。

目标:①补一个**确定性、当日可闭环**的午盘选股复盘节点，产出买入组/规避组逐票 α 记分表（供后续 web/经验沉淀消费，列名与盘后复盘兼容）；②把午盘选股输出从「85 只全序」重构为**【今日可买入清单】+【今日规避清单】两栏 + 时效/行动标注**；③预注册一套验证闸门，先定「怎么算迭代成功」再评判。

## 2. 复盘闭环设计（短板 A）

### 2.1 核心思路:午盘选股「当日就能闭环」——这是它区别于盘后选股的结构性优势

盘后选股当天收盘才选出，最早只能次日验证。午盘选股 **11:30 就选出**，而当日收盘（含全A等权基准 `data/breadth`）**15:05 就落盘** —— 所以午盘选出的票**当天 15:xx 就能记「下午半场」的 α**。这是午盘选股独有的、盘后拿不到的快反馈闭环。

### 2.2 两个记分 horizon

| Horizon | 建仓基准价 → 结算价 | 衡量什么 | 何时可算 |
|---|---|---|---|
| **下午 α（核心）** | 当日 11:30 冻结价 → 当日收盘价 | 「午盘选出、尾盘/下午可买」的当日下午超额，直接对齐用户「今日可买入」侧重点 | 当日 15:05（breadth 落盘）后 |
| **T+1 α（稳健性）** | 前一日 11:30 冻结价 → 次日收盘价 | 隔日持有超额，与盘后选股同 horizon，便于横向比 | 次日 15:05 后 |

- **下午 α = (当日收盘价 − 11:30 冻结价)/11:30 冻结价 × 100 − 全A等权下午基准**。这是 **D-0 当日闭环**（午盘票当天就能验下午表现），是午盘选股独有、盘后 eod-review（复盘 D-1）拿不到的时段。
  - ⚠️ 基准口径细化点（**分叉 D1**）:`data/breadth` 的 `mean_pct` 是「昨收→今收」全日口径，与「11:30→今收」的下午口径**不同源**。下午 α 的基准需要「全A等权**下午**涨跌」(11:30→收盘)。
  - **实现依赖**:算全A下午等权，需要全A的「11:30 冻结价」向量 + 当日收盘价向量。收盘价在主档 K 线（15:05+ 可得）；11:30 冻结价 `intraday_screen.run_intraday_screen` **已经拉到内存**（`quotes`）但未落盘。**建议:让 `intraday_screen` 把它已取的全A 11:30 快照落盘**（如 `data/intraday_noon_snapshot/<date>.json`，含 code→price），复盘节点读它现算下午等权——快照在采集时刻冻结、防未来天然成立。下午等权用 `breadth.equal_weight_mean_pct`（作用于下午涨跌向量），复用唯一真源、不自算。
- **T+1 α = 次日收盘涨跌% − 次日全A等权 mean_pct**，与盘后复盘同口径同源，直接复用 `data/breadth`。

### 2.3 买入组 / 规避组分别记分 + 分离度

复盘对午盘输出的**两栏**分别记分:

- **买入组**:期望 α 显著为正（选得准 → 下午/次日跑赢基准）。
- **规避组**:期望 α 显著为负（规避得准 → 下午/次日跑输基准）。
- **分离度** = 买入组均值 α − 规避组均值 α，是「这套切分有没有区分力」的核心度量（详见 §4 闸门）。

### 2.4 节点归属与产物（**分叉 D2**:谁来跑）

复盘记分是**纯确定性**计算（收盘价 − 基准，无需 LLM），三个候选:

| 方案 | 描述 | 优 | 劣 |
|---|---|---|---|
| **A. 独立确定性 pipeline 节点（推荐）** | 新增 `tools/pipeline/intraday_review.py` + `tools.run intraday_review`，新 launchd `com.stock.intraday_review` 每交易日 **~15:12** 跑（breadth 15:05 之后） | 与午盘选股同为确定性节点、职责单一、可测试、当日闭环；不依赖 agent 在场 | 多一个 launchd（需用户装 plist） |
| B. 挂到盘后 eod-review agent 会话 | 15:10 的收盘复盘会话里加一节「午盘票复盘」 | 不加定时任务 | eod-review 是 agent 驱动、非确定性、不保证在场；午盘复盘变成「有人跑才有」，不稳定 |
| C. 挂到 `com.stock.breadth` 之后 | breadth 节点尾部串一段午盘复盘 | 不加新 launchd、天然在基准之后 | 破坏 breadth 单一职责；breadth 失败会连带；耦合高 |

**推荐 A**:确定性、可测、当日闭环、与选股节点对称。加 launchd 属于「改定时任务」——**本设计只提议，plist 由统筹/用户来装**（守则:实现窗不碰定时任务）。

**产物路径（分叉 D3）**:
- 候选 A（推荐）:`docs/每日分析/复盘/午盘_<date>.md`（与盘后复盘 `复盘/<date>.md` 并存、不覆盖）。
- 候选 B:并入盘后 `复盘/<date>.md` 追加一节。
- 推荐 A:午盘复盘独立成档，路径规整、web 解析可独立寻址。

### 2.5 记分表结构（与盘后复盘列名兼容）

沿用盘后复盘的**逐票收盘记分表**列名（web 末级回退可直接读），按组分表:

```
## 午盘选股复盘 · 下午 α（当日 11:30→收盘）

### 买入组 · 逐票收盘记分
| 代码/名称 | <date> 下午涨跌% | α vs 全A等权 | 收盘判定 |
|---|---|---|---|
| 000xxx 名称 | +x.xx% | +x.xxpp | ✅/◻️/⚠️ |

### 规避组 · 逐票收盘记分
| 代码/名称 | <date> 下午涨跌% | α vs 全A等权 | 收盘判定 |
| ... |
```

- **列名策略（分叉 D4 — 已可定）**:午盘复盘是**独立档**（`复盘/午盘_<date>.md`），当前无 web 解析器读它，**不与盘后 `复盘/<D>.md` 的解析竞争**。故:
  - 用**语义准确**的列名「`<date> 下午涨跌%`」（不叫「收盘涨跌%」以免误读半日口径）。
  - **α 列保持 web 兼容格式**:列名 `α vs 全A等权`（含「α」+「等权」，满足 `_alpha_col` 口径），值 `+X.XXpp`/`−X.XXpp`（Unicode 负号，同 `_fmt_alpha`）——**这样将来若要把午盘复盘接进 web，α 列可零改直接被读**。
  - **节标题避开「逐票收盘记分」**(盘后表用它、web 按 heading 打分)，午盘复盘用如「午盘选股复盘 · 下午 α 记分」，避免与盘后表竞争选表。
- 追加「组别」信息通过**分表标题**（买入组/规避组）承载，不新增列 → 结构最简、兼容性最好。
- 记分小结（分离度、命中率）写在表下，供经验沉淀消费。

## 3. 输出侧重点重构（短板 B）

### 3.1 从「85 只全序」→「今日可买入 + 今日规避」两栏 + 收敛

现 `render_intraday_md` 输出「午盘候选 · 买入排序（完整分全序，85 只）」。重构为**聚焦三块**:

1. **【今日可买入清单】**（**5 只**，带时效/行动标注 + 简明理由）—— 输出重心
2. **【今日规避清单】**（**3 只**，带规避理由）—— 纠偏参照
3. **（保留）完整候选台账**（折叠在末尾或单独区，全序 85 只不丢，供复盘与审计追溯）

> 保留全序台账的理由:复盘节点要拿「午盘选了哪些票」，且审计/防未来核查需要全量留痕。聚焦只改**呈现重心**，不丢数据。

### 3.2 可买入 / 规避的判定口径（可解释切分规则）

用既有字段组合切分（`完整分`、`消息面方向`、`数据面综合分`），**可解释、可预注册、可回测**。

**已定口径（用户 2026-09-10 拍板 D5）:买入固定 5 只、规避固定 3 只。**
- **今日可买入(5 只)**:`消息面方向 ∈ {看多, 中性}`（**排除看空**）中，按 `完整分` 降序取 **Top 5**。
- **今日规避(3 只)**:优先取 `消息面方向 = 看空` 的票；不足 3 只则按 `完整分` 升序补齐最低分票，凑满 **3 只**。
- **中间大多数**:不进任一栏（**收敛**，正是「聚焦」的关键）。

**定这个小样本(5/3)的用意（用户口径，写死进节点注释与文档，防未来重写时漂移）**:
- **主评价对象 = 买入 5 只**——午盘选股的价值就看「买入选得准不准」。
- **规避 3 只是纠偏参照，不是主指标**——它的作用是「防止模型系统性偏差把烂票也捧上去」，用买入-规避的方向对照来暴露偏差、纠正，而非独立追求「规避得多准」。
- 故 §4 闸门以**买入组绝对表现**为主闸门，规避组/分离度作辅助参照。

### 3.3 时效 / 行动标注

因侧重点是「今日未结束交易日内可买入」，每只买入票带**行动标注**:

| 标注 | 含义 | 触发条件（候选逻辑，待标定） |
|---|---|---|
| **尾盘可买** | 当日下午/尾盘即可建仓 | 完整分高 + 消息面看多 + 数据面趋势/强势类命中 |
| **次日观察** | 今日不追、次日看确认 | 完整分中上 + 消息面中性 / 量能半日存疑 |
| **仅规避** | 明确回避 | 进规避组 |

> 诚实边界:午盘量能仅累计半日（`intraday_screen.py` 已注明），「尾盘可买」不做重量能承诺，标注以价形/趋势/横截面 + 消息面为主。

### 3.4 收益来源与验证假设（为什么午盘这个时点有 alpha）

- **信息增量**:午盘已含「今日开盘 + 上午」的价形/趋势/换手，比昨收多半日信息；消息面三段式在午盘时点回灌当日新闻/情绪 → 捕捉「今日午前发酵、下午延续」的动量与事件。
- **与盘后选股的差异化**:盘后选股 horizon 是「次日」；午盘选股 horizon 是「**当日下午**」，抓的是日内延续性（上午强 → 下午续强 / 上午异动 → 下午规避），是盘后拿不到的时段。
- **可证伪假设**（重心=买入）:**H1（核心）「买入 5 只下午 α 显著 > 0、命中率 ≥55%」**；H2（辅助）「买入-规避分离度 > 0」作纠偏参照。H1 不成立即判午盘买入选股无 alpha；H2 塌陷则回查模型偏差（见 §4）。

## 4. 预注册验证闸门（先定达标标准再评判）

> 项目铁律:先定「怎么算成功」再看结果，别拿「看着合理」下结论（REVS 合成因子就是被预注册闸门证伪的）。以下阈值**在实现前预注册**、写死进复盘节点断言 / 文档。

> 口径重心（D5 拍板）:**买入 5 只是主评价对象，规避 3 只是纠偏参照**。故主闸门押在买入组绝对表现，分离度/规避组降为辅助。⚠️ 5/3 是**小样本**——单日不足以判定，所有闸门都在**滚动多日池化**样本上评。

**主闸门（下午 α horizon，午盘选股的核心价值 = 买入选得准）**:
- **G1 买入组超额（核心）**:滚动窗口内 `mean(买入 5 只 · 下午α) > 0` 且显著为正（普跌日按等权基准算超额，非绝对涨）。
- **G2 买入组命中率（核心）**:买入组「下午 α > 0」占比 ≥ **55%**（池化所有交易日的买入票）。

**辅助参照（纠偏，不作一票否决主闸门）**:
- **G3 方向分离度**:`mean(买入组下午α) − mean(规避组下午α) > +0.30pp`（≥ 项目背离阈值量级）——用来暴露「模型是否系统性把烂票也捧上去」。分离度塌陷 = 有偏差，回查切分，而非直接判失败。
- **G4 多日稳健**:G1/G2 在滚动 **≥ 10 个交易日** 样本上成立（非单日），且不被 1~2 个极端值主导（看买入组中位数 α 同向）。

**硬红线（一票否决）**:
- **R1 防未来**:复盘记分只用 ≤ 结算时点数据;下午 α 的建仓价 = 11:30 冻结价（绝不用盘后回看的午盘价重构）;基准用当日 `data/breadth`，不引入未来日。
- **R2 基准一致**:α 一律 vs 全A等权（下午 α 用下午等权口径，见 D1），不偷换指数口径充数。
- **R3 样本诚实**:停牌/无快照/涨跌停无法成交的票，记分时标注剔除口径，不美化。

**判定**:主闸门 G1~G4 全过 → 该切分口径「验证成功」，可固化；任一不过 → 记录、回到 §3.2 调切分或 §3.3 标注，不宣称成功。首期先跑 **观察期（≥10 交易日）积累样本**，闸门作为「达标线」而非「首日必过」。

## 5. web 展示端兼容（已调研，事实清晰）

web 对 markdown 的解析集中在 `tools/selection_summary.py` + `tools/pipeline/intraday_snapshot.py`（`parse_pick_codes`），由 `web/data_access.py` 调用。**全靠表头列名子串命中，对未知格式一律宽容跳过、不报错。** 关键事实:

1. **侧重点重构（改 `日内全A_<date>.md`）零 web 风险**:`/selection-analysis` 页只读**盘后** `选股/<D>.md`（`selection_summary.build_postmarket_view`，`sel_p = sel_dir/f"{D}.md"`）。`日内全A_<date>.md`（`MD_PREFIX="日内全A"`）**当前无任何 web 解析器读取**——两栏重构、保留/删全序表都不影响 web。
2. **`日内_<date>.md`（盯盘研判，非本轮对象）** 被 `intraday_watch.py` 的 `parse_pick_codes` 读，靠机读锚点 `<!-- PICKS: ... -->` 或「买入排序」节扫码——本轮**不碰**它。
3. **真正脆弱处 = 盘后 `选股/<D>.md` 的「买入建议排序」表**:`_ranking()` 靠子串 `代码`/`名称`|`票`/`表态`|`建议`/`一句话`|`理由` 命中。**本轮不改盘后选股产物**，故无风险。
4. **午盘复盘档若将来接 web**:`parse_review_close_pct`/`_scorecard` 要求「首列含 票/代码/名称 + α 列（含 α 且含 vs/等权）」；新增独立表**不破坏**现有解析（遍历所有表按 heading 打分取最优，`逐票收盘记分`=2 分最高）——只要午盘复盘表 heading **不含「逐票」**、就不与盘后表竞争选表（见 §2.5 已采纳）。

**结论**:本轮**无需改任何 web 解析代码**。午盘复盘表按 §2.5 的兼容列名写即可为将来接 web 留好接口。

# 收盘选股主路径 新闻/LLM 富集并行化（设计）

> 2026-09-09 · 目标：把收盘选股主路径（`screenall`）对候选集的新闻采集 + 三层情绪 LLM
> 从**逐只串行**改成**有界并发**（默认 workers=4），修"选股跑数小时"的新瓶颈。
> ⚠️ 非投资建议，研究模拟。并发只改采集顺序、**不改选股口径/策略**。

## 诊断（根因定位）

- 生产日常收盘选股入口 = `ops/launchd/pull_refresh.sh:85` → `python -m tools.run screenall --no-fetch`
  → `run_screen_all()` → 阶段②候选定向富集 `enrich_candidates(cand_set, ...)`（`tools/run.py`）。
- `enrich_candidates` 里最贵的两步**未传 workers → 默认 1 = 逐只串行**：
  - `collect_message(need_news)`（新闻/舆情/百度个股，网络 IO 型）；
  - `run_sentiment(codes)`（**逐票 `analyze_stock` 跑 LLM，是本路径主耗时**；内部还调
    `news_ai.write_news_ai(codes, workers=...)`）。
  今晚候选集 ~557 只逐只串行 → 富集耗时被拉到数小时。
- 函数本身**早已支持**有界并发：`collect_message(codes, workers=1)` / `run_sentiment(codes, workers=1)`
  的 docstring 明确 >1 时各源/每票在有界线程池并发、原子落盘、结果与完成顺序无关。**只是调用方没传**。
- 并发原语 `tools/parallel.pmap`：`workers<=1` 退串行；结果按输入序回填（与完成顺序无关）；
  `max_workers=min(workers,n)` 有界。等价性/有界/缓存安全已由 `tests/test_并行富集.py` 锁死。

> 注：任务书原指 `tools/run.py:960/965`，那两行实为 `run_two_stage`（`pipeline` 命令，非日常收盘入口）。
> 收盘主路径的真正串行点在 `enrich_candidates`（532/576 一带）。故只改此处，`run_two_stage` 不动。

## 方案

1. **config 开关**（`tools/config/strategy.py` 的 `THRESHOLDS` + 同步 `config/strategy.json`）：
   新增顶层键 `消息面富集.并发数`，**默认 4**（避开 qwen 网关高并发 429；≥1；**=1 一键退回串行** kill-switch）。
   与既有 `消息面回灌.并发数=6`（`candidate_message` 阶段）相互独立、各管各的节点。
2. **接线**（`tools/run.py`）：新增 `_enrich_workers()` 读 config（缺省 4、误配 0/负钳 1），
   `enrich_candidates` 的 `collect_message` / `run_sentiment` 各按 `workers=_enrich_workers()` 传入。
   `news_ai.write_news_ai` 在 `run_sentiment` 内经 workers 参数自动透传，无需单独接。
3. **只改收盘主路径**：不动 `run_two_stage`（pipeline）、`cmd_all`（全A/自选）、`candidate_message`
   （自有 `消息面回灌.并发数=6`）——它们不读本值、仍默认串行不受影响。
4. **正确性**：并发只改"怎么算"、不改"算什么"；各票独立原子落盘、结果与完成顺序无关；
   防未来/口径不变（`analyze_stock`/各 collector 自身按 as_of 锚定）。

## 测试

`tests/test_enrich_candidates.py` 新增 4 用例：workers 按 config 透传（默认4）/ config=1 退串行透传 /
no_llm 下情绪不跑但新闻仍按 config 并发 / `_enrich_workers` 缺省与误配兜底。
并发本身的"并行==串行·有界·缓存安全"复用 `tests/test_并行富集.py`（pmap 层已锁）。

## 提速预估

557 只、串行单只 LLM 富集耗时设为 t：
- 串行 ≈ 557·t；并发 4 ≈ 557·t/4 + 少量线程/汇总开销 ≈ **降到约 1/4**（数小时 → ~小几十分钟量级）。
- 实际受 LLM 网关限流/缓存命中影响；观察到大量 429 就把 `消息面富集.并发数` 调低。

## 风险与回滚

- 峰值在飞 LLM 请求 = 本值 × 每票内 `LLM_EXTRACT_WORKERS`，过高会触发网关 429（client 自带退避）。
  默认 4 为稳妥起点。
- **一键回滚**：`config/strategy.json` 的 `消息面富集.并发数` 置 1 → 逐值等价旧串行路径。

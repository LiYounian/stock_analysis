# Phase-1 闭环产出回写主仓 · 实现说明

> 实现窗（intelligent-maxwell-e49cf0）｜2026-09-10 晚
> 依据设计：`docs/计划/2026-09-10_选股读不到闭环产出_修复设计.md`（统筹拍板 Phase-1=方案B）
> 免责：工程可靠性修复，非投资建议。

## 1. 一句话

闭环从 dailyjob worktree 跑、产出写在 dailyjob（`settings.PROJECT_ROOT=代码所在=dailyjob`），
主仓消费者（选股门控/eod-review/web）读主仓 → 读不到 → 选股天天误跳过。
Phase-1 在**闭环已调用的 python 步骤末尾**把当日产出**原子回写主仓**，恢复"主仓=消费侧单一真源"不变量。

## 2. 落点（关键：随 dailyjob 每轮 reset --hard origin/main 自动部署）

- 新增模块 `tools/sync/mirror_to_main.py`，函数 `mirror_daily_to_main(date)`。
- **挂进 `tools/sync/upload.py::main()` 末尾**（在回执落盘 + pool_ack 处理之后、return 前），best-effort try/except 包裹，失败只告警不破上传。
- 闭环 `pull_refresh.sh` ③/③补齐两轮都调 `python -m tools.sync.upload`，故 main() 每轮结束都回写；
  **最后一轮(--pool-ack)= 闭环最后一个 python 步** → 回写带上最终 receipt。
- ⚠️**不新增 pull_refresh.sh 的 bash 行**——wrapper 改动本项目不自动部署；放 python 步则随 reset 自动生效。

## 3. 主仓根定位（不用 PROJECT_ROOT）

优先级：显式参数 > env `STOCK_MAIN_REPO` > `data/master` symlink 目标的祖父目录（dailyjob 生产场景：
`data/master` 是指向主仓 `.../stock_analysis/data/master` 的 symlink）> 默认 `/Users/yqg/Documents/projects/stock_analysis`。
**源==目标（在主仓自身跑）→ no-op**，不自拷自。

## 4. 回写内容与顺序（原子 + receipt 最后）

1. `data/analysis/<D>/` 整目录（策略视图 + per-stock json + `market_forecast.json` + `估值位监控.json` + 告警 marker）——**逐文件 temp+os.replace 原子拷**。该日目录 0 个 git 跟踪文件，纯未跟踪 churn，安全。
2. `data/analysis/backtest/*forward_scorecard*.csv`（scorecard 滚存，均未跟踪）——同款原子拷。
   **绝不整目录拷 backtest**：该目录有 23 个已跟踪 fixture（eval_v3.json / calib_*.json…），拷过去会脏主仓跟踪文件、挡 ff-only。只拷 `*forward_scorecard*.csv` 精确避开。
3. `data/sync_receipts/<D>.json`——**最后写**，原子。它是选股门控"就绪信号",保住"receipt 存在⟹analysis 全套就位"语义。

原子性靠：每个文件 temp+`os.replace`（消费者不会读到写一半的文件）+ receipt 全局最后落。

## 5. git 安全

只 copy 文件，**绝不 git add/commit/symlink**。当日 daily 目录在主仓本就未跟踪，拷过去仍未跟踪。

## 6. 测试（tests/test_mirror_to_main.py）

锁语义：① analysis+receipt 落到主仓目标；② receipt 最后写（用 mtime/调用序断言）；③ 源==目标 no-op；
④ 只拷 *forward_scorecard*.csv、不碰 backtest 里其它文件；⑤ 逐文件原子(临时文件不残留)；⑥ 不产生 git 变更。

## 2. 结构(先框架后实现)

新增独立包 `tools/scheduling/`(与旧 `tools/scheduler.py` 并存,不动旧模块,P3 再决定替换):

```
tools/scheduling/
  __init__.py
  models.py       # TaskSpec / NotifyEvent dataclass;schema 校验(fail-loud)
  registry.py     # load_registry(path)->list[TaskSpec];热重载(mtime diff)
  tasks.yaml      # SSOT 声明式任务表(上表 9+ 条,cron/timeout/retries/notify_on/enabled)
  notifier.py     # Notifier 接口 + LogNotifier(默认) + WebhookNotifier(飞书/钉钉/通用) + build_notifier()
  runtime.py      # build_scheduler(registry, notifier, dry_run):包装 锁/超时/重试/misfire/告警;心跳;热reload
  __main__.py     # CLI: validate / list / next / run [--dry-run] / heartbeat
```

- **注册表 schema**:`{id, cmd(argv list), cron, timeout_sec, retries, retry_backoff_sec, depends_on[], notify_on[failure|misfire|success], enabled, tags[], description}`。
- **凭证**:notifier 配置只存 env **变量名**(如 `webhook_url_env: STOCK_ALERT_WEBHOOK`),运行时从 env 解析;值绝不入库。
- **dry-run/影子**:runtime 支持 `dry_run=True` —— 到点只 log "would run <cmd>",不 Popen、不真跑;
  用于与 live launchd 并行观察一致性,零生产副作用。
- **告警口径**:job wrapper 捕获 失败(非0退出/异常/超时)→ `notify_on` 含 failure 则发;
  misfire(APScheduler misfire 事件)→ 发;心跳 job 定期发"存活"。

## 3. 测试(锁语义)

`tests/test_scheduling_framework.py`:
1. 注册表解析:合法 YAML → TaskSpec 列表;非法(缺字段/坏 cron)→ fail-loud 抛错。
2. 热生效:改 cron 后 reload → job trigger 变更、replace_existing 生效。
3. 告警触发:mock notifier,任务抛异常/超时 → 收到 failure 事件;misfire → 收到 misfire 事件;成功且 notify_on 无 success → 不发。
4. misfire/coalesce/max_instances=1 参数正确注册。
5. **dry-run 不执行**:dry_run 模式下 mock 的命令执行器零调用(锁死"影子不碰生产")。
6. 凭证脱敏:WebhookNotifier 从 env 变量名解析、缺失 env 时 fail-soft 记日志不崩、不打印明文 url。

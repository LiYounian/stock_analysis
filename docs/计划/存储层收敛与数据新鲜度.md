# 计划:存储层收敛 + 数据新鲜度 + 采集健壮性

> 状态:✅ 已完成(2026-08-06,合并至 main 87485fa,165 测)· 依据"三块答案复盘"识别的可优化点。
> 遗留:load_X 尚未接入 `is_stale` 告警(API 就绪,见工程进度待做);全量跑一轮验证 meta sidecar 真实落盘。
> 一句话:把 `store` 层从半死代码扶正为**唯一落盘/读盘入口**,顺带补齐**采集元数据(新鲜度)**、**原子写**,再各自加 **UGC 时间窗**、**政策备源**。

## 背景(为什么做)
复盘采集/存储三块,核实后确认的真问题:
1. **存储双轨**:`store/repo.py` 已建(13 测)但 collectors **零调用**,各自拼路径直写 → `kind→格式` 映射双份、store 沦为半死代码。
2. **raw 无采集元数据**:落盘只有数据、无 `fetched_at/source` → `load_X` 盲读,分析可能用陈旧数据不自知。
3. **UGC 无时间窗**:news 按 cutoff 裁,ugc 只取最新 N 帖不看跨度 → `heat_score` 跨票不可比。
4. **新闻/政策单点**:全押东财 `stock_news_em`,无备源。
5. **非原子写**:直接覆盖,崩溃/并发产生半截文件。
（政策去重、LLM 缓存 key 复核后**无问题**,不改。）

## 分两拨执行(文件边界)
### 拨一 · 存储地基(主窗口单写者先做,是拨二的共同底座)
改 `store/repo.py` + `config/settings.py` + `tests/test_store.py`:
- **原子写**:`_write_json` / `put_raw`(parquet)/ `put_view` 一律"写 `.tmp` → `os.replace`"。
- **采集元数据 sidecar**:`put_raw(kind, code, payload, meta=None)` 旁写 `{code}.meta.json`,含 `fetched_at`(自动)/`source`/`rows`。
- **新鲜度 API**:`get_raw_meta` / `raw_age_days` / `is_stale(kind, code, max_days)`;`settings.RAW_STALE_DAYS`。
- 验收:store 全测绿 + 新增原子/元数据/新鲜度断言。

### 拨二 · 采集器接入(拨一落地后并行起 3 个 subagent,文件互斥)
| Agent | 拥有文件 | 做什么 |
|---|---|---|
| A | market/fundamental/announcement/fundflow/news.py | 落盘/读盘改走 `store.put_raw(...,meta={"source":..})` / `store.get_raw`,删私有 `_path`;公开 `fetch_/load_` 签名不变 |
| B | ugc.py | 同上迁移 + **加时间窗 cutoff**(对齐 `NEWS_LOOKBACK_DAYS`)+ `heat_score` 归一每日 |
| C | policy.py | 同上迁移 + **补 `news_cctv` 备源**(东财失败时回落) |

## 预期效果(改完应看到)
- collectors 里 `grep store.put_raw` 有命中、私有 `_path` 消失;`kind→格式` 只在 store 一处。
- `data/raw/{kind}/{code}.meta.json` 出现,带 `fetched_at/source`。
- `store.is_stale("kline","000021",3)` 对陈旧/缺失数据返回 True。
- ugc 帖子受时间窗约束、heat 跨票可比;政策在东财挂时能走备源出数。
- 全量 `pytest tests/ -q` 绿,无回归。

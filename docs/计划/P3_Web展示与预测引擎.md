# P3 · Web 展示 + 选股筛选 + 预测引擎(计划)

> 状态:**待审阅** · 编写 2026-08-05
> 选型(用户拍板):Web = **FastAPI + Jinja2 + Chart.js**;预测 = **先统计后 ML**(两者都要,分阶段)。
> 目标:一个可本地部署、后续可上服务器的 Web,展示每日新闻/利好利空、选股筛选、1/5/10 日预测、止盈止损位。

---

## 0. 诚实性边界(必须先立)

- **股价不可被可靠"预言"**。本系统的"预测"= 基于历史数据的**概率化情景**(上涨概率 + 预期波动区间),不是点位保证。
- **止盈止损**= 基于 ATR + 支撑压力位的**规则化建议区间**,非承诺。
- Web 所有预测/筛选处**显著标注**:"仅供参考,非投资建议,据此交易风险自负"。
- 方法**透明可回测**:每个预测都能追溯到输入信号,不做黑箱玄学。

---

## 1. 整体数据流(在现有基础上扩展)

```
collect(行情/基本面/公告/资金流) → analyze(技术/拐点/基本面/公告)
        → aggregate(综合评分+筛选) → predict(支撑压力/止盈止损/情景区间)
        → 落 data/store/*.json → Web 读取渲染
```

Web 不直接算,只读**预生成的结构化数据**(离线 `run.py` 刷新)——响应快、可定时、部署简单。

## 2. 子阶段拆解

### P3-A · 资金流采集 `collectors/fundflow.py`(curl_cffi 东财)
| 函数 | I/O |
|---|---|
| `fetch_fundflow(codes, days)` | curl_cffi 伪装 chrome 直连东财 fflow 接口 → `{code: DataFrame[date, 主力净流入, 超大单, 大单, 中单, 小单, 主力净占比]}`,落盘 |
| `load_fundflow(code)` | 读缓存 |
- 派生指标:近 5 日主力净流入合计、主力净流入连续天数、今日主力净占比。

### P3-B · 综合聚合与选股 `analysis/portfolio.py`(填现有 stub)
| 函数 | I/O |
|---|---|
| `aggregate(all)` | 融合 技术评级 + 拐点评分 + 基本面 + 公告方向 + 资金流 → 单票综合画像 + 板块聚合 |
| `screen(all, filters)` | 多维筛选:如"拐点启动 + 主力净流入 + 非高估" → 选股结果列表 |
| `pick_focus(all, rule="hybrid")` | 重点票(技术异动 + 资金流 + 公告事件综合) |

### P3-C · 预测/推荐引擎(统计版)`analysis/predict.py`
| 产出 | 方法(透明) |
|---|---|
| **近三次放量定位** | 找最近 3 个放量日(量比>阈值)及其价位 → 供支撑压力与主力成本参考(需求明确要) |
| **支撑/压力位** | 近 N 日 swing low/high + 近期密集成交价区 + 放量位 |
| **止损位 / 止盈位** | 按持有期各给:止损 = 入场 − k×ATR(或最近支撑下方);止盈 = 入场 + m×ATR(或压力位)。k/m 可配 |
| **1/5/10 日情景区间** | 基于近期波动率给 ±1σ 区间 + 历史相似形态上涨频率(经验概率) |
| **买卖倾向推荐** | 综合超买超卖 + 拐点 + 资金流 → 偏买/偏卖/观望 + 依据 |
| **推荐金额(仓位)** | ⚠️ 口径待定(需求 N3):基于总资金 + 风险偏好反推(如单笔最大亏损 = 总资金×r%,仓位 = 风险额/(入场−止损))。**接口先留,待用户给总资金/风险偏好** |
| **风险收益比** | (止盈−入场)/(入场−止损) |
- 输出契约:`predict(kline, tech, capital=None, risk=None) → {近三次放量[], 支撑位[], 压力位[], 各持有期{止损, 止盈, 推荐仓位/金额}, 买卖倾向, 情景:{1/5/10日:{涨概率, 下沿, 上沿}}, 风险收益比}`
- 明确不做点位预测;区间基于波动率,概率基于历史频率;推荐金额在 N3 明确前只出"占位/需参数"。

### P3-D · Web 应用 `web/`(FastAPI + Jinja2 + Chart.js)
```
web/
├── app.py            # FastAPI 入口 + 路由
├── data_access.py    # 读 data/store 与报告数据
├── templates/        # Jinja2:base / dashboard / screen / stock / news
└── static/           # css + Chart.js + 少量 js
```
页面:
1. **首页 Dashboard**:今日组合情绪温度、板块强弱、异动/拐点榜、重要公告、资金流 Top。
2. **选股页**:多维筛选结果表(可按拐点/资金流/评级排序)。
3. **个股页**:K线图(Chart.js,叠加均线/支撑压力/止盈止损线)+ 技术/基本面/公告/资金流 + 预测情景区间。
4. **新闻页**:每日事件 + 相关股票 + 利好/利空。**现在**用公告(公司行为已有方向);**新闻正文级**待 P2-C LLM。

### P3-E · ML 预测 + 回测(后置,第二阶段)
- 特征:技术指标 + 资金流 + 形态标签;标签:未来 n 日收益(分类涨跌 / 回归幅度)。
- **回测框架先行**(防过拟合自欺):时间序列切分、样本外验证、与统计版对比基准。
- 装 scikit-learn/scipy;模型从简单(逻辑回归/GBDT)起步。
- ⚠️ 只有回测显著优于统计基准才上线,否则保留统计版。

## 6. 风险 / 依赖
- curl_cffi 伪装若失效(东财升级反爬)→ 资金流降级为量价代理指标(放量/量比),不阻塞。
- 统计预测的"概率"是历史频率,非未来保证——文案与代码注释都要讲清,避免误导。
- 新闻页完整能力(正文利好利空)仍依赖 P2-C 的 LLM(Q7)。
- ML 阶段过拟合风险 → 回测框架先行,样本外为准。

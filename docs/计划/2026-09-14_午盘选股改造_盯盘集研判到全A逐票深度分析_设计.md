## 1. 现状核查（已读代码/日志/产物，结论）

### 1.1 两条午盘流水（并存，职责不同）
| 节点 | 类型 | 触发 | 产物 | 深度 |
|---|---|---|---|---|
| `tools/pipeline/intraday_screen.py` | **launchd** `com.stock.intraday_screen` | 工作日 **11:32**（RunAtLoad=false，5 个 Weekday） | `docs/每日分析/选股/日内全A_<date>.md` | 程序化、lean、浅（事件标签+情绪+分数），**无逐票深度** |
| `daily-stock-noon-analysis`（SKILL） | **Claude 定时任务**（桌面 App） | 午休 ~11:45 | `docs/每日分析/选股/日内_<date>.md` | 深，但**只盯盘集 ~19**（要改的就是它） |

- 盘后母本 `daily-stock-selection` = 深度 SOP 参照（定性→数据层→消息面→交叉→深度预测含α/β→我vs系统→⑦退出⑧方向前提⑨盯点单问化）。
- launchd **不受桌面 App 挂起影响**；Claude 定时任务**会漂移数小时**（经验 #16，09-03 曾漂 3h16m）——**这是本改造 13:00 可行性的头号风险，见 §4**。

### 1.2 候选源：机读候选**已存在**（关键发现）
`intraday_screen` 每轮产出里已有充分机读候选，Claude 深度分析可直接消费：
- **`日内全A_<date>.md`**（`MD_PREFIX="日内全A"`，noon 冻结、close 不覆盖）内含：
  - `## 今日可买入`（Top-5，主评价对象）+ `D-0 交易计划`（ATR/振幅锚定的止损/止盈/了结）
  - `## 今日规避`（Top-3，纠偏参照）
  - **`<details>完整候选台账`**：全序 ~85 只，每只带 `完整分 / 数据面综合分 / 消息面方向 / 消息面分 / 候选来源 / 理由`。
- **`data/analysis/<date>/候选池消息面确认.json`**（view「候选池消息面确认」的 `重排`）：**同数据的结构化版**，
  但**路径与收盘 `run_screen_all` 共享 → 收盘会覆盖**（09-14 该文件 mtime 12:42 是午盘版，16:05 已被收盘覆盖）。
  午盘 live（11:45~13:00，收盘前）读到的是午盘版，但**post-hoc/复盘/验证不可靠**。
- `data/intraday/<date>/noon_screen_snapshot.json`：全A 11:30 冻结快照（price/open/pct_chg/turnover），noon 冻结、不入库、不覆盖。

### 1.3 时间实测（09-14，真实 launchd 单轮）
| 时刻 | 事件 | 证据 |
|---|---|---|
| 11:32:10 | launchd 触发、run 开始 | 日志 wrapper `$(date)` 行 |
| 11:32:53 | 11:30 全A快照落盘（run 早段） | `noon_screen_snapshot.json` mtime |
| **12:42:19** | **阶段2 消息面回灌完成、候选池 md/json 落盘（≈整轮结束）** | `候选池消息面确认.json` mtime + 日志尾 + 日志文件 mtime 12:42 |

→ **`intraday_screen` 全量候选池（含阶段2 LLM 消息面）~11:32→12:42 ≈ 70min**。阶段1（数据初筛 lean）约「十几分钟」（~11:50 就绪），阶段2（candidate_message 对 ~50-85 shortlist 跑 LLM）约 50min 是慢的大头。

## 2. 设计决策（请统筹审 / 必要时报用户）

### D1 · 候选源接线：加**轻量机读旁路 JSON**（推荐），SKILL 优先读它、回退解析 md 台账
- **方案对比**：
  - A) SKILL 直接解析 `日内全A_<date>.md` 完整台账表 → **零代码改动**，但 markdown 解析较脆。
  - B) **加旁路 JSON（推荐）**：在 `intraday_screen` 末尾**额外**落 `data/intraday/<date>/noon_candidates.json`
    （= `view["重排"]` 全序 + 买入/规避切分 + breadth + as_of + freeze_label）。**noon 冻结、独立文件名、close 不覆盖、gitignored、不碰主档**；机读稳、可复现、留审计痕。
  - C) 读共享 view json `候选池消息面确认.json` → **收盘覆盖、不可靠**，否决。
- **推荐 B**，且 SKILL 设计为「优先读旁路 JSON，缺失回退解析 `日内全A_` 台账」→ 双保险，任一在即可跑。
- **B 的实现边界（铁律）**：只在 `run_intraday_screen` 末尾**追加一个 `persist_noon_candidates()` 旁路调用**
  （复用已读的同一 view），**不动阶段1/阶段2 主逻辑**、不改评分、不改现有产物。加开关 `persist_candidates=True` 便于测试关。

### D2 · 新午盘 Claude 产物写哪个文件名
- **推荐**：新午盘深度产物**继续写 `日内_<date>.md`**（沿用当前 noon SKILL 的文件名），`日内全A_` 保持为
  `intraday_screen` 的候选池源。语义变化：`日内_` 从「盯盘集研判」变为「全A候选池 Top-N 逐票深度」。
- **下游影响（统筹换线前必须核）**：`intraday_watch.py` 经 `intraday_snapshot.parse_pick_codes` 读
  `日内_<date>.md` 的 **`<!-- PICKS: ... -->` 锚点**识别当日盯盘候选。改造后 PICKS = 全A午盘**买入票**（而非盯盘集）
  → 下午 watch 监控对象随之变成午盘买入票。**这是期望的新行为**，但**换线时统筹须确认 watch 语义可接受**。
  SKILL 硬要求**保留 PICKS 锚点**（否则 watch 取空）。
- 备选：新产物写全新文件名（如 `日内深度_<date>.md`）避免与旧语义混淆——但会断开 watch，需同步改 watch（超出本线范围）。**默认走推荐案**。

### D3 · 深度分析消费哪个候选阶段（决定 13:00 可行性，见 §4）
- 候选池「完整分」排序依赖阶段2（~12:42 才就绪）→ 若等全量，Claude 深度窗口只剩 ~12:42→13:00 ≈ 18min，**赶不上**。
- **Claude 深度 SOP 本就自跑消息面（baidu_news+WebSearch）**，不必依赖 intraday_screen 的阶段2 LLM 消息面。
  → **可门控在「阶段1 数据初筛就绪（~11:50）」即开工**，按**数据面综合分**排序取 Top-N 深挖，自做消息面。
- 但排序质量：阶段1 只有数据面分（无消息面回灌）。**权衡**：早开工（阶段1，~11:50，窗口足）vs 排序更全（阶段2，~12:42，窗口紧）。
  **推荐**：SKILL 有界等待——**优先等阶段2 全量候选（旁路 JSON 存在即用），但设「≤12:20 仍无全量→降级用阶段1/上一版就绪候选，自做消息面」的 fallback**，兼顾质量与 13:00。

### D4 · 深度范围与只数
- **范围 = 全A候选池 Top（买入组 5 只为主评价对象 + 可扩看 Top-8~10 台账挑检验样本）**，**彻底不含盯盘集/自选**
  （自选若恰好进候选池 Top 属正常，按候选源身份对待，不做「自选」特殊逻辑）。
- **逐票深挖聚焦 ~5 只**（对齐母本 3~5 只 + 时间预算），每只走完整深度 SOP。

## 3. 新午盘 SKILL 草案结构（写 repo `docs/参考/` 留痕；**不写 ~/.claude live**）

草案文件：`docs/参考/午盘选股SKILL草案_daily-stock-noon-analysis_v2.md`（本线产出②）。骨架：

1. **角色 + 铁律**：午盘全A深度分析师；防未来 ≤11:30 冻结；半日 bar/量能按半日语境读；非投资建议；绝不反问。
2. **第0步·门控（硬）**：
   - `date` 确认交易日；非交易日退出。
   - **候选就绪门控**：有界轮询等 `intraday_screen` 当日候选（旁路 JSON 或 `日内全A_<date>.md`）就绪；
     ≤12:20 无全量→降级用阶段1/最近就绪候选并显式标注（D3）。
   - **时点自证**：写触发/执行/采集三时刻；漂移>阈值必标「哪个维度因漂移未检验」（经验 #16）。
3. **第1步·方法依据**：读最新 `经验沉淀/v<date>.md` + `docs/计划/每日选股分析机制.md`；α 基准=全A等权唯一真源。
4. **第2步·市场环境（β 背景）**：读 `market_forecast.json`（缺则用候选池 breadth + 自拉指数）→ 定性偏多/偏空/震荡；偏空日买入表态整体降级、标 β 风险。
5. **第3步·选 Top-N**：从候选池买入组 + 台账，按①完整分/数据面分②多策略命中③多样化，选 ~5 只，标类型（买入候选/检验样本），必须有真买入候选。
6. **第4步·逐票深度（对齐母本，每票必填）**：
   定性分票 → 数据层（noon snapshot + noon per-stock json + 候选池 数据面分/理由；**半日量能语境**）→
   消息面（强制 baidu_news + 必要 WebSearch，锚定 ≤当日午盘；情绪质量 unknown/missing 不给最强表态、不把 0/null 当中性）→
   数据×消息面交叉 → 深度结论：①买入/可参与/观望/规避（不对冲）②当日情景③1日方向+置信（下午 horizon 为主）
   ④α/β 拆分（β 读 market_forecast，基准=全A等权；盘中只定性、妖股不写方向盖棺 #17/#24）⑤我vs系统
   **⑦退出/止盈纪律**（D-0 定位：ATR/振幅锚定止损/止盈 + **当日收盘无条件了结** + 涨停封板卖不出处理；可复用候选池 D-0 交易计划表）
   **⑧方向前提=触发信号**（触发未现只给「低波动待动」；高波动票加跳空作废保护 #20；超跌反抽闸门别一律设 MA5 #31）
   **⑨盯点单问化**（每条可独立判定、复合拆两问）。
7. **第5步·产出 `日内_<date>.md`**：
   开头写数据时点（11:30 冻结）+ 范围（全A候选池 Top-N，**非盯盘集**）+ 非投资建议 +（如降级）阶段/漂移标注；
   市场环境 → 逐票深度 → **今日可买入排序表（明确表态 + 关键价位 + D-0 止损/止盈/了结）** → 遇到的问题。
   **机读锚点（硬）**：文件第一行 `<!-- PICKS: 买入票6位代码,... -->`（保 watch）；跳过则 `<!-- PICKS: none -->`。
8. **纪律**：只读代码/数据、只写 `docs/每日分析/选股/日内_<date>.md`；不 git、不改代码、不改定时任务；时间紧、高效、赶 13:00。

## 4. 时间 / token 预算 + 13:00 可行性结论（deliverable ③）

### 4.1 候选源时间（launchd，免漂移）
- 阶段1 数据初筛就绪 ~**11:50**；全量候选池（阶段2）就绪 ~**12:42**。候选源本身**能在午盘窗口内产出**、免桌面漂移。

### 4.2 Claude 深度预算（估）
- 聚焦 ~5 只，每只：数据层读取 + baidu_news/WebSearch + 交叉 + 深度结论 + 退出/盯点。
- **token 估**：input ~150K~300K（经验沉淀最新版大 + 候选池 + per-stock json + 消息面），output ~15K~30K；单轮量级。
- **agent 工时估**：~15~30min（含 LLM 往返 + baidu_news/WebSearch 采集 + 渲染）。→ 端到端手跑将实测校准（§5）。

### 4.3 13:00 可行性结论（**诚实**）
- **两大风险**：
  1. **候选全量 ~12:42 就绪 → 只剩 ~18min**，5 只深挖赶不上 13:00。**缓解**：D3 门控在阶段1（~11:50）就绪即开工、自做消息面 → 窗口拉到 ~70min，可行。
  2. **头号风险：Claude 定时任务漂移**（桌面 App 非活动时挂起数小时）。若 noon 任务本身不在 11:45~12:00 触发，则**无论候选多快都保证不了 13:00**。母本 selection 能容忍漂移（盘后无硬 deadline），**午盘有 13:00 硬 deadline → 漂移是结构性冲突**。
- **结论**：**候选源侧 13:00 可行（launchd 免漂移，阶段1 ~11:50 就绪）；Claude 深度侧「若按时触发」~15~30min 可卡进 11:50~13:00 窗口。但只要 Claude 定时任务漂移，13:00 无法保证。**
- **给统筹/用户的选项（换线前定）**：
  - (a) 维持 Claude 定时任务，**best-effort 13:00**：按时触发则出可操作午盘选股；漂移则产「迟到/次日向」产物 + 诚实时点标注（当前母本模式）。
  - (b) **改由 launchd 触发 headless Claude**（仿 `intraday_screen.sh` wrapper），免漂移、真保 13:00——**基建改动，超本线范围，供统筹/用户决策**。
  - (c) 压缩深度（3 只 / 更轻 per-stock）以适配残余窗口。
  - **本线推荐**：SKILL 按 (a) 写（best-effort + 门控 + 时点自证），并在草案里显式建议统筹评估 (b)。

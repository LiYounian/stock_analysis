# 采集器静默失效三修 — 截断/陈旧/漏召从静默变有声

> 分支 `fix/collectors-silent-invalid-data`(基于 origin/main)。三处同一类病:
> **把不可信数据当有效返回、永不告警**。核心不是"补全数据",而是让不可信状态**有声**
> (显式标记 + 日志告警),下游不再把"截断/陈旧/漏召"误读成"无信号"。

## 诊断(均已实证复现,conda env `stock_analysis`)

### #26(高)大宗交易 5000 行静默截断 — `smart_money._fetch_block_market`
- akshare `stock_dzjy_mrmx` **硬编码 `pageSize=5000, pageNumber=1`、sortColumns=SECURITY_CODE**,
  命中 5000 即静默截断(只返回代码排序靠前的 5000 行,高位代码如 300857 被切掉)。
- 实证:`('20260301','20260903')` 返 **恰好 5000 行 → 300857 = 0 笔**;
  窄窗 `('20260801','20260903')` 返 2438 行 → **300857 = 4 笔**。
- `fetch_smart_money` 默认 `days=90` 正落在截断区 → 宽窗拿到假的"无大宗交易"。

### #27(高)百度新闻静默陈旧 — `baidu_news`
- `skip_fresh` 门控只看 `store.is_stale`(采集时刻 `fetched_at`),**从不看条目发布日期**。
- 只要今天拉过(fetched_at 新鲜),哪怕最新条目落后几十天也永不告警。
- 结构性缺陷(与今日返回是否恰好陈旧无关):**新鲜度判据缺"最新条目日期"这一维**。

### #29(中)财联社漏召 — `news._fetch_cls`
- 根因是**覆盖太薄**而非"名字没匹配":akshare `stock_info_global_cls` **硬编码 `rn=20`**,
  只返回全市场**最近 20 条**电报快照,对任一具体票按名过滤≈恒为 0。
- 且 300857 不在 stock_pool → `name=""` → `_fetch_cls` **静默返回 []**(盲区当"无风险")。
- 把"0 条"当"无快讯风险"会误判。

## 修法(预期效果)

### #26 递归缩窗 + 命中上限告警
- 新增 `_BLOCK_PAGE_CAP=5000`;`_fetch_block_market` 改为**按日期二分递归缩窗**:
  单窗命中 ≥ 上限 → 折半日期区间分别重取(子窗互斥无重叠、拼接即全量),
  每次缩窗 `logger.warning` 一次(有声);单日仍命中上限=不可再分 → `logger.error`
  并标 `df.attrs['truncated']`(接受当日截断但**响亮告警**,绝不静默)。
- 预期:宽窗 `days=90` 对 300857 恢复到 4 笔(与窄窗一致),日志出现"命中上限二分重取"。

### #27 最新条目日期新鲜度 + 显式标记
- 新增 `_newest_item_date` / `content_stale_days`;`fetch_baidu_news` 落盘 meta 增
  `newest_item_date` / `item_stale_days` / `content_stale`(bool),陈旧超阈值 `logger.warning`。
- 阈值 `settings.BAIDU_NEWS_ITEM_STALE_DAYS`(默认 14 天,可 env 覆盖)。
- 呼应"情绪打分失败三态":缺失/陈旧不得静默当有效。
- 预期:最新条目落后 >14 天的票,meta.content_stale=True 且日志告警。

### #29 盲区/薄覆盖有声 + 匹配归一
- `name` 缺失(不在池/无名)→ `logger.warning`(盲区:无法按名过滤),不再静默 [];
- 记录 feed 覆盖下界(最旧条目日期),`cutoff < 覆盖下界` → `logger.warning`("覆盖仅
  最近快照,0 条≠无风险");名字匹配做 `strip` 归一。
- 预期:0 条时日志明确区分"确无"与"覆盖不足/盲区无法判定"。

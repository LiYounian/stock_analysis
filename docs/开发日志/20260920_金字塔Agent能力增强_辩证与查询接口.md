## 目标与用户拍板的边界

诉求三条:①强化工具与信息获取 ②培养辩证思考 ③把本地已有分析成果转成"固定查询方式"(MCP 式:固定格式+固定地点+告知能查什么,不部署服务)。

关键边界(用户 AskUserQuestion 拍板):
- **开深度不开广度**:放开辩证/查证/我vs系统出入,但**仍守金字塔骨架 top-N 池边界**(不重新召回、不加塞池外票、数值一律程序算)。金字塔当初"闭卷"是为独立性/可复现,辩证=证据链内质疑,不是抛开骨架自由发挥。
- **DeepSeek/千问 先走乙案**(决策包加厚,不给 function-calling)后评估;甲案(function-calling)留待评估后定。
- 三个模型能力落差是结构性的(Claude Code 会话有 Read/Bash/WebSearch;DS/千问 headless、联网难给)——目标是"各按能力上限拉满 + 明确分层",非强行拉平。

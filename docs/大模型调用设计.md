## 0. 一句话总览

数据层(行情/基本面/技术指标)**纯代码,不用 LLM**;LLM 只用在**文本/情绪侧**:
从新闻里**抽关键信息**、给文本**打情感/判影响方向**、把政策/舆情**归纳成结论**。
所有调用走**一个统一客户端 `tools/llm/client.py`**,provider 可插拔(用户 API / qwen 二选一或混用)。

## 1. 哪里需要 LLM(触点清单)

| # | 触点(模块) | 任务 | 输入 → 输出 | 调用类型 | 量级/频率 | 可否外包 qwen |
|---|---|---|---|---|---|---|
| L1 | `analysis/event.py`(新闻/公告关键信息提取) | 从新闻/公告正文抽结构化事件 | 文本 → `{事件类型, 涉及主体, 金额/数字, 时间, 影响方向}` | **结构化抽取**(JSON) | 中(每票每日数条) | ✅ 适合 |
| L2 | `analysis/sentiment.py`(情感打分) | 判文本利好/利空/中性 + 分值 | 文本 → `{score:-1~1, label, reason}` | **结构化抽取**(JSON) | **大**(新闻+研报+UGC 批量) | ✅ 最该外包 |
| L3 | `collectors/policy.py` 配套解读 | 政策新闻 → 影响哪些行业/方向/强度 | 政策文本 + 行业列表 → `{受影响行业, 方向, 强度, 依据}` | **结构化抽取**(JSON) | 小(每日数条) | ✅ 适合 |
| L4 | `analysis/event.py`(舆情/大V观点归纳) | UGC 一堆帖 → 观点倾向 + 热点摘要 | 多条文本 → `{主流观点, 多空比, 争议点}` | **归纳/摘要** | 中 | ✅ 适合 |
| L5 | `analysis/portfolio.py`(主线归纳,可选) | 组合层结构化结果 → 一句话主线判断 | 统计数据 → 自然语言主线结论 | **归纳/摘要** | 极小(每次1条) | 可自己做 |
| L6 | `report/builder.py`(报告叙事,可选) | 结构化结果 → 人话报告段落 | 结构化数据 → Markdown 叙述 | **归纳/摘要** | 小 | 可自己做 |

**优先级**:L1/L2 是刚需(用户强调的"从新闻提取关键信息 + 文本分析");L3 次之;L4~L6 是增强项。
**成本大头**:L2 情感打分(全量文本批处理)→ 默认走 qwen 外包(约法第 10 条),不烧主 API 额度。

## 2. 两种调用模式

| 模式 | 用于 | 要点 |
|---|---|---|
| **结构化抽取**(structured) | L1/L2/L3 | 强制模型只输出 JSON(给定 schema);解析失败**抛错重试**,不静默返回空(约法第 5 条,防"静默截断漏报") |
| **归纳/摘要**(freeform) | L4/L5/L6 | 输出自然语言;对格式要求松 |

## 3. 统一接口设计(`tools/llm/client.py`)

**抽象:一个协议 + 可插拔实现,业务层只依赖抽象,不关心是哪个 provider。**

```python
class LLMClient(Protocol):
    def chat(self, messages: list[dict], *, temperature: float = 0.0,
             max_tokens: int = 2048) -> str: ...
    # 结构化抽取:内部拼 prompt + 强制 JSON + 解析校验 + 失败重试
    def extract(self, text: str, schema: dict, *, instruction: str,
                temperature: float = 0.0) -> dict: ...
    # 批量抽取:分批(见 settings.QWEN_BATCH_SIZE),省往返
```

## 4. 结构化抽取的健壮性(关键,锁进测试)

1. **强制 JSON**:prompt 明确"只输出 JSON,无多余文字";优先用 provider 的 JSON mode(若支持)。
2. **解析失败抛错重试**:最多 `LLM_MAX_RETRY` 次;仍失败则该条标 `error` 落盘(可见、可重跑),**绝不静默返回空**。
3. **schema 校验**:抽取结果按预期字段校验,缺字段视为失败。
4. **降级**:LLM 整体不可用时,情感/事件字段标 `unknown`,流水线继续跑(数据层不受影响),报告注明"情绪分析缺失"。
5. **缓存**:抽取结果落 `data/raw/llm_cache/`,改下游逻辑时免重复调用(参考既有项目"抽取结果缓存 + 重算"经验)。

## 0. 读者须知：财报行业专家子系统怎么运转（公共背景）

### 0.1 它解决什么问题

财报数值分析（增速/盈利质量/健康/运营/回报五维 + 红旗排雷）如果用**一套跨行业绝对阈值**，
会把行业差异抹平——银行天然高杠杆、光模块天然高存货、白酒天然高毛利。「行业财报专家」机制
让每个申万一级行业可以**覆写五维评分区间、五维权重、跳过不适用的通用红旗、增加本行业专属红旗**，
命中不到专家的票退回通用兜底。

### 0.2 一次分析的数据流（关键文件与函数）

```
collectors 落 raw 三大表(带披露日)
  → tools/analysis/financial/metrics.py        compute_derived()   算衍生指标(增速/毛利率/周转…)
  → tools/analysis/financial/industry/          get_expert(key)     按申万一级 KEY 路由到行业专家
  → tools/analysis/financial/flags.py           evaluate_flags()    通用红旗(可被专家 SKIP / 追加 extra)
  → tools/analysis/financial/scoring.py         quality_score()     五维→0~100+评级(吃专家 specs/weights)
  → tools/analysis/financial/analyzer.py        analyze()           编排，产出按报告期视图
                                                build_financial_block()  落 per-stock 顶层 financial 轻量块
```

- **专家路由**：[analyzer.py](../../tools/analysis/financial/analyzer.py) 的 `_industry_key(code, industry, as_of)`
  把该票解析成**申万一级**行业名（优先 `record.meta.industry` → 申万二级半导体池 → `board.board_of`
  证监会门类 → 时变正式行业救援），再 `get_expert(key)` 取模块。
- **专家如何被调用**：`analyze()` 内 `exp.dimension_specs()` / `exp.weights()` / `exp.SKIP_FLAGS` /
  `exp.extra_flags(derived, rec)` 分别喂给 `scoring.quality_score(..., specs=, weights=)` 和
  `flags.evaluate_flags(..., skip=, extra=)`。可选钩子 `exp.dynamic_skip(derived, rec)` 按当期指标
  动态豁免通用红旗。
- **结果落盘**：`build_financial_block()` → `_compute_financial_block()` 把最新已披露报告期摘要写进
  per-stock JSON `data/analysis/<date>/<code>.json` 的顶层 `financial` 块，含字段：
  `行业专家`（命中的专家 KEY，null=通用兜底）、`口径说明`（专家 NOTE）、`quality_score`、`评级`、
  `five_dims`、`flags`/`flags_detail`、`行业评分档`（见 0.4）等。

### 0.3 专家模块契约（每个 `industry/<行业>.py` 必须导出）

自动发现在 [industry/\_\_init\_\_.py](../../tools/analysis/financial/industry/__init__.py) 的 `_discover()`：
扫本包内所有**非下划线开头**、导出 `KEY` 且具备 `_REQUIRED=("KEY","dimension_specs","SKIP_FLAGS","extra_flags")`
的模块，动态注册进 `EXPERTS: {KEY: module}`。**新增一个行业只需丢一个 `.py`，无需改任何共享文件。**

| 导出 | 类型 | 作用 |
|---|---|---|
| `KEY` | `str` | 申万一级规范名，路由键，必须精确匹配（如 `"通信"`） |
| `NOTE` | `str` | 页面标注的口径说明 |
| `dimension_specs()` | `dict` | 覆写五维子指标区间，格式 `{维: [(显示名, derived键, 0分端, 100分端), …]}`；反向指标 0分端>100分端 |
| `weights()` | `dict\|None` | 覆写五维权重；`None`=用通用 |
| `SKIP_FLAGS` | `list[str]` | 本行业不判的通用红旗名（清单见 §0.5） |
| `extra_flags(derived, structured)` | `list[dict]` | 本行业专属红旗，返回成形 `[{code,命中,严重度,值}, …]`，仅 `命中=True` 并入 |
| `dynamic_skip(derived, structured)` | `list[str]`（可选钩子） | 按当期指标动态豁免通用红旗 |

**红线**：纯函数、无网络、无状态、不 import 其它行业模块；一切缺值→该项 `None`/不命中，**绝不抛异常**；
不碰 `as_of`（analyzer 已按披露日过滤，无未来函数）；阈值/区间/权重工程占位，注释注明"待标定"。

完整开发规范见 [docs/财报分析专家/模块开发规范.md](../财报分析专家/模块开发规范.md)（§3 列全部可用 `derived` 键与
`structured` 科目，§4 列通用红旗清单）。参考实现：[industry/通信.py](../../tools/analysis/financial/industry/通信.py)。

## 一、~80 轻量行业专家扩充

### 1.1 背景现状

- 当前 16 个是**重量专家**（如 [industry/通信.py](../../tools/analysis/financial/industry/通信.py) 151 行、
  [industry/电子.py](../../tools/analysis/financial/industry/电子.py) 16KB）：全套五维区间覆写 + 权重 + 多条专属红旗 + `dynamic_skip`，且各自配套一份
  `docs/财报分析专家/<行业>_..._财报分析方案.md` 深度方案 + 单测。开发成本高。
- 大量个股落到"无专属专家"→通用兜底。growth_quality_tool 已能把这种票标"通用口径(无行业专属专家)"
  （字段 `通用兜底`），但通用五维区间对差异大的行业（如钢铁 vs 白酒）刻画粗。
- **路由粒度 = 申万一级**：`_industry_key()` 经 `industry_map.to_sw()` 只解析到**申万一级（31 个）**。
  这是本任务最关键的约束（见 1.3.A）。

### 1.2 需求目标

在不改共享引擎的前提下，用**简化版专家**扩大行业覆盖，把"有专属阈值/专属红旗"的个股比例显著提高。
"轻量版"= 相对重量专家做**减法**：

- **必做**：行业化五维区间校准（`dimension_specs()`，至少校准与本行业最相关的 2~3 个子指标区间，
  其余维度可沿用通用默认）；
- **必做**：1~2 条本行业最典型的专属红旗（`extra_flags`）；
- **可选/可省**：`weights()` 可返回 `None`（用通用等权）；`dynamic_skip` 可不实现；深度方案 md 可用
  精简"要点卡"替代整篇方案。

目标规模 **~80 档**。⚠️ **但申万一级只有 31 个**——要达到 ~80 必须下沉到**申万二级**（见 1.3.A 的方案抉择）。

### 1.3 实现要点 / 接口契约

#### A.（关键抉择）"~80" 的粒度：一级填满 vs 下沉二级 —— 需统筹/用户拍板

现有路由只认申万一级，31 个一级即上限。达到 ~80 有三条路，请统筹在动手前拍板：

| 方案 | 内容 | 优 | 劣 |
|---|---|---|---|
| **A1 只填一级** | 给剩余 15 个一级各补 1 个轻量专家 → 共 31 | 零路由改动、最省、风险最低 | 到不了 80；一级内部差异大的行业（电子/机械/化工）仍粗 |
| **A2 一级填满+二级下沉**（推荐） | 先填 15 个一级；再对**高价值/内部异质大**的申万二级补轻量专家 → ~80 | 覆盖细、贴合"~80" | **需扩路由到二级**（硬依赖，见下）+ 需二级映射表 |
| **A3 直接二级为主** | 主力做申万二级专家 | 最细 | 路由/数据/标定成本最大，样本更薄 |

**推荐 A2，分两阶段**：阶段 1a 填满 15 个一级（无路由改动，可立刻并行开工）；阶段 1b 扩二级路由 +
补 ~50 个高价值二级专家。**阶段 1b 的路由扩展是硬依赖，必须先做**：

- 现 `EXPERTS` 以 KEY→module，KEY 是申万一级名。二级方案需：
  1. `industry_map` 增加**证监会门类/细分文本 → 申万二级**映射（或引入申万二级成分表，参考现有
     `_in_semi_universe()` 用 `config/semi_universe.json`（申万二级 801081）路由半导体票到"电子"的先例）；
  2. `_industry_key()` 增"二级优先、一级兜底"的两级路由：先查二级专家，miss 再退一级专家，再退通用；
  3. 专家 KEY 命名需区分一二级（如二级用 `"电子/半导体"` 或独立 KEY），并保证 `_discover()` 不冲突。
- **此项改动会碰共享文件 `analyzer.py`/`industry_map.py`/`__init__.py`**，不属于"轻量专家纯加文件"的范畴，
  应作为独立子任务、独立分支、配套测试，先落地再批量加二级专家。

> 若统筹选 A1，则本节 §1.3.B 起按"填 15 个一级"执行，规模写实为 31，不强凑 80。

#### B. 轻量专家最小实现规范（每个专家）

新文件 `tools/analysis/financial/industry/<行业>.py`，最小骨架：

```python
"""<行业>财报专家(轻量版·P0 数值层)。⚠️ 非投资建议;阈值工程占位待标定。"""
from __future__ import annotations

KEY = "<申万一级规范名>"        # A1;A2 二级见路由约定
NOTE = "<一句话:本行业特别看什么、哪些通用指标要放宽>"

def dimension_specs() -> dict:
    """只需校准与本行业最相关的 2~3 个子指标区间;其余维度可整段省略(缺的维 scoring 用通用默认)。
    注意:返回的 dict 会**整体替换**通用 specs(scoring.five_dims 用 specs or dimension_specs())。
    故省略某维=该维不评分。若只想改个别子指标,建议仍写全五维、仅调目标区间(拷通用默认再改)。"""
    return {...}

def weights() -> dict | None:
    return None                 # 轻量版默认用通用等权;有强偏好再给

SKIP_FLAGS = [...]              # 从 §0.5 选;想不清就 []

def extra_flags(derived: dict, structured: dict) -> list[dict]:
    out = []
    # 1~2 条本行业最典型红旗;缺值不命中、不抛异常
    return out
```

> ⚠️ **实现坑（必须周知）**：`scoring.five_dims()` 用 `specs or dimension_specs()`——专家返回的
> `dimension_specs()` 会**整体替换**通用五维，不是逐维 merge。所以轻量专家若只想微调 1 个维度，
> 也应**拷贝通用五维默认（见 scoring.py `dimension_specs()` 的 else 分支）再改目标区间**，
> 否则未写的维度会缺失、评分覆盖度下降。这是轻量版最容易踩的错。

**注册方式**：无需注册，丢文件即被 `_discover()` 自动发现。KEY 拼错/缺契约字段会被跳过并 warning。

#### C. 优先补哪些行业（按 A 股行业分布 / 覆盖缺口）

- **一级缺口（阶段 1a，全做）**：上市公司数量与选股命中率优先——建议先做**钢铁、煤炭、石油石化、
  公用事业、建筑装饰、商贸零售、家用电器、轻工制造、纺织服饰、农林牧渔、建筑材料、社会服务、环保、
  美容护理、综合**。其中"综合"是兜底类（如 000504 现落此），可给极简专家或维持通用兜底，优先级最低。
- **二级下沉（阶段 1b，挑高价值）**：优先内部异质大、选股常命中的赛道，如
  电子（消费电子/面板/被动元件/PCB 已部分在电子专家覆盖，可拆）、机械设备（工程机械/自动化/机器人）、
  电力设备（光伏/锂电/风电/电网设备）、基础化工（农化/氟化工/新材料）、医药生物（CXO/创新药/器械/中药）、
  食品饮料（白酒/啤酒/调味品/乳品）、有色（工业金属/能源金属/贵金属）。具体清单由承接方按
  `config/code_industry.json` 的实际分布 + 自选池覆盖统计确定，**信息不全自行按申万二级主流分类定，不反问**。

#### D. 阈值取值来源

轻量专家的区间/红旗阈值一律先给**工程占位**（注释"待标定"），随后由 §三同款标定 harness
（[_calibration.py](../../tools/analysis/financial/industry/_calibration.py)）在样本充足行业上做分布锚定。
样本薄的行业**只保留占位、不硬编**（与通信现状一致）。

### 1.4 数据与防未来

- 专家是**纯函数**，只吃单期 `derived`/`structured`，不碰 `as_of`——无未来函数责任在 analyzer（已做）。
- 二级路由（A2）若引入行业分类，**必须走时变正式行业**（`disambiguate._formal_sw_at` /
  `industry_history`，严格 `date<=as_of`），不能回填现状，防未来函数。

### 1.5 验收 / 测试

- **落盘命中**：对已知属于新专家行业的样本票跑 `analyzer.analyze(code, as_of=...)`，断言产出
  `financial` 块的 `行业专家` 字段 == 新 KEY（非 null、非其它专家）、`口径说明` == 新 NOTE。
  可直接读现成 `data/analysis/<date>/<code>.json` 或临跑（用 `~/.conda/envs/stock_analysis/bin/python`）。
- **单测**（每个专家一份 `tests/test_industry_<x>.py`，勿碰 `tests/test_financial.py`）：

  - `weights()` 返回 dict 或 None；
  - `extra_flags` **每条专属红旗**至少一个"命中/不命中"边界断言（锁语义，防未来重写误删规则）；
  - `extra_flags({}, {})` 与全空三大表不抛异常、返回 list。
- **回归**：跑 `pytest tests/test_industry_*.py -q` 全绿；随机抽若干票确认专家命中率上升、通用兜底占比下降。
- A2 路由改动需额外单测：二级命中优先、二级 miss 回退一级、都 miss 回退通用、防未来（as_of 前分类）。

### 1.6 工作量估（token 量级 + agent 小时）

- **阶段 1a（填 15 个一级轻量专家 + 单测）**：每个专家 ~简化实现，可 **3~5 个/批并行**（互不共享写）。
  单专家 input ~30~50K token（读规范+邻近专家参考+写码+写测），output ~5~8K。15 个合计
  input ~0.6~0.9M token、output ~0.1M。agent 执行 ~3~5 小时（含标定回填与审阅往返）。
- **阶段 1b（二级路由改造 + ~50 个二级轻量专家）**：路由改造是**关键路径**、需仔细设计+测试，
  ~1 个 agent-小时 + 100~150K token。50 个二级专家可大批并行，合计 input ~2~3M token、output ~0.4M，
  agent 执行 ~8~12 小时。
- 建议**分轮**：先 1a 交付见效，再决策 1b 是否全量。

## 二、PE-PB 行业分位（B 期）

### 2.1 背景现状

- [valuation_tool.py](../../tools/pyramid/tools/valuation_tool.py) 现有 5 条估值条目：PE(TTM)、PB、
  PEG(现算)、**PE历史分位**、市值口径。
- **PE历史分位是"自身历史分位"**：读 `valuation.pe_percentile`（0~1，现值 PE 在**该票自身**历史 PE 序列中的
  ≤x 占比），生产者是 [collectors/fundamental.py](../../tools/collectors/fundamental.py) 的
  `PE分位`（`_percentile(vals, vals[-1])`，vals=该票估值序列的 PE），经
  [serialize.py](../../tools/analysis/serialize.py) 写进 `valuation.pe_percentile`/`pe_percentile_window`。
- **行业分位尚缺**：valuation_tool 的 PE/PB 意味模板反复标注
  「PE/PB 仍跨市场粗档；行业分位需当日全行业横截面管线=**B期**，暂未接入」。
  [指标词表.py](../../tools/pyramid/指标词表.py) 的毛利率/净利率条目也写「跨行业粗参考，**精确需行业分位**」。
- 结论：**"行业分位"= 当日全行业横截面口径**（该票 PE/PB 相对同行业其它票现值的排名分位），
  这正是本项要补的 B 期能力。

### 2.2 需求目标

给 valuation 增加**个股 PE / PB 在所属行业内的分位**，让"贵不贵"从跨市场粗档升级为同业对比。
主口径 = **当日行业横截面分位**（primary）；可选扩展 = 行业 PE 中枢的历史分位（temporal，见 2.3 备选）。

产出：valuation_tool 新增两条（或并入现有 PE/PB 条）：「PE行业分位」「PB行业分位」，
值 = 0~100%（该票 PE/PB 在同行业当日横截面中的 ≤x 占比，**越低越便宜**），带档位与影响文案。

### 2.3 实现要点 / 接口契约

**A. 分位计算（横截面，primary）**

- **归类口径**：申万一级（与专家路由一致，用 `industry_map.to_sw` / `_industry_key` 同源，
  防未来走 `industry_history`）。样本 = 当日该行业内 `pe_valid=True & mode==PE适用` 的票（亏损/金融剔除，
  与现有 PE 适用性判定一致）；PB 同理（PB 对金融/重资产更有意义，样本口径可略宽，需在文案标注）。
- **算法**：`pctl = (#同行业票 PE ≤ 本票 PE) / #同行业有效票`。样本量 `n` 必须随值输出，
  **n 太小（建议 `<8`）→ 标"样本不足不编"**，不给虚分位（沿用系统"宁缺勿错"惯例）。
- **落盘位置**：横截面分位需要"当日全行业票"上下文，**不能在单票 valuation_tool.run 内现算**（它只读单票 JSON）。
  应在**批处理/serialize 阶段**先算好、写进每票 `valuation.pe_industry_percentile` /
  `pb_industry_percentile`（+ `industry_percentile_n` + `industry_percentile_sw` 行业名），
  valuation_tool 与 pe_percentile 同样**纯读字段、不重算**。
  → 需在选股管线里加一个"当日行业横截面分位"计算步骤（新函数，建议放
  `tools/analysis/` 下独立模块，输入当日全池 valuation，输出 {code: {pe_industry_pctl, pb_industry_pctl, n}}）。

**B. 接进 valuation_tool**

- 加档位表常量 `_PE行业分位档` / `_PB行业分位档`（0~1，语义同 `_PE分位档`：极低/偏低/中位/偏高/极高），
  与现有 `_PE分位档` 并列，**写死在本文件、拼装层零加工**（与本文件既有口径贯通一致）。
- `run()` 内读 `val.get("pe_industry_percentile")`，命中且 `n>=阈值` → `格档()` + 影响文案；
  缺/样本不足 → 标"行业分位缺失/样本不足"，**不回退成自身历史分位冒充**（口径不同，混用会误导）。
- 影响文案对齐现有风格（如"处同行业估值底部、相对同业便宜、加分"）。

**C. 接进统一指标词表**

- [指标词表.py](../../tools/pyramid/指标词表.py) `_基本面()` 增两条「PE行业分位」「PB行业分位」，
  区间串用 `render_区间(_PE行业分位档, fmt=_pct, 单位="%")` **程序化渲染**（防漂移，禁手抄）。
- 顺带把毛利率/净利率条目的"精确需行业分位"措辞更新为"已接行业分位见 growth_quality/valuation"（若同时接入）。
- **注意防漂移锁**：`tests/pyramid/test_指标词表.py` 会校验词表区间与档位表常量一致，新增档位表需同步。

### 2.4 数据与防未来

- **横截面同 as_of**：所有同行业票的 PE/PB 必须取**同一 as_of 的 point-in-time 值**（PE=当日收盘价×股本
  ÷ 已披露 TTM 净利；已披露=disclosure_date≤as_of）。严禁用未披露报告期或未来价。
- **行业归类防未来**：用 `industry_history` 时变分类（`date<=as_of`），不回填现状。
- **样本口径写进产物**：`industry_percentile_n` 与行业名随分位落盘，供 valuation_tool 展示"基于 N 只同业票"，
  避免小样本被当权威。

### 2.5 验收 / 测试

- **横截面正确性**：构造一批同行业票（已知 PE 序列），断言分位 = 排名占比；边界（最便宜=接近 0、
  最贵=接近 1）正确；`n<阈值` 返回"样本不足"。
- **防未来**：断言某票在其报告期披露日之前不进入横截面样本（用 as_of 卡）。
- **valuation_tool 语义锁**：新增测试断言"命中行业分位→出档+文案""缺字段→标缺失不编""不回退自身历史分位"。
- **词表防漂移**：`tests/pyramid/test_指标词表.py` 全绿（区间随档位表自动跟随）。
- 端到端：跑一日选股，抽查 per-stock JSON 有 `pe_industry_percentile` 且 valuation 展示出行业分位条。

### 2.6 工作量估（token 量级 + agent 小时）

- 横截面分位计算模块（新函数 + 接管线 + 落盘）：input ~80~120K token、output ~10~15K；~1.5 agent-小时。
- 接 valuation_tool + 词表 + 测试：input ~60~90K token、output ~10K；~1 agent-小时。
- 合计 input ~0.15~0.2M token、output ~25K，agent 执行 ~2.5~3.5 小时（含防未来核验与审阅）。
- 备选 temporal 口径（行业 PE 中枢历史分位）如要做，另 +~1 agent-小时（需行业指数 PE 历史序列源，
  当前无现成源，属额外数据依赖，**建议不纳入本轮**）。

## 三、通信专家样本扩充与重标定

### 3.1 背景现状

- [industry/通信.py](../../tools/analysis/financial/industry/通信.py)（光模块/ICT 设备）已实现全套五维覆写 +
  7 条专属红旗（毛利率下滑、存货畸高滞销、应收暴增于营收、合同负债转弱、研发投入偏弱、增收利润背离、
  研发资本化激进）。
- **但阈值几乎全是工程占位**：模块注释明写「标定 2026-08：当前财报快照池内**无通信行业票（0 覆盖）**，
  无从做分布标定，下列阈值全部保留工程占位」。仅 `_HI_研发资本化比=1.7` 做过一次标定，且注明
  「通信 21 票/100 期（全 A 面板，**样本薄**），p90≈1.65，样本薄标定不稳，1.7 为保守占位」。
- 标定 harness = [_calibration.py](../../tools/analysis/financial/industry/_calibration.py)：
  `build_panel()` 每 (code, period) 一行，锚定**披露日**，前瞻 `FWD_DAYS=120` 交易日算收益/回撤 →
  `blowup` 暴雷标签（收益≤-30% 或回撤≤-45% 或审计非标）；`recommend_full()` 对
  `THRESHOLD_REGISTRY` 每项算现阈值命中率 + 分布锚定推荐（hi→p90 / lo→p10），**样本 `<8` 保留占位**。
  通信在登记表中只有 `_HI_研发资本化比` 一行（其余通信红旗未映射到面板连续度量）。

### 3.2 样本不足的影响

- 通信 7 条红旗中 6 条阈值是拍脑袋圆整数，**未经分布验证**：可能太松（从不发声）或太严（误杀良性备货）。
- `_HI_研发资本化比` 虽标过但样本薄（21 票）、分布不稳。
- 五维区间（成长上限 80/100、毛利率 10~40 等）同样是占位，未用通信实际分布校准。
- 后果：通信票的评分与红旗**可信度低**，与已充分标定的 8 个行业（电子/计算机/基础化工/医药生物/食品饮料/
  交通运输/机械设备/有色/电力设备，见 `THRESHOLD_REGISTRY` 与 `recommend_full` 的 `n>=8` 分支）不在一个水位。

### 3.3 需求目标

把通信从"占位为主"提升到"分布标定"水位：
1. **补通信样本**到可标定量（目标：通信票数 × 报告期数使**每个待标 metric 有效样本 `n>=8`**，
   暴雷区分度子集 `n_pos>=3 & n_neg>=3` 更佳）；
2. 用扩充样本**重标定**通信五维区间 + 7 条红旗阈值，替换占位；
3. 建立**可复现的重标定验证**流程。

### 3.4 实现要点 / 接口契约

**A. 要补哪些样本数据**

- `_calibration.py` 的样本来自 `DATA_ROOT/data/raw/*/financial_report/*.json`（三大表 + 披露日）+
  `DATA_ROOT/data/master/kline/<code>.parquet`（前瞻行情）+ `config/code_industry.json`（code→行业）。
  `DATA_ROOT` 默认主仓（worktree 无 data/，见 3.5）。
- **补三类**：
  1. **通信行业成分票清单**：从 `config/code_industry.json` 找出所有映射到申万一级"通信"的票
     （光模块、ICT 设备、运营商、通信终端等），确认覆盖面（当前池仅 21 票太少）；
  2. **这些票的历史 `financial_report` raw**：多报告期三大表（含开发支出/研发费用/合同负债/存货/应收等
     通信红旗实际比较的科目），报告期越多面板行数越多；
  3. **这些票的 `kline` parquet**：覆盖各报告期披露日之后 ≥120 交易日，才能产出 `blowup` 结局标签。
- 补数据走现有 collectors（`tools/collectors/financial*.py` 采三大表、kline 采集脚本），
  **本线只写需求、不执行采集**；采集由数据线/统筹调度。承接方需产出：待补票清单 + 缺哪些报告期/kline 区间。

**B. 把通信红旗纳入标定登记表**

- 现 `THRESHOLD_REGISTRY` 通信只有研发资本化一行。需为可映射到面板连续度量的通信红旗补登记：
  `_GM_DROP_PCT`(毛利率同比降,对应 metric 需在 `_metrics_for_period` 补"毛利率同比升")、
  `_INV_GAP_PCT`(存货营收增速差,已有 `存货营收增速差`)、`_AR_GAP_PCT`(应收营收增速差,已有)、
  `_CONTRACT_DROP_PCT`(合同负债环比,已有)、`_RD_MIN_PCT`(研发费用率,已有)、`_PROFIT_LAG_PCT`(营收扣非增速差,
  面板需补该 metric)。
- `_metrics_for_period()` 缺的连续度量（如"营收扣非增速差""毛利率同比升"）需补进面板（改 `_calibration.py`，
  属该文件内改动，不碰其它共享文件）。
- 登记方向：上尾为坏→`hi`(锚 p90)、下尾为坏→`lo`(锚 p10)，与现有项一致。

**C. 重标定与回填**

- 跑 `python -m tools.analysis.financial.industry._calibration --recommend`（需 `CALIB_DATA_ROOT` 指向
  主仓 data，见 3.5），读通信各 metric 的 `n / 现命中率 / 推荐值(p90 或 p10)`。
- **只回填 `n>=8` 的项**；`n<8` 仍保留占位并在注释注明"样本仍薄"。回填时更新通信.py 常量注释里的
  标定日期/样本量/分位锚（与现有 `_HI_研发资本化比` 注释格式一致）。
- 五维区间校准：用 `summarize()` 输出的通信各 metric 分位（p10~p90）反推合理的 0 分端/100 分端
  （如毛利率 100 分端≈p90、0 分端≈p10），替换占位；同样只在样本够时做。

### 3.5 数据与防未来

- **防未来红线（硬）**：`_calibration.py` 每样本锚在**披露日** as_of，`blowup` 只用 `date>as_of` 起 120 日行情
  （`_forward_outcome` 已实现）；标定新增 metric 不得破坏这一点。
- **数据位置**：worktree 下无 `data/`，标定与真实数据在**主仓**。跑标定需
  `CALIB_DATA_ROOT=/Users/yqg/Documents/projects/stock_analysis`（默认已指主仓）或 `--data-root` 指过去。
  读代码用 `~/.conda/envs/stock_analysis/bin/python`（默认 python 缺依赖）。
- 采集补数据不入库敏感信息；标定产物（面板 CSV）落 `data/analysis/`，不进 git。

### 3.6 验收 / 测试

- **样本达标**：`recommend_full()` 输出中通信各待标 metric `n>=8`（研发资本化、存货增速差、应收增速差、
  合同负债环比、研发费用率、毛利率同比、营收扣非增速差）；报告面板通信 `n_rows/n_codes/n_labeled/n_blowup`。
- **重标定生效**：通信.py 占位常量被替换为分布锚定值，注释更新标定日期/样本量/锚分位；`n<8` 的项如实保留占位。
- **红旗合理性**：重标后各红旗"现命中率"落在合理区间（≈0.5=太松、≈0=从不发声，参考
  `_print_recommend` 的提示语义）；有暴雷区分度时报 `blowup_med vs ok_med`。
- **回归**：`tests/test_industry_通信.py`（或 tongxin）全绿——每条红旗命中/不命中边界断言仍成立
  （标定改的是阈值数值，不改红旗逻辑，语义锁应仍通过；若阈值变动使某断言的构造值跨界，需同步更新测试构造值并说明）。
- **可复现**：记录标定命令、`CALIB_DATA_ROOT`、样本快照日期，写进通信方案 md 的「实现状态/标定记录」节。

### 3.7 工作量估（token 量级 + agent 小时）

- 需求侧（补数据清单 + 登记表/面板 metric 扩充 + 重标定脚本跑通 + 回填）：
  input ~0.1~0.15M token、output ~15~20K；agent 执行 ~2~3 小时。
- **数据采集本身不计入**（由数据线/collectors 执行，取决于通信票数与历史深度；若池内通信票需从 21 扩到
  50+ 并补多期三大表+kline，采集耗时另估，属数据工程）。
- 若通信票在全市场本就偏少（光模块/ICT 是小行业），**样本天花板可能仍不足**——此时如实保留占位、
  只标 `n>=8` 的项，不硬凑（与现状诚实一致）。这是本项最大不确定性。

# 策略建议 · 新闻 LLM「与本股关系」对策略选中票系统性误判为"无关"

> 来源：2026-09-02 选股分析——002084 海鸥住工、301246 宏源药业的 **本公司自己的新闻** 被 `news_ai` 大量标为「无关」。
> 状态：**待统筹排期（建议优先，根因已定位、修复面很小）**。
> 优先级：**高**——影响范围是**整个策略选中集**（非自选池的全部票），且被影响的信号会被下游**直接丢弃**（权重0）。
> ⚠️ 非投资建议。本文档只提议，不改代码。

---

## 1. 动机（本轮暴露的样本）

09-02 逐票分析读 `data/analysis/2026-09-02/news_ai/<code>.json` 时发现，AI 富集字段 `ai.与本股关系` 出现整片的"无关"，且 `ai.原因` 的措辞高度模板化：

| 票 | 新闻标题 | AI 判定 | AI 给的理由（原文） |
|---|---|---|---|
| 002084 | 7连板海鸥住工：若股价进一步异常上涨，可能申请停牌核查 | 中性 / **无关** | "新闻主体为海鸥住工，**与目标股票002084无关**" |
| 002084 | 海鸥住工涨1.42%，成交额15.40亿元，今日主力净流入-8808.24万 | 中性 / **无关** | "新闻主体为海鸥住工，与目标股票002084无关" |
| 002084 | 海鸥住工连续7个交易日涨停收盘 累计涨幅达95.54% | 中性 / **无关** | 同型 |
| 301246 | 宏源药业上半年实现归母净利润1.56亿元 同比增长2789% | 利好 / **无关** | "新闻主体为宏源药业，**并非目标股票301246**" |
| 301246 | 宏源药业：2026年第二季度公司经营业绩环比出现阶段性下滑 | 利空 / **无关** | "新闻主体为宏源药业，并非目标股票301246" |
| 301246 | 宏源药业2026年半年度营收13.42亿元，同比增长52.05% | 利好 / **无关** | 同型 |

002084 的 69 条里，**几乎全部关键新闻**（7连板、停牌核查风险提示、主力净流出8808万）都被判"无关"；301246 的中报业绩（+2789%）与当日业绩降温公告（Q2环比下滑）同样被判"无关"。
→ 这两只票恰恰是本轮**最依赖消息面才能判对**的票（游资连板 / 技术超卖被消息面否掉）。若分析师直接采信系统情绪分，会把它们的消息面读成"无消息"。

## 2. 诊断（根因已定位，一行）

**根因：`name` 取不到时回退成了 `code`，导致 prompt 里让 LLM 比对的"公司名"变成了一串数字代码。**

- [tools/analysis/event.py:167-168](../../../tools/analysis/event.py)
  ```python
  s = stock_pool.get(code)
  name = s.name if s else code          # ← 池外票 name 回退成 code
  ```
- prompt 模板把这个 `name` 直接插进关系判定约束：[tools/llm/prompts.py:30](../../../tools/llm/prompts.py)
  ```python
  f"- '与本股关系':若新闻只是顺带提及代码/名称、主体并非{name},填'无关';"
  f"直接讲{name}自身填'直接';讲行业/同板块间接影响填'间接'。\n"
  ```
  当 `name == "002084"` 时，这句话变成"**主体并非 002084 就填无关**"。LLM 于是把新闻主体（"海鸥住工"）与字符串"002084"做比较，**按指令严格执行、得出"无关"** —— 这不是模型幻觉，是 prompt 被喂错了变量。

**为什么正好命中策略选中票**：`stock_pool` 只装**自选池**，当日实测 `stock_pool.get_codes()` 长度 = **15**（`['300308','300502','000938',…]`）。而 `news_ai/` 当日有 **54** 个 code，即 **约 39 只策略选中票全部走了 name→code 的回退路径**。自选池内的票（如 300502/300684）不受影响，所以此前复盘（分析对象多在自选池内）没暴露这个问题。

**下游放大：被判"无关"的事件会被直接丢弃，不是降权。**
- [tools/analysis/event.py:29](../../../tools/analysis/event.py)：`_REL_W = {"直接": 1.0, "间接": 0.5, "无关": 0.0}`
- [tools/analysis/event.py:261-263](../../../tools/analysis/event.py)：`rel = _REL_W.get(...)` → **`if rel == 0: continue`**（整条事件跳过，不进净情绪分）
- [tools/analysis/conditional_predict.py:667](../../../tools/analysis/conditional_predict.py)：`if e.get("与本股关系") not in rel_w: continue`（结构性倾斜同样丢弃）
- [tools/analysis/serialize.py:136](../../../tools/analysis/serialize.py)：只把 `直接/间接` 的事件写进 record

→ 净效果：**策略选中票的 `sentiment` / 事件倾斜信号被系统性掏空**，情绪专家在这些票上等于哑火。这与经验 #4（"系统 events/sentiment 是加工分，可能建立在残缺新闻上"）是同一类问题的**上游根因**。

## 3. 改进提议（只提议）

1. **主修（必做，改动极小）**：`name` 不再只从 `stock_pool` 取，按优先级链回退——
   `stock_pool.get(code).name` → 当日 panel / per-stock `meta.name` → 全A代码名映射 → **最后才**用 code。
2. **兜底（防同类复发）**：`prompts.news_extract_instruction` 增加防御——当传入的 `name` 与 `code` 相等（或 `name` 形如纯数字/为空）时，**不生成"主体并非{name}即无关"这句约束**，改为"以新闻是否讲述该股票代码对应的上市公司为准，无法判断时填'间接'"。避免"名字缺失"直接翻转成"无关"这种**静默失效**。
3. **可观测（建议一并做）**：富集环节统计并落一个 `name_fallback_ratio`（本批有多少票走了 name→code 回退）；比值 >0 就在日志 WARN。本轮这个比值是 **39/54 ≈ 72%**，有这个指标的话第一天就会被发现。
4. **不建议**的做法：靠"事后修正无关标签"或"把无关权重从0改成0.3"来打补丁——那会把真正的蹭词新闻也放进来，破坏 `与本股关系` 这个字段的本意（防蹭词）。**根因是输入错，应修输入。**

## 4. 回测/验收口径

这是**数据正确性 bug 而非 alpha 策略**，不需要 A/B 收益回测，按"修复前后一致性"验收：

- **主验收**：取本轮两只样本（002084 / 301246）重跑富集，断言"标题中含公司名的本股新闻"其 `与本股关系` **不再为"无关"**（002084 的 7连板/停牌核查/主力净流出三条、301246 的中报+2789% 与 Q2环比下滑两条，必须为"直接"）。
- **回归验收**：`name_fallback_ratio == 0`（选中集全部票都拿到真名）。
- **不劣化验收**：自选池 15 只票（本来 name 正确）修复前后 `与本股关系` 分布**不变**——证明没有把"无关"过度翻正。
- **蹭词保护验收**：构造/挑选真蹭词样本（标题只顺带提及代码、主体是别的公司，如 301246 里的"电解液周报丨比亚迪…新宙邦冲刺港交所"），断言仍判"无关"。
- **kill-switch**：不需要（纯输入修正，无策略语义变化）；但第2条 prompt 兜底建议加配置开关，便于比对两种措辞的判定差异。

# 候选定向富集覆盖（修「买入候选反而没有系统数据」硬伤）

> 性质：A股量化分析研究工程，非投资建议。本文记录一处数据覆盖硬伤的根因、修复方案、验收口径与成本。

## 一、动机（硬伤）

日常生产走 `screenall → run_screen_all`（`tools/run.py`）。闭环里**最贵的新闻采集 + LLM 情绪 + 财报（M2）**
出于 token 纪律，只对 `news_subset = 自选池 ∪ 每策略前 N`（`SCREENALL_NEWS_TOPK` 默认 5）采集；而
`serialize/factor/council/横表` 覆盖 `llm_subset = union_picks ∪ 自选`（各策略选出并集，约数百只）。

后果：**最终被深度分析/推荐买入的候选票，如果排在各自策略前 N 名之外，就拿不到系统的
news_ai / sentiment / financial / fundflow**——即「被推荐买入的票反而没有系统数据支撑」。

实证（2026-09-02，3 只买入候选 vs 2 只自选检验样本）：

| 票 | 角色 | news_ai | sentiment | financial | fundflow |
|---|---|---|---|---|---|
| 002811 郑中设计 | **买入·首选** | 缺 | 缺 | 缺 | 缺 |
| 603270 金帝股份 | **买入·可参与** | 缺 | 缺 | 缺 | 缺 |
| 688569 铁科轨道 | **买入·可参与** | 缺 | 缺 | 缺 | 缺 |
| 301246 宏源药业 | 自选/检验 | 有 | 有 | 有 | 有 |
| 002084 海鸥住工 | 自选/检验 | 有 | 有 | 有 | 缺 |

当日 `data/analysis/2026-09-02/` 全量 455 条记录（= llm_subset）里，仅 sentiment 117 / financial 107 /
fundflow 128 / news_ai 54 覆盖 —— 约 3/4 的记录（含全部 3 只买入候选）没有系统消息面/财报/资金流，
分析师只能临时用 WebSearch 个人补消息面。09-02 选股文档已自行标注此限制。

## 二、根因

`tools/run.py` `run_screen_all`：
- `news_subset`（新闻 + LLM 情绪 + 财报三表/年报/文本）只覆盖「自选 ∪ 每策略前 N」，**买入候选常在 N 名之外**。
- `fundflow`：`collect_values_missing(llm_subset)` 名义覆盖全并集，但**采集源不稳时候选票易缺**（09-02 三只买入候选全缺）。

## 三、方案：候选定向富集（幂等的定向富集函数）

新增 `enrich_candidates(codes, as_of, no_llm=False)`（`tools/run.py`）：对一批候选票**确保**采到
`新闻 → LLM 情绪 → 财报（三大表 + 年报 PDF + LLM 文本）→ 资金流`。特性：

- **幂等 / skip-if-cached**：各维按本地缓存分维取尚无缓存的子集，只补缺、不重采；LLM 层结果按输入
  hash 缓存（`data/raw/llm_cache`），重跑只对新票计费、不破坏已有数据。
- **优雅降级不阻断**：任一源失败 → `_safe` 降级，不中止；短超时快速失败（`FETCH_TIMEOUT`）。
- **防未来函数**：各采集器 / 财报文本层自身按 `as_of` / 披露日锚定，本函数不放宽口径。
- **缺数据不静默**：返回覆盖报告 `{candidates, counts, per_code, degraded, summary}`，逐票逐维标
  `ok`（有非空数据）/ `empty`（源当日确无——合法降级）/ `missing`（采集失败未落盘）/
  `skipped_no_llm`（数据模式跳过 LLM）；`empty`/`missing` 一律进 `degraded` 明细。

两个调用入口（呼应「固定代码 + 工具调用」方向）：
1. **闭环**：`run_screen_all` 在各策略选出后、serialize/上传前，对**候选集**调用 `enrich_candidates`
   （替换原 `news_subset` 口径的 collect_message/run_sentiment/run_financial_* + 扩 fundflow）。
2. **按需**：`python -m tools.run enrich <code...> [--date YYYY-MM-DD] [--no-llm]` —— 选股分析流程中
   发现某票缺系统数据，先跑本命令补数再深度分析。

### 候选集口径（成本 / 覆盖权衡）

`SCREENALL_ENRICH_TOPK`（默认 `0`）：
- **`0`（默认，airtight）**：候选集 = `union_picks ∪ 自选` = `llm_subset` = **所有被 serialize 成 record 的票**。
  任何可能被深度分析 / 推荐买入的票都有系统数据——彻底堵死本硬伤。
- **`M > 0`（限成本）**：候选集 = `每策略前 M ∪ 自选`。M 越小越省 token，但排名靠后的边缘候选可能仍缺数据。
  `serialize/factor/council` 仍对全 `llm_subset`（记录不缩），只是贵活富集集更小。

选默认 airtight 的理由：买入候选由下游分析（人/agent）在 record/策略视图里跨策略挑选，系统事前无法
预知哪只会被选为买入；只有覆盖全部 record 才能保证「不让最终买入候选空着」（任务硬原则）。ops 若要压
token 可调 `SCREENALL_ENRICH_TOPK=M` 收窄。

## 四、验收口径

自动化测试（锁语义，防未来重写误删）：
- `tests/test_enrich_candidates.py`：
  - 全缺数据候选票富集后四维 `ok`（核心验收）；
  - **skip-if-cached 幂等**：已缓存票不进任何 fetch 名单、只补缺失票；
  - **缺数据降级不静默**：源不可得 → `empty`/`missing` 并进 `degraded`（四维都在，非静默空）；
  - `no_llm` 透传：跳过 run_sentiment / run_financial_text，sentiment 维标 `skipped_no_llm`；
  - 空候选集安全返回。
- `tests/test_screenall.py`：闭环候选富集集口径（默认 = llm_subset / `SCREENALL_ENRICH_TOPK` 收窄）、
  enrich 必在 serialize 之前、no_llm 透传。

真实端到端（2026-09-02 三只买入候选，本机沙箱部分源可达）：
`python -m tools.run enrich 002811 603270 688569 --date 2026-09-02 --no-llm`
- 首跑：news `ok3` / financial `ok3` / fundflow `missing3`（东财资金流源沙箱不可达 → **显式降级**，
  进 `degraded={'002811':{'fundflow':'missing'},...}`，非静默）；sentiment `no_llm`（数据模式）。
- 二跑：`需采 新闻 0 / 财报三表 0 / 年报 0 / 资金流 3` —— news/financial **未重采**（skip-if-cached
  幂等），只重试仍不可达的 fundflow。
- 结论：修复前三只买入候选四维全缺；修复后经定向富集拿到 news + financial，且失败的 fundflow 被**显式标记**
  而非静默空。fundflow 的 `ok` 路径由单测覆盖（沙箱该源被封）。

## 五、成本

- **富集集规模**：从 `news_subset`（自选 ∪ 每策略前 5，2026-09-02 约 54~117 只）扩到 `llm_subset`
  （union ∪ 自选，2026-09-02 = 455 只）。即多富集约 300~400 只。
- **量级**：新闻采集 ~8×（网络为主，便宜）；LLM 情绪 + 财报文本约 3~4×（约 340 只增量，一次性/日，
  已缓存票近乎零开销）。财报三表 / 年报 / fundflow 为网络采集（无 LLM）。
- **调节**：`SCREENALL_ENRICH_TOPK=M` 可把 LLM 富集集压回「每策略前 M ∪ 自选」，按预算折中。
- 幂等：同日重跑只补新票、不重复烧钱。

## 六、是否建议接生产

**建议接**（默认 `SCREENALL_ENRICH_TOPK=0` airtight）：这是「买入候选必须有系统数据」的正确性修复，
成本增量为一次性/日且可用 env 收窄；失败优雅降级、缺数据显式标记，不引入闭环中止风险。若首轮想控成本，
可先设 `SCREENALL_ENRICH_TOPK=15~20` 观测覆盖率，再逐步放开到 0。

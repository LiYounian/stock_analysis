# 策略建议（每日分析 → 策略修改建议）

> 这里记录**每日选股分析中发现的、对策略的修改建议**。每条建议=一份诊断+改进提议+回测口径的文档，是"用实盘分析反哺策略迭代"的产出。
> ⚠️ 非投资建议。所有建议只提议，**不直接改策略代码**——需走 统筹审→实现窗→回测评测，**达标才接生产**（带 kill-switch 可回退）。

## 怎么用
- **分析师（含合作者/其 agent）**：每日复盘/选股时若发现"策略误导了我 / 我的判断与策略有出入 / 策略有明显缺陷"，就在这里新增或更新一份建议（topic 命名，如 `资金流融资盘甄别.md`），写清：**动机(哪次分析暴露)→诊断(根因+证据file:line)→改进提议(只提议)→回测口径(A/B+达标标准+kill-switch)→待决**。
- **统筹**：定期审这里的建议，排期到实现窗；实现+回测达标后更新下表"状态"，并回填实现 commit。

## 命名与规范
- 文件按 **topic** 命名（一个策略问题一份，跨天持续更新，别按日期拆碎）。
- 每份顶部注明"首次提出日期 + 来源分析"；重大更新在文档内记 changelog。
- 引用代码用 `file.py:line`（可点击）；引用仓库文件的 markdown 链接从本目录用 `../../../tools/...`（本目录在 docs 下第 2 层）。

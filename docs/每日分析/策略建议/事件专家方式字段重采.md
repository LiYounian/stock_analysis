# 策略改进提议 · 事件专家「方式」字段填满（减持性质区分数据供给）

> 来源：2026-09-02 调研——合议「事件驱动专家」减持性质区分依赖的「方式」字段（变动途径：
> 协议转让/集中竞价/大宗交易）当前**100% 为空**，导致所有减持一律按"二级抛售看空"处理，
> 无法把"协议转让给产业资本/战投的战略引资"从"套现抛售"里摘出来。
> 状态：**提议（诊断 + 数据源方案 + 验证口径，未改代码）**。⚠️ 非投资建议。

---

## 0. 一句话结论

**根因：采集端选错了数据源。** 事件专家想用「方式」区分减持性质，但采集走的东财
`stock_ggcg_em()`（股东增减持汇总）接口**根本不返回任何变动方式列**，所以列名模糊匹配恒不命中、
`方式` 字段全表写 None。**下游判定逻辑（`classify_share_change` / `judge_corporate_action`）
是完好的**，缺的纯粹是数据供给。修复 = 换/补一个带"变动途径"字段的源。

---

## 1. 「方式」字段本该是什么语义

- 定义（采集端注释 `tools/collectors/event_driven.py:107`）：**「方式」= 变动途径**，取值如
  `"协议转让" / "集中竞价" / "大宗交易"`。
- 用途（`tools/analysis/event_driven/judge.py:58-89` `classify_share_change`）：同为"减持"，
  **二级市场抛售套现**（集中竞价/大宗交易）与**协议转让给产业资本/战投**性质相反——
  - 协议转让给产业方/战投 → 判「战略引资」→ **不看空、轻度偏正**（背书信号，`judge.py:120-123`）；
  - 协议转让但受让方性质不明 → 判「协议转让待定」→ **中性、低置信**（`judge.py:124-126`）；
  - 无任何方式/文本线索的减持 → 「普通减持」→ 沿用**看空**（`judge.py:89`）。
- 消费链：`experts.py:expert_事件驱动` → `event_driven/summary.summarize` → `summary._load_precise`
  （`method = r.get("方式")`，`summary.py`）→ `judge.judge_corporate_action(..., method=method, text=ann_text)`。

## 2. 为什么现在是空的（根因 + 证据）

**根因：源接口无此列，不是字段名对不上、也不是 LLM 抽取问题。**

1. 采集端**期望**一个变动方式列，用模糊匹配去找：
   `method_col = _find_col(raw, "变动方式", "变动途径", "减持方式", "方式")`
   （`tools/collectors/event_driven.py:124`）。
2. 但源接口 `ak.stock_ggcg_em()`（东财-股东增减持）当前（akshare **1.18.81**）**返回列里没有任何一个含上述关键字**。实测列名：
   ```
   ['代码','名称','最新价','涨跌幅','股东名称',
    '持股变动信息-增减','持股变动信息-变动数量','持股变动信息-占总股本比例','持股变动信息-占流通股比例',
    '变动后持股情况-持股总数','变动后持股情况-占总股本比例','变动后持股情况-持流通股数','变动后持股情况-占流通股比例',
    '变动开始日','变动截止日','公告日']
   ```
   → `_find_col` 返 None → `method_col=None` → 每行 `方式=None`（`event_driven.py:139-143`）。
3. 落盘缓存实测印证：`load_insider_trades('latest')` 共 **146,234 条**，`方式` 列 **non-null = 0 / 146234**（全 None）。
   > 对比：同表的 `方向`（"持股变动信息-增减"含"增减"关键字✓）、`变动股数`（"持股变动信息-变动数量"✓）、`日期`（"公告日"✓）都正常命中——**唯独没有变动方式这一列可命中**。所以是"这个接口就没有这个字段"，不是匹配写错。

**次生问题（文本兜底也基本失效）**：`classify_share_change` 还能用公告文本（`text=ann_text`）兜底判性质，
文本来自 `record['events']` 的标题/摘要（`summary._strategic_hint`）。但：
- 富集侧 `serialize.py:162-163` 的 events 只带 `date/type/impact/title`，**不带 summary**；
- 全 A 合议路径 `screen_council.build_min_record` **根本不塞 events**（record['events']=None）。
→ 所以现状下减持性质区分**几乎全部退化为"普通减持=看空"**，战略引资/协议转让识别形同虚设。

## 3. 修复提议（换/补数据源）

按代价从低到高：

### 方案 A（推荐）：补采东财「董监高持股变动明细」`stock_hold_management_detail_em`
- 该接口**自带 `变动原因` 列**，实测取值即"集中竞价 / 大宗交易 / 协议转让"等——正是要的"方式"语义。实测列：
  `['日期','代码','名称','变动人','变动股数','成交均价','变动金额','变动原因','变动比例','变动后持股数','持股种类','董监高人员姓名','职务','变动人与董监高的关系','开始时持有','结束后持有']`
- 改动：`fetch_insider_trades` 增补一路从该接口取 `变动原因` 映射为 `方式`，与现有 `stock_ggcg_em` 按 `code+日期` 合并（或新增一路缓存 tag）。`_find_col(..., "变动原因")` 即可命中。
- **局限（须诚实标注）**：该接口是**董监高（含相关人员）**口径，与 `stock_ggcg_em` 的**大股东/机构增减持**口径**不完全重合**。大股东协议转让减持不一定进董监高明细。→ 覆盖率有限，只能填一部分。

### 方案 B：交易所披露源 `stock_share_hold_change_sse/szse/bse`
- 沪深北交易所"董监高人员股份变动"披露，通常带变动方式/途径字段，权威但需按代码/交易所分片查询、拼装成本更高。可作 A 的补充源。

### 方案 C（并行、低成本）：修文本兜底链路
- 让 `serialize.py` 的 events 带上 `summary`（不只 title），并在合议全 A 的 `build_min_record` 里为**候选票**（top_k 分层补采，见「合议专家覆盖补全」§A）塞 `record['events']`。
- 这样即使源无"方式"列，`classify_share_change` 也能用公告标题/摘要里的"协议转让/引入战投/战略入股"等关键词（`judge._has_kw` 已有关键词表）兜底判性质。
- 好处：不新增接口依赖，且对"战略引资"这类**语义在公告文本里最全**的场景更贴合。
- 代价：只对补采了 events 的候选票生效，非全 A。

**建议组合**：**A（补 `变动原因` 精字段）+ C（修文本兜底）** 双管——精字段覆盖董监高部分，文本兜底覆盖大股东协议转让的语义识别，互补。B 作为将来提升覆盖率的备选。

## 4. 验证口径（数据质量，**不跑收益回测**）

「方式」是数据字段，验证其"填没填满 + 填得对不对"，不是验证 alpha：

| 指标 | 口径 | 达标标准 |
|---|---|---|
| **① 方式填充率** | 修后 `load_insider_trades` 里 `方式` non-null 占比（含合并了 `变动原因` 的行） | 现状 0% → **A 后 > 0 且覆盖董监高样本的主体**；报告绝对填充率 |
| **② 取值合法性** | 非空「方式」落在预期取值域（协议转让/集中竞价/大宗交易/…）的比例 | **≥ 95%**（防脏值/乱码进 `classify_share_change`） |
| **③ 性质区分激活率** | 减持样本里被判为"战略引资"或"协议转让待定"（非"普通减持"）的比例 | 现状≈0% → **修后 > 0**；抽样人工核对方向判定正确（协议转让给产业方→不看空）|
| **④ 回归不破坏** | 无「方式」的减持仍判"普通减持=看空"（向后兼容，`judge.py:89`） | 主仓测试 `tests/test_event_driven*` 全绿 + 新增断言锁语义 |

**判定**：①③从 0 变正、②达标、④不破坏，即判"方式字段供给修复成立"。抽 10–20 个协议转让/战略引资案例人工核对方向判定即可，无需前瞻收益。

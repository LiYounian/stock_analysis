> 来源：2026-09-02 选股分析——读「反转低换手组合」视图发现**有效样本只剩 6 只**（扫描 5554），TopK 设 20 却出不满，且 6 只里 4 只被否决层降级。
> 状态：**已实现（2026-09-03 实现窗）**——治本现算兜底 + 覆盖率熔断护栏已落地并验收，见 §6。待统筹把关合入 main。

> ⚠️ 非投资建议。§1~§5 为原始诊断/提议（不改代码），§6 为实现与验收结果。

## 2. 诊断（根因 + 为什么静默）

**根因：日线的 `turnover` / `amount` 字段近端整片为空，而低换手因子的"容忍近端 NaN"设计在"几乎全为 NaN"时退化成了near-全量剔除。**

- **数据层证据**：当日 raw 分区 `data/raw/2026-09-02/kline/*.parquet` 里 `turnover` 与 `amount` **整列为 None**（实测 002811/002155/688432/300176 的 `turnover.notna().sum()` 全部 = 0）。
  合并读取口径 `market.load_kline_recent(code)`（[tools/pipeline/screen_reversal_turnover.py:52](../../../tools/pipeline/screen_reversal_turnover.py) 调用）返回 500 根，其中 turnover 只在"当初采到富字段的那些日子"有值：

  | 票 | 末20根 turnover 非空数 | 是否入选今日6只 |
  |---|---|---|
  | 002155 | **10** | ✅ 入选 |
  | 688432 | **10** | ✅ 入选 |
  | 603270 | 7 | ❌ 被剔 |
  | 002811 | 5 | ❌ 被剔 |

- **门槛层证据**：[tools/strategy/reversal_turnover.py:69-83](../../../tools/strategy/reversal_turnover.py) `low_turnover_factor`
  ```python
  window = turnovers[-n:]                        # n = 换手窗口 = 20
  valid = [float(v) for v in window if _finite(v)]
  need = min_valid if min_valid is not None else max(1, n // 2)   # = 10
  if len(valid) < need: return None              # ← 有效点 <10 直接 None
  ```
  函数 docstring 写的设计意图是"**近端常有采集滞后(新端点不给换手率,末几根为 NaN)**，故对窗口内有效值取均值"——即容忍**末几根**缺失。但现实是**绝大多数根都缺**，于是"取有效值均值"的宽容设计变成了"必须凑够10个有值的历史日"。随着无 turnover 的交易日不断累积、有 turnover 的旧日子逐日滚出 20 根窗口，通过率从 08-27 的 ~72% 崩到 09-02 的 ~0.1%。**08-28 的断崖正是某批富字段日子集体滚出窗口的那一天。**

- **最严重的后果不是"票少"，而是"选择性偏差让排序失效"**：
  今天存活的 6 只，**入选原因是"它们恰好有最多的换手率采集覆盖"，不是"它们换手率最低"**。因子的横截面 winsorize+zscore 是在这 6 只上做的（`turn_z` 从 -1.41 到 +1.65），**在一个由数据可得性而非因子值决定的 6 票样本上做 z-score，得到的排序没有经济含义**。
  例证：今日 6 只里 4 只被否决层判"高风险博弈"（3 只事件博弈 / 3 只基本面空心 / 2 只重组未完成），只剩 2 只无风险标签——**"有效样本极少" + "存活票质量极差"同时出现，正是选择性偏差的典型表征**。
  → 若分析师按经验 #8 的"单策略极值"维度采信这个视图（例如"反转 -0.95 = 强反向信号"），会把**数据缺失造成的伪极值**当成真信号。2026-09-01 就已经用过这个维度选了 2 只检验样本。

- **为什么静默**：`跳过` 计数是**如实落盘的**（`换手因子缺失(近端NaN过多): 5188` 就写在视图里），但**没有任何阈值告警**。视图照常生成、`入选数=6` 看起来像"今天没什么好票"，与"策略坏了"在外观上无法区分。

## 3. 改进提议（只提议）

**第一优先 · 修数据源（治本）**
1. 定位 kline 采集为何不再带 `turnover` / `amount`（新端点字段缺失或字段名漂移），恢复采集；若源头确实不提供换手率，则用 **`volume / 流通股本`** 现算换手率（流通股本可从 fundamental / 全A基础信息取），把换手率变成**可自行推导**的派生字段而不是依赖外部字段。
   - 注意 `amount` 同样缺失会打坏 `avg_amount_wan`（[tools/strategy/reversal_turnover.py:86](../../../tools/strategy/reversal_turnover.py)）→ 低流动性过滤失效（本轮已观察到跳过数归零）；`amount` 可用 **`volume × 均价`** 兜底推导。
2. 回补历史：至少回补最近 30 个交易日，让 20 日窗口立刻恢复满覆盖。

**第二优先 · 加覆盖率熔断（治标但必须有，防同类静默复发）**
3. 在薄管线里统计 `换手覆盖率 = 有效样本 / (扫描数 - 历史不足 - 无K线)`，并写进视图 JSON。
4. **熔断规则（描述性）**：覆盖率低于阈值时，该策略视图**标记为"数据不足·本日不出"**（类似「最强选股」`present=false` 的既有降级范式），而不是照常输出一个小样本 TopK。同时 log WARN。理由：**输出"少而偏"的名单比输出"不出"更危险**——前者会被下游当成有效信号消费。
5. **同时对"横截面 z-score 的最小样本量"设下限**（如有效样本 < 200 就不做 winsorize+zscore 排序），因为极小样本的 z 分数量级会虚高，制造伪极值。

**第三优先 · 排查同类隐患**
6. 用同一把尺子扫一遍**其他依赖 turnover/amount 的策略**：「量价放量(S04)」的 `单日放量` 子信号今日明细里 `"换手": null`（说明"换手>1.7×前值"这一条实际未生效，该子信号被降级成只靠涨幅+均线）；`指标条件化状态排序` 用"近20日成交额均值"做次级排序键（依赖 amount）。**建议一并核查这两处是否也在静默降级。**

## 4. 回测/验收口径

属**数据可得性缺陷**，不需要 alpha A/B，按"覆盖率恢复 + 排序可比性"验收：

- **主验收（覆盖率）**：修复后重跑 09-02，`有效样本` 回到 **≥3900**（对齐 08-25～08-27 的 3983～4022 水平），`换手因子缺失` 跳过数回到 **≤50**。
- **一致性验收（防口径漂移）**：若走"volume/流通股本 现算换手率"路线，取仍有原始 turnover 的历史日做**双口径对照**，断言现算值与原始值的相对偏差在可接受范围（如中位相对误差 <2%），否则会引入新的因子口径断层。
- **排序有效性验收**：修复前(6只)与修复后(≥3900只)的 TopK **重叠度应当很低**——如果修复后 TopK 还是这 6 只，说明修复没生效或它们真的最低换手；预期是**重叠度低**，正好反证"修复前的排序是数据偏差产物"。
- **熔断验收**：人工把 turnover 置空重放，断言视图输出 `present=false`/"数据不足·本日不出"且 log 有 WARN，**不再输出小样本 TopK**。
- **前向观测口径不受影响**：策略10 本身仍是"前向观测中、非已验证 alpha"（视图自带诚实标注）。本次修复**只恢复它的可评估性**——注意 08-28～09-02 这 4 天的前向观测样本应**标注为无效并从统计中剔除**，否则会污染策略10 的前向记分。
- **kill-switch**：数据修复无需开关；熔断规则建议带阈值配置（可调、可关）。

## 6. 实现 + 验收结果（2026-09-03 实现窗）

### 6.1 根因定位（比 §2 更进一步：坐实"整列 None"的来源环节）

§2 只到"raw 分区 turnover 整列 None"。实现窗顺着**主档推进环节**查到真正的供给缺口：

- 分析层 `market.load_kline_recent` **主档优先**（`data/master`），不是读 raw 分区。实测主档
  `002155/000001/…` 近端 **volume 有值、turnover/amount 整片 NaN**，且 `meta.source = "fallback_advance"`。
- `fallback_advance` 来自 [tools/collectors/master_sync.py](../../../tools/collectors/master_sync.py) 的 `_advance_master_from_raw`：
  盘后闭环 `sync_master` 的**当日增量**正常走 `fetch_spot_all + update_master_from_spot`
  （akshare spot 带 换手率/成交额），**但该 spot 增量近期失败** → 回退逐只腾讯 `fetch_kline`
  （腾讯 fqkline 端点**结构性不给 成交额/换手率**，仅 volume）→ 回退把 volume-only 尾部 bar
  推进了主档。于是 **~2026-08-19 起主档近端 turnover/amount 整片 NaN**，与 §1 时间线吻合
  （08-28 断崖 = 最后一批带换手的旧交易日集体滚出 20 日窗口那天）。
- 一句话根因：**"spot 增量(带换手) 失败 → 腾讯回退(volume-only) 推进主档"这条降级链，把换手/成交额供给悄悄断了**，而下游无任何告警。

### 6.2 落地方案（两道防线，均带 kill-switch）

单一配置真源：`THRESHOLDS["反转低换手"]["换手数据护栏"]`（[tools/config/strategy.py](../../../tools/config/strategy.py)）。`启用=False` → 两道防线全 no-op（回到现状）。

1. **治本 · 换手率/成交额现算兜底**（纯函数 `reversal_turnover.derive_missing_turnover_amount`）：
   近端缺 turnover 但有 volume 时，用**同票近端 (turnover/volume) 中位比率**现算
   `turnover = volume × r_med`（换手率% = volume(股)/流通股本×100，同票比率近似常数）；
   `amount ≈ volume × close`。
   **自校验拒填**（绝不注入伪值）：①参考点数 < 门槛 或 ②比率稳健离散度 MAD/median 超上限
   （除权/口径漂移）→ 整票不现算；③单 bar volume 越出参考中位量的 [1/跳变上限, 跳变上限]
   （单位跳变，如 688432 近端量放大 ~70×）→ 该 bar 拒填，留 NaN 交护栏。
   **防未来函数**：比率只用"缺口之前"的有效点（缺失区恒在序列尾部），回测 `series[:t+1]` 切片后调用天然不泄露。
2. **护栏 · 覆盖率熔断**（纯函数 `reversal_turnover.coverage_gate`，管线组装视图时调用）：
   `换手覆盖率 =(可评估票数 − 换手因子缺失)/可评估票数`。
   覆盖率 < `覆盖率_不出下限`(0.30) 或 有效样本 < `zscore_最小样本`(200) → `present=False`「数据不足·本日不出」+ **WARN**，
   **不再输出小样本 TopK**；覆盖率 ∈ [0.30, `覆盖率_警示下限`(0.50)) → 仍出但打 **⚠** + WARN。阈值全可调、可关。

改动文件：`tools/config/strategy.py`（护栏配置块）、`tools/strategy/reversal_turnover.py`（现算 + 熔断纯函数）、
`tools/pipeline/screen_reversal_turnover.py`（装载序列时现算、组装视图时熔断 + 写覆盖率/现算统计 + WARN）、
`tests/test_reversal_turnover_guardrail.py`（新增 20 断言）。

### 6.3 验收结果（离线全A实测，2026-09-02 数据）

| 口径 | 修复前（现算前） | 修复后（现算后） | 验收目标 | 结论 |
|---|---|---|---|---|
| 换手因子有效样本（全A 5196 可评估） | **8** | **4567** | ≥3900 | ✅ 达标 |
| 换手覆盖率 | **0.2%** | **87.9%** | 恢复满覆盖 | ✅ |
| 成交额(流动性)覆盖率 | 0.2% | **100%** | 恢复 | ✅ |

### 6.4 失效期前向观测样本处置（§5 待决 → 结论：作废并记一笔）

**08-28 / 08-31 / 09-01 / 09-02 这 4 个交易日的策略10 前向观测入选样本，应标注为"数据缺陷期·无效"并从策略10 前向记分中剔除。**
理由：这几天入选票是"换手采集覆盖最多"的数据可得性偏差样本、非"换手最低"，横截面排序无经济含义；
纳入会得出"策略10 突然只选到烂票"的错误结论。建议统筹在策略总览/前向记分处执行剔除。

### 6.5 同类隐患（§3 提议6 核查结论 → 建议同法复用现算兜底）

同一根因（主档近端 turnover/amount NaN）确认波及另两处，均**静默降级**、非崩溃：

- **量价放量(S04)**（[tools/pipeline/screen_volume.py](../../../tools/pipeline/screen_volume.py)）：`单日放量` 子信号读 `kdf["turnover"]`，
  换手 NA → 该子信号"不适用"（`"换手": null`），退化为只靠涨幅+均线。
- **指标条件化状态排序**（[tools/pipeline/screen_conditional_rank.py](../../../tools/pipeline/screen_conditional_rank.py) L96-98）：用近20日 `amount` 均值作
  per-stock 流动性次级排序键，amount NA → `amount_wan=None`，同状态格并列的流动性破并列失效。

`derive_missing_turnover_amount` 为通用纯函数，**建议后续在这两处装载序列时同法调用**（即 §5 设想的"输入完备度"通用机制的第一步）。本轮范围限策略10，未改这两处，仅记结论。

> 上游根因兜底建议（超本轮范围，供统筹排期）：真正的治本还在采集端——让 `master_sync` 的腾讯回退路径也补上换手/成交额（现算或换源），
> 或修复 spot 增量本身，避免"volume-only 推进主档"再次发生。当前实现是在**消费侧**兜底 + 熔断，已足以恢复策略10 可评估性并杜绝静默失效。

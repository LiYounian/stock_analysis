# 策略建议 · record 会过期的块（fundflow 等）需自证口径日期 + provenance 改三态

> 状态：**提议**（只提议、不改代码）。来源：2026-09-04 盘中核实 §五问题1 + 移交盯点验证。⚠️ 非投资建议。

## 问题
`data/analysis/<日>/<code>.json` 里"会过期的块"（`fundflow` 等）存在**"沿用昨日值却标 provenance=true"**的风险，下游无法分辨"当日真取到"与"沿用旧值"。
- 证据（一行）：301246 在 2026-09-02 与 2026-09-03 两份 record 里的 `fundflow` 四个字段（−15894219.0 / −12.71 / −31080593.0 / 0）**逐字节相同**，而 `provenance.fundflow` 两天都是 `true`。
- 影响：09-03 复盘移交的"301246 主力是否转净流入"盯点，次日**仍无法验证**（口径过期不可采信）。这正是 commit `07f6469`（"会过期的 record 块一律自证口径日期"）要治的问题，但 `fundflow` 块显然未被覆盖（块内无任何 `as_of`/采集时刻字段）。

## 建议
1. `fundflow`（及同类会过期块）内**增加 `as_of` / `captured_at` 自证字段**。
2. `provenance` 从布尔改为**三态 `{ok | stale | missing}`**：沿用旧值时标 `stale` 并带 `source_date`，真缺时标 `missing`，不再用 `true` 掩盖过期。
3. 下游（选股/复盘）遇 `stale`/`missing` 一律按"未取数/口径过期"处理，不得当当日实况引用。

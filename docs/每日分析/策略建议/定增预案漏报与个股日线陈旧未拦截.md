# 策略建议 · ①存量融资"推进中定增"漏报 ②个股日线陈旧未被策略视图拦截

> 状态：**提议**（只提议、不改代码）。来源：2026-09-04 盘后选股逐票尽调。⚠️ 非投资建议。

## 问题 1 · `equity_financing` 的「推进中定增」对新披露预案漏报

经验沉淀 §6「待验证假设」已把**"有无存续可转债/定增/解禁"列为逐票固定一问**，本次照做，用 `tools.collectors.equity_financing` 的 `summarize_asof()` 查 5 只票。结果 **603162 海通发展** 返回：

```
固定一问: 有存续可转债=False  有推进中定增=False  有临近解禁_90日=True
定增: 推进中 0 笔 / 已实施锁定中 0 笔
源状态: {'定增': 'qbzf+公告检索'}      ← 注意：本票**未降级**
降级: []
```

但事实是：**2026-09-03 晚间该公司刚公布定增预案，拟募资不超 20 亿元用于船舶购置项目**；2026-09-04 17:18 又公告"股票交易异常波动，定增事项尚需审批"。这是当下驱动它两连板的**核心催化**，而"固定一问"给出的答案是"没有推进中定增"。

关键在于：**其它 4 只票的 `源状态.定增` 都是 `'qbzf+公告检索不可得'` 且 `降级` 非空**（会提示"推进中定增不可判"），唯独 603162 显示检索**成功**、降级为空——也就是说这不是一次"我知道我没查到"的诚实降级，而是一次**"我以为我查到了，结论是没有"的静默假阴性**。下游若信任这个 False，会漏掉最重要的那条基本面变量。

推测原因：`qbzf`（全部增发）接口只收录已进入发行/实施阶段的定增，**董事会预案阶段（尚需股东会+交易所+证监会审批）不在其中**；而公告检索这一路对"向特定对象发行A股股票"这类标题的匹配可能没覆盖到。

### 建议

1. **区分三种返回值**，不要把"查到了且没有"和"查不到"压成同一个 `False`：`有推进中定增 ∈ {是, 否, 不可判}`。当仅 `qbzf` 可用而公告检索未命中时，一律返回 `不可判` 而非 `否`。
2. **补预案阶段的采集口径**：把「董事会预案 / 股东会审议 / 交易所受理 / 证监会注册」纳入 `阶段` 枚举，来源可用巨潮公告标题正则（`向特定对象发行`/`非公开发行`/`定增预案`/`募集资金`）+ 已有的 `announcement` 采集器交叉。
3. **降级信息要按票给**：本次 5 只票里 4 只降级、1 只未降级却给了假阴性，说明降级标记的粒度/触发条件与实际可靠性不一致，需对齐。
4. 逐票分析侧的临时兜底：**"固定一问"的答案必须与当日 `baidu_news`/`announcement` 交叉一次**，不能只信 `summarize_asof` 的布尔值。本次正是靠新闻标题才发现矛盾。

## 问题 2 · 个股日线陈旧（缺 4 个交易日）未被策略视图拦截

**002870 香山股份** 出现在 2026-09-04 的 `量价放量`（连续放量）、`最大范围选股`、`SEPA合格池`/`SEPA观察池` 四个视图里，各视图 `as_of` 均为 `2026-09-04`。但 `data/master/kline/002870.parquet` 的**最后一根 bar 是 2026-08-31**，缺 09-01/09-02/09-03/09-04 共 4 个交易日。

于是这些视图实际是拿 **08-31 的收盘价（53.00，当日 +6.23%）当成 09-04 的状态**在打分和入选。按"口径多样性"排序时它排在并列第一档，**是本次选股差点选中的票**（对账 `last bar` 时才发现）。这属于**用陈旧数据冒充当日数据**，与经验 #16 的红线同类。

### 建议

1. **screener 层加新鲜度门**：所有策略视图在取 `closes_loader` / kline 时，校验 `df['date'].max() == as_of`，不等则**跳过该票**并计入 `跳过数(数据陈旧)`，在视图元信息里列出被跳过的代码。
2. 视图里增加 `数据新鲜度` 统计（`最新bar=as_of 的票数 / 有效样本`），低于阈值时整份视图标 `degraded`。
3. 闭环侧对"连续 N 日未更新"的个股告警，避免个别票长期静默掉队（002870 已落后 4 个交易日仍在正常入选）。

## 对应经验

问题 1 呼应经验 #4（加工分/加工结论要用原始消息面对账）与 §6 固定一问；问题 2 呼应经验 #16（防未来函数与数据时点自证）——**"用过期数据冒充当日"和"用未来数据"是同一红线的两侧**。

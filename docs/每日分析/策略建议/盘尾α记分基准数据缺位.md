# 策略建议 · 盘尾复盘缺"当日收盘横截面"产出：α 记分基准要靠现场临时拉 5214 只票复算

> 来源：2026-09-03 盘尾复盘。经验 #11 要求 α 记分基准用**全A等权 mean_pct + 全市场中位数**，但**没有任何现成产出提供"当日收盘的全市场横截面"**，本次只能现场对全A票池批量拉腾讯报价（5214 只 / ≈105 个批请求）临时复算。
> 状态：**待统筹排期**。
> 优先级：中高（每个交易日的复盘记分都依赖它；口径错会让整条经验链的胜负判断失真）。
> ⚠️ 非投资建议。本文档只提议，**不改代码、不改任何定时任务配置**。

---

## 1. 动机（09-03 实际踩到的三个问题）

### 问题A · α 记分基准无现成数据源
09-03 收盘实况：

| 口径 | 当日 | 读法 |
|---|---|---|
| 上证 / 沪深300 / 中证500 | +0.02% / **+0.10%** / +0.34% | 指数看起来"中性偏暖" |
| **全A等权 mean_pct** | **-0.305%** | 个股实际承担的β |
| **全市场中位数** | **-0.605%** | 典型个股在亏钱 |
| 涨跌家数 | 涨 1805 / 跌 3274 / 平 135 | **净广度 -0.282** |

**指数与等权/中位数背离 0.4~0.9pp。** 用指数当α基准会系统性错判（本日 688569 用指数看"跑输不多"，用等权看是真跑输；002811 的 +7.84% 用指数记 α +7.74pp、用等权记 α **+8.15pp**）。
但现有产出里**拿不到这三行**：
- `market_forecast.json` 由 **18:36 的选股任务**生成（复盘 15:10 时还不存在）；
- 且它的广度维是**用于预测的 as-of 特征**（`tools/analysis/market_forecast/breadth.py`），语义是"截至该日的因果特征"，**不是"给复盘用的当日收盘实况快照"**；
- `data/analysis/<date>/` 当日目录在 15:10 时是**空的**。

### 问题B · 现场绕行的成本与不可复用
本次绕行 = 一段临时脚本扫 `data/master/kline/*.parquet` 取票池（5214 只，排除北交所）→ 按 `_BATCH=50` 批量拉 `qt.gtimg.cn` → 按 `market_forecast/features.py` 的 proxy 定义算 mean_pct。
问题：**不落盘、不可复用、无审计留痕、每天重复一遍**；且未来若换分析师（含中小模型），大概率**不会做这一步**，直接退回用指数当基准 → 经验 #11 形同废纸。

### 问题C · 盘尾复盘(15:10) 早于当日闭环(18:36)，资金/筹码类盯点系统性不可验
09-03 有 **6 条盯点**因此标"未取数"：
- 603270「逐笔主买占比能否翻正」（无 `tick`）
- 301246「主力能否转连续净流入」「融资余额是否继续单边增」（无 `fundflow` / `margin`）
- 002084「龙虎榜席位性质」（无 `lhb`）
- 002811 / 301246 的资金侧交叉验证
这不是分析师偷懒，是**排期结构决定的**：复盘在闭环前 3.4 小时跑。

## 2. 诊断（根因）

1. **产出定位缺位**：`market_forecast` 的广度模块是"预测特征"，没有一个模块负责"**盘后横截面实况快照**"这个语义。二者时点与用途不同（前者因果 as-of、供模型；后者当日收盘、供记分）。
2. **依赖顺序倒置**：复盘任务 15:10 依赖的数据由 18:36 的任务生成。
3. **口径只在文档里、不在数据里**：`tools/analysis/market_forecast/forecast.py` 已把"个股β基准默认 proxy"写进产出说明（09-03 已接生产），但**复盘侧的 α 基准没有对应的机器可读字段**，只能靠分析师读经验文档自觉执行。

## 3. 改进提议（只提议）

### 提议1（主）· 新增轻量产出 `data/analysis/<date>/market_eod.json`
**内容**（一个文件、一次全市场批量报价即可，无需闭环）：
- `mean_pct`（全A等权当日涨幅，proxy 定义）、`median_pct`
- `adv` / `dec` / `flat` / `net_breadth`
- `limit_up` / `limit_down`（沿用 `breadth.py` 的按板块涨停线启发式）
- 横截面分位 `p10/p25/p75/p90`
- `benchmarks`：上证/深成/创业板/沪深300/中证500/中证1000/中证全指/科创50 的收盘与涨跌
- `divergence`：`index_vs_equalweight`（HS300 − mean_pct）与 `flag`（背离 ≥0.3pp 置 true）
- 自证字段：`captured_at` / `nominal_at` / `drift_seconds` / `source` / `universe_size` / `missing`

**触发方式**：沿用 09-03 已落地的 **OS 级 launchd 快照节点**同一机制（`tools/pipeline/intraday_snapshot.py` 已有 `fetch_quotes()` 批量能力），加一个 **15:05 收盘槽位**（`slot=eod`），耗时量级与盘中快照同级。
**好处**：复盘任务 15:10 开工即可读；口径固定在代码里而非分析师自觉；有 `captured_at` 可审计；顺带给选股任务（18:36）省一次全市场扫描。

### 提议2 · 盘尾复盘与闭环的时序（**只提议，本任务不改 cron**）
两个可选：
- **(a) 复盘拆两段（推荐）**：15:10 段只做"**收盘价 + market_eod 即可完成**"的记分（方向命中/α/盯点里的价量项）；资金/筹码/龙虎榜类盯点移到**次日晨间的补验段**（届时当日闭环已跑完）。改动小、不动闭环排期。
- **(b) 把复盘挪到闭环之后**（如 19:30）：能一次验完，但 ①复盘产出会晚于选股任务，而选股要读经验新版 → 依赖成环，需同时挪选股；②闭环任何延迟都会把复盘顶掉。**风险高于收益，不推荐。**

### 提议3 · 把 α 基准写成机器可读字段
在 `market_eod.json` 里显式给 `alpha_baseline: {"primary": "mean_pct", "secondary": "median_pct", "background": "hs300"}`，与 `forecast.py` 已声明的"个股β基准默认 proxy"对齐，让复盘侧的基准选择**不依赖分析师记不记得经验 #11**。

## 4. 验收 / 回测口径

- **正确性**：用 09-03 本次现场复算值作黄金样本——`mean_pct = -0.305%`、`median_pct = -0.605%`、`adv=1805 / dec=3274 / flat=135`、`net_breadth = -0.282`、`universe=5214`。新产出须**逐项复现**（浮点容差 0.005pp）。
- **离线回溯**：对 2026-08 全月用 `data/master/kline` 离线复算 `market_eod`（收盘价已有，无需触网），检查与当日各指数的**背离分布**：
  - 达标标准：能算出每个交易日的 mean_pct/median/广度，缺样率 < 1%；
  - **必要性证据**：统计"|HS300 − mean_pct| ≥ 0.3pp"的交易日占比。**若占比 > 20%，说明用指数当α基准会经常错判，本提议必要**（09-03 单日背离 0.4pp）。
- **kill-switch**：删除 `market_eod.json` / 关掉 15:05 槽位 → 复盘退回"现场批量复算"的现状，无其它模块依赖，零副作用。
- **不改动**：`market_forecast` 的预测口径与 `breadth.py` 的 as-of 语义**一律不动**（新产出是并列的第二个模块，不复用它的因果窗，避免污染回测）。

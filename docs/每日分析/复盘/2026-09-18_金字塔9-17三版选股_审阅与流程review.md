## 2. (a) 三版为什么是这样——举证

### 2.1 都真走了流程
- **召回独立**：575 票里 455 只只来自 K 线过闸（全 A 独立扫描），只有 8 只来自 agent 主线（且全部是千问 agent 的票，见 §4 P0-3）。三版没有一只买入/规避票在 top15 之外，符合"不加池外票"边界。
- **骨架数字全对**：三版文中每票的骨架分与五子分（如 300776 = 量价100+板块40+共识50+排雷70+宏观40 → 64.50）与重跑一致；DeepSeek/千问的 adjust_log 序位（#3 600410、#4 688498、#5 688795、#6 000725、#7 002531、#8 300776、#9 301571、#15 300559）与表 1.1 完全一致。Claude 版写的 #2/#5/#6 及"#3～#4 高位不选"亦一致。
- **浓缩块引用属实**：DeepSeek/千问的 evidence 字段（"pos60: 0.45【中】中枢区"、"量比1.96≥1.5∧收阳∧站上MA5∧破前高"、"角色: 龙头·主选（板块roster）"）都能在 `price_volume`/`gate`/`sector_context` 的 to_prompt 输出里找到原句；Claude 版的"vsMA20 −14.3%""距60高 −39.5%""净催化强正 net96"同样是工具原值。

### 2.2 三版差异只落在"骨架未表达的维度"
当时 top15 可分三簇：
- **高位簇 7 只**（pos60 0.74～0.90：600410/688498/002531/301571/603042/688620/300559）——三方都没买，DeepSeek/千问把其中 301571/300559 列规避，Claude 列 603042。**三方一致回避高位是骨架里 pos60 档只给 0/8/15 分、区分度不够的补偿**。

- **低位簇 3 只**：688795（vsMA20 −14.3%、财报高危）、000725（爆量 2.90、财报"中"）、300776（干净）。

### 2.3 排雷子分 = 数据覆盖代理（当时 top15 的最大隐性驱动）
- `fake_good_news` 在 events 缺失时返回嫌疑档"低"（源码 `档 = "中" if 命中>=2 else ("低" if 命中==1 else "低")`，即 0 命中也是"低"）→ `子分_排雷` 给 70。有 per-stock json 且近 7 日无利好 → "无嫌疑" → 100。
- 当时 556 只排序票：排雷 70 的 **541** 只、100 的 **15** 只；那 15 只就是有 per-stock json 的 002025/688795/000725/002870/002095/688185/688130/002174/688553/300502/300308/603199/002142/601838/600995。
- 4.5 分骨架分（30×0.15）在一个 64～66 分密集区里是决定性的。**反事实**（missing 视同无嫌疑）：top15 变为 301551 74.90 / 600410 / 688498 / 002531 / 300776 69.00 / 301571 / 603042 / 688620 / 300205 / 300689 / 301165 / 300559 / 603528 / 300207 / 002137，**002025、688795、000725 全部出局**。
- 结论：三方对照里"002025 分歧=P2 缺口"只说对一半；另一半是排雷维度奖励了"有档但没近期利好"的票，而这批票里恰有财报最差的两只。补 P2 后这两只被 veto，问题被掩盖但根因（missing 降分）仍在，会继续压低 541 只无档票。

### 3.2 成因分析
1. **骨架结构决定了 80%**：top15 低位票只有 3 只、龙头只有 1 只，任何"回避高位"的 LLM 都会落到 301551+300776+{002025|688795|000725}。Claude 的选择空间只在第三只。
2. **仓内跨文档先验，不是"经验"**：`docs/计划/2026-09-18_D2原型_闸门排序回填_9-17试算.md`（09-18 00:34 入库）第 51 行已列"财报高危红旗 5（002025 评级差；…688795 存货高企）"；`H1H5 诊断` 文档也记了 688795 剔除原因。Claude Code 版是统筹窗口手做，读过这些文件，所以能在骨架无财报维度时"补雷"。这解释了为什么 DeepSeek/千问（只看决策包）补不了——**它们的输入被严格限定在决策包内，Claude 的输入没有**。三方对照把它归为"经验"低估了输入不对等。
3. **形态偏好被骨架牵引**：同一天同一 agent 的过渡版（`金字塔统筹_ClaudeCode.md`）买 600995/601061/300308，全是**缩量回踩**防御票（"今日 −1.78% 缩量回踩近20日低点"）；换成骨架后立刻变成**放量突破**票。开发日志 §四.2 也自述"骨架偏好放量突破，把缩量回踩票排后面"。所以"Claude 偏放量突破"不是 Claude 的偏好，是骨架的。
4. **跨版本一致的只有"低位"**：过渡版 300308 pos60 0.197、本版 000725 0.13 / 300776 0.22，两版都把 pos60 极低当核心买点。这是 Claude 自身较稳定的倾向（源于经验散文里反复出现的"不追高"）。

### 3.3 对 09-18 收盘的提前假设（仅用 ≤09-17 信息；forward 口径见 `tools/review/model_a.py`：限价=首入场，D+1 最低价触及才成交；成交后 D+1 低点<MA5 记 stop_flag，D+1 收正且未破 MA5 才持到 D+2）

**先说结构性前提**：三只买入的限价都是 MA5，分别需要从 09-17 收盘回撤 −2.4% / −6.6% / −5.7% 才能成交。对刚放量突破的票，这意味着：
- 若 09-18 延续强势 → **未触发，记"踏空"(runaway_up)**，不计盈亏；
- 若回撤到 MA5 成交 → 低点大概率已≤MA5，**stop_flag 几乎必然为真**，只能按 D+1 收盘离场。
所以对这三只，"兑现"的实际含义是 **runaway_up 为真**（票涨了但没买到），"证伪"是成交后 D+1 收盘低于限价。评价时要把"方向对/错"与"撮合到/没到"分开记。

## 4. (c) 流程与参数 review（按优先级）

### P0（会直接扭曲排序或放进不该进的票）
1. **排雷子分对 missing 降分**（§2.3）。`fake_good_news` events 缺失时应返回"无嫌疑/不可判"且排雷子分给满分（或独立标 `coverage=missing` 不进分），否则 541/556 的无档票被系统性压 4.5 分。修复后需重跑 9-17 验证 top15 变化（反事实已给：002025/688795/000725 出局）。语义锁测试要加"missing 不扣分"。
2. **K 线过闸没剔 ST**。`shared_pool._scan_kline` 只用 `metrics`+`in_pool`，pyramid_select_v1 的 ST/退市名称过滤在 `hard_veto`，没被复用。9-17 池内 16 只 ST/*ST（300205 *ST天喻 / 002217 ST合力泰 / 600818 ST中路 / 600476 *ST湘邮 / 002360 / 600423 / 300338 / 603822 / 600165 / 603377 / 300462 / 600365 / 002816 / 603557 / 300419 / 688121），*ST天喻 当时骨架 #12、现在 #9。应在召回层剔除，并在 `veto_reason` 加"ST/退市"兜底。
3. **agent 主线只读 `selections` 键**。DeepSeek agent 收盘 json 顶层键是 `选股`，`_load_agent` 读不到 → 9-17 agent 主线 8 票全是千问的，DeepSeek 的 600995/002033/601061/002204 + 4 观察票没进"来源标签"。修 loader（兼容 `选股`/`selections`），并在 `shared_pool` 浓缩块里按 agent 分开计数。

### P1（影响可用性与可回测性）
4. **入场方式一律"回踩MA5"与骨架偏好矛盾**（§3.3）。`d2_package` 对每张卡片调 entry_price 时未传 method，全走 MA5 限价，对刚 T1 突破的票要等 −2%～−7% 回撤；止损又固定为 MA20，MA5≈MA20 时止损只剩 −0.1%（301551）。建议：按 gate 层级/形态自动选方法（T1 破前高 → `突破新高确认` 受控追高旁路；T2 → 回踩MA5），止损加 ATR 或最小距离下限；LLM 只在候选方法中选，不写数字。
5. **宏观催化 = 板块净催化数值** 实际是新闻条数放大器（§2.4）。建议：净催化档改为按板块内利好占比或分位截断，或先把权重从 0.10 降到 0.05，等 P3 `market_regime` 建好再接 β 定调。
6. **策略共识维度信息量低且与板块角色双重计分**。council missing、多策略仅 4 票（由 `每日选股.json` 5 picks 派生）、agent 8 票；实质上 50 分只来自"roster∩K线"（19 只），其余 25 分。而 roster 成员本身就是 `板块角色` 的角色分来源 → 同一事实计两次（0.25+0.20）。建议：来源计数改为"有效来源数/present 来源数"归一，或把 roster 从共识分母里拿掉直到 council/多策略源稳定。
7. **并列严重、topN 边界靠代码排序**。前 40 里 62.70×6、62.50×4、61.45×4、64.45×3、64.35×3；#15 300559 与 #16 603528 同分 64.09，进 top15 只因代码顺序。建议加连续 tie-break（如 量比、涨幅、−pos60 的标准化和），或 topN 改为"分数阈值 + 上限"。
8. **经验规则在骨架里等于零**。`experience_rules` 按 code 过滤要求规则原文引用该代码，9-17 池内命中 >0 的仅 4/556 只；`排雷` 子分的经验项从未触发。建议：按环节（排雷/排序）取通则进浓缩块给 LLM 读，骨架里的经验扣分改成基于结构化条件（如"连续 3 日放量减分"）而非 code 引用。

### P2（覆盖、留痕、口径）
9. **财报覆盖**：9-17 目录 per-stock json 84 只（83 只有 financial 字段），落到召回池内只有 15 只有档；财报 veto 只对"恰好有档"的票生效，等价于选择性惩罚。P2 的真正工作是把慢变财报字段铺到全池（至少铺到 K 线过闸 475）。
10. **召回阈值**：池条件 = 收阳 ∧ >MA5 ∧ 1%≤涨幅<9% ∧ 量比≥1.2 ∧ pos60<0.95，与 T2 条件重叠，T3 恒空（池内 T1 266 / T2 215 / T3 42 / 未入层 33，后两类来自 roster/agent 源）。两个可商量点：① 涨幅上限 9% 对 20cm 板一刀切，9%～19.5% 的强势创业板/科创票全被 K 线源排除，只能靠 roster 进池；② 量比 1.2 偏松（放量 444 / 爆量 53 / 平量 53 / 缩量 6），可考虑量比≥1.3 或加 20 日均额分层。是否改要看 forward。
11. **审计链**：决策包文本与 LLM 原始回复应默认落 `data/analysis/<as_of>/金字塔决策包_<as_of>.md` 与 `_raw_<label>.txt`；否则无法复核"LLM 看到了什么"。同时 `render_md` 的"计分 N"改用排序票数（556）并注明含义。
12. **LLM 产数字校验**：渲染/校对层对 thesis/discipline 文本做数字正则检查（价位形状的小数），发现即告警。Claude 手做版也应过同一校验（"可放宽到 20.8/110" 就该被拦）。
13. **检验设计**：财报/估值类维度不用 D+1 验，改 10～20 交易日窗口的回撤与相对收益；D+1/D+2 只验量价与撮合。三方对照 §四 的"002025 财报隐患是否 D+1 显现"建议改写。
14. **文本修订**：Claude 版 601571→301571；"DeepSeek/千问曾关注"改为"千问 agent 观察 5.5"；删去"可放宽到 20.8/110"或改为方法名（如"止损可改用 MA20 下 ATR 一倍"由程序回填）。

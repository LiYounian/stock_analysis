## 0. 结论摘要（10 条）

1. **财报是最新的但当时没人用**：per-stock financial 全部为 2026-06-30 半年报（披露 08-20～08-29、分析日 09-02～09-08），as_of 09-17 下这就是最新可得口径。但 9-17 三版的决策包里**没有财报块**，DeepSeek/千问零财报输入；Claude Code 版靠仓内文档先验。
2. **财报工具现在也有严重口径 bug**：84 只候选里 28 只评级"**风险**"（quality 低至 2.87），`_redflag_verdict` 只认"差"→ "风险"只落"中"（扣 30、不否决），而"差"（quality 35～50）反而"高危"否决。**最差档位漏判**。
3. **基石里 35% 权重压在一个自标"不进生产选股"的模块上**：sector_focus/regime 的诚实边界写着 "forward-shadow·non-gating·不进生产选股(P3 gated 才接)"，D2 却用它算 板块角色 0.25 + 宏观催化 0.10。
4. **评分口径有一处自相矛盾**：量价子分给低位 +15（×0.30），板块角色子分的 RS 档给高位 +30（×0.25）。同一个 pos60 两套词、两个方向，净效果**偏向高位 1.75～3.0 分**，与设计稿"偏好低位放量突破"相反。这直接解释了当时 top15 有 7 只 pos60≥0.74 的票。
5. **拍板③"首入场=D+1 开盘附近限价、回踩=加仓"没有落地**：entry_price 的首入场与加仓位是同一个数（MA5），forward 记分器又用第三套口径（限价=D 收盘）。上篇 §3.3 用 MA5 推的撮合假设**据此修正**（见 §4）。
6. **三方趋同是设计结果，不是模型巧合**：DeepSeek/千问用**逐字相同**的 system+user prompt、同一 15 张卡、temperature=0、单轮、零工具；prompt 里明写"哑铃/降 beta/回避高位与过热拥挤"。Claude Code 版无 prompt 记录，是统筹手工读包。
7. **实验证明：拿掉骨架数字仍趋同**。B 组（top30、删骨架分与序位、卡片乱序）两模型买入**完全一致**：688781 视涯科技 / 688261 东微半导 / 300776 帝尔激光。模型自述权重 DeepSeek "位置 40%/量比 30%/板块角色 30%"、千问 "位置 > 量价形态 > 净催化"——**候选卡只暴露这几个维度，模型只能在这几个维度上有偏好**。
8. **视野确实被锁死**：575 池只给 15 张（2.6%）；召回 K 线源条件（收阳∧>MA5∧涨幅≥1%∧量比≥1.2）**结构性排除缩量回踩形态**；9-17 其他四模式与两 agent 的全部推荐票在骨架里排 #259～#534 或根本不在池；程序候选池 84 只与召回池 575 只交集仅 15。三版看到的世界与前一天 agent 看到的世界几乎不相交。
9. **候选窗一放宽就出坏票**：top30 里千问在温度 0.8 下买入 ***ST天喻 300205**（ST 未剔）；DeepSeek 在 top30 下放弃 301551、转买 pos60 0.87/0.74 的 600410/002531，与它在 top15 下"回避高位"的理由自相矛盾——说明模型"偏好"并不稳定，被候选集结构牵着走。
10. **优化方向**（§5）：先修 6 个确定性 bug；再把"差异化"做成设计目标——给三个 Agent 不同的风格提示词与不同的召回视角（趋势突破 / 低吸回踩 / 事件催化），恢复 G1 公理让 Agent 能自己在池里 list/filter/fetch，骨架退回"参考排序"而非"候选边界"；收盘复盘按 成交/踏空/止损 三态与 T 层拆记。

### 3.4 趋同成因实验（真跑，只落 scratchpad）
候选窗与 prompt 变体对两模型的影响（当前口径骨架，002025/688795 已被财报否决）：

| 变体 | DeepSeek 买 / 避 | 千问 买 / 避 | 两模型买入重合 |
|---|---|---|---|
| 原版 top15·t=0（9-17 正式） | 002025 300776 301551 / 000725 301571 300559 | 688795 300776 301551 / 301571 300559 002531 | 2/3 |
| A top30·同 prompt·t=0 | **300776 600410 002531** / 601579 600088 002137 | 300776 301551 688175 / 601579 002137 600088 | 1/3 |
| B top30·**删骨架分与序位·卡片乱序**·t=0·要求自述权重 | **688781 688261 300776** / 601579 600088 002137 | **688261 688781 300776** / 600088 002137 601579 | **3/3** |
| C top15·t=0.8 | 301551 300776 002531 / 002137 301571 603042 | 301551 300776 ***ST天喻 300205** / 002137 301571 002531 | 2/3 |

模型自述（B 组）：DeepSeek "位置 40% / 量比 30% / 板块角色 30%"；千问 "位置(低位优先) > 量价形态(无长上影/T1) > 板块净催化(强正)"。

**读法**：
1. **趋同的第一来源是候选卡的维度结构，不是骨架数字**。B 组把数字全拿掉，两模型仍选出完全相同的 3 只，且自述权重几乎一样——因为浓缩块只暴露 pos60 / 量比 / T 层 / 角色 / 净催化 / 长上影 这几个维度，任何模型"用自己的偏好"都只能在这几个维度上做单调选择（低位 + T1 + 强催化），答案就唯一化了。
2. **第二来源是 prompt 的风格指令**。"哑铃/降 beta/回避高位与过热拥挤"直接写在能做项里，三份 adjust_log 都用了这套话；C 组温度 0.8 也没跑出别的逻辑。
3. **模型个性是存在的，但不稳定且被候选集牵引**：DeepSeek 在 top15 下规避高位、到 top30 下却买 pos60 0.87/0.74 的 600410/002531（理由改成"趋势完好/逆向逻辑"）；千问在温度 0.8 下买了 *ST。两者的"偏好"更像是**在给定候选集里找相对最不差的**，而不是有稳定投资风格。
4. **骨架数字的作用是"锚"而非"决定"**：A 组 vs B 组，同一 30 只票，有数字时两模型分别保留了骨架 #1/#2/#4；没数字时全去买 #20/#22 的低位电子票。说明 LLM 看到骨架分会给前排票加权（锚定），去掉后完全按自己维度走。
5. **规避端三组完全一致**（601579/600088/002137）：规避是由浓缩块的"极高位 0.94～0.95 / 拥挤 A / 长上影 0.85+爆量 6.73"这几条硬信号决定的，与模型无关——这部分本来就该由程序 veto，不必浪费 LLM。

### 3.5 召回锁视野的量化

- 9-17 其他产线的票在骨架里的位置：DeepSeek agent 推荐 600995 #534、002033/601061/002204 **不在池**；千问 agent 600995 #534、300308 #489、002142 #512、601838 #513、603199 #499、300502 #316；程序选股 9 只推荐 #23～#519 或不在池；定时任务 601872/300802 被否决（涨停/极高位）、601061 不在池；过渡版塔尖 3 只 #489～#534。**前一天所有人看好的票，在这套骨架里没有一只进前 20。**

### 5.1 确定性 bug（先修，无需讨论）

4. `financial_redflag._redflag_verdict` 把评级"风险"纳入最高档（风险 ≥ 差），语义锁加 "风险→高危"。
5. `d2_package`：市场定调与子分改文字渲染（禁裸 dict）；★重点板块改按 focus_score 且排除 过热A/拐点A；决策包与 LLM 原文默认落盘到 `data/analysis/<as_of>/`。
6. `entry_price`：首入场与加仓分离（首入场=开盘附近限价规则待定义，如 前收×[0.99,1.01] 区间挂单），止损加 ATR/最小距离；`d2_package` 按 T 层传 method；记分器与工具统一 `entry_rule` 字段（[D1]§6 H5）。

### 5.2 评分口径（需拍板）
7. **RS档 与 pos60档 二选一**：板块角色子分去掉 RS 项（RS 本就是个股 pos60，不是板块信息），或把"位置"独立成一个基石、统一词表（接 `rubric_map`）。
8. `宏观催化` 权重 0.10 → 暂降或改为"净催化分位/利好占比"截断；等 P3 market_regime。
9. `策略共识` 分母按 present 来源归一；roster 不再同时进 共识 与 角色。
10. 并列 tie-break 加连续项；topN 改"分数阈值 + 分层配额"（见 5.3）。
11. sector_focus 的 "non-gating 不进生产选股" 边界要么解除（补验证），要么 D2 把它降为"上下文"而非基石。

### 5.3 让三个 Agent 真正差异化（结构改动，建议按此方向设计 D2 v2）
- **候选窗从 top15 改为分桶配额**：按 T 层 × 位置 × 形态 分桶（如 T1 低位放量 / T1 中位破前高 / 角色龙头 / 缩量回踩至 MA5·MA20 / 事件催化票），每桶给 3～5 张卡，总 25～30 张。目的：让不同偏好的模型有不同的东西可选。缩量回踩桶需要**新增一条 K 线召回条件**（收阴或缩量 ∧ 位于 MA20 上方 ∧ 5 日涨幅>0），否则该形态永远进不了池。
- **三个 Agent 三套风格 prompt**（用户定义，描述性约束，不塞 case）：如 A=趋势突破派（重 T 层/破前高/板块动量）、B=低吸回踩派（重位置/均线支撑/缩量）、C=事件催化派（重净催化/消息/财报质量）。三方共用同一候选包但**风格指令不同**，趋同才有信息量。当前 prompt 里的"哑铃/降 beta/回避高位"应从"能做项"移到"市场定调给出的当日建议"，由 regime 决定，不写死。
- **恢复 G1 公理**：给三个 LLM 挂 function-calling 工具（`list_pool(filters)` / `get_card(code)` / `run_tool(name, code)`），骨架排序作为 `list_pool` 的默认排序而非边界；限制预算（如 ≤30 次调用），trace 落盘。9-17 收盘 agent 版已证明这条产线能跑（55/64 次调用、trace 完整）。
- **程序 veto 前移**：极高位 ≥0.9、拥挤 A+过热、长上影+爆量 这些三组实验里 100% 一致的规避判据，直接进 `veto_reason`，把 LLM 的注意力留给真正需要判断的票。
- **Claude Code 版必须留痕**：统筹手工做也要落 prompt/读了哪些文件/adjust_log 到同一 json 结构，否则三方不可比。

### 5.4 检验设计
- 收盘复盘按 **成交 / 高开未成交(runaway) / 成交后 stop_flag** 三态记，再看 r_exit 与 α；按 T 层、按位置桶拆。
- 三方 Jaccard（买入集合）作为每日指标；目标不是越低越好，而是**"分歧票的 forward 表现有没有信息量"**——若分歧票的方向命中率与共识票相当，说明多 Agent 有分散价值。
- 财报/估值维度改 10～20 日窗口验证；D+1/D+2 只验量价与撮合。
- 每次改口径（权重/档位/召回条件）都在 9-17 上重跑一次骨架并存档 top30 对照，作为回归基线。

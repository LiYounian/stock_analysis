# 数据采集与分析(每日闭环)

> **是什么**:盘后「拉数 → 全 A 选股 → 贵活只做子集 → 上传远端」的流水线说明,给人读、给策略提供者对齐口径。
> **应用到哪**:本机 launchd `com.stock.pullrefresh`(工作日约 15:40);入口 `python -m tools.run screenall`。
> **应用在什么模块**:`ops/launchd/pull_refresh.sh` · `tools/run.py`(`run_screen_all`) · `tools/collectors/master_sync.py` · 各 `tools/pipeline/screen_*.py`。
> **权威开关**:`PULL_FETCH`、`SCREENALL_NEWS_TOPK`(默认 5);K 线窗口见 `tools/config/settings.py`(`KLINE_DAYS=250`,`DAILY_KLINE_ROWS=500`)。
> ⚠️ 非投资建议。本文写**现在实际怎么跑**和**目标口径差在哪**,不改代码。

---

## 1. 目标口径(要对齐的四条)

1. **每天增量拉全 A 日 K**;一只票历史从**近一年**起够用(约 250 根交易日)。
2. **用策略扫全 A**(不是只扫自选池)。
3. 各策略先筛出大约 **10～30 只**,再从中只取**最好的 5 只**做新闻采集和 LLM 分析。
4. **自选池全部**做新闻采集和 LLM 分析。

---

## 2. 现在是不是这个流程

**骨架是的,有两处明显偏离。**

| 目标 | 现在 | 对齐? |
|---|---|---|
| 每天增量拉全 A K 线 | 能力有(`master_sync`:主档齐则 spot 当日一根;缺/太旧才 baostock 回填)。**已开启**——launchd plist 设 `PULL_FETCH=1` + `FETCH_WORKERS=1`(单进程),每日盘后自采推进主档 | **是**(2026-08-20 起) |
| 历史从近一年起 | 日筛只读近 **500** 根(~2 年),够用。主档里往往是多年全历史,不是「只存一年」。首次回填走 baostock **全历史**,不是只拉 250 根 | **日筛够近一年;落盘更长** |
| 策略分析全 A | `screenall` 对全 A(排除北交,约 5500 只)跑策略 **0/1/2/3/4** | **是**(仅这五条进闭环) |
| 每策略筛 10～30 只 | **没有统一上限**。策略0 固定 Top20;策略4 固定 Top30;策略1/2/3 是规则命中即入,可 0 只也可 50+ 只(08-18:策略2=56、策略3=0、策略1=5) | **部分是** |
| 每策略最好 5 只做新闻 | `SCREENALL_NEWS_TOPK` 默认 **5**:新闻/情绪/财报 LLM 只对「每策略入选清单的前 5 名 ∪ 自选」 | **是** |
| 自选全部做新闻 | `news_subset = 每策略前5 并集 ∪ stock_pool.json` | **是** |

08-18 实证:全 A 筛选 + 中心记录 120 只 + 新闻子集约 31 只(自选 ∪ 每策略前 5)+ 上传 132/132。当天**没有**新 K 线。

## 3. 每日实际步骤(盘后闭环)

工作日 15:40 左右 `ops/launchd/pull_refresh.sh`:

```
① 全 A K 线增量     已开启(plist PULL_FETCH=1);**单进程 FETCH_WORKERS=1** 跑 ops.remote_fetch
                    (spot 当日 bar;失败回退逐只腾讯/新浪)。单进程避 mini_racer 多进程崩,~73min
② screenall --no-fetch
     ├ 策略 0/1/2/3/4 扫全 A(只读主档,不重采 K)
     ├ 便宜分析:选出并集 ∪ 自选 → serialize / 事件 / 多因子 / 合议 / 横表
     └ 贵活:自选 ∪ 每策略前 5 → 新闻/舆情 + LLM 情绪 + 财报三大表/年报/LLM 文本
②.5 前瞻记分卡       滚存 picks vs 到期收益(不阻断)
③ 签名上传远端       tools.sync.upload 当日产物
```

手动等价:

```bash
# 每日闭环已自动开自采(plist 里 PULL_FETCH=1 + FETCH_WORKERS=1)。手动单跑 ① 时:
FETCH_WORKERS=1 python -m ops.remote_fetch --date $(date +%F)   # 单进程,必须 =1 否则 mini_racer 崩
python -m tools.run screenall --no-fetch   # 与闭环②相同;读已推进的主档
```

`python -m tools.run all` **不是**这条全 A 闭环:它默认只跑自选开发子集。

## 4. 两层子集(不要混)

| 集合 | 怎么来 | 做什么 | 贵不贵 |
|---|---|---|---|
| 全 A `codes_all` | `universe.universe_codes()`(剔北交 8/4 开头) | 只做策略 0–4 的规则/排序扫描 | 便宜(K 线近史) |
| 分析集 `llm_subset` | 五策略入选**全部**并集 ∪ 自选 | 中心记录、合议、多因子、事件、横表、上传个股页 | 中(无 LLM 新闻) |
| 新闻集 `news_subset` | 每策略入选清单**截前 5** ∪ 自选 | 新闻/股吧、情绪 LLM、财报 PDF+文本 | 贵(控 token) |

「最好的 5 只」= 该策略 view 里清单的**前 5 个 code**(排序型=分最高;规则型=入选顺序,不是另做一轮打分)。

## 5. 各策略在闭环里出多少票

| 策略 | 全 A 扫描方式 | 入选规模(代码口径) |
|---|---|---|
| 0 多专家合议 | 综合分降序 | 固定 **Top 20**(`screen_council.TOP_N`) |
| 1 趋势深跌反包 | 四条硬规则 AND | 无上限,命中才进(常很少) |
| 2 放量后缩量回踩 | 规则命中 | 无上限(可远超 30) |
| 3 箱体形态 | 规则命中 | 无上限(可 0) |
| 4 动量组合 A 腿 | 动量分排序 | 固定 **Top 30** |
| 5 自选池小市值 | **不进** screenall | Web 对自选 records 实时算 |
| 6 半导体多因子 | **不进** screenall | Web 对 records ∩ 半导体池 178 只实时算;本机自选常为空 |

SEPA+VCP 监控是另一条(`run sepa`,午间/收盘),**不走**本新闻子集,见 [本地部署与监控手册](../参考/本地部署与监控手册.md)。

## 6. K 线「近一年」具体指什么

- 日筛/选股:`load_kline_recent` 默认 **500** 根(~2 年),覆盖 MA200 + 52 周高,比「一年」更宽。
- 单票首次 `fetch_kline` 默认 `KLINE_DAYS=250`(~一年)。
- 每日增量(开启自采时):全 A **一次 spot** 追加当天一根,不重拉一年。
- 主档陈旧超过 7 天或覆盖不足 90%:会 baostock **全历史回填**(重、慢)。
- **mini_racer 崩溃根因订正(2026-08-20 实测)**:曾归因"内存吃紧"**不准**——峰值仅 ~433MB。真因是 **mini_racer(V8)在多进程 fork 子进程里重复初始化**(PartitionAlloc 致命检查,SIGTRAP),`FETCH_WORKERS=10` 触发。**改单进程 `FETCH_WORKERS=1` 即不崩**(全A 5548 跑通、退出码0、峰值414MB、~73min),故 ① 已恢复自动。

「每天都有当天收盘价」现已达成(plist `PULL_FETCH=1`);代价是 ① 串行 ~73min,排在 ② 前。

## 7. 和目标还差什么(若要改代码)

1. ✅ 已做:闭环默认打开全 A 日 K 增量(plist `PULL_FETCH=1`,单进程避崩)。可选进一步:换不依赖 mini_racer 的增量源(baostock/逐只),彻底摆脱 V8。
2. 策略 1/2/3 加「最多 30 / 至少不强制凑 10」的截断,避免新闻前 5 取自一份很长的无序命中表。
3. 策略 5/6 若也要进「全 A → 前 5 做新闻」,需另接 screenall(现在只在选股页用已有 records)。

改这三项前应单独立需求,不在本文改代码。

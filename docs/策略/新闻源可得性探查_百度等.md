# 新闻源可得性探查:百度 / 东财 / 新浪 / 同花顺 / 财联社

> 日期:2026-08-30 · 分支 research/baidu-news · ⚠️ 非投资建议 · 仅研究,未落生产采集。
> 背景:已知 akshare `stock_news_em`(东财个股)只回到 ~2 周 / 10~100 条且有幸存者偏差 → **多年历史新闻重建不可行**(旧定论)。本轮进一步探查:**百度个股页有没有可用接口?能回溯多久?能不能用于历史回测?** 顺带复核东财/新浪/同花顺/财联社。
> 探查方式:少量抽样实测(000001 平安银行、600519 贵州茅台、300750 宁德时代、000002),curl_cffi 伪装 chrome 直连 + 浏览器内 fetch 抓包。**未做绕验证码等破坏性抓取,遵守 robots/合规。** 原型脚本在 scratchpad(`probe_baidu.py / probe_sentiment.py / probe_depth.py / probe_sina.py`)。

---

## 0. 一句话结论

**百度个股新闻能拿到,且质量优于现有源**:公开 JSON 接口 `finance.pae.baidu.com/vapi/sentimentlist`,免登录、curl_cffi 直取、带**真实发布时间戳 + 百度自带利好/利空标签**,聚合了同花顺+东财+证券之星等多家。
**但历史深度受"条数硬上限(≈800~850 条/票)"约束,不是按日期**:低频票(如平安银行)一次可拉到 **~11 个月**、日期连续;高频大票(如宁德时代)只到 **~2 个月**。
**可回测性:不能重建多年历史,但一次性快照可作"数月~1年"的时间戳化 warm-start**;且**前向增量采集应直接换/并入百度**(严格优于当前东财∪新浪∪财联社)。

## 1. 百度个股新闻(重点)

### 1.1 接口(实测举证)

- 百度股市通旧域名 `gushitong.baidu.com/stock/ab-000001` 现 **302 跳转到 `finance.baidu.com`**(已改版为 "FinScope-AI")。个股页顶部有 `概览/资金/简况/股评/资讯/财务/分析` 标签。
- 点"**资讯**"标签实测抓包,新闻列表走这个 XHR:

  ```
  GET https://finance.pae.baidu.com/vapi/sentimentlist
      ?market=ab&code=000001&query=000001&financeType=stock
      &benefitType=&pn=0&rn=20&is_fallback=0&finClientType=pc
  ```

- **免登录、无 cookie 也能取**:curl_cffi `impersonate="chrome"` 直连即 200(与项目现有新浪/UGC 同套指纹)。实测 000001/600519 均直接返 JSON。
- 反爬:**本接口低反爬**(3 次快速连打全 200)。注意同域的 `vapi/v1/getquotation`(行情)**有风控**——无 session 直连返 `403 hit risk / isCaptchaEnabled`;但**新闻这个 sentimentlist 接口不触发**。故采新闻可行,不必碰有验证码的行情接口。

### 1.2 返回结构(每条字段)

`Result[0].TplData.aiSentimentXcxListInfo.sentimentListInfo[]`,每条:

| 字段 | 含义 | 举例 |
|---|---|---|
| `title` | 标题 | "半年报新动向!多位牛散进驻A股银行…" |
| `abstract` | 摘要(1~2 句) | "…截至6月末合计持有平安银行0.99%股权…" |
| `publishTime` | **真实发布时间(unix 秒)** | `1788075687` = 2026-08-30 15:41 北京 |
| `provider` | **原始出处** | 同花顺 / 东方财富网 / 证券之星 / LSEG / 时代周报… |
| `originUrl` / `api` | 原文链接(多为东财 emwap) | emwap.eastmoney.com/info/detail/… |
| `benefitType` | **百度自带情绪标签** | `1`=利好 / `-1`=利空 / `0`=中性 |
| `messageType` | 类型 | `2`=资讯(主) / `1`=少量(疑公告) |
| `news_id` | 去重主键 | 32位hash |

**时间戳是"发布时间"而非"抓取/事件时间"**(已举证):`publishTime=1788075687` 解码 = 2026-08-30,与原文东财文章 id `202608303859…`(日期码 20260830)一致。

**关键增益 vs 现有源**:① 自带 `benefitType` 利好/利空标签(可省一次 LLM 极性判定或做交叉校验);② `provider` 聚合了**同花顺(占比最高)+ 东财 + 证券之星**等多家——比项目当前"东财∪新浪∪财联社"覆盖更广;③ 单次一个请求即可,不用逐页翻。

### 1.3 历史深度(实测,rn 大小决定单次条数,存在硬上限)

`rn` 参数控制单次返回条数,实测**硬上限约 800~850 条/票**,再大也截断。深度 = 条数上限 / 该票新闻密度 → **深度随新闻热度反比变化**:

| 代码 | 名称 | 单拉(rn=1000)条数 | 覆盖时间跨度 | 不同日期数 | 最大日期间隔 |
|---|---|---|---|---|---|
| 000001 | 平安银行(低频) | 789 | **2025-10-01 ~ 2026-08-30(~11 个月)** | 245 天 | 10 天(春节假期) |
| 600519 | 贵州茅台(中高频) | 851 | 2026-04-16 ~ 08-29(~4.5 个月) | — | — |
| 300750 | 宁德时代(极高频) | 830 | **2026-07-07 ~ 08-29(~2 个月)** | 54 天 | 1 天 |

- **窗内是连续的,不是"只留重要新闻"**:000001 在 334 个自然日里覆盖 245 个不同日期、最大空档仅 10 天(恰春节休市)→ 密度接近"逐日基本都有",**不是幸存者式的稀疏保留**。这与旧 akshare 东财源"~2 周只剩 10 条"的强幸存者偏差明显不同。
- ⚠️ **存疑点(已如实记)**:早期用 `pn=20&rn=20` 深翻曾出现 "第0页=近一周、第20条项=5个月前" 的跳变、且 pn≥40 返空;但改用**单次大 rn**(rn=100/1000)拉取则日期连续、无跳变。判断 pn 小步深翻是接口分页 quirk/缓存所致,**采集应用大 rn 单拉**,以连续结果为准。

### 1.4 百度可回测性判定

- **多年历史重建:不可行**。条数硬上限 ~850 条,高频大票只够 2 个月;且这是**"今天"的快照**,只能看到今天仍在供的条目,**被平台后期下架/降权的旧新闻不可见**(残留幸存者风险,无历史快照无法证伪)。
- **数月~约1年的时间戳化 warm-start:可行(有条件)**。因为每条带真实 `publishTime`,一次性拉取后可按发布时间分桶,对窗内任意历史日 D 只用 `publishTime<=D` 的新闻做**无未来函数**的回测切片。低频票能拿近一年、大票只 2 个月——**能覆盖的窗口就能回测,覆盖不到的更早历史拿不到**。
- **前向增量:强烈推荐**。免登录、单请求、带时间戳+情绪标签+多家聚合 → **应并入/替换现有个股新闻采集**,每日盘后快照落库,长期攒成真正干净的前向消息面样本。

## 2. 其它源复核

### 2.1 新浪 `vCB_AllNewsStock`(项目已用)

- 接口:`vip.stock.finance.sina.com.cn/corp/view/vCB_AllNewsStock.php?symbol=sh600519&Page=N`,SSR HTML(gb2312),curl_cffi 直取,**列表带"YYYY-MM-DD HH:MM"发布时间**(用 `&nbsp;` 分隔,解析需先替换)。项目当前只翻 3 页 / 7 天窗。
- 深度实测:**翻页很深、25 页未见空**(~40 条/页)。600519 翻 25 页(999 条)回到 2026-07-17(~6 周);000001 翻 25 页(1000 条)回到 2026-05-07(~4 个月)。同样是**新闻密度决定回溯**,但**未见硬条数上限**,继续翻可能更深(未过度深翻以防限流)。
- 时间戳:✅ 真实发布时间。覆盖:仅**新浪自采/转载**(比百度窄);列表页**无正文**(只标题+链接+时间);**无情绪标签**。
- **可回测性:与百度同级——一次性快照可 warm-start 数月~数月+**;残留"今日快照"幸存者风险同样存在。可作百度的**交叉印证/兜底源**。

### 2.2 东财 `stock_news_em`(akshare,项目主源)

- 深度浅:实测口径 ~2 周 / 10~100 条,越旧越稀疏 → **强幸存者偏差**(旧定论,本轮未推翻)。
- **可回测性:不可用于历史**(窗太短且幸存者化);仅作前向增量的一个并入源。**注意:百度 sentimentlist 的 provider 大量是"东方财富网"、originUrl 是 emwap.eastmoney,等于百度已把东财新闻带时间戳+更深地聚合进来了** → 直接用百度比单独打 akshare 东财更划算。

### 2.3 同花顺(THS)

- 百度 sentimentlist 的 provider 里**同花顺占比最高**(000001 样本 789 条中 500 条来自同花顺)→ **百度已聚合同花顺**,无需再单独接。
- 直连 THS 个股新闻页有 `hexin-v` 动态 cookie 反爬,成本高、收益低(内容已被百度覆盖),**不建议单独接**。

### 2.4 财联社电报 `stock_info_global_cls`(项目已用)

- 另有百度全站快讯 `finance.pae.baidu.com/selfselect/expressnews`(7x24,免登录返 JSON,32KB/页)与之类似。
- 性质:**全市场滚动快讯**,非个股历史归档。带时间、覆盖突发/宏观/管制,**只适合前向增量补盲区**,**不能拉个股历史**。项目现状(总是查并入)合理,维持即可。

## 4. 结论与建议(诚实)

1. **百度能拿到,且是当前最优个股新闻源**:免登录 JSON、真实发布时间、自带利好/利空标签、多家聚合(含同花顺+东财)。建议**前向采集换成/并入百度 sentimentlist**(单请求、覆盖广、省一次极性 LLM)。落生产另起实现分支,本轮只研究。
2. **历史回测:是"部分可行"的修正,不是翻案**。多年历史重建仍不可行(条数上限 + 今日快照的残留幸存者风险)。但**一次性百度/新浪快照能给出数月(大票)~约1年(小票)的时间戳化、窗内连续的新闻切片**,足以为消息面回测做 warm-start / 冷启动种子——比"只有 akshare 2 周"强得多。用时须诚实标注:**覆盖窗口按票而异、更早历史缺失、下架条目不可见**。
3. **前向累积仍是治本**(与现有 `forward_scorecard` 一致):今起每日盘后快照百度个股新闻入库,长期攒成无幸存者偏差的干净样本。

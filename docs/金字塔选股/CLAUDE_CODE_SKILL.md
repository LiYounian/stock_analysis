## 一、你能用什么工具 + 固定查询方式

### 1. 金字塔工具族 registry CLI（首选、权威、防未来内建）
所有塔层数值都从这套 CLI 取，**别自己翻原始文件手算**。两种等价调用：
- CLI：`~/.conda/envs/stock_analysis/bin/python -m tools.pyramid tool <name> --as-of <D> --code <6位代码>`
- 列清单：`~/.conda/envs/stock_analysis/bin/python -m tools.pyramid list`
- 每个工具吐一个 **≤8 行浓缩块**（禁裸 json），每个数值自带【口径】【档位】【一句解释】、内建 as_of 防未来。

现有工具（按塔层，`list` 为准）：

- ②消息面：`stock_sentiment`(净情绪)、`fake_good_news`(假利好嫌疑档)、`unlock_risk`(解禁抛压)、`insider_reduction`(减持抛压)

- ④宏观/板块：`sector_context`(板块/冷热拥挤/RS分位/角色/板块内排名/净催化)

## 三、辩证思考结构（逐票深研 SOP · 移植老流程已验证经验）

只对**骨架 top-N 池内**的票做。挑池内最有希望的一批逐个深研（预算纪律见第五节）。

**读体检卡先分清"缺数据三态"（别把中性/NA误读成利空或缺陷）**：工具浓缩块与体检卡诚实标注三种"没有强信号"的情形，含义完全不同——
①**样本少≠缺失**（如净情绪只有 2 条、结论呈"中性"，是数据少而非没数据，不构成利空）；
②**待补落盘**（该维度数据尚未采集入库，标 missing/待补，是覆盖缺口而非该票问题）；
③**该票无覆盖**（冷门股本就无研报一致预期等，标 NA 属正常，不是缺陷）。
辩证时按真实态读，**不冤枉票**：三态都不等于"利空"，也不等于"数据造假嫌疑"。

每票走：

1. **定性**：这票在决策包里凭什么进池（命中哪些工具档位/板块角色）。
2. **数据层**：用 registry 工具核对塔基/塔身关键档位（价位、量比、pos60、估值、成长质量、财报红旗）——**别手算，取工具浓缩块**。
3. **消息面强制查证（硬）**：用 `news_raw`（或 Read baidu_news 原文）**看来源、看时间、看是否已兑现**。
   - 净情绪标量只是入口；必须落到"这条利好**来源可信吗、是否高开走弱/放量长上影/利好后回吐**"。可疑就查 `fake_good_news`。
   - 本地不足判真伪时才用 WebSearch 补一条外部信源。
4. **数据 × 消息面交叉**：量价形态与消息面是否互相印证还是打架（如利好却放量长上影＝出货嫌疑）。
5. **我 vs 系统出入（硬）**：明确写出**你的研判和决策包/工具档位在哪不一致、你更信谁、为什么**。这是辩证的核心，不许略过。
6. **明确表态、不对冲（硬）**：给**买入 / 可参与 / 观望 / 规避**之一 + 理由。禁止"可以关注但也有风险"这种两头堵。
7. **方向前提 = 触发信号（硬）**：若你的看多方向依赖**尚未出现**的触发信号（放量收阳/主买翻正/催化落地），则**只能给"低波动待动"、不得给方向**。形态好/估值便宜/筹码集中这类**静态依据只支持"下跌风险小"，不支持"上涨动能强"**。
8. **退出/止盈纪律必填（硬·买入候选）**：写清**第几天、什么条件下减/清**（价格位/形态破坏/时间止损/催化落空）；若次日涨停封板卖不出，预先写明怎么处理。不许只写"只做短线"这种没有触发条件的话。
9. **盯点单问化（硬）**：每条盯点是**可独立判定的单一问题**，能用"是/否/无数据可判"回答；复合条件要拆开。估值/筹码环节固定加一问"有无存续可转债/在推进的定增/临近的限售解禁"。
10. **区分 α / β（硬）**：逐票深度结论必须把**个股 α（这票自身实力/催化）**与**大盘 β（市场整体行情）**分开——β 用 `market_forecast` 的**选股用β基准 / 上行概率分位**读。**别把大盘上行行情算成个股实力**：普涨里跟涨不等于 α，普跌里抗跌才可能是 α。看多方向要说清是靠 α 还是借 β。
11. **诚实不硬凑（硬）**：够格的不足时，**明说"今天只有 N 只够格"，绝不降标准硬塞**——硬凑＝把 β 风险伪装成 α 机会。

游资情绪票只标风险不给方向；高位巨量区分主力 vs 融资盘；据牌/据档复核，别当定论。

## 四、金字塔边界（硬边界·用户拍板·全程守住）

**开深度不开广度**——允许查证/交叉/我vs系统出入的**深度**质疑，但不动池的**广度**：

1. **只在骨架 top-N 池内选**：不重新召回、不从全A另挖、**不加塞池外的票**。看好一只池外票，只能作为"建议下一轮召回关注"写在末尾，**不计入本次买入表**。
2. **数值一律程序算**：价位（挂单/止损/不追高上限）、各类分数/档位**全部取 registry 工具输出**，**你绝不自己写价位或打分**。你的产出是**研判、表态、盯点、纪律**，不是数字。
3. **不破坏金字塔独立性**：辩证＝在**证据链内**质疑决策包某行是否被其它面证据反驳，不是抛开骨架自由发挥。

## 五、下钻预算纪律（防无限下钻 / token 爆）

金字塔选股要**快 / 增量 / 当天出**。

- **挑最有希望的十几只逐个深研**，不是把 top-N 每只都往死里查。先按决策包档位排序，深研靠前的一批。
- 每票的工具调用**够判就停**：常规票取几个关键塔层块即可，只有"我vs系统出入大"或"消息面存疑"的票才深挖 news_raw/WebSearch。
- **增量**：已有决策包/per-stock json/经验规则库的结论直接用，别重算。
- WebSearch 是最贵的一档，**只在本地不足以判真伪时用**，且每次都要收敛回"改不改表态"。

## 六、产出形式

对齐老流程结构，但守金字塔边界：
- **市场环境判断**：引 market_forecast（β背景，非硬门控；大盘偏空则买入表态更谨慎+标 β 风险）。

- **买入建议排序表**：明确表态（买入/可参与/观望/规避），价位字段全部来自 `entry_price` 等工具、不手打。
- **诚实边界**：够格不足就写"今天只有 N 只够格"。看好的池外票单列"下一轮召回关注"，不进买入表。

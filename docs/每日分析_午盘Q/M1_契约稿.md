## 三、fundflow_intraday.py · I/O 契约

**为什么新建**：现有 `fundflow.py` 是日线（`daykline` 端点），Q3 需要 5min/1min 分时（`fflow/kline` 端点）。curl_cffi 反墙套路完全复用。

```python
"""东财 fflow/kline 分时资金流(1min/5min)。curl_cffi 反墙,只对候选池拉。

数据源:push2his.eastmoney.com/api/qt/stock/fflow/kline/get(实测通,见 _数据源实测.md)
落盘:走 store 层(kind="fundflow_intraday",parquet),分区 date+code
用途:Q3 主力/大单/超大单/中单/小单 5min 分时净流入
"""

FREQ_5MIN = 5
FREQ_1MIN = 1

def fetch_one(
    code: str,
    freq: int = FREQ_5MIN,          # 5 或 1
    as_of: str | None = None,        # "HH:MM"; None 表示不截断,拿全天
) -> pd.DataFrame:
    """拉单票分时资金流(不落盘)。

    返回列 ["time", "主力净流入", "小单净流入", "中单净流入",
                "大单净流入", "超大单净流入", "主力净占比"]
    - time: datetime,分辨率 = freq 分钟
    - 净流入单位:元
    - 空数据 → 抛 RuntimeError(不返回空 df 伪装成功,同 fundflow.py)
    - 网络失败 → 抛(不静默重试,由上层判)

    ⚠️ `as_of` 是**当前日截断**参数(防未来函数):`time > as_of` 的行被剔除。
       生产 14:30 首判传 "14:30",14:50 复核传 "14:50"。
    """
    raise NotImplementedError

def collect(
    codes: list[str],
    freq: int = FREQ_5MIN,
    as_of: str | None = None,
) -> tuple[dict[str, pd.DataFrame], list[dict]]:
    """批量拉候选池,单票失败进 errors,不炸整批。上限 codes ≤ 50。

    返回 ({code: DataFrame}, [{code, reason}, ...])
    """
    raise NotImplementedError
```

**关键设计**：
- 只对**候选池**（≤15 只）拉，不做全 A 排名（东财 `push2/clist` 被墙）
- `as_of` 参数是**未来函数红线**——14:30 复现时必须能把 `time > 14:30` 切掉
- 落盘契约与 store 层解耦，`kind="fundflow_intraday"` 交给 store 决定文件路径

## 四、gate.py · I/O 契约

```python
"""午盘 Q 大盘闸门(14:30 首判 + 14:50 复核)。

依赖:
  · data/intraday/<date>/T<slot>.json    ← 由 intraday_snapshot 落盘(指数分时价)
  · data/breadth/<date>.json             ← 由 market_breadth 落盘(全A广度)
        ⚠️ 若 market_breadth 一天落多次(1430/1450/1505),文件会互相覆盖?——需实测
        (预留 §六 待定问题)
输出:
  · data/analysis/midday_q/gate_<date>.json   ← 首判+复核合并
"""

def compute_gate(
    date: str,           # "YYYY-MM-DD"
    as_of: str,          # "14:30" 或 "14:50"
    snapshot_path: Path | None = None,   # 显式路径覆盖(测试用),None → 用 intraday_snapshot.snapshot_path
    breadth_path: Path | None = None,    # 同上
) -> dict:
    """闸门判定结果(字段结构见方案文档 00_大盘闸门.md §输出契约)。

    返回:
    {
        "date": "2026-09-07",
        "as_of": "14:30",
        "state": "强势" | "弱势" | "震荡" | "崩盘" | "未知",
        "indicators": {
            "hs300_intraday_pct": float | None,      # G1
            "csi1000_intraday_pct": float | None,     # G2
            "up_down_ratio": float | None,             # G3
            "limit_up_down_ratio": float | None,      # G4
            "money_effect": int | None,                 # G5(≥3%家数 - ≤-3%家数)
            "northbound_net_yi": float | None,          # G6(可能 NaN,已停披露)
        },
        "allowed_strategies": ["Q1"] | ["Q2"] | ["Q3"] | ...,
        "position_pct": 0.0..1.0,
        "reasons": ["G1=+0.31%(震荡)", "G4=1.8(震荡)", ...],

    - G6 允许缺失(北向已停披露)
```

## 五、midday_q_gate.py（pipeline）· I/O 契约

```python
"""launchd 触发的闸门节点。仿 intraday_snapshot.py 的结构:
  · 单参 --stage {1430|1450|final}
  · 幂等:输出文件已存在 → 跳过 exit 0
  · 非交易日跳过
  · 依赖上游文件未就绪 → warn 并 exit 1(不落文件,下游按缺文件降级)
  · 独立日志 logs/midday_q_gate.log
"""

def run(stage: str, *, date: str | None = None, force: bool = False) -> int:
    """
    stage:
      "1430" → compute_gate("14:30") → gate_<date>.json 的 stage1_1430 段
      "1450" → compute_gate("14:50") → 补齐 stage2_1450 段
      "final" → merge_two_stage(...) → 补齐 final 段 + flipped

    返回退出码 0/1(仿 intraday_snapshot.run)。
    """
    raise NotImplementedError
```

**为什么拆三 stage 而不是 14:50 一把跑**：
- 14:30 时上游快照/广度已就绪，可以先落首判结果，让 Q1/Q2/Q3 screener 拿去用
- 14:50 上游再跑一遍，闸门做复核
- 14:50:30 才 merge，才决定 final 允许策略——最迟 14:52 出最终清单，还剩 3min 下单窗口

## 六、待定问题（审核阶段）

1. **market_breadth 一天多次跑会不会互相覆盖？**
   看 `breadth_path(date)` 返回 `data/breadth/<date>.json`（一天一份）。若 14:30 跑后 15:05 又跑，14:30 的数据会被覆盖。需要：
   - 方案 α：把午盘 Q 的广度落到 `data/breadth/<date>_T<slot>.json`（多份，改 pipeline）
   - 方案 β：闸门 pipeline 跑完立即拷贝 `<date>.json` → `<date>_T1430.json`（不改 pipeline）
   - **倾向 β**（不动稳定代码）

2. **config/strategy.json 里 `midday_q.gate.*` 阈值段还没建**：
   - 方案 α：M1 就把阈值段建起来（跟 6 项指标阈值一起）
   - 方案 β：先在 gate.py 里 hardcode 常量，M3.a 回测校准后再入 config
   - **倾向 α**（宪法 §2 阈值单一真源）

3. **launchd 触发顺序保证**：14:30 需要先跑 snapshot + breadth，30 秒后才跑闸门——launchd 没有依赖机制，要靠时间错开还是 `midday_q_gate.sh` 里 poll 等文件？
   - 方案 α：错开 30 秒（14:30:00 snapshot / 14:30:00 breadth / 14:30:30 gate）
   - 方案 β：gate.sh 里循环 poll `<date>_T1430.json` 存在，最多等 60s
   - **倾向 α**（简单）；β 是加固方案，回测后再定

4. **north 数据源**（G6）：`market_forecast/fundflow.py` 是走两融不是走北向个股——G6 值实际怎么算？可能要在 gate.py 里对北向拿"停披露前的旧值"做保护性 fallback。
   - **待定**：M1 先跳过 G6（阈值判定按 5 项算，允许 1 项缺失），M3 阶段再补

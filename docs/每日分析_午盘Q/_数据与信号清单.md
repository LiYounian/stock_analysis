## 四、定时任务时序（14:30 首判 + 14:50 复核）

```
09:30  收盘 T-1 数据入库（现有 daily 任务已覆盖）
09:31  预热：加载 T-1 均线 + 静态过滤名单 + 陆股通标的名单
09:35+ 分时采集器持续运行（每 5min tick）
14:30  首判：
       1. 大盘闸门 gate.py(asof=14:30) → gate_{date}.json.首判_14:30
       2. 依 首判.允许策略 触发 Q1/Q2/Q3 screener(asof=14:30)
          → q{1,2,3}_{date}_1430.json  （候选池）
       3. 派单器合并 → combined_{date}_1430.json
       4. 落 view 到 web 面板 /selection?strategy=midday_q&stage=1430
14:50  复核：
       1. 大盘闸门 gate.py(asof=14:50) → gate_{date}.json.复核_14:50
       2. 对首判入选票跑复核 screener(asof=14:50, confirm-from=..._1430.json)
          → q{1,2,3}_{date}_1450.json  （最终清单）
       3. 若大盘闸门翻转到弱势/崩盘 → 最终清单强制置空
       4. 派单器合并 → combined_{date}.json（最终）
       5. 落 view /selection?strategy=midday_q&stage=final
14:55  尾盘下单窗口（人工执行，本项目暂**不做**自动下单）
次日 14:30-14:50  卖出（人工，尾盘 VWAP · 无止损 · v0.3 修订 2026-09-08）
次日 15:30  隔夜复盘：读昨日 combined + 今日开盘/T+1 收盘 → 落 backtest 记录
```

## 六、决策记录 & 待定

- ✅ **数据源方案 A**：生产 = gtimg 快照差分 + curl_cffi 东财 fflow；akshare 分时全弃用（见 [_数据源实测.md](_数据源实测.md)）
- ✅ **回测样本策略 = 未来采样**：M1 上线起每日落 14:30/14:50 快照，累积 60 交易日再做分时回测（约 M1 后 3 个月）；中间用日线口径的"降级回测"
- ✅ **决策时序**：14:30 首判 + 14:50 复核

待定：

1. **T-1 均线复权口径**：现有 `data/raw/kline/` 是复权还是不复权？——回测阶段需明确统一（隔夜策略对复权敏感度低，但仍需锁死口径）
2. **gtimg 稳定性**：项目已跑很久，实测稳定；14:30 → 14:50 只有 20 min，采集失败要有快速降级（延用 14:30 首判、告警但不空手）
3. **fflow_intraday 采集节流**：候选池最多 15 只（Q1+Q2+Q3 各 5）× 每 slot 1 次 = 30 次 API/天，东财 fflow 有无隐性限流待观察

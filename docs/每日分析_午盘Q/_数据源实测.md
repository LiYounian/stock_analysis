#### ⚠️ 2026-09-16 复测修订（`fflow/kline` 口径变更）

09-16 午盘 Q pipeline 实跑，Q3 候选 6/6 全报"分时资金流为空"。排查**非**代码/代码错，是东财改了口径。
复测矩阵（贵州茅台 600519 / 中际旭创 300308 / 工商银行 601398 等大票结论一致）：

| host | klt | 结果 |
|---|:-:|---|
| `push2his` | 5 / 15 / 30 / 60 | ❌ `rc=102, data=null` —— **分钟粒度已下线** |
| `push2his` | 1 | ⚠️ `rc=0` 但 `klines=[]` —— 历史 host 不返分时 |
| **`push2`** | **1** | ✅ **通，240 根/交易日** ← 现用 |
| `push2` | 5 | ❌ `rc=102` |
| `push2his` | 101（日线 `daykline`） | ✅ 仍通（`fundflow.py` 未受影响） |

**两个结论**：
1. **5min 粒度不再可得**，只能用 1min（Q3 信号按分钟格求和，粒度变细不影响口径）。
2. **host 必须换成 `push2`**（实时），`push2his`（历史）对分时返空。

**另一个必须修的隐藏问题**：东财 `klines` 的 5 类净流入是**当日累计值**，不是每格增量。
实证：茅台 09-16 最后一根 `-116,319,237` ≈ 日线 `fundflow.py` 当日 `-116,319,232`（吻合）；
而 240 根直接求和 = **-164 亿**（无意义）。原 `main_net_since()` 按增量求和消费 → 若不转换，
Q3 的 `MainNetPM` 会是彻底的废数。故 `fundflow_intraday.fetch_one` 现统一 **diff 转增量后再落盘**。
校验：增量自 13:00 求和 == 累计终值 − 12:59 累计值（中际旭创 09-16 = 102,448,260 ✅）。

此外东财现只返 **6 列**（`主力净占比` 不再返回）→ `_parse` 的 IndexError 兜底填 NaN，
列结构不变；该列下游无人消费（已 grep 确认）。

### 通道 3｜mootdx（通达信 TCP 7709） — ❌ 本机全挂

15 台服务器实测，两种失败模式：

- **能建 TCP 会话（4/15）**：`TdxFunctionCallError: calling function error` —— 协议解析炸（`struct.unpack requires 4 bytes`），可能是本机 IP 被识别为异常/境外，服务器返回不完整报文
- **建不上会话（11/15）**：`TdxConnectionError: connection timeout error` —— 8s TCP 握手都完不成，运营商 QoS 或 IP 黑洞

**结论**：本机无法用 mootdx 拿分钟 K 或历史逐笔。（`tdx_l2.py` 保留在仓，未来换网络环境可能可用；本次午盘 Q 不依赖）

### 通道 4｜baostock 分钟频 — ✅ **通（2026-09-17 补测，推翻原结论）**

> ⚠️ **09-07 那轮漏测了这条**。当时只测了 akshare / 东财 push2 / mootdx 三条路，
> 于是得出"个股价格分时·历史回测 = ❌ 无历史源"，并据此把 M3.b 推迟到
> "未来采样满 60 交易日"（约 3 个月）。**这个前提是错的。**
>
> 而 baostock **早就是本项目依赖**（主档日 K 就是它采的，见 `collectors/market.py`），
> 只是没人试过它的 `frequency="5"`。

```python
bs.query_history_k_data_plus("sh.600519", "date,time,open,high,low,close,volume,amount",
                              start_date=..., end_date=..., frequency="5", adjustflag="3")
```

| 验证项 | 结果 |
|---|:-:|
| 单日 5min bar 根数 | ✅ 48 根（完整） |

## 四、方案 A（用户拍板 2026-09-07）

**核心决策**：生产日内先跑起来，回测走"未来采样"路径。

### 生产日内（M1-M2 立即做）

1. 复用 `gtimg_quote.py` + `intraday_snapshot.py`，新增 **14:30 / 14:50 两个 slot**
2. 新建 `fundflow_intraday.py` 采集器 —— curl_cffi 直连东财 `fflow/kline`，只对候选池拉（≤50 只）
3. 大盘广度复用现有 `market_breadth` 的 `cross_section_stats`（单一真源，不重造）

### 回测（M3 阶段）

**不做"历史分时回填"**（数据不可得）。改用"未来采样"：

- 从 M1 上线之日起，**每天 14:30 / 14:50 落快照** → `data/intraday/<date>/T1430.json` + `T1450.json`
- 累积到 **60 交易日** 后（约 3 个月），再做完整分时回测
- 中间阶段用**降级回测**：仅用 T-1 收盘 + T 日开高低收 + 日线资金流，跑粗回测辨方向
- 若"未来采样"期间发现新的历史分时通道（付费/换网/新库），随时补历史

### 里程碑修订

- M3 拆成 **M3.a（降级回测，日线口径）** + **M3.b（分时回测，未来 60 日采样后）**
- M4 上线判定：M3.a 就足以做 alpha 方向判断；M3.b 再做精调

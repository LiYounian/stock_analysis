## 2. 计划文档 = 需求文档(负责人约定)⭐

**约定**:从现在起,`docs/计划/` 下的每份文档就是一份 **"需求文档"** —— 承载"我们想加什么需求"。
一个需求 / 一个 Phase 一份,**动手前写、与负责人审阅对齐后再执行**(对应开发规范约法第 1 条:留痕第一、靠文档交接)。

每份需求文档**必须写清**(照模板来):

1. **原始需求** —— 负责人 / 同事的原话或忠实转述(不要提前脑补加工,先如实记录)。
2. **要实现哪些功能** —— 把需求拆成**可验收的功能点**(每点可判断做没做完)。
3. **实现计划** —— 分期 / 涉及模块(`tools/`、`web/` 路径)/ 接口签名 / 工作量估(token + agent 工时)。
4. **关联** —— 对应的 [工程进度.md](工程进度.md) 条目、依赖的其它需求 / 模块 / 待拍板项。

**怎么写**:直接复制 [计划/_需求文档模板.md](计划/_需求文档模板.md),按骨架填空。
**命名**:`需求名.md` 或沿用 Phase 命名 `Pn_特性名.md`(如 `P1_技术面打通.md`)。
**生命周期**:写 → 负责人审阅 → 执行 → 完成后在文首标 `✅ 已落地` 并记录"实际与计划的偏差" → 该轮小结进 [开发日志](日志/开发日志.md)。

> 说明:`docs/计划/` 里已有一批历史计划文档(P1/P2/P3E、回测层、存储层收敛、按日期存储、新闻 AI 评论等),**保持原样**,它们本身就是需求文档的实例;新需求一律按上面的模板补齐四段。

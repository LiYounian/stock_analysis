# A 股自选池分析系统 · 架构设计

> 状态:**待审阅**(v0.1,框架先行,尚未填实现)
> 更新:2026-08-05
> 方向决策:**方案 2 —— 先抓组合/行业层面共性主线,再挑重点票深挖**

---

## 1. 目标与范围

对一个 **32 只硬科技成长股自选池**(见 [股票清单.md](股票清单.md),半导体 44% 为主线)做两类分析:

1. **技术指标分析** —— K线、量价、均线、MACD/KDJ/RSI 等
2. **情绪影响分析** —— 三个层面驱动:
   - **政策影响**(国内:央行/证监会/产业政策;国外:美联储/出口管制/关税)
   - **公司内部行为/新闻**(增减持、回购、业绩预告、诉讼、重大合同)
   - **舆情**(研报评级、雪球/股吧市场评论、炒股大V/博主观点)

**方案 2 的两层产出:**
- **组合层**:行业分布、主线强弱、板块情绪温度、异动票筛选
- **重点票层**:从组合层筛出的少数重点票,做技术面 + 情绪面深挖

**非目标(本期不做):** 实盘交易、自动下单、高频、给个人投资建议(仅做信息聚合与信号呈现)。

## 2. 分层架构总览

```
┌─────────────────────────────────────────────────────────┐
│  编排层  tools/run.py         (串起全流程,一键出报告)      │
├─────────────────────────────────────────────────────────┤
│  报告层  tools/report/        (组合层报告 + 重点票报告)     │
├─────────────────────────────────────────────────────────┤
│  分析层  tools/analysis/      技术指标 / 情绪打分 /         │
│                               事件三层分类 / 组合聚合        │
├─────────────────────────────────────────────────────────┤
│  采集层  tools/collectors/    行情 / 基本面 / 公告 /        │
│                               新闻研报 / UGC舆情 / 政策      │
├─────────────────────────────────────────────────────────┤
│  存储层  data/raw/            原始数据落盘缓存(parquet/json)│
├─────────────────────────────────────────────────────────┤
│  配置层  tools/config/        股票池 / 全局参数              │
└─────────────────────────────────────────────────────────┘
```

**设计原则:**
- **采集与分析解耦** —— 采集层只负责"把数据拉下来落盘",分析层只读本地缓存,互不阻塞;可分别调试。
- **能落 AKShare 就别自建爬虫** —— 浏览器抓取仅用于 AKShare 拿不到的 UGC 舆情。
- **每个模块单一职责** —— 一个 collector 只管一类数据源,一个 analysis 只管一种计算。
- **情感打分外包 qwen** —— 舆情/新闻的情感倾向判断是高耗 token 的批量任务,走 qwen 网关不烧主额度。

## 3. 数据流

```
配置(32只票) 
   │
   ▼
采集层 ──► data/raw/ 缓存 ──► 分析层 ──► 报告层
   │                            │
   ├ market      (K线/量价)     ├ technical  (指标计算)
   ├ fundamental (财报/估值)     ├ sentiment  (情感打分, qwen)
   ├ announcement(巨潮公告)      ├ event      (政策/公司/舆情三层归类)
   ├ news        (新闻/研报)     └ portfolio  (组合层聚合:行业共性/主线)
   ├ ugc         (雪球/股吧)          │
   └ policy      (WebSearch政策)      ▼
                              report/builder ──► docs/报告/*.md
```

## 4. 模块清单与输入输出契约

> 框架先行:先定每个脚本的 I/O 契约,实现留空(`NotImplementedError`)。审阅时重点看**契约是否合理**。

### 4.1 配置层 `tools/config/`

| 文件 | 职责 | 关键接口(输入 → 输出) |
|---|---|---|
| `stock_pool.py` | 32 只票池 + 行业分类(数据即代码) | `get_pool() → list[Stock]`;`Stock{code, name, industry, sector}` |
| `settings.py` | 全局参数:缓存路径、K线周期、抓取限频、qwen 开关 | 模块级常量 + `load()` |

### 4.2 采集层 `tools/collectors/`(每个 collector 统一签名:`fetch(codes, **kw) → 落盘 + 返回 DataFrame/dict`)

| 文件 | 数据 | 主数据源 | 输入 → 输出 |
|---|---|---|---|
| `market.py` | 日K线、量价 | AKShare `stock_zh_a_hist`(备:东财 push2his 接口) | `fetch_kline(codes, start, end, adjust) → data/raw/kline/{code}.parquet` |
| `fundamental.py` | 财报、估值、ROE、行业对比 | AKShare `stock_financial_abstract` / `stock_a_indicator_lg` | `fetch_fundamental(codes) → data/raw/fundamental/{code}.json` |
| `announcement.py` | 公司公告(增减持/回购/业绩预告/诉讼) | AKShare 巨潮 `stock_zh_a_disclosure_report_cninfo` + `stock_yjyg_em` | `fetch_announcements(codes, days) → data/raw/announcement/{code}.json` |
| `news.py` | 个股新闻 + 研报 | AKShare `stock_news_em` / `stock_research_report_em` | `fetch_news(codes, days) → data/raw/news/{code}.json` |
| `ugc.py` | 雪球讨论 / 东财股吧(市场评论、大V) | 浏览器抓取(chrome MCP,需登录态) | `fetch_ugc(codes, limit) → data/raw/ugc/{code}.json` |
| `policy.py` | 宏观/行业政策(国内外) | WebSearch 定向 query | `fetch_policy(keywords, days) → data/raw/policy/policy_{date}.json` |

### 4.3 分析层 `tools/analysis/`

| 文件 | 职责 | 输入 → 输出 |
|---|---|---|
| `technical.py` | 计算技术指标(纯本地算,不依赖网络) | `compute(kline_df) → {ma, macd, kdj, rsi, vol_signal, ...}` |
| `sentiment.py` | 对新闻/研报/UGC 文本做情感打分(**外包 qwen 批量**) | `score(texts: list[str]) → list[{score:-1~1, label, reason}]` |
| `event.py` | 把公告/新闻/政策归入**三层**(政策/公司行为/舆情)并打标重要度 | `classify(items) → list[{layer, tag, importance, impact_direction}]` |
| `portfolio.py` | 组合层聚合:行业分布、主线强弱、板块情绪温度、异动票筛选 | `aggregate(all_stock_results) → {industry_stats, hot_theme, sentiment_temp, watchlist}` |

### 4.4 报告层 `tools/report/`

| 文件 | 职责 | 输入 → 输出 |
|---|---|---|
| `builder.py` | 渲染两级报告(组合层 + 重点票层)为 Markdown | `build_portfolio_report(...) → docs/报告/组合_{date}.md`;`build_stock_report(code, ...) → docs/报告/个股_{code}_{date}.md` |

### 4.5 编排层 `tools/run.py`

一键流程:`采集 → 分析 → 组合聚合 → 筛重点票 → 深挖 → 出报告`。
支持子命令:`run.py collect` / `run.py analyze` / `run.py report` / `run.py all`。

## 5. 情绪分析三层建模(本系统重点/难点)

| 层面 | 数据来源 | 采集难度 | 处理方式 |
|---|---|---|---|
| **政策**(国内外) | WebSearch 定向 + 财经媒体 | 中(信噪比低) | 关键词命中 → qwen 判断影响方向/强度 → 归到受影响行业 |
| **公司内部行为/新闻** | 巨潮公告 + 东财新闻(结构化) | **低(优先做)** | 规则打标(增减持/回购/预告)+ qwen 补充定性 |
| **舆情/大V** | 雪球 + 股吧 UGC | **高(强反爬/需登录)** | 只对目标票池抓,做**热度指标**(讨论量/涨跌情绪比)+ qwen 情感打分 |

**落地优先级:** 结构化舆情(公告/研报/业绩预告)先做 → 政策次之 → UGC 情绪最后做(最难,先做量化热度,再做情感)。

## 6. 技术栈与依赖

| 用途 | 选型 |
|---|---|
| 语言 | Python 3.13 |
| 行情/基本面/公告/新闻 | **akshare**(基座,免费无 token) |
| 缺口补充 | tushare(需 token)/ baostock(免费历史行情) |
| 数据处理 | pandas / numpy |
| 技术指标 | 本地自算(或 `ta` 库,待定) |
| UGC 抓取 | chrome-devtools MCP(雪球/股吧,复用已有登录态) |
| 政策/新闻检索 | WebSearch |
| 情感打分 | **qwen-delegate**(批量外包,不烧主额度) |
| 缓存格式 | parquet(行情)/ json(文本类) |

> ⚠️ 数据源冗余:调研发现 Tushare Pro 曾突发停运,不单点依赖,akshare 为主 + 多源备份。

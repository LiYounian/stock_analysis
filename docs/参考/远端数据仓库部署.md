# 远端数据仓库部署(Phase 1:远端常驻采集 + 本地按需拉取)

> 本期闭合"远端常驻采集 → 本地按需拉取"这半环。数据流向:
> **远端机盘中/盘后采集全A → 落滚动主档(data/master) → 本地经 ingest `/pull` 增量拉回**。
> 与既有"本地算 → 远端看"(`tools.sync.upload` → ingest `/ingest`)对称,共用同一 ingest 服务与同一把 HMAC 密钥。

## 组件一览

| 端 | 组件 | 作用 |
|----|------|------|
| 远端 | `ops.remote_fetch` + `stock-fetch.{service,timer}` | 交易日守卫 → 全A 当日增量落主档 |
| 远端 | `tools.sync.ingest` 的 GET `/pull`(端口 8802,与 `/ingest` 共存) | 鉴权+验签后回增量原始数据 |
| 本地 | `tools.sync.pull` | 签名 GET `/pull` → 校验 → 写本地主档(幂等)→ 推进水位 |

## 鉴权(安全红线)

`/pull` 暴露原始数据,门禁与 `/ingest` 同严、**同一把密钥**:

1. `Authorization: Bearer <SYNC_INGEST_TOKEN>` 缺/错 → **401**
2. 按 token 滑窗限流(`SYNC_RATE_MAX`/`SYNC_RATE_WINDOW_S`)→ 超限 **429**
3. HMAC 钢印:GET 无 body,故把请求要素(kind/since/codes/ts/nonce/key_id)塞进信封 `meta` 一起签(`sign.pull_envelope`),签名走头 `X-Sync-Sig`(配 `X-Sync-Ts`/`X-Sync-Nonce`/`X-Sync-Key-Id`)。**未签名 / 错密钥 → 403**
4. 签名时间戳时效(`SYNC_REPLAY_WINDOW_S`,默认 300s)→ 超窗 **409**(挡被截获的旧签名 URL 无限重放)

响应**只含原始数据**(kline bars),NaN→null;**绝不返任何密钥/配置**。每次请求(成功/失败)都落 ingest 审计(`source=pull`)。

## 远端部署步骤

```bash
# 0. 依赖:远端需 akshare(全A spot 增量 + 交易日历);首次全量回填还需 baostock
/srv/stock_analysis/.venv/bin/pip install akshare baostock

# 1. 密钥/令牌写受限文件(chmod 600),两端同一把
sudo install -m 600 /dev/stdin /etc/stock-analysis/sync.env <<'EOF'
SYNC_INGEST_TOKEN=<与本地同一令牌>
SYNC_SIGNING_KEY=<与本地同一 HMAC 密钥>
SYNC_KEY_ID=k1
EOF

# 2. ingest 服务(收上传 + 供 /pull);已有则跳过
sudo cp ops/systemd/stock-ingest.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now stock-ingest

# 3. 首次全量回填主档(baostock 逐只拉全历史,耗时较久,手动跑一次)
/srv/stock_analysis/.venv/bin/python -m ops.remote_fetch --backfill

# 4. 常驻采集定时器(交易日守卫 + 全A 当日增量,默认每 30min)
sudo cp ops/systemd/stock-fetch.service ops/systemd/stock-fetch.timer /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now stock-fetch.timer
```

- `stock-fetch.service`(oneshot):非交易日自动跳过(不触网、不写库);交易日 `market.update_master_from_spot()` 一次 spot 拿全A当日 bar，按 date 幂等 append 到主档，盘中多跑无害。
- 交易日判定优先用 akshare 交易日历(`tool_trade_date_hist_sina`),不可用时回退"工作日近似"(周末跳过)——回退只会把节假日误判为交易日(多跑一次空 spot,幂等无害),不会漏采交易日。

## 本地拉取用法

```bash
# 环境变量(与远端同一把密钥):SYNC_INGEST_URL 指向远端 .../ingest,客户端自动推导出 .../pull
export SYNC_INGEST_URL=https://<remote-host>:8802/ingest
export SYNC_INGEST_TOKEN=<同一令牌>
export SYNC_SIGNING_KEY=<同一 HMAC 密钥>
export SYNC_KEY_ID=k1
# 自签证书(如有):export SYNC_INGEST_CA=/path/to/ca.pem  # 只这一张,不动全局 CA

# 增量拉取(首拉=全量;之后按水位只拉 date>上次最新)
/srv/stock_analysis/.venv/bin/python -m tools.sync.pull --kind kline
# 可选:--since 2026-08-01(覆盖水位)  --codes 000001,600000(缺省全A)  --url <显式 /pull 地址>
```

- 水位落 `data/sync_receipts/pull_<kind>.json`(记 `last_max_date`),下次自动增量。
- 写本地主档走 `repo.append_master_kline`,按 date 去重幂等;重复拉不产生重复行。
- **远端不可达 / 非 2xx**:退避重试(网络/5xx),4xx 永久失败;失败时**保留本地旧数据、不推进水位**、明确报错。

## 参数与扩展

- `/pull` 参数:`kind`(现支持 `kline`,预留 fundamental/fundflow/announcement)、`since`(YYYY-MM-DD 增量水位,空=全历史)、`codes`(逗号分隔 6 位码,空=全A)。
- 客户端超时 `SYNC_PULL_TIMEOUT_S`(默认 120s);上传侧对应 `SYNC_UPLOAD_TIMEOUT_S`。

## 本机 loopback 自证(开发验证)

单测 `tests/test_sync_pull.py` 用 FastAPI TestClient 做单进程 loopback;另可起真实 uvicorn 端到端验:
未签名→403、无 token→401、错密钥→403、合法签名→200 且只回 `date>since` 增量、NaN→null、
写本地主档幂等、水位推进。真机远端部署验证在生产机执行上面的步骤即可。

# 本地部署与监控手册

> 面向**在自己电脑上跑这套工具的人**(含策略提供者):从安装环境、拉数据、起网页,到打开午间/收盘监控。
> ⚠️ **非投资建议**。本工具不自动下单、不给精确买点;页面上的「收缩结构参考」不是「VCP 完成」。
> 更细的环境坑见 [环境说明.md](环境说明.md);远端服务器只读展示见 [部署说明.md](部署说明.md)。本文只管**本机一条龙**。

---

## 0. 先建立这张图

两件独立的事,顺序不能反:

```
拉数 / 扫描(会联网、会算)  →  产物落到 data/analysis/<日期>/  →  网页只读渲染
     tools.run …                                              uvicorn :8801
```

- **网页自己不算、不拉行情。** 没跑过命令,页面就是空的。
- **SEPA+VCP 监控**是独立扫描,不占用选股页「策略5」(那是自选池小市值)。看监控请打开 `/sepa`。

建议本机长期开着两个终端:一个常驻网页,一个按需或定时跑拉数/监控。

## 1. 安装环境

需要已安装 Anaconda / Miniconda。项目环境名 `stock_analysis`,Python 3.11。

```bash
git clone <仓库地址> stock_analysis
cd stock_analysis

conda create -y -n stock_analysis python=3.11
conda activate stock_analysis
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

Apple Silicon Mac 若装依赖失败,按 [环境说明 · Apple Silicon](环境说明.md#macos--apple-siliconm-系列安装说明) 建 x86_64 环境。

非交互脚本里 `conda activate` 经常失效,后面命令一律可以写成:

```bash
PY="$HOME/.conda/envs/stock_analysis/bin/python"
$PY -m tools.run …          # 拉数
$PY -m uvicorn web.app:app --port 8801
```

可选:情绪/财报 LLM 需要三个环境变量(不配也能跑技术面和 SEPA 监控,只是新闻情绪为空):

```bash
export LLM_BASE_URL="https://你的网关/v1"
export LLM_API_KEY="你的密钥"
# 模型名代码里写死,不必设 LLM_MODEL
```

密钥只放本机环境变量或 `~/.config/stock/sync.env`(权限 600),**不要写进仓库**。

装完先确认环境:

```bash
$PY -m pytest tests/test_sepa_vcp.py tests/test_scheduler.py tests/test_web.py -q
```

## 2. 起网页(只读服务)

数据可以后补,网页可以先起:

```bash
conda activate stock_analysis
uvicorn web.app:app --port 8801
```

浏览器打开 **http://localhost:8801**

| 路径 | 看什么 |
|---|---|
| `/` | 今日概览(自选池中心记录) |
| `/selection` | 选股结果(策略 0–5,策略5=自选池小市值) |
| **`/sepa`** | **SEPA+VCP 监控**(合格池 + 观察池 + 雷达) |
| `/sepa/{代码}` | 该票「收缩结构参考」图(高→低线段,不叫 VCP 完成) |
| `/financial` | 财报分析 |
| `/screen` | 预设筛选 |
| `/news` | 新闻 |
| `/pool` | 票池管理 |

开发改代码可加 `--reload`。端口被占用就换 `--port 8080`。

## 3. 拉数据:哪些命令、什么时候跑

所有命令都在**项目根目录**、**已激活 conda 环境**下执行。`--all` 表示票池管理里的全池(默认开发子集约 10 只)。

### 3.1 命令一览

| 命令 | 联网? | 干什么 | 什么时候用 |
|---|---|---|---|
| `python -m tools.run collect [--all]` | 是 | 数值面:K 线主档 + 基本面 + 公告 + 资金流 | 日常刷新行情/财报数字 |
| `python -m tools.run message [--all]` | 是 | 消息面:新闻 / 舆情 / 政策 | 要看情绪、新闻页时 |
| `python -m tools.run sentiment [--all]` | 否(调 LLM) | 三层情绪打分 | 配了 LLM 之后 |
| `python -m tools.run serialize [--all]` | 否 | 组装中心记录 + 普通 K 线图 | 采集完要上「今日概览 / 个股页」 |
| `python -m tools.run events` | 是 | 业绩预告/快报、增减持 | 事件专家需要 |
| `python -m tools.run factor` | 否 | 多因子截面 | 合议多因子专家 |
| `python -m tools.run council` | 否 | 回写合议块 | serialize 之后 |
| `python -m tools.run panel` / `screen` | 否 | 横向总表 / 预设筛选视图 | 要看 `/screen` |
| `python -m tools.run pattern [--universe N]` | 视数据 | 形态选股全 A 扫描 | 形态策略 |
| `python -m tools.run sepa [选项]` | 默认是 | **SEPA+VCP 监控**(本文重点) | 午间 / 收盘 |
| `python -m tools.run all [--all]` | 是 | 上面采集→情绪→组装→事件→因子→合议→视图,一条龙 | 盘后想一次跑完自选池 |
| `python -m tools.run pipeline [--universe N]` | 是 | 全 A 先便宜筛,再只对候选做新闻/LLM | 全市场选股管线 |
| `python -m tools.run screenall [--universe N] [--no-llm] [--no-fetch]` | 视参数 | 全 A 多策略选股 | 策略 0–4 盘后扫描 |

K 线走**滚动主档** `data/master/kline/<代码>.parquet`(每股一份长历史)。`collect` 内部会 `master_sync`:主档没有或太旧就用 baostock 拉全量,否则只 append 当日 bar。

### 3.2 第一次在本机(推荐顺序)

```bash
# ① 先让票池管理里的自选池有中心记录(网页今日概览不空)
python -m tools.run all --all

# ② SEPA 监控要扫全 A,需要全市场日 K。若 data/master/kline/ 还是空的:
#    用 collect 对全 A 同步主档(首次 baostock 较久,之后每天只增量)。
#    没有现成全 A 列表时,可先跑一次带联网的 sepa,它会按票池拉当日 spot 并尝试补主档。
python -m tools.run sepa --session 收盘 --universe 200
# 确认雷达有输出、http://localhost:8801/sepa 有表之后,再去掉 --universe 做全量。

# ③ 已有主档、只想离线试扫描(不触网):
python -m tools.run sepa --session 收盘 --no-fetch
```

首次全 A 主档回补耗时长、吃磁盘,可放到晚上跑。之后每个交易日只需增量。

### 3.3 每个交易日(手动版)

| 时段 | 建议命令 | 说明 |
|---|---|---|
| 午间休市后(约 11:35) | `python -m tools.run sepa --session 午间` | 先 spot 写入当日未完成 bar,再扫合格池 |
| 收盘后(约 15:30–15:40) | `python -m tools.run sepa --session 收盘` | 用收盘 bar 再扫一遍,覆盖午间结果 |
| 收盘后(若还要自选池/选股/新闻) | `python -m tools.run all --all` | 全链路;和 sepa **分开跑**,不要绑在一起等 LLM |

`--no-fetch` 表示**不拉当日 spot、不补主档**,只用磁盘上已有 K 线。适合没网验收,或主档已由别的任务更新过。

## 4. 开启 SEPA+VCP 监控(自动跑)

监控范围:当日过 SEPA 均线三条的票(约 200–400),不是全市场盯盘,也**没有**分钟级/tick。每天最多两趟:午间、收盘。

三选一即可,不要重复挂。

### 4.1 macOS · launchd(推荐本机)

```bash
REPO="$(pwd)"   # 须在仓库根目录
chmod +x "$REPO/ops/launchd/sepa_monitor.sh"
sed "s#__REPO__#$REPO#g" "$REPO/ops/launchd/com.stock.sepa.plist" \
  > ~/Library/LaunchAgents/com.stock.sepa.plist
launchctl load -w ~/Library/LaunchAgents/com.stock.sepa.plist
```

效果:工作日 **11:35** 与 **15:35** 自动跑。日志在 `logs/sepa.log` / `logs/sepa.err`。

解释器优先读 `STOCK_PYTHON`,否则 `~/.conda/envs/stock_analysis/bin/python`。可在 `~/.config/stock/sync.env` 里写:

```bash
STOCK_PYTHON=/Users/你/miniconda3/envs/stock_analysis/bin/python
```

Mac 在到点时必须**已开机且未休眠**,否则会错过(launchd 不会补跑盘中那一趟)。系统设置里打开「防止自动进入睡眠」,或用 `caffeinate`。

卸载:`launchctl unload -w ~/Library/LaunchAgents/com.stock.sepa.plist`

### 4.2 Linux · systemd timer

把 `ops/systemd/stock-sepa.service`、`stock-sepa-noon.timer`、`stock-sepa-close.timer` 里的路径/用户改成自己的,拷到 `/etc/systemd/system/`,然后:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now stock-sepa-noon.timer stock-sepa-close.timer
```

脚本同样按钟点选择午间/收盘。

### 4.3 crontab(任意 Unix)

```cron
# 工作日午间 / 收盘;把 PY 和 REPO 换成自己的绝对路径
35 11 * * 1-5 cd /path/to/stock_analysis && /path/to/python -m tools.run sepa --session 午间 >> logs/sepa.log 2>&1
35 15 * * 1-5 cd /path/to/stock_analysis && /path/to/python -m tools.run sepa --session 收盘 >> logs/sepa.log 2>&1
```

### 4.4 进程内调度(已经在跑 `tools.scheduler` 时)

与现有「盘后全量 `run all`」分开的开关,默认关:

```bash
SCHED_ENABLED=true \
SCHED_SEPA_ENABLED=true \
python -m tools.scheduler
```

会额外注册工作日 11:35 / 15:35 两趟。全链路间隔仍由 `SCHED_FULL_INTERVAL_MIN` 控制。SEPA **不调用 LLM**。

## 5. 怎么看结果

1. 扫描结束后终端会打印一段「雷达」摘要,例如:

   ```
   【收盘雷达】
   重点：N只
   VCP进行中：……
   新入池+星：……
   失效移出：……
   ```

2. 打开 **http://localhost:8801/sepa**
   - **表2 重点观察池**:新候选 / VCP进行中 / 接近枢纽 / 结构破坏(满足任一即入;一只可多标签)
   - **表1 技术合格池**:过 SEPA 均线三条的全部;星标只展示、不过滤、不排序
   - 点代码进入 `/sepa/{代码}`,主图标题是 **「收缩结构参考」**

3. 产物文件(给排查用):

   - `data/analysis/<日期>/SEPA合格池.json`
   - `data/analysis/<日期>/SEPA观察池.json`
   - `data/analysis/<日期>/SEPA雷达.json`
   - `data/analysis/<日期>/sepa_vcp_chart/<代码>.json`

同一天后一趟(收盘)会覆盖前一趟(午间)的同名 view。

## 6. 规则备忘(给策略提供者核对)

权威需求:[SEPA_VCP监控模块_需求](../计划/SEPA_VCP监控模块_需求.md)。阈值真源:`tools/config/strategy.py` → `THRESHOLDS["SEPA_VCP"]`。

- SEPA 入池(原书三条,不调整):股价 > MA50 > MA150 > MA200;MA200 当前 > 20 日前;股价在 MA50 与 MA200 上方。
- 剔 ST 名称、代码头 4/8/9(北交/B 股,数据卫生)。
- VCP 一轮 = 波段高→低,至少 3 个交易日;只比**当前轮 vs 上一轮**(振幅缩小 + higher low);无末轮绝对阈值。
- 盘中刺破前低、收盘收回 = 洗盘算活;收盘较前低跌破超过 1.5% 且收不回 = 结构破坏。
- 基本面星 / 板块星只展示。pivot 窗口 3、距前高 8% 等是工程占位,先跑再肉眼标定。
- **说明**:pivot=3 在全历史 K 线上往往会切出很多轮,页面和雷达只展示回撤链末 3 段;若觉得太碎,改 `tools/config/strategy.py` 里 `THRESHOLDS["SEPA_VCP"]["pivot窗口"]`。

## 7. 常见问题

| 现象 | 怎么处理 |
|---|---|
| `/sepa` 两个表都空 | 还没跑 `tools.run sepa`,或扫的日期与网页日期下拉不一致 |
| 今日概览突然变空 | 只跑了 `sepa`、没跑当天 `all`/`serialize` 时,日期下拉的「最新」会变成只有监控视图的那天。其它页请改选有中心记录的日期;`/sepa` 不受影响 |
| 合格池有、观察池空 | 正常:观察池只要「新候选/进行中/接近枢纽/结构破坏」;刚入池且无星不会进表2 |
| 午间结果还是昨天的价 | 没用默认联网扫描(漏了 `--session 午间` 且加了 `--no-fetch`),或 spot 被墙。看 `logs/sepa.err` |
| 全量扫描很慢 | 先 `--universe 200` 验证,再全量。有主档后阶段①只算均线,阶段②只对合格的 200–400 只切波段 |
| 网页有表、图是空的 | 加了 `--no-chart`,或该票不在观察池(只给观察池写图) |
| `conda activate` 在 launchd 里无效 | 在 `sync.env` 设 `STOCK_PYTHON` 为 conda 环境里 python 的绝对路径 |
| 想停自动监控 | macOS `launchctl unload`;Linux `systemctl disable --now` 那两个 timer;crontab 删两行 |

## 8. 和「远端展示端」的关系

如果你只是**自己看**,做到本文第 2–4 步即可,不必上云。

如果还要把页面挂到公网给别人看:本机继续负责拉数和 `sepa` 扫描,远端服务器只起 Web、不采集。传输与 HTTPS 见 [部署说明.md](部署说明.md) 后半与 [远端自动更新与自愈.md](远端自动更新与自愈.md)。把 SEPA 三个 view(及观察池的 `sepa_vcp_chart`)一并同步过去,远端 `/sepa` 才能显示。

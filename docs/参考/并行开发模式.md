# 并行开发模式:主窗口统筹 + Subagent + Git Worktree

> 可复用的开发方法论(本项目实践沉淀,可迁移到任何 Claude Code 项目)。
> 一句话:**主窗口当"项目经理"——规划/拆包/验收/合并;每个独立任务丢给一个 subagent,在隔离的 git worktree 里并行开发,做完自动回传,主窗口跑测试验收后合 main。各干各的,互不撞车。**

---

## 1. 为什么需要它(解决什么问题)

- **单窗口串行**:一次只能干一件事,慢。
- **多窗口/多 Agent 共享一个工作目录写 git**:HEAD 被互相切走、提交落错分支、代码丢失。→ 本项目早期踩过多次(靠 `git reflog` 找回)。
- **根因**:多个执行者共享**同一个 working tree + 同一个 HEAD**。
- **解法**:**git worktree** 给每个任务一个**独立工作目录 + 独立分支**,HEAD 互相隔离 → 并行**零冲突**。

---

## 2. 两种并行模式

| | 模式 A:Task Chip → 独立窗口 | 模式 B:Subagent(常用) |
|---|---|---|
| 执行者 | 用户点开的**独立 Claude 会话** | 主会话内 `Agent` 工具起的**子 agent** |
| 隔离 | 各自 worktree | `isolation: "worktree"` |
| 结果回传 | 靠 push 分支,人工在窗口间搬 | **自动回传给主窗口** |
| 适合 | 想盯着 / 分窗口独立管理的任务 | 主窗口自己编排 + 整合的任务 |

两者可混用。**模式 B 更省事**(结果自动回来,不用人工搬),本项目主用 B。

---

## 3. 角色与铁律

- **主窗口 = 统筹 + 验收 + 集成**:固定在**主仓**,**只在 `main` 做合并**,自己不在此开发。
- **Subagent / Worktree = 并行执行**:各自独立分支;**只 commit 到自己分支,不合并 main、不 push**(主窗口统一合)。
- **Git 铁律**:① main 只集成;② 一任务一分支一写者一 worktree;③ 每次 git 操作前 `git status`(必要时 `reflog`);④ 小步 commit;⑤ 合并只在主窗口做。

---

## 4. 让它顺的 4 个前提(缺一容易撞)

1. **解耦架构 + 数据契约**:模块围绕**中心数据契约**开发(生产者写、消费者读,互不 import 内部)→ 天生独立 → 可并行。这是并行的地基。
2. **文件边界隔离**:每个 subagent **只动一组互斥的文件**(最好是各自的新文件夹)→ 合并零冲突。**改同一共享文件的任务不能并行**(见 §6)。
3. **自包含 prompt**:subagent **看不到主会话的对话**,prompt 必须自带全部上下文(任务/要读哪些规范/接口契约/验收标准/用哪个分支/commit 不合并/报告什么)。
4. **主窗口验收**:拿回分支先跑**全量测试** + 抽查设计,**再合并;绝不盲合**。

---

## 5. 完整流程(the loop)

```
主窗口:统筹
  │  拆包:给每个待开发模块划好「独立位置 + 需求契约(接口/验收)」
  ▼
起 N 个 subagent(Agent 工具,isolation=worktree,文件边界互斥)
  │  各自:读规范 → 在隔离 worktree 开发 → 自测(pytest)→ commit 到 feat/<x>
  ▼  (自动回传报告:分支/文件/测试/决策)
主窗口:逐个验收
  │  git merge --no-ff feat/<x> → 跑全量测试确认无回归 → git push main
  ▼
清理:删 feat 分支 + prune subagent worktree
  ▼
更新「工程进度」文档(进行中→已完成),写开发日志
```

---

## 6. 什么时候用 / 不用(判据:文件集是否互斥)

- ✅ **能并行**:多个**独立模块**(各自新文件夹)、文件集互斥。例:同时开 回测层 / 政策采集 / UGC 采集(改 `tools/backtest/`、`collectors/policy.py`、`collectors/ugc.py`,零重叠)。
- ⚠️ **须串行/单写者**:改**同一共享文件**(如 `serialize.py` / `strategy.py`)、跨模块重构(如"命名统一")。
- 💡 **技巧**:两个逻辑相关的任务想并行时,**先划死文件所有权**让它们不重叠。例:"情绪打分接入"只动 `event.py/prompts.py/run.py`;"情绪并入决策"只动 `predict.py/serialize.py/strategy.py` → 互斥即可并行。

## 7. 实操模板

### 7.1 手动开 worktree(模式 A / 主窗口自己开一条)
```bash
ROOT=/path/to/主仓
git -C "$ROOT" worktree add "$ROOT/../worktree/<任务名>" -b feat/<任务名>
# 到该 worktree 目录内开发/测试/commit/push
git -C "$ROOT" worktree remove ../worktree/<任务名>   # 合并后清理
```

### 7.2 起 Subagent(模式 B)—— `Agent` 工具
- 参数:`isolation: "worktree"`,一条消息里起多个即并行。
- **Prompt 模板**(自包含,堵反问):
```
你是本项目开发 agent,在隔离 git worktree 工作(与他人零冲突)。主仓 <绝对路径>。
测试用 <环境 python 绝对路径>。(需 env 变量的联网测试:zsh -c "source ~/.zshrc>/dev/null 2>&1; <cmd>")

## 任务:<一句话>
## 严格文件边界(只准改这些,绝不动其它):
  改:<文件A> <文件B>   新增:<测试文件>   —— 绝不动 <会与并行任务冲突的文件>
## 先读(理解规范/契约):<开发规范> <架构设计> <相关契约> <相邻代码风格>
## 实现:<接口契约 + 要点 + 依赖方向约束>
## 测试:<断言要锁什么语义> —— `pytest <测试文件> -q` 必须全绿,顺带全量不回归
## 交付:git checkout -b feat/<x>;commit(清晰 message);**不合并 main、不 push**。
           报告:分支名 / 新增文件 / pytest 结果 / 关键设计决策。
重要:你没有多轮交互,**绝不反问**,信息不全按规范+现有代码风格自定。
```

### 7.3 主窗口验收 + 合并 + 清理
```bash
git status -sb                                  # 操作前必查(铁律)
git merge --no-ff feat/<x> -m "Merge: <x>"
$PY -m pytest tests/ -q                          # 全量验收,确认无回归
git push origin main
git worktree list | grep agent | awk '{print $1}' | while read w; do git worktree remove --force "$w"; done
git worktree prune; git branch -d feat/<x>       # worktree 移除后才能删其分支
```

---

## 8. 踩坑实录(为什么这样定)

- **早期**:多窗口/多 session 共享主仓 working tree,并发写 git → P4.0 提交被另一 session 冲掉、分支被重置、working tree 回退 → **靠 reflog 定位丢失 commit,`git checkout <hash> -- 文件` 找回**。
- **改用 worktree 后**:连续 **7 个 subagent** 并行(策略层/存取层/回测/政策/UGC/情绪打分/情绪并入),**0 并发事故、0 丢代码**。→ 隔离是根治,不是打补丁。

---

## 9. 复用到新项目的 checklist

- [ ] 项目有**清晰分层 + 数据契约**(解耦地基,否则并行会撞)
- [ ] 有一份**「工程进度 / 任务看板」活文档**(拆包 + 认领,标注哪些任务"文件互斥可并行")
- [ ] **主窗口固定主仓、只做合并**;约定 worktree 根目录(如 `项目/../worktree/`)
- [ ] 备好 **subagent prompt 模板**(§7.2:文件边界 + 自包含 + 验收标准)
- [ ] 验收 = **全量测试 + 抽查设计**,再合并
- [ ] 合并后**清理分支 + prune worktree**,更新进度/日志
- [ ] 记住判据:**能不能并行,只看文件集是否互斥**

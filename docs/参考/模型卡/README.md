## 1. 模型卡模板(统一 schema)

新增任何模型必须按下述固定小节填卡。**参数现值一律带 `文件:行` 出处;权重等"真源常量"只引出处、
不在多处复制数值**(复制=漂移源;需要机器校验的值走 §2 的一致性测试)。

```markdown
# 模型卡:<模型名>

> 一句话:<这个模型是什么、给谁用>。核实日 <YYYY-MM-DD>。

## 1. 标识
- **模型名 / ID**:<name>(`<写死点 文件:行>`)
- **kind**:LLM / 统计 / 规则 / 会话驱动
- **用途**:<在系统里承担什么职责>
- **通道**:<内部网关 / fintopia 网关 / Claude Code 窗口 …>
- **接线状态**:已接生产 / 配了未接线 / 会话驱动非程序化

## 2. 数据源
<每个数据源:源、回溯范围、披露滞后(防未来)、上游依赖>

## 3. 输入特征(维度 × 因子搭配)
<每维:因子怎么算、算子来源,引 `文件:行`;LLM 类则写 prompt 输入构成 / 输出 schema>

## 4. 训练 / 加工方式
<统计模型:walk-forward / expanding window / 重训了什么、没重训什么;
 LLM:是否微调(通常否)、prompt 工程、批处理、think 模式;规则:合成机制>

## 5. 关键参数现值(带出处)
<逐个参数:名 = 现值 (`文件:行`);真源常量只引出处不复制值>

## 6. 效力 & 局限(诚实标注)
<样本外指标 + 口径;已知局限,如无经济 alpha / 幸存者偏差 / 覆盖率不足>

## 7. 变更日志
<改模型/权重/因子/接线状态必追加:日期 — 改了什么 — 决策人 — 出处>
```

## 2. 权重一致性测试(防文档漂移)

**问题**:叙事文档易与代码漂移(改 `strategy.py` 忘改文档)。
**兜底**:`tests/test_model_card_weight_consistency.py` 断言三方一致——
**代码真值(`strategy.py:370`)== 模型卡记载值 == 测试内 EXPECTED 常量**。

- 模型卡 `market_forecast.md` 内有一个 `WEIGHTS_TABLE` 机读小表(见该卡 §5),测试解析它。
- 改组权重的正确姿势:**同时**改 `strategy.py:370`、`market_forecast.md` 的 WEIGHTS_TABLE、测试 EXPECTED,
  三处不一致测试即红——这就是"锁语义"(呼应约法第 6 条)。
- 叙事段(A/B 结论、局限)无法自动校验,靠规范 + review。

> 新增小模型时:P2 规范要求"带卡 + 若有组权重则纳入一致性测试"。

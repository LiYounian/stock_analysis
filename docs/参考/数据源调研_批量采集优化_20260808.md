# 批量采集 A股全市场日K：开源方案对比与落地架构（2026-08-08）

> 背景：现状用 akshare/腾讯/新浪逐只串行抓、每只 sleep 0.5s，全A一轮 30–40 分钟。
> 目标：全量历史一次性落地 + 每日增量 append，更快更稳。
> 调研方式：PyPI/GitHub API/接口实测（2026-08-08 当日数据）。
> 与《数据源调研.md》关系：该篇是"数据源选型总览"，本篇专注"全A日K批量采集"这一个问题的落地。

## 〇、本机环境硬约束（调研中实测确认）

- 东财 push2（kline/clist）对本机做 **TLS 指纹(JA3)过滤**：python-requests/undici 直接被 RST，curl 可通（今日用 undici 客户端实测 clist 再次被 RST）。见问题台账 B1。
  → 任何"东财一次拿全市场"的方案在本机必须走 `curl_cffi`（impersonate 浏览器指纹）或子进程 curl，否则不可用。
- 腾讯 `stock_zh_a_hist_tx`、新浪 `stock_zh_a_daily`、baostock 本机均可用（现有 market.py 已验证）。

## 二、并发采集最佳实践

**结论先行**：这个量级（<2 万请求）用 `ThreadPoolExecutor` 就够，asyncio+aiohttp 只有在直连原生批量接口且请求数上万时才有边际收益。真正的杠杆不是并发模型，而是①把"逐只一请求"换成"批量/快照"，②合理的限速+退避。

| 源 | 建议并发 | 限速/jitter | 批量粒度 | 备注 |
|---|---|---|---|---|
| 东财 push2his（历史K） | 8–12 | 每请求 jitter 100–200ms，持续 ≤10 req/s | 1只/请求 | >20 req/s 易触发 IP 临时封禁（分钟~小时级）；本机另被 JA3 墙，需 curl_cffi |
| 腾讯 qt.gtimg.cn（实时快照） | 4–6 | 批间隔 150–250ms | **50–80只/请求** | 宽容度高，全A仅 70–110 个请求 |
| 新浪 hq.sinajs.cn | ≤4 | 批间隔 ≥300ms | 50–100只/请求 | 必须带 `Referer: https://finance.sina.com.cn`；最易 403，仅第三备选 |
| baostock | **4–8 进程**（非线程） | 无需额外 sleep | 1只/查询 | 每进程一个 login 连接、连接非线程安全；无封禁，但也别超 ~10 连接 |

- **退避重试**：指数退避 + full jitter：`wait = min(cap, base·2ⁿ)·rand(0,1)`，base=1s、cap=30s、≤5 次。
- **熔断换源**：某源出现 403/429 或连续 5 次失败 → 该源冷却 60–120s，切下一源（延续 market.py 现有 `DEFAULT_SOURCES` fallback 思路）。
- **多源轮换**：历史K主备链=腾讯→新浪→baostock；快照主备链=腾讯批量→东财 clist(curl_cffi)→baostock 逐只兜底。
- **不要**用公共代理池：本机单 IP 足够支撑全A日K量级，代理反而引入更高失败率。UA 用常规浏览器 UA 即可——本机东财案例证明它筛的是 TLS 指纹不是 UA。

## 四、推荐落地架构（全量历史一次性落地 + 每日增量 append）

```
全量历史（一次性）            每日增量（16:00 后）              周期对账
┌─────────────────────┐     ┌──────────────────────────┐    ┌────────────────────┐
│ baostock 6–8 进程并发 │     │ 腾讯批量行情 70–110 请求    │    │ 每周: baostock 重拉  │
│ 不复权日K + 复权因子   │     │ → 全市场当日 OHLCV (~15s)  │    │ 最近5日 diff 修正     │
│ → 逐票 parquet(~15min)│     │ → append 各票 parquet      │    │ 除权季: 复权因子全刷新 │
└─────────────────────┘     │ 新股: code diff → 腾讯回补   │    └────────────────────┘
  失败票→腾讯 hist_tx 兜底      │ 停牌: query_all_stock 对照  │
                              └──────────────────────────┘
```

**关键决策与理由**
1. **存不复权 + 复权因子，读时计算前复权**。⚠️ 正确性坑：现价方案若按 `KLINE_ADJUST=qfq` 每日 append 前复权价，历史 bar 会在每次除权后整体漂移，新旧数据不一致。不复权价是唯一可 append 的稳定序列；复权因子来自 `baostock.query_adjust_factor`。
2. **全量历史选 baostock 而非东财/腾讯**：专用服务器无指纹墙/封禁、免积分、可多进程、数据干净（本项目 board.py 已验证其可用）。速度不占优但"稳"在一次性工程里权重最高。
3. **每日增量选腾讯批量行情快照**：本机唯一"快且无墙"的全市场通道，全A 70–110 请求 ~15s，比逐只快 100 倍+；东财 clist 单请求方案留作 curl_cffi 可用时的备选（更快，1 请求）。
4. **增量时序**：交易日 16:00 后跑（确保收盘结算完成）；先 `query_all_stock(day)` 拿当日名单 → 快照取 OHLCV → append → 与昨日名单 diff 出新股 → 新股走 `stock_zh_a_hist_tx` 回补全历史。
5. Tushare 的 `daily(trade_date=...)` 是付费档的最优解（积分够的话，增量一个调用搞定且含标准复权口径），作为可选升级项。

**代码骨架**

```python
# A. 全量历史：baostock 多进程（连接必须在子进程内建立，每进程一个 login）
import baostock as bs
from concurrent.futures import ProcessPoolExecutor

def _worker(chunk: list[str], start="1990-01-01", end="2026-08-08"):
    bs.login()
    frames = {}
    for code in chunk:
        sec = f"{'sh' if code[0] in ('6','9') else 'sz'}.{code}"
        rs = bs.query_history_k_data_plus(
            sec, "date,code,open,high,low,close,volume,amount,turn,pctChg",
            start_date=start, end_date=end, frequency="d", adjustflag="3")  # 3=不复权
        rows = []
        while rs.error_code == "0" and rs.next():
            rows.append(rs.get_row_data())
        frames[code] = pd.DataFrame(rows, columns=rs.fields)
    bs.logout()
    return frames

def backfill_all(codes, workers=6):
    chunks = [codes[i::workers] for i in range(workers)]
    with ProcessPoolExecutor(max_workers=workers) as ex:
        for part in ex.map(_worker, chunks):
            for code, df in part.items():
                store.put_raw("kline", code, normalize(df), meta={"source": "baostock"})

# B. 每日增量：腾讯批量行情快照（全A 70–110 请求）
def tencent_snapshot(codes, batch=60, workers=6) -> dict[str, dict]:
    def one_batch(part):
        q = ",".join(market_prefix(c) for c in part)
        r = requests.get(f"https://qt.gtimg.cn/q={q}", timeout=10)
        r.encoding = "gbk"
        out = {}
        for line in r.text.strip().split(";"):
            if "=" not in line:
                continue
            f = line.split("=", 1)[1].strip().strip('"').split("~")
            if len(f) < 40:
                continue
            out[f[2]] = dict(open=float(f[5]), high=float(f[33]), low=float(f[34]),
                             close=float(f[3]), volume=float(f[6]) * 100,
                             amount=float(f[37]) * 1e4)
        return out
    batches = [codes[i:i+batch] for i in range(0, len(codes), batch)]
    out = {}
    with ThreadPoolExecutor(max_workers=workers) as ex:
        for part in ex.map(one_batch, batches):
            out.update(part)
    return out  # 之后逐票 append 到 parquet（读旧→concat 当日行→写回）

# C. 东财 clist 单请求全市场（需 curl_cffi 过 JA3；requests 会被 RST）
def eastmoney_snapshot_all():
    from curl_cffi import requests as creq
    url = ("https://82.push2.eastmoney.com/api/qt/clist/get"
           "?pn=1&pz=6000&po=1&np=1&fltt=2&invt=2&fid=f12"
           "&fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23"
           "&fields=f12,f14,f2,f5,f6,f15,f16,f17,f18")
    diff = creq.get(url, impersonate="chrome", timeout=15).json()["data"]["diff"]
    # f17=开 f15=高 f16=低 f2=最新(收) f5=量 f6=额 f18=昨收
    return diff

# D. 通用退避重试（full jitter）
def with_backoff(fn, tries=5, base=1.0, cap=30.0):
    for n in range(tries):
        try:
            return fn()
        except Exception:
            if n == tries - 1:
                raise
            time.sleep(min(cap, base * 2 ** n) * random.random())
```

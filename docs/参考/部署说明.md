# 部署说明(新手上手教程)

> 面向**第一次拿到这份代码的人**:从零把项目跑起来,四步——
> ① 拉取代码 → ② 安装环境 → ③ 配置 & 跑数据 → ④ 把网页支起来。
> 每一步都有可直接复制的命令块。跟着做完,浏览器打开 `http://localhost:8801` 就能看到四个页面。

## 这个项目是什么形态

- **离线数据管线**:一条命令 `python -m tools.run all` 把行情/基本面/公告/资金流/新闻/情绪采集并算好,产物按日期落到 `data/analysis/<日期>/`。
- **Web 服务**:一个只读的 FastAPI 站点,不做计算,只读 `data/analysis` 里的结果渲染成网页。

两者解耦。**顺序很关键:先跑数据管线生成数据,再起 Web**;否则页面会是空的。

```
python -m tools.run all  ──►  data/analysis/<日期>/(中心记录 + 视图)  ──►  Web 只读渲染
```

## 第一步:拉取代码

```bash
# 克隆仓库(把 <仓库地址> 换成实际地址),并进入目录
git clone <仓库地址> stock_analysis
cd stock_analysis
```

之后所有命令都默认在这个项目根目录下执行。

---

## 第二步:安装运行环境

项目用**独立 conda 环境**,环境名 `stock_analysis`,Python 3.11。

```bash
# 1) 创建环境(需已安装 Anaconda / Miniconda)
conda create -y -n stock_analysis python=3.11

# 2) 激活环境(之后每开一个新终端都要先激活)
conda activate stock_analysis

# 3) 安装依赖
pip install -r requirements.txt
```

国内网络装依赖慢,可加清华镜像加速:

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 精确版本锁定在 `requirements-lock.txt`;要完全复现同一套依赖版本,把上面的
> `requirements.txt` 换成 `requirements-lock.txt` 即可。

### 关键依赖都干什么

| 依赖 | 作用 |
|---|---|
| `akshare` | A 股行情/基本面/公告等数据的统一采集接口(核心数据源) |
| `curl_cffi` | 伪装浏览器 TLS 指纹,解锁东财资金流等接口、绕过 JA3 反爬 |
| `pandas` / `numpy` | 数据处理与技术指标计算 |
| `pyarrow` | parquet 格式的采集缓存读写 |
| `openai` | 调用 OpenAI 兼容网关做 LLM 情绪/新闻抽取(**可选**,见第三步) |
| `fastapi` | Web 服务框架 |
| `uvicorn` | 跑 FastAPI 的 ASGI 服务器 |
| `jinja2` | 网页模板渲染 |
| `SQLAlchemy` | store 的 DB 后端(把中心记录/视图存进数据库;默认 SQLite,可切 MySQL/Postgres) |
| `APScheduler` | 进程内定时调度(按配置间隔自动跑数据流水线) |
| `pytest` | 单元测试(用来验证环境是否装好) |

> `SQLAlchemy` / `APScheduler` 是新增的存储后端 + 定时调度依赖,`pip install -r requirements.txt` 会一并装上。
> 若把 `DB_URL` 指向 MySQL / Postgres,还需按 requirements 注释各自装 `pymysql` / `psycopg[binary]`。

## 第三步:配置 LLM(可选)+ 跑数据流水线

### 3.1 配置 LLM(只有情绪面需要,不配也能跑)

情绪面(新闻/舆情/政策的 LLM 打分)需要一个 **OpenAI 兼容网关**。通过三个环境变量提供,
在启动前于当前 shell 里导出即可:

```bash
export LLM_BASE_URL="https://你的网关地址/v1"   # OpenAI 兼容的 base_url
export LLM_API_KEY="你的密钥"                    # API key
export LLM_MODEL="你的模型名"                    # 模型名,如不设有内置默认值
```

要长期生效,把这三行写进你自己的 shell 配置(如 `~/.zshrc`)后重开终端。

> **安全铁律**:这三个值**只放本机环境变量,绝不写进仓库任何文件**。代码里只引用变量名,
> 不含任何真实 url / key。

**不配 LLM 也能跑**:数据管线会自动检测,未配置时跳过情绪打分——技术面指标、超买超卖、
止盈止损、情景预测这些照常产出,只是**情绪层降级为空**(页面上情绪相关字段留空)。

### 3.2 跑数据流水线

激活环境后,一条命令跑通全链路(采集 → 情绪 → 组装中心记录 → 视图):

```bash
python -m tools.run all
```

- **开发默认只跑 10 只随机样本**:首次运行会从全池(32 只)随机抽 10 只,固化到
  `config/dev_sample.json`,之后每次复用同一批,保证可复现。想重选就删掉这个文件再跑。
- **跑全池 32 只**,加 `--all`:

  ```bash
  python -m tools.run all --all
  ```

- **产物落盘**:所有结果写到 `data/analysis/<日期>/`(按日期分区,当天日期自动取)。
  `data/` 不入库(已 gitignore),所以新环境**必须先跑一次**才有数据。

**单步命令**(排查问题或只想跑某一环时用,顺序即依赖顺序):

```bash
python -m tools.run collect      # 采集数值面(K线/基本面/公告/资金流,联网)
python -m tools.run message      # 采集消息面(新闻/舆情/政策,联网)
python -m tools.run sentiment    # LLM 三层情绪打分(需第 3.1 步的 LLM 配置)
python -m tools.run serialize    # 组装中心记录 + K线图表视图
python -m tools.run panel        # 横向总表视图
python -m tools.run screen       # 组合聚合 + 预设选股视图
```

单步同样支持 `--all` 切全池。

## 第四步:把网页支起来

数据跑完后,在**同一个激活了 `stock_analysis` 环境**的终端起 Web 服务:

```bash
uvicorn web.app:app --port 8801
```

然后浏览器打开:**http://localhost:8801**

开发时想改代码自动重载,可加 `--reload`:

```bash
uvicorn web.app:app --reload --port 8801
```

### 四个页面

| 路径 | 页面 | 内容 |
|---|---|---|
| `/` | 今日概览 | 组合总览、当日重点 |
| `/screen` | 选股 | 预设筛选 + 组合共性概览 |
| `/news` | 新闻 | 公司行为 / 公告 |
| `/stock/{code}` | 个股评估 | K线 + 止盈止损 + 情景预测 + 基本面 + 资金流(`{code}` 换成股票代码) |

全站均标注「非投资建议」。

## 常见问题

- **页面是空的 / 报找不到数据**:多半是还没跑数据管线,或跑的日期与今天不符。
  先执行 `python -m tools.run all`,确认 `data/analysis/<今天日期>/` 有产物,再起 Web。
- **资金流为空、少数票缺数据**:东财接口偶发限流,采集有间隔(`FETCH_SLEEP_SEC`)节流,
  仍可能有个别票资金流拿不到。**不阻塞整体流程**,过一会儿重跑一次即可补齐。
- **8801 端口被占用**:换个端口,`--port` 改成别的,例如 `uvicorn web.app:app --port 8080`,
  浏览器地址同步改成对应端口。
- **`conda activate` 在脚本/非交互终端里不生效**:交互式终端里正常用 `conda activate stock_analysis`
  即可;若在脚本里失效,可直接用环境内 Python 的路径调用(即环境 `bin/` 下的 `python`)。
- **情绪相关字段全空**:说明没配 LLM(第 3.1 步),或网关不可用。按需配置后重跑 `sentiment` 与 `serialize`。

## 第五步(可选):存储后端切数据库 + 定时自动刷新

默认存文件、手动跑数据。想让数据**进数据库**并**按配置刷新时间自动拉取**,用下面两个能力(都靠环境变量开,默认关,不影响前四步)。

### 5.1 把产物存进数据库(store DB 后端)

默认 `STORE_BACKEND=file`(产物落 `data/analysis/<日期>/`)。设成 `db` 即改存数据库:

```bash
# SQLite(零运维,默认库文件 data/app.db)——跑数据时写库
STORE_BACKEND=db python -m tools.run all
# 起 Web 也要带同样的后端,才会从库里读(否则读的是文件)
STORE_BACKEND=db uvicorn web.app:app --port 8801
```

换 MySQL / Postgres:装好驱动,再用 `DB_URL` 指过去(其余不变):

```bash
pip install pymysql                      # MySQL 驱动(Postgres 用 psycopg[binary])
STORE_BACKEND=db DB_URL="mysql+pymysql://user:pwd@host:3306/stock" python -m tools.run all
```

- 只有**分析产物**(中心记录 / panel / screen / chart 等视图)入库;**采集原始缓存**(K线/基本面…)仍走文件。
- `web/` 代码零改动——同一套展示层,`STORE_BACKEND` 决定读文件还是读库。
- 建表自动完成(首次连库即建 `record`/`view`/`code_view`)。

### 5.2 定时自动拉取(进程内调度)

把手动的 `python -m tools.run all` 变成按间隔自动跑。开关和间隔全走环境变量:

```bash
SCHED_ENABLED=true \
SCHED_FULL_INTERVAL_MIN=1440 \      # T1 盘后全量:每隔多少分钟跑一次(1440=每天)
SCHED_FULL_ALL=true \               # true=爬「票池管理」全池;false=只爬 10 只开发子集
STORE_BACKEND=db \                  # 配合 5.1,跑完直接入库
python -m tools.scheduler
```

- 前台常驻,`Ctrl-C` 退出;`SCHED_ENABLED` 不为 true 会拒绝启动。
- **每轮跑前自动重载票池**:常驻期间在网页「票池管理」增删的股票,下一轮即生效,无需重启。
- `SCHED_BACKFILL_INTERVAL_MIN`(默认 0=关):T5 兜底补数,间隔重跑采集补上轮失败票(如资金流限流)。
- 想快速看它触发一次:把 `SCHED_FULL_INTERVAL_MIN` 设成 `1`(1 分钟后跑第一轮)。

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `STORE_BACKEND` | `file` | `file` 存文件 / `db` 存数据库 |
| `DB_URL` | `sqlite:///data/app.db` | 数据库连接串(SQLAlchemy URL) |
| `SCHED_ENABLED` | `false` | 定时调度总开关 |
| `SCHED_FULL_INTERVAL_MIN` | `1440` | T1 全量任务间隔(分钟,<=0 禁用) |
| `SCHED_BACKFILL_INTERVAL_MIN` | `0` | T5 兜底补数间隔(分钟,<=0 禁用) |
| `SCHED_FULL_ALL` | `true` | 定时任务爬全池 vs 10 只开发子集 |

## 进阶:服务器 / 生产部署(概览)

个人本地跑到第四步就够用了。长期在服务器上跑,分两种角色,别混:

- **本地端(算数据)**:采集 + 分析 + 情绪打分,唯一联网的一端。用 §5.2 的进程内调度常驻自动跑,或系统 crontab 每交易日盘后跑一次 `python -m tools.run all --all`。票池/阈值改 `tools/config/stock_pool.py` / `strategy.py`。
- **展示端(只看数据)**:远端服务器上**只读展示**,不采集、不算、不触网、不需要任何 LLM 密钥。完整落地步骤见下方「远端部署」。

> 架构约束(务必遵守):展示端**只读**。它不跑 `tools.run`、不跑 `tools.scheduler`,只起 Web。数据由本地端产出、经 git(A 期)或签名上传(B 期,规划中)送达展示端。

# 远端部署(阿里云服务器 · Git 拉取 · 只读展示)

> 面向**在服务器上执行部署的运维/Agent**:把展示端网页在一台公网服务器上常驻跑起来,
> 走 HTTPS,数据经 git 拉取。整节命令可直接执行,**幂等**(重复跑不出错)。
> 下列尖括号占位符按实际替换:`<仓库地址>`(git 远端)、`<域名>`(绑定的域名或公网 IP)。
>
> **常驻 + 自动更新/自愈见** [远端自动更新与自愈.md](远端自动更新与自愈.md):systemd 常驻(崩溃/重启自愈)、定时 `git pull` 自动更新、失败回滚;其中「**本项目实际部署记录(阿里 A 期)**」是**当前线上实配的真源**(路径/用户/5 分钟定时/导入 DB 钩子),换机或转交照它一比一复现。

## 0. 这一期部署什么(A 期:Git 携带数据 + 展示端导入 DB + 只读展示)

目标:展示端网页**从数据库取数展示**,且远端**不跑采集、不跑大模型、不跑定时任务**(远端没有 LLM API,也不需要)。做法:

- 本地端算好的**文件产物**随代码一起在 git 里(`data/analysis/<日期>/`)。
- 展示端 `git pull` 拿到文件后,用**导入器**(`tools.sync.import_to_db`,只搬运不重算)把产物一次性灌进 DB。
- 展示端 web 以 `STORE_BACKEND=db` **从库里读**,渲染四页。
- **不需要**:采集、LLM 密钥、定时调度、ingest 接口——这些要么属于本地端,要么属于 B 期(见文末)。

数据流:

```
本地端(采集+分析,唯一联网端) → git push
        │
        ▼
     git 仓库(携带 data/analysis 文件产物)
        │
        ▼  展示端 git pull
        │
        ▼  python -m tools.sync.import_to_db   ← 只搬运,不重算、不触网、不用 LLM
        │
        ▼
     展示端 DB(SQLite,默认 data/app.db)
        │
        ▼  STORE_BACKEND=db uvicorn/gunicorn 只读
        ▼
     浏览器(四页)
```

> 为什么 git 带文件、却又导进 DB?因为你要的是「页面从 DB 取数」,而远端不能重算。git 只当**数据搬运工**把文件产物送到远端,导入器把它转进 DB,web 从此只认 DB。这也把「DB 读取」这条路径在远端完整跑通,为 B 期(签名上传直接入库)铺好地基。

## 1. 服务器准备(一次性)

假设一台全新的阿里云 ECS(Ubuntu 22.04 / Alibaba Cloud Linux 均可)。用 root 或有 sudo 的账号。

```bash
# 系统依赖:Python 3.11、git、nginx、证书工具
# —— Ubuntu/Debian ——
sudo apt update
sudo apt install -y python3.11 python3.11-venv git nginx
# —— Alibaba Cloud Linux / CentOS 系(用 dnf,包名可能是 python3.11 或 python311)——
# sudo dnf install -y python3.11 git nginx
```

**安全组 / 防火墙**:页面展示端口是 **8801**。

- **默认(直接暴露 8801)**:在阿里云 ECS 安全组放行 **8801**,浏览器直接访问 `http://<公网IP>:8801`。本地防火墙同理(如 `ufw allow 8801/tcp`)。
- **可选加固(nginx + HTTPS,见 §5)**:改为放行 **80、443**、**不要**放行 8801(那时应用只监听本机、由 nginx 反代)。

> 直接暴露 8801 最简单、适合快速上线;但它是 **HTTP 明文**。长期公网建议走 §5 的 nginx + HTTPS。

## 2. 拉取代码 + 数据

用一个专用非 root 用户跑应用(此处用 `deploy`,按需换名)。远端已具备该仓读权限,直接拉:

```bash
sudo useradd -m -s /bin/bash deploy 2>/dev/null || true    # 已存在则跳过
sudo mkdir -p /srv && sudo chown deploy:deploy /srv
sudo -u deploy git clone <仓库地址> /srv/stock_analysis \
  || sudo -u deploy git -C /srv/stock_analysis pull --ff-only    # 已克隆则更新
```

`data/analysis/` 在 git 里,`clone/pull` 会一并带下来——这就是展示端要读的数据。

## 3. 建虚拟环境 + 装依赖

```bash
sudo -u deploy bash -lc '
  cd /srv/stock_analysis
  python3.11 -m venv .venv
  ./.venv/bin/pip install --upgrade pip
  ./.venv/bin/pip install -r requirements.txt      # 国内慢可加 -i https://pypi.tuna.tsinghua.edu.cn/simple
  ./.venv/bin/pip install gunicorn                  # 生产用的进程管理器
'
```

> 展示端只读,理论上用不到 `akshare`/`curl_cffi`/`openai` 等采集与 LLM 依赖,但装全量 `requirements.txt` 最省心、避免漏依赖;磁盘不紧张就照装。

**冒烟自检**(能 import + 起得来即 OK):

```bash
sudo -u deploy bash -lc 'cd /srv/stock_analysis && ./.venv/bin/python -c "import web.app; print(\"web ok\")"'
```

> `SQLAlchemy` 已在 `requirements.txt` 里(DB 后端依赖),无需另装。默认库是单文件 SQLite(`data/app.db`),零运维。

## 3.5 把 git 带来的产物导入数据库(每次更新数据都跑)

导入器只读 `data/analysis` 文件、写入 DB,不重算、不触网、不用 LLM。默认写到 `data/app.db`:

```bash
sudo -u deploy bash -lc 'cd /srv/stock_analysis && ./.venv/bin/python -m tools.sync.import_to_db'
# 只导某一天:加 --date 2026-08-07
# 换库:在命令前加 DB_URL="postgresql+psycopg://user:pwd@host/db"(需先装对应驱动)
```

- **幂等**:重复跑不会产生重复数据(按 日期×code 覆盖)。
- 成功会打印类似 `导入完成:{'dates': N, 'records': .., 'views': .., 'code_views': ..}`。
- 页面空多半是这步没跑或 `data/analysis` 没数据(展示端不产数据,靠本地端 push)。

## 4. 用 systemd 常驻 Web(gunicorn + uvicorn worker)

创建服务单元。默认让应用**直接监听 8801 对外**(`0.0.0.0:8801`);若走 §5 nginx 加固,把绑定改成 `127.0.0.1:8801`(只本机)即可:

```bash
sudo tee /etc/systemd/system/stock-web.service >/dev/null <<'UNIT'
[Unit]
Description=Stock Analysis Web (read-only display)
After=network.target

[Service]
User=deploy
WorkingDirectory=/srv/stock_analysis
# 展示端只读:从 DB 读(§3.5 已把产物导入库);无需任何 LLM 密钥
# 换 MySQL/Postgres 时再加一行 Environment=DB_URL=...;默认单文件 SQLite 不必设
Environment=STORE_BACKEND=db
ExecStart=/srv/stock_analysis/.venv/bin/gunicorn web.app:app \
  -k uvicorn.workers.UvicornWorker -b 0.0.0.0:8801 -w 2 --timeout 60
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable --now stock-web
sudo systemctl status stock-web --no-pager      # 应为 active (running)
curl -sS http://127.0.0.1:8801/ | head -c 200   # 本机能拿到页面即 OK
```

到这一步(默认直接暴露),放行安全组 8801 后,浏览器打开 **`http://<公网IP>:8801`** 就能看四页了。要 HTTPS/域名再往下做 §5。

## 5.(可选加固)Nginx 反向代理 + HTTPS

> 只想在 8801 上看页面的话,§4 已经够了,可跳过本节。要 **HTTPS / 绑域名 / 不把应用直接暴露公网**,再做这节。
> 启用 nginx 时:①把 §4 systemd 里的 `-b 0.0.0.0:8801` 改回 `-b 127.0.0.1:8801`(应用只本机)并 `systemctl daemon-reload && systemctl restart stock-web`;②安全组关掉 8801、放行 80/443。

先配 80 反代(证书申请也走它):

```bash
sudo tee /etc/nginx/conf.d/stock-web.conf >/dev/null <<'NGINX'
server {
    listen 80;
    server_name <域名>;
    location / {
        proxy_pass http://127.0.0.1:8801;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
NGINX

sudo nginx -t && sudo systemctl reload nginx
```

再用 certbot 自动签发 + 配 HTTPS(需 `<域名>` 已解析到本机公网 IP):

```bash
sudo apt install -y certbot python3-certbot-nginx        # 或 dnf install certbot python3-certbot-nginx
sudo certbot --nginx -d <域名> --non-interactive --agree-tos -m <运维邮箱> --redirect
# --redirect 会自动把 80 跳到 443;证书到期 certbot 定时任务自动续期
```

> 只有域名时才能用 certbot 签 HTTPS。**只有公网 IP、暂无域名**:可先只跑第 5 节的 80 反代验证连通,HTTPS 待域名就绪再补;公网明文仅供临时验证,别长期裸跑。

验证:浏览器打开 `https://<域名>`,四页(`/`、`/screen`、`/news`、`/stock/{code}`)正常即部署完成。

## 6. 更新数据 / 代码(日常运维)

A 期数据与代码都在 git。本地端 push 后,展示端拉取 → **重新导入 DB**。web 每次请求实时读库,**导入完即刻生效,数据更新无需重启**;只有**代码**变动才需重启服务。做成一个幂等脚本:

```bash
sudo tee /srv/stock_analysis/deploy_update.sh >/dev/null <<'SH'
#!/usr/bin/env bash
set -euo pipefail
cd /srv/stock_analysis
BEFORE=$(git rev-parse HEAD)
git pull --ff-only
AFTER=$(git rev-parse HEAD)
# 依赖有变动时再装(没变很快跳过)
./.venv/bin/pip install -q -r requirements.txt
# 把最新产物导入 DB(幂等)
./.venv/bin/python -m tools.sync.import_to_db
# 代码有变动才重启服务(仅数据变动无需重启)
if [ "$BEFORE" != "$AFTER" ]; then sudo systemctl restart stock-web; fi
echo "updated $BEFORE -> $AFTER at $(date -Is)"
SH
sudo chmod +x /srv/stock_analysis/deploy_update.sh
```

之后每次本地端 push 了新数据,在服务器跑一次即可:

```bash
sudo /srv/stock_analysis/deploy_update.sh
```

> 想全自动:给上面脚本挂个 crontab(如每小时拉一次)。注意 A 期把数据放进 git 只是过渡手段;B 期上线签名上传后,数据将不再随 git 走、也不再需要导入器(见文末)。

## 7. 排障

- **`systemctl status stock-web` 不是 running**:看日志 `journalctl -u stock-web -n 50 --no-pager`;多为依赖没装全或 8801 被占。
- **浏览器连不上 `<公网IP>:8801`**:①安全组是否放行 8801;②服务是否 `active`;③绑定是否 `0.0.0.0:8801`(不是 `127.0.0.1`,否则外网连不到)。
- **页面空 / 找不到数据**:分两步查——① `ls /srv/stock_analysis/data/analysis` 有没有日期产物(没有就是本地端还没 push 或没 pull);② 有产物但页面空,多半是 **§3.5 导入 DB 没跑**,补跑 `./.venv/bin/python -m tools.sync.import_to_db`。也确认服务是 `STORE_BACKEND=db`(读库)而不是读了空文件目录。展示端**不产数据**。
- **502 Bad Gateway**(仅 §5 nginx 模式):nginx 通、但后端没起——查 stock-web 是否 running、绑定是否 `127.0.0.1:8801`。
- **证书签发失败**:多为 `<域名>` 未解析到本机公网 IP,或安全组没放行 80。
- **git pull 冲突**:展示端**只读代码、绝不本地改**;真冲突时 `git fetch && git reset --hard origin/main`(仅在确认服务器无本地改动时)。

## 8. 给远端执行 Agent 的须知

- 上述命令**幂等**,可安全重跑。遇报错**不要反复重试同一条**,读日志定位后再动;信息不全按本文档默认值执行并在结果里说明假设,**不要反问**。
- **绝不**把任何密钥/令牌写进仓库或本文档;展示端 A 期本就不需要密钥。
- 部署完成的判据:`systemctl is-active stock-web` 为 `active`,且 `http://<公网IP>:8801`(或走 §5 后 `https://<域名>`)四页可访问。
- 完成后回报:服务器系统、Python 版本、部署路径、服务状态、访问地址、遇到并解决的问题。

# B 期:签名上传 + ingest 收录(替代 git 携带数据)

A 期用 git 携带数据够简单,但数据混在代码仓、更新要 pull。B 期落地后:本地端算完**一键签名上传**当日产物,展示端 **ingest 服务**验签后落库,网页即刻可见——数据不再随 git 走、也不再需要导入器。

数据流:
```
本地端(算完)─ python -m tools.sync.upload --date <日> ─签名(HMAC+key_id+ts+nonce)→ HTTPS POST
                                                                  │
展示端 ingest 服务(独立端口 8802)token→验签→防重放→时效→契约→幂等落库→审计 → DB ─ web(8801) 只读
```

## B1. 密钥与令牌(两端环境变量,禁硬编/禁入库)

一套共享密钥 + 一个鉴权令牌,**本地端与展示端各配一份相同值**。全走环境变量(见 `tools/config/settings.py` 同步配置块):

| 变量 | 展示端 | 本地端 | 含义 |
|---|---|---|---|
| `SYNC_INGEST_TOKEN` | ✅ | ✅ | Bearer 鉴权令牌(相同值) |
| `SYNC_SIGNING_KEY` | ✅ | ✅ | 当前 HMAC 共享密钥(相同值) |
| `SYNC_KEY_ID` | | ✅ | 本地端当前密钥标识(默认 k1) |
| `SYNC_SIGNING_KEY_OLD` / `SYNC_KEY_ID_OLD` | ✅ | | 轮换窗口内的旧密钥(平滑切换,见 B4) |
| `SYNC_INGEST_URL` | | ✅ | 展示端 ingest 地址,如 `https://<域名>/ingest` |
| `SYNC_INGEST_PORT` | ✅ | | ingest 监听端口(默认 8802) |
| `SYNC_REPLAY_WINDOW_S` / `SYNC_MAX_AGE_DAYS` | ✅ | | 防重放窗口(默认 300s)/ 时效保留天(默认 90) |
| `SYNC_SOURCE_ID` | | ✅ | 本地端来源标识 |

生成随机密钥/令牌(在**安全的地方**执行,值只进两端环境变量,别落文件/仓库):
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"   # 各生成一个给 KEY 和 TOKEN
```

## B2. 展示端:常驻 ingest 服务(systemd)

ingest 只监听本机,由 nginx 做 TLS(公网**必须** HTTPS——令牌/数据不能明文过网):
```bash
sudo tee /etc/systemd/system/stock-ingest.service >/dev/null <<'UNIT'
[Unit]
Description=Stock Analysis Ingest (write endpoint)
After=network.target

[Service]
User=deploy
WorkingDirectory=/srv/stock_analysis
Environment=STORE_BACKEND=db
Environment=SYNC_INGEST_PORT=8802
# 密钥/令牌不要写进本文件;用 systemd 的 EnvironmentFile 从受限权限文件注入:
EnvironmentFile=/etc/stock-analysis/sync.env
ExecStart=/srv/stock_analysis/.venv/bin/python -m tools.sync.ingest
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
UNIT

# 密钥文件(chmod 600,只 root/deploy 可读;绝不进 git):
sudo mkdir -p /etc/stock-analysis
sudo tee /etc/stock-analysis/sync.env >/dev/null <<'ENV'
SYNC_INGEST_TOKEN=<粘贴令牌>
SYNC_SIGNING_KEY=<粘贴密钥>
DB_URL=sqlite:////srv/stock_analysis/data/app.db
ENV
sudo chmod 600 /etc/stock-analysis/sync.env

sudo systemctl daemon-reload && sudo systemctl enable --now stock-ingest
curl -sS http://127.0.0.1:8802/health        # {"ok":true,...} 即起来了
```

nginx 把 ingest 挂到 HTTPS(与 §5 同套证书,加一个 location 或独立 server):
```
# 在 §5 的 443 server 里加:
location /ingest { proxy_pass http://127.0.0.1:8802/ingest; proxy_set_header Host $host; }
```
> 安全组只开 443(nginx),**不要**对外开 8802。
>
> **无域名场景(本项目当前)**:用**自签 TLS(给公网 IP 签,SAN 含 IP)**即可加密,不必等域名——本地端用 `SYNC_INGEST_CA` 指向该自签证书(上传显式 `verify=`,不污染采集端 CA)。完整可复现步骤见 [远端自动更新与自愈.md](远端自动更新与自愈.md) 的「本项目实际部署记录(B 期:启用 ingest 签名上传)」。

## B3. 本地端:签名上传

本地端配好 B1 的环境变量后,算完当日数据即可上传:
```bash
export SYNC_INGEST_URL="https://<域名>/ingest"
export SYNC_INGEST_TOKEN="<令牌>"  SYNC_SIGNING_KEY="<密钥>"  SYNC_KEY_ID="k1"  SYNC_SOURCE_ID="local-1"
python -m tools.sync.upload --date $(date +%F)      # 打包+签名+分片上传+失败重试
```
- 按票分片、失败指数退避重试;回执在 `data/sync_receipts/<日>.json`。
- 部分失败重跑同一命令:只补失败分片(`--force` 可全重发)。
- 上传成功后,展示端 web(8801)即刻能看到当日数据——**不再需要 git 携带数据 / 导入器**。

## B4. 密钥轮换(双密钥窗口)

平滑换 `SYNC_SIGNING_KEY`,不中断上传:
1. 展示端:把**旧**密钥填到 `SYNC_SIGNING_KEY_OLD`/`SYNC_KEY_ID_OLD`,新密钥填 `SYNC_SIGNING_KEY`,重启 ingest。此时新旧签名**都验通过**。
2. 本地端:改用新密钥 + 新 `SYNC_KEY_ID`,继续上传。
3. 观察一段时间确认本地端全切新后,展示端清空 `SYNC_SIGNING_KEY_OLD` 重启,旧密钥失效。

## B5. 运维

- **nonce 清理**:`seen_nonce` 表会累积;定时清理超窗口的(如挂 crontab 调 `tools.sync.audit.purge_old_nonces(<很久以前的iso>)`)。
- **审计**:每次 ingest(成功/失败)在 `ingest_audit` 留一条,含来源/日期/验签结果/条数;定期查它排错与安全审计。
- **DB 备份 + 保留天数**:`data/app.db` 定期备份;历史日期数据按 `SYNC_MAX_AGE_DAYS` 之外可清理(展示端时效已拒收过老上传)。
- **健康检查**:`curl https://<域名>/ingest`（GET 会 405,`/health` 返回 ok);systemd `Restart=always` 保活。

## 0. 一句话总览

系统分**四层**,只有最后一层依赖境外模型(Claude):
1. **量化管线**(采集/筛选/策略0合议/多因子打分/广度)= **纯 Python,不用任何 LLM**,launchd 定时、程序化。
2. **大模型(LLM)层** = **DeepSeek(主,已接生产)** + **千问(备,配了未接线)**,走内部/网关 API、无头程序化。
3. **小统计模型** = **大盘预测 market_forecast**(四维因子加权,非 LLM),程序化、每日滚动重训。
4. **深度分析/调度层** = **Claude Opus 4.8**(窗口驱动、即席)——补选股/复盘/多窗编排,**依赖 Claude Code,非程序化**。

## 2. 小统计模型:大盘预测 market_forecast(重点·数据源与因子搭配)

> 目录 `tools/analysis/market_forecast/`;设计 `docs/计划/大盘预测策略.md`;README 同目录。

- **它做什么**:预测 **沪深300 / 全A等权代理指数** 的 **T+1、T+5「上涨方向概率 + 五档」**(只给方向概率,**不预测涨跌幅**)。
- **模型**:`CompositeModel`(四维可解释因子加权,主)/ `LogisticModel`(对照)。**不是神经网络/大参数模型**。

### 2.1 四维因子 × 数据源 × 因子构成

| 维 | 模块 | 数据源 | 因子怎么搭 |
|---|---|---|---|
| 技术 | `technical_index.py` | 指数自身 K 线 | 复用 technical 算子(MA/MACD/RSI/BIAS 等),as-of 向量化因果 rolling |
| 广度 | `breadth.py` | 全 A 横截面(扫 master/kline,回溯 2018) | 涨跌家数/净广度、**涨停线按板块**、above/below_ma20 占比等 |
| 消息面 | `sentiment.py` | `analysis/*/sentiment_policy.json`(上游=baidu 标签+event.py/DeepSeek) | 日度政策舆情净利好度;历史仅 ~1 月 |
| 资金流 | `fundflow.py` | **SSE 市场级两融**(akshare `stock_margin_sse`,回溯 2022,**仅沪市**) | 融资买入强度、余额 5 日/20 日动量;盘后披露→**滞后 ≥1 交易日**(防未来) |

### 2.2 "训练"到底训了什么(walk-forward)

1. 每维因子 **标准化**(z-score + 温莎化裁剪,防近零方差爆掉);
2. **定向**:每个特征在**训练集内**与"次日涨跌标签"算相关、取符号(决定正向/反向);
3. 分维取均值打分 → 按 **组权重(手工设的 `因子权重` config)** 合成;
4. **校准**成逻辑函数 → P(上涨) + 五档。
- **被拟合的**:标准化统计量 + 定向符号 + 校准系数 —— **每次都只在训练集上拟合**;生产 `forecast.py` 每天产出时用"截至 T 之前的全部历史" **重新 fit**(expanding window,**即每日滚动重训**,`forecast.py:101-106`)。
- **⚠️ 没被学习的**:**维间组权重是手工固定的**(config),不随市场自适应——这是当前"会固化"的点(见 §4)。
- 标签 = T+1/T+5 前瞻收益方向(合法);walk-forward 训练集严格早于测试日,单测锁死防未来。

### 2.3 效力(诚实标注)与局限

- 沪深300 T+1 命中率约 **54.3%**(样本外~210 日),胜 50%/惯性基线但幅度小(标准误≈3.4pp);
- **无经济 alpha**——方向能微弱猜、多空收益价差≈0("钱换不出来");
- 四维标称、**实际只有技术+广度真起作用**:消息面历史浅→按覆盖率自动降权≈0;**资金流权重=0.0(kill-switch,2026-09-02 用户/统筹决策关闭,`strategy.py:370`)**——A/B 判别力弱正不显著,暂不参与预测、待 hs300 历史累积再复核;
- 全A代理指数含**幸存者偏差**(只含当前在市个股→偏高),绝对收益别当真。
- **定位**:只作选股时的 β 方向背景,**绝不当收益依据**。

## 3. 窗口调用 vs API 调用(程序化现状)

- **API 调用(无头程序化)**:量化管线 + DeepSeek/千问 + market_forecast —— launchd 触发 Python,电脑醒着+网关通就自动出结果,**不需要 Claude 窗口**。
- **窗口调用(会话驱动)**:深度选股分析/复盘/多窗调度(我)—— 依赖窗口活着 + Claude Code 模型。
- **现状=两套并存**:自动管线已不依赖 Claude;**真正还依赖 Claude Code 的是"深度分析/判断"这一层**。

## 4. 已定方向与待解决(→ 架构设计承接)

用户 2026-09-13 明确的方向:
1. **模型优先千问 + DeepSeek**,且随两家推新的更强/更快模型**持续上引**;架构要**模型可插拔 + 易升级**。
2. **谨慎境外模型(Claude 等)**:不禁用,但有"将来无法调用"的风险,**关键路径不锁死 Claude**,Claude 逐步退到"研发/兜底"。
3. **能接管线的接管线、能实际模拟应用的用起来**;迁移前**双跑对比**(两模型并跑、分析差距),时间允许**试开 think 思考模式**看能否提质。
4. **小模型要文档化**数据源+因子搭配(本文档 §2 即为此)。
5. **模型实时进化**:不能只训一次;当前系数虽每日滚动重训,但**维间组权重手工固定**、无在线自适应——需设计**滚动重训 + 因子权重可调 + 漂移监控**,别固化旧权重。
6. **定时任务框架**:加任务=注册即跑、改任务=热生效;收编现有 launchd 乱象;健壮(不因电脑睡/卡而漏跑)。

# 远端自动更新与自愈(展示端免手动上机)

> 目标:远端服务器**周期性拉最新代码 + 重启服务**,自己不崩、免手动维护。
> 核心是 `ops/remote_update.py`(可单测的编排)+ systemd unit/timer 模板。
> 真实 apply 在**远端服务器由你执行**;本文给可直接跑的步骤,尖括号占位符按实际替换。

前置:展示端已按 [部署说明.md](部署说明.md) 起好 web(8801)+ ingest(8802),`/etc/stock-analysis/sync.env` 已配密钥。

## 它做什么(一轮 run_update)

```
① 环境检查+自愈:仓库 / venv / 必需 env(STORE_BACKEND=db + 密钥变量)/ DB 目录 / 端口
     ├ 能补的补(如建 DB 目录)
     └ 补不了的(缺 venv、缺密钥 env)→ 清晰报错、退出码 1,不往下走
② 更新:git fetch + merge --ff-only origin/<分支>;仅当有变更才 pip 装依赖
③ 重启+验证:重启 web + ingest;任一重启后健康检查(/health 或 /)不过
     → 自动回滚到更新前 commit(需要则重装依赖)+ 重启 + 返回告警
```

幂等、可重复跑;远端专有值(路径/分支/端口)走参数或 env,不硬编、无密钥入库。

## 先干跑一次(不改任何东西)

```bash
cd /srv/stock_analysis
./.venv/bin/python -m ops.remote_update --dry-run     # 只打印将执行的命令
```

真跑一次(手动触发一轮更新):
```bash
sudo -u deploy env $(cat /etc/stock-analysis/sync.env | xargs) \
  STORE_BACKEND=db /srv/stock_analysis/.venv/bin/python -m ops.remote_update \
  --repo-dir /srv/stock_analysis --branch main
# 退出码 0=成功;1=环境不满足或重启失败已回滚(看日志)
```

参数(也可用同名大写 env:`REMOTE_REPO_DIR`/`REMOTE_BRANCH`/`REMOTE_PYTHON`/`REMOTE_MODE`):
| 参数 | 默认 | 说明 |
|---|---|---|
| `--repo-dir` | `/srv/stock_analysis` | 仓库路径 |
| `--branch` | `main` | 拉取分支 |
| `--python` | `.venv/bin/python` | venv python(相对仓库) |
| `--mode` | `systemd` | 重启方式:`systemd` / `nohup` 兜底 |
| `--dry-run` | 关 | 只打印命令不执行 |

## 定时自动跑(systemd timer,推荐)

模板在 `ops/systemd/`。安装:
```bash
# 1) 服务 + 定时器(占位符已按 /srv/stock_analysis 写好,按需改)
sudo cp /srv/stock_analysis/ops/systemd/stock-autoupdate.service /etc/systemd/system/
sudo cp /srv/stock_analysis/ops/systemd/stock-autoupdate.timer   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now stock-autoupdate.timer

# 2) 看下次触发时间 / 手动触发一次 / 看日志
systemctl list-timers stock-autoupdate.timer --no-pager
sudo systemctl start stock-autoupdate.service
journalctl -u stock-autoupdate.service -n 50 --no-pager
```
默认每小时一轮(见 `.timer` 的 `OnUnitActiveSec=1h`,可改)。`Persistent=true` 保证关机错过也会补跑。

**cron 替代**(无 systemd 时):
```bash
# crontab -e,每小时一次;日志追加,便于排查
0 * * * * cd /srv/stock_analysis && ./.venv/bin/python -m ops.remote_update >> logs/autoupdate.log 2>&1
```

## 进程自愈(保活)

web/ingest 的 systemd unit 已带 `Restart=always`(见部署说明 §4 / B2)——进程崩溃自动重启。auto-update 只负责"更新+更新失败回滚";"进程挂了自己拉起"由 `Restart=always` 兜。`nohup` 兜底模式无此保活,建议尽量用 systemd。

## 告警接入

`run_update` 失败(环境不满足 / 重启失败已回滚)返回退出码 1、日志含 `alert`。把告警接到你的渠道:
```bash
/srv/stock_analysis/.venv/bin/python -m ops.remote_update || \
  curl -s -X POST "<你的告警webhook>" -d "stock 展示端自动更新失败,已回滚,请上机查看"
```
(webhook 地址走 env/参数,别写进仓库。)

## 排障

- **退出码 1、step=env**:日志列出缺什么。缺密钥 env → 检查 `sync.env` 是否被 EnvironmentFile 正确注入;缺 venv → 先建 venv 装依赖。
- **step=restart、已回滚**:代码更新后新版本起不来,已自动退回上一个可用 commit。上机看 `journalctl -u stock-web`/`stock-ingest` 定位新版本为何起不来。
- **timer 不触发**:`systemctl list-timers` 看状态;确认 `enable --now` 过。
- **健康检查总失败但服务其实在跑**:确认端口(web 8801 / ingest 8802)与 unit 里 `-b` 绑定一致,且监听 127.0.0.1。

## 本地已测 vs 远端人工

- **已单测**(`tests/test_ops_remote_update.py`):环境检查判定、缺配置报错、DB 目录自愈、重启命令构造、有/无变更分支、重启失败回滚、参数解析。
- **需远端人工验证**:systemd unit/timer 真实安装与触发、真实 git pull/pip、真实服务重启与健康、告警 webhook 联通——这些依赖真实服务器,按上文步骤在远端执行。

# 本项目实际部署记录(阿里云 · A 期:只跑展示端,无 ingest)

> 忠实记录当前线上实配,便于复现/转交。与上文通用模板的差异:部署路径 `/home/admin/stock_analysis`、
> 运行用户 `admin`、只跑 `stock-web`(未部署 ingest)、开发期定时 **5 分钟**、更新后自动**导入 DB**。
> 服务器专有信息(公网 IP / hostname / 密钥)不入库。

**拓扑**:裸 `uvicorn` 已转为 systemd 常驻;nginx 监听 80 反代到 8801;展示端读 DB(`STORE_BACKEND=db`),数据经 git 携带、更新时由 `import_to_db` 灌库。

### 1. 展示端 web 转 systemd 常驻(`stock-web`)
```bash
pkill -f 'uvicorn web.app:app' 2>/dev/null || true; sleep 2   # 停旧的裸进程,腾出 8801
sudo tee /etc/systemd/system/stock-web.service >/dev/null <<'UNIT'
[Unit]
Description=Stock Analysis Web (read-only display, port 8801)
After=network.target
[Service]
User=admin
WorkingDirectory=/home/admin/stock_analysis
Environment=STORE_BACKEND=db
ExecStart=/home/admin/stock_analysis/.venv/bin/python3 -m uvicorn web.app:app --host 0.0.0.0 --port 8801
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload && sudo systemctl enable --now stock-web
```

### 2. 窄授权:允许 admin 免密只重启 stock-web(供自动更新调用)
```bash
SYSCTL=$(command -v systemctl)
sudo tee /etc/sudoers.d/stock-autoupdate >/dev/null <<EOF
admin ALL=(root) NOPASSWD: $SYSCTL restart stock-web, $SYSCTL start stock-web, $SYSCTL stop stock-web
EOF
sudo chmod 440 /etc/sudoers.d/stock-autoupdate && sudo visudo -cf /etc/sudoers.d/stock-autoupdate
```

### 3. 自动更新服务 + 5 分钟定时器
```bash
sudo tee /etc/systemd/system/stock-autoupdate.service >/dev/null <<'UNIT'
[Unit]
Description=Stock auto-update (pull + import DB + restart stock-web if repo changed)
After=network.target
[Service]
Type=oneshot
User=admin
WorkingDirectory=/home/admin/stock_analysis
Environment=HOME=/home/admin
Environment=STORE_BACKEND=db
Environment=REMOTE_REPO_DIR=/home/admin/stock_analysis
Environment=REMOTE_BRANCH=main
Environment=REMOTE_PYTHON=.venv/bin/python3
Environment=REMOTE_SERVICES=stock-web:8801
Environment=REMOTE_REQUIRED_ENV=STORE_BACKEND
Environment=REMOTE_POST_UPDATE=/home/admin/stock_analysis/.venv/bin/python3 -m tools.sync.import_to_db
ExecStart=/home/admin/stock_analysis/.venv/bin/python3 -m ops.remote_update
UNIT
sudo tee /etc/systemd/system/stock-autoupdate.timer >/dev/null <<'UNIT'
[Unit]
Description=Run stock auto-update every 5 minutes
[Timer]
OnBootSec=2min
OnUnitActiveSec=5min
Persistent=true
Unit=stock-autoupdate.service
[Install]
WantedBy=timers.target
UNIT
sudo systemctl daemon-reload && sudo systemctl enable --now stock-autoupdate.timer
```

### 4. 验证
```bash
sudo systemctl start stock-autoupdate.service && sleep 6
journalctl -u stock-autoupdate.service -n 20 --no-pager   # 无变更应见 "更新完成:changed=False"
systemctl list-timers stock-autoupdate.timer --no-pager   # 下次触发约 5 分钟后
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8801/   # 200
```

### 关键说明
- **服务以 `admin` 跑**:git/pip 保持 admin 属主,不搞乱权限;只有"重启 stock-web"走窄授权 sudo。
- **`Environment=HOME=/home/admin`**:否则 systemd 非交互环境里 git 找不到 SSH key/配置,拉取会失败。
- **`REMOTE_POST_UPDATE`(导入 DB)**:展示端读 DB,数据(随 git 携带)推送后必须重新导入才刷新;有变更时自动执行。
- **只跑展示端**:`REMOTE_SERVICES=stock-web:8801` + `REMOTE_REQUIRED_ENV=STORE_BACKEND`——不碰未部署的 ingest、不要求 B 期密钥。将来部署 ingest 再各自追加。
- **单元文件不在 git**:`/etc/systemd/system/*.service`、`/etc/sudoers.d/*` 属服务器本地配置,改了要手动同步;本节即其真源,照此复现即可。

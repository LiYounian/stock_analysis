# 财报数据源调研：审计机构名称 & 财报正文文本

调研环境：`~/.conda/envs/stock_analysis/bin/python`，akshare **1.18.81**
（`/Users/yqg/.conda/envs/stock_analysis/lib/python3.11/site-packages/akshare`）
调研方式：源码 grep + 单票（600519 贵州茅台）串行联网实测，未触发全市场回拉。
调研日期：2026-08-15

---

## 背景与现状

项目已用 `stock_profit_sheet_by_report_em` / `stock_balance_sheet_by_report_em` /
`stock_cash_flow_sheet_by_report_em`（源码在 `stock_feature/stock_three_report_em.py`）
采三大表，字段里带 `REPORT_DATE`（报告期）、`NOTICE_DATE`（披露日）、`OPINION_TYPE`（审计意见类型）。

**关键事实（实测 600519 利润表，203 列 / 103 行）**：
- 三大表**确实带 `OPINION_TYPE`**（如 `标准无保留意见`），只在年报行有值，季报行为 `NaN`。
- 但三大表**不含审计机构 / 会计师事务所名称**——203 列里唯一审计相关列就是 `OPINION_TYPE`。

即：**审计意见有了，审计机构名称缺**。这正是任务1要补的缺口。

---

## 任务1 · 审计机构 / 会计师事务所名称源

用途：拿到"某股票·某年报期·审计事务所名称" → 比对证监会证券资格所名录 → 不在名录 = 闸门1判财报不可信。

### 候选函数清单

| 候选 | 函数 / 途径 | 参数 | 返回关键列 | 是否覆盖"每股·每年报期" | 实测 |
|---|---|---|---|---|---|
| A | `stock_ipo_declare_em` | `symbol` 报告类型 | `会计师事务所`、`律师事务所` | ❌ 仅**IPO 在审企业**，非全A、非年报期 | 未跑（源码确认字段） |
| B | `stock_register_em`（科创板/创业板等注册制申报） | `symbol` 板块 | `会计师事务所`、`ACCOUNT_FIRM` | ❌ 仅**注册制 IPO 申报**企业 | 未跑（源码确认字段） |
| C | 三大表 EM 接口 | `symbol` | `OPINION_TYPE`（无事务所名） | 有审计意见、**无事务所名** | ✅ 实测：无事务所列 |
| D | `stock_zh_a_disclosure_report_cninfo`（巨潮公告） | `symbol/market/category='年报'/日期` | `代码/简称/公告标题/公告时间/公告链接` | 有年报 PDF 链接，正文/事务所名需二次解析 | ✅ 实测：仅标题+链接 |
| E（兜底） | 年报 PDF 内"审计报告"章节 | 通过 D 拿 PDF url，自行下载+解析 | 报告正文含事务所全称 + 签字 CPA | ✅ 覆盖全A全年报期 | 未跑（方案性） |

grep 结论：akshare 全库里"会计师事务所 / 审计"字样**只出现在 IPO / 注册制申报**相关文件
（`stock_fundamental/stock_ipo_declare.py`、`stock_fundamental/stock_register_em.py`），
`ACCOUNT_FIRM → 会计师事务所` 字段仅服务在审 IPO 企业。**akshare 无"全A上市公司·历年年报审计事务所"的现成接口。**

### 推荐

**没有一个 akshare 原生接口能直接、批量给出"全A·每年报期·审计事务所名称"。** 分层推荐：

1. **首选（工程最省事、覆盖最全）= 方案 E：从年报 PDF 的"审计报告"章节抽事务所名。**
   路径：`stock_zh_a_disclosure_report_cninfo(category='年报')` 拿到年报 PDF 链接 → 下载 PDF →
   定位"审计报告"段（正文里必含"XX会计师事务所（特殊普通合伙）"+ 签字注册会计师）→ 正则/LLM 抽事务所全称。
   **与任务2共用同一条 PDF 管线**（见下），边际成本低。可支撑闸门1。
2. **名录来源要单独准备**：证监会证券资格所名录（"具备证券期货相关业务资格的会计师事务所"）
   由**中注协 / 证监会官网**公布，**不在 akshare 里**，需单独抓取或人工维护一份 JSON。
   > 提示：该名录实际家数近年约 **40 家上下**（历年有增减），任务描述的"~105家"可能是含非证券资格的全部大所口径或旧数据，落地前请以中注协最新公告核对，避免闸门1误杀。
3. **外部数据库兜底**（若要省去 PDF 解析）：CSMAR / Wind / 同花顺 iFinD / 巨潮"诚信档案"均有"审计机构"结构化字段，但收费或需账号；中注协每年发布的《上市公司年报审计快报》也含"公司↔事务所"映射，可脚本抓取。

**能否支撑闸门1**：能，但**依赖新增一条 PDF 解析（或外部库）管线 + 一份自维护的资格名录**，
非"改一行 akshare 调用"即可拿到。建议按方案E落地并把名录固化进 repo（脱敏无关，纯公开名单）。

## 任务2 · 财报正文 / 年报 MD&A 全文文本源

用途：喂 LLM 抽定性信息（增长来源 / 在手订单 / 风险提示）。已知 cninfo 公告接口只给标题+URL、无正文。

### 候选函数清单

| 候选 | 函数 | 参数 | 返回内容 | 是不是"可喂 LLM 的正文" | 实测 |
|---|---|---|---|---|---|
| A | `stock_zh_a_disclosure_report_cninfo` | `symbol/market/category/日期` | `代码/简称/公告标题/公告时间/公告链接` | ❌ 只有标题 + 巨潮详情页链接，**无正文** | ✅ 实测确认 |
| B | `stock_notice_report` / `stock_individual_notice_report`（东财公告） | `symbol/date` 或 `symbol/security/日期` | 公告标题 + `网址`（detail html） | ❌ 同样只给标题 + URL | 未跑（源码确认：`stock_fundamental/stock_notice.py` 拼 `网址` 列） |
| C | `stock_zygc_em`（主营构成 F10） | `symbol`（带市场前缀 `SH600519`） | `报告日期/分类类型/主营构成/主营收入/收入比例/主营成本/毛利率` 等 | △ **结构化分部数据**，非自由文本 MD&A，但能喂 LLM 做"增长来源/业务结构"定量定性 | ✅ 实测：600519 返回 200 行，覆盖到 2026-06-30 |
| D | `stock_profile_cninfo`（公司概况） | `symbol` | `主营业务/经营范围/机构简介` 等短文本 | △ 有自由文本但是**公司简介级**，非年报 MD&A、无风险提示/在手订单 | ✅ 实测：字段确认 |
| E | `stock_irm_cninfo` / `stock_irm_ans_cninfo`（互动易问答） | `symbol` | `提问内容/回答内容` | △ 投资者问答自由文本，可补"在手订单/风险"侧写，非年报正文 | 未跑（源码确认字段） |
| F（兜底/首选正文） | 年报 PDF 全文（巨潮/东财） | 由 A/B 拿 PDF url，自行下载+解析 | **年报完整正文**（含"管理层讨论与分析 MD&A""风险因素""在手订单"） | ✅ 唯一能拿到真·MD&A 全文 | 未跑（方案性） |

grep 结论：akshare 里**没有直接返回"定期报告正文 / MD&A 全文纯文本"的函数**。
所有公告类接口（cninfo/东财）都止步于"标题 + 详情页/PDF 链接"。

### 推荐

- **要真·MD&A 全文（增长来源 / 在手订单 / 风险提示）→ 只能走方案 F：下载年报 PDF 后自行解析。**
  管线：`stock_zh_a_disclosure_report_cninfo(category='年报')` 取 PDF url → 下载 →
  `pymupdf(fitz)` 或 `pdfplumber` 抽文本 → 按章节标题（"管理层讨论与分析""公司面临的风险"等）
  切段 → 喂 LLM。**成本/依赖**：新增 PDF 解析依赖（pymupdf 轻、纯 pip）；单份年报几百页，
  抽文本快但 token 大，建议只切 MD&A + 风险两章再喂 LLM，别整本灌。
  **与任务1方案E完全共用这条 PDF 管线**（同一份 PDF 里既有审计报告段、又有 MD&A 段），强协同。
- **不想碰 PDF 的轻量替代（覆盖不到全部定性维度）**：
  `stock_zygc_em`（分部收入结构，定位"增长来源"最直接、结构化好喂）
  + `stock_profile_cninfo`（业务/经营范围简介）
  + `stock_irm_cninfo`（互动易问答，侧面补"在手订单/风险"）三者拼接。
  优点：纯 akshare、无 PDF 依赖、token 小；缺点：拿不到年报原文的"风险提示"和"MD&A 完整叙述"。

**能否支撑 LLM 文本层**：
- 若可接受"结构化 + 简介 + 问答"的近似定性 → `stock_zygc_em` + `stock_profile_cninfo` + `stock_irm_cninfo` 即刻可用，零新依赖。
- 若要求年报原文级 MD&A / 风险提示 → **必须上 PDF 解析管线（方案F）**，akshare 只能提供 PDF 入口 URL，正文要自解析。

## 一句话总结（给统筹者）

- **任务1（审计机构名）**：akshare 无现成全A接口（`会计师事务所`字段只覆盖 IPO/注册制在审企业）；三大表只带 `OPINION_TYPE` 无事务所名。**支撑闸门1需新增：年报 PDF"审计报告"段解析 + 自维护证券资格所名录（名录不在 akshare，且实际约40家，"105家"需核对）。**
- **任务2（财报正文）**：akshare 无"MD&A 全文"接口，公告类只给标题+URL。**真·正文只能走年报 PDF 自解析（方案F，与任务1共用同一管线）；不碰 PDF 的话，`stock_zygc_em`+`stock_profile_cninfo`+`stock_irm_cninfo` 可作轻量近似，但缺年报级风险提示。**

# 前端 K线图表库调研

> 目标：给"展示 A 股 K线图 + 股价增长曲线"选一个**开源免费**、已原生实现
> 蜡烛图 + 成交量 + 均线叠加 + 缩放 + 十字光标的图表库，减少手搓成本。
> 现状：Web 用 FastAPI + Jinja2 + **Chart.js** 手搓折线 K线（`~项目根/web/`）。
> 数据来自 `chart` 视图：`{dates, close, ma5, ma20, ma60, volume}`。
>
> star 数、协议为调研时（2026-08）从各库 GitHub 主页 / 官网核实所得，
> 版本号未逐一核对，标注处见"需核实"。

## 一句话推荐

**首选 TradingView Lightweight Charts**：Apache-2.0 免费商用、体积最小（~40KB
gzip）、蜡烛图/成交量/线叠加/十字光标/缩放全部原生，接入我们现有视图数据几乎
零改造。**若后续要"内置一堆技术指标 + 画线工具"再考虑换 KLineChart**；
**若图表种类要泛化（不止 K线）选 ECharts**。

## 关键结论

1. **Highcharts 直接排除**：商用不免费，与"开源免费"目标冲突。
2. **Plotly.js 不推荐**：体积大、K线不是它的专长，为一个 K线页引入过重。
3. 真正值得选的是 **Lightweight Charts / KLineChart / ECharts** 三选一，都是
   Apache-2.0 免费商用：
   - **只要"标准券商 K线视觉 + 最小体积 + 最省接入"** → Lightweight Charts。
   - **要"开箱即用的一堆技术指标 + 画线工具"** → KLineChart（省去自己算指标）。
   - **图表要泛化（选股页、资金流、情绪等多种图共用一套库）** → ECharts。

## 针对本项目的迁移建议

### 选型：Lightweight Charts（首选）

理由贴合现状：我们已在分析层（`~项目根/tools/analysis/`）算好 MA5/20/60，
不需要图表库再算指标，KLineChart"内置指标"的最大卖点对我们价值有限；而
Lightweight Charts 体积最小、纯 `<script>` 即可引入、和现在 Chart.js 的
"CDN + 一段 JS"接入方式完全同构，替换成本最低。

### 一个必须先做的数据改造（重要）

现在 `chart` 视图只有 `close`，**没有 open/high/low**，画不了真蜡烛图。
好消息：源头数据是全的——`~项目根/tools/collectors/market.py` 的
`load_kline` 返回的 DataFrame 已含 `open/high/low/close/volume`
（见 `_STD_COLS`）。只需在 `~项目根/tools/analysis/chart.py` 的
`build_chart()` 里多序列化三列即可：

```python
# 在 build_chart 返回体中补充(col() 已定义):
"open":  col("open"),
"high":  col("high"),
"low":   col("low"),
# dates/close/ma5/ma20/ma60/volume 保持不变(向后兼容旧折线)
```

同步更新 `_EMPTY` 与视图注释里的字段清单。这是**唯一需要动分析层的地方**，
且是纯增字段、不破坏现有 Chart.js 折线（旧字段全保留）。

### 前端接入怎么喂数据

Lightweight Charts 的数据格式是 `[{time, open, high, low, close}, ...]` 与
`[{time, value}, ...]`，把现有视图数组按下标 zip 即可，`time` 用 `dates`
里的 `YYYY-MM-DD`：

- 蜡烛图：`candleSeries.setData(dates.map((d,i)=>({time:d, open:open[i], high:high[i], low:low[i], close:close[i]})))`
- 均线：三条 `addLineSeries()`，分别喂 `{time, value:ma5[i]}` 等（`null` 值过滤掉）。
- 成交量：`addHistogramSeries()` 用独立 priceScale 贴底显示。
- 十字光标 / 缩放 / 平移：默认开启，无需额外代码。

改动集中在 `~项目根/web/static/stock.js`（重写 K线部分）+
`~项目根/web/templates/stock.html`（换 CDN 脚本引用，`klineData` 注入不变）。
"股价增长曲线"若指累计涨幅/净值曲线，用一条 LineSeries 叠加或单独一图即可。

### API 版本提醒（需核实）

Lightweight Charts v5 起创建 series 的 API 从 `chart.addCandlestickSeries()`
改为 `chart.addSeries(CandlestickSeries, ...)`。接入前**核实所选版本的建 series
写法**，按该版本文档调用，避免照抄旧教程。

### 工作量量级估计（agent 视角）

- **数据层补 OHLC**：约 5–10 分钟、几 K token（改 `chart.py` 一处 + 跑一次
  `write_charts` 重新落盘视图）。
- **前端重写 K线**：约 0.5–1 小时、input+output 合计 ~30–60K token
  （读现有 stock.js/html → 换库 → 蜡烛+成交量+3 均线+缩放 → 本地起服务肉眼
  验证）。
- **测试**：加一个断言 `chart` 视图含 open/high/low 且长度与 close 对齐的
  小测试，锁住"蜡烛图数据完整性"语义。

合计：**半天量级、~10 万 token 以内**即可完成从折线到真蜡烛图 K线的迁移，
其中最大不确定性是 Lightweight Charts 版本 API 差异（见上"版本提醒"）。

## 1. 项目定位

**一个 A 股行情的「策略辅助工具」。**

- **辅助**,不代替决策:系统做分析、给推荐(含止盈止损、推荐金额),**最终买不买、怎么操作由用户自己定**。
- 边界:**非投资建议**,所有推荐显著标注"仅供参考、风险自负"(见 [P3 计划](../计划/P3_Web展示与预测引擎.md) 诚实性边界)。
- 形态:可本地/服务器部署的 Web,展示每日信息与个股策略。

---

## 2. 原始需求(用户原话要点,忠实记录)

- 主要处理 **A 股**;同时分析 A 股/港股/美股**新闻带来的影响**。
- 两大分析:**技术指标分析** + **情绪影响分析**(情绪三层:政策[国内外] / 公司内部行为或新闻 / 舆情[评论、大V、博主])。
- **最大的策略 = 分析股票**。核心是评估一只股票**有没有超买超卖**——两个来源:**情绪面** + **数据指标面**。
- 评估会看:**近三次放量在哪里**、**支撑点在哪里**、**K 线**、**各种技术指标**。
- 评估**之前**有一道 **选股筛选**;筛选的**具体做法留口子**,用户后续再讲/再讨论。
- **深度挖掘**:要开一个 **财报分析**模块(单独文件夹、进架构),财报怎么分析/看什么/产出什么/是否用大模型做数据提取 —— **留口子,后续单独聊**。
- **买卖推荐**:评估完超买超卖 → 给出"**当前是否适合买入/卖出**"的推荐 → 进一步给**不同持有期的止亏线/止盈线** + **具体推荐金额(钱数)**。
- Web 要展示:每日新闻 + 相关股票 + 利好/利空;数据分析选股;1/5/10 日预测;止盈止损位。
- 要求:整理需求、梳理架构、梳理文档;**凡用户说要但还没给的,记下来**;**要调研的,写清楚**(进开发日志)。

## 3. 抽象后的需求:两阶段 + 支撑模块

系统抽象成**两阶段主流程**:

```
[阶段一] 选股筛选 Screener   ──►   [阶段二] 个股评估 Evaluator   ──►   买卖推荐 + 止盈止损 + 推荐金额
  (从票池/全市场筛候选)              (超买超卖/放量/支撑/K线/指标/情绪)
  ⚠️ 规则留口子,待用户定             ⚠️ 超买超卖 = 情绪面 + 数据面 双维度
```

### 阶段二「个股评估」评估维度
| 维度 | 内容 | 现状 |
|---|---|---|
| 数据指标面超买超卖 | KDJ/RSI/乖离/量能共振 | 技术模块已有(含拐点/超跌) |
| 情绪面超买超卖 | 舆情热度、消息面过热/恐慌 | 待 P2-C/P4(LLM) |
| 近三次放量定位 | 找最近 3 个放量日及其价位 | 待做(技术模块扩展) |
| 支撑/压力位 | 前高前低/密集成交/均线/整数关 | 待做(predict) |
| K线 + 各类指标 | 见 [技术指标说明.md](../参考/技术指标说明.md) | 部分有 |
| 资金流向 | 主力/超大/大/中/小单净流入 | curl_cffi 已通,P3.1 采集 |

### 买卖推荐(阶段二产出)
- 结论:偏买入 / 偏卖出 / 观望 + 依据。
- **不同持有期(1/5/10 日)**的止亏线、止盈线 —— **以百分比表达**(最大亏损%/目标盈利%)。
- **预测**:各持有期预期收益% + 上涨概率(历史频率)。
- 全部**百分比口径**,与买入手数/金额无关(用户明确:不需要总资金)。

## 4. 目标达成的定义(验收视角)

用户能在 Web 上:
1. 看到**筛选**出的候选股列表(阶段一)。
2. 点进任一股 → 看到完整**评估**:超买超卖判定(技术+情绪)、近三次放量位、支撑压力位、K线图、各指标读数。
3. 得到**买/卖/观望推荐** + **不同持有期止盈止损位** + **推荐金额**。
4. 全程可追溯依据、且标注非投资建议。

# 乙案效果验证 · W3 加厚决策包是否真改变选股行为（2026-09-20）

> 性质：金字塔 DeepSeek/千问 **受限调整合成层**的 A/B 机制验证 · 研究模拟 · 非投资建议。
> 口径：**temperature=0 机制验证口径** —— 与生产实际 temperature 可能不同，结论限"机制上会不会
> 改变选股"，**不外推生产分布**（生产可能带采样温度，名单波动幅度会更大）。

## 0. 一句话结论

W3 加厚（W3-A 每票新闻digest + W3-B SYSTEM_PROMPT 辩证核对段）**在 2026-09-17 这天没有实质
改变选股结果**：两模型买入名单 A=B 完全不变，规避名单各仅 1/3 槽位漂移，且该漂移经归因**可归到
"digest 有没有(文本扰动)"而非"digest 说了什么(内容)"**。真正被验证"起了作用"的是 **W3-B 辩证段
改变了推理表述**（诚实标注 digest 缺失、不硬凑利好），而 **W3-A digest 内容因当日新闻覆盖近乎为零
(1/20 富信息、且那 1 条 65 篇全未标注)而无内容可被援引**。→ 瓶颈是**新闻数据覆盖/标注**，不是提示词，
更不是取数机制。**据此建议：backlog4 甲案(function-calling)暂缓，先补 news 数据覆盖与利好/利空标注。**

## 1. 实验设计（干净 A/B，只读开关，生产打分/召回/落盘零改）

- 关键文件加只读开关（`tools/experimental/d2_pyramid_llm_select.py`，commit 见回执）：
  - `--no-digest`：渲染前清空每张 card 的新闻digest行 → 决策包退回 pre-W3-A 无 digest 形态；
    **生产 `d2_package.py` 一字未改**（其 `out.extend(digest or [])` 自然渲染空）。
  - `--baseline-prompt`：用 `SYSTEM_PROMPT_BASELINE`（byte 级取自 git `dec442f^`，即 W3-B 辩证段
    增补之前的原文，无辩证核对段、不引用 digest）；现有 `SYSTEM_PROMPT` 不动。
- 两臂：**A臂(before)** = `--no-digest --baseline-prompt`（关 digest+旧 prompt）；
  **B臂(现状)** = 无 flag（digest 开+加厚 prompt）。
- 同 `as_of=2026-09-17`（收盘→预测 09-18）、同池（骨架 top15 分桶实入 20 票）、`temperature=0`；
  `build_package` 只建一次、派生 digest 开/关两版文本，省调用。数据用主仓 `data/analysis/2026-09-17`
  （`--data-root` 指主仓，未在 worktree 重算落盘）。
- 归因格（refinement：B≠A 有实质差异时可选，单 provider）：DeepSeek 补
  **Donly**=只开 digest（digest 开+旧 prompt）、**Xonly**=只开辩证段（digest 关+新 prompt），
  分离 W3-A vs W3-B 的驱动。
- token：4 主格合计 151,499；DeepSeek 2 归因格另 ~7 万。6 次真调用（走内部网关，非交互 env 用 `zsh -ic`）。

## 2. 三档证据（①②③ 分开陈述；因果结论落 ②/③，①单看不作数）

### ① 名单级（弱证据，含文本扰动，不单独作数）

| 模型 | 臂 | 买入 | 规避 |
|---|---|---|---|
| DeepSeek | A(旧) | 688175 / 600640 / 300776 | 301551 / 002849 / 301571 |
| DeepSeek | B(新) | 688175 / 600640 / 300776 | **301571 / 002849 / 000572** |
| 千问 | A(旧) | 688175 / 600847 / 300776 | 301551 / 000572 / 002281 |
| 千问 | B(新) | 688175 / 300776 / 600847 | **301551 / 301571 / 002281** |

- **买入名单：两模型 A=B 完全不变**（仅千问顺序微调）。
- **规避名单：各 1/3 槽位漂移**——DeepSeek 301551↔000572；千问 000572↔301571。

### ② 理由级（因果主证据：B 臂是否真引用 digest / 辨真伪 / 据此改判）

- **W3-B 辩证段确有作用（推理表述被改变）**：千问_B 的 adjust_log 出现 A 臂完全没有的一条
  "辩证核对说明：多数票基本面/资金面/新闻digest数据缺失(missing)，无法做跨面反驳……对缺失数据的票
  不硬凑利好，按不确定处理并强调控仓"。这正是辩证段要求的"消息面存疑时明说依据不足、不硬凑"，
  是 prompt 生效的直接痕迹。DeepSeek_B 也对新增规避 000572 写了 "新闻digest显示该票仅被大盘综述
  提及"——即**引用了 digest**。
- **但 W3-A digest 内容无信号可援引**：当日 20 张候选卡中 **仅 1 张(000572)digest 富信息**，
  且那 1 张是"近65条 利好0/利空0/中性0/**未标注65**"——**全部未标注，零真伪信号**；其余 19 张为
  "0条新闻/无覆盖"降级。故 DeepSeek_B 对 000572 的 digest 援引，实质是"注意到 digest 没内容"，
  真正的规避理由仍是板块过冷+个股高位（量价/板块面），digest 只是陪衬。
- 结论：**辩证段改了"怎么说"，digest 没能改"选什么"**——因为没有 digest 内容可供推理。

### ③ 表态迁移级（结合归因格）

DeepSeek 四格对照（分离驱动）：

| 格 | digest | prompt | 买入第3槽 | 规避第3槽 |
|---|---|---|---|---|
| A | 关 | 旧 | 600640 | 301571 |
| B | 开 | 新 | 600640 | **000572** |
| Donly | 开 | 旧 | 600847 | **000572** |
| Xonly | 关 | 新 | 002281 | 301551 |

- **规避 000572 当且仅当 digest=开**（B、Donly 有；A、Xonly 无）→ 唯一的名单变化**跟随 digest 的
  "有无(文本扰动)"，而非 digest 内容**（其内容零信号）。这正坐实 refinement(1)：temp=0 下"名单变"
  可能只是加了一段文本的扰动。
- 买入第 3 槽在四格间也抖动（600640/600847/002281）→ 说明**即便 temp=0，单样本仍有模型噪声**，
  边际槽位不稳定，更不能只凭①下结论。

## 3. 结论：改变了行为吗？改得对吗？

- **改变行为？** 机制上**弱改变、且不在选股结果**。买入不变；规避的 1 槽漂移是 digest 存在与否的
  文本扰动 + 单样本噪声，非 digest 内容驱动。**唯一被证实真起作用的是 W3-B 辩证段对推理表述的
  改变**（诚实标注缺失、不硬凑利好）。
- **改得对吗？** 方向对：辩证段让模型在数据缺失时诚实处理、不编利好，是想要的行为，无害。
  但 **W3 的核心卖点（给闭卷 LLM 一份可辨真伪的 digest）在本日无法兑现**，因为新闻数据本身近乎
  没有覆盖/标注（1/20，且那 1 条全未标注）。**当前瓶颈是数据（news_raw 覆盖+利好/利空标注），
  不是提示词。**
- 与 pre-加厚 Sep18 基线（旁证，非严格对照）：Sep18 那次买入含 航天电器/摩尔线程 等，本轮骨架
  已迭代（688175 高凌信息成双模型共识首选），名单差异主要来自**骨架/数据快照演进**，非 W3 加厚，
  故不作因果依据。

## 4. 对 backlog4「甲案 function-calling 要不要做」的建议

**建议：暂缓甲案，先补数据。** 理由：

1. 甲案的价值是让 LLM 按需下钻 news_raw 拿全量原文。但本次验证显示 **news 数据在 20 票里 19 票
   0条/缺失、唯一有量的 1 票 65 条全未标注**——**下钻也无内容可取**，function-calling 会撞同一个
   数据瓶颈，投入产出比低。
2. 应先做的是**闭卷 digest 侧的数据工程**：查清为何 19/20 无新闻覆盖、为何有覆盖的票"未标注"占满
   （利好/利空标注管道是否失效）；把覆盖率与标注率提上来后，**闭卷 digest 本身就能提供真伪信号**，
   多数场景无需 function-calling。
3. 待数据覆盖/标注达标后再评估甲案：那时可在**同一 A/B 框架**下真正衡量"按需下钻 vs 闭卷 digest"
   的增量——本次搭好的只读开关与 driver 可直接复用。

## 5. 复现

入库位置：`tools/experimental/ab_verify/`（研究模拟·非投资建议；真跑产物不入库）。
data 达标后评估甲案可直接复用同一套开关+driver。

- 严格 A/B（4 格）：`ab_verify/ab_driver.py`（build 一次→ digest 开/关两版→ 2 provider×2 臂）
  ```
  zsh -ic 'cd <repo> && PYTHONPATH=. ~/.conda/envs/stock_analysis/bin/python \
      -m tools.experimental.ab_verify.ab_driver \
      --data-root <生产data父目录> --out-dir <非repo产物目录>'
  ```
- 归因（单 provider 2 格）：`ab_verify/attr_driver.py`（Donly 只 digest / Xonly 只辩证段）
  ```
  zsh -ic 'cd <repo> && PYTHONPATH=. ~/.conda/envs/stock_analysis/bin/python \
      -m tools.experimental.ab_verify.attr_driver \
      --provider deepseek_v4pro --label DeepSeek \
      --data-root <生产data父目录> --out-dir <非repo产物目录>'
  ```
- 单格 CLI 等价：`d2_pyramid_llm_select.py` 的 `--no-digest`/`--baseline-prompt` 任意组合。
- 产物：各格 `raw_*.txt` / `out_*.json` / `ab_summary.json` / `attr_summary.json` 落 `--out-dir`
  （默认系统临时目录，**绝不写入 repo**）。
- caveat：全程 temp=0 机制验证口径，结论限"机制上会不会改变选股"，不外推带温度的生产分布。
